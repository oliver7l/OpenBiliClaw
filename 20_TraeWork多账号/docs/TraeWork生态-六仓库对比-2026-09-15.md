## 1. WorkDaddy —— 本生态工程质量天花板

**架构**：本机回环 CDP（Chrome DevTools Protocol）注入 WorkBuddy 渲染进程，**零侵入、零重签名、不改官方安装包**。daemon（9357 行）+ inject（13389 行）+ lib（1595 行），**732 项测试**。

**对我们最有价值的三个发现**：

1. **账号切换不用重启应用**：`JSON 替换 + CDP reload`。对比我们的 TraeWork 切换（必须重启客户端）和 workbuddy-switch 的切换（重启 WorkBuddy）——CDP 注入路线能做到无感切换，代价是要维护注入层。
2. **会话产物复制的归属机制**（读官方 `main/conversations.js` 得出）：官方 `ConversationImpl.filterArtifactsOwnedByConversation` 对工作目录外的 PresentFiles 产物要求 `_meta.ownerConversationId` 匹配当前会话。所以跨账号复制会话产物必须**改写 owner 为目标会话 ID、保留同源 lineage、其余会话的 owner 不动**；读失败/格式错误不覆盖目标；官方并发写入时保留新数据。
3. **mtime 反直觉细节**：`selectLatestAutoCopyMember` 用内容 mtime 选"最新副本"做同步源——复制动作会制造较新 mtime，导致旧副本在下一轮被当成最新来源（同步回滚）。**修复＝复制载荷保留原始文件时间**。这是任何做"本地数据多副本同步"的人都会踩的坑。

**其它**：免打扰＝零决策权限弹窗自动通过（睡前挂任务）；自动化任务（自然语言创建/事件/定时）；积分分段条形图（≤1 天透明度 0.05 → ≥30 天 1.0 线性）。文档纪律极强（版本递增、真机 CDP 往返验证记录、Windows junction 的删除边界防护）。

**风险**：AGPL-3.0（传染性，参考实现思路可以，抄代码进闭源项目不行）；注入对象就是 WorkBuddy 本体，官方升级可能失效。

## 2. traehop —— 与我们切换工具的直接对标

**切换序列**（`trae-switcher.js`）：杀 Trae → 写 `machineid` 文件（数据目录根）→ 清缓存（`state.vscdb.backup`、两处 `Cookies-journal`）→ storage.json 里**删 `iCubeAuthInfo://usertag`**、重生成三个 telemetry id → 写 `AUTH_KEY`（iCubeAuthInfo）+ `ENTITLEMENT_KEY` + `SERVER_KEY` → 重启。

**宝藏：登录态可以从纯 token 现场构造**。`buildUserInfo` 给出 auth JSON 完整 schema：`{token, refreshToken, expiredAt(ISO), refreshExpiredAt, tokenReleaseAt, userId, host(按 region 三选一: api.trae.com.cn / api-us-east.trae.ai / api-sg-central.trae.ai), userRegion{region,_aiRegion}, account{scope:'marscode', loginScope:'trae', storeRegion...}}`，配套 `trae-crypt/trae-byte-crypto` 自加密。意味着**不需要动过 IDE 的完整快照，一个 token 就能造出可注入的登录态**。

**与我们的 `twa_switch_account.py` 对比**：
- 我们＝档案式整体换 storage.json（设备标识随档案走，天然一致）；traehop＝同文件内换三个键 + 重新生成设备标识（token 从账号库来）。
- traehop 目标是 Trae IDE（含国际区），我们是 TRAE SOLO CN——host 和字段细节有差异，不能直接照抄 buildUserInfo。
- **已吸收**：`usertag` 键删除 + 缓存清理清单已并入我们的切换脚本。
- 它的定位哲学值得学：只做手动切换、不做自动轮换、不做代理，README 明确"不是额度套利工具"。

## 3. workbuddy2api —— Go 网关的池化参考

`internal/{auth,pool,scheduler,session,upstream,redisstore,logfmt}` + `cmd/{server,login,signin,credit,activity,trial}`。OpenAI 兼容 `/v1/chat/completions`，OAuth 登录、账号池轮转、熔断与冷却、会话粘性、积分补充（trial/credit 子命令）。与 smart-open 三池 dispatch、Waxilo 智能接管同主题，Go 生态里最完整的一份。对我们 LLM provider 层的"多凭据池化"方案，这是第三个可对照实现（前两个：smart-open 的 Rust 版、workbuddy-switch 的防抖三元组）。

## 4. workbuddy-auto-signin —— mac 上最省事的 WorkBuddy 签到

单文件 `signin.py`（1216 行），自包含、只读本机登录态、零内置密钥，**mac/win/linux 三平台**（macOS 走 launchd，附 plist 模板）。签到接口逆向自桌面端（作者自述腾讯改版可能失效）。相比 AIAutomator（五平台聚合但仅 Windows）——**这是 mac 上做 WorkBuddy 签到的现成答案**，TraeWork 签到则已由 TraeWorkAssistant 覆盖。

## 5. trae-credential-reverse-engineering —— 切换工具的知识底座

分 phase 文档（侦察→数据收集→格式分析→加密→密钥提取→解密）：4/4 凭证解密、98 个 TRAE API 路径、**完整 ECDSA P-256 设备证明续期流程**、18/18 测试。与我们 `twa_scan_accounts.py` 的解密链（URE⊕DRE 常量 + SHA512 两次派生 + AES-128-CBC）同源互证；其 phase5/6 可作为续期 20403 问题（DeviceID + 签发私钥一致性）的权威参考。

## 6. Trae-Work-CN-Account-Manager

Tauri，多开 + 机器码管理，Windows 向。对本机价值低（我们已经用单客户端+档案切换替代多开），仅存档。

## 附注：github.com 被墙时的克隆办法

今晚 `github.com` 直连与全部本地代理均 SSL_ERROR_SYSCALL，但 `api.github.com` 与 `codeload.github.com` 正常。克隆替代通道：

```bash
br=$(curl -s https://api.github.com/repos/OWNER/REPO | python3 -c "import json,sys;print(json.load(sys.stdin)['default_branch'])")
curl -sL "https://codeload.github.com/OWNER/REPO/tar.gz/refs/heads/$br" -o /tmp/repo.tar.gz
tar xzf /tmp/repo.tar.gz && mv REPO-$br REPO
```

（无 .git 历史；需要历史时等 github.com 恢复后 `git fetch --unshallow` 补。）
