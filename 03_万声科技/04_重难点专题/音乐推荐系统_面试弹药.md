## 一句话核心

音乐推荐的本质是**内容推荐的特殊形态**：可重复消费、3 秒切歌（跳过即负反馈）、列表连续播放（序列问题）——这三条决定了它和电商/短视频推荐的关键差异，也是面试一切音乐题的锚点。

## 弹药卡

### ① 综述与基础

**面试可用点**
- 音乐稀疏性：用户平均只听曲库 0.1% 的歌，CF 面临 >99.9% 稀疏，内容过滤（音频/歌词/上下文）是缓解手段
- 多模态是音乐天然属性：音频特征（BPM/调性/响度/音色/情绪）+ 歌词文本 + 封面视觉 + 标签元数据
- 情绪/场景：通勤、运动、学习、深夜——上下文感知是音乐推荐加分项
- 趋势：LLM 生成式推荐（TalkPlay 把推荐重构成 next-token prediction）正在颠覆"检索式 IR"范式

**话术**：先讲"音乐没有下单动作、3 秒切歌、可重复消费"，再讲多模态与序列建模——面试官立刻知道你抓到了音乐的本质。

### ② 工业实践（重点背，全是大厂实证）

| 厂 | 实践 | 数字锚点 |
|---|---|---|
| 网易云 | 统一多场景精排 + 多模态对齐模块（歌词/封面/音频） | 人均播放时长 +3%、歌单分发 +50% |
| 网易云 | PIANO 列表级重排：[CLS] 信息聚合节点 + 查询意图对齐 | CTR +0.62%、CVR +4.45% |
| 网易云 | Climber 生成式推荐（CIKM2025 最佳论文） | 多尺度序列提取 + 自适应 Transformer + 逐位门控 |
| Spotify | 用户表征：音频+协同双编码器 → 三时间尺度（6月/1月/1周）→ 自编码器 | 全产品共享，NRT 近实时更新 |
| Spotify | Contextual Bandit 内容类型校准（音乐/播客比例） | 比静态历史比例准确度 +35% |
| Spotify | Mostra 音乐序列多利益方优化（WWW'22） | Set Transformer + submodular beam search |
| Yandex | 1B 参数生成式推荐 Transformer（KDD'26） | 收听时长 +2.26%、点赞 +6.37%（公开最大增益） |
| 快手 | OneRec 端到端生成式推荐 | 运营成本降至 10.6%、GMV +21% |

**话术**：讲精排时把"序列建模 + 多目标（播放/完播/收藏）+ 列表级重排"串起来，每个环节给一个数字锚点。

### ③ 冷启动（音乐岗高频追问）

**面试可用点**
- 用户冷启动：热门兜底 → 注册信息画像 → 兴趣标签 → 少量行为 → 试探分发 → 跨域迁移
- 新歌冷启动（音乐特有，重点）：
  - **Side info 迁移**：用非冷启动模型导出的曲风/语种/艺人 embedding 给冷歌打分
  - **多模态表征**：CLIP 预训练（音频 Transformer + 歌词 BERT），两阶段（先预训练再喂精排）
  - **I2I2U 间接建模**：冷歌→相似歌→目标用户；对比学习增强
  - **多模态 DSSM 用户兴趣边界建模**
- 网易云 MAIL（CIKM2021）：双塔零样本兴趣学习，直播 CTR +13~15%
- 网易云音乐品鉴家机制：数据发掘垂类品鉴人，冷启动成功率 **3% → 40%+**（强力案例）

**话术**：新歌冷启动 = "没有行为就用多模态表征 + 相似迁移"，结尾用品鉴家 3%→40% 收，直接封死追问。

### ④ 歌单 / 播放列表生成

**面试可用点**
- 自动歌单续播（APC）是列表级问题的工业形态：represent-then-aggregate 框架（Deezer, SIGIR'23）
- 播放列表 = 有序歌曲序列 → 语言建模思路（word2vec/RNN/attention）
- LLM 生成歌单：查询类型分类器动态调节个性化强度（Zvuk）——"什么时候该个性化、什么时候该按描述来"
- RL 生成歌单：attention 语言模型 + 策略梯度

**话术**：歌单生成是"序列问题 + 个性化程度自适应"，可接在精排列表级重排后面讲，形成完整列表链路。

### ⑤ 面试链路（召回→粗排→精排→重排）

**面试可用点**
- 四层漏斗的本质：**用有限算力找最优结果**（1 亿物料全精排要 277 小时——先抛矛盾再讲分层）
- 召回：多路（CF/向量/热门/实时兴趣）+ 通道配额 + 去重；强调覆盖率而非准确率
- 粗排：轻量模型（双塔/浅 DNN）几千→几百，平衡精度与开销
- 精排：多任务深度模型（DIN/DeepFM/MMoE）预测 CTR/时长/完播/收藏；特征=用户/物料/上下文/交叉/实时
- 重排：list-wise 全局优化——多样性（MMR/DPP）、去重、频控、新鲜度、业务配额、探索流量
- 排序目标三范式：point-wise（精排）/ pair-wise / list-wise（重排）

**话术**：答链路题先讲"为什么分层"（算力矛盾），再逐层讲职责，最后强调"精排看单点、重排看整列表"。
