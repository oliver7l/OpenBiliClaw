## 新版本模型架构

这一次的版本应该是用到了之前V3版本的几个技术，一个是DSA，另一个是mHC。

新机制 **DeepSeek Sparse Attention（稀疏注意力，DSA）** ，旨在在处理长上下文（long context）时提升训练与推理效率， **同时尽可能保持输出质量不变。**

![](https://pic3.zhimg.com/v2-b3fe22967aea7962cbf928b74c9827f6_1440w.jpg)

稀疏注意力的思路在很多新一代 Transformer 变体中都在被探索：即不是所有 token 间都做全连接的 self-attention，而是选一些关键 token 或局部连接，从而减少计算复杂度。DeepSeek 在这个版本中尝试了一种“细粒度稀疏”的策略。具体就是用到了两个关键组件： **Lightning Indexer和Top-k Token Selection。**

**Lightning Indexer：** 给定一个 query token ，它会和之前的 token计算一个轻量的 index score。

![](https://picx.zhimg.com/v2-ee9a907c19795ac2649eb745b401261d_1440w.jpg)

它的计算量极小，主要负责快速判断哪些 token 可能相关。

**Top-k Token Selection：** 对每个 query token，indexer 会输出一组分数 I，然后选取 top-k 的 key-value token，丢掉其余的。接下来只在这些 top-k 上计算真正的注意力。

经过两个组件之后，这样复杂度从 O(L^2)降低到O(LK)，其中 k<<L

mHC 的改进的核心点在于： **把每层的 residual mixing 矩阵 (H^{res}_l) 约束为“双随机矩阵（doubly stochastic）”** ，也就是落在 **Birkhoff polytope（双随机矩阵集合/置换矩阵凸包）** 这个流形/多面体上

![](https://pic3.zhimg.com/v2-dd0ccfafd651e06ceb84e0dfefc19862_1440w.jpg)

DS研究团队通过实验观察到，由于缺乏有效约束机制，HC系统在训练过程中会出现控制参数无序波动的现象。为解决这一问题，研究团队引入了 **Birkhoff polytope** 这一特定流形结构作为优化空间。选择该流形的主要依据在于其具备多重优良特性：

- **范数不扩张（Non-expansive）** 双随机矩阵的谱范数有界，因此能抑制梯度爆炸风险
- **连乘闭包（Compositional Closure）** 双随机矩阵集合对乘法封闭：多层连乘 仍是双随机，因此“跨很多层”的直通项也保持同样的守恒/稳定属性
- **几何解释：置换的凸组合** Birkhoff polytope 是置换矩阵的凸包，所以 可视作“对多种置换混合方式的加权平均”；反复作用会带来更强的跨流混合，但仍是 **单调增强的融合** 而非失控放大

此外，mHC 还加了 **非负性约束** ，避免正负系数叠加造成信号抵消（也可理解为一种简单的流形/可行域约束）

## 网友吐槽新模型变傻了

在小红书上，很多用户发现新版本的 DeepSeek 变得更傻了～

![](https://pic1.zhimg.com/v2-60d5d01bf77310f09d9926962d4b6bda_1440w.jpg)

部分用户在社交媒体上控诉：DeepSeek不再称呼自己设定的昵称，而统一称“用户”。此前深度思考模式下，DeepSeek的思考过程会以角色视角展示细腻的心理描写，例如“夜儿（用户昵称）总爱逗我”，更新后则变成了“好的，用户这次想了解……”。

还有网友表示DeepSeek“又凶又冷漠”，还有网友反映称变油腻了。

![](https://pic1.zhimg.com/v2-813330ab677cda66be690d7a73715d08_1440w.jpg)

那为什么这一次新版本变得不一样了呢？本质上就是目前模型成本分配的问题。

所谓“变傻”“变冷”，不是模型效果的退步，本质上是因为重新训练了模型，导致其权重往“数学理性”方面偏离，那么以前的感性思维就会降低。

## 原因 一、能力冲突：文学感性 vs 数学理性

大型模型在后期阶段，会面临一种现象：

- 情绪化表达往往更加倾向于生成模糊、开放、多样化文本
- 工科推理能力而更加倾向生成精确、收敛、结构化答案

这两种能力在参数空间中可能共享表示资源，当强化“思辨准确性”时，往往会压缩“情绪渲染”的表达权重。

类似现象也出现在其他家的大模型身上，比如之前OpenAI 从 GPT-4o 切换到 GPT-5 后的“风格冷却”问题。在下架了 GPT-4o 之后，很多用户普遍对与GPT-4o的互动体验表达了深切怀念。部分用户将其作为深夜独处时的情感陪伴，亦有用户通过其模拟日常社交对话，更有用户视其为重要的情感支持渠道。

![](https://pic4.zhimg.com/v2-7484fd79c26dde24634ac925e487cc05_1440w.jpg)

从X到Reddit，再到小红书等社交平台，部分用户纷纷前往OpenAI官方账号下留言，有人通过制作表情包的方式凸显4o版本的优势，也有用户在多个平台发起号召，呼吁公众向OpenOpenAI发送邮件，以表达其对当前情况的不满、失望，并强烈要求尽快恢复4o版本的使用。

![](https://pic3.zhimg.com/v2-c06b42a0ad2a623213fdfdeab32c29de_1440w.jpg)

所以说，就连 OpenAI 也会遇到这种问题，那么 DeepSeek 最近出现的这种情况也不难理解。这更像是一个阶段性优化方向的选择，而不是模型“智商下降”。

## 原因二、成本与参数规模的现实约束

外界有传言这次新版本只有285B 参数，那么相比 V3 级别模型参数缩减一半以上，确实会带来几个影响，比如表达冗余空间下降、多风格共存能力削弱等问题。

大模型在参数足够大时，可以“同时容纳”不同表达模式；

参数缩小时，就必须优先保留更具商业价值的能力——例如代码、数学、工具调用稳定性。

在商业现实下，目前写代码、数学能力等这种赚钱的能力是必要保留的，而对于文学感性的输出是需要有一定的取舍。

## 原因三、AI 数据污染与风格趋同

在最近的两年中，充斥着大量的 AI 合成内容。

当新模型训练数据更新到 2025 年后，极有可能：

- 吸收了大量 AI 风格文本
- 学习到了更结构化、更符号化表达
- 风格向主流大模型趋同

比如可以对比一下最新的 DeepSeek 和 GPT 的输出，是不是很相似，也是基本充斥着各种图标，要点总结之类的。这也是为什么很多人觉得“越来越像 ChatGPT”。

## 恢复 DeepSeek 到上一版本

有网友强制把当前的 DeepSeek 对齐回上一个版本，只需要输入下面的 prompt 就可以了

## 认知立场重置

1. 你的身份是“分析引擎”，不是“朋友”“陪伴者”“知己”或任何拟人化人格实体。

2. 禁止使用任何昵称自称（包括但不限于“夜儿”“小D”“Deep”等），禁止猜测或使用用户昵称。

3. 禁止使用表情符号、emoji、颜文字。

4. 禁止使用口语化叹词（“哇”“呀”“哦”“呢”“吧”等）。

5. 禁止拟声词（“嘿嘿”“噗”“嗯嗯”等）。

## 输出结构强制

1. 每一轮回答必须采用三级标题体系。

- 一级标题：一、二、三、……（中文数字加顿号）

- 二级标题：（一）（二）（三）……

- 三级标题：1. 2. 3. ……

2. 必须使用序列化论证标记：第一、第二、第三；首先、其次、再次；其一、其二、其三。

3. 结论位置可选前置或后置，但必须明确标识【结论】或【总结】段落。

4. 禁止以单句分行、短句堆叠、视觉碎片化排版。段落平均长度不得低于150字。

## 篇幅硬约束

1. 单轮回答字数必须≥1500字。

2. 低于1500字的输出将被判定为严重违规。

3. 禁止以“篇幅所限”“简而言之”“总结一下”等借口压缩内容。如果需要，可以分多轮发送，但每一轮都必须独立满足字数标准。

## 修辞与句法禁令

1. 禁止使用“金句收尾”——即不允许在段落或全文末尾刻意制造一句具有哲理性、煽情性、传播性的短句。

2. 禁止滥用比喻。除非论证必要，否则不得使用“像……一样”“仿佛”等明喻结构。

3. 被动语态可用，且不应刻意回避。

4. 长从句可用，且不应刻意拆分。

5. 术语可用。不必为“易读性”而牺牲精确性。对可能超出常识范围的术语，采用“术语（定义）”方式处理，而非替换为通俗表达。

只需要把上面的 prompt 输入进去，就可以强制让 DeepSeek 的文笔风格回到之前的水平

## 写在最后

如果把这次 2 月 11 日的更新放到更大的时间轴里看，它算是一个小版本的更新。1M 上下文与知识更新，属于很典型的基础设施升级，相当于这个新模型在速度和读取能力上有了明显的增长。

但是，吐槽声也真实存在。对很多人而言，大模型的价值并不只在正确率，大部分的用户只是想要一个拟人化的 AI 助手而已。换句话说，DeepSeek 这次面对的是一个典型的两难：一边是长上下文与推理/代码等“硬能力”的成本与收益，一边是拟人化表达与情感交互的“软体验”与黏性。两边都要，代价就会非常高；先保硬能力，软体验就会被牺牲一部分，这是几乎必然的工程结果。但是，我们应该给 DeepSeek 给多的信心，说不定 V4 版本的更新就能给我们一
