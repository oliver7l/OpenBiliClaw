最近Hermes Agent这个词语突然之间火爆起来。而且在短时间内github星星数达到了恐怖的56k

![](https://pica.zhimg.com/v2-31429d81e52f167a730231cab9ba96a2_1440w.jpg)

很多人都在说，龙虾危险了！毕竟这次的Hermes Agent主打的就是能够不断记忆，不断自我迭代。用过龙虾很多人都知道， **它像个记性不太好的工具人同事** ——每次开会都要从头对齐一遍需求，上回说好的流程下回又忘了。你刚教会它怎么查数据库，换个聊天窗口它就一脸茫然地问：“咱们第一步干啥来着？”

这种“鱼的记忆”带来的痛苦是实实在在的：

- **重复造轮子** ：每次执行复杂任务，都得把相同的前置条件和注意事项重新念一遍，像是在给新人做入职培训，一训就是一百遍。
- **Token烧得肉疼** ：一遍遍地重新推理、重新试错，上下文窗口里塞满了重复的指令和修正，月底一看账单，心比大润发的杀鱼刀还冷。
- **稳定性全靠玄学** ：同样的任务，今天能跑通，明天可能卡在一个莫名其妙的环节，你去问它为什么，它比你还无辜。

所以当Hermes带着“ **我记性好，还会自己学** ”的人设出现时，很多人第一反应就是—— **龙虾那套“每次都重新认识世界”的玩法，是不是该被扫进历史垃圾桶了？**

毕竟，谁会拒绝一个能记住你上次说“我不喜欢用sudo”之后再也不乱提、能把你上次手动调了三遍的参数直接固化成技能、甚至能从失败里自己长教训的Agent呢？

这种对比太强烈了，强烈到让人觉得 **龙虾如果不赶紧把自己的记性治一治，可能真的会被会进化的新物种慢慢挤到墙角** 。

## 龙虾最被人诟病的问题，Skill 自主进化并不能解决

这件事放到 OpenClaw，也就是大家俗称的“小龙虾”身上，会看得更清楚。

OpenClaw 最常被人吐槽的地方，其实一直很稳定：

一是 **token 消耗大** ，账单很容易吓人；

二是 **长时间运行稳定性差** ，容易中断、失联、跑崩。

乍一看，这是两个问题。往下拆你会发现，它们很多时候其实来自同一个源头：

**Agent 在用低质量、脆弱的工具，去完成本该由确定性工具完成的任务。**

最典型的就是浏览器自动化。很多 Agent 系统表面上看很聪明，实际上大量时间都花在“看网页”“猜状态”“点按钮”“发现失败”“重新规划”“再次尝试”这种循环里。 **网页 DOM 一变，按钮状态一抖，弹窗位置一换，整个流程就开始反复试错。**

而这些试错都不是免费的。每一次观察页面、分析状态、决定下一步，都在继续消耗 token。任务越长，失败越多；失败越多，成本越高；成本越高，失联和中断的概率也越大。

于是你会发现，稳定性差和成本高，根本不是两回事，它们其实是一回事的两面：

**工具越脆弱，试错越多；试错越多，token 烧得越快；链路越长，系统越容易崩。**

从这个角度看，Hermes 的 Skill 自主进化，解决的是“如何更聪明地使用一个工具”；但它没有直接解决“高质量工具本身稀缺”这个问题。

Skill 能让 Agent 更熟练地驾驭一匹跛脚马，但它并不能把跛脚马直接变成千里马。

这才是今天很多 Agent 真正卡住的地方： **不是 Skill 不够强，而是下面能被调度的高质量原子工具太少。**

## **Hermes：不止是更聪明，更是“自己人”**

Hermes的迅速崛起，源于它精准地抓住了OpenClaw用户的几个核心痛点，其差异化的能力主要体现在三个方面：

![](https://pic1.zhimg.com/v2-97e5c29ff9117f6503af624378538db4_1440w.jpg)

**“越用越懂你”的进化闭环** ：这是它最根本的突破。Hermes内置了一个“记忆-技能-数据”的闭环学习系统。

- **记忆层** ：通过MEMORY.md和USER.md等文件，它能主动记录你的偏好和环境，像一位熟悉你工作习惯的同事，摆脱了“鱼的记忆”。
- **技能层** ：完成复杂任务后，它会自动将操作过程提炼为标准化的 **Skill文件** ，下次遇到类似任务可直接调用，不再从零开始推理。
- **数据层** ：它甚至能将交互行为转化为训练数据，为模型未来的进化提供燃料，极具前瞻性。

**对“痛点”的降维打击** ：OpenClaw因工具链不稳定等问题，导致 **Token消耗大、运行成本高** 。而Hermes通过将成功经验固化为Skill，让Agent能熟练调用已验证的方法，避免了大量低效的试错，从而显著降低了Token消耗，提升了稳定性。

**更深度的“本地优先”** ：与OpenClaw将本地模型视为一个普通“供应商”不同，Hermes将本地模型奉为 **“第一公民”** 。它的配置极其简洁，本地模型和云端模型地位完全平等，可随时灵活切换。对于注重隐私、成本和离线可用性的开发者来说，这是一个巨大的吸引力。

## 快速安装一个属于你的Hermes

安装非常简单，基本上一条命令就能完成：

```text
curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash
```

这套安装脚本会自动处理大部分准备工作，包括依赖安装（如 Python、Node.js、ripgrep、ffmpeg）、仓库克隆、虚拟环境创建、全局 hermes 命令配置，以及 LLM Provider 的基础设置。跑完之后，就可以直接开始使用。

由于这是一键安装脚本，实际耗时会受到本机环境、网络情况以及已有依赖状态影响。如果中途看起来像是“卡住不动”，通常不一定是真的报错，也可能只是还在安装某些组件。这个时候可以稍微多等一会儿；如果长时间没有进展，再考虑切换网络或重新执行一次。

安装完成后，直接运行下面这条命令，就可以正式开启对话：

```text
source ~/.bashrc   # or: source ~/.zshrc
hermes             # Start chatting!
```

## Hermes 会击败 OpenClaw 吗？

回到最开始的问题：Hermes，会击败 OpenClaw 吗？

**它会冲击 OpenClaw，但决定胜负的，主要还是谁更早补上 CLI 这一层基础设施。**

Hermes 现在风评越来越好，是因为它抓住了一个非常对路的方向：让 Agent 具备经验沉淀能力，让系统不是每次都从零开始。这当然是进步，而且是很重要的进步。

但如果下面还是一堆脆弱浏览器自动化、一堆高 token 成本的语义兜底、一堆不适合 Agent 调用的低质量工具，那么 Hermes 最后也会遇到和 OpenClaw 类似的问题：

贵、慢、不稳定、难调试。

也就是说，Hermes 真正的价值在于 **Skill 层的问题，开始有人认真解决了。**

**但 Agent 的下一个真正战场，不在 Skill，而在 CLI。**

Hermes 今天的机会，主要是它有机会在更高一层架构上，把“经验沉淀”和“工具调用”重新组织起来。

谁能先把它结合好，谁才有机会笑到最后。
