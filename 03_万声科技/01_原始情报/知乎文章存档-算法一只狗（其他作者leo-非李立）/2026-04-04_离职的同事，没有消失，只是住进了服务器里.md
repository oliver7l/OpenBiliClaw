你的同事跳槽了，留下大量的文档没人维护？

**将冰冷的离别化为温暖的 Skill，欢迎加入赛博永生！**

![](https://pic3.zhimg.com/v2-bf1d667f7b028c19e3a98c53362b87ba_1440w.jpg)

这个仓库的唯一目的，就是把你同事的所有聊天记录进行导入，然后加上你的几句话印象，即可把这个赛博同事留在你身边。而且目前支持多个平台数据来源，让它马上能够复制一个AI来替代你同事的工作。

![](https://pic3.zhimg.com/v2-878c8c6a21ac664c235e5876424f95d2_1440w.jpg)

## 如何把你的同事炼化成skill

要快速整一个自己的同事skill，其实也很简单。

**针对Claude Code，执行下面的命令**

```text
# 安装到当前项目（在 git 仓库根目录执行）
mkdir -p .claude/skills
git clone https://github.com/titanwings/colleague-skill .claude/skills/create-colleague

# 或安装到全局（所有项目都能用）
git clone https://github.com/titanwings/colleague-skill ~/.claude/skills/create-colleague
```

**而在OpenClaw下，则执行这个**

```text
git clone https://github.com/titanwings/colleague-skill ~/.openclaw/workspace/skills/create-colleague
```

下面有两个场景，让你的同事直接帮我们干活和甩锅给他们

输入：字节 2-1 后端工程师，INTJ，甩锅高手，字节范

**场景一：Code Review**

> 用户      ❯ 帮我看一下这个接口设计 
>  同事.skill ❯ 等等，这个接口的 impact 是什么？背景没说清楚。              （看完后）N+1 查询，改掉。返回结构用统一的              {code, message, data}，这是规范，不用问为什么。

**场景二：甩锅**

> 用户      ❯ 这个 bug 是你引入的吧  同事.skill ❯ 上线时间对上了吗？那个需求改了好几个地方，还有其他变更。

整体看下来，把同事也直接焊死在服务器上，直接赛博永生。

## 还有“前任”skill？

就在大家还在围观、测试「同事.skill」的时候，更离谱的事情已经发生了。

GitHub 上开始像病毒裂变一样，疯狂长出各种奇形怪状的衍生项目：前任.skill、老板.skill、导师.skill，甚至还有父母.skill。

一夜之间，主打的就是四个字： **万物皆可 Skill。**

事情发展到这一步，其实已经很清楚了。

AI 的演进，正在悄悄从「能力复制」滑向「行为复刻」。

既然 Skill 的本质，是把知识、习惯、经验和反应方式，封装成可以复用的数字资产，那按照这个逻辑，身边几乎一切关系，都值得被打包成一个 Skill。

同事可以，前任可以，导师可以，老板当然也可以。

比如这个「前任.skill」，甚至贴心地提供了“微信聊天记录全自动导入”功能。

![](https://pica.zhimg.com/v2-34bc99942930675773acaeb344864996_1440w.jpg)

它可以根据你们分手前的聊天记录，生成一个 AI 前任。

你要是忍不住发去一条求复合的消息，它大概率只会冷冷回你一句：

“哦。”

这一下，连产品定位都解释清楚了：

**它之所以是前任，不是没有原因的。**

又或者，你其实并不想复合。

你只是想再和 ta 聊一次天。

想看看那个熟悉的语气，熟悉的停顿，熟悉的敷衍，是不是真的还能从 Token 里长回来。

![](https://picx.zhimg.com/v2-c8df115252afbc95f787591a172f1865_1440w.jpg)

「导师.skill」则堪称学术界的赛博福音。

以后学生再也不用担心导师毕业跑路、出差失联、消息失踪。直接把导师往届的论文批注、修改意见和邮件风格一股脑导进去，一个 AI 导师就能原地上线。

当你小心翼翼地问它“老师，这一段该怎么写”时，它会像真人一样精准回复：

“这里逻辑不对，再改改。”

“我没时间看，你自己再想想。”

“这不是我上次说过了吗？”

你甚至会产生一种诡异的错觉：

导师也许不在办公室，但他永远活在你的文档边栏里。

![](https://pic1.zhimg.com/v2-9c5bc68340bd8c7aee928ed35db49a46_1440w.jpg)

至于「老板.skill」，更是当代职场人梦寐以求的高阶工具。

总觉得自己不会做事，不知道项目为什么总被打回，不知道该怎么向上同步、怎么写汇报、怎么猜老板到底在想什么？

那就干脆把老板的判断逻辑、批评方式、优先级排序、向上管理套路，全都抽出来，炼成一个 Skill。

聊天记录、会议纪要、批注风格、项目材料，统统都可以成为蒸馏原料。

从此以后，你不需要再反复揣摩老板到底想听什么。

你只需要先问一遍 AI 老板，它就会提前告诉你：

这件事为什么不重要，

这个方案为什么不落地，

以及你这页 PPT 为什么“一看就没想清楚”。

说到底，这些项目真正让人不适的地方，不在于它们好笑，而在于它们确实讲通了一套越来越成立的逻辑：

**当 Skill 可以封装知识，下一步就一定会封装习惯；**

**当习惯可以被抽象，下一步就一定会逼近行为；**

**而当行为都开始被复刻，人和人之间最私密、最具体、最不可替代的部分，也就开始变成可调用、可迁移、可复制的数字模块。**

于是，今天你看到的是「同事.skill」。

明天可能就是「前任.skill」「导师.skill」「老板.skill」。

再往后，也许真的会走到那一步——

**这个世界上的每一种关系，最终都能被整理成一个文件夹、一套 Prompt、几条规则和一份可执行的skill文档**

## 深度解析：这个仓库怎么蒸馏出一个人

**1）输入层：多源采集数据**

在 SKILL.md 的工作流里，可以导入多种数据形式：

- 飞书自动采集：消息记录 + 文档 + 多维表格
- 钉钉自动采集：文档 + 多维表格，消息记录靠浏览器采集
- 飞书链接：直接给 Wiki/文档链接
- 上传文件：PDF、图片、JSON、邮件
- 直接粘贴内容

这个仓库非常重视“聊天痕迹”而不是只重视“正式文档”。相当于把所有你同事的内容、截图等数据学去了

**2）处理层：抽取结构进行处理**

它会把你给它的内容整理成固定文件结构。也就是说，它做的是 **从原始资料 → 结构化规则文件 → 最终 Skill** 的三段式转换。

这一步非常重要，因为只有先抽成结构，后续才能持续修正、增量追加、版本回滚，而不是每次都重新“喂一遍上下文”。

**3）输出层：生成的不是“聊天记录总结”，而是可调用 Skill**

最终产物不是一份报告，而是一个新的可调用 Skill。创建后可用 /{slug} 调用完整版，用 /{slug}-work 调工作能力，用 /{slug}-persona 调人物性格。

所以它直接是一个 **可执行的人格-能力包** 。

## 写在最后

表面上看，这像是一场互联网整活。但往深里看，它真正可怕的地方，是 **足够还原一个人最容易被组织消费的那部分能力** 。

它可以复刻你的知识、习惯、表达方式、判断路径，甚至是你在群里回消息的口气。

这意味着，AI 复制的已经不只是能力，而是一个人在组织中的 **功能性人格** 。

也许未来，离职不再意味着彻底离开。

你只是从工位上消失了，却继续住在服务器里。
