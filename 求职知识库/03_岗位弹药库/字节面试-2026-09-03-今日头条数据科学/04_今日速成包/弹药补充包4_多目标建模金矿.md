## 💣 弹药14 · MMoE 多目标排序（短内容浮层）★你的招牌主菜

### 项目全景（一页讲清）
```
场景：QQ看点信息流短内容浮层（类似微博）——曝光pv 2亿/天、uv 3kw/天；消费pv 2.3亿/天、uv 2kw/天
目标：提升业务总时长 + 大盘累计时长
问题：浮层场景无明显点击信号、目标众多且部分稀疏 → 单目标建模顾此失彼
方案：MMoE 对"停留时长 + 进评论"做多目标建模；专家网络差异性（DNN+FM+CIN）、专家组、专家层次化
效果：短内容总时长 +6.96%、大盘累计时长 +0.76%、短内容互动行为 +35%、浮层时长 +6.8%
```

### 完整话术（可直接背）
> "我讲一个我做过的**多目标排序**项目——QQ 看点的短内容浮层推荐。这个场景类似微博的信息流，规模是**曝光 pv 2 亿/天、uv 3kw/天，消费 pv 2.3 亿/天**。业务目标是**提升总时长和大盘累计时长**。
>
> 核心难点：浮层场景**没有明显的点击信号**，但又有很多目标要兼顾——时长、互动（进评论）、消费，而且有些目标比较稀疏。单目标建模会顾此失彼：只优化时长，互动就掉；只优化互动，时长不够。所以我把排序模型从单目标升级成 **MMoE 多目标**，对**停留时长 + 进评论**联合建模。
>
> 做法上有几个关键点：第一，**专家网络设计**——MMoE 核心是多个专家 + 门控路由，我验证了**专家间的差异性很重要**（DNN+FM+CIN 组合最优），还做了专家组网络、专家层次化建模；第二，**目标选择**——我总结了三原则：**目标不能太稀疏、目标间不能太冗余、目标间要有一定相关性**，用斯皮尔曼相关系数量化目标相关性，选既有相关性又不冗余的目标组合，而不是一味加目标；第三，**特征**——我把用户行为序列、交互特征、召回理由都接入。
>
> 上线效果：**短内容总时长相对提升 6.96%、大盘累计时长提升 0.76%、短内容互动行为提升 35%、浮层时长提升 6.8%**。这个项目也帮我所在的团队拿了**腾讯看点 Q1 技术攻坚奖**。"

### ⚡ 追问链
- **"为什么用 MMoE 不用 ESMM/多任务 hard sharing？"** → 浮层场景没有清晰的"点击→转化"漏斗，ESMM 更适合有转化链路的场景（我用在主 feeds）；MMoE 通过门控让不同任务自动选择不同专家，适合目标间关系不固定的浮层场景。
- **"目标怎么选？为什么是时长+进评论？"** → 目标选择三原则：不稀疏、不冗余、有相关性。时长代表消费深度、进评论代表互动，两个相关性适中且都重要；用斯皮尔曼相关系数量化，避免选到互相冗余的目标。
- **"专家网络差异性怎么做的？"** → 让不同专家用不同结构（DNN/LR/FM/CIN），避免专家学成一样；实验中 **DNN+FM+CIN 组合最优**；还做了专家组、层次化。
- **"和单目标比提升在哪？"** → 单目标顾此失彼，多目标让时长和互动一起涨；互动 +35% 是单目标做不到的。
- **"为什么短内容总时长+6.96% 但大盘只有+0.76%？"** → 因为浮层在大盘时长里占比有限，但**大盘的正向**说明是净增益不是内部转移，这是最重要的判断。

## 💣 弹药15 · 多目标对齐：召回与精排目标统一 ★原创亮点

### 项目全景
```
背景：精排已经多目标化，但召回还是单目标 → 精排层拿不到"综合最优"的候选集（目标Gap）
问题：多路单目标召回，各自选TopK，但"综合最优"的候选可能都没进 → 有效召回率低
方案演进：①多路单目标召回（稀疏目标学不充分、多模型资源大）
         ②多路单目标 + 多目标粗排
         ③（采纳）多目标模型召回：用户/物品侧分别学多个目标向量，共享数据联合训练，架构支持目标扩展
线上实践：探索向量拼接"一份索引、一次请求"直接召回综合最优，提升有效召回率
```

### 完整话术（可直接背）
> "这个项目我解决的是**召回和精排的目标对齐**问题。背景：当时精排已经迭代成多目标模型，但召回还是单目标——**召回层按各自目标挑出来的 TopK，和精排要的'综合最优'不一致**，导致精排层拿不到足够好的候选集，这就是所谓的**目标 Gap**。
>
> 我先分析了三个方案。**方案一：多路单目标召回**——按目标1召回 100、按目标2召回 100；问题是稀疏目标学不充分、多个模型训练和线上资源消耗大。**方案二：多路单目标+多目标粗排**——能缓解但没解决本质。**方案三（我采纳的）：多目标模型召回**——让**用户侧和物品侧分别学习多个目标向量**，目标向量一一对应各自训练，多目标**共享训练数据、联合训练**，模型架构支持目标扩展。线上拿到多个用户向量，在各自索引里召回。
>
> 这个方案最关键的洞察是**有效召回率**问题：单目标召回按各自目标选 TopK，比如目标1召回100、目标2召回100，其中真正'综合最优'的可能只有 40 个，**有效召回率只有 40%，极端情况甚至接近 0%**。所以我又做了线上实践优化——探索**向量拼接**这种简而美的方案，一份索引、一次请求，直接召回综合最优，**大幅提升有效召回率**。
>
> 效果上，这个对齐让召回层真正喂给了精排层它想要的候选，业务时长和互动继续提升。"

### ⚡ 追问链
- **"有效召回率为什么这么低？"** → 召回按各自目标选 TopK，而精排要综合最优；两个 TopK 的交集中'综合最优'占比低，极端时完全不重合。
- **"多目标模型召回怎么建索引？"** → 物品侧多个目标向量建立多份索引，用户侧线上得到多个用户向量分别召回，再融合/拼接取综合最优。
- **"向量拼接和分索引召回哪个好？"** → 分索引多次请求成本高；向量拼接一份索引一次请求，简而美，实践效果好。
- **"为什么精排多目标了召回必须跟着多目标？"** → 上下对齐才没有短板效应；召回是候选集的上游，目标不对齐，精排再强也拿不到好候选（劣币驱逐良币）。

## 💣 弹药16 · 时长消偏建模（样本偏差处理）★方法论亮点

### 完整话术（可直接背）
> "多目标建模里我遇到一个很典型的问题：**时长样本有偏差**。同一个 25 秒的停留，曝光在第一个位置还是第四个位置，意义完全不同——位置靠前天然停留长；段子天然时长长、短文本天然时长短。如果统一按一个阈值标正负，会把**'因为位置好所以停留长'当成'用户喜欢'**，模型学歪，内容生态也不健康。
>
> 我的做法是**相对分位判定**：拿这次停留时长和**过去 k 小时同类内容、同位置的分位值**比。举例：这次停留 25 秒，如果过去 k 小时曝光在第一个位置的平均停留是 28 秒 → 判负样本；如果曝光在第四个位置平均 18 秒 → 判正样本；如果这个 item 是段子（平均 26 秒）→ 判负；是短文本（平均 23 秒）→ 判正。这样样本判定更合理，内容生态也更健康。
>
> 我沿着这个思路迭代了五版时长建模：**直接回归（不好，受极值影响）→ log 回归（缓解）→ 统一阈值二分类（有效但阈值不合理）→ 统计分位阈值（更好）→ 分位阈值+时长分段权重（实验最优）→ 多分类建模（继续实验中）**。
>
> 上线效果：**短内容浮层停留时长 +1.5%、大盘累计使用时长 +0.34%**。"

### ⚡ 追问链
- **"为什么要消偏？不消会怎样？"** → 位置/类型偏差让模型把"曝光位置好"误当"用户喜欢"，越推越偏，短内容生态恶化。
- **"相对分位和统一阈值差在哪？"** → 统一阈值把不同位置/类型一视同仁，不公平；相对分位对齐到"同类同位置的基准"，判定更合理。
- **"为什么最终用分位阈值+时长分段权重？"** → 分位阈值解决偏置，时长分段（如 25s/50s/100s 分段做正样本权重）把**时长强度**也用上，比二分类信息更全，效果最优。
- **"这个方法论能推广吗？"** → 能，任何"行为量度受上下文影响"的样本都能用相对分位消偏，比如推荐位置的点击、视频完播率。

## 💣 弹药17 · ESMM 多目标 + 双稳态损失（图集主 feeds）★算法深度

### 完整话术（可直接背）
> "在主 feeds 场景，我用 **ESMM 做点击+转化/点击+时长的多任务建模**。背景：主 feeds 有个经典问题——**转化有样本选择偏差和稀疏性**，比如用户先点击再转化，如果只对'点击'建模，会偏向点击高但转化低的样本。
>
> 我的方案演进四步：**①样本构造**（点击+转化为正样本→正样本变少）；**②损失函数优化**（对转化 pv 高的点击样本更敏感→消费 pv +1.23%）；**③点击率+转化率两个独立模型**（资源消耗大、转化稀疏学不充分）；**④ESMM 多任务建模**（消费 pv +1.76%）。ESMM 的核心是**完整空间建模**：`pCTCVR = pCTR × pCVR`，用曝光→点击、点击→转化全链路的样本一起学，既解决了样本选择偏差，又让转化目标借用点击信号学得更充分。
>
> 配套还做了**损失函数优化**：转化存在异常样本会支配总损失、样本又严重不均衡（大量简单负样本），我引入**双稳态损失函数（Bistable）+ Focal loss**——双稳态通过参数 t1/t2 降低异常样本对 loss 的影响，Focal loss 平衡正负样本和难易样本。
>
> 整体效果：**图集消费 pv +2.72%、图集时长 +8.11%、人均时长 +10%**；ESMM 的多任务方案也复用到了小说、短内容等新品类。"

### ⚡ 追问链
- **"ESMM 怎么解决样本选择偏差？"** → 完整空间建模：pCTCVR=pCTR×pCVR，用全链路（曝光→点击→转化）样本，而不是只在点击样本上学转化，消除了"只在点击后样本训练"的选择偏差。
- **"为什么不用一个联合模型直接预测转化？"** → 转化样本稀疏，直接学不够；ESMM 让 CVR 塔共享 CTR 的表示，借用点击信号，学得更充分。
- **"双稳态损失是什么？"** → Google 提出的鲁棒损失，通过 t1∈(0,1)、t2∈[1,∞) 两个参数压低异常样本对梯度的支配；配 Focal loss 处理样本不均衡。
- **"这套方法能用到别的业务吗？"** → 能，我后来把它推广到小说、短内容品类；任何"有先后行为链+转化稀疏"的业务都适用。

## 💣 弹药18 · 模型/特征细节加分包（按需展开）

以下是你答辩里的技术细节，面试官追问到哪个就展开哪个：

1. **Kernel 矩阵做不同 embedding size 特征交叉**：特征1(size64)×特征2(size16) 无法直接相乘 → 用 64×16 kernel 矩阵算交叉权重；对比 Attention-Net：参数量 1024 vs 3072（省 2/3）、训练 19min vs 23min、AUC 0.74562 vs 0.74563（持平）→ **参数更少、更快、效果持平**。
2. **Attention 支持变长行为序列**：行为序列截断会丢兴趣（体育类兴趣丢失）→ 动态补全 → UNK 占比过重掩盖真实兴趣 → 在 Attention 上层加 **Mask 层** 对补全的 UNK 向量 Mask → **消费 pv +2.59%**。
3. **RNN 建模兴趣演变**：用户兴趣有转移（美女→体育）→ RNN 取最后状态有信息损失 → **各状态加权输出（Attention 学权重）** → **消费 pv +1.34%**；后续用 self-attention+position embedding 替换 RNN 降耗时。
4. **召回侧工程**：图集向量预训练（行为少的图集也能召回）、负样本按热度降采样（相关性更好）、行为少用户序列扩充；DSSM 内容侧加属性特征提升泛化（新内容也能召回）。
5. **特征体系**：序列特征（itemid 序列按艾宾浩斯遗忘曲线衰减权重、分类/标签序列按统计占比权重）、交叉特征（分年龄/性别点击数率）、召回理由作为特征传入排序层；特征规模千万级、模型参数亿级。

### 方法论金句（排序/召回，直接背）
> "排序是**目标、特征、模型**三者的艺术。主 feeds 场景重点是**点击之后的消费**，有样本选择偏差 → 用 ESMM 完整空间多任务建模；浮层场景无明显点击信号、目标众多 → 用 MMoE 多目标综合考量 + 目标选择三原则。召回的样本是'良莠不齐里选潜在优质'，环境更复杂，要多路召回 + 负样本优化 + 多目标对齐。"
