## 第 2 题 · 项目深挖①：关注→留存因果 🎯 弹药 1 + 4 + 8

**🎤** "讲一个你最有代表性的项目，跟用户留存相关的。"

**✅ 直接背（完整 STAR）：**
> "我讲**'关注行为对留存的因果影响'**，这是我在腾讯做 QQ 看点时用户侧留存的核心命题。
>
> **背景**：团队要判断"关注"这个关系链值不值得重点投入，是不是拉留存的有效抓手。当时普遍直觉是"关注越多留存越高"，但我们要的是**因果结论**，不是相关。
>
> **方法**：三步。第一，定义指标：用**周活跃天数、日均时长、未来 6 天留存**做核心观察。第二，数据打通：把关注行为表 `t_dwa_kd_fans_focus_di_day` 和用户行为表、画像表关联，**剔除官方导流号**这些干扰样本。第三，**因果验证**：不只看分组相关——对互动行为做了 **DID 双重差分**（`Y = β0 + β1·is_treatment + β2·is_post + β3·(treat×post)`，β3 就是因果增量），并做平行趋势检验。
>
> **结论（数字）**：关注用户 vs 未关注：**周活跃天数 +21.2%、日均时长 +1.6%、未来 6 天留存 +9.4pp**。细分：一线城市时长 +5.47%（整体的 3.4 倍）、50 岁以上活跃 +26.45%、女性留存 +18pp。另一个关键发现是**关注数 14 个拐点**——关注到 14 个留存最高，超 14 转负（账号质量问题），且第 9~14 天慢慢达成效果最好。
>
> **难点**：最难的是因果性。我最初做分组对比，发现关注用户天然是高活，这是**幸存者偏差**。所以补了 DID、分层验证，还做了新用户"关注 2 个 vs 1 个"的对比（次留 +9pp），才敢下因果结论。
>
> **商业影响**：这套结论直接支撑了账号推荐的投入——推荐每天触达 3000w 用户但关注转化率只有 0.8%，而个人页关注转化率 3.6% 是它的 4 倍多，把账号推荐链路做深就是明显的留存增量空间。"

**⚡ 追问应对：**
- "为什么用 DID 不用随机实验？" → 关注行为没法强制随机，DID 用行为前后差分 + 对照组抵消时间趋势；新用户关注数对比是天然的近自然实验。
- "14 个拐点怎么排除巧合？" → 分群看不同关注数的留存曲线，9~14 天慢慢达成最优、超 14 转负与账号质量一致，多个角度互相印证。
- "结论能上实验吗？" → 已给出实验设计建议：对 0 关注新用户做关注引导 AB，用次留/7日留存做主指标验证。

## 第 3 题 · 项目深挖②：DAU 下降排查 + 热水池 🎯 弹药 2 + 11

**🎤** "DAU 连续下降你怎么排查？讲一个你做过的专项。"

**✅ 直接背（五步法 + 方法论升级）：**
> "我做过一个 **DAU 六周下降专项**：从 9057w 掉到 8410w，降了 647w、约 7.7%。我的排查是**五步法**：
>
> **第一步看大盘**：确认降幅、周期，排除埋点/统计口径问题。
> **第二步拆结构**：按新老、活跃层级拆——发现**新增稳定在 20w 上下、次留稳定 50%+，但 DAU 还在跌**，说明问题不在"入水口"，在"水池里"。
> **第三步方法论升级（烧水池理论）**：把 DAU 看成用户池的沸腾程度——**水池里的水 = 累计用户，沸腾的水 = 当天 DAU，水沸腾的概率 = 用户活性 P，烧水的柴 = 促活手段**。用近 6 个月活跃用户近似累计用户（**只损失 4% DAU**），定义**温度 = DAU / 前 6 月总用户数 × 100** 来长期监控池子健康度。
> **第四步量化归因**：红点停投约 **200w**、暑期文件约 **150w**、push 热点约 **47w**、高活转低活约 **400w**；其中**120 天以上沉默用户占比从 23% 突增到 43%**，直接造成 **46 万 DAU 下滑**。
> **第五步给措施**：沉默用户专门召回、引入工具性功能"先来再说"、探索规律性访问产品（新闻早直播间、运动模式），红点提频预计拉回 80w。
>
> 这个项目的价值是：我建立了一套**"用户池活性/温度"监控指标**，不只看次留这种入口指标，能提前发现老用户长沉默的结构性风险。"

**⚡ 追问应对：**
- "次留稳为什么 DAU 还跌？" → 次留只刻画新用户入口，DAU 由整个用户池决定；老用户长沉默在悄悄流失，多日留存滞后、离散，掩盖了结构性变化。
- "归因怎么防止重复计算？" → 每类用独立行为口径（红点看启 UV 降幅×0.3 系数、push 看热点周期），逐类核算再相加。
- "46 万怎么算的？" → 假设其他沉默段不变，仅把 120 天以上占比和活性换成变化后值，对整体活性的影响 × 冷水用户盘子。

## 第 5 题 · 业务 Case：信息流 DAU 连续下跌 🎯 弹药 2 + 11 + 9

**🎤** "头条信息流 DAU 连续一个月下跌，你怎么分析？"

**✅ 直接背（四步框架）：**
> "我会按四步走。
> **第一步定口径**：明确 DAU 定义（去重口径、是否含被动打开）、下跌的时间范围和幅度，先排除大盘趋势和埋点问题——这是'是不是真的跌'。
> **第二步拆指标**：`DAU = 新增 + 回访 - 流失`，继续拆新老用户、活跃层级（高/中/低）、启动方式（主动/被动/端外）；判断是**入口问题还是池子问题**——如果新增和次留都稳，那问题就在老用户池。
> **第三步排假设**：五类——①大盘/节假日/竞品；②产品与策略改动（版本、推荐算法、推送红点、激励）；③内容供给（热点缺失、作者流失、内容质量）；④外部流量（投放、渠道）；⑤技术故障（埋点、崩溃）。
> **第四步验证定位**：用**用户池活性**看长沉默人群的变化（我在腾讯就发现 120 天以上沉默用户占比突增导致 46 万 DAU 下滑），用**因果/实验**确认策略改动的影响，用流失用户画像+流失去向看竞品和替代，最后量化每一类贡献，按'可解释占比 × 可操作收益'排序给措施和预期。"

**⚡ 追问应对：**
- "第一步先看什么？" → 先看是不是埋点/大盘导致的伪下跌，再拆结构。
- "怎么给优先级？" → 按可解释占比 × 可操作收益排序，优先动因清楚且收益大的。
- "如果最后归因都不显著呢？" → 说明是系统性/慢变量问题（用户习惯迁移、大盘人口红利），转向长期抓手（用户池活性监控、内容供给）。

## 第 7 题 · 手撕 SQL（高频 3 题完整答案）🎯 速刷题单

**🎤 ① "写 SQL：算每日新增用户（首日活跃）的次日留存率"**
```sql
-- 每日新增 = 当天首次活跃
WITH first_day AS (
  SELECT user_id, MIN(dt) AS first_dt
  FROM user_active_daily
  GROUP BY user_id
),
new_users AS (
  SELECT first_dt AS dt, user_id FROM first_day
)
SELECT
  n.dt,
  COUNT(DISTINCT n.user_id)                                   AS new_cnt,
  COUNT(DISTINCT a.user_id)                                   AS keep_cnt,
  ROUND(COUNT(DISTINCT a.user_id) / COUNT(DISTINCT n.user_id), 4) AS d1_retention
FROM new_users n
LEFT JOIN user_active_daily a
  ON n.user_id = a.user_id AND a.dt = DATE_ADD(n.dt, 1)
GROUP BY n.dt
ORDER BY n.dt;
```

**🎤 ② "写 SQL：找出连续活跃 3 天及以上的用户"**
```sql
-- 连续N天的通用套路：日期 - row_number() 的分组
WITH t AS (
  SELECT user_id, dt,
         DATE_SUB(dt, ROW_NUMBER() OVER(PARTITION BY user_id ORDER BY dt)) AS grp
  FROM user_active_daily
)
SELECT DISTINCT user_id
FROM t
GROUP BY user_id, grp
HAVING COUNT(*) >= 3;
```

**🎤 ③ "写 SQL：统计关注漏斗（曝光→进个人页→关注）"**
```sql
SELECT
  COUNT(DISTINCT CASE WHEN is_exposure THEN user_id END)  AS exposured_users,
  COUNT(DISTINCT CASE WHEN is_view_profile THEN user_id END) AS view_profile_users,
  COUNT(DISTINCT CASE WHEN is_follow THEN user_id END)    AS followed_users,
  ROUND(COUNT(DISTINCT CASE WHEN is_view_profile THEN user_id END)
        / COUNT(DISTINCT CASE WHEN is_exposure THEN user_id END), 4) AS expo2view,
  ROUND(COUNT(DISTINCT CASE WHEN is_follow THEN user_id END)
        / COUNT(DISTINCT CASE WHEN is_view_profile THEN user_id END), 4) AS view2follow
FROM user_follow_funnel
WHERE dt = '2026-09-02';
```

**⚡ 追问：数据倾斜怎么处理？** → 四板斧：①过滤异常 key（如空值/热点 key 单独处理）；②`skew join`/加盐（热点 key 加随机前缀打散）；③两阶段聚合（先局部 group 再全局 group）；④大表 join 小表用 map join / broadcast。

## 第 8 题 · AB 实验 / 因果推断 🎯 弹药 3

**🎤** "如何验证一个新推荐策略是否有效？AB 实验有哪些坑？"

**✅ 直接背：**
> "我会按**设计→执行→分析**三步走。
> **设计**：先定指标——主指标（时长/留存/收入）+ 护栏指标（体验/多样性/渗透），防止'时长涨了体验崩了'；再随机化——用户级分桶，同一用户不同端会串扰，要统一；用**功效分析**算最小样本量（预估效应 + 波动率）。
> **执行**：上线前做 **AA 实验**验证分流均匀 + **SRM（样本量守恒）检验**，防止分桶不均。
> **分析**：区分**统计显著与业务显著**（看效应量和置信区间，不只是 p 值）；看**分群异质性**（哪些用户受益、哪些受损）；防止**偷看**（多次看显著性要用序贯检验/EGO 控制）；长期看**南辕北辙指标**（短期时长涨、长期留存跌）。
> **因果补充**：如果无法随机（比如功能不可控），我用 **DID / PSM**，讲平行趋势检验和共同支撑假设。"

**⚡ 追问应对：**
- "怎么算样本量？" → 功效分析：`n ∝ (z_α + z_β)² · σ² / δ²`，δ 是最小可检测效应，σ 是波动。
- "SRM 是什么？" → 实验组/对照组样本量偏离预期比例，说明分流或流失有问题，结果不可信。
- "DID 和 AB 区别？" → AB 是随机分组（最强因果）；DID 是准实验，用前后差分+对照组抵消趋势，要平行趋势检验。
