## 一、CTR / CVR 预估

### 1. 模型演进路线（面试常问"用什么模型"）
LR → FM → DeepFM → DIN → DIEN → MMoE → 多目标
- 每个阶段演进理由要讲清楚（线性→交叉→深度→注意力→多任务→多目标）

### 2. 为什么推荐系统用 Wide & Deep 而不是纯 Deep？
- Wide 侧记忆高频共现模式（如"下载了微信的用户也常下载QQ"）
- Deep 侧泛化到未见过的新模式
- 两者互补

### 3. 评估指标
| 指标 | 说明 |
|---|---|
| AUC | 排序能力，不依赖阈值 |
| LogLoss | 概率校准程度 |
| 校准偏差（Calibration） | 预估均值/实际均值，越接近1越好 |
| GAUC | 按用户分组的 AUC 均值，更贴近业务 |
| PCOC | 预估/实际（PCOC=Predicted CTR / Observed CTR），接近1最好 |

### 4. 校准怎么做（结合 OPPO 多位置校准）
> "不同位置（首屏/次屏/搜索位）曝光质量、用户注意力、竞争环境不同，CTR 天然差异大。我做了分位置校准：为每个位置统计实际 CTR 和预估 CTR 比例，对预估做位置维度的校准，保证每个位置预估和实际基本对齐。OPPO 优化前主要切片偏差 50%+，优化后控制在 20% 以内，PCOC 收敛到接近 1。"

### 5. 样本怎么构建（必考工程题）
- 正样本：点击/转化；负样本：曝光未点击
- **样本选择偏差**：用曝光空间而非点击空间样本（否则只在模型推过的内容上训练）
- **负采样比例**：广告 CTR 低（千分之几），正负严重不平衡，负采样+加权
- **去噪**：过滤无效点击、误点、机器人
- **时间口径**：训练/验证按时间切分，避免数据穿越

### 6. 特征工程（四大类）
- 用户特征（画像、历史行为序列、品类偏好）
- 广告特征（广告主、素材、品类、历史表现）
- 上下文特征（位置、时间、场景、网络）
- 交叉特征（用户×广告品类等）
- 高维稀疏特征处理：Embedding、特征哈希、特征筛选

## 二、多任务 / 多目标建模（腾讯+OPPO强项）

### 1. 为什么要多任务学习？
- 多个目标（CTR、CVR、时长、互动、LTV）单任务各自训练的问题：
  - **样本选择偏差**（CVR 只在点击样本训练）
  - **数据稀疏**（CVR 正样本少，借 CTR 数据互补）
  - **工程成本**（每任务一个模型）
- 多任务共享底层 embedding，信息互补 + 全空间建模（ESMM）

### 2. ESMM 原理（必背）
- 把 CVR 放在**完整曝光空间**建模：pCTCVR = pCTR × pCVR
- 两个塔共享 embedding，用"曝光→点击→转化"链路监督
- 解决：样本选择偏差（CVR 传统只在点击样本训练）+ 数据稀疏

### 3. MMoE 原理
- 多个**专家网络（Expert）** + 多个**门控（Gate）**，每个任务通过自己的 Gate 对专家输出加权组合，实现**软共享**
- 相比硬共享缓解负迁移
- 变体：MMoE-Group（专家分组）、MMoE-Special（特殊专家）、MMoE-Skill，隔离冲突任务、保留任务特有信号

### 4. 两个目标相关性低甚至负相关怎么办？
- 模型结构：分组专家/特殊专家隔离信号
- 目标定义：检查代理目标是否选错
- 权重/帕累托：动态权重平衡
- 核心判断：任务冲突是模型问题还是业务目标问题

## 三、LTV 预估（广告/买量核心）

### 1. 为什么预估 LTV
- 买量出价、分发加权、资源分配都要求在用户早期（D0-D3）就预测未来 LTV30/90，等不起队列统计

### 2. LTV 预估方法阶梯（由浅入深，必背）
| 方法 | 思路 | 适用 |
|---|---|---|
| 比例系数法 | LTV_n = LTV_d × 历史(LTV_n/LTV_d)系数 | 工业界 baseline，稳定好用 |
| 曲线拟合外推 | 拟合个体/队列早期收入曲线外推 | 队列级 |
| ML回归 | 特征=早期行为(D0-3登录/时长/关卡/付费/看广告/社交)，标签=LTV_n；GBDT/DNN | 用户级 |
| 两阶段建模 | 先分类"会不会付费"，再对付费用户回归"付多少"；LTV=p(付费)×E[金额] | 解决零膨胀 |
| ZILN分布建模(Google) | 零膨胀对数正态：分类头判零/非零 + lognormal回归头估金额，还能输出不确定性 | 业界主流进阶 |
| 序列模型 | 用行为序列(Transformer)建模兴趣演化 | 行为丰富场景 |

### 3. surrogate（代理指标）法
- 不直接估 LTV360，先估早期可观测的强相关代理指标（D7留存、D7付费、D3时长、关卡进度）
- 再用代理指标到 LTV360 的历史映射外推
- 本质：**把长窗口问题转成短窗口问题**（谷歌 Surrogate 分析法）

### 4. LTV 防守追问
- **比例系数 K 不稳定？** → 分渠道/分品类/分用户层统计；监控 K 漂移；用近期成熟队列滚动更新；异常回退曲线拟合
- **版本大更新后历史曲线失效？** → 引入版本/活动特征条件外推；或用更新后的短期数据重拟合参数
- **和买量出价结合？** → 出价按 pLTV360：bid ∝ pLTV360，约束 LTV360/CPI > 1 回本线；不确定性大的用户降低出价或留探索预算

## 四、冷启动（广告+推荐，最常考）

### 1. 新广告/新计划冷启动（问题+解法）
**问题：** 新计划没有点击/转化历史，pCTR/pCVR 只能靠猜，eCPM 低，竞不到量；即使竞到成本也不可控。

**解法三类：**
1. **先验迁移（核心）**：
   - 按行业/素材类型/定向人群/落地页类目聚类，新计划继承同类老计划的 pCTR/pCVR 先验
   - **素材特征建模**：用素材的图像/文本 embedding（CV/NLP）直接预估 CTR，不依赖历史行为（内容理解解决冷启动）
   - 广告主历史：同账户老计划表现作为账户级先验
2. **贝叶斯平滑**：
   - pCTR = (点击 + α×先验CTR) / (曝光 + α)，α 是平滑强度
   - 数据少靠先验，数据多靠自己——置信度过渡平滑（和阿里妈妈 Bayes-SIR 同一思想）
3. **探索扶持（流量侧）**：
   - 给新计划保量/boost：竞价中加探索权重，或留专属探索流量池
   - 探索预算：广告主侧设"冷启动期"，允许成本偏高，换数据积累

### 2. 设计一个广告冷启动系统（系统设计题）
- 探索流量池：划出 5-10% 流量给冷启动广告
- 先验初始化：基于品类/开发者历史特征初始化预估
- UCB/Epsilon-Greedy：多臂老虎机平衡探索与利用
- 渐进式退出：曝光量达阈值后逐步过渡正常竞价
- 冷启动审核：实时监控冷启动广告转化率，低于阈值自动下线

### 3. oCPX 冷启动常见误区（面试加分）
1. **频繁改出价**：冷启动期模型在探索，频繁改出价打乱模型学习，延长冷启动周期
2. **跑一天就关停**：样本量不足就判定效果差，很多计划只是还没度过探索期
3. **一次性大幅加预算**：预算翻倍导致流量池突变，模型需重新学习，成本大概率反弹；正确做法是每次加预算不超过 20%-30%

**面试标准话术：**
> "冷启动阶段的数据分析，我不会只看绝对成本下结论，因为小样本的随机波动很大。首先会判断样本量是否足够，至少积累 30 个转化、置信区间波动在可接受范围内，再评估效果；冷启动前期重点看健康度：拿量能力、CTR、链路通畅度、转化信号，预判计划能不能跑起来；同时避免频繁调整出价、过早关停、大幅加预算这类会干扰模型学习的操作。"

## 五、对比学习（OPPO 项目，简历亮点）

### 1. 对比学习原理
- 拉近相似样本，推远不相似样本
- 推荐中解决长尾/稀疏问题，提升用户/物品表征质量

### 2. 三个对比辅助任务（简历写法，必背）
1. **user-user 场景粒度对比（学"相似用户"）**：
   - 正样本对：行为模式相似的用户（同场景、同品类偏好、行为序列相似）
   - 负样本对：随机采样的不同兴趣用户
   - 学什么：让相似用户 embedding 靠近
   - 为什么有用：中长尾用户自己行为少，借"和他像的活跃用户"把表征拉到正确位置——用群体信息补个体稀疏
2. **正负反馈对比（学"喜欢vs不喜欢"）**：
   - 正样本：用户深度行为（下载、长时、付费）对应 item
   - 负样本：曝光未点击、或点击即走的 item
   - 学什么：让"真喜欢"和"假喜欢/不喜欢"在空间里拉开
3. **深浅行为对比（点击vs下载vs激活）**：多粒度行为在特征空间对齐

### 3. 防守追问
- **正样本怎么构造，相似用户怎么定义？** → 行为序列相似度 + 同场景同品类偏好规则筛选，或预训练模型算 user embedding 相似度取 topK；清洗避免把"都点了热门"误判为相似
- **和 user embedding 聚类/协同过滤区别？** → 协同过滤是离散、基于统计的；对比学习端到端学连续表征，能融合更多特征且和主模型联合优化
- **α（辅助loss权重）怎么调？** → 网格搜索 + 观察中长尾离线 AUC/GAUC 和线上指标；α 太大会伤害头部主任务，选头部不降、中长尾明显涨的点
- **怎么验证是中长尾涨的？** → 分用户活跃度分桶看实验：头部持平、中长尾桶 ARPU +2.3%，符合"补稀疏"预期，因果链对得上

## 六、端云协同（OPPO 项目，系统设计加分）

### 1. 端云推荐架构（简历写法）
- 云侧训练 / 端侧推理 / 端云联合训练三种范式灵活切换
- 核心模型云端训练，轻量模型部署端侧实时推理，用端侧实时行为增量更新
- 模型压缩（量化、剪枝）+ 参数分拆，大模型拆小模块按需加载
- 云端负载成本降约 25%，端上实时性显著提升

### 2. 实时特征降级 + 近线更新（海外弱网场景）
- 在线层：只用端侧可获取的特征（设备信息、本地缓存的最近行为）
- 近线层：每隔 15-30 分钟批量更新用户画像（不依赖实时流）
- 离线层：每天全量更新模型参数
- **"三层时效"架构**降低了对实时数据管道的依赖，在网络不稳定海外环境更鲁棒

## 七、多模态（JD第3条职责）

### 1. 多模态怎么做（OPPO 版）
- 用预训练 CNN（ResNet/ViT）提取图像特征、BERT 提取文本特征
- 融合方式：简单拼接（concat + MLP）或 **Cross-Attention**（图像特征和文本特征互相 attention，效果更好）
- 基于对比学习框架，让应用多模态表征和用户行为序列表征对齐到同一语义空间
- 新应用无用户行为，也能通过内容特征与用户画像匹配做冷启动
- 结果：中长尾用户 ARPU +2.3%

### 2. 对广告素材做 CTR 预估，图像特征怎么做？
- 预训练 CNN 提取图像特征
- 和用户行为特征做 Cross-Attention
- 多模态融合：文本特征（BERT）+ 图像特征（ViT）+ 行为特征（DIN）

## 八、大模型 + 推荐/广告（前沿加分）

### 1. 大模型做推荐的价值点
- **跨语言语义对齐**（海外应用商店最大价值）：
  - 东南亚六国六种语言，用户搜索词和应用描述语言不同，传统关键词匹配失效
  - 用多语言 LLM（mBERT / XLM-R）把不同语言的应用描述和搜索词映射到同一语义空间
  - 机器翻译辅助任务 + 对比学习（同一应用不同语言描述做正样本对）
  - 参考 Coupang CSRM-LLM：在线 A/B 缺陷率降低 45.8%，会话购买率提升 0.866%
- **适配器微调（Adapter）**：不修改国内模型原始参数，插入小型适配器模块只训练适配器，冻结预训练参数，为各国配置适配器；某国效果不好只重训该国适配器，不影响其他国家

### 2. 面试话术（大模型+海外推荐）
> "海外应用商店推荐中，大模型最大的价值是跨语言语义对齐。东南亚六国六种语言，用户用印尼语搜'edit video'，需要匹配到英语、韩语、中文描述的应用。我们用多语言 LLM（如 XLM-R）把不同语言的应用描述和搜索词映射到同一个语义空间，实现了跨语言的精准匹配。参考 Coupang 的实践，这种方式在新兴市场可以把搜索缺陷率降低 45% 以上。"
