## 一、广告算法与机制深度题（最高频）

### 1. 讲一下RTB（实时竞价）的完整流程

**要点：**
- 用户访问媒体 → 媒体发起广告请求 → SSP/SDK发送到ADX → ADX发起竞价请求给各DSP → DSP根据用户画像和广告主出价策略返回出价 → ADX选择最高价胜出 → 展示广告 → 监测曝光/点击/转化
- 整个流程通常在100ms内完成

**关键角色：** 广告主 → DSP → ADX → SSP → 媒体

### 2. 第一价拍卖 vs 第二价拍卖的区别

| 维度 | 第一价 | 第二价（GSP） |
|:---|:---|:---|
| 成交价 | 出价最高的价格 | 出价第二高的价格+0.01 |
| 出价策略 | 需博弈，出价低于真实估值 | 按真实估值出价是占优策略 |
| 平台收入 | 不稳定，波动大 | 更稳定 |
| 广告主体验 | 容易后悔出价过高 | 更公平，减少后悔 |

**扩展：** 现在业界主流是**第一价拍卖**（Google AdX从2019年改的），因为第二价有"bid shading"问题——DSP会策略性压低出价，反而导致平台收入下降。

### 3. Header Bidding 是什么？和RTB有什么关系？

**要点：**
- Header Bidding是RTB的一种实现方式，在媒体页面Head中嵌入JS代码，同时向多个ADX/DSP发起竞价
- 与传统RTB的"瀑布流（Waterfall）"方式对比：瀑布流是顺序请求，先问高价的再问低价的；Header Bidding是并发请求
- 好处：并发请求让所有DSP有公平竞争机会，媒体收入更高（通常提升10-30%）
- 现在很多媒体用**Prebid.js**做Header Bidding

### 4. oCPX的数学原理

**本质：** `bid = tCPA × pCVR / (1+λ)`

- tCPA：广告主设定的目标转化成本
- pCVR：模型预估的转化率
- λ：调节因子，控制出价激进程度

**关键问题：**
- pCVR预估不准怎么办？→ 校准（Calibration），用保序回归或温度缩放
- 冷启动广告没有pCVR怎么办？→ 用行业先验做贝叶斯平滑
- 如何防止预算超支？→ 设置日预算上限+实时监控消耗速度

**扩展：** 业界最新实践是**阿里AliBoost**（你在千问聊过的那个论文），对冷启动广告做分层助推。

### 5. 广告归因（Attribution）怎么做？

**常见模型：**
- 最后点击归因（Last Click）：最常用，但忽略前期渠道贡献
- 首次点击归因（First Click）：强调拉新渠道
- 线性归因：所有接触点均分
- 时间衰减归因：越靠近转化的接触点权重越高
- 数据驱动归因（Shapley Value）：基于博弈论，计算每个渠道的边际贡献

**面试加分：** 提到Shapley Value在归因中的应用，和你之前做的"特征重要度分析"可以用同一套逻辑讲。

### 6. 广告定向（Targeting）有哪些方式？

- 上下文定向（Contextual）：根据页面内容匹配广告
- 用户画像定向（Demographic）：年龄/性别/地域
- 行为定向（Behavioral）：浏览/搜索/购买历史
- 重定向（Retargeting）：对访问过广告主网站的用户再次投放
- 相似人群扩展（Look-alike）：以种子用户为基础，扩展相似人群
- 自动定向（Auto Targeting）：由算法自动学习最优定向组合

## 二、机器学习/深度学习基础题（必考）

### 1. 特征工程相关问题

**Q: 推荐/广告系统中常用的特征有哪些？**

- **用户特征**：用户画像（年龄/性别/地域）、行为序列（近期点击/下载/安装的APP）、长期兴趣偏好
- **广告/商品特征**：品类、价格、大小、历史CTR/CVR、素材特征（图像/文本）
- **上下文特征**：时间、位置、设备类型、网络环境
- **交叉特征**：用户×广告品类、用户×时间等

**Q: 怎么做特征选择？**

你回答这个问题时，可以直接用你的实际经验：**"我在腾讯做过模型深度分析系统，支持单slot、Shapley、梯度三种特征重要度分析方法"**——这是你的亮点，一定要亮出来。

### 2. 模型相关问题

**Q: 为什么推荐系统用Wide & Deep而不是纯Deep？**

Wide侧记忆高频共现模式（如"下载了微信的用户也常下载QQ"），Deep侧泛化到未见过的新模式。两者互补。

**Q: 讲讲MMoE的原理**

MMoE（Multi-gate Mixture of Experts）核心思想：不同任务共享底层的Expert网络，每个任务有自己的Gate来控制不同Expert的权重。解决了多任务学习中"共享底层"带来的任务冲突问题。

**你在腾讯和OPPO都用了MMoE，这个可以展开讲。**

**Q: 对比学习的原理和在推荐中的应用**

- 核心：拉近相似样本，推远不相似样本
- 推荐中的应用：解决长尾/稀疏问题，提升用户/物品表征质量
- 你的做法：多粒度自监督框架（user-user、正负反馈、深浅行为）

### 3. 评估指标

**Q: CTR预估模型的评估指标有哪些？**

| 指标 | 说明 |
|:---|:---|
| AUC | 排序能力，不依赖阈值 |
| LogLoss | 概率校准程度 |
| 校准偏差（Calibration） | 预估均值/实际均值，越接近1越好 |
| GAUC | 按用户分组的AUC均值，更贴近业务 |

**Q: 校准偏差怎么做的？**

**这是你自己的经验（OPPO多位置预估校准），可以直接答：**
"我们当时发现CTR预估偏差在30%以上，通过多位置预估校准，把偏差降到20%以内。做法是：对不同位置的展示做分位置校准，因为顶部位置和底部位置的真实CTR天然不同，需要做分位置归一化。"

## 三、系统设计题

### 1. 设计一个CTR预估系统

**要点：**
- **离线训练**：样本构建（曝光→点击为正样本，曝光无点击为负样本）→ 特征工程 → 模型训练 → 模型评估 → 模型发布
- **在线服务**：接收到请求 → 提取特征 → 模型推理 → 返回pCTR
- **实时更新**：近线训练（Nearline），用实时日志流更新模型参数
- **监控告警**：AUC监控、校准偏差监控、特征分布监控

**面试话术：**
"我在腾讯做过模型深度分析系统，包括特征重要度分析、AUC下钻、指标监控告警，对这个全链路有实操经验。"

### 2. 设计一个广告冷启动系统

**要点：**
- **探索流量池**：划出5-10%流量给冷启动广告
- **先验初始化**：基于品类/开发者历史特征初始化预估
- **UCB/Epsilon-Greedy**：多臂老虎机算法平衡探索与利用
- **渐进式退出**：曝光量达到阈值后逐步过渡到正常竞价
- **冷启动审核**：实时监控冷启动广告的转化率，低于阈值自动下线

### 3. 设计一个广告推荐系统

**架构分层：**
1. **召回层**：从百万级广告库中选出千级候选
   - 倒排索引召回（基于标签/定向条件）
   - 向量召回（DSSM双塔模型）
   - 热度召回（热门广告兜底）
2. **粗排层**：从千级候选压缩到百级
   - 轻量模型（双塔/DSSM）快速打分
3. **精排层**：对百级候选精确排序
   - Deep模型（DeepFM/DIN/MMoE）
   - 多目标建模（CTR+CVR）
4. **重排层**：多样性控制、业务规则过滤
   - 打散（MMR算法）
   - 广告主预算控制

## 四、场景分析题

### 1. CTR涨了但收入降了，怎么分析？

**思路（和你分析OPPO ARPU问题的思路一样）：**
- 拆解指标：`收入 = 曝光 × CTR × 转化率 × 客单价`
- 定位是哪个因子导致的下降
- 可能原因：CTR涨是因为高点击低价值的广告占了更多流量，导致转化率和客单价下降
- 解决方案：引入LTV导向的排序，不只优化CTR

### 2. 广告出价太高，ROI差，怎么优化？

- 分析ROI拆解：`ROI = 收入 / 成本 = (转化数 × 客单价) / (出价 × 展现量)`
- 优化方向：
  - 降低出价（可能损失曝光量）
  - 提升转化率（优化定向/素材）
  - 提升客单价（定向高价值用户）
- 更精细的做法：分用户群设置不同的出价，高价值用户出高价，低价值用户出低价

### 3. 新广告没有曝光，怎么办？

- 检查冷启动策略是否生效
- 确保出价在合理范围内（对比行业均值）
- 检查定向条件是否过于严格（放宽定向）
- 检查素材质量（是否有违规内容）
- 如果以上都正常，可能需要人工干预（Boost曝光）

## 五、数学与统计题

### 1. AB实验相关问题

**Q: 实验需要跑多久？**

- 取决于样本量，用`sample size = (Z_α/2 + Z_β)² × (σ₁² + σ₂²) / δ²`估算
- 至少跑一个完整的业务周期（比如7天，覆盖周末和工作日差异）
- 考虑"新奇效应"（Novelty Effect），新策略刚开始效果可能被高估

**Q: 实验组和对照组怎么分流？**

- 用户级分流（最常用）：按用户ID hash分桶，保证同一用户始终在同组
- 请求级分流：每次请求独立随机，适合流量充足场景
- 广告级分流：按广告分桶，适合广告策略实验

**Q: 多个实验同时跑，流量不够怎么办？**

- 重叠实验框架（Overlapping Experiment）：Google的论文，不同层的实验可以重叠
- 保证不同实验的维度正交（比如一个按用户分，一个按广告分）
- 使用Interleaving实验方法（两种策略交替展示给同一用户），适合排序模型对比

### 2. 偏差与方差

**Q: 什么是偏差-方差权衡？**

- 偏差（Bias）：模型预测值与真实值的差异，高偏差=欠拟合
- 方差（Variance）：不同训练集上模型预测的差异，高方差=过拟合
- 权衡：增加模型复杂度→偏差降低方差升高→找到最佳平衡点

**Q: 如何处理样本不平衡？**

- 正负样本比例1:100甚至更高
- 处理方法：
  - 负采样（下采样）：随机丢弃部分负样本
  - 过采样（上采样）：复制正样本或SMOTE生成
  - 加权损失函数：给正样本更高的权重
  - 使用AUC等不依赖阈值的评估指标
  - 注意：负采样后需要对预估结果做校准（Calibration）

## 六、编程与算法题

### 常见SQL题

**1. 计算每个广告的CTR（点击率）**
```sql
SELECT 
  ad_id,
  SUM(IF(action='click', 1, 0)) / COUNT(DISTINCT impression_id) AS ctr
FROM ad_log
GROUP BY ad_id;
```

**2. 找出每个用户的Top 3广告品类**
```sql
WITH ranked AS (
  SELECT 
    user_id,
    category,
    COUNT(*) AS cnt,
    ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY COUNT(*) DESC) AS rn
  FROM ad_click_log
  GROUP BY user_id, category
)
SELECT user_id, category, cnt
FROM ranked
WHERE rn <= 3;
```

**3. 计算留存率**
```sql
SELECT 
  t1.date,
  COUNT(DISTINCT t1.user_id) AS active_users,
  COUNT(DISTINCT t2.user_id) AS retained_users,
  COUNT(DISTINCT t2.user_id) / COUNT(DISTINCT t1.user_id) AS retention_rate
FROM user_behavior t1
LEFT JOIN user_behavior t2 
  ON t1.user_id = t2.user_id 
  AND t2.date = DATE_ADD(t1.date, INTERVAL 1 DAY)
GROUP BY t1.date;
```

### 常见算法题思路

**1. 广告的CTR预估用什么模型？为什么？**

由浅入深说：
- LR → FM → DeepFM → DIN → DIEN → MMoE → 多目标
- 每个阶段的演进理由要说清楚

**2. 如何处理高维稀疏特征？**

- Embedding：将高维稀疏特征映射到低维稠密向量
- 特征哈希（Feature Hashing）：减少内存占用
- 特征筛选：去掉低频特征

**3. 对广告素材做点击率预估，图像特征怎么做？**

- 预训练CNN提取图像特征
- 和用户行为特征做Cross-Attention
- 多模态融合：文本特征（BERT）+ 图像特征（ViT）+ 行为特征（DIN）

## 七、行为面试题

### 1. 你工作中遇到的最有挑战的事情是什么？

**建议用OPPO的项目讲：**
"在OPPO做多位置预估校准是最有挑战的。不同位置的CTR天然差异很大，如果不做校准，排序会偏向高曝光位置。我们分析了大量数据后发现，位置偏差在不同用户群和不同品类上的表现也不一样。最后我们做了分位置、分用户群的校准策略，把CTR偏差从30%降到20%以内。"

### 3. 为什么从上家公司离职？

"在OPPO做了一年多，感觉应用商店推荐的天花板比较明显，我想往更核心的广告算法方向发展。而且OPPO的广告基础设施相对薄弱，很多从零搭建的工作虽然锻炼人，但也希望能去一个广告体系更成熟的团队深度学习。"
