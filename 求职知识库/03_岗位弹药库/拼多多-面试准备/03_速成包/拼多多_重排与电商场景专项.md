## 一、先把 GMV 拆开——所有电商推荐题的锚点

> **GMV = UV × CTR × CVR × 客单价**（再细分：曝光 UV × 曝光转化率 × 点击转化率 × 件单价 × 件单量）

**这张公式是万能答题框架**。任何"怎么提升 XX"的题，先落到公式的哪一环，再说手段：

| 目标 | 对应环节 | 手段 |
|---|---|---|
| 提升 GMV | 全链路 | 多目标建模（CTR×CVR 联合）而不是单点击 |
| 提升 CTR | 点击率 | 排序模型、兴趣建模、标题/主图多模态 |
| 提升 CVR | 转化率 | ESMM 解 SSB、详情页停留/加购等中间信号、延迟反馈建模 |
| 提升客单价 | 价格/凑单 | 重排阶段做价格带搭配、凑单推荐、满减引导 |
| 提升复购 | 长期 | 长期兴趣 + 生命周期建模、Push/推荐协同 |

**面试话术（可口述）**：
> "我看电商指标习惯先落到 GMV 的分解上。比如'GMV 掉了但 CTR 没掉'，第一反应是拆 UV/CTR/CVR/客单价哪一环掉的，而不是直接调模型。如果是 CVR 掉，会先区分是流量结构变了（曝光人群质量）还是真的转化能力下降——这个可以用分人群的 CVR 曲线看。"

## 二、重排（Rerank）专题 —— JD 第 1 条明写，必须能讲

### 2.1 为什么要重排：精排的天然缺陷

| 精排的问题 | 重排怎么补 |
|---|---|
| **pointwise 打分**：独立评估每个 item，不管彼此 | 重排是 **listwise**，考虑列表内相互影响 |
| 无多样性约束 | 类目/价格带/店铺打散 |
| 无业务约束 | 库存、促销、价格带、去重、疲劳度 |
| 无法建模「看了 A 之后还想看 B」 | 上下文/序列影响建模 |

### 2.2 三代重排方法（按这个脉络讲，显得成体系）

**① 启发式 / 多样性（最基础，也最常用）**

- **MMR**（Maximal Marginal Relevance）：`argmax_i [ λ·sim(q,i) − (1−λ)·max_j∈S sim(i,j) ]`
  - λ 权衡相关性与多样性；**贪心**逐位选，复杂度 O(n²) 但实用
  - 优点：简单可解释、可控；缺点：只考虑两两相似，非最优
- **DPP**（Determinantal Point Process）：用行列式点过程建模「集合的多样性」，核矩阵行列式越大表示越多样
  - 优点：数学上优雅、全局多样性；缺点：核矩阵构造和求解成本高，工业界常用**贪心近似**或滑动窗口 DPP
- **打散规则**：类目/店铺/作者/价格带 硬约束（同店最多 N 个、同类目最多 M 个）——**工业界最常用、最稳**

**② 上下文感知重排（Context-aware / Listwise）**

- 把「已选中的前 k 个 item」作为上下文输入模型，预测第 k+1 个
- 代表：
  - **Seq2Sliding Window**（阿里）：用已选序列 + 候选集做序列生成，评估整个列表收益
  - **PRS / EdgeRec**（阿里）：端上重排，结合用户实时行为
  - **Exact-K / 生成器-评估器**：生成多个候选排列，用评估器打分选最优
- 关键：**训练目标从 pointwise logloss 变成 listwise（整个列表的 GMV/时长）**

**③ 生成式重排（Generative Rerank，前沿）**

- 直接生成最优列表（而非打分排序），如 **Seq2Seq / 强化学习 / 生成式推荐（OneRec 类）**
- 优势：天然端到端优化列表级目标；挑战：推理时延、可控性差、线上稳定性
- **评价口径**：不能只看 CTR，要看列表级指标（人均 GMV、总时长、退出率）

### 2.3 电商重排的特殊约束（这是加分点，很多人漏）

| 约束 | 说明 | 常见做法 |
|---|---|---|
| **库存** | 推荐了但没货 = 白推，伤体验 | 重排后接库存校验/过滤，或在候选阶段就过滤 |
| **价格带** | 全是低价或全是高价都伤转化 | 价格带多样性打散；按用户价格偏好调整分布 |
| **促销/活动** | 大促期要倾斜活动商品 | 业务加权（boost）而非硬插，避免伤自然分发 |
| **去重/疲劳度** | 同一商品反复出现 | 曝光去重、session 内去重、疲劳衰减 |
| **凑单** | 满减场景（满 99 减 20） | 重排阶段做**凑单推荐**：预测还差多少、推合适价格商品 |
| **店铺/品牌打散** | 避免被单一商家霸屏 | 硬约束 + 生态份额上限 |
| **多目标业务权衡** | GMV vs 广告收入 vs 体验 | 重排融合公式里显式加业务项，或用带约束优化（拉格朗日） |

**面试话术（可口述，讲"我没做过电商重排"时的迁移说法）**：
> "电商重排我确实没有直接做过，但**重排的本质问题我处理过**——在腾讯做账号推荐时用 Thompson Sampling 做重排层的多样性探索，核心矛盾是一样的：精排是 pointwise 的，不管列表内相互影响，重排要补的就是'列表级收益 + 业务约束'。方法上我从 MMR 这类启发式打散、到上下文感知的 listwise 都会，电商场景额外要处理的是库存、价格带、凑单、店铺打散这些业务约束——这些是工程规则层，我能快速补。"

⚠️ **诚实红线**：Thompson Sampling 你说的是"类目维度采样做多样性探索"，这是真实的；但**不要说你做过电商的价格带/凑单重排**。说"方法可迁移、业务规则需要补"反而加分。

### 2.4 重排高频追问（防守）

| 追问 | 答法 |
|---|---|
| MMR 的 λ 怎么定？ | 离线网格搜索 + 线上 AB，看相关性与多样性指标的帕累托前沿；不同场景（首页/详情页）分开调 |
| DPP 复杂度高怎么上线？ | 贪心近似；或只在 top-K（如 top 50）窗口内做；或离线预计算部分核 |
| 重排会不会伤害 CTR？ | 会，这是**权衡**。所以重排要单独做 AB，看的是列表级指标（人均 GMV/时长）不是单 item CTR |
| 打散太狠导致相关性掉怎么办？ | 分层打散（先按类目粗打散，再在类目内按分排序）；打散强度做成可配置，按场景调 |
| 重排和精排的特征有什么区别？ | 重排有**列表内上下文特征**（已选 item 的类目/价格分布、当前位置的剩余曝光机会）、**用户 session 内实时行为** |

## 三、电商推荐 vs 内容推荐 vs 广告 —— 差异是必考题

| 维度 | 内容推荐（腾讯/抖音） | 电商推荐（拼多多） | 广告（OPPO/百度） |
|---|---|---|---|
| **核心目标** | 时长、互动、留存 | **GMV/订单**、复购 | eCPM、ROAS |
| **反馈信号** | 点击、时长、点赞（**稠密**） | 点击→加购→下单（**稀疏、漏斗深**） | 点击、转化（稀疏） |
| **样本稀疏性** | 相对轻 | **重**（下单率远低于点击率） | 重 |
| **延迟反馈** | 轻（点击即时） | **重**（下单可能几小时后，退货更久） | 中（转化回传延迟） |
| **物品生命周期** | 内容海量、时效强 | 商品相对稳定但有库存/上下架 | 广告有投放排期 |
| **价格因素** | 无 | **核心变量**（价格敏感、比价、凑单） | 出价是核心 |
| **约束** | 内容安全、多样性 | **库存、履约、促销、店铺生态** | 预算、出价、频次 |
| **多目标冲突** | 时长 vs 互动 vs 留存 | **CTR vs CVR vs GMV vs 客单价** | CTR vs CVR vs 收入 |

**面试话术（"你怎么从内容/广告迁移到电商"）**：
> "最大的差别在**反馈漏斗的深度和稀疏性**。内容推荐点击就是终点，电商点击只是开始——点击到下单还有加购、下单、支付、退货好几层，样本越往后越稀疏，还有延迟反馈问题（用户可能几小时后才下单）。所以电商更依赖 **ESMM 这类全空间多任务建模** 和 **中间信号（加购、收藏、详情页停留）作辅助目标**。这块我在腾讯做 ESMM 时处理过类似结构——把稀疏的深层目标通过 pCTR×pCVR 分解到全空间训练。
>
> 另一个差别是**价格**。内容推荐没有价格这个变量，电商里价格既是特征也是决策变量，会引出价格带多样性、凑单、比价这些独特问题。这块是业务规则层，我判断上手快。"

## 四、用户长短期兴趣建模（JD 第 3 条明写）

### 4.1 为什么长短期要分开

- **长期兴趣**：稳定偏好（品类、价格带、品牌）→ 决定"大方向对不对"
- **短期兴趣**：session 内意图（刚搜了什么、刚点了什么）→ 决定"当下推得准不准"
- 只推长期：不响应实时意图；只推短期：越推越窄（信息茧房）

### 4.2 模型演进（按这条线讲）

| 模型 | 核心 | 解决什么 |
|---|---|---|
| **DIN** | 对候选 item 做 **attention** 到用户历史行为 | 用户兴趣不是固定向量，随候选变化 |
| **DIEN** | GRU 抽取兴趣**演化** + AUGRU（带 attention 更新门） | 兴趣是会变的，要建模演化 |
| **DSIN** | 按 session 分段（session 内同质、间异质） | session 内是短期意图 |
| **SIM / ETA** | 两阶段：先检索（GSU）再精确建模（ESU） | 长序列（千级）建模的**工程可行性** |
| **MIND / ComiRec** | **多兴趣**向量（胶囊网络/多通道） | 用户兴趣本就多元，单向量表达力不够 |

### 4.3 你的迁移弹药（真实且对口）

> "长短期兴趣我在腾讯做账号推荐时直接处理过：用户既有稳定的长期兴趣（关注了哪些作者、长期消费的品类），也有 session 内的即时意图。我们的做法是**分桶**——长期兴趣走用户画像 + 长期行为序列的 embedding，短期走实时行为序列；召回层两边各出一路，再在融合时按用户活跃度调权。
>
> 多兴趣这块我用过 **Thompson Sampling 做探索**，本质是在解决单向量表达的局限——你说的 MIND 多兴趣向量是表征层的解法，TS 是策略层的解法，两者可以叠加：多兴趣向量提供更丰富的候选，TS 决定探索哪个。"

⚠️ 诚实：TS 是你真实做过的；DIN/DIEN 如果你没实操过，说"原理清楚、没在生产上训过"。

## 五、CVR 建模与延迟反馈（电商必考）

| 问题 | 解法 |
|---|---|
| **SSB（样本选择偏差）** | ESMM：pCTCVR = pCTR × pCVR，全空间训练（你在腾讯做过的就是这个） |
| **数据稀疏（DS）** | 共享 embedding、迁移学习 |
| **延迟反馈** | 假负样本问题（还没转化被标成负）→ **DFM**（延迟反馈模型，建模转化延迟分布）、**ESDF**、或按"观察窗口"截断 + 重要性加权 |
| **CVR 预估偏高/偏低** | 校准（保序回归、PCOC 监控）；负采样还原 |
| **退货/取消** | 建模"净 GMV"而非"下单 GMV"，或用真实成交作延迟正样本 |

**面试话术**：
> "CVR 的两个经典坑——SSB 和数据稀疏——我在腾讯用 ESMM 处理过：把 CVR 放到全曝光空间训练，用 pCTR×pCVR 分解，避免只在点击样本上训练导致的选择偏差。延迟反馈这块我理解的标准做法是建模转化延迟分布（DFM 那类），或者用足够长的观察窗口 + 重要性加权来缓解假负样本。生产上我做过的是**校准**：监控 PCOC，用保序回归校准，保证预估值能用于出价/融合。"

## 六、面试 Q&A（12 组，第一人称口述）

**Q1：怎么提升 GMV？**
> "先拆 GMV = UV × CTR × CVR × 客单价。四个环节分别看：UV 靠流量分配和入口优化；CTR 靠排序模型和兴趣建模；CVR 靠 ESMM 类全空间建模 + 中间信号；客单价靠重排做凑单和价格带搭配。实际我会先看哪一环是当前瓶颈——比如 CVR 明显低于行业，那投入 CVR 建模性价比最高。"

**Q2：重排为什么不能直接放在精排里做？**
> "因为精排是 pointwise 的，逐个打分；重排要处理列表内的相互影响和业务约束，本质是 listwise 问题。工程上也是分开的——精排要扛大候选集低延迟，重排只在 top-N 上做，可以用更重的模型。"

**Q3：MMR 和 DPP 选哪个？**
> "工业界我倾向先用 MMR：简单、可解释、λ 好调、线上稳。DPP 数学上更优雅、全局多样性更好，但核矩阵构造和求解成本高，一般做贪心近似或在滑动窗口内用。如果业务对多样性要求特别高、且有工程资源，才上 DPP。"

**Q4：电商推荐怎么处理库存？**
> "三层：候选生成阶段过滤无货；精排把库存状态做特征（低库存降权）；重排后接一次硬校验。另外要处理'超卖'——大促期库存变动快，需要近实时库存同步。"

**Q5：为什么电商 CTR 模型的效果不如内容推荐好评估？**
> "因为 CTR 不是终点。推了点击但不买的商品，CTR 很好看但 GMV 没涨。所以电商必须上多目标，把 CVR、加购这些深层信号一起建模，评估看 GMV 而不是单 CTR。这也是为什么我看指标一定先看分解。"

**Q6：你怎么看"重排会伤害 CTR"？**
> "这是必然的权衡，重排本来就是在相关性和多样性/业务约束之间做交换。所以重排的价值不能用 CTR 衡量，要用列表级指标——人均 GMV、人均订单、session 时长、退出率。上线必须单独 AB。"

**Q7：多目标在电商里怎么融合？**
> "两种：一是加权求和（如 score = CTR^a × CVR^b × 价格因子^c），权重离线网格/贝叶斯搜参 + 线上 AB；二是带约束优化（在 CTR 不降的前提下最大化 GMV），用拉格朗日或对偶。实际工业界第一种更常见，因为可控、好调。"

**Q8：电商冷启动怎么做？**
> "分三层：用户冷启动靠人口属性 + 设备 + 地域 + 站外行为做群体画像，配合 bandit 快速探索；商品冷启动靠内容理解（标题/类目/图像多模态 embedding）+ 少量流量探索 + 相似商品迁移；系统冷启动靠规则/热度兜底。"

**Q9：价格敏感用户怎么建模？**
> "价格既做特征（历史客单价、价格偏好分档、对促销的响应率），也要在重排里用（价格带分布匹配用户偏好）。另外促销敏感度是单独维度——有些用户只对满减有反应，可以建模'促销响应率'。"

**Q10：你没做过电商，怎么保证快速上手？**
> "算法链路是通用的——召回、粗排、精排、重排、重排的业务规则层。我做过全链路（腾讯）、做过 CTR/CVR 建模和出价（OPPO/百度），缺的是电商特有的业务规则：库存、履约、促销节奏、价格带策略。这些是规则和经验层，我认为几周能补上，而且我习惯先把指标体系（GMV 分解）理清楚再动手。"

**Q11：AB 实验 GMV 涨了但复购跌了，怎么判断？**
> "先看是不是'透支'——短期用促销/爆款拉动了 GMV 但伤了长期体验。要拆新客/老客、看 cohort 留存曲线、看复购周期是否拉长。如果确认是透支，说明目标函数少了对长期价值的约束，需要在多目标里加长期项或做长期 holdout 实验。"

**Q12：为什么想来拼多多？**
> "两点：一是电商是算法价值最直接的场景——推荐结果直接对应 GMV，反馈闭环短，我喜欢这种'改一行模型能看到钱'的感觉；二是拼多多的量级和低价心智带来的问题独特性（价格敏感、供应链效率）是别的平台没有的，这对我有吸引力。"（⚠️ 别提加班、别提前东家负面）
