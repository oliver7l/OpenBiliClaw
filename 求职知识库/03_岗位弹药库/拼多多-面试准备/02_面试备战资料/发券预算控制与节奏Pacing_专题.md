# 发券预算控制与节奏 Pacing：工业界做法完整专题

> 适用：拼多多 / 美团 / 阿里 / 腾讯 推荐算法、增长算法、智能营销面试
> 前置：本专题是「发券如何融入推荐系统」的姊妹篇，专注**预算控制 / 发券节奏**这一层。
> 核心命题：**券不能超预算（资损），也不能一小时烧光（错失全天优质流量）**——工业界怎么同时解决这两个相反的问题。

---

## 〇、为什么单独讲预算控制（问题定义）

发券预算控制要同时防两种失效，且二者方向相反、必须一起解：

- **超预算（资损）**：日券预算 1 万，上午就花光，下午空白、且可能触发财务红线。
- **烧太快（错失优质流量）**：同样花光，但全砸在早高峰低质流量；该在晚高峰转化的高价值用户没券可领，整体 ROI 变差。

朴素方案「每小时花 `预算 ÷ 24`」为什么不行（CalibreOS 面试体系总结的 3 个坑）：

1. **流量供给不均匀**：白天晚 8–10 点流量是凌晨的 5–10 倍，按比例均摊→凌晨有钱花不出去、晚高峰预算不够被迫高价抢量。
2. **用户价值分布不均匀**：零售转化集中在晚上、B2B 在工作时段；ASAP（前置花完）和 SMOOTH（均匀铺）优化的是不同目标，选错损失 10–30% 投放价值。
3. **Pacing 与出价耦合**：现代自动出价（Google Smart Bidding / Meta Advantage+）里出价由 auto-bidder 按 tROAS 生成，pacing 必须**嵌进出价生成器**，不能当事后补丁。

数学形态：把发券系统当成一个**控制对象（plant）**——输入是发券决策、输出是累计花费，用反馈控制逼近一条"理想消耗曲线"。

---

## 一、第一层决策：选节奏模式 SMOOTH vs ASAP

| 模式 | 含义 | 适用 |
|---|---|---|
| **SMOOTH（均匀铺）** | 全天按理想曲线 `r(t) = G·t/T` 平滑消耗 | 品牌曝光、大日预算、需触达均匀（拼多多日常智能券、合约式保量） |
| **ASAP（尽快花）** | 预算尽早花完，抓住早期高价值用户 | 转化窗口短、直接响应、大促某时段抢量 |

对发券场景：日常智能券走 **SMOOTH**（别一下烧光、也别半夜空白）；大促冲量某时段可切 ASAP。这是节奏控制的**第一层决策**，必须先定。

---

## 二、控制器核心：PID 跟踪理想消耗曲线

工业界最主流（CyberAgent/ABEMA、Snap、Roku、Twitter、ShareChat 都这么干）。把发券系统建模为：

```
观察量 N(t) = 累计已发券成本
目标值 r(t) = G · t / T        （G=总预算，T=周期，线性参考轨道）
误差   e(t)  = 实际 − 理想      （正=花太快，负=花太慢）
控制量 u(t) → 经 sigmoid 压到 [0,1] → 变成"参与发券的概率"或"出价乘数" α
```

工业里几乎都用 **PI 控制（丢掉 D 项）**——D 项放大观测噪声，发券是离散请求系统，留 D 反而抖（CyberAgent 明确"迷わず切る"）。

**CyberAgent/ABEMA 的两个关键工程技巧（可直接引用）：**
- **对数比尺度不变误差** `e = −log(N(t) / r(t))`：让 G=10³ 和 G=10⁶ 的券活动能用**同一套 PI 增益**跑，不用每个活动重新调参（消除规模依赖）。
- **连续值→0/1 桥接**：用 `sigmoid + Bernoulli 抽样`，把"发券概率 0.5"变成真正"一半请求发、一半不发"，而不是 On/Off 硬切（硬切在请求洪峰时根本控不住）。

**数字例子（你最关心的"别一下烧光"）：**
- 日券预算 `G = 10,000` 元，按 SMOOTH，`r(t=12h) = 5,000`。
- 早高峰流量大、Persuadable 用户多，到中午**实际已花 8,300**（超了 3,300）。
- `e = 8300 − 5000 = +3300 > 0` → 控制器输出 `α < 1`，下午只以 `α` 比例参与发券请求。
- 剩余 1,700 元被强制拉伸到 12 小时里慢慢放，避免"上午烧光、下午空白"。

## 三、两种执行机制：出价修饰 vs 概率节流

控制器算出 `α` 后怎么落地，工业界两条路（CalibreOS 强调：**不是可互换，是设计选择**）：

| 机制 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **Bid Modification / Bid Shading**（出价修饰） | 出价乘 `α`，不改是否参与 | 保住拍卖效率、不影响参与分布 | 反馈慢；小预算初始值错会瞬间花完 |
| **Probabilistic Throttling**（概率节流） | 不改出价，按 `α` 随机丢弃一部分发券机会 | 简单、>100 万 QPS 也便宜；小广告主最爱 | 扭曲参与分布，但工程代价低 |

**对发券的取舍**：券是"参加就发"，没有拍卖出价概念，所以发券场景天然更适合 **概率节流**（按 `α` 决定这条请求给不给药券资格）。
**Yahoo Smart Pacing（KDD'15）现成模板**：把请求按 pCTR 分层，每层一个节流率，效果好的层节流率低（多发）、效果差的层节流率高（少发），用残差反馈调各层速率。Facebook / Google / LinkedIn / Yahoo 的概率节流（arXiv 2207.04690 综述）是广告界最广泛采用的预算控制方法。

## 四、对偶视角：λ 是预算的"影子价格"

学术与工业统一的框架（CalibreOS、微软 Bing 论文 Gaitonde et al.），把预算控制写成约束优化：

```
max Σ v_i · x_i      s.t.   Σ c_i · x_i ≤ B
x_i ∈ [0,1] = 第 i 次请求的发券参与概率
```

对偶变量 `λ_c`（每个预算一个）就是**预算约束的影子价格**，直接当出价乘数：

```
bid_effective = bid_raw / (1 + λ_c)
```

- `λ_c → 0`：预算宽松，随便发；
- `λ_c 大`：预算紧，节流。
- 控制器用**在线次梯度下降**实时解 `λ_c`（观察到花超了就调大 λ）。

**微软 Bing 理论保证**：Gaitonde et al. 证明这类梯度 pacing 的 liquid welfare ≥ 最优的 1/2，**且不需要收敛**就能保证（绕开均衡计算的复杂度障碍）——这解释了为什么工业界敢用"边跑边调"的简单控制器。

## 五、防"一下烧光"的硬保险（BAAI/百度 AAAI'24）

这是"不要一下子消耗光"最直接对应的工程（来自合约广告《Percentile Risk-Constrained Budget Pacing》，虽是广告但可平移到券）。平滑释放的主要挑战是**释放过快**（消耗不可回撤；释放过慢可后期加速补救），所以设计重点压在"防爆量"：

1. **止血控制（circuit breaker）**：一旦线上已"爆量"，梯度更新要多次才压得住、小时预算早没了。额外加一个**通用通过率硬控，把释放速度封顶在 2 倍**，先止损失血，再让对偶因子慢慢回正。
2. **冷启动小流量试探**：刚上线的前几分钟，通过率设 **10%** 试水，防初始值不准直接爆量。
3. **梯度裁剪（静态+动态）**：PID 步长太大就抖、太小就慢。动态梯度裁剪按"当前百分位位置"算上下界——百分位 0.9→0.8 时参竞率直接翻倍，所以靠近 1 时步长必须更小（可变步长）。
4. **风险百分位约束**：把对偶因子锁在安全百分位内（如 top 5% 优质流量参竞），超过就有爆量风险，pacing 主动压低。
5. **硬停 vs 软停**：到 100% 预算是硬停（简单但有"午夜悬崖"）还是软停（继续以低 α 投到日末，容忍 2–5% 超投，平台当 goodwill 吸收）——多数平台选软停保平滑。

## 六、Snap 迟滞控制器（WWW'26 最新工业证据）

**论文**：*Feedback Control for Small Budget Campaigns in Advertising*（WWW Companion 2026，Snap Inc.）。
**做法**：把 **bucketized hysteresis（分桶迟滞）+ proportional feedback（比例反馈）** 组合，提供稳定且自适应的花费控制；并给出参数选取的分析框架，可个性化跟踪花费速率。
**真实拍卖实验结论**（可直接背的数字）：
- pacing error 降低 **13%**；
- **λ 波动率降低 54%**（λ-volatility reduction）；
对比的是 legacy 变量步长 pacing 系统。特别适合**小预算活动**——这也正是发券场景里"单用户/单商品日券额度小"的典型情况，迟滞控制能避免一会儿猛发一会儿停。

## 七、券补贴专属：预算约束下的分配与 RL（发券真正的落点）

前面是"控制花速"，这一层是"在预算内决定给谁发、发多少"——和发券专题里 MCKP 那节是同一件事，但工业界已经上强化学习：

- **阿里 BCORLE(λ)（NeurIPS'21，淘宝特价版）**：发券建模成 **CMDP（约束马尔可夫决策过程）**，目标最大化留存、约束不超预算。`λ` 是预算的"价格"。关键创新 **λ-Generalization**——把 λ 当状态特征喂进策略，预算一变**不用重训模型**（传统方法每改一次 λ 要重学整个策略，淘宝 2M 用户 × 13 种券 × 7 天周期根本跑不动）。落地：**ROI 比传统 uplift 模型高 13–15%**，训练从 2.18h 降到 26 分钟。
- **蚂蚁 AIM（Ant + 清华）**：Offline Constrained Deep RL，解决"Memory Wall"（存上千个策略模型不现实）。核心：任何混合策略都能表示成 **m+2 个基策略的凸组合**，只存常数个。用支付宝 420 万样本验证：**周 DAU +0.6%、券成本 −0.8%**；且发现"短期指标严重低估激励价值"——1 天 DAU 只 +32%，7 天 DAU 高达 +82%（证明要按长期价值发券，而非只看当天转化）。
- **蚂蚁 Model-based CMDP（CIKM'19）**：二分搜索 + 模型规划解对偶，利用单调性，不每次重训。
- **美团 CoLA（SIGIR'26）**：*Optimizing Marketing Subsidies via Counterfactual Learning with Asymmetric Reward*。两阶段：先用订单信息+条件独立粗估"期望最小补贴阈值"，再用**非对称损失函数**精修；预算约束下按 **Sharpe ratio（夏普比率）优先**排候选定最终发券策略。线上 A/B 总利润与增量杠杆比最优。
- **滴滴 DiDi Food 智能补贴**：架构 = 增量预估 + 分发策略。增量预估用 **LightGBM uplift**（T-Learner 思路），离线评估 **AUUC**；样本构建时**剔除被线上模型干预后的样本**（否则离线评估失真）。分发用 贪心 / 整数规划 / RL 在约束下求全局最优。明确把补贴问题拆成"增量预估（因果）" + "约束下分配（运筹）"两个子问题。
- **E3IR（KDD'25）**：端到端可微 MCKP，把"给谁发、发多少档"建模成多选择背包，用单调性/平滑性域约束让面额跟着梯度走（接发券专题 A2/E3IR）。

## 八、反作弊 / 套利防控（预算护栏的最后一公里）

预算控制不只是"花得匀"，还要"花得值"——防薅是硬约束：

- **静态规则漏洞**：专利 CN119941323A 指出传统阶梯补贴易被套利（短时间频繁下单、设备切换攫取补贴）；需要实时异常检测。
- **动态博弈 + RL + 联邦异常检测**：该专利用企业智能体 ↔ 用户智能体动态博弈对抗学习，跨机构联邦训练异常检测模型，对抗训练识别恶意套利，调补贴发放。
- **因果去噪**：上专题讲到 HMUM 的 downlift（发券反而掉转化的人）+ RDD 断点回归去核销噪音，是预算不被"羊毛党"吃掉的关键。

## 九、落到拼多多发券：硬约束 + 节奏串接（完整链路）

把上面所有层串回推荐系统（接发券专题 §2 七环节改造的 2.6 预算 Pacing 节）：

```
精排估 (pCTR_nat, uplift, value)
        ↓
机制层【券分配】MCKP / RL（BCORLE / AIM / CoLA 思路）
        ↓   选出"给谁发、发哪档"，不超 15%/70%/80% 硬上限
预算 Pacing 层：把当天该发的券，按 SMOOTH 曲线 + PID(α) + 概率节流 摊到 24h
        ↓
止血 / 冷启 / 梯度裁剪：防某小时爆量
        ↓
曝光
```

拼多多的硬约束（上轮讲的）就是 Pacing 层的**绝对天花板**：单日有效券 ≤ 推广费 15%、单张 ≤ 售价 70%、单品日券 ≤ 推广费 80%。PID 的 λ 越接近上限越大、发券越克制；概率节流决定每个请求"给不给药券资格"。

## 十、面试答题模板

**30 秒版（背这个）：**
> 发券预算控制要防"超预算"和"烧太快"两种失效。工业界分两层：分配层用 MCKP/CMDP+RL（阿里 BCORLE、蚂蚁 AIM、美团 CoLA）在预算内决定给谁发哪档；节奏层用 Budget Pacing 把券摊到全天——核心是 PID 控制器跟踪理想消耗曲线 `r(t)=G·t/T`，输出 `α` 通过概率节流（不改出价、只随机丢发券机会）落地；对偶视角 `λ` 当预算影子价格在线调；再加止血控制（释放速度封顶 2 倍）、冷启动 10% 试探、梯度裁剪三道保险防爆量。Snap WWW'26 用 bucketized hysteresis 把 λ 波动率降 54%。拼多多 15%/70%/80% 是 Pacing 硬天花板。SMOOTH 均匀铺防烧光，大促某时段可切 ASAP。

**2 分钟版（含公式与论文名）：**
> 发券预算控制要同时解决超预算和烧太快。第一层先选节奏：SMOOTH（r(t)=G·t/T 均匀铺，日常券）vs ASAP（大促抢量）。第二层控制器：把发券当 plant，PID 跟踪理想消耗曲线，误差 e=实际−理想，工业用 PI（丢 D 项），CyberAgent 用对数比尺度不变误差+N(t)/r(t) 让不同规模活动共用一套增益，sigmoid+Bernoulli 把 α 变 0/1 决策。第三层执行：概率节流（Facebook/Google/Yahoo 主流，不改出价只随机丢机会）比 bid shading 更适合券场景。对偶视角 λ 是预算影子价格，bid_eff=bid/(1+λ)，在线次梯度下降，微软 Bing 证明 liquid welfare≥1/2 且不需收敛。第四层防烧光保险：百度 AAAI'24 止血控制封顶 2 倍 + 冷启 10% + 动态梯度裁剪；Snap WWW'26 bucketized hysteresis 把 λ 波动率降 54%、pacing error 降 13%。第五层分配：阿里 BCORLE(λ) 用 λ-Generalization 不重训、ROI +13~15%；蚂蚁 AIM 用 m+2 基策略解 Memory Wall、周 DAU +0.6% 成本 −0.8%；美团 CoLA 非对称奖励 + Sharpe 优先；滴滴增量预估(LightGBM uplift, AUUC) + 分发(贪心/整数规划/RL)。最后拼多多 15%/70%/80% 是 Pacing 硬上限。

## 十一、易错点自查（7 条坑）

1. ❌ 把"每小时等额"当 pacing → 流量/价值不均匀会翻车。
2. ❌ 以为 AUC 能评估 pacing → pacing 看的是消耗曲线贴合度，不是排序指标。
3. ❌ 节流和出价修饰混为一谈 → 券场景无出价，选概率节流。
4. ❌ 只估 uplift 不控制 λ → 预算会超；λ 必须在线随花费反馈。
5. ❌ 没有止血/冷启 → 初始值错就瞬间爆量烧光。
6. ❌ 分配与 pacing 两段甩锅 → 美团 AAAI'23 证明要桥接成一体（Direct Heterogeneous Causal Learning）。
7. ❌ 忽视反作弊 → 静态规则被套利，需动态博弈+RL+联邦异常检测 + downlift/RDD 去噪。
