## C-1 LC 3 无重复字符的最长子串 ⭐⭐⭐（真考 4 次，最高频）

**出处**：S5 一面、S2 二面、S8 一面、S11 0812 二面。S8 原话："**面试官要求 O(n)，写 O(n²) 会被打回**"。

**问题**：给定字符串 `s`，找出不含重复字符的最长连续子串的长度。

### 标准解（滑动窗口 + 哈希记录位置，O(n)）

```python
def lengthOfLongestSubstring(s: str) -> int:
    last = {}          # 字符 -> 最近一次出现的下标
    left = 0
    ans = 0
    for right, ch in enumerate(s):
        if ch in last and last[ch] >= left:
            left = last[ch] + 1      # 窗口左边界跳到重复字符的右边
        last[ch] = right
        ans = max(ans, right - left + 1)
    return ans
```

- **时间复杂度** O(n)（每个字符进/出窗口各一次）；**空间** O(min(n, 字符集))。
- **两个易错点**：① 判断重复必须带 `last[ch] >= left`，否则会把窗口外的旧位置误判为重复（这是 O(n²) 心态写出来的最常见 bug）；② 更新答案要在调整 `left` **之后**。

### 追问 1：为什么用「记录上一次位置」而不是「哈希 set 模板」？

用 `set` + `while s[left] in window: remove(s[left]); left += 1` 也是 O(n) 均摊，但**内层 while 的写法面试官会追问"最坏是不是 O(n²)"**——其实是 O(n)（left 最多移动 n 次），但你要能答清楚。用「记位置」写法内层无循环，更干净，推荐主答这个。

### 追问 2（真考变体）：如果字符串首尾可以相连，最长是多少？

即**环形字符串**上的最长无重复子串。解法：令 `t = s + s`，在 `t` 上跑滑动窗口，但**窗口长度上限为 n**（不能超过原串一圈）。

```python
def maxLenCircular(s: str) -> int:
    n = len(s)
    if n == 0: return 0
    if len(set(s)) == n: return n        # 全不重复，答案就是 n
    t, last, left, ans = s + s, {}, 0, 0
    for right, ch in enumerate(t):
        if ch in last and last[ch] >= left:
            left = last[ch] + 1
        last[ch] = right
        if right - left + 1 > n:         # 环形限制：窗口不能超过 n
            left = right - n + 1
        ans = max(ans, right - left + 1)
    return ans
```

**口诀**：环形 = 拼接 + **窗口设上限 n**。少了这个上限就会跑到 2n。

### 追问 3：如果要返回子串本身而不是长度？

滑动窗口里同时维护 `start`（当前最优窗口起点）+ `best_len`，循环中若刷新了就记 `start = left`，最后 `return s[start:start+best_len]`。

## C-2 蓄水池抽样（Reservoir Sampling）⭐⭐

**出处**：S12 面经熊《一面凉经》——候选人原话"**没见过这种题型，崩**"。这是**"会的人 3 分钟，不会的人直接死"**的题，性价比极高。

**问题**：给你一个长度未知的数据流（只允许遍历一次），从中**等概率**抽取 m 个元素。

### 标准解

```python
import random

def reservoir(stream, m: int):
    """stream: 可迭代的数据流（长度未知）；返回等概率抽中的 m 个元素"""
    res = []
    for i, x in enumerate(stream):        # i 从 0 开始
        if i < m:
            res.append(x)                 # 前 m 个直接进池
        else:
            j = random.randint(0, i)      # 在 [0, i] 中取一个随机下标
            if j < m:                     # 概率 m/(i+1) 替换池中元素
                res[j] = x
    return res
```

### 为什么每个元素被抽中的概率都是 m/n？（必须能推）

- **前 m 个元素**：第 `i`（≥m）个元素到来时，它被替换掉的概率是 `m/(i+1)`，**不被替换**的概率是 `i/(i+1)`。所以在全部 n 个元素走完后，某个初始元素留在池中的概率为

  `∏_{i=m}^{n-1} (i/(i+1)) = m/n`。

- **第 i（i≥m）个元素**：它进来时被选中入池的概率是 `m/(i+1)`；之后不被后续元素替换掉的概率是 `∏_{j=i+1}^{n-1} (j/(j+1)) = (i+1)/n`。相乘 = `m/(i+1) × (i+1)/n = m/n`。

结论：**所有元素被抽中的概率都是 m/n，与元素位置无关。**

### 追问 1：m=1 的简化版？（最常考）

```python
def random_one(stream):
    choice = None
    for i, x in enumerate(stream):
        if random.randint(0, i) == 0:      # 概率 1/(i+1)
            choice = x
    return choice
```

### 追问 2：为什么要用它？

不知道总量 n、不能二次遍历、不能全存进内存的场景：**海量日志里随机抽一批样本**、**大文件随机取 k 行**、**流式数据的均匀采样**。这是"概率等价"的采样，不是"前 m 个"（前 m 个有偏）。

### 追问 3：加权蓄水池抽样（A-Res 算法）？

每个元素权重 `w_i`，抽 m 个的概率正比于权重：对第 i 个元素取 key = `u^(1/w_i)`（u ~ U(0,1)），维护一个大小为 m 的**最小堆**，最后堆里就是结果。用于"按曝光量/热度加权采样"。

## C-3 打印 1~N 位所有数字（大数用字符串表示）⭐⭐

**出处**：S12 面经熊（魏无忌·二面）。

**问题**：输入数字 n，按顺序打印出从 1 到最大的 n 位十进制数。例如 n=3，打印 1~999。

> **陷阱**：n 可能很大（比如 n=100），`int` 一定溢出。**这题考的就是"你意识到不能用 int"**——第一句话就要说出来。

### 解法一：字符串模拟大数加法（推荐，最稳）

```python
def print_max_n_digits(n: int):
    if n <= 0: return
    num = ['0'] * n                       # 数字按位存，低位在右
    while not increment(num):
        print(''.join(num).lstrip('0') or '0')

def increment(num: list) -> bool:
    """自增；溢出（全 9 再加）时返回 True"""
    carry = 1
    for i in range(len(num) - 1, -1, -1):  # 从低位到高位
        if carry == 0:
            break
        total = int(num[i]) + carry
        if total >= 10:
            if i == 0:                     # 最高位也进位 → 溢出
                return True
            num[i] = str(total - 10)
            carry = 1
        else:
            num[i] = str(total)
            carry = 0
    return False
```

### 解法二：递归全排列（更短，本质等价）

n 位数字 = n 个位置，每个位置可放 0~9 的**全排列**，递归即可：

```python
def print_max_n_digits(n: int):
    if n <= 0: return
    buf = ['0'] * n
    def dfs(idx):
        if idx == n:
            s = ''.join(buf).lstrip('0')
            if s: print(s)
            return
        for d in range(10):
            buf[idx] = str(d)
            dfs(idx + 1)
    dfs(0)
```

- **复杂度**：共 10^n 个数，每个数 O(n) 位 → O(n · 10^n)。
- **追问**：面试官可能让你"判断是不是回文大数""大数加法/乘法怎么实现"——**统一心法：用字符串（或数组）存每一位，从低位往高位模拟进位**。

## C-4 LC 73 矩阵置零（O(1) 空间）⭐

**出处**：S6 二面。

**问题**：若矩阵中某元素为 0，则将其所在行和列所有元素都置 0。

> **陷阱**：你发现一个 0 就立刻把行列清零，会把"原本不是 0 的位置"也当成 0 的源头，**结果整张矩阵全变 0**。必须"先标记、后清除"。

### 标准解（用首行首列当标记位，O(1) 额外空间）

```python
def setZeroes(matrix: list) -> None:
    R, C = len(matrix), len(matrix[0])
    first_row_zero = any(matrix[0][c] == 0 for c in range(C))
    first_col_zero = any(matrix[r][0] == 0 for r in range(R))

    # 用第一行/第一列记录"该行/该列是否需要清零"（标记位提前存好，所以不冲突）
    for r in range(1, R):
        for c in range(1, C):
            if matrix[r][c] == 0:
                matrix[r][0] = 0
                matrix[0][c] = 0

    for r in range(1, R):
        for c in range(1, C):
            if matrix[r][0] == 0 or matrix[0][c] == 0:
                matrix[r][c] = 0

    if first_row_zero:
        for c in range(C): matrix[0][c] = 0
    if first_col_zero:
        for r in range(R): matrix[r][0] = 0
```

- **为什么不会冲突**：第一行/第一列的"自己是否要清零"在开头就用两个 bool 存下来了，所以它们的格子可以放心当标记位。
- **追问**：允许 O(m+n) 空间怎么做？（两个 bool 数组，思路同上但更简单）；如果矩阵元素是浮点数、要判断"是否等于 0"怎么办？（用 `abs(x) < eps`，别用 `==`）

## C-5 从前序 + 中序构建二叉树，再层序打印验证 ⭐

**出处**：S7 一面（Temu 用户增长）。

**问题**：给定前序遍历和中序遍历，构建二叉树，然后层序打印验证。

```python
from collections import deque

class TreeNode:
    def __init__(self, val): self.val, self.left, self.right = val, None, None

def build(pre: list, ino: list) -> TreeNode:
    idx = {v: i for i, v in enumerate(ino)}     # 中序值 -> 下标，O(1) 定位根
    def helper(pl, pr, il, ir):
        if pl > pr: return None
        root_val = pre[pl]
        k = idx[root_val]                        # 根在中序中的位置
        left_size = k - il                       # 左子树节点数
        node = TreeNode(root_val)
        node.left = helper(pl + 1, pl + left_size, il, k - 1)
        node.right = helper(pl + left_size + 1, pr, k + 1, ir)
        return node
    return helper(0, len(pre) - 1, 0, len(ino) - 1)

def level_order(root: TreeNode) -> list:
    if not root: return []
    q, res = deque([root]), []
    while q:
        node = q.popleft()
        res.append(node.val)
        if node.left: q.append(node.left)
        if node.right: q.append(node.right)
    return res
```

- **核心不变量**：前序的第一个 = 根；在中序里找到根，**左边是左子树、右边是右子树**；两段的长度对上前序的区间。
- **复杂度**：O(n)（用哈希表定位根，否则 O(n²)）。
- **追问 1**：为什么**只有前序 + 中序**能唯一确定？前序 + 后序行不行？（不行，无法区分只有一个孩子的左右；除非是**满二叉树**。）
- **追问 2**：如果树里有**重复值**怎么办？（哈希表存"值 → 下标列表"或者用下标定位，重复值会让区间划分歧义，需按题目约定）
- **追问 3**：**不建树**直接输出后序？（递归区间时先左后右再打根即可——这是同一道题的高频变体）

## C-6 LC 5 最长回文子串 ⭐

**出处**：S2 三面。

```python
def longestPalindrome(s: str) -> str:
    if not s: return ""
    start, end = 0, 0
    def expand(l, r):
        while l >= 0 and r < len(s) and s[l] == s[r]:
            l, r = l - 1, r + 1
        return l + 1, r - 1          # 返回回文区间
    for i in range(len(s)):
        l1, r1 = expand(i, i)        # 奇回文：中心是 1 个字符
        l2, r2 = expand(i, i + 1)    # 偶回文：中心是 2 个字符
        if r1 - l1 > end - start: start, end = l1, r1
        if r2 - l2 > end - start: start, end = l2, r2
    return s[start:end + 1]
```

- **中心扩展** O(n²)，空间 O(1)。**为什么必须有奇偶两次扩展**：`abba` / `aba` 两种中心形态，漏一个就错。
- **追问 1**：有 O(n) 解法吗？（**Manacher**：插入 `#` 统一奇偶 + 维护最右回文边界 `r` 和中心 `c`，利用回文对称性复用半径，每个字符最多扩展一次 → O(n)。能说出思想和复杂度即可，手写不多见）
- **追问 2**：改成求**最长回文子序列**（不要求连续）？（DP，`dp[i][j] = dp[i+1][j-1] + 2 if s[i]==s[j] else max(dp[i+1][j], dp[i][j-1])`）

## C-7 LC 15 三数之和 ⭐

**出处**：S5 二面。

```python
def threeSum(nums: list) -> list:
    nums.sort()
    res, n = [], len(nums)
    for i in range(n - 2):
        if nums[i] > 0: break                    # 剪枝：最小的都 > 0，不可能凑 0
        if i > 0 and nums[i] == nums[i - 1]: continue   # 跳过重复的"第一个数"
        l, r = i + 1, n - 1
        while l < r:
            total = nums[i] + nums[l] + nums[r]
            if total == 0:
                res.append([nums[i], nums[l], nums[r]])
                while l < r and nums[l] == nums[l + 1]: l += 1   # 跳过重复左
                while l < r and nums[r] == nums[r - 1]: r -= 1   # 跳过重复右
                l, r = l + 1, r - 1
            elif total < 0: l += 1
            else: r -= 1
    return res
```

- **复杂度** O(n²)；**去重是这题的全部难点**：排序后在**三个位置**分别跳重复（i、l、r），漏一处就出重复三元组。
- **追问**：三数之和**最接近 target**？（双指针，维护 `abs(total - target)` 最小值）；四数之和？（外层再套一层循环 + 同样的双指针，注意两层去重）

## C-8 手写带 L1/L2 正则项的交叉熵损失 ⭐

**出处**：S5 一面（"手推 + 实现"）。

**问题**：写出带 L1/L2 正则的交叉熵损失函数及其梯度。

设权重 `w`，样本 `(x_i, y_i)`，y 为 one-hot，预测 `p = softmax(Wx + b)`：

```
L = -1/N Σ_i Σ_c y_ic · log(p_ic)  +  λ1 · ‖W‖₁  +  λ2/2 · ‖W‖₂²
```

- **L1**：`‖W‖₁ = Σ_j |w_j|`，梯度 `∂/∂w = sign(w)`（次梯度，在 0 处取 0 或 0~1 之间任意值）。
- **L2**：`(λ2/2)‖W‖₂² = (λ2/2)Σ_j w_j²`，梯度 `∂/∂w = λ2 · w`（**乘以 1/2 就是为了求导后干净地剩 λw**，面试可以点一句）。

```python
import numpy as np

def softmax(z):
    z = z - z.max(axis=1, keepdims=True)         # 数值稳定，必须减 max
    e = np.exp(z)
    return e / e.sum(axis=1, keepdims=True)

def ce_loss_with_reg(W, b, X, Y, lam1=0.0, lam2=0.0):
    """X: (N, D), Y: (N, C) one-hot"""
    N = X.shape[0]
    P = softmax(X @ W + b)                        # (N, C)
    ce = -np.sum(Y * np.log(P + 1e-12)) / N
    l1 = lam1 * np.sum(np.abs(W))
    l2 = lam2 / 2 * np.sum(W * W)
    loss = ce + l1 + l2
    dZ = (P - Y) / N                              # softmax + CE 的天赐梯度
    dW = X.T @ dZ + lam1 * np.sign(W) + lam2 * W
    db = dZ.sum(axis=0)
    return loss, dW, db
```

- **必答的一句**：**softmax + 交叉熵的梯度就是 `p - y`**，极其简洁，这是二者配对使用的根本原因（推导：`∂L/∂z_c = p_c - y_c`）。
- **追问 1**：为什么 L1 能产生**稀疏解**？（梯度是常数 `sign(w)`，不管 w 多小都把它往 0 推，到达 0 后次梯度区间包含 0 就能"停住"；L2 梯度 `λw` 随 w 变小而变小，只能无限逼近 0 → **L1 稀疏、L2 平滑**）
- **追问 2**：L1 不可导怎么优化？（近端梯度 / ISTA / 坐标下降 / 子梯度下降；工程上常用**近似 + 截断**）
- **追问 3**：正则项为什么不加到 bias 上？（bias 的正则化会强行把偏置压 0，破坏拟合能力，一般只正则权重）

## C-9 手写 SoftNMS ⭐

**出处**：S12（魏无忌·一面），目标检测岗常考。

**问题**：NMS 把 IoU 超阈值的框直接删掉，容易误删重叠的真实目标。SoftNMS 怎么改？

```python
def soft_nms(boxes, scores, iou_thr=0.3, sigma=0.5, method='gaussian', score_thr=0.001):
    """boxes: [(x1,y1,x2,y2), ...]"""
    N = len(boxes)
    for i in range(N):
        max_idx, max_score = i, scores[i]
        for j in range(i + 1, N):                 # 每轮找剩余分数最高的框
            if scores[j] > max_score:
                max_idx, max_score = j, scores[j]
        boxes[i], boxes[max_idx] = boxes[max_idx], boxes[i]
        scores[i], scores[max_idx] = scores[max_idx], scores[i]

        for j in range(i + 1, N):
            iou = compute_iou(boxes[i], boxes[j])
            if method == 'linear':
                if iou > iou_thr: scores[j] *= (1 - iou)      # 线性衰减
            else:                                            # gaussian（默认，效果更好）
                scores[j] *= np.exp(-(iou * iou) / sigma)
            if scores[j] < score_thr: scores[j] = 0          # 分太低直接清掉
    return boxes, scores
```

- **一句话区别**：NMS 是**硬删除**（IoU 超阈值 → 该框直接消失），SoftNMS 是**软降权**（IoU 越大，分数衰减越狠，但不立刻删，可能之后被别的框救回来）。
- **追问 1**：为什么 Gaussian 比 Linear 好？（Linear 在 IoU 略超阈值时衰减过猛、不连续；Gaussian 平滑连续，对"高 IoU 但确实是不同物体"更友好）
- **追问 2**：现在工业界还用它吗？（**基本被替代**：主流是 **NMS-free**——DETR 系列用匈牙利二分图匹配、FCOS/ATSS 用 centerness、YOLOv8 用 DFL。SoftNMS 现在主要出现在面试和旧模型里）
- **追问 3**：IoU 是求交并比，`IoU = 交面积 / 并面积`；还有 GIoU/DIoU/CIoU（把中心点距离、长宽比加入回归损失）。

## C-10 SQL：最大连续登录天数 ⭐

**出处**：S5 一面。

**问题**：给定用户登录表 `login(user_id, login_date)`，求每个用户的最大连续登录天数。

### 核心技巧：`日期 - 行号 = 分组标识`

```sql
WITH t AS (
    SELECT user_id, login_date,
           DATE_SUB(login_date, INTERVAL
               ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY login_date) DAY) AS grp
    FROM (SELECT DISTINCT user_id, login_date FROM login) d   -- 去重，一天多次登录算一次
)
SELECT user_id, MAX(cnt) AS max_consecutive_days
FROM (
    SELECT user_id, grp, COUNT(*) AS cnt
    FROM t
    GROUP BY user_id, grp
) x
GROUP BY user_id;
```

- **为什么成立**：连续日期的日期值每天 +1，行号也每天 +1，**两者相减得到同一个常量** → 同一段连续登录会落到同一个 `grp` 里。日期一旦断档，差值就变了。
- **必须先去重**：同一用户同一天登录多次（多行）会破坏差值恒定性。
- **追问 1**：用 MySQL 5.7（无窗口函数）怎么写？（用户变量 `@row := IF(@uid = user_id, @row + 1, 1)` 模拟行号，或用自连接的差值法，但复杂且慢）
- **追问 2**：改成求"连续登录 ≥ 3 天的用户数"？（把 `MAX(cnt)` 换成 `HAVING COUNT(*) >= 3` 或外层 filter）
- **追问 3**：改成求"每个用户**当前**连续登录天数"？（加 `WHERE login_date >= CURDATE() - INTERVAL k DAY` 限制窗口，或对最后一段单独取）

## C-11 杂项小题速查（拼多多爱考的小题，10 秒内要能答）

### 1) 0~1000 内所有含数字 3、6、9 的数字个数

**正解用补集算，别暴力数**：

- 0~999 共 1000 个数，按三位（允许前导 0）看，每一位可放除 3/6/9 外的 **7 个数字**（0,1,2,4,5,7,8）→ 完全不含 3/6/9 的有 `7³ = 343` 个。
- 1000 本身不含 3/6/9 → 补集 = 343 + 1 = **344**。
- **答案 = 1001 − 344 = 657**。

> 面试官想听的是**补集思想**（"至少含一个"很难算，"一个都不含"很好算），不是枚举。

### 2) 3 台打印机分配打印队列，使总完成时间最小

**多机调度问题（NP-hard）的经典贪心：LPT（Longest Processing Time first）**

每次把**当前最大的任务**分给**当前负载最小的打印机**。实现：任务按耗时降序排，用**最小堆**维护 3 台机器的当前负载，每次 `heappop` 最小负载 → 加上任务耗时 → `heappush` 回去。

```python
import heapq
def min_time(jobs, k=3):
    heap = [0] * k                      # k 台机器的当前负载
    heapq.heapify(heap)
    for t in sorted(jobs, reverse=True):  # 长任务优先
        load = heapq.heappop(heap)      # 负载最小的机器
        heapq.heappush(heap, load + t)
    return max(heap)
```

- 追问：这是最优解吗？（LPT 是 4/3 - 1/(3k) 近似比的贪心，**不一定全局最优**——最优要用 DP/状压或回溯，n 大时用贪心）

### 3) 单例模式（懒汉式）

```java
// 双检锁（推荐：既能懒加载，又线程安全且性能好）
public class Singleton {
    private static volatile Singleton instance;     // volatile 防指令重排，必须加
    private Singleton() {}
    public static Singleton getInstance() {
        if (instance == null) {                     // 第一次检查（无锁，快）
            synchronized (Singleton.class) {
                if (instance == null) {             // 第二次检查（防并发重复创建）
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}
```

- **懒汉 vs 饿汉**：懒汉 = 第一次调用才创建（省资源，但要处理线程安全）；饿汉 = 类加载时就创建（简单、天然线程安全，但可能浪费）。
- **volatile 的作用**：`instance = new Singleton()` 分三步（分配内存 → 初始化 → 赋值引用），JVM 可能重排成 1→3→2，此时另一个线程可能拿到"构造未完成"的对象。`volatile` 禁止这种重排。
- **更好的写法**：静态内部类（`Holder`）—— 由 JVM 类加载机制保证线程安全 + 懒加载，无需加锁。

### 4) 实现链表，支持插入 / 删除 / 查询

```python
class ListNode:
    def __init__(self, val=0, nxt=None): self.val, self.next = val, nxt

class LinkedList:
    def __init__(self):
        self.dummy = ListNode()       # 哨兵节点，省掉"删头/插头"的特判
        self.size = 0
    def add_at_head(self, val):
        self.dummy.next = ListNode(val, self.dummy.next); self.size += 1
    def get(self, idx):
        if idx < 0 or idx >= self.size: return -1
        p = self.dummy.next
        for _ in range(idx): p = p.next
        return p.val
    def delete_at(self, idx):
        if idx < 0 or idx >= self.size: return
        p = self.dummy
        for _ in range(idx): p = p.next
        p.next = p.next.next; self.size -= 1
```

- **抓手**：用**哨兵（dummy）节点**统一边界，否则删除头节点要写特判。这是面试官看你会不会写链表的标志。

### 5) 手写 self-attention 公式与代码

```
Attention(Q, K, V) = softmax(QKᵀ / √d_k) V
```

```python
def self_attention(X, Wq, Wk, Wv):        # X: (L, d)
    Q, K, V = X @ Wq, X @ Wk, X @ Wv
    d_k = Q.shape[-1]
    scores = Q @ K.T / (d_k ** 0.5)       # 缩放，防止点积过大
    A = softmax(scores, axis=-1)          # 行归一化
    return A @ V, A
```

- **为什么除以 √d_k**：Q、K 各维独立、均值 0 方差 1 时，点积的方差是 d_k。d_k 越大，点积数值越大 → softmax 进入饱和区 → 梯度趋近 0（梯度消失）。除以 √d_k 把方差拉回 1，保持梯度的健康尺度。

### 6) 计算平方根（不用 math.sqrt）

**牛顿迭代法**：求 `√a` 即解 `x² - a = 0`，迭代 `x = (x + a/x) / 2`。

```python
def sqrt_newton(a, eps=1e-10):
    if a < 0: raise ValueError
    if a == 0: return 0
    x = a
    while abs(x * x - a) > eps:
        x = (x + a / x) / 2
    return x
```

- **收敛**：二次收敛（每步有效位数翻倍），约 20 次迭代即可到 double 精度。追问："为什么二次收敛？"——泰勒展开可证误差 `e_{k+1} ≈ e_k² / (2x*)`。

# 三、八股真题带答案

## 3.1 推荐 / 搜广推基础 `[S4 一面]`

### Q1 三种偏差（位置 / 曝光 / 流行度）的来源与解法差异 ⭐⭐⭐

| 偏差 | 来源 | 危害 | 主流解法 |
|---|---|---|---|
| **位置偏差 (Position Bias)** | 用户天然更爱点靠前的位置，与内容质量无关 | 模型学到的是"位置好坏"而非"内容好坏"，且**线上位置永远在变** | **PAL**（Position-Aware Learning：训练时把位置当特征，线上推理置 0）；**特征改造**（训练把位置设为 unknown）；**两塔解耦**（POSO：position tower + content tower） |
| **曝光偏差 (Exposure Bias)** | 只有被曝光的物品才有标签，未曝光的"可能是好物品"永远没机会 | 训练分布 ≠ 真实分布，模型把"没被曝光"当负样本 | **IPS / 逆倾向得分**（按曝光概率加权，pw 高的样本权重低）；**DR（Doubly Robust）**：IPS 打底 + 直接法模型兜底，方差更小 |
| **流行度偏差 (Popularity Bias)** | 热门物品曝光多 → 点击多 → 模型更推 → 更热门，马太效应 | 长尾/新物品没流量，生态恶化 | **因果 embedding**（把"物品流行度"这个混杂因子显式建模，推荐时反事实干预）；**去流行度正则 / 重加权**；**基于图的去偏**（如 Popularity Debiasing with Causal Graph） |

**一句话总结三者的差异**：位置偏差是**"同一个物品因位置不同而效果不同"**；曝光偏差是**"只有部分物品被观测到"**（样本缺失）；流行度偏差是**"观测本身被热度扭曲"**（混杂）。三者分别对应"特征污染 / 样本缺失 / 混杂因子"。

### Q2 Wide&Deep / DeepFM / DCN / DIN 各自解决什么问题

- **Wide&Deep**：Wide 学**记忆**（人工交叉特征，捕捉"同时买了 A 和 B"这种共现），Deep 学**泛化**（embedding + MLP 捕捉未见过的组合）。解决的问题：纯 LR 缺泛化、纯 DNN 缺记忆。
- **DeepFM**：把 Wide 的人工交叉换成 **FM 二阶交叉**，且 FM 和 Deep **共享同一套 embedding**（省参、端到端）。解决的问题：Wide&Deep 还要人工做交叉特征。
- **DCN / DCN-V2**：用 **Cross Network** 显式做**高阶**特征交叉（`x_{l+1} = x_0 · x_lᵀ · w + b + x_l`），V2 用矩阵替代向量提升表达能力。解决的问题：FM 只到二阶，DCN 能到任意阶。
- **DIN**：用 **attention 根据候选物品动态调整历史行为的权重**（"看了鞋子 vs 看了口红，历史点击的权重不同"）。解决的问题：固定宽度的用户表示无法表达"多峰兴趣"，且不能随候选自适应。

**一句话主线**：**从"人工交叉"到"自动交叉"到"高阶交叉"到"兴趣自适应"**。

### Q3 双塔召回的优缺点；为什么 serving 阶段不放交叉特征 ⭐⭐

- **优点**：用户塔和物品塔**解耦** → 物品向量可**离线预计算 + 建 ANN 索引**（Faiss/HNSW），线上只需算用户向量再近邻检索，**千万级候选毫秒级响应**。
- **缺点**：**用户和物品只在最后做内积/余弦**，交互能力弱，精度天然不如精排的交叉模型。
- **为什么 serving 不放交叉**：一旦有交叉特征（`用户×物品` 的组合），物品向量就**不再是固定的**——换一个用户，所有物品的表示都得重算，**预计算和索引全部失效**，退化成 O(候选数) 的在线计算，性能和成本都不可接受。所以业界做法是：**召回用双塔（快），精排用交叉（准）**，用级联各取所长。

### Q4 负采样 + in-batch negative + logQ correction ⭐⭐

- **负采样**：全量 softmax 代价太高（物品几百万），从"未交互物品"里随机抽一批当负样本。
- **in-batch negative**：一个 batch 里，**其他样本的正物品**直接当本样本的负样本，无需额外采样，GPU 利用率高（这是双塔训练的标准做法）。
- **logQ correction**：in-batch negative 是从"按热度采样"（sampled softmax）来的，负样本的分布不是均匀分布，而是 `Q(i)`（通常正比于物品热度）。这会让模型**系统性高估热门物品**。修正办法是在 logits 上**减去 `log Q(i)`**：`score(i) = u·v_i − log Q(i)`。
  - 直觉：一个物品被抽成负样本的概率越高（越热门），说明它"被惩罚的次数越多"，所以要**补偿回来**，让打分无偏。
  - 工程上 `Q(i)` 常用**物品曝光频次的 0.75 次幂**（`p^0.75`，来自 word2vec 的平滑技巧）。

### Q5 AUC vs GAUC，为什么推荐场景看 GAUC ⭐⭐

- **AUC**：全局指标，衡量"随机取一个正样本和一个负样本，模型给正样本打分更高的概率"，**对全局排序负责**。
- **问题**：推荐里**同一用户内部的排序才是有意义的**。AUC 会把"用户 A 的样本"和"用户 B 的样本"混在一起算——如果用户 A 天然点击率高，模型只要学会"识别高活用户"就能把 AUC 刷得很高，但**单个用户内部的排序可能很差**。
- **GAUC**：按用户（或按请求）分组算 AUC，再按**该组样本量加权平均**：
  `GAUC = Σ_u (n_u / n) · AUC_u`
- **一句话**：AUC 回答"模型整体能不能区分好物品"，GAUC 回答"**对每个用户，模型能不能把 ta 想点的排前面**"——后者才是推荐真正在优化的东西。

## 3.2 因果推断 / uplift / 多目标 `[S4 二面]`

### Q1 智能补贴为什么用 uplift 而不是 CTR ⭐⭐⭐

- **CTR 回答的是"谁会点/谁会买"**，uplift 回答的是"**因为发了这张券，谁才买**"（增量）。
- 用 CTR/CVR 选人发券会踩两个坑：
  1. **"必然转化者"（Sure Thing）**：本来就要买的人，你给他发券 = **纯白送钱**（补贴浪费）。这批人恰恰是 CTR 最高的。
  2. **"顽固不化者"（Lost Cause）**：怎么发都不买，也是浪费。
- 应该只发给 **"说服敏感者"（Persuadable）** —— 不发不买、发了才买。uplit 的目标就是**识别这批人**。
- 人群四象限（必背）：**Sure Thing（必买）/ Persuadable（可说服）/ Lost Cause（不回）/ Do Not Disturb（睡美人：一发券反而反感）**。CTR 模型只能定位第一象限，uplift 才能定位第二象限。

### Q2 只有观察数据怎么办（PSM / DR-learner）⭐

- **问题**：A/B 实验能拿随机数据，但历史数据都是观察数据——**发券的用户和没发券的用户本身就不同**（发券可能偏向高价值用户），直接比均值会被**混杂因子**污染。
- **PSM（倾向得分匹配）**：用协变量 `X` 拟合"被处理的概率"（propensity score `e(X)`），把处理组和对照组中**倾向得分相近**的样本配对，让两组在协变量上**可比**，再算差值。
  - 前提假设：**CIA（条件独立假设）**——控制了 X 之后，处理分配与结果无关；以及**共同支撑域**。
- **DR-learner（Doubly Robust）**：**IPS 加权 + 结果模型回归**结合。当"倾向得分模型"或"结果模型"**任一正确**时，估计都一致（双保险），且方差比纯 IPS 小。
- **痛点提醒**：PSM 只能平衡**可观测**的混杂，**不可观测**的混杂无解 → 所以最终还是优先做随机实验。

### Q3 T-learner / S-learner / X-learner / DR-learner 的区别 ⭐⭐

| 方法 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **S-learner**（Single） | 把所有样本建**一个**模型，treatment 当**特征**输入，预测时把 t=0/1 各跑一次相减 | 简单、样本利用率高 | 当 treatment 特征被模型**忽略**时，uplift 恒为 0；treatment 与特征交互弱时效果差 |
| **T-learner**（Two） | 处理组、对照组**各建一个模型**，两个模型预测相减 | 直观、能捕捉任意异质性 | 两组样本不均衡时，小样本那侧模型不准；**两个模型的误差会叠加到差值上**，方差大 |
| **X-learner** | 先用 T-learner 拿粗估，再**用另一组的样本算"残差/反事实"**去修正，最后对两个估计做加权（权重用倾向得分） | 处理组/对照组**严重不均衡**时表现最好 | 实现复杂 |
| **DR-learner** | 用**交叉拟合（cross-fitting）**+ 双稳健损失，直接优化 CATE 的估计，方差小且无偏 | 理论性质最好（双稳健） | 工程实现最重 |

**记忆口诀**：S 是"一个模型加个开关"，T 是"两个模型相减"，X 是"互相补课"，DR 是"双保险 + 交叉拟合"。

### Q4 ESMM 如何解决 CVR 的样本选择偏差（SSB）⭐⭐

- **SSB 从哪来**：CVR = 点击后购买的概率。训练 CVR 模型只能用**点击样本**，但线上推理是对**所有曝光**做的。而点击样本是"用户筛选过的偏置样本"，与全体样本分布不同 → **训练/推理分布不一致**。
- **ESMM 的核心 trick**：不直接训 CVR，而是训 **CTR 和 CTCVR 两个全空间任务**（在所有曝光样本上），利用恒等式：

  `pCTCVR = pCTR × pCVR`

  即 `p(曝光→购买) = p(曝光→点击) × p(点击→购买)`。

  模型两个塔共享 embedding，pCTCVR 用**全部曝光样本**（含未点击）作标签。这样 **CVR 塔虽然只在点击样本上产生梯度，但其表示是被全空间任务共同训练的**，样本空间对齐了。
- **另一个好处**：CVR 的标签极其稀疏（曝光→点击→购买层层衰减），ESMM 通过共享参数让 CTR 的丰富样本**增强 CVR 的学习**。
- **直接推论题**：为什么不能单独用点击样本训 CVR？（因为推理时面对的是曝光全空间，分布不一致）

### Q5 MMoE vs PLE，什么时候发生 negative transfer ⭐⭐

- **MMoE**：底层共享一组 expert，每个任务一个 **gate**（软选择），输出是 experts 的加权和。相比"硬共享"（所有任务共用底层），MMoE 让每个任务能**选择性地用不同专家**。
- **PLE（Progressive Layered Extraction）**：MMoE 的升级——区分 **共享专家（shared experts）+ 任务专属专家（task-specific experts）**，并且**多层叠加**（逐层分离）。核心动机是解决 MMoE 的**"跷跷板现象"**：提升一个任务往往损害另一个任务。
- **Negative transfer（负迁移）什么时候发生**：**任务之间相关性低甚至是冲突的时候**。比如"点击率"和"退货率"——一个催着推、一个拦着推；再比如"短视频完播"与"长视频观看"对时长的要求相反。这时共享底层会互相拖累，表现**还不如各任务单独建模**。
- **判断与解法**：看各任务 loss 是否此消彼长（跷跷板）；解法是**给冲突任务分配独立专家**（PLE 的思路）、**缩小共享层**、或者干脆**拆成两个模型**。
- **可主动抛的实战**：腾讯 MMoE-Group/Special/Skill 的结构演化；你做过 ESMM 统一 CTR/CVR，可以顺势聊"两个任务强相关所以共享有效，但退货率这类反向任务就不适合硬共享"。

### Q6 Pacing 算法（PID / 线性规划）预算平滑 ⭐⭐

- **问题**：广告主/活动给了总预算 B，要在一天内花完，但**不能"前 1 小时花光"**（流量浪费、系统压力大），也**不能"到点还剩一大半"**（预算跑不完）。这就是**预算平滑（budget pacing）**。
- **PID 控制**：把"实际消耗速率"和"目标消耗速率（预算 / 剩余时间）"的偏差当误差，用 **P（比例）+ I（积分）+ D（微分）** 三项调整出价系数 λ：
  - P：偏差越大，调得越狠；
  - I：消除长期稳态偏差（比如预算一直花不完）；
  - D：抑制震荡（消耗速率抖动时提前刹车）。
  - 工程上常见做法：**每 30 min 用 PID 调一次出价系数**（你 OPPO oCPX 就是这么干的）。
- **线性规划**：把"每个时段投放量"当决策变量，目标最大化总收益 / 最小化超投风险，约束是 `Σ spend_t = B` 且每时段有上下限。适合**离线/准实时**求解。
- **追问**：怎么判断 pacing 健康？（看"消耗曲线"是否平滑贴近理想斜线、预算完成率是否达标、超投率是否可控）

## 3.3 大模型 `[S2 / S6]`

### Q1 RLHF / RLAIF / DPO 的原理与优劣 ⭐⭐

| 方法 | 流程 | 优点 | 缺点 |
|---|---|---|---|
| **RLHF** | ① SFT → ② 训**奖励模型 RM**（人偏好排序）→ ③ 用 PPO 优化策略，加 KL 惩罚防跑偏 | 效果上限高，是 ChatGPT 的路线 | **工程重**：要维护 4 个模型（policy / ref / reward / critic），PPO 超参敏感、训练不稳 |
| **RLAIF** | 和 RLHF 一样，但**偏好标注由 AI 完成**（用强模型打分/排序） | **摆脱人工标注**，成本低、可规模化；对人类难判断的任务（长文本、代码）效果可能更好 | 受**标注模型的偏好偏置**影响，有"AI 审美同质化"风险 |
| **DPO** | 直接用**偏好数据 + 一个闭式损失**优化策略，**不需要显式奖励模型、不需要 RL 采样** | **简单稳定**、只需 policy + ref 两个模型、训练快；效果接近 RLHF | 对**偏好数据质量**敏感；本质是"隐式奖励"，探索性弱于在线 RL |

- **电商客服/导购场景该选哪个**：偏 **DPO 或 RLAIF**。原因：① 电商有**大量真实对话/人工标注语料**，DPO 直接吃偏好对即可，不需要重建 RL 工程；② 需要快速迭代、成本可控；③ 若要做"长期用户满意度"这类难以人工打标的目标，可用 RLAIF 让强模型当裁判。

### Q2 SFT 流程 / 目标 / 数据集构建；过拟合与知识遗忘 ⭐

- **流程**：选基座 → 构建指令数据（instruction/input/output）→ 加 prompt 模板 → 全参微调或 LoRA 微调 → 评估。
- **训练目标**：**只在 answer（输出）部分算 token-level 交叉熵**，instruction 部分 mask 掉不算 loss。
- **数据集构建原则**：**质量 > 数量**；覆盖目标场景的**任务类型多样性**；格式统一；正负样本/难度配比合理；清洗掉低质、重复、敏感数据。
- **过拟合**：训练 loss 持续降但验证 loss 抬头 → 早停、降学习率、加数据、加正则、LoRA 降低可训练参数量、训练轮数控制在 1~3 epoch。
- **知识遗忘（灾难性遗忘）**：微调后通用能力下降。解法：① **混入通用数据**（如 5%~20% 的通用指令）；② **LoRA/Adapter** 只更新少量参数；③ 降低学习率；④ 用**回放（replay）** 旧任务样本。

### Q3 如何判断训练收敛 / 训练崩溃怎么定位 ⭐

- **判断收敛**：训练 loss 与验证 loss 都趋于平稳（连续 N 步波动 < 阈值）；下游 eval 指标（领域准确率 / PPL）不再提升；梯度范数稳定不爆。
- **必备监控**：**loss 曲线、学习率、梯度范数（grad norm）、显存占用、吞吐（tokens/s）、loss scale（混合精度）、各层激活的均值/方差**。
- **崩溃快速定位套路**（按这个顺序说，显得有经验）：
  1. **看 loss 形态**：NaN 突现 → 先去查**学习率过大 / 除零 / 溢出**；
  2. **看 grad norm**：突然飙高 → 梯度爆炸（梯度裁剪 + 降 lr）；
  3. **看 loss scale**：混合精度下 loss scale 掉到 0 → 溢出；
  4. **缩小复现**：用极小 batch + 固定随机种子跑单步，逐步排查数据、模型、优化器；
  5. **查数据**：脏样本/空样本/超长样本导致 attention 爆显存或 loss 异常。

### Q4 幻觉成因与电商商品信息生成的缓解方案 ⭐

- **成因**：① 训练目标是"预测下一个 token"而非"说真话"，模型倾向于生成流畅而非正确的内容；② 训练数据里的错误/长尾知识被记住；③ 解码采样（temperature > 0）引入随机性；④ 上下文不足时模型会"编"。
- **缓解**：**RAG**（把商品库/参数/规格检索出来喂进上下文，让模型"照着抄"）；**事实性约束**（结构化字段强校验 + 规则兜底）；**后置校验**（关键字段用工具/规则核对，不一致就重写或打标）；**降低 temperature / 用约束解码**；**要求引用来源**（让模型标注信息来自哪条检索结果）。

### Q5 Transformer / self-attention 全流程 ⭐⭐

- **结构**：`Multi-Head Self-Attention → Add & Norm → FFN → Add & Norm`，Encoder 全是双向注意力，Decoder 是**带 causal mask 的自注意力 + 对 Encoder 的 cross-attention**。
- **计算**：`Q=XWq, K=XWk, V=XWv` → `Attention = softmax(QKᵀ/√d_k)V`。多头 = 把 d 维切成 h 份并行做，再拼接投影（不同头关注不同子空间/关系）。
- **复杂度**：**O(L²·d)**，瓶颈在 L²（序列长度的平方）。
- **Encoder vs Decoder**：Encoder 能看到全序列（双向），适合理解任务（分类/抽取）；Decoder 只能用**因果 mask**看左侧，适合生成（自回归）。

### Q6 self-attention 为什么除以 √d；有哪些降复杂度方案 ⭐⭐

- **除以 √d**：Q、K 各维独立同分布（均值 0、方差 1）时，点积的方差是 **d**。d 大 ⇒ 点积数值大 ⇒ softmax 落到饱和区（一个位置接近 1、其余接近 0） ⇒ 梯度趋近 0。除以 √d 把方差归一到 1，保持梯度尺度健康。（这是上一节 C-11-5 的同一考点，coding 和八股会各问一遍）
- **降复杂度方案**（能报名字 + 一句话即可）：
  - **稀疏注意力**（Longformer / BigBird）：只算局部窗口 + 少量全局 token；
  - **低秩/线性注意力**（Linformer / Performer）：用核函数近似 softmax，把 O(L²) 降到 O(L)；
  - **滑窗/分块**（Swin 的 window attention）；
  - **FlashAttention**：不减少理论复杂度，但通过**分块 + 不物化注意力矩阵**大幅减少显存读写（IO-aware）；
  - **KV Cache / MQA / GQA**：推理侧压缩 KV 显存。

### Q7 主流大模型架构差异；Decoder-only 的优势 ⭐

- **架构三族**：**Encoder-only**（BERT，理解类任务）、**Encoder-Decoder**（T5，翻译/摘要）、**Decoder-only**（GPT / Qwen / DeepSeek / Llama）。
- **Decoder-only 的优势**：
  1. **训练目标统一**（next-token prediction），**任何文本都能当训练数据**，数据利用率最高；
  2. **架构简单、易于规模化**（不需要 cross-attention，便于张量/流水线并行）；
  3. **天然支持 in-context learning 和零样本泛化**（few-shot 提示即插即用）；
  4. **生成任务天然适配**（一次前向出一个 token + KV Cache 复用）。
- **追问**：Qwen / DeepSeek / GPT 的差异？（DeepSeek 的 **MLA（Multi-head Latent Attention）**压缩 KV Cache、MoE 稀疏激活；Qwen 的 GQA + 长上下文支持；GPT 系闭源，但同样往 MoE/长上下文走）

### Q8 并行策略：数据 / 张量 / 流水线 ⭐

| 并行 | 切什么 | 通信 | 适用 |
|---|---|---|---|
| **数据并行 (DP)** | 切**数据**，每卡一份完整模型，梯度 all-reduce | 梯度同步（通信量大） | 模型能装进单卡 |
| **张量并行 (TP)** | 切**单层内的矩阵**（如列切 Wq/Wk/Wv、行切 FFN） | 每层前后都要 all-reduce（**通信频繁**） | 单层太大装不下；**要求高带宽（同机 NVLink）** |
| **流水线并行 (PP)** | 切**层**（前几层在卡 1、后几层在卡 2） | 只在层边界传激活（通信少） | 模型太深；需处理**气泡（bubble）**，用 micro-batch 填充 |
| **ZeRO** | 切**优化器状态 / 梯度 / 参数**（不切计算） | 按需 all-gather | 显存瓶颈的通用解法 |

### Q9 Megatron-LM 怎么做 Tensor Parallel；ZeRO 三阶段 ⭐

- **Megatron-LM 的 TP**：
  - **MLP 层**：第一个矩阵**按列切**（`Y = GeLU(XA)`，A 列切成 A1/A2，各卡算 Y1/Y2，**无需通信**），第二个矩阵**按行切**（`Z = YB`，B 行切成 B1/B2，各卡算部分和，**一次 all-reduce 得到 Z**）。**"列切 → 行切"保证整个前向只通信 1 次**，这是 Megatron 设计的精髓。
  - **Attention 层**：多头天然可切——**每个头分到不同卡**上算，输出投影按行切 + all-reduce。
- **ZeRO 三阶段**（都是"切显存，不切计算"，逐级更省显存、通信更多）：
  - **ZeRO-1**：只切**优化器状态**（Adam 的 m/v + fp32 参数副本，占显存大头）；
  - **ZeRO-2**：再切**梯度**；
  - **ZeRO-3**：再切**模型参数**本身（用到某层时才 all-gather 该层参数）。
- **一句话**：ZeRO-1 省最多、代价最小；ZeRO-3 最省但通信最重。

### Q10 只有 8 张 A100 怎么训 30B 模型 ⭐⭐

这是"组合拳"题，按这个顺序答：

1. **显存估算**：30B 参数，纯 fp16 权重 = 60 GB；训练还要梯度（+60 GB）和 Adam 优化器状态（fp32 的 m/v/主权重，约 +360 GB）→ **单卡完全放不下**。
2. **切分策略**：**ZeRO-3**（把参数 + 梯度 + 优化器状态都切到 8 张卡）或 **TP + PP + DP 三维并行**（如 TP=8 或 TP=4×PP=2）。
3. **省显存**：**混合精度**（bf16）+ **梯度检查点（activation checkpointing）**（用计算换显存）+ **FlashAttention**（不物化注意力矩阵）+ **offload**（优化器状态/参数卸载到 CPU，牺牲速度换容量）。
4. **降训练成本**：**LoRA / QLoRA**（只训少量低秩参数，冻结主干）；**梯度累积**（小 batch 模拟大 batch）。
5. **数据侧**：**序列打包（packing）** 提高 token 利用率；**分布式数据加载**避免 IO 瓶颈。
6. **结论口径**：8×A100(80G) 训 30B **全参**需要 ZeRO-3 + offload + 梯度检查点，速度很慢；**更现实的方案是 LoRA 微调**。

### Q11 FlashAttention 为什么更快；LoRA 为什么能减参 ⭐⭐

- **FlashAttention**：注意力**理论复杂度不变**，快在 **IO**。标准实现要显式写出 `L×L` 的注意力矩阵（存到 HBM 再读回来），而 HBM 带宽是瓶颈。FlashAttention 用 **tiling（分块）+ online softmax**：把 Q/K/V 分块塞进 **SRAM** 里算，**不物化完整的注意力矩阵**，只把 softmax 的归一化因子滚动更新（running max / running sum）。→ **显存 O(L) 而非 O(L²)，速度 2~4×**。
- **LoRA**：冻结原权重 `W`，只训练一个**低秩增量** `ΔW = BA`（`B: d×r, A: r×d`，r ≪ d）。可训练参数量从 `d×d` 降到 `2dr`，**减少几个数量级**；推理时可把 `BA` 合并回 `W`（`W + BA`），**不增加推理延迟**；不同任务可挂不同 LoRA，切换成本低。
- **rank r 的影响**：r 越大表达能力越强、参数越多，但**收益递减**；常用 r=8/16/32/64。任务越"偏离"基座（领域差异大），需要的 r 越大。追问："增大 r 会不会更好？"——不一定，r 太大可能过拟合且失去"低秩约束"的正则效果。

### Q12 梯度消失/爆炸；ReLU vs GLU；显存优化 ⭐

- **梯度消失/爆炸**：深层网络反向传播时梯度连乘 → 小于 1 的因子连乘趋 0、大于 1 的连乘趋 ∞。解法：**残差连接**（提供梯度高速通路）、**LayerNorm**、**合理初始化**（Xavier/He 针对激活函数）、**梯度裁剪**、**门控结构**（LSTM/GLU）。
- **ReLU vs GLU**：ReLU = `max(0, x)`（简单、便宜、缓解梯度消失，但有 dead ReLU）；**GLU = `(XW + b) ⊗ σ(XV + c)`**（用门控决定"放多少信息通过"，表达能力强、训练更稳，代价是多一组参数和一次 sigmoid）。主流 LLM 的 FFN 多用 **SwiGLU**。
- **显存优化**：混合精度（bf16 存激活/权重）、**梯度检查点**、**ZeRO / FSDP**、**ZeRO-Offload**、**FlashAttention**、**序列打包**、减小 micro-batch + 梯度累积、**8-bit 优化器（bitsandbytes）**。

### Q13 长上下文方案；电商长文本怎么优化 ⭐

- **方案**：① **位置编码外推**（RoPE 的 NTK-aware 插值 / YaRN / 位置插值 PI）；② **注意力改造**（滑窗注意力、稀疏注意力、FlashAttention + 分块）；③ **KV Cache 压缩**（MQA/GQA/MLA）；④ **RAG 替代长上下文**（只用相关片段）；⑤ **分块 + 摘要 + 递归聚合**（map-reduce 式处理超长文档）。
- **电商场景**：商品详情/评论/客服会话很长 → 优先 **RAG 检索关键字段**（而非把全文塞进去）、**结构化字段抽取**（价格/规格/库存本来就在库里，直接查比让模型读更准）、会话场景用**滑动窗口摘要**保留近期上下文 + 长期记忆。

## 3.4 CV / 多模态 `[S1]`（非目标方向，扫一眼）

- **backbone 设计讲究**：精度/速度/显存的权衡；感受野（大核 vs 堆叠小核）；多尺度特征融合（FPN）；是否可量化（有没有对量化不友好的算子）。
- **为什么 RepVGG 不适合量化**：RepVGG 训练时是**多分支**（3×3 + 1×1 + identity），推理时重参数化成**单个 3×3**。重参数化的合并会引入**大量 BN 折叠计算**，各分支的 BN scale 分布差异大，**量化时 scale 被少数大分支主导，小分支的精度被吃掉**；且结构过于规整，量化误差缺少补偿空间。改进：量化感知训练（QAT）、对每个分支单独量化再合并（如 QARepVGG）、用注意力/多样化结构增加量化鲁棒性。
- **目标检测发展史**：传统 HOG+SVM → **RCNN 系**（RCNN→Fast→Faster，两阶段，anchor-based）→ **YOLO/SSD**（一阶段，回归）→ **anchor-free**（FCOS/CenterNet）→ **DETR**（Transformer + 集合预测，NMS-free）→ **CLIP 之后的开放词汇检测**（GLIP/GroundingDINO，文本提示出框）。
- **CLIP 原理与缺点**：双塔（图像 Encoder + 文本 Encoder）在**对比学习**下对齐图文表示，用**对比损失**（in-batch 的图文配对为正）。缺点：① 只能给"相似度"不能做细粒度定位；② **对否定/关系/计数不敏感**（"没有猫"和"有猫"的 embedding 接近）；③ 受训练数据分布限制，长尾概念差；④ 需要**大 batch**（负样本多才能学好对比）。
- **"CLIP 训练的 batch 应该越大还是越小"**：**从方差/区分度看应该越大**。对比学习里，batch 内其他样本就是负样本，batch 越大 ⇒ 负样本越多 ⇒ 学到的表示区分度越高、梯度估计方差越小。这也是 CLIP 用超大 batch（数万）+ 大批量优化技巧的原因。
- **MoCo 原理**：维护一个**队列（memory bank）**存历史 batch 的 encoded key，用**动量更新的 Encoder（momentum encoder）**保证队列里的特征一致（否则新旧特征分布不一致，对比失效）。**如何增大 batch**：不靠增大真实 batch，而是靠**队列缓存大量历史负样本**（相当于把负样本数从 batch size 扩到 queue size），动量更新保证"code book 不漂移"。
- **标签分配 / Sinkhorn / NMS-free**：标签分配 = 决定"哪个预测框负责哪个 GT"（MaxIoU / ATSS / SimOTA / 匈牙利匹配）。DETR 用**匈牙利二分图匹配**（一对一，天然无需 NMS）。**Sinkhorn** 是"可微的近似二分图匹配"（在打分矩阵上迭代行列归一化，得到双随机矩阵，可作为 soft 匹配的层嵌进网络）。其他 NMS-free 策略：**一对多辅助头 + 一对一主头**（如 YOLOv10 的双重分配）、**centerness/quality 打分**、**集合预测**。
- **高斯牛顿 vs LM；LM 的多视角**：**高斯牛顿**用 `J^T J` 近似 Hessian，在残差小/问题接近线性时收敛快（二次收敛），但 `J^T J` 可能不可逆/不正定。**LM** 引入阻尼因子 `λ`：`(J^T J + λI) Δ = -J^T r`——λ 大时退化成**梯度下降**（稳但慢），λ 小时退化成**高斯牛顿**（快但可能不稳），并用"是否降低残差"动态调 λ。多视角：**信赖域方法**（带球约束的二次模型）、**信赖域 vs 线搜索**、**岭回归的推广**、**插值于 GD 和 GN 之间**。
- **为什么深度学习不容易陷入局部最小**：高维空间中"鞍点远多于局部极小"；且高维下局部极小的 loss 通常也接近全局（大量等价的平坦极小）；SGD 的噪声 + 大 batch 的重叠性帮助逃逸。

## 3.5 风控 / 数据分析 `[S5]`

- **MySQL 主键与索引怎么设、为什么、底层结构**：主键用**自增 BIGINT**（避免页分裂、保证写入有序、占用小、便于 InnoDB 聚簇索引组织）。InnoDB 主键是**聚簇索引**（数据即索引，叶子存整行）；二级索引叶子存主键值，回表拿行。索引底层是 **B+ 树**（矮胖、范围查询友好、非叶节点只存键所以单页能放更多、磁盘 IO 少；相比 B 树，B+ 的叶子链表利于范围扫描）。业务上给**高频过滤/排序字段**建索引，注意**最左前缀**和**区分度**。
- **XGBoost / 过拟合 / KS 与 AUC**：XGBoost = 加法模型的**二阶泰勒**梯度提升 + 正则化（叶子数 γ + 叶子权重 L2）+ 行列采样。**过拟合缓解**：减 max_depth、增 min_child_weight、调大 γ、加 λ/α、降低学习率 + 增树数、行列采样、早停。**AUC** 看排序能力（对阈值不敏感）；**KS** = 正负样本累积分布差的最大值（衡量"最佳阈值下的区分度"），金融风控常用 KS 选阈值。
- **特征有效性 IV / PSI**：**IV（信息量/Information Value）** = `Σ (好人占比 − 坏人占比) × WOE`，衡量单个特征对"好/坏"的区分能力（经验阈值：<0.02 无用、0.1~0.3 中等、>0.5 需警惕过拟合）。**PSI（群体稳定性指数）** = `Σ (实际占比 − 预期占比) × ln(实际/预期)`，衡量**分布是否漂移**（<0.1 稳定、0.1~0.25 需关注、>0.25 不稳定）。**一个是"有没有用"，一个是"稳不稳"**，上线特征两个都要看。
- **A/B test：DAG 图 / 分层抽样为什么减小方差**：DAG = 有向无环图，用于描述实验的分流层级（用户 → 实验 → 层 → 桶），保证**同一层内互斥、不同层间正交**。**分层抽样（stratified sampling）减小方差的数学原理**：把总体按协变量分成若干层，层内同质、层间异质；总方差 = `Σ w_h² · σ_h²`（层内方差加权和）+ 层间方差项，分层后**层间差异被消掉**（因为每层都按比例抽样，层间不再贡献方差），所以 `Var_strat ≤ Var_SRS`。实验里对应"按用户活跃度分层"能显著降低指标方差、提高检验功效。
- **DML 原理 / Neyman 正交**：**DML（Double/Debiased Machine Learning）** 用**交叉拟合（cross-fitting）** + **残差回归**估计因果效应：用 ML 模型分别拟合 `E[Y|X]` 和 `E[T|X]`，拿残差 `Y−Ŷ` 和 `T−T̂` 做回归。**Neyman 正交**指：估计量对**干扰函数（nuisance function）的一阶扰动不敏感**——即 `∂/∂η E[ψ] = 0`。直觉是"把一阶偏差项消掉"，这样即使 ML 模型估计 `E[Y|X]` 有小误差，也不会**一阶**污染最终的因果估计（只留下可忽略的高阶误差）。这是 DML 能用任意 ML 模型 + 达到 √n 收敛的根本原因。
- **牛顿法 / 拟牛顿 / XGBoost 的优化**：牛顿法用二阶导数（Hessian）找极值，收敛快但算 Hessian 代价高；**拟牛顿**（BFGS/L-BFGS）用梯度历史近似 Hessian（省去二阶计算）。**XGBoost 用的是二阶泰勒展开**（用一阶梯度 g 和二阶梯度 h 直接算出叶子最优权重 `w* = -G/(H+λ)`），所以**本质是牛顿法一族**（用二阶信息）。

## 3.6 传统 ML / 框架 `[S11 / S12]`

### Q1 手推 LR（从 logit 到损失到梯度）

1. **logit**：`z = wᵀx + b`
2. **概率**：`p = σ(z) = 1/(1+e^{-z})`，等价于 **对数几率是线性的**：`ln(p/(1-p)) = wᵀx + b`
3. **似然**：`L(w) = ∏ p_i^{y_i} (1-p_i)^{1-y_i}`
4. **取负对数得损失（交叉熵）**：`J(w) = -Σ [y_i ln p_i + (1-y_i) ln(1-p_i)]`
5. **梯度**：`∂J/∂w = Σ (p_i - y_i) x_i` —— **完美简洁**，这是 sigmoid + 交叉熵配对的产物。
6. **更新**：`w ← w - η(p - y)x`

### Q2 L1 正则化损失函数如何求解

目标 `J(w) = 损失 + λ‖w‖₁`，L1 在 0 处不可导。解法：
- **子梯度下降**：用 `sign(w)` 作为次梯度；
- **坐标下降 + 软阈值算子**：对每个 `w_j` 单独优化，解形如 `w_j = soft_threshold(ρ_j, λ)`，即"小于 λ 的置 0，大于的收缩 λ"——**这就是 L1 产生稀疏性的机制**；
- **近端梯度法（ISTA/FISTA）**：梯度步之后套一个近端算子（soft-thresholding），收敛有保证；
- **LARS**：最小角回归，沿"与残差相关性相同"的方向前进，天然产生稀疏解。

### Q3 LSTM 公式（背下来）

```
f_t = σ(W_f · [h_{t-1}, x_t] + b_f)      遗忘门
i_t = σ(W_i · [h_{t-1}, x_t] + b_i)      输入门
o_t = σ(W_o · [h_{t-1}, x_t] + b_o)      输出门
C̃_t = tanh(W_C · [h_{t-1}, x_t] + b_C)   候选记忆
C_t = f_t ⊙ C_{t-1} + i_t ⊙ C̃_t          细胞状态更新
h_t = o_t ⊙ tanh(C_t)                     隐状态输出
```

- **核心**：`C_t` 的更新是**加法**（`f_t ⊙ C_{t-1} + ...`），梯度沿"细胞状态高速公路"传回，避免了 RNN 的连乘梯度消失。**遗忘门控制"忘多少旧的"，输入门控制"写多少新的"，输出门控制"露多少出来"**。

### Q4 `tensor.detach()` 与 `tensor.item()`

- **`detach()`**：返回一个**共享数据但脱离计算图**的新 tensor（`requires_grad=False`）。用于**阻断梯度**（如目标网络更新、构造 target、取出中间结果当常量）。
- **`item()`**：把**单元素 tensor** 转成 Python 标量（`float`/`int`）。用于**打印日志、累加统计量**。
- **一句区分**：`detach()` 管**计算图**，`item()` 管**取值**。共同点：两者都会让你**不能再对它反传**。

### Q5 自监督 / 半监督 / 无监督 / 自回归的关系

- **无监督**是"没有标签"的总称；**自监督**是无监督的**主流实现方式**——**从数据自身构造监督信号**（预测被遮住的词、预测下一句、对比正负样本）。
- **半监督**是"少量标签 + 大量无标签"（伪标签、一致性正则、FixMatch）。
- **自回归**是一种**建模方式**（用前 k 个预测第 k+1 个），可以是自监督的目标（语言模型），也可以是监督的目标（时序预测）。
- **一句话**：自监督 ⊂ 无监督（按标签维度）；自回归是一种目标形式（按建模维度）；半监督是"标签少"场景。**关系是"维度不同"，不是互斥**。

# 五、场景题 / 系统设计（7 题）

## 5.1 设计广告竞价 + 出价系统（召回→粗排→精排→出价→pacing）`[S4 三面]` ⭐⭐⭐

**这题是你的强项（OPPO 广告全链路），要主动抛。**

分层讲：

1. **召回**：从百万广告主里按定向（人群/地域/时段）和相关性召回几千条 → 双塔 + ANN。
2. **粗排**：几千 → 几百，轻量模型（双塔/线性 + 少量交叉）。
3. **精排**：几百 → 几十，**预估 pCTR × pCVR**（多任务模型，MMoE/PLE），算 **eCPM 排序**。
4. **出价（竞价）**：二价/一价拍卖。**oCPX 模式**下广告主给"转化目标出价"（如 30 元/下单），平台需**把转化出价折算成点击出价**：`点击出价 = 转化出价 × pCVR`。竞价排序按 `eCPM = 出价 × pCTR`。
5. **Pacing**：预算平滑，**PID 每 30 min 调一次出价系数 λ**（这是你 OPPO 真做过的，重点讲），目标"预算按时花完且不过投"。
6. **机制设计要点**：**激励相容（truthful bidding）**、**GSP/VCG** 的选择、**广告密度上限**、**冷启动探索预算**、**防作弊（点击欺诈）**。
7. **监控**：消耗速率、超投率、eCPM 分布、广告主 ROI。

## 5.2 新用户冷启动（群体画像 + bandit + meta-learning）`[S4 三面]` ⭐⭐

- **为什么难**：新用户**没有行为序列**，个性化无从下手。
- **三层解法**：
  1. **群体画像（群体先验）**：用注册渠道、设备、地域、时段等**弱特征**，把新用户映射到"相似人群"，用该人群的偏好做**先验打分**（= 贝叶斯先验）。
  2. **Bandit 探索（Thompson Sampling / UCB）**：不要只利用先验，要**主动探索**——给新用户的推荐里混入一定比例的探索内容，用探索流量的反馈更新其后验。**你 OPPO 的"探索流量池 + 贝叶斯平滑"，通过率 +15%**。
  3. **Meta-learning（元学习）**：学习"如何快速适应新用户"的初始化（MAML 思想），让模型用**极少交互**就能快速个性化。
- **关键指标**：新用户 7 日留存、首日点击率、探索效率（ε 的取值）、以及"探索/利用"的平衡。

## 5.3 线上 AUC 没掉，但 GMV 掉 3%，怎么排查 ⭐⭐⭐

**这是"数据感"考题，考的是排查框架，不是标准答案。** 按"从模型 → 数据 → 系统 → 业务"排：

1. **先确认指标口径**：GMV 是**全站**还是**某个实验桶**？掉的是**哪部分**（新客/老客、某类目、某端）？——**先切维度定位范围**。
2. **模型/预估层**：AUC 只看**排序能力**，不看**校准（calibration）**。GMV 高度依赖**绝对价格/概率**（比如出价、Pacing、GMV 预估），所以首查 **PCVR 的校准是否漂移**（预估 5% 实际 3%）→ **AUC 不掉但 calibration 崩了，就会 GMV 掉**。
3. **排序结构问题**：AUC 保住了"相对顺序"，但可能是**高分位被少数高价商品占据**（结构性变化），导致实际转化变差。看**分数分布 / 位置分布 / 类目分布**是否漂移。
4. **数据层**：特征穿越、特征延迟（当天新特征没回填）、样本分布漂移（用户结构变了）、**新品类目 embedding 没学到**。
5. **系统层**：延迟升高导致**超时降级**（回退到热门兜底）、召回数量减少、缓存击穿、某条链路限流。
6. **业务/外部**：大促节奏、竞对补贴、供应链缺货（推了买不到）、流量结构变化（买量渠道切换）。
7. **验证手段**：**分桶对比 + 特征回放（replay）+ 指标下钻 + 反事实分析**。

**一句总结**：**AUC 是"排序"，GMV 是"排序 × 校准 × 覆盖 × 供给"**，所以 AUC 不掉不代表链路健康——第一嫌疑永远是**校准**。

## 5.4 AB 实验显著正向，全量后效果消失 ⭐⭐⭐

可能原因（按概率排序）：

1. **新奇效应（Novelty Effect）**：用户对新策略短期好奇点击，长期回落 → **需要跑 ≥2 周，看趋势而非单点**。
2. **实验期污染 / SUTVA 违背**：实验组和对照组互相影响（同一用户被两个桶影响、社交/推荐的同质内容外溢），全量后"对照组消失"，效果自然没了。
3. **流量结构差异**：实验只跑了 X% 流量，或许是**低竞争时段 / 特定人群**，全量后面对的是更难的人群。
4. **幸存者偏差 / 样本选择**：实验期恰好赶上活动、节假日；或实验桶和线上流量的用户构成不同。
5. **反馈回路（Feedback Loop）**：实验期模型看不到全量数据，全量后推荐结果互相影响（马太效应加剧、内容同质化），生态指标恶化。
6. **统计问题**：**样本量不足就宣布显著**（多重比较未校正）、**指标是代理指标**（点击涨了但转化没涨）、**实验周期不足**（未覆盖完整周期）。
7. **工程问题**：全量后 QPS 升高导致**降级/超时**，实际生效的策略和实验期不一致（配置没同步、特征在线上取不到）。

**正确做法**：设计阶段就做 **A/A 校验**、**分层正交**、**跑满周期**、**预注册指标 + 护栏指标**、**灰度逐步放量（1%→5%→20%→50%）** 并在每一步观察。

## 5.5 高并发短链系统设计（发号器 / 缓存 / 碰撞）`[S3]` ⭐

- **发号器**：
  - **自增 ID + 转 62 进制**（[0-9a-zA-Z]，6 位 = 568 亿）；
  - 分布式发号：**Redis INCR**（简单但有单点/持久化风险）、**号段模式**（一次取 1000 个，本地分配，减少 Redis 压力）、**雪花算法 Snowflake**（时间戳+机器 ID+序列，趋势递增但需处理时钟回拨）。
- **映射与碰撞**：短码 → 长链的映射（MySQL / Redis / KV），如果短码由"长链哈希"生成要处理**哈希碰撞**（加盐重试、或用发号器天然无碰撞）。
- **读取性能**：**短码是热点 Key** → 多级缓存（本地 Caffeine + Redis）+ CDN 层缓存 302；高 QPS 用**布隆过滤器**挡不存在的短码（防缓存穿透）。
- **写**：发号 → 落库 → 写缓存（**先写库再删缓存**，防不一致）。
- **监控**：QPS、缓存命中率、P99 延迟、短码碰撞率。

## 5.6 分布式事务 TCC（空回滚、悬挂）`[S3]` ⭐

- **TCC**：**Try**（预留资源，如冻结额度）→ **Confirm**（确认提交）→ **Cancel**（释放预留）。相比 2PC，TCC 不长时间持有数据库锁。
- **空回滚**：Try 阶段因为网络超时**没执行成功**，但事务协调器认为失败并发起 Cancel → Cancel 在"没有预留资源"的情况下被调用。
  - **解决**：Cancel 里先**判断是否存在 Try 记录**，没有就直接返回成功（幂等空操作）；或用"防悬挂表"记录事务状态。
- **悬挂（Hanging）**：Try 的网络请求**延迟到最后才到达**——此时 Cancel 已经执行完了，这个迟到的 Try 又预留了资源，导致**资源被永久占用**。
  - **解决**：**Cancel 时写入一条"已回滚"标记**，Try 执行前先检查该标记，若已回滚则**拒绝执行 Try**。
- **幂等**：Confirm/Cancel 都可能重试，必须用**事务 ID 做幂等键**。

## 5.7 TOP K 问题 / 秒杀设计

- **TOP K**：
  - **内存够**：`heapq` 维护大小 K 的**小顶堆**，O(n log K)；
  - **数据海量/流式**：**分治 + 归并**（分片各取 topK，再合并）；或**哈希分桶 + 每桶小顶堆**。
  - **注意**：如果 K 很小（如 top 10）而 n 极大，先分桶再堆最快；如果要求"第 K 大精确值"可用**快速选择（QuickSelect）** O(n) 平均。
- **秒杀设计**：
  1. **前端**：按钮置灰、答题防脚本、静态资源 CDN；
  2. **网关层**：限流（令牌桶）、黑名单、验证码；
  3. **库存**：**Redis 预减库存**（Lua 原子操作）+ 异步下单（MQ 削峰）；库存扣减用 `DECR` 返回负值即失败，**不要用数据库悲观锁**（扛不住）；
  4. **防超卖**：Redis 原子扣减 + 唯一索引（`user_id × 活动_id` 幂等）+ MQ 串行落库；
  5. **兜底**：库存回滚（下单失败时 Redis `INCR` 回补）、削峰队列限长、降级到"排队中"页。
