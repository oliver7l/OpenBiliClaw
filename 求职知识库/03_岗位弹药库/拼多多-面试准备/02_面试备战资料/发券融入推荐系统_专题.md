# 发券如何融入推荐系统：从优化目标到链路的完整改造（拼多多·推荐算法二面）

> 适用场景：推荐算法 / 广告算法 / 增长算法岗，被问到"补贴、发券、智能营销怎么接进现有推荐系统""uplift 模型怎么落地"。
> 一句话总纲：发券改的不是"加个特征"，而是把推荐系统的**优化目标**从"最大化转化"换成"在预算内最大化净收益"。

---

## 一、核心认知：发券改的是"优化目标"

没发券时，推荐系统的目标约等于"让最多人转化"（最大化 pCTR/pCVR）。
发了券，目标变成"在预算内让净收益最大"：

```
目标  = Σ [ uplift(x, c) × value(x) − c ]        （增量价值 − 券成本）
约束  = 总券成本 ≤ 当日预算（拼多多硬上限见第五节）
```

- `uplift(x, c)` = 给特征 x 的用户发面额 c 的券带来的**增量**转化（发券相对不发券多出来的部分）。
- `value(x)` = 这笔转化的期望 GMV / 毛利。
- `c` = 券成本。
- 关键点：uplift 才是"发券带来的增量"，pCTR 是"本来就会转化"。**目标函数一变，下面排序 / 特征 / 样本全得跟着变。**

---

## 二、为什么普通 CTR 模型不能直接用来发券

普通 CTR 模型估 `P(买 | 特征)`。问题：它估计的是"自然转化概率"，不包括"发券的增量"。

具体例子（value 假设 100 元/单）：
- 用户**小明**：价格不敏感，日常 CTR 0.80。发券后转化 0.82，真实增益 +0.02 → 增量价值 2 元 < 5 元券成本 → **不该发**（白送钱，属于 Sure Thing）。
- 用户**小红**：价格极敏感，日常 CTR 0.05。发券后转化 0.45，真实增益 +0.40 → 增量价值 40 元 >> 5 元券成本 → **该发**（净赚 35，属于 Persuadable）。

如果按 CTR 排序发券，小红（CTR 0.05）排不到前面，钱全砸在小明（CTR 0.80）身上 —— **把预算发给了不需要券的人**。这就是必须上 uplift 模型的铁理由。

## 三、Uplift 模型：在算什么、怎么训、怎么评估

### 3.1 反事实问题
你永远只能观察一种状态（发了 or 没发），uplift = 两种状态的差值永远观测不到。模型的任务就是估计这个差值。

### 3.2 四象限人群（输出的决策含义）
用 P0=不发券转化、P1=发券转化，差值=uplift：

| 人群 | P0 | P1 | uplift | 决策 |
|---|---|---|---|---|
| Sure Thing（必买） | 0.80 | 0.82 | +0.02 | 不发，白送钱 |
| Persuadable（可说服） | 0.10 | 0.45 | +0.35 | 发，券最有效 |
| Lost Cause（没救） | 0.05 | 0.06 | +0.01 | 不发，发了也不买 |
| Do Not Disturb（反感） | 0.40 | 0.30 | **−0.10** | 绝对不发，券起反作用 |

注意 Do Not Disturb 是**负增益**（论文叫 downlift）。决策不是"uplift>0 就发"，而是只在 Persuadable 发、面额匹配敏感度，其余三象限基本不发。

### 3.3 模型选型（按复杂度）
- **S-Learner**：一个模型，把"是否发券 T"当普通特征，`uplift = f(X,T=1) − f(X,T=0)`。简单但 T 被稀释。
- **T-Learner（工业最常用，携程生产选它）**：两个独立模型分别估 P1 / P0，相减得 uplift。不稀释但要防方差抖动。
- **X-Learner**：发券样本远少于不发券时用，交叉修正小样本侧。
- **DNN 系（TARNet / CanniUplift）**：共享表示 + 双 treatment head；但 CanniUplift 实证**解耦 control 网络（EUEN）比共享表示更稳**，因"自然转化"和"券增量"机理不同。

### 3.4 评估：AUUC / Qini（不能用 AUC）
没有个体 uplift 真值，无法逐人判对错，所以 AUC 失效。只能在群体层面看"按预测 uplift 从高到低发券，累计增益是否单调上升"：
- 随机发券基线 = Qini 对角线（平缓线性）。
- 好模型曲线明显翘在基线上方，面积（AUUC）大。

## 四、改造推荐系统的七个环节（重点）

原链路：`召回 → 粗排 → 精排(CTR/CVR) → 重排(多样性) → 机制层(出价) → 曝光`

### 4.1 精排分数怎么改（最关键）
- 错误改法：券面额当特征喂原 CTR 模型，仍按 pCTR 排序 → 钱发给 Sure Thing。
- 正确改法 A（uplift 当排序信号）：精排输出 `pCTR_nat(x)` 和 `uplift(x,c)`，排序分改为
  `score = pCTR_nat(x) + uplift(x,c) × value(x) − λ·c`
  其中 λ = 预算紧张度（来自 Pacing，越接近上限 λ 越大越克制）。
- 正确改法 B（约束优化，工业主流）：精排只估 `(pCTR_nat, uplift)`，把"给谁发、发多少面额"交给机制层做预算分配（见 4.5 的 MCKP）。
- 决策规则一句话：**uplift(x,c)×value(x) > c 才发，且选刚好跨阈值的最小面额 c**（拼多多"单张≤70%售价"即卡最小有效面额）。

### 4.2 特征体系加什么
新增三类，且要支持"反事实查询"——特征是"给定 (x, c)"而非只"给定 x"（打分时要假设"如果发这张券"）：
- 券侧：候选面额 c、券类型、可否叠加、剩余库存。
- 用户价格敏感度：历史折扣弹性、是否券敏感人群、历史**核销率**（领了且用了才算，低核销=白发）。
- 预算侧：该用户/商品/类目当日已发券额度、剩余预算（Pacing 用）+ 时段上下文。
普通 CTR 完全不需要这些。

### 4.3 样本怎么造
- 必须有**随机对照**：线上随机抽一部分人发券（T=1）、一部分不发（T=0），记录 Y（是否转化）。
- 标签：Y、T（是否发券）、c（面额）。
- **CIA 条件独立**：随机保证 `T ⟂ X`，于是 P(Y|T=1,X) 与 P(Y|T=0,X) 无偏，相减才是真 uplift。
- 离线没随机数据时：用 **PSM（倾向分匹配）** 或 **IV（工具变量）** 去偏，但工业界首选线上随机实验拿干净样本（携程、阿里文娱都强调）。
- 坑：样本必须包含"发了但没核销"的人，否则高估 uplift。

### 4.4 训练损失（常被漏）
- TARNet：共享底层 + 双 head，loss = `CE(P1) + CE(P0)`。
- CanniUplift：解耦 control 网络（EUEN）+ 平台级对齐 PGA loss（发券/核销平台不对齐）+ RDD 去噪（洗刷单）。
- 也可直接优化 AUUC 的排序型 loss，让模型为评估指标负责。

### 4.5 决策层放置：机制层 + 预算分配（常被漏）
精排出 `(pCTR_nat, uplift)` 后，在**重排/机制层**新增"券分配"模块：
- 建模成 **MCKP 多选择背包**：每人从 {不发, 发3元, 发5元, 发8元} 选一档，约束总券成本≤预算，目标最大化 Σ增量价值。
- 贪心（滴滴外卖）：uplift 高→低、面额低→高，预算烧完停。
- 整数规划/ILP：离线 batch 精确解。
- E3IR（KDD'25）：端到端可微分配 + 单调/平滑约束，面额跟着梯度走。
- 美团 AAAI'23 警告：别把"ML 估 uplift"和"OR 做分配"做成两段甩锅——误差会累积，要用**决策因素桥**把两层连成一体（Direct Heterogeneous Causal Learning）。

### 4.6 预算 Pacing（常被漏）
券不是一次性撒完：
- PID 控制器：λ（放量乘数）按"实际花费 vs 目标"误差反馈；throttle（直接不投）vs bid-modify（调出价不改曝光，更平滑）。
- 迟滞控制器（Snap）：加迟滞后 λ 波动率降 54%，避免一会儿猛发一会儿停。
- ML pacing：直接学 delivery curve（什么时段放多少）。

### 4.7 评估与反作弊（常被漏）
- 离线 AUUC / Qini；线上必须随机分流做 holdout。
- 反作弊：downlift（HMUM）识别"发券反而掉转化"的人；RDD 去核销噪音防薅羊毛。

## 五、工业界真实做法（阿里/美团/腾讯/携程/滴滴/拼多多）

- **携程·火车票短信发券**：生产选 **T-Learner**（稳定可解释），也试过 GRF/TARNet；四象限人群分流。
- **滴滴外卖智能补贴**：**LightGBM uplift + 贪心/整数规划**分发，Qini/AUUC 评估（树模型+OR 分配典型组合）。
- **阿里文娱·淘票票智能票补**：**One Model 差分响应** + CIA 随机实验 + **用户价格敏感度曲线**校准 + **背包问题**分配。
- **CanniUplift（电商）**：**T-Learner + EUEN 解耦 control 网络优于共享表示**；平台级对齐 PGA + 兑换分解 RDD 去噪。
- **美团 AAAI'23 Direct Heterogeneous Causal Learning**：ML-OR 决策因素桥接，避免两段式误差累积。
- **E3IR（KDD'25）**：MCKP 端到端可微分配，单调性/平滑性域约束。
- 补充：VALOR（B2B treatment-gated）、HMUM（短视频多 treatment 异质 uplift，提 downlift）、CauseRec/CASR/CIRS（因果推断进推荐综述）。
- **拼多多智能优惠券硬约束（可直接引用的业务口径）**：每 10 元推广费抽约 5 元发券；单日有效券 ≤ 当日推广费 15%；单张券 ≤ 商品售价 70%；单品单日券 ≤ 该商品推广费 80%；**千人千面**按价格敏感度差异化发券。

## 六、改造后完整链路图

```
召回 ─┐（可加"券敏感人群"通道）
粗排 ─┤（可加 uplift 粗排）
精排 ─┼─ 输出 (pCTR_nat, uplift(x,c), value)   ← 改了分数 + 特征 + 损失
重排 ─┤
机制层 ─┼─ 新增【券分配】MCKP + Pacing λ         ← 新增模块
曝光 ─┘
评估：AUUC/Qini + 线上随机 holdout                ← 新增指标
```

## 七、面试答题模板（两种时长）

**30 秒版（先给结论）**：
"发券本质是把推荐目标从最大化转化改成预算约束下最大化净收益（增量价值减券成本）。所以不是加个特征，而是四件事：① 精排分数从 pCTR 换成 uplift（只对 Persuadable 人群加权）；② 特征加价格敏感度和核销率、且支持反事实查询；③ 样本必须随机发券对照（CIA）拿无偏 uplift；④ 在机制层做预算分配（背包/MCKP）加 Pacing 控放量，评估用 AUUC 而不是 AUC。"

**2 分钟版（展开 + 例子）**：
先讲目标函数变化 → 用小明/小红说明为什么 CTR 会把钱发给不需要券的人 → 四象限说明只在 Persuadable 发 → 模型选 T-Learner/CanniUplift 解耦 control → 样本讲随机实验+CIA、离线 PSM/IV → 训练损失 EUEN/PGA/RDD → 决策层用 MCKP + 美团 ML-OR 桥接避免两段误差 → 预算 Pacing 用 PID/迟滞 → 评估 AUUC/Qini + 反作弊 downlift → 收尾提拼多多 15%/70%/80% 硬约束体现预算边界。

## 八、易错点自查（别踩坑）

1. 说"把券面额当特征喂 CTR" = 错（钱发给 Sure Thing）。
2. 用 AUC 评估 uplift = 错（必须用 AUUC/Qini）。
3. 没提随机实验/CIA = 漏（样本无偏是前提）。
4. 只在精排改、没提机制层预算分配 = 漏（预算约束在机制层落地）。
5. 忽略 Do Not Disturb/downlift = 漏（有人发券反而掉转化）。
6. 两段式 ML+OR 甩锅 = 踩美团点名的误差累积坑（要桥接）。
7. 没提预算 Pacing = 漏（券要按天/时段控放量）。
