# Data Agent 开源项目调研（GitHub，2026-09-17）

> 目的：为 `scripts/data_agent/` 迭代找参照系 + 给「微信支付-数据科学」面试攒行业视野。
> 结论先行：**不引入重型平台，按"点"抄四个机制**——自学习回流（Vanna）、术语管理+语义修正（SuperSonic）、自我纠错+投票（APEX-SQL）、生产治理（audit/drift）。

## 一、项目全景（按参考价值排序）

## 二、评测基准视野（面试谈资）

- **BIRD**（NeurIPS 2023，12,751 问-SQL 对，95 真实库）：当前金标准，指标=执行准确率；**带 evidence（列值示例+schema 描述），用它 +3~8 分**——正好印证我们"目录+业务注释"路线
- **Spider 2.0**（企业级工作流，多库多方言）：GPT-4o 仅 10%，最强 agent ~35%——"真实企业库远比基准难"的论据
- VLDB 2026 论文：BIRD 等基准存在**系统性标注错误**，排行榜分数要打折看——评测集本身也要被评测（联动经验沉淀本的"规则升格"思想）
- 7B 量级专用模型 sqlcoder-7b-2 ≈57% BIRD——我们 qwen2.5:7b 的生成质量有专调模型可换

## 四、迭代路线（按投入产出，每周一步）

1. **W1 · 自学习闭环（抄 Vanna）**：ask 成功的问答对经用户确认后回流黄金集；ask 日志表（audit trail）
2. **W2 · 语义修正器（抄 SuperSonic）**：生成 SQL 后做列名/表名校验（对照目录），不存在则回喂报错让模型自修正，最多 2 轮
3. **W3 · 多采样投票（抄 APEX-SQL）**：长尾问题 n=3 采样，结果一致性做置信信号（不一致→降置信/澄清）
4. **W4 · eval 自动化**：评测接 workbuddy 自动化（周跑+推送准确率趋势=漂移监控）
5. 后置：Text-to-Chart（WrenAI 参照）、指标口径关系图当轻量 KG（面试答知识图谱的话术落地）

## 五、面试话术更新（一段话版本）

> "我给自己的数据仓库（8 库 90+ 表）做过一个 Data Agent：口径层优先、模板+生成混合路由、只读护栏三层防幻觉、黄金集评测做到 10/10。设计参照了 Vanna 的 RAG 自学习、SuperSonic 的语义修正和腾讯 APEX-SQL 的执行反馈自纠错——下一步是把成功查询回流做成闭环。"

对比原话术（§1"如果让我建我会怎么做"）——从假设句变成了进行时。
