一、ESMM 四版迭代 最硬的一段故事 · 必讲

背景（一句话）

主 feeds 排序原本是点击率单目标。但用户点进图集后会进入浮层"一拖 N"连续浏览—— 不同图集能拖出的 pv 是不同的（有的 2 个，有的 5 个）。只优化点击，就会推"好点但拖不动"的图集。 所以目标要从"点击"扩展到"点击 + 转化 pv"。
版本做了什么线上效果暴露的问题 / 为什么还不够
V1改样本构造：正样本从"点击"改成"点击 + 转化"，倾向推点击且转化的图集 —正样本变少，学习不充分（点击样本但转化 pv<1 的不算正样本了）
V2改损失函数：对每个样本按转化 pv 算权重 w，权重作用于该样本 loss，让 loss 对"转化 pv 高的点击样本"更敏感 +1.23%权重函数只是加权，本质是单目标打补丁，没有真正对转化目标建模
V3改模型结构：点击 + 转化多任务建模（三版不同权重函数并列试） +1.35%
+1.38%
+1.76%		两个塔各学各的，转化目标稀疏 + 训练/serving 资源消耗大
V4ESMM：底层共享 embedding，上层 CTR Net / CVR Net 双子网络，
pCTCVR = pCTR × pCVR，训练空间统一到曝光层		 +2.7%
消费 pv		 见下方"为什么还要动 loss"
V4 之后为什么还要改 loss（这是最可能追问的一层）：
转化样本有两个脏特性 —— ① 异常样本支配损失（转化 pv 长尾极大，异常值把分类边界拽歪）； ② 大量简单易分的负样本。所以我再叠了两个东西：
· 双稳态损失函数（Google 2019）：引入 t1∈(0,1) 约束逻辑损失的上界、t2∈[1,∞) 控制尾部衰减速度，降低异常样本对训练的影响；
· Focal loss：平衡因子 α 平衡正负样本比例，难易因子 γ 平衡难易样本，防止模型被简单负样本带偏；
· 最终优化目标 = 双稳态损失 + Focal loss → 消费 pv 相对 +2.7%。
加分收尾（主动说迁移性）："后来业务目标从点击+转化改成点击+时长，这套方案仍然适用—— 图集总时长相对 +8%，人均时长 +10%。所以我更愿意把它理解成一套'完整空间建模 + 抗噪损失'的方法，而不是绑定某个具体目标。"

二、MMoE 深度：你做过实验，不是背论文 专家退化 · 有第一手证据

业务背景（浮层场景）

短内容和长图文不同：用户在内容本身停留短，但互动需求强（评论/点赞/分享/下滑/不退出）。 而且没有明确的"点击"概念——所以主 feeds 用 ESMM，浮层用 MMoE。

① 目标怎么选（方法论，比模型本身更值钱）

候选目标结论
停留时长✅ 单 pv 时长↑、pv↓、总时长↑
进评论✅ 进评论率↑、评论区时长↑、总时长↑
点赞❌ 行为太稀疏，建模效果不佳
不退出 / 下滑❌ 样本量过大、高度冗余（大部分样本都成立）
时长+评论+点赞与"时长+评论"差不多 → 冗余，砍掉
三条选型原则（可直接口述）：
1. 目标不能太稀疏；2. 目标间不能太冗余；3. 目标间要有一定相关性。
相关性怎么衡量？用皮尔逊相关系数（Google 的做法）—— 原话我记的是"有相关性的任务能更好发挥作用，臭味相投、惺惺相惜、合作愉快；相关性太高则有冗余，取其一即可"。 实测：下滑与不退出相关性高（取其一），停留时长与进评论有一定相关性。

② 发现的坑：专家退化（这是你的一手证据，别浪费）

建模效果提升不明显时，我把 Gate 参数打出来看，发现两个目标只激活了一个专家—— 推测专家之间没学到差异性。这是 MMoE 最典型的失效模式，多数人只会背"多专家"，我是真的打印 gate 权重验证过。

③ 针对它做的三组实验

改法结果
改专家网络类型
DNN / FM / LR / CIN		DNN + FM + CIN 最佳
门控 + 定制共享部分
Self part / Share part（即 PLE 思路）		✅ 有效 —— 显式分离共享专家与任务独有专家，逼出差异性
专家组网络
引入 Expert leader，专家之间可交流、分层		⚠️ 目前未有明显提升，持续优化中（诚实说法，见下）

④ 调参结论（被问"你怎么调多目标模型"时）

  • expert num ↑ → 效果提升，但要在性能与效果间权衡
  • embedding size ↑ → 效果提升，同样是性能权衡
  • 时长阈值：不同阈值做过实验，最佳 7s，此时总时长指标最优
  • 训练方式对比过：交替式 vs 联合式
⚠️ 被问"专家组网络为什么没效果"——这样答：
"这也是我后来反思的点。专家之间加交流、加组长，直觉上应该更好，但实测没有明显提升， 我判断是组间通信引入了额外的优化难度，且没有对应的约束去保证组间差异性。 如果现在重做，我会先做消融确认是通信机制的问题还是组长聚合方式的问题， 再加正交约束 / 差异正则去显式拉开专家表征。这件事当时没有做完，是个遗憾。"

三、多目标召回 最有区分度的创新 · 建议主动带出

问题

精排已经是多目标，召回还是时长单目标，两层有 Gap —— 精排拿不到足够好的候选集。

三条方案的取舍

方案问题
① 多路单目标模型召回学习不充分 + 资源消耗大
② 多路单目标 + 多目标粗排链路更长，仍没解决候选集本身的问题
③ 多目标模型召回（选中）多目标共享训练数据、联合训练学习充分，架构支持目标扩展（可加点赞/分享/关注）

真正的坑：有效召回率（这段最显功力）

1
常规做法：每个目标的物品向量各建一份索引，线上拿到用户多份向量后各自召回 topK。
2
问题：按目标1 召回 1000 个 + 按目标2 召回 1000 个 = 2000 个候选， 但其中综合最优的只有 600 个 → 有效召回率仅 30%。因为精排要的是"综合最优"， 召回交出来的却是"各自最优"，两集合的交集部分才是有效部分。
3
我的做法：把多个目标向量 concat，把目标权重直接作用到对应向量上， 只建一份索引、一次请求。这样打分天然就是综合打分，直接召回综合最优候选集。
4
关键细节（务必说出来）：不能对 concat 前的向量做 sigmoid。 因为"两个 sigmoid 分数加权求和" ≠ "两个向量融入权重后 concat 再点积"——前者与预期不符。 分数就是两个向量点乘，向量展开重组后要能还原成加权求和的形式。
线上效果：单 pv 时长 +8%，短内容总时长 +4%。
方法论金句（收尾用）：
"排序是优中选优，召回是鱼龙混杂、良莠不齐中选出潜在优质—— 召回面对的环境更复杂，所以召回的样本要更兼顾全面：曝光未点击之外要补全局随机负采样和热度负采样， 因为曝光样本已经是上一版召回/粗排/精排替用户筛过的。"

四、时长建模消偏 小切口 · 体现问题意识

做法问题
传统做法对时长做回归 / 给每种内容类型设不同阈值做二分类
（段子阈值 a，Gif 阈值 b）		 ① 回归会倾向推"停留时长天然长"的内容；
② 每类型设阈值不够优雅，且阈值随数据分布漂移
我的做法分位相对判定：
duration_cur 与 duration_last_2hour_x_percent（过去 2 小时该内容停留时长的 x 分位）比较，
大于则为正样本，否则为负；x 由数据分布 + 线上 AB 实验确定		自适应、无需按类型设阈值
效果：浮层停留时长 +1.5%，大盘累计使用时长 +0.34%。

五、跨域 / 多品类推荐 简历"多品类统一推荐"的出处

结构：三方特征 + 三类专家 —— 小说特征→小说专家、图文特征→图文专家、共有特征→共享专家， 上层 Gate 分别出 pre_ctr_novel / pre_time_novel 与 pre_ctr_article / pre_time_article。 用图文（大域）的丰富行为去补小说（小域）的稀疏。
效果：相对仅用小说样本 —— 小说点击率 +8%，小说时长 +19%。
延伸（附录内容，被追问用）：MMoE + DSSM 做多目标召回 —— 原本 DSSM 召回是点击单目标， 改成点击 + 时长多目标（Expert0/1/2 + GateA/GateB，item feature 与 user feature 双塔）。 这项是指导新人完成的——如果被问到带人/影响力，这是现成素材。

七、方法论总结 & 前瞻 收尾拔高 · 他问"你怎么看推荐"时

"抛开一些 trick 来谈，总体是从目标导向出发——用目标驱动特征建设（特征体系）， 用目标驱动模型结构适配（ESMM / MMoE），再由特征反过来驱动模型结构调整（DIN）。 排序是目标、特征、模型的综合体，三者相辅相成，不可分割看待。"
