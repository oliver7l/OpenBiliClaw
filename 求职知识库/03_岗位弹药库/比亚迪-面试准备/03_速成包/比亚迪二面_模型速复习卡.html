算法背景面试官的讲法三原则：① 先给一句话定位，再讲结构，最后讲你改了什么（他不需要科普，需要看你理解到哪一层）； ② 主动说清"这个模型解决什么问题、不解决什么问题"，比背结构更打动人； ③ 被追问"和 XX 的区别"时，用问题驱动回答：它们解决的是不同问题（见下表），而不是背公式。

一、你简历上的模型全景：一句话定位 + 解决什么问题

模型一句话定位解决的核心问题你用在哪
DSSM
召回		 双塔向量召回：用户塔 / 物品塔各自出 Embedding，线上点积算分 把"匹配"变成向量检索，可离线建库 + ANN 检索，解决召回规模和时延；代价是两塔无法交叉特征（晚交互） 腾讯看点多品类统一召回；微视 EMB_DSSM / EMB_DSSM_NEW_USER
ESMM
排序/级联		 全链路多目标：pCTCVR = pCTR × pCVR，两个塔共享底层 Embedding 级联目标（曝光→点击→转化）的样本空间不对齐 + 转化稀疏 + 选择偏差（只在点击后样本学 CVR） 看点图集 2019.09 点击+转化、2019.10 点击+时长
MMoE
排序/平行		 多专家 + 多门控：共享若干 Expert，每个任务一个 Gate 加权 平行多目标（时长、互动、评论）互相冲突的"跷跷板"，用门控让不同任务选不同专家 短内容浮层精排（无量 3.0，BG 首个全量多目标业务）
MiNet
跨域		 跨域/多端兴趣迁移：源域辅助目标域，注意力做兴趣对齐 同一用户在多个端/场景行为稀疏或分布不同（QB / 小视频 / 个人主页），用小域数据补大域或反过来 腾讯多端统一推荐
GBDT / XGBoost
树模型		 集成树：GBDT 梯度提升（一阶），XGBoost 加二阶泰勒 + 正则 + 工程优化 中小规模、特征以稠密统计类为主时的强基线；可解释、抗噪声；XGBoost 相比 GBDT 多了正则项（防过拟合）+ 二阶信息 + 并行/缺失值处理 百度国际化应用商店 CTR 预估（eCPM +20%+）、CVR 预估
SSL4Rec
对比学习		 自监督对比学习 + 推荐：对序列/特征做扰动构造正负样本，拉近相似表示 行为稀疏、长尾 item / 新 item 表示学不好；用自监督信号补监督信号的不足 OPPO 分发推荐（对比学习 × 推荐）
Thompson Sampling
探索利用		 贝叶斯 bandit：对每个候选的收益做后验采样，按采样值排序 重排阶段的探索/利用：给新内容、低曝光内容出头机会，同时用不确定性自动调节探索量（不用手调 ε） 微视账号推荐重排（AB 有真实指标）
图嵌入召回
召回		 把用户-作者-内容建成图，随机游走 / GNN 学节点 Embedding 做相似召回 高阶关系：itemCF 只捕捉一阶共现，图嵌入能捕捉"相似账号的相似账号"；对关注/转粉这种稀疏关系更友好 微视账号推荐（追打召回、作者相似链）
DS-Chat / LLM+推荐
前沿		 用 LLM 做语义理解/预训练：appid 序列预训练 + 语义 Embedding 传统 ID 类特征无语义、冷启动差、跨域难迁移；LLM 补语义与知识 OPPO LLM+推荐预研（简历独立章节，二面重点）
PSM / DID
因果		 PSM 倾向得分匹配造对照；DID 双重差分剔除时间趋势 不能随机分流时的增量效果评估（金融/营销常见），控制选择偏差 + 时间趋势 中信营销策略归因（额度提升、定价对标）

二、最容易被追问的"区别题"（他一定会挑一个问）

1. ESMM vs MMoE —— 最高频

维度ESMMMMoE
目标关系级联/链式（曝光→点击→转化，有先后依赖）平行/并列（时长、互动、评论，无先后）
核心公式pCTCVR = pCTR × pCVR（乘法关系天然成立）y_k = gate_k(x) · [expert_1..n]，门控加权
解决什么转化稀疏 + 选择偏差 SSB（CVR 只在点击样本上训练）+ 样本空间不对齐任务间负迁移/跷跷板（相关性弱的多目标互相拖累）
为什么有效共享底层 Embedding，让稀疏的 CVR 塔跟着 CTR 塔一起学；把训练空间统一到曝光层多个 Expert 提供不同表征子空间，Gate 让每个任务自适应选择，冲突任务各用各的专家
局限只能处理有乘法链条的级联目标，平行目标用不上专家多了会退化/同质化（所有 gate 趋同），且不一定缓解跷跷板 → 进阶是 PLE（显式分离共享/独有专家）
你的讲法（30 秒）："这两个其实解决的不是一类问题。图集的点击-转化是级联关系，转化样本稀疏且只在点击后才有标签，所以上 ESMM，用曝光层对齐样本空间、pCTCVR=pCTR×pCVR 把稀疏目标拆出来训。短内容浮层的时长和互动是平行关系，互相打架，所以上 MMoE，用门控让两个任务选不同的专家。如果再往后做，平行目标的跷跷板更彻底的解法是 PLE，把共享专家和任务独有专家显式分开。"

2. 双塔（DSSM）为什么用于召回而不是精排？

  • 速度：物品塔可离线算好建 ANN 索引（HNSW/IVF），线上只算一次用户向量 → 毫秒级，可覆盖千万候选
  • 代价：用户和物品直到最后点积才交互，无法建模交叉特征（如"用户历史里有没有这类题材"），表达力弱于精排的 DIN/DIEN/DeepFM
  • 追问预备：怎么补救？→ 用户塔输入序列 + attention（DIN 思路）、加"历史点击 item 向量池"做 target attention 前置于双塔、或双塔后接一个轻量交叉层（如 COLD / 双塔+浅层交叉）

3. itemCF / Swing vs 图嵌入 vs 双塔 Embedding（召回三兄弟）

方法信号来源优势短板
itemCF / Swing共现矩阵、一阶邻居可解释、实时性好、冷启动快（新 item 有几次行为就能算）只有一阶关系，长尾稀疏
图嵌入（EGES/GNN）多跳邻居、高阶结构能挖"相似的相似"，对稀疏关系（关注/转粉）友好训练与更新成本高，实时性差
双塔 Embedding监督目标（点击/转化/时长）直接对齐业务目标，端到端可优化多目标依赖样本量，冷启动差，需要 ANN 基建
讲法："工程上我们是多路召回并行——itemCF 保底可解释、图嵌入补高阶、双塔对齐业务目标，最后混排。它们不是替代关系，覆盖的候选空间不一样。"

4. Thompson Sampling vs UCB vs ε-greedy（重排探索）

  • ε-greedy：固定概率随机探索 → 简单但探索量与不确定性无关，浪费流量
  • UCB：均值 + 置信上界（乐观面对不确定性）→ 确定性策略，探索量随观测次数自动下降
  • Thompson Sampling：从后验分布采样，按采样值排序 → 随机化策略，天然带多样性，实践上在 CTR 场景常优于 UCB，且易与业务先验（Beta-Binomial 共轭）结合，计算便宜
  • 你为什么选 TS：后验方差随曝光收敛，新内容自动多曝、老内容自动收敛，不需要手调探索率；且采样带来结果多样性，正好契合"账号推荐要让用户发现新作者"这个目标

5. PSM vs DID vs AB（营销归因）二面营销方向重点

方法适用控制什么你的例子
A/B可随机分流一切混淆（Randomization）能分流的策略：策略客群 vs 对照客群
PSM不能随机，但有可观测协变量选择偏差（高额度用户本身资质更好）额度提升效果：匹配"资质相似"的对照用户
DID不能随机，但有前后两期数据时间趋势 + 固有差异（需平行趋势假设）策略上线前后对比 + 剔除自然趋势
讲法："金融里部分策略涉及全量客群，不能随机分流，所以我用 PSM 造可比对照、DID 剔时间趋势，并明确标注这是准实验、保守估计——这个口径要主动暴露，比硬说'我证明提升了 X%'可信得多。"

三、其他高概率考点（算法背景面试官会顺手问）

A. 校准（OPPO 多位置偏差 30%→20%）

  • 为什么偏：负采样/采样率还原、位置偏差（曝光位置越靠前点击越高）、多位置分布不一致
  • 怎么做：负采样率还原公式、保序回归 / Platt Scaling（对 pCTR 做单调校准）、分位置分场景单独校准 + 融合
  • 评估指标：不只是 AUC，看 PCOC（预估/实际）、Calibration Error、分桶校准曲线

B. 冷启动

  • 用户侧：新用户桶（NEW_USER）单独召回池、人口属性/上下文兜底、快速兴趣收敛（explore_state 档位 10/20/30）
  • Item 侧：冷启动分档池（一/二/三档渐进曝光）、贝叶斯平滑处理少量曝光的高方差统计
  • OPPO 广告侧可补充：探索池 10%、冷启通过率 +15%、新广告曝光 +30%

C. 多目标融合怎么定权重

  • 手工网格搜 → 在线实时搜参 → 贝叶斯优化（高斯过程 + 采集函数）
  • 你做过的：无量 3.0 上多目标融合自动调参（离线网格 + 在线实时搜参 v3 + 贝叶斯）
  • 选参策略：AUC 不劣化 + 时长提升 + 互动提升 + 约束 VV 不掉，多条件筛选后排序取优

D. 离线/在线评估

  • 离线：AUC / GAUC（分组 AUC，工业界更靠谱）/ 召回率@K；注意离线涨不一定线上涨（样本偏差、position bias）
  • 在线：AB 置信度（你说 4 格置信度）、大盘指标与场景指标分层看，防止"场景涨大盘跌"
  • 留存类要看长窗口（广义 DAU 留存 +0.07%）

E. 时长/连续目标怎么建模

  • 三种方式：回归（MSE）、分档分类、顺序/生存分析（观看时长的截断问题）
  • 坑：时长与视频时长强相关，直接回归会被长视频主导 → 归一化 / 分位数 / 加权

F. LLM + 推荐（二面重点，见专项文档）

  • 三层切入：① 召回用语义向量补冷启动/跨域；② 排序把 LLM Embedding 当强语义特征；③ 判别式→生成式，Prompt 控多目标
  • 你的弹药：appid 序列预训练、DS-Chat 训练环境
  • 落地顾虑要给：推理时延（离线生成 Embedding / 蒸馏到小模型）、成本、效果边界

四、讲模型时的"防追问"话术模板

结构：问题 → 为什么老方案不行 → 模型怎么解决的 → 我具体改了什么/踩过什么坑 → 效果数字 → 局限和下一步

示例（MMoE）："问题是短内容浮层的时长和互动互相打架，单目标模型一起训会出现跷跷板，一个涨一个跌。MMoE 的做法是放多个专家网络、每个任务配一个门控自适应加权，让冲突任务各用各的表征子空间。我在无量 3.0 上把它接进去全量，成为 BG 第一个跑通多目标的业务。效果上大盘时长 +0.42%、互动 +35%、浮层时长 +6.8%（4 格置信度）。局限是专家训练到后面会趋同，如果再做我会考虑 PLE 把共享和独有专家显式分开。"
数字口径（严格按简历，别注水）：腾讯：大盘时长 +0.42%、互动 +35%、浮层时长 +6.8%、短内容总时长 +2.85%、广义 DAU +0.10%、留存 +0.07%；召回侧进评论率 +80%、篇均时长 +8%、总时长 +4%。OPPO：偏差 30%→20%、ARPU +1.04%、云端负载 -25%。百度：eCPM +20%+。中信：客群 3819万/1944万/678万、抢夺规模 3.8 亿/月、办理率 +10%。
