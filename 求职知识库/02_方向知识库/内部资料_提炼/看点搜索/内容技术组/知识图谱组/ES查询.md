## 关键方法 · 模型 · 指标
- 支持对返回结果按多种策略进行排序
- 在线查询请求分流，减小Neo4j图引擎负载
- 但是在实际使用中，我们经常需要通过别名查询实体，或者通过模糊匹配进行查询，所以亟需图谱进一步拓展检索方式，以支持更多应用场景，更好的为业务赋能
- labels : string list ，需要匹配实体的标签(领域)，要求参数用 [] 符号修饰，多个标签是 AND 关系，标签内以_分隔是OR关系，如果为空则直接填 ""
- 6.2 性能优化
- 支持查询结果按权值进行排序
- 2. 默认以score字段倒排序
- 支持按条件批量导出功能，解放图谱人力
- 3. labels可以不写领域完整路径
- 查询接口逐步按需提供元数据查询、状态查询、统计汇总等等需求，实现图谱中台化
- 注意：1. label、properties里面的属性字段不要用单引号或双引号包含
- 更改图谱数据在线Query格式，对外表现为统一接口，以语义更丰富的Json区分请求
- 2. labels、properties和fuzzyProperties不能同时为空
- 返回的实体列表以Json数组形式，每个实体格式与图谱hive表中一致，只是data里只保留属性名与属性值
- 示例： "[name:[ '德华 '], alias :['华仔', '华哥']]" （查询名称模糊匹配到德华，同时别名模糊匹配华仔或者华哥）
- 注意：1. sort的key-value list 不需要[]修饰，如果不需要指定排序情况，则直接填空字符串""，里面的属性字段不要用单引号或双引号包含
- fuzzyProperties : key-value list ， 实体属性（暂时只支持名称和别名） 模糊匹配（切词匹配） 的值列表，其他要求同properties一致
- getEntityByNameAlias ( labels, properties, fuzzyProperties, sort, limit, except, nodeFilter )
- PCG图谱中台，融合了QQ浏览器、腾讯新闻、腾讯视频、游戏内容生态中心先知游戏图谱、IEG增值服务部游谱等众多图谱数据，力争提供最大、最全、最好的百科+垂类知识图谱产品，现在已经广泛的应用于PCG各个业务上
- properties : key-value list ， 实体属性（暂时只支持名称和别名） 精确匹配 的值列表，要求参数用 [] 符号修饰，每个元素是一个 key-value 对，标识要过滤的属性字段和过滤字段的值，如果为空则直接填 ""
- 在调用方式上，PCG中台图谱将图谱数据存储在Neo4j中， 并通过TAF服务封装了对图引擎的各种查询方式，各业务方通过调用中台提供的丰富APi进行数据查询，能够通过名称或者实体ID进行精确查询，按领域或者属性值进行过滤，满足低延时、高性能、强稳定等等优点
- sort : key-value list ， 指明实体返回结果排序信息， key-value 中的 key 为属性字段， value 为排序方式（ -1 ：降序、 1 升序）， key value 通过冒号分割，多个 key-value 对通过逗号分割
- getEntityByNameAlias("[影视明星 ]", "[alias:[ '华仔 ','华哥'] ]", "[name:['德华']]", "rank:-1", "50", "", "") // 查找影视明星中，别名包含“华仔”或者“华哥”且名称模糊匹配“德华”的实体，按rank倒排，返回前50个
