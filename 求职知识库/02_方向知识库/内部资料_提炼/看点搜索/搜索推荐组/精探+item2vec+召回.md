## 关键方法 · 模型 · 指标
- 向量 UCF：通过当前文章 doc1 的 embedding 召回若干（100）相似文章 doc2，再把 doc2 点击过的词 query 推给 doc1
- End2end 向量召回：直接通过文章 embedding 召回相似的 query embedding
- 调研 graph embedding 的过程见志远的文档： 图embedding方法的总结 、 Plato调研
- query 不参与训练，query embedding 都是模型估的，模型从文章学习
- 为了比较各种方法召回的相关性，预先训练一个独立的语言模型用来评估召回结果的（字面内容上的）相关性，作为独立的评估基准
- 当前使用 graph embedding 的一个问题是使用 doc-doc 或 doc-query 共现建图会把一些不相关的节点连接起来
- 这个方法主要是要解决模型召回的邻近物品（doc 或 query）不相关的问题
- 调研 item2vec 的缘起是为了解决 graph embedding 的不足
- 使用用户行为构造会话路径，用户行为包括对所有物品的交互，如浏览文章、点击推荐搜索词、主动搜索等
- 对于一个待评估召回模型，随机选择1000篇文章，每篇文章召回前20个搜索词（或相似文章），然后用相关性模型计算平均相似度
- 10%小流量实验效果（CTR 取2020.8.9 - 2020.8.15平均，其他取2020.8.9线上统计数据）：
- 文章向量没练好，召回的相似文章也很奇怪
- doc-qury 向量空间距离计算方法：欧氏距离，余弦相似度
- 默认使用全量用户一天的数据，有些模型使用了全量用户一周数据会注明
- 为了保证 query 质量，限制召回的 query 是线上有点击过的
- 向量长度越大，语义区分的越开，召回的文章或 query 就越相似，是符合预期的
- 长度短的向量欧氏距离也较近，在靠近原点的地方会偶尔召回一些方向不同但距离较近的点
- 以下实验训练数据 = 天级会话，subword，向量长度 = 100，迭代轮数 = 5
- 最终上线模型：天级会话，subword，窗口大小 = 2，向量长度 = 256，迭代轮数 = 5
- 虽然红框中的文章有的是影视相关，有的和用户兴趣有关，但内容层面和《三十而已》较远，不符合相关推荐对于相关性的要求
