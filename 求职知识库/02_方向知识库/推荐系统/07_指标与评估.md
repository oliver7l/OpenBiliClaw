## 一、推荐系统指标体系全景

我在腾讯QQ看点做推荐数据分析时，搭建了从北极星到过程指标再到漏斗指标的完整指标体系。推荐系统的评估不能只看单一指标，需要分层设计、互相校验。

### 1.1 指标层级设计

| 层级 | 指标名 | 定义 | 用途 |
|------|--------|------|------|
| **北极星指标** | DAU / 信息流DAU | 日活跃用户数（严口径：当日有主feeds真实曝光） | 衡量产品整体健康度，推荐最终目标是留住用户 |
| **北极星指标** | 人均使用时长 | 产品使用总时长/DAU | 衡量用户消费深度，推荐质量的最终体现 |
| **北极星指标** | 月活跃天数 | 用户一个月内活跃天数 | 衡量用户粘性，比"一周使用5次"更能反映依赖度（来源：QB分析handbook） |
| **过程指标** | 曝光PV / 曝光UV | 推荐内容曝光量/曝光用户数 | 衡量推荐覆盖广度 |
| **过程指标** | CTR（点击率） | 点击PV/曝光PV | 衡量推荐精准度，核心排序指标 |
| **过程指标** | 消费VV / 消费PV | 视频播放量/图文阅读量 | 衡量内容消费深度 |
| **过程指标** | 人均消费VV | 总消费VV/消费用户数 | 衡量单用户消费深度 |
| **过程指标** | 完播率 / 阅读完成度 | 完整播放数/播放数 | 衡量内容质量与推荐匹配度 |
| **过程指标** | 1s快划率 | 1秒内划走的比例 | 负反馈指标，衡量推荐不匹配程度 |
| **互动指标** | 点赞率 / 评论率 / 分享率 / 收藏率 | 互动行为数/曝光数 | 衡量用户参与度与内容质量 |
| **互动指标** | 关注率 / 关注UCTR | 关注行为数/曝光卡片数；关注用户数/实验用户数 | 社交推荐核心指标（来源：好友推荐指标建设） |
| **留存指标** | 次日留存 / 7日留存 | 次日/7日后仍活跃的用户比例 | 推荐长期价值的最终衡量 |
| **漏斗指标** | 大盘DAU→信息流DAU转化率 | 信息流DAU/大盘DAU | 衡量推荐场景的用户渗透 |
| **漏斗指标** | 曝光→点击→消费→互动→关注转化率 | 各环节转化率 | 定位推荐链路瓶颈 |

### 1.2 QQ看点/QB的指标层级实践

在QQ看点和QB（QQ浏览器）双端做推荐时，我注意到两端指标口径需要对齐：

- **看点端**：DAU为财报广义DAU，信息流消费是核心场景
- **QB端**：DAU有宽口径和严口径之分，严口径信息流DAU才是推荐真正影响的用户群。QB大盘流水表每天1.3亿人，join严口径DAU后8000万，刨除延迟上报后仅剩6900万，其中信息流用户4100万（来源：qb大盘到qb信息流路径漏斗）

> **面试口述版**：我在QQ看点做推荐数据分析时，指标体系分三层：北极星是DAU和人均时长，过程指标是CTR、消费VV、完播率，漏斗指标是从大盘到信息流再到曝光点击消费的逐层转化。特别要注意口径一致性——QB有宽口径和严口径DAU，推荐只对严口径信息流用户负责，大盘里有大量僵尸用户和纯浏览器用户，不能混在一起评估。

## 二、QB分析Handbook

### 2.1 分析师核心素养

我在QB团队时，内部handbook强调分析师要永远问自己三个问题：
1. 我是否真的找到了一个值得解决的问题？
2. 我是否真的很想或者能够解决它？
3. 我所提出的解决方案或者归因是否真的正确？

同时借鉴滴滴分析师十条：核心能力是思辨、对讲真话负责保持中立、论据充分论证严谨观点简明、**数据先于观点而不是观点先于数据**、分析什么问题往往比用什么方法更重要、好的分析师给别人输入而不只是帮别人输出。

### 2.2 分析框架

| 分析维度 | 核心问题 | 关键指标 |
|----------|----------|----------|
| 指标体系大盘 | 整体健康度如何？ | DAU、时长、留存、活跃度分布 |
| App获取分析 | 获客效率如何？ | 渠道ROI、渠道留存、获客成本 |
| 用户画像分析 | 用户是谁？ | 人口属性、兴趣标签、TGI |
| 用户粘性分析 | 用户有多依赖产品？ | 月活跃天数、使用频次、间隔天数 |
| 用户生命周期流转 | 用户在各阶段如何流转？ | 新增→成长→成熟→衰退→沉默转化率 |
| 核心功能拆解 | 用户真的在用核心功能吗？ | 功能渗透率、使用频次、Magic Number |
| 行为路径分析 | 用户主操作路径是什么？ | 路径分布、Aha Moment、操作流断点 |
| 用户使用时长分析 | 用户用了多久？分布如何？ | 时长分布、人均时长、异常点 |
| 跨平台分析 | 跨平台用户占比？ | 移动端/PC端重合度、跨端导流 |

### 2.3 渠道ROI评估方法

业内通行方法是对以下六个角度打分（十分制，取平均分）：
- **成本**：预计花费
- **定向**：是否容易接触到目标受众
- **控制**：多大程度可以控制试验、终止和调整
- **时间投入**：启动试验需要多久
- **产出时间**：多久拿到结果
- **规模**：渠道规模量

### 2.4 关键分析洞察（来自handbook实例）

- **用户粘性**：月活跃天数是比"使用次数"更好的粘性指标。一周内使用5天比一天内使用5次更能反映用户依赖度（来源：QB分析handbook）
- **新用户留存**：QB活跃用户留存优势明显，但新用户留存没有优势甚至偶尔劣势，新用户留存需要重点关注
- **feeds消费**：看热点的用户群留存明显高于其他群组，引导用户"看热点"是提升留存的有效手段
- **搜索用户**：命中搜索直达的用户留存率在以肉眼可见的速度变好
- **小说tab**：用户留存在显著变差
- **核心功能**：名画识别UV比植物高，但PV/UV接近1，说明名画是一次性需求，植物是多次性需求，需要不同的运营策略

> **面试口述版**：我在QB做分析时，handbook里最核心的原则是"数据先于观点"。分析框架覆盖九个维度：大盘、获客、画像、粘性、生命周期、核心功能、行为路径、时长、跨平台。做渠道评估时我们用六维打分法：成本、定向、控制、时间投入、产出时间、规模。一个关键洞察是：月活跃天数比使用次数更能衡量粘性——一周用5天和一天用5次完全是两个概念。

## 三、离线评估指标

### 3.1 离线评估体系设计

我在QQ看点负责推荐算法离线评估时，搭建了覆盖召回质量、多样性、新颖性、热门覆盖等维度的离线指标体系。离线评估是算法迭代的第一道关卡，目标是在上线前快速筛选出有潜力的算法。

### 3.2 核心离线指标详解

| 指标名 | 定义 | 用途 | 来源 |
|--------|------|------|------|
| **HitRate（命中率）** | 单个用户召回结果topK与播放序列topK的交集数，整体取平均 | 衡量召回的准确性，最核心的召回指标 | 离线评估指标项目 |
| **DurationRate（时长加权命中率）** | 在HitRate基础上加上播放时间作为权重 | 衡量召回内容的消费深度，比纯命中率更贴近真实体验 | 离线评估指标项目 |
| **CoverRate（覆盖率）** | 这批用户召回的topK的总item数 | 衡量召回的覆盖广度，防止召回过于集中 | 离线评估指标项目 |
| **NoveltyRate（新颖度）** | novelty = 1 - (historyrate/100.0)，historyrate为召回结果与历史播放序列的交集比例 | 衡量推荐的新颖性，防止过度推荐历史内容 | 离线评估指标项目 |
| **HistoryRate（历史重复率）** | 召回结果中与过去播放序列的交集比例 | 与NoveltyRate互补，监控重复推荐 | 离线评估指标项目 |
| **Entropy（类目熵）** | 信息熵公式计算每个用户下的类目熵，整体取平均，数值越大种类越多 | 衡量推荐结果的多样性 | 离线评估指标项目 |
| **TypeNum（类型数）** | 每路召回里电影、电视剧、综艺、少儿、动漫、纪录片的平均个数 | 监控各内容类型的召回数量分布 | 离线评估指标项目 |
| **TypeRate（类型覆盖率）** | 每路召回里各内容类型的覆盖率 | 监控各内容类型的召回覆盖 | 离线评估指标项目 |
| **Simi（召回相近度）** | Jaccard similarity，监控算法间结果是否过于相近 | 防止多路召回结果同质化，导致加一路召回效果不明显 | 离线评估指标项目 |
| **NewCoverRate（新热覆盖率）** | 召回里对新热剧（最近一周/半月/一月上架专辑）topK的覆盖率 | 衡量新内容的召回能力，冷启动相关 | 离线评估指标项目 |
| **NewCoverNum（新热覆盖数）** | 召回里对新热剧topK的覆盖数量 | NewCoverRate的绝对值版本 | 离线评估指标项目 |
| **HotCoverRate（热门覆盖率）** | 热门cid覆盖率（天热为天播放次数top100，周热为周播放top100） | 衡量热门内容的召回能力 | 离线评估指标项目 |
| **HotCoverNum（热门覆盖数）** | 热门cid覆盖量 | HotCoverRate的绝对值版本 | 离线评估指标项目 |
| **CidTimeAvg（平均剧集时长）** | 召回列表里cid的平均剧集时长（分钟） | 监控召回内容的时长分布 | 离线评估指标项目 |

### 3.3 排序模型离线评估

排序模型的离线评估除了上述召回指标外，还包括：
- **AUC**：ROC曲线下面积，衡量排序模型整体区分能力
- **GAUC**：分组AUC，按用户分组计算AUC后加权平均，消除用户本身活跃度差异的影响，更能反映排序质量
- **NDCG**：归一化折损累计增益，衡量排序位置的准确性，高相关内容排在前面得分更高
- **Recall@K**：topK召回中命中正样本的比例
- **Precision@K**：topK中真正样本的比例

### 3.4 离线与在线一致性

离线指标和在线指标经常出现不一致，我在实践中总结了几个关键原因和应对方法：

**不一致的原因：**
1. **离线评估的样本偏差**：离线用历史数据评估，用户已经看过的内容不会再点击，但离线评估时不排除已曝光内容
2. **位置偏差**：离线评估不考虑展示位置对CTR的影响，而在线上位置偏差显著
3. **探索与利用的平衡**：离线评估倾向于利用已知偏好，线上需要探索新内容
4. **延迟反馈**：视频消费、留存等指标有延迟，离线即时指标无法捕捉
5. **生态影响**：单用户体验提升不代表整体DAU提升，可能存在挤出效应

**应对方法：**
- 离线评估时排除用户已曝光内容
- 引入位置偏差校正（IPW等方法）
- 建立离线-在线相关性监控，定期校验
- 离线指标作为初筛，最终以上线AB实验为准

### 3.5 冷启动离线评估

冷启动场景的离线评估有特殊性。我在做离线冷启训练时，使用了DQN（深度Q网络）框架，将卷积层替换为全连接层，隐单元个数设定为512,256,128,64（来源：离线冷启训练实现与分析）。

**Reward设计**：reward定义为(auc, mean_watch_duration, mean_duration, click_propotion, like_propotion, baseline_score)与权重向量w的内积。

关键发现：
- reward权重的选择对结果影响极大。w=(1,0.01,0.05,1,1,0)时算法倾向于选择alpha较小的action
- 修改为w=(1,0,0,1,10,0)后结果相对正常
- 加入baseline_score惩罚项（w中最后一个参数）可以约束模型不偏离线上策略太远，但权重过大会导致模型不收敛（w=(1,0,0,1,10,1)时loss不下降）
- w=(1,0,0,1,10,0.2)时约2/3状态选择线上策略，penalty项发挥了效果

> **面试口述版**：我在QQ看点搭建了推荐离线评估体系，召回侧有15个指标，核心是HitRate（命中率）、DurationRate（时长加权命中率）、CoverRate（覆盖率）、NoveltyRate（新颖度）、Entropy（类目熵）、Simi（多路召回相近度）。排序侧用AUC、GAUC、NDCG。离线和在线不一致是常态，主要原因是样本偏差、位置偏差和延迟反馈。我们的做法是离线做初筛，最终以上线AB为准，同时定期做离线-在线相关性校验。冷启动我用DQN做过离线训练，reward权重设计非常关键，加baseline惩罚可以约束不偏离线上策略，但权重太大会不收敛。

## 四、用户分群与核心用户分层

### 4.1 QB用户分群模型

我在QB做用户分群时，设计了一个三维度的分群模型，定位是"介于千人一面和千人千面之间"——既不像千人一面那样呆板，又不像千人千面那样不可控。

**分群维度选择**（三个维度，理由是相关性偏弱、张量夹角大，且业务含义充分、抓手明确）：

| 维度 | 指标名 | 字段 | 取值范围 |
|------|--------|------|----------|
| **频次** | 最近30天活跃天数 | active_days_month | [1,30] |
| **逛** | 主feeds真实曝光次数 | exp_main_tl | [0,++) |
| **消费** | 产品使用时长 | duration_session | [0,++) |

**分群节点划分**（抽样样本量943,726，分为64个组，平均每组约1.4万，分组均匀）：

| 节点 | 频次（活跃天数） | 逛（曝光次数） | 消费（时长/分钟） |
|------|------------------|----------------|-------------------|
| 节点1 | 5 | 5 | 30 |
| 节点2 | 15 | 10 | 120 |
| 节点3 | 25 | 30 | 300 |

每个维度按节点切分为4档，3个维度共4×4×4=64个用户群。

**重要背景**：建议用信息流DAU而不是大盘DAU做分群，因为大盘DAU有大量僵尸用户（来源：QB用户分群模型）。

### 4.2 核心用户特征分析

#### 4.2.1 核心用户定义

我在QQ看点定义核心用户为：**主动且较稳定地使用看点的用户 = 某周活跃后下周依然有超过2天使用看点的用户**。

选取五月最后一周用户，判断六月第一周使用天数是否超过2天。

#### 4.2.2 核心用户特征提取方法

使用**SkopeRules模型**（基于决策树的规则提取算法）提取核心用户特征，参数配置：
- max_depth=7, max_depth_duplication=20, n_estimators=30
- precision_min=0.5, recall_min=0.05
- 特征：exp_main_tl, duration_session, inter_zan_cnt, inter_collect_cnt, inter_share_cnt, main_tl_reflash_cnt, main_tl_slideup_cnt, chan_reflash_cnt, app_enter_cnt, total_consume_cnt, active_days

#### 4.2.3 核心用户三大特征

从SkopeRules提取的15条高置信规则中，概括出核心用户的三条主要特征：

| 特征类型 | 具体条件 | 规则精度 |
|----------|----------|----------|
| **高频活跃** | 一周活跃6天以上 | 最高98.9% |
| **中频活跃+足够进入次数** | 一周活跃5天且app进入≥7次；活跃4天且进入≥6次；活跃3天且进入≥5次 | 90%-95% |
| **低频活跃+足够时长** | 一周活跃1-2天，且总时长大于11分钟 | 68%-82% |
| **互动行为** | 有点赞、收藏、分享行为的用户 | 直接视为核心用户 |

**核心用户规模**：
- 按定义圈定的核心用户：**97,816,754，占一周用户51.8%**
- 通过提取特征筛选出的核心用户：**93,081,176，占49.3%**（来源：核心用户特征分析和分层）

### 4.3 核心用户分层与内容消费关联

使用**CCA（典型相关分析）**分析用户赛道×品类消费变化与用户表现（总时长、活跃天数变化）之间的关系。

#### 4.3.1 曝光PV变化与用户表现的关联

核心用户每月时长和活跃天数的变化趋势与以下品类曝光PV变化**正相关**（按相关性从大到小）：

**最强相关**：网红达人、搞笑、生活、社会
**较强相关**：游戏、娱乐、科学、电视剧、美食

#### 4.3.2 点击PV变化与用户表现的关联

- 相比曝光PV，点击PV变化与用户表现变化的关联性相对小一些
- 6-7月（M3）对应的变量明显比M1、M2多，说明六七月份核心用户点击变化与用户表现变化相关性更大
- 四五月份：娱乐、电视剧、网红达人、美食、游戏、电影、综艺正相关
- 六七月份：游戏、电视剧、网红达人、生活、娱乐、搞笑、动漫、综艺、电影、教育正相关，其中娱乐、电视剧、网红达人、生活、游戏相关性最大

#### 4.3.3 周内不同日期的内容偏好差异

| 时间段 | 与时长占比相关性最强的品类 |
|--------|---------------------------|
| **周六周日** | 生活小视频、网红达人小视频、搞笑小视频、游戏短视频、电视剧短视频、电影短视频 |
| **周一周三周五** | 生活小视频、搞笑小视频、游戏短视频、娱乐小视频、娱乐图文、电影短视频 |
| **每日通用** | 生活小视频始终是影响时长占比最大的品类 |

相比周末，工作日的娱乐品类与时长占比相关性更高，电视剧、网红达人品类相关性更低。

#### 4.3.4 QB信息流核心用户选择标准

周总时长大于84分钟，或至少有关注/分享/点赞/评论其中一种行为，或周活跃4-5天且后台点击>4.5次，或周活跃4-5天且周时长>12分钟，或周活跃>5天。

### 4.4 用户分层对比表

|----------|------------|----------|--------|----------|------|

## 五、次活模型与留存预测

### 5.1 次活模型定义

我在QB搭建了次活预测模型，目标是**预测月活用户次日是否会主启**（主动打开APP）。

**正负样本定义**：
- 全部样本集合：月活用户（包括T日往前28天内活跃的用户）
- 正样本：月活用户中，T+1日有主启的用户
- 负样本：月活用户除正样本外的其他所有用户

### 5.2 特征工程

| 特征类别 | 具体特征 | 预处理方式 |
|----------|----------|------------|
| **活跃状态特征** | 近7/14/21/28天的累积活跃天数、累积主启天数、累积时长 | 数值特征 |
| **活跃序列特征** | 近30天活跃状态(0/1)、主启状态(0/1)、当日时长的序列化表示 | 序列特征 |
| **基础画像** | 年龄、性别、星座、手机类型、运营商、学历 | OneHot编码 |
| **端内行为** | 每日总PV、总曝光等 | 初版未使用 |

### 5.3 模型架构与效果

**模型**：Embedding + WDL（Wide & Deep Learning）

**数据摸底（2020年8月）**：

| 日期 | 日活表 | 当日有主启 | 主启占比 |
|------|--------|-----------|----------|
| 20200801 | 126,018,039 | 85,282,541 | 67.67% |
| 20200802 | 121,529,666 | 83,206,282 | 68.47% |
| 20200805 | 135,134,106 | 90,185,995 | 66.74% |
| 20200806 | 134,349,472 | 89,555,619 | 66.66% |
| 20200807 | 132,780,994 | 86,166,823 | 64.89% |

**训练效果**：
- 正例8kw，按1:1负采样，得到8kw样本
- 训练集（0815分区）：**AUC=0.86**
- 测试集（0816分区）：**AUC=0.88**
- 预测集（0818分区）：**AUC=0.84**

**不同阈值下的精确率和召回率**：

| 用户群 | 阈值 | Precision | Recall |
|--------|------|-----------|--------|
| 月活用户 | 0.8 | 76% | 50% |
| 月活∩T+1日活（次日真正受影响用户） | 0.7 | 89% | 56% |

**训练集扩充为三日后**（0815-0817训练，0818测试）：**AUC=0.849**

### 5.4 模型输出与应用

输出GSP标签：次日活跃打分，以0.1为步长，范围0.5-0.9。

应用场景：
- 对高概率次日活跃用户进行差异化运营
- 对低概率用户进行召回干预（Push、红点等）
- 作为用户生命周期管理的输入

### 5.5 留存预测方法论

次活模型本质上是短期留存预测（次日），更长期的留存预测可以：
- 扩展预测目标：7日留存、14日留存、30日留存
- 增加时间窗口特征：用户生命周期阶段、历史留存模式
- 结合内容消费特征：消费品类多样性、消费深度变化趋势
- 使用生存分析模型：预测用户流失时间点而非二分类

> **面试口述版**：我在QB做过次活预测模型，目标是预测月活用户次日是否主动打开APP。用Embedding+WDL架构，特征包括近7/14/21/28天的活跃天数、主启天数、时长，近30天的活跃序列，以及基础画像OneHot。正负样本1:1采样各8kw，训练AUC 0.86，测试AUC 0.88，预测AUC 0.84。在月活∩次日日活的用户群上，阈值0.7时precision 89%、recall 56%。模型输出0.5-0.9的打分标签，用于差异化运营和召回干预。

## 六、DAU异常拆解方法论

DAU异常拆解是数据科学岗面试最高频的考点之一。我在QB经历过DAU持续六周下降的完整拆解，形成了一套系统化的方法论。

### 6.1 DAU下跌拆解框架

```
DAU下跌
├── 1. 确认问题：跌幅、持续时间、是否季节性
├── 2. 人口属性拆解：年龄、城市等级、性别、手机品牌
├── 3. 活跃度拆解：高活/中活/低活/沉默用户的流转变化
├── 4. 业务渗透拆解：各业务（资讯/小说/搜索/文件等）用户的变化
├── 5. 归因分析
│   ├── 高活用户下跌归因（CART决策树建模）
│   ├── 资讯用户下跌归因（内容类型对留存间隔的影响）
│   ├── 小说用户下跌归因（产品变更、竞品影响）
│   └── 运营策略变更（红点、Push、活动等）
├── 6. 路径漏斗分析：首启→主启→信息流→消费各环节
├── 7. 外部因素：竞品、季节性、疫情等
└── 8. 结论与行动建议
```

### 6.2 六周下降案例详解

**问题定义**：2020年6月15日（周一）-7月26日（周日），共六个自然周，QB DAU呈现线性下降趋势。

**背景事实**：
- 最近一年QB大盘DAU经历了三升三降
- 此时间段刚好是北京新发地二次疫情后的回落期
- 一次疫情拉动的用户和二次疫情拉动的用户左右箭头刚好持平

#### 6.2.1 跌幅量化

| 业务 | 局部高点→低点 | 高点降幅 | 局部低点→更低点 | 低点降幅 |
|------|-------------|---------|----------------|---------|
| **大盘** | 9057w→8410w（647w） | 7.7% | 8249w→7833w | 5.3% |
| **资讯** | 4939w→4595w | 7.4% | 4412w→4310w | 2.3% |
| **文件** | 1936w→1755w | 10.3% | 1644w→1498w | 9.7% |
| **小说** | 885w→762w | 16.1% | 754w→540w | **39.6%** |

#### 6.2.2 人口属性拆解

使用决策树建模，按年龄段、城市等级、性别、手机品牌聚类，找到下跌明显人群：

| 人群 | 变化 |
|------|------|
| 51岁以上用户 | **下跌20.9%**（流失最严重） |
| 13-15岁用户 | 上涨9% |
| 一线城市用户 | 下跌3% |
| 非一线城市用户 | 上涨7.4% |
| 三线城市（安卓用户） | 上涨9.8% |

#### 6.2.3 业务渗透拆解

| 用户群 | 变化 |
|--------|------|
| 小说业务低活用户 | **下跌12.7%** |
| 小说低活且搜索高活用户 | **下跌18.1%** |
| 小说业务中活用户 | 上涨6% |
| 小说中活且文件高活用户 | 上涨15% |
| 三方网页高活用户 | 上涨4% |
| 非文件高活+非三方网页高活+非小说中低活 | 下跌7% |

#### 6.2.4 高活用户下跌归因（CART决策树）

随机抽取100w 618当日高活用户，以guid粒度进行CART分类树建模，特征包括：成为QB用户的期间（first_date分pre/in/post_pre/post四段）、疫情前是否高活、业务渗透数目、QB使用时长（中高低）、首启为主启的比例。

**特征重要度结论**：影响高活用户最重要的因素是**在6.10号之前用户是否是高活用户**。

| 用户类型 | 流失率 |
|----------|--------|
| 疫情前不是高活的用户 | **76%流失**（连续7天没再来） |
| 疫情前是低活的用户 | **92.9%流失** |
| 疫情前是高活的用户 | 仅36.9%流失 |
| 疫情前高活但首启主启比例<0.7 | **72.5%流失** |

**核心结论**：
- 疫情前高活用户有63.1%概率留下来
- 但如果没有主启心智（首启主启概率<0.7），留存概率骤降到27.5%
- 疫情前不是高活用户，留存概率仅24%
- 新发地二次疫情唤起的中低活+沉默用户，以及没有建立主启心智的用户，在6.15-7.26期间慢慢流失，构成这轮下跌的主要动力

#### 6.2.5 资讯用户下跌归因

统计用户在615-716期间每次访问QB时阅读文章的类型，建模分析影响用户留存间隔的文章类型：

| 内容类型 | 对留存间隔的影响 |
|----------|----------------|
| 教育类、时事、广告创意、体育 | 留存间隔**变长**（用户来得更慢，偏负面） |
| 壁纸头像、心灵鸡汤、文化、旅游 | 留存间隔**变短**（用户来得更快，偏正面） |
| 摄影、美女 | 整体能缩短留存间隔，但波动较大 |

推测：不同人群对这几类资讯反馈不同，"我之蜜糖彼之砒霜"。

#### 6.2.6 小说用户下跌归因

**直接原因**：产品在6月1号下架了盗版转码功能，导致小说用户大幅衰减。

#### 6.2.7 跌幅归因汇总（647w总降幅）

| 归因因素 | 可解释降幅 | 计算逻辑 |
|----------|-----------|----------|
| 桌面红点停投 | **~200w** | 6月全量发红点，7月仅新用户+沉默+低活发放，结合红点AB实验比例折算 |
| 主动文件暑期下降 | **~150w** | 文件tab+高级功能连续下降，降幅超过大盘，比例折算 |
| Push DAU下降（热点消退） | **~47w** | push有启UV降幅 × 0.3 |
| 用户活跃度下降（高活→高活比例下降，中活转低活/沉默上升） | **~400w** | 与前三点有一定重合度 |
| CTR下降 | 潜在传导 | 推荐侧排查中，CTR下降与DAU存在潜在传导关系 |

**后续企稳**：7.26后QB大盘DAU相对企稳在8100w位置，短期内（3-6周）利空因素已兑现，预计不会进一步下跌。

**竞品验证**：相同时间范围腾讯新闻走向也有类似趋势，QB DAU、资讯DAU、腾讯新闻DAU保持"同趋势"，说明有行业性因素。

### 6.3 路径漏斗分析

#### 6.3.1 首启主启与外部调起路径

取2020.9.8的DAU，分析用户前10步操作路径，区分主启（start_type='qb'）和外部调起（start_type='pull'）两种启动方式。

**关键发现**：
- 主启用户和外部调起用户的行为路径差异显著
- 外部调起用户需要更好的承接策略，转化为主启

#### 6.3.2 大盘到信息流路径漏斗

2020.9.2大盘严口径DAU用户，分析前5个场景每一步人数：

**路径渗透率排序**：

| 起始路径 | 信息流最终渗透率 |
|----------|----------------|
| QB小说起始 | **>60%**（最高） |
| 外部文件→基础框架 | 40-50% |
| 基础框架×4或×3 | 40-50% |
| 基础框架→搜索 | ~40% |
| 基础框架→内部文件 | ~40% |
| WEB其他开头 | 最差 |

**关键洞察**：
- 用户从明确场景（小说、文件）一旦来到"基础框架"场景，信息流渗透率大大提高
- "基础框架→搜索"分支贡献信息流用户400万+，搜索场景渗透不高但信息明确，是承接重点
- 连续几个"基础框架"的用户，多数去了WEB网页和WEB长视频，其中>42万去了外部视频网站或成人网站
- 对这部分用户的建议：成人内容用户回主feeds推男科医疗知识文章；动漫/电影/剧集用户做内容引入和专门推荐

**数据口径说明**：
- QB大盘流水表每天1.3亿人，join严口径DAU后8000万
- 刨除延迟上报后仅剩6900万
- 信息流用户4100万（不刨除延迟前4500万，当天资讯DAU 4200万）

### 6.4 DAU拆解的结构化流程

> **面试口述版**：DAU跌了怎么排查？我在QB经历过持续六周下跌647万的完整拆解。我的方法论是八步：第一确认问题（跌幅、时长、季节性）；第二人口属性拆解（年龄、城市、性别、机型，用决策树找下跌人群）；第三活跃度拆解（高/中/低活的流转矩阵）；第四业务渗透拆解（各业务用户变化）；第五归因建模（高活用户用CART决策树，资讯用户分析内容类型对留存间隔的影响）；第六路径漏斗（首启→主启→信息流各环节转化率）；第七外部因素（竞品、季节、疫情）；第八结论和行动。

> 具体到这个案例：51岁以上用户跌了20.9%，小说低活用户跌12.7%。归因发现最关键的因素是疫情前是否高活——疫情前非高活用户76%流失，低活用户92.9%流失，而高活用户只有36.9%流失。但高活用户如果首启主启比例<0.7（没有主启心智），72.5%会流失。跌幅归因：红点停投解释200万，文件暑期下降150万，Push消退47万，用户活跃度下降400万（有重合）。小说下跌是因为6月1号下架了盗版转码功能。最后企稳在8100万，腾讯新闻同趋势验证了行业性因素。

#### 7.7.1 业务使用关联规则

- 文件功能：**约52%**（主动或被动）
- 网页浏览：**约38%**
- 信息流：**约36%**
- 搜索：**约21%**

**关联规则发现**（支持度>0.05，置信度>0.6，提升度>1.5）：

#### 7.7.2 关联规则在推荐中的应用价值

1. **交叉推荐**：利用业务间的关联规则做交叉推荐，如小说用户推信息流内容

3. **冷启动**：新用户使用了某个业务后，可以基于关联规则推荐相关业务的内容
4. **流失预警**：用户从多业务使用退化为单业务使用时，可能是流失前兆

## 九、推荐实验系统

### 9.1 AB实验平台架构

我在腾讯视频和QQ看点做推荐时，使用过两套实验系统：

| 系统 | 使用团队 | 特点 |
|------|---------|------|
| **试金石系统1.0** | 腾讯视频长视频推荐 | 50多路实验，精排/粗排/rerank等 |
| **骡马系统** | 信息流看点、腾讯视频短视频 | 60%流量，包括UI、粗排、精排、混排合计十几层 |

**实验系统核心实现思路**：对流量分桶，选取1%或5%等小流量，与对比路进行一定时间对比，参数较优的评估放量。

### 9.2 实验系统核心指标

| 指标 | 定义 | 意义 |
|------|------|------|
| **上线速度** | 实验上线越快，算法效果评估越快 | 决定算法迭代速度 |
| **对比时间** | 对比效果的时间越短，评估越快 | 决定实验周期 |
| **对比指标** | CTR、VV、AU等，视业务样式决定 | 实验效果的核心衡量 |

### 9.3 实验配置与流程

**腾讯视频短视频推荐现状**：
- 精排有6个实验路，粗排、DNN召回、rerank都是两路实验+一base路配置
- 上线一周左右进行数据对比，**一个月完成一个实验**
- 新服务空跑一周观察数据，一周左右可以做数据对比

**信息流看点实验流程**：
1. 新服务空跑一周，观察数据
2. 一周左右做数据对比
3. 平均一个月完成一个实验
4. 邮件报备技术leader，批准后放量

### 9.4 实验设计要点

**流量分层**：
- UI层、粗排层、精排层、混排层等多层实验并行
- 各层之间需要正交分流，保证实验间互不干扰
- 每层有base路作为对照

**实验周期**：
- 空跑期：新服务上线先空跑，验证数据上报和系统稳定性
- 对比期：至少一周，覆盖完整的周中周末周期
- 观察期：放量后持续观察，防止延迟效应

**指标显著性**：
- 核心指标需要达到统计显著性（通常p<0.05）
- 关注指标的方差和样本量，小流量实验可能需要更长时间
- 多重比较校正：同时看多个指标时，需要控制假阳性率

**护栏指标**：
- 即使核心指标提升，也要监控护栏指标（如负反馈率、崩溃率、延迟等）
- 护栏指标恶化时，即使核心指标正向也不能放量

### 9.5 离线实验vs在线实验

| 维度 | 离线实验 | 在线AB实验 |
|------|---------|-----------|
| **成本** | 低，用历史数据计算 | 高，需要真实流量 |
| **速度** | 快，小时级出结果 | 慢，至少一周 |
| **准确性** | 有偏差（样本偏差、位置偏差） | 真实准确 |
| **可探索性** | 高，可以快速试错 | 低，有用户体验风险 |
| **适用场景** | 算法初筛、特征工程验证 | 最终效果验证、上线决策 |
| **关系** | 离线是在线的前置筛选 | 在线是离线的最终验证 |

**最佳实践**：离线实验做初筛（AUC、HitRate等指标提升明显的算法），在线AB做最终验证，两者结合提高迭代效率。

### 9.6 行业实验系统参考

- **Netflix**：大规模在线分层实验体系
- **抖音**：高效实验平台，支持快速迭代
- **阿里妈妈**：大规模在线分层实验
- **58招聘**：自建实验系统

> **面试口述版**：我在腾讯视频和QQ看点做推荐时，用的是骡马AB实验系统。实验流程是：新服务先空跑一周观察数据，然后小流量（1%-5%）对比至少一周，核心指标显著后邮件报备leader批准放量，平均一个月完成一个实验。系统是多层正交分流的，UI、粗排、精排、混排十几层并行，每层有base路对照。实验设计要点：第一必须覆盖完整周中周末周期；第二核心指标要统计显著p<0.05；第三要有护栏指标（负反馈率、延迟、崩溃），护栏恶化即使核心正向也不能放；第四多重比较要校正。离线和在线的关系是：离线做初筛快速试错，在线做最终验证，离线AUC提升不代表在线DAU提升，最终以上线AB为准。

### 10.5 市场分析方法论

**竞品监测的完整框架**：
1. **渗透率监测**：竞品在我方用户中的安装率/活跃率
2. **变动趋势**：竞品渗透率的时间序列变化，识别快速增长的竞品
3. **用户重合分析**：竞品用户与我方流失用户的重合度，判断是否被竞品抢走
4. **分品类监测**：按业务品类（资讯、小说、视频、搜索）分别监测竞品
5. **外部验证**：结合行业报告、第三方数据（QuestMobile等）交叉验证

> **面试口述版**：我在QB做过竞品安装率监测，用欧拉中台的APP安装列表数据。2020年8月的水位是：抖音68%、百度62%为第一档，今日头条34%、腾讯新闻32%为第二档，七猫9%、番茄8%为第三档。关键发现是：浏览器和资讯类竞品安装率基本没变化，但小说垂类竞品增长很快——番茄从2%涨到8%，七猫从5%涨到9%。这正好对应了QB小说业务DAU下跌39.6%的情况，验证了竞品压力是小说业务下跌的重要外部因素。竞品监测的方法论是：渗透率监测+变动趋势+用户重合分析+分品类监测+外部数据交叉验证。

## 十一、面试话术

### 11.1 自我介绍（推荐数据分析方向）

> 我在腾讯QQ看点和QB（QQ浏览器）做了四年推荐数据分析，核心工作包括三块：第一是推荐指标体系建设，从北极星DAU/时长到过程指标CTR/消费VV再到漏斗转化率，搭建了完整的评估体系，离线侧有15个召回指标和AUC/GAUC/NDCG排序指标；第二是用户理解，做过核心用户特征提取（用SkopeRules+CCA分析，发现网红达人/搞笑/生活/社会品类与核心用户时长强正相关）、用户分群模型（频次×逛×消费三维64群）、次活预测模型（WDL，AUC 0.84-0.88）；第三是业务分析，主导过QB大盘DAU持续六周下跌647万的完整拆解，从人口属性、活跃度、业务渗透到归因建模，定位了红点停投、文件暑期下降、用户主启心智缺失等核心原因。还做过粉丝数据摸底、好友推荐指标建设、竞品监测等工作。

### 11.2 高频Q&A

**Q：推荐系统怎么评估？**

A：推荐系统评估分离线和在线两套体系。离线评估我在看点搭建了15个指标，召回侧核心是HitRate（命中率）、DurationRate（时长加权命中率）、CoverRate（覆盖率）、NoveltyRate（新颖度=1-历史重复率）、Entropy（类目熵衡量多样性）、Simi（多路召回Jaccard相近度，防止同质化）、NewCoverRate/HotCoverRate（新热内容覆盖率）。排序侧用AUC、GAUC（按用户分组消除活跃度偏差）、NDCG、Recall@K。在线评估就是AB实验，北极星指标是DAU和人均时长，过程指标是CTR、消费VV、完播率、1s快划率，互动指标是点赞评论分享关注率，留存指标是次留7留。离线和在线经常不一致，原因是样本偏差、位置偏差、延迟反馈和生态影响，所以离线只做初筛，最终以上线AB为准。

**Q：DAU跌了怎么排查？**

A：我的方法论是八步拆解法。第一步确认问题：跌幅多少、持续多久、是不是季节性（对比去年同期、看腾讯新闻等竞品是否同趋势）。第二步人口属性拆解：按年龄、城市等级、性别、手机品牌用决策树找下跌最明显的人群。第三步活跃度拆解：做高/中/低活/沉默的流转矩阵，看哪个流转环节变化大。第四步业务渗透拆解：各业务（资讯/小说/搜索/文件）用户的变化。第五步归因建模：对高活用户用CART决策树找最重要的影响因子，对资讯用户分析内容类型对留存间隔的影响。第六步路径漏斗：首启→主启→信息流→消费各环节转化率变化。第七步外部因素：竞品、季节、疫情、运营策略变更（红点/Push/活动）。第八步结论和行动建议。

我在QB实际做过六周下跌647万的拆解，发现最关键的因素是疫情前是否高活——非高活用户76%流失，高活但首启主启比例<0.7（没有主启心智）的用户72.5%流失。归因上红点停投解释200万，文件暑期下降150万，Push消退47万，用户活跃度下降400万。

**Q：怎么做用户分层？**

A：我在QB做过两套用户分层。第一套是用户分群模型，用三个维度：频次（月活跃天数）、逛（主feeds真实曝光次数）、消费（产品使用时长），每个维度按节点切4档，共64群。选这三个维度的理由是相关性弱（张量夹角大）、业务含义充分抓手明确。第二套是核心用户分层，定义核心用户是"某周活跃后下周仍有超过2天使用"的用户，占比51.8%。用SkopeRules提取出三大特征：高频（周活6天+）、中频+足够进入次数（周活3-5天且app进入5-7次+）、低频+足够时长（周活1-2天但时长>11分钟），加上有互动行为的用户。然后用CCA分析内容消费变化和用户表现变化的关联，发现网红达人、搞笑、生活、社会四个品类与核心用户时长和活跃天数正相关性最强，生活小视频每天都是影响时长的最大品类。这些分层直接用于差异化运营和推荐策略调整。

**Q：离线指标和线上不一致怎么办？**

A：首先要理解不一致是常态，不是异常。我总结了四个主要原因：第一是样本偏差，离线用历史数据评估，用户已经看过的内容不会再点击，但离线不排除已曝光；第二是位置偏差，离线不考虑展示位置对CTR的影响，线上位置偏差显著（首条CTR远高于第十条）；第三是延迟反馈，视频消费、留存这些指标有延迟，离线即时指标捕捉不到；第四是生态影响，单用户体验提升不代表整体DAU提升，可能存在挤出效应或者新内容挤占了老内容的曝光。

应对方法：离线评估时排除用户已曝光内容；引入位置偏差校正（如IPW逆倾向加权）；建立离线-在线相关性监控，定期校验哪些离线指标和在线相关性高、哪些低；离线指标作为初筛门槛，最终决策一定以上线AB实验为准。另外可以做replay实验（用线上真实曝光日志离线重放），比纯离线计算更接近线上效果。

**Q：怎么衡量推荐的多样性和新颖性？**

A：多样性我用两个指标：Entropy（类目熵，用信息熵公式计算每个用户召回结果的类目分布，数值越大种类越多）和TypeNum/TypeRate（每路召回里各内容类型的平均个数和覆盖率）。新颖性用NoveltyRate = 1 - HistoryRate，HistoryRate是召回结果与用户过去播放序列的交集比例。另外还有Simi指标，用Jaccard similarity计算多路召回之间的相近度，如果两路召回结果太像（Simi过高），说明加一路召回没有增量效果。这些指标的平衡很重要：多样性和新颖性太高会牺牲精准度，太低会导致用户疲劳，需要在AB实验中找到最优平衡点。

**Q：次活/留存预测模型怎么做？**

A：我在QB做过次活预测模型，目标是预测月活用户次日是否主动打开APP。正负样本：正样本是月活用户中T+1有主启的，负样本是其余月活用户，1:1负采样各8kw。特征分三类：活跃状态特征（近7/14/21/28天的累积活跃天数、主启天数、时长）、活跃序列特征（近30天活跃0/1、主启0/1、时长的序列化表示）、基础画像（年龄性别星座手机运营商学历OneHot）。模型用Embedding+WDL。效果：训练AUC 0.86，测试AUC 0.88，预测AUC 0.84。在月活∩次日日活用户群上阈值0.7时precision 89%、recall 56%。输出0.5-0.9的打分标签，用于差异化运营——高概率用户正常服务，低概率用户做Push/红点召回干预。更长期的留存预测可以扩展到7日/14日/30日，结合生存分析模型预测流失时间点。

**Q：推荐实验怎么设计？需要注意什么？**

A：推荐实验的设计要点：第一是流量分层正交，UI、粗排、精排、混排各层独立分流互不干扰，每层有base路对照；第二是实验周期，新服务先空跑一周验证数据上报，然后对比至少一周覆盖完整周中周末，平均一个月完成一个实验；第三是指标体系，核心指标（CTR/VV/时长）要统计显著p<0.05，同时要有护栏指标（负反馈率、1s快划率、延迟、崩溃），护栏恶化即使核心正向也不能放量；第四是多重比较校正，同时看多个指标时控制假阳性率；第五是小流量起步（1%-5%），效果验证后逐步放量，邮件报备技术leader批准。离线和在线的关系是离线做初筛快速试错，在线做最终验证。

**Q：关注/社交推荐怎么评估？和内容推荐有什么不同？**

A：社交推荐的评估有特殊性。我在微视负责好友推荐指标建设时，核心指标分四层：流量层（实验用户数、曝光卡片数）、关注层（关注UCTR=关注用户数/实验用户数、关注CTR=点击关注数/曝光卡片数、人均关注数）、头像点击层、负反馈层（X按钮率）。还有全局指标（非推荐场景的关注量，防止推荐挤占自然关注）和留存指标（次日留存、关注页次留）。

和内容推荐的不同点：第一，关注行为的价值在长期留存不在即时CTR，用户关注了一个创作者后，后续会持续消费其内容，所以要关注次留、关注页次留这些长周期指标；第二，要拆达人vs好友，两者推荐逻辑和评估标准不同；第三，负反馈（X按钮）特别重要，推错了人用户体验伤害很大；第四，埋点必须落recommend_id不能只用test_id，否则无法做后续归因；第五，要监控全局关注量，不能只看推荐场景产生的关注，防止推荐挤占了用户自然关注的行为。

**Q：怎么发现和定位推荐系统的问题？**

A：我通常从三个层面发现问题。第一是指标监控层，建立核心指标的日报/周报，设置异动告警（如CTR环比下降超过5%触发告警），按场景（首页/频道/搜索结果）、内容类型（图文/视频/小视频）、用户群（新用户/老用户/高活/低活）下钻。第二是漏斗分析层，从曝光→点击→消费→互动→关注逐层看转化率，定位哪个环节出了问题。比如曝光UV涨了但CTR降了，可能是推荐精准度下降；CTR没降但消费VV降了，可能是内容质量问题或标题党。第三是用户反馈层，看负反馈率（不感兴趣、举报）、1s快划率、用户评论反馈。

定位到问题后，用AB实验验证因果关系，而不是只看相关性。比如CTR下降，先看是不是算法版本变更导致的，回滚验证；再看是不是内容供给侧变化（新内容减少、热门内容下线）；再看是不是用户结构变化（新用户占比增加拉低了整体CTR）。
