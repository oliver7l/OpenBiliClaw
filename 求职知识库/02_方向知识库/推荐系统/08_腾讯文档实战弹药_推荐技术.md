## 1. 大模型推荐系统调研（LLM for Recommendation）

### 核心知识
- **两条路线**：
  1. **fine-tune LLM**：基于预训练大模型 + 推荐业务数据做 SFT 微调，比直接 prompt/in-context 效果更好。代表 TALLRec（中科大）：用用户历史交互构建样本，LoRA 轻量级微调。输入如 `"User Preference: item1,item4,...; User Unpreference: item2,...; Whether user will enjoy target: item_{n+1}"`，输出 `Yes/No`。
  2. **Generative Retrieval**（生成式检索）：GPT 预测下一个词 vs 推荐预测用户下一个交互物品。把 item 转成 semanticID（raw data→embedding→压缩为 semanticID 序列），用语义 ID 序列预测下一物品的 ID（生成 ID 中仅 2% 不在内容库），用于召回阶段。代表 Google《Recommender Systems with Generative Retrieval》。
- **LLM 的性能 & 成本问题（面试高频）**：
  - LLM 延迟秒级（5-30s）vs 推荐要求毫秒级（<500ms）；
  - 频繁调用成本高。
  - **解决思路**：①缓存（预生成结果/向量存 KV 或向量库，线上查缓存）；②缩小模型（蒸馏、剪枝、量化）。

### 面试话术
> "大模型在推荐侧，我关注两件事：一是怎么用起来，二是怎么用得起。用起来方面，业界主流分两条路——一条是微调路线，像 TALLRec 那样用用户历史交互构造样本、LoRA 轻量 SFT，让模型懂推荐任务；另一条是生成式检索路线，把 item 压缩成 semanticID 序列，让模型直接预测下一个要交互的 ID 做召回。用得起方面，核心矛盾是延迟和成本——LLM 秒级延迟撑不起线上毫秒级调用，所以要么提前缓存大模型产出的向量和结果、线上走向量库检索，要么蒸馏剪枝量化把模型做小。我理解大模型在推荐的落地优先级是：先离线/缓存场景（召回向量、冷启内容理解），再逐步渗透在线精排。"

## 2. 字节最新召回模型 · 深度检索 DR（Deep Retrieval）

### 核心知识
- **背景**：向量内积检索受限于 embedding 表达；阿里 TDM/JTM 用树结构索引，但树难学、对结果敏感、叶子稀疏、item 只能挂一个叶子。
- **DR 框架**：用 **D×K 维矩阵作为索引结构**，模型预测走 D 步、每步 K 种选择，共 K^D 条路径（编码），每条路径代表一个含多 item 的集合，一个 item 可同时在多条路径（**多对多编码**）。
- **优势**：①训练阶段 item 路径与 NN 参数用 **EM 类型算法联合训练**；②多对多编码让模型能学 user-item 更复杂关系。
- **预测阶段**：基于 user embedding 用 **beam search** 选候选路径。
- **效果**：取得与暴力算法相当的效果，解决超大规模推荐匹配问题。

### 面试话术
> "召回侧的突破点，我研究过字节的 Deep Retrieval。它打破了向量内积检索和树检索的限制——树检索（TDM/JTM）的问题是树结构难学、对结果敏感、item 只能挂一个叶子节点，表达受限。DR 用一个 D×K 的矩阵做索引，模型走 D 步、每步 K 选，形成多对多的路径编码：一个 item 可以同时在多条路径里，这样能多角度刻画 item。训练上路径和网络参数一起用 EM 类算法联合优化，线上用 beam search 基于 user embedding 选路径。它给我们的启发是：召回索引结构本身可以是可学习的，而不是固定的 embedding 检索。"

## 3. 技术原力 · 推荐走的路（腾讯内部推荐架构复盘）

### 核心知识
- **推荐系统与中台关系**：Client 行为上报→请求推荐→推荐结果→特征上报→离线处理与模型训练→内容特征/用户特征；基础组件（无量训练平台、trpc、实验系统、存储、内容理解/NLP/视频理解、ola画像）。"通用性越强的组件越省成本、效率越高"。
- **各层算力分配**：召回层大量独立特色结果（10万级~1000万级）→粗排→精排→混排。
- **召回现状与方向**：
  - 现状：老产品上百路召回策略、雷同但各自研发、无法复用。
  - 方向：召回算法组件化/通用化；单次请求算大量结果；**萃取召回（pairwise 学序而非仅正负）**；图模型/序列建模隐式召回占比上升（视频场景）；**长 session 计算用户兴趣 embedding 做召回**；**外部数据做深度理解算用户强兴趣（新浅用户最受益）**；**多模态召回**；负样本从"相关度不好"的结果中选比随机负样本效果好。
- **粗排**：单次算几千上万条，双塔偏性能、复杂模型偏效果；高性能打分 **PE 框架**可做默认召回模型；**粗排学习精排、Cascade 学展现多目标**；按用户类型/物品类型做多头学习目标。
- **精排**：排内存几百 G~T 级；**长 session 特征**、多模态特征、TB 级特征、特征配置化（特征中台）；**按用户类型（新浅/老用户）、物品类型做多头学习目标**；**复杂结构与 GPU 联合优化**；训练更新速度要快（新浅用户反馈更明显）。无量平台历程 FTRL→单Deep→WDL→可定制模型。
- **多目标**：底层目标比上层少、深度目标未建立；融合偏直接加/乘、参数不够个性化、搜参效率不高；解法：召回/粗排复用高性能多目标模型、**AutoML 搜参**、网络结构与融合方法算子化组件化。
- **细节**：MMOE 多专家、多目标 6 塔 56 标、skip/完成率多目标、Cascade、Listwise 学习、各业务槽位预估模型、长 session 上文特征影响混排。

### 面试话术（架构题）
> "我在内容平台做推荐时对全链路有整体理解。一套推荐系统从下往上分五层：召回、粗排、精排、混排、策略。召回的目标是广度——单次请求算 10 万到千万级候选，重点在召回路线的丰富性和组件化，我会关注几件事：多模态召回、长 session 用户兴趣 embedding、以及从'相关度不好'的样本里挖负样本（比随机负样本效果好）。粗排解决性能与效果的平衡，单次算几千到上万条，用高性能打分模型，让粗排去学精排的序。精排是效果核心，我重点做三件事：特征规模化和配置化、按用户类型和物品类型做多头学习目标（比如新浅用户 vs 老用户、短内容 vs 长内容目标不同）、以及复杂模型上 GPU 联合优化来控制成本。最后多目标融合，我的经验是底层召回粗排要尽早对齐上层目标，融合参数别手搜，用 AutoML 搜，网络结构和融合方法要算子化、组件化，方便多业务复用。"

### 面试话术（单点题：长 session / 冷启动）
> "长 session 这块，我的理解是 session 越长越能刻画用户长期兴趣，但数据稀疏，关键是把 session 特征用好——要么算用户兴趣 embedding 做召回，要么在精排里作为强特征。冷启动对新浅用户，最有效的是外部数据和内容理解：用外部数据算出用户强兴趣，对没有行为的新用户帮助最直接；同时模型训练更新要快，让模型尽快学到新行为。"

## 4. 对比学习在推荐系统

### 核心知识
- **三大研究点（难度递增）**：Data Augmentation（数据增强）→ Sampling Strategy（采样）→ Loss Function（损失函数）。
- **三种融入方式**：Joint Learning（JL，最常用）、Pre-training & Fine-tuning（PF）、Integrated Learning（IL）。
- **数据增强**：图增强（GNN 常用），data-level 增强缺点——方法繁多需人工试、可能破坏内部关联、需要先验知识（如序列里对长度为 2 的节点做 Mask 可能和原序列完全无关；二部图 edge dropout 可能拆成两个分离子图）。
- **进阶**：借鉴 GAN 加噪声利于训练——每层 GNN 加噪声扰动，让 final embedding 和第一层 GNN embedding 的节点做对比学习（同一个物品输入、模型自带扰动得到不同 embedding 再对比，类似 DuoRec）。
- **InfoNCE 性质**：特征归一化让模型自带挖掘硬负样本能力；负样本数量越多越好。NCE 是把 data/noise 二分类，InfoNCE 推广到多分类（Softmax 形式）。
- **为什么用自监督（4 个理由）**：①数据稀疏（推荐 10 篇只点 1 篇，可自监督增强点击数据）；②item 长尾分布（长尾 item 行为少，可增强）；③跨域推荐多 view 融合，自监督融合而非线性加权；④增强鲁棒性/对抗噪音（Mask、Dropout 等）。

### 面试话术
> "对比学习在推荐里我主要把它当自监督信号用。核心是三个问题：数据增强怎么做、正负样本怎么采、损失函数怎么定。主流三种融入方式里 Joint Learning 最常用，就是主任务和对比辅助任务联合训练。我的经验是有几个落地点：一是解决稀疏，推荐里点击数据很少，自监督增强点击数据；二是长尾，长尾 item 行为少，靠增强补齐；三是鲁棒性，用 Mask、Dropout 做扰动。InfoNCE 有两个很实用的性质——特征归一化以后模型能自己挖硬负样本，负样本数量越多越好，所以采样时要把负样本量做大。"
