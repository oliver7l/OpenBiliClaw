## 项目一 · 微视账号推荐系统（UGC 粉丝/账号推荐）

### 项目背景
QQ看点 UGC 化，用户关注作者后缺少"持续关注更多优质账号"的抓手。目标：在 QB 信息流/小视频/个人主页等场景做**账号推荐**，让用户从"看内容"升级为"关注账号"，提升关注生态和复购（转粉）。

### 系统架构：四路召回 + 过滤 + 混排
```
用户请求
  ├─ ① 作者追打召回：基于"当前关注作者"找相似作者
  │    ├─ 同分类热门作者（按近期涨粉率+复购率综合排序）
  │    ├─ 协同 itemCF：关注 U-I 矩阵算作者相似
  │    ├─ 作者 embedding 直接复用（内容中心账号相似链）
  │    └─ 作者特征聚类（K-means，召回同簇 top）
  ├─ ② 用户兴趣召回
  │    ├─ 用户 top 分类兴趣 → 该分类热门作者
  │    ├─ 用户 tag 词 × 作者能力 tag（作者发文做 tf-idf 取 top 词，算 jaccard 距离）
  │    └─ 用户协同：关注列表 one-hot 相似度 → 相似用户关注的其他作者
  ├─ ③ 热门召回：运营行业大V（限咖位）+ 后验 top 关注转粉账号（卡时效）
  └─ ④ 其他召回：爱互动作者（近一月互动、阅读完成率高的文章作者）
  ↓ 过滤
  ├─ 过滤已关注作者（关注关系去重）
  └─ 退场机制：作者重复曝光需特殊设计（定义一天内过滤）
  ↓ 混排 + 展示
```

### 关键工程细节（追问弹药）
- **转粉能力建模**：用 `kd_video_puin_follow_level_24hour`（每小时 900 万行、20.4 万账号），follow_level = 转粉率换算的能力等级，作为高转粉账号的挖掘信号。
- **账号数据**：账号信息千万级（`t_dws_puin_b_c_data_daily`），但 20 万账号仅 4k 能关联分类（数据稀疏，需自己补特征）。
- **召回策略命名规范**：队列 `Q_业务_名称`（如 Q_FIREWORK_COLD_START），召回策略 `POOL-METHOD`（如 POOL_RECOM-QB_CH1），便于配置化和中台管理。

### 内容召回（UGC 内容推荐召回，配套弹药）
- **内容池分层**：大盘池 POOL_RECOM、首屏池 POOL_FIRSTSHOW、冷启动一/二/三档池（POOL_COLDSTART_LEVEL_1/2/3）。
- **画像召回**：按 QB 画像一级/二级/三级分类 + 标签，老用户和新用户分开（NEW_USER 桶）。
- **Embedding 召回**：基于用户点击/播放序列训练内容 embedding（封面/标题/视频帧/行为），线上用最近点击列表 N=10 触发；含 **DSSM 双塔模型召回**（新老用户分开 EMB_DSSM_NEW_USER / EMB_DSSM）。
- **冷启动**：explore_state 档位（10/20/30）+ account_merged_score>0.88 过滤，三档渐进曝光。
- **兜底**：nolan 侧 KDWB_RANDOM_BASELINE_RECALL，推荐失败触发。

### 特征体系
- **亲密度**：guid 维度（互动汇总/真实曝光点击/时长）+ guid-文章 + guid-puin 聚合，输出用户-账号亲密度分。
- **账号特征**：分类、等级、创作能力、粉丝数等。
- **分层**：基础数据（关注/粉丝列表）→ 账号特征 → 用户特征 → 内容特征 → 用户账号亲密度。

### 面试话术（STAR）
> **S 背景**：QQ 看点做 UGC 化，作者生态起来后，用户"关注更多优质账号"的需求没有被满足，关注复购和转粉效率低。我负责从 0 到 1 搭建账号推荐系统。
> **T 目标**：在信息流、小视频、个人主页多个场景推荐相似账号，提升关注转化和转粉率。
> **A 动作**：我设计了四路召回——第一路"作者追打"，基于用户已关注作者找相似（同分类热门、itemCF、作者 embedding、聚类四种子路）；第二路"用户兴趣"，用分类兴趣、tag 词匹配作者能力 tag（tf-idf+jaccard）、用户协同三种方式；第三路"热门"，运营大V + 后验高转粉账号；第四路"爱互动作者"。召回后做已关注过滤和作者退场机制（避免重复曝光）。同时建了转粉能力等级模型，从 900 万行/小时级别的关注流水里挖高转粉账号作为候选池。
> **R 结果**：账号推荐落地到 QB 关注、feeds、小视频、个人主页等场景，打通了从内容消费到关注沉淀的链路。（注：效果数值在实验平台，讲述时聚焦系统设计和工程落地。）

## 项目二 · 看点图集推荐 · 多目标（ESMM/MMoE）

### 项目背景
图集（多图内容）和短内容场景，单一目标（点击）不能同时兼顾时长、互动、转化，导致指标互相打架。需要在排序阶段引入多目标。

### 技术方案演进（时间线，可完整复述）
1. **2019.09 · 图集点击+转化 ESMM 多目标**：把"点击"和"转化"两个目标放到 ESMM 框架里联合建模，用曝光层做样本空间对齐，解决选择偏差和稀疏转化问题。
2. **2019.10 · 图集点击+时长 ESMM 多目标**：在 ESMM 基础上加入"时长"目标，兼顾点击和深度消费。
3. **2020.04 · 短内容浮层多目标精排**：短内容（短视频）浮层场景，精排引入多目标，同时优化停留时长和用户互动。
4. **2020.06 · 短内容浮层多目标召回**：把多目标从精排下沉到召回，让召回也带多目标信号。
5. **无量 3.0 · MMoE 多目标上线**：负责快速对接无量 3.0 平台，引入 MMoE（多专家多门控）模型，同时优化停留时长和用户互动行为，**成为 BG 第一个在无量 3.0 全量上线多目标的业务**。

### 核心效果数据（真实，可直接引用）
**短内容浮层多目标精排**（4格置信度）：
- 大盘累积使用时长 +0.42%
- 大盘广义 DAU +0.10%
- 广义 DAU 留存 +0.07%
- 短内容互动行为 +35%
- 短内容浮层时长 +6.8%
- 短内容总时长 +2.85%

**短内容浮层多目标召回**（实验桶 56/67 vs 对照桶 90/91）：
- 进评论率 +80%
- 进评论数 +70%+
- 篇均时长 +8%
- 总时长 +4%

- **排序方法论总结**、**多任务多目标学习总结**

### 面试话术（STAR）
> **S 背景**：看点图集和短内容是核心消费场景，但单目标模型只能优化点击，时长、互动、转化三个指标互相打架——点得多但不爱看、互动高但时长差。
> **T 目标**：在精排和召回都引入多目标，让模型同时优化时长、互动、转化，带动大盘核心指标。
> **A 动作**：分两步走。精排侧先做图集 ESMM（点击+转化、点击+时长），用曝光层对齐样本空间解决稀疏转化；短内容浮层场景再上 MMoE 多目标精排，并牵头把无量 3.0 平台接进来，成了 BG 第一个在无量 3.0 全量上线多目标的业务。召回侧把多目标下沉，做多目标召回，让候选质量也按多目标来。过程中我沉淀了整套召回/排序方法论和负样本优化方法。
> **R 结果**：精排上线后大盘累积使用时长 +0.42%、互动行为 +35%、浮层时长 +6.8%、总时长 +2.85%（4 格置信度）；召回上线后进评论率 +80%、篇均时长 +8%、总时长 +4%。

### 追问应对：ESMM 为什么能解决转化稀疏？
> "ESMM 的核心是两个共享底座的塔：pCTCVR 塔（曝光→点击→转化的全链路）和 pCTR 塔。它把样本空间统一到曝光层，用 pCTCVR = pCTR × pCVR 的乘法关系把稀疏的转化目标拆出来训练，避免只在点击后样本上学 CVR 的选择偏差，同时通过共享 embedding 让稀疏转化塔也能学到信息。"
