# 推荐系统重排与多样性方法论

## 一、重排在推荐系统中的位置

### 1.1 链路定位

我在腾讯微视做推荐重排时，整个推荐链路是：**召回 → 粗排 → 精排 → 重排 → 展示**。重排是精排之后、展示之前的最后一道算法关卡。

精排的主流做法是 **pointwise ranking**——对每个 item 独立预估 pCTR/pCVR 并打分排序。pointwise 的最大问题是：**候选集中相似的 item 打分过于接近，很容易导致排序列表头部出现过于相近的 item**（来源：DPP+多样性重排.txt）。比如用户喜欢电视剧，精排可能把 5 部同类型电视剧全堆在头部，用户刷两下就腻了。

重排的核心价值就是解决这个"列表级"问题：**不再孤立看单个 item 的分数，而是看整个列表的组合质量**——既要有相关性（每个 item 本身质量高），又要有多样性（item 之间不重复、不冗余），还要满足业务约束（保量、打散、去重等）。

### 1.2 重排的目标与约束

| 维度 | 目标 | 具体手段 |
|------|------|----------|
| 相关性 | 保持精排的排序质量，不显著损失 CTR/VV | DPP 中质量分作为向量幅值；个性化重排用精排瓶颈层向量 |
| 多样性 | 避免头部同类目扎堆，提升浏览深度 | DPP 行列式最大化、类目打散、sliding-window DPP |
| 业务约束 | 满足运营/商业化/冷启动诉求 | 保量机制（PID 控制、加权扶持）、运营锁定位 |
| 公平性/生态 | 长尾内容获得曝光，避免马太效应 | 保量配比后剩余位置做个性化长尾推荐 |

**可背诵要点**：
- **重排 = 列表级优化**，精排是 pointwise（单点打分），重排是 listwise（列表组合）。
- 重排不替代精排，而是在精排结果之上做"二次排列"，**本质是带约束的次模函数最大化**。
- 我在微视的重排层同时承载了三件事：**DPP 多样性打散、保量加权、运营锁定位**。

> **面试口述版**："重排是推荐链路的收尾环节，在精排之后、展示之前。精排是 pointwise 的，每个 item 独立打分，问题是相似 item 分数接近，头部容易扎堆。重排做的是列表级优化——我在微视的重排层同时做了三件事：用 DPP 做多样性打散、用 PID 控制做保量加权、还有运营锁定位。核心思路是把单个 item 的质量分和 item 之间的相似度一起放进一个目标函数里，做次模最大化，保证列表整体的相关性和多样性平衡。"

## 二、DPP 多样性重排

### 2.1 问题背景

我在微视做 DPP 的直接动机是：**解决模块内出现过多属于单一类目的视频**（来源：DPP+多样性重排.txt）。精排 pointwise 打分导致同类目视频分数接近，头部扎堆。

当时调研了三篇核心论文：
1. **Hulu Fast-MAP-DPP**：Fast Greedy MAP Inference for Determinantal Point Process to Improve Recommendation Diversity（NIPS 2018）——线上方案基于此实现
2. **YouTube DPP**：http://jgillenw.com/cikm2018.pdf
3. **Criteo Tensorized DPP**：https://dl.acm.org/doi/pdf/10.1145/3292500.3330952——后续研究方向

### 2.2 DPP 核心思想：行列式的几何意义

DPP（Determinantal Point Process，行列式点过程）的本质是一个**次模函数最大化的贪婪计算过程**（来源：DPP+多样性重排.txt）。

原文给出的几何直觉非常关键：

> 一个 vector 表示一个 item，vector 的**幅值**表示质量（可以理解为 CTR、排序列）；与另一个 item 的**夹角**相当于相似度（多样性指标）。我们的目标就是让这个**行列式越大越好**（幅值尽可能大，夹角尽可能大）。（来源：DPP+多样性重排.txt）

行列式的几何意义是**多维空间中向量张成的平行多面体的体积**。体积 = 各边长度的乘积 × 各边夹角的正弦值。所以：
- **幅值大** → 边长长 → item 质量高 → 相关性好
- **夹角大** → 正弦值大 → item 之间相似度低 → 多样性好

行列式同时编码了质量和多样性，**DPP 可以对质量分和相关性做到很好的 balance**（来源：DPP+多样性重排.txt）。

### 2.3 核矩阵构造（公式推导）

设候选 item 集合为 $\mathcal{V} = \{1, 2, \dots, N\}$，为每个 item $i$ 构造一个特征向量 $\phi_i \in \mathbb{R}^d$。

**核矩阵（Kernel Matrix）** $L \in \mathbb{R}^{N \times N}$ 定义为：

```
L = Φ^T · Φ

其中 Φ = [φ_1, φ_2, ..., φ_N] 是 d×N 的特征矩阵
L_ij = φ_i · φ_j  （向量内积）
```

将 $\phi_i$ 分解为**质量项**和**相似度项**：

```
φ_i = q_i · f_i

其中：
  q_i = item i 的质量分（CTR / 精排分数 / pCTR），标量，对应向量"幅值"
  f_i = item i 的内容特征向量（类目、embedding 等），||f_i|| = 1（单位向量），对应向量"方向"
```

代入核矩阵：

```
L_ij = (q_i · f_i) · (q_j · f_j)
     = q_i · q_j · (f_i · f_j)
     = q_i · q_j · s_ij

其中 s_ij = f_i · f_j = cos(θ_ij)，即两个 item 特征向量的余弦相似度，对应"夹角"
```

所以核矩阵可以写成**质量-相似度分解形式**：

```
L = diag(q) · S · diag(q)

其中：
  diag(q) = 以质量分 q_i 为对角元的对角矩阵
  S = 相似度矩阵，S_ij = f_i · f_j
```

**关键性质**：
- 对角元 $L_{ii} = q_i^2$，只和自身质量有关
- 非对角元 $L_{ij} = q_i q_j s_{ij}$，质量越高、相似度越高，核值越大

### 2.4 DPP 概率模型与 MAP 推断

对于任意子集 $Y \subseteq \mathcal{V}$，DPP 定义该子集被选中的概率正比于其子矩阵的行列式：

```
P(Y) ∝ det(L_Y)

其中 L_Y 是 L 中仅保留 Y 中 item 对应行和列的子矩阵
```

**MAP（Maximum A Posteriori）推断**就是找一个大小为 k 的子集 $Y^*$，使得行列式最大：

```
Y^* = argmax_{|Y|=k} det(L_Y)
```

这是一个 NP-hard 问题，但 DPP 的目标函数是**次模函数（submodular）**，可以用贪心算法近似求解，且有常数近似比保证。

### 2.5 贪心求解算法（Fast Greedy MAP）

Hulu 的 Fast-MAP-DPP 论文提出了高效的贪心推断。核心思想：**每次选择一个能使行列式边际增益最大的 item 加入结果集**。

设已选集合为 $S$，候选 item $j \notin S$，将 $j$ 加入后的行列式边际增益为：

```
det(L_{S∪{j}}) = det(L_S) · (L_jj - L_jS · L_S^{-1} · L_Sj)

边际增益 = det(L_S) · (L_jj - L_jS · L_S^{-1} · L_Sj)
```

由于 $\det(L_S)$ 对所有候选 $j$ 是常数，贪心选择等价于最大化：

```
gain(j | S) = L_jj - L_jS · L_S^{-1} · L_Sj
```

其中：
- $L_{jj} = q_j^2$：item $j$ 自身的质量分平方
- $L_{jS}$：item $j$ 与已选集合 $S$ 中各 item 的核值行向量
- $L_S^{-1}$：已选集合核矩阵的逆

**直观解释**：
- $L_{jj}$ 项鼓励选质量高的 item（相关性）
- $L_{jS} L_S^{-1} L_{Sj}$ 项惩罚与已选集合相似的 item（多样性）
- 两者之差就是"净增益"

**贪心算法伪代码**：

```
输入：核矩阵 L (N×N)，目标列表长度 k
输出：重排后的列表 Y（长度 k）

1.  Y = ∅
2.  for t = 1 to k:
3.      对每个 j ∉ Y:
4.          gain(j) = L_jj - L_{jY} · L_Y^{-1} · L_{Yj}
5.      j* = argmax_j gain(j)
6.      Y = Y ∪ {j*}
7.      更新 L_Y^{-1}（用 Cholesky 分解增量更新，避免每次重新求逆）
8.  return Y
```

**效率要点**：Hulu Fast-MAP-DPP 的核心优化是用 **Cholesky 分解增量更新** $L_Y^{-1}$，每次新增一个 item 只需 $O(|Y|^2)$ 而非 $O(|Y|^3)$ 的矩阵求逆，使得 DPP 的计算效率**比 pairwise/listwise ranking 要快很多**（来源：DPP+多样性重排.txt），并且能**基本保持原有的 ranking 排序**（来源：DPP+多样性重排.txt）。

### 2.6 多样性与相关性的平衡

DPP 天然平衡了质量和多样性，但在实际工程中还可以通过参数调节：

| 调节手段 | 作用 | 微视实践 |
|----------|------|----------|
| 质量分 $q_i$ 的缩放 | 放大 $q_i$ → 更偏重相关性；缩小 → 更偏重多样性 | 用精排 pCTR 作为质量分 |
| 相似度矩阵 $S$ 的构造 | 用类目 one-hot → 硬打散；用 embedding 余弦 → 软打散 | 结合内容特征 |
| 前 N 位固定 | 保证头部最高质量 item 不被打散 | **前两个位置不动，后面按 DPP 重排**（来源：DPP+多样性重排.txt） |
| sliding-window | 只在窗口内做 DPP 最优，窗口滑动 | **最新上线版本基于 sliding-window DPP**（来源：DPP+多样性重排.txt） |

**Sliding-Window DPP 原理**：保证滑动窗口内的（多样性和相关性指标）组合最优，每次将窗口进行滑动（来源：DPP+多样性重排.txt）。相比全局 DPP，sliding-window 降低了计算量，同时避免长列表尾部多样性失控。

线上还有**强逻辑补充**：如 topN 不打散（来源：DPP+多样性重排.txt）——即精排 topN 的 item 强制保留原序，不参与 DPP 重排，保证头部核心内容的曝光确定性。

### 2.7 在微视的落地配置

DPP 上线的模块包括（来源：DPP+多样性重排.txt）：
- **精选**：聚合模块、重磅热播、混排模块
- **个人页**：我的下载（底层页）

实时逻辑接口人：longkaihu

**可背诵要点**：
- **DPP 核矩阵 $L_{ij} = q_i q_j s_{ij}$**，质量做幅值、相似度做夹角，行列式 = 体积。
- **贪心选择 = 最大化边际增益 $L_{jj} - L_{jS}L_S^{-1}L_{Sj}$**，前项是质量、后项是与已选集合的相似惩罚。
- DPP 是次模函数，贪心有近似比保证；Hulu Fast-MAP 用 Cholesky 增量更新，效率高于 pairwise/listwise。
- 微视实践：**前两位固定 + sliding-window DPP + topN 不打散**，工程上兼顾质量和多样性。

> **面试口述版**："DPP 的核心是把每个 item 表示成一个向量，向量的长度是质量分（比如 pCTR），向量之间的夹角是相似度。多个向量张成的行列式就是多维空间的体积——体积大意味着边长长（质量高）且夹角大（多样性好）。核矩阵 L 的元素 L_ij = q_i × q_j × s_ij。MAP 推断就是找 k 个 item 让子行列式最大，这是个次模最大化问题，用贪心做：每次选边际增益最大的 item，增益公式是 L_jj 减去它和已选集合的相似惩罚项。Hulu 的 Fast-MAP-DPP 用 Cholesky 增量更新求逆，效率很高。我们在微视是前两个位置不动，后面用 sliding-window DPP 重排，还加了 topN 不打散的强逻辑。"

## 三、个性化重排（Personalized Re-ranking）

### 3.1 问题背景

DPP 解决的是**全局多样性**——对所有用户用同一套相似度度量做打散。但实际上，**不同用户对多样性的偏好是不同的**。

Personalized Re-ranking for Recommendation 这篇论文解决的是**精排排序后的混排问题，是半个多样性问题的解决方案**（来源：Personalized+Re-ranking+for+Recommendation.txt）。

论文指出传统 learning to rank 模型的不足：缺少两类额外信息（来源：Personalized+Re-ranking+for+Recommendation.txt）：
- **a) item 之间的影响**——这就是通常解决的多样性范畴
- **b) 用户与 item 之间的影响**——很少有工作考虑，item 之间的影响会传导到用户

论文的核心创新：**通过一个个性化矩阵 PV（Personalized Vector）来学习用户的编码函数，来个性化 item 之间的影响**（来源：Personalized+Re-ranking+for+Recommendation.txt）。这本质上就是**个性化多样性**。

### 3.2 个性化多样性的直觉

原文举了一个非常好的例子（来源：Personalized+Re-ranking+for+Recommendation.txt）：

> 假设我们有一个多样性打散策略：相邻商品不同类目。
>
> - 一个**对价格敏感**的用户：价格在重排序中应该被凸显，内容的差异程度可能没那么重要。给用户推荐**相似的、但价格不同**的商品可能更促进成交。
> - 一个**对价格不敏感**的用户：浏览内容中应该出现**尽量丰富品类**的内容，促进浏览从而促进成交。

这就是个性化多样性问题——**打散的维度应该因人而异**。价格敏感用户应该在"价格"维度上打散，而不是在"类目"维度上打散。

### 3.3 模型架构

模型分为三部分（来源：Personalized+Re-ranking+for+Recommendation.txt）：

#### 输入层

目标是准备初始化列表中 item 综合的表达送给 encoding 层：

1. **构造定长序列 S**：由精排生成的结果，和精排一样准备原始特征矩阵 X
2. **构造 PV（Personalized Vector）**：
   - 编码两个 item 的特征向量，对 item 之间的相互影响建模
   - 但仅做 item 间影响不足以实现个性化——影响如何传导给用户是未知的
   - PV 是**预训练生成**的，模型结构和精排一致
   - 工程简化：通过对**精排瓶颈层向量的抽取**，在 item 特征上做拼接，引入 `<u, i>` 的差异化权重表达
   - 将 PV 向量和 item 特征向量做连接，得到**拼接矩阵 E**
3. **构造 PE（Position Embedding）**：
   - 在向量 E 上加上一个 PE 矩阵
   - 本质是 **item 级别的 position bias**
   - PE 是学出来的

#### 编码层

使用 **Transformer** 架构，self-attention 机制使得模型可以度量**任意两个 item 之间的距离**，避免了 RNN 受限于距离的特性（来源：Personalized+Re-ranking+for+Recommendation.txt）。通过 attention 把想组合的特征组合起来。

#### 输出层

用 **softmax** 计算每个 item 的点击率，得到重排后的分数。

### 3.4 与全局重排（DPP）的对比

| 维度 | DPP 全局重排 | Personalized Re-ranking |
|------|-------------|------------------------|
| 多样性度量 | 全局统一的相似度矩阵 S | 个性化矩阵 PV，用户级编码 |
| 打散维度 | 固定（类目/内容 embedding） | 因人而异（价格敏感用户在价格维度打散） |
| 模型 | 行列式点过程，无监督/贪心 | Transformer + self-attention，有监督学习 |
| 质量分来源 | 精排 pCTR 作为 q_i | 精排瓶颈层向量拼接 PV |
| 可解释性 | 强（行列式几何意义清晰） | 较弱（attention 权重） |
| 计算效率 | 高（Cholesky 增量更新） | 中等（Transformer 推理） |
| 工程复杂度 | 低 | 中（需预训练 PV、在线推理） |
| 微视状态 | **已上线**（sliding-window DPP） | 论文调研阶段，尝试成本不高 |

**可背诵要点**：
- 全局 DPP 是"所有人用同一把尺子打散"，个性化重排是"每个人的打散维度不同"。
- 论文核心是 **PV 个性化矩阵 + Transformer self-attention**，PV 通过精排瓶颈层向量预训练得到，工程上复用精排结构。
- self-attention 的优势是能度量**任意两个 item 的距离**，不受序列距离限制（RNN 的痛点）。
- 输入 = item 特征拼接 PV + PE 位置偏置，编码 = Transformer，输出 = softmax 点击率。

> **面试口述版**："DPP 是全局多样性，所有用户用同一套相似度。但个性化重排这篇论文指出，多样性应该因人而异——比如价格敏感的用户，应该在价格维度上打散，给他推荐相似但价格不同的东西；价格不敏感的用户才需要丰富品类。模型用 Transformer 做编码，self-attention 能捕捉任意两个 item 的相互影响。关键是引入了一个 PV 个性化向量，通过精排瓶颈层预训练得到，和 item 特征拼接后输入 Transformer，再加上可学习的位置编码 PE，最后 softmax 输出重排分数。工程上复用精排结构，尝试成本不高。"

## 四、曝光量分布约束下的分配策略

> 注：本章节对应源文件「曝光量分布约束下的分配策略.txt」原文内容缺失（仅含标题与"网络请求失败！"），以下内容基于保量机制一/二期中曝光约束、流量分配相关设计归纳整理。

### 4.1 为什么需要曝光量分布约束

推荐系统如果纯按 pCTR 排序，会导致**马太效应**：头部内容曝光越来越多，长尾内容永远没有机会。这在短视频/长视频平台都有问题：
- 新上线内容没有冷启动曝光，无法积累数据
- 商业化售卖的内容（贴片广告）需要保证 VV 达到约定量级
- 多平台播放的内容需要在竞品对比中保证分发量
- 优质内容需要打造品质感，需要分发保障

保量系统的定位是：**在完成有保量诉求/播放诉求/商业化诉求内容的分发基础上，灵活地释放出更多长尾流量，带来全平台整体的正向收益**（来源：保量机制一期.txt）。

### 4.2 曝光约束建模：海报位三分法

微视一期的做法是将海报位区分为三类（来源：保量机制一期.txt）：

| 位置类型 | 占比 | 用途 | 配置方式 |
|----------|------|------|----------|
| **运营锁定** | 固定位 | 新上线内容 N 天锁定，完成强曝光诉求 | CMS 配置 |
| **保量配比** | ≤80% | 按比例对需要保量的内容进行曝光保量，保证有 VV 要求的内容被扶持 | CMS 配置曝光占比 |
| **个性化推荐** | 剩余位 | 长尾推荐，提升整体效果 | 算法推荐 |

**关键约束**：与运营商议的保量百分比**尽量控制在 80% 以内**（来源：保量机制一期.txt），留出至少 20% 的位置给个性化长尾推荐，避免保量挤占过多算法流量。

### 4.3 流量分配的优先级排序

保量配比的排序逻辑分三级优先级（来源：保量机制一期.txt）：

```
第一优先级：锁定 —— 不做曝光过滤，强制出
第二优先级：保量 —— 依据 CMS 配置的曝光占比，采用 PID 控制方式
         保证保量 item 的效果和曝光量 + 兜底逻辑
第三优先级：推荐 —— 未选取上的保量内容加入推荐召回
```

**排序规则**：保量后的分数与推荐 pCTR **统一排序**（来源：保量机制一期.txt）。也就是说，保量 item 不是硬插入，而是通过加权后的分数和推荐 item 一起竞争排序位置。

### 4.4 生态平衡设计

- **保量去重**：保量内容只做 **cid 去重**，不做同栏目去重（来源：保量机制一期.txt）——保证保量内容能充分曝光
- **推荐去重**：推荐内容做**同栏目/同 cid 去重**（来源：保量机制一期.txt）——保证推荐位的多样性
- **未选中的保量内容回流推荐池**：未被保量选中的内容加入所有视频列表按 pCTR 排序，补齐要出的个数（来源：保量机制一期.txt）
- **兜底机制**：当曝光实时数据延迟 10 分钟以上时，按保量 1.0 方案出——生成一个随机数，对比配置的曝光占比来判断是否出（来源：保量机制一期.txt）

**可背诵要点**：
- 曝光约束的核心是**三分法**：运营锁定 + 保量配比（≤80%）+ 个性化推荐（≥20%）。
- 保量 item 不是硬插入，而是**加权后和推荐 pCTR 统一排序**，兼顾业务目标和算法效果。
- 生态平衡靠"保量位宽松去重 + 推荐位严格去重 + 未选中回流"实现。

> **面试口述版**："曝光量分配我们用的是三分法——运营锁定位、保量配比位、个性化推荐位。保量占比控制在 80% 以内，至少留 20% 给长尾。保量内容不是硬插的，是加权后和推荐 pCTR 一起统一排序。去重策略也有区分：保量位只做 cid 去重保证曝光充分，推荐位做同栏目和 cid 去重保证多样性。没被保量选中的内容会回流到推荐池继续竞争。"

## 五、保量机制

### 5.1 一期方案：运营配比 + PID 控制

#### 5.1.1 一期定位

在保量模块（长视频频道页卡头部的六小图模块），对内容进行一定比例的曝光保量，希望使内容整体符合分发诉求（来源：保量机制二期.txt）。

支持频道：**精选、电视剧、动漫、电影、综艺**（来源：保量机制一期.txt）。

#### 5.1.2 PID 控制原理

一期的核心技术是 **PID 控制器**（比例-积分-微分控制器），由比例单元（P）、积分单元（I）和微分单元（D）组成，通过调整 $K_p, K_i, K_d$ 三个增益来调定特性（来源：保量机制一期.txt）。

**误差定义**：

```
e(i) = displayRatio(i) - cidRatio(i)

其中：
  displayRatio(i) = 第 i 个时间分片中，玲珑系统(CMS)配置的 cid 曝光占比
  cidRatio(i) = 实际 cid 在整个模块中的曝光占比 = cidPV(i) / modulePV(i)
  cidPV(i) 和 modulePV(i) 都是当天 0 点开始累计的曝光量
```

**时间分片设计**：
- 每 **5 分钟**为一个分片
- 只保留 **2 小时**分片数据，共计 **24 个分片**（来源：保量机制一期.txt）
- 分片逆序排列：分片1 = 最近5分钟，分片24 = 2小时前

**PID 输出**作为保量 item 的加权分数，与推荐 pCTR 统一排序。PID 的三个单元作用：
- **P（比例）**：当前误差越大，加权越强——快速响应缺量
- **I（积分）**：累计历史误差——消除稳态偏差，保证最终达标
- **D（微分）**：误差变化趋势——抑制超调，避免过度扶持

#### 5.1.3 一期实验安排

1. 只将 PID 公式替换现有的保量公式，选保量 cid 的逻辑不变
2. 不特意安排出保量流量，只用 PID 公式计算后的分数排序（来源：保量机制一期.txt）

#### 5.1.4 一期存在的问题

二期文档明确指出了一期的两个核心问题（来源：保量机制二期.txt）：

1. **局部模块场景保量曝光，与 VV 有一定差距，不一定能达到效果；利用率较低**——只在频道页卡头部六小图模块保量，曝光量有限，无法满足大剧的 VV 诉求
2. **技术手段上**：现有的保量是在重排层做加权，召回层是当一路硬性召回，硬性召回在某些模块可能不适用（比如明星模块等），需改为在召回和重排层做加权，需要解决的问题是**新内容如何实时进入召回池**

### 5.2 二期方案：全局定量扶持机制

#### 5.2.1 二期定位

保量二期预期升级为**整体的定量扶持机制**（来源：保量机制二期.txt）：
- 以定量扶持的方式，在各个场景、针对各个内容，从召回/算法/排序等多个角度进行全方位扶持
- 不局限于头部内容，成为一套**通用、适应性强**的方案
- 全局推荐场景生效
- 支持不同类型的保量/冷启动诉求

#### 5.2.2 业务诉求分类

二期梳理了四类保量诉求（来源：保量机制二期.txt）：

| 诉求类型 | 具体场景 |
|----------|----------|
| 商业化诉求 | 头部内容进行了商业化售卖，为保证贴片收入，内容的 VV 必须达到一定量 |
| 竞品对比诉求 | 部分内容多平台播放，竞品对比过程中，需要保证平台分发量达到一定程度 |
| 品质打造诉求 | 部分优质、高质量内容，为打造品质感，需要有一定的分发保障或分发冷启动诉求 |
| 任务性诉求 | 部分任务性的内容诉求，需要保障分发 |

#### 5.2.3 二期核心算法：VV 预估驱动的动态保量

二期不再依赖 CMS 手动配置曝光占比，而是**基于预估 VV 自动计算所需曝光占比**（来源：保量机制二期.txt）：

**步骤 1：单集 VV 预估**
```
新栏目/专辑上线前，通过相似内容的经验 + 前期预估总 vv 量
（媒资中的 estimate_vv_for_ad），预测每一期(集)的 vv 量
```

**步骤 2：当天 VV 预估函数**
```
item 当天的 vv 量 = f(已更新集数, 已更新天数)
```

**步骤 3：实时动态调整**
```
item_vv = f(已更新集数, 已更新天数) + 前期缺量
（实时拉取媒资信息，当天所需 vv 量随着 item 的更新随时变化）
```

**步骤 4：全平台 VV 预估**
```
all_vv = f(工作日, 节假日, 周一~日, 寒暑假)
```

**步骤 5：计算所需曝光占比**
```
item 当天所需的 vv 占比 = item_vv / all_vv
用这个数据替代现有的 CMS 保量配置
```

**步骤 6-7：实时统计**
- 分 item + 平台分桶的当天累计信息：精选频道的曝光量、播放量、CTR；全平台的曝光量、播放量、CTR
- 分 item + 平台分桶的切片信息：全平台的曝光量、播放量、CTR
- 分平台桶统计全平台的 VV，计算 item 的实际 VV 占比

**步骤 8：闭环控制**
```
实时部分根据步骤 5、6、7 的结果，替代原保量中的
"期望曝光占比"和"实际曝光占比"两个参数，传给引擎
```

**特殊情况**：若没有明确预估 VV，则根据诉求定级确定扶持力度（来源：保量机制二期.txt）。

#### 5.2.4 保量体系通用化：全链路加权

二期将保量从"重排层单点加权"升级为**全链路扶持**（来源：保量机制二期.txt）：

| 链路环节 | 保量手段 |
|----------|----------|
| **召回** | 召回池粗排时，加大保量内容权重，保证其有可能出现在精排内容中 |
| **排序** | 排序时进行 pCTR 加权 |
| **外显逻辑** | 曝光/播放过滤；模块间去重；模块内去重；同栏目同系列去重等灵活定义 |

**核心难点**：解决**内容实时入库**的问题——新内容如何实时进入召回池（来源：保量机制二期.txt）。

### 5.3 一二期融合方案

二期最终落地的是**一二期融合保量**（来源：保量机制二期.txt）：

> 一期运营配置保量模块，保证保量模块曝光量的同时，引入二期商业化预估 VV 指标，在尽量不降低总 VV 的同时，帮助运营同学保量头部内容。运营可以调整这个内容的预估总 VV 指标，推荐来把控保量力度。

#### 5.3.1 缺量分级加权

根据 item 的预估缺量比例，配置扶持力度（来源：保量机制二期.txt）：

```
实验配置：
"ka_sec_weight": "0_0.1_1.05:0.1_0.3_1.1:0.3_0.5_1.2:0.5_0.8_1.3:0.8_1_1.35"
```

| 缺量比例区间 | 扶持力度（pCTR 乘数） |
|-------------|---------------------|
| (0, 10%] | 1.05 |
| (10%, 30%] | 1.1 |
| (30%, 50%] | 1.2 |
| (50%, 80%] | 1.3 |
| (80%, 100%] | 1.35 |

即：缺量越多，加权力度越大，从 1.05 到 1.35 递增（来源：保量机制二期.txt）。

#### 5.3.2 实验结果

实验组（182803）vs 对照组（182801）（来源：保量机制二期.txt）：

| 指标 | 结果 | 显著性 |
|------|------|--------|
| 精选页卡缺量栏目各项指标 | 均有显著提升 | 显著 |
| 精选频道综艺品类播放用户 | **+0.78%** | 显著 |
| 精选频道综艺品类 VV | **+0.9%** | 显著 |
| 整体综艺品类播放用户量、人均播放时长 | 略有提升 | — |
| 整体综艺品类 VV | — | 不显著 |
| 精选页人均 VV、人均时长 | **略降约 0.5%** | — |
| APP 全局影响 | — | 不显著 |

**结论**：保量融合方案显著提升了缺量内容的分发效果和综艺品类指标，对全局无显著负向影响，精选页人均指标略有下降但在可接受范围内。

### 5.4 一期 vs 二期对比

| 维度 | 一期 | 二期 |
|------|------|------|
| 生效范围 | 局部模块（频道页卡头部六小图） | **全局推荐场景** |
| 保量目标 | 曝光占比（CMS 手动配置） | **VV 量（预估驱动，自动计算）** |
| 控制方式 | PID 控制曝光占比 | 闭环 VV 保量 + 开环固定加权 |
| 加权位置 | 仅重排层加权 + 硬性召回 | **召回 + 排序 + 外显全链路** |
| 配置方式 | CMS 配置曝光占比 | 媒资 estimate_vv_for_ad 自动计算 |
| 适用内容 | 头部内容 | 头部 + 长尾 + 冷启动，通用化 |
| 时间粒度 | 5 分钟分片，保留 24 个分片 | 实时统计 + 当天累计 + 切片 |
| 核心问题 | 局部曝光与 VV 有差距，利用率低 | 需解决内容实时入库 |
| 最终形态 | — | 一二期融合：缺量分级加权（1.05~1.35） |

**可背诵要点**：
- 一期用 **PID 控制器**做曝光占比闭环，5 分钟一个分片，保留 24 个分片，误差 = 配置占比 - 实际占比。
- 二期升级为**全局 VV 定量扶持**，通过 `item_vv / all_vv` 自动计算所需占比，全链路加权（召回+排序+外显）。
- 最终落地**一二期融合**：按缺量比例分级加权，缺量 (0,10%]→1.05 到 (80%,100%]→1.35。
- 实验：精选综艺播放用户 +0.78%、VV +0.9%，全局无显著负向。

> **面试口述版**："保量我做了一期和二期。一期是在频道页卡的六小图模块，用 PID 控制器做曝光占比闭环——每 5 分钟一个分片，误差是 CMS 配置占比减实际占比，PID 输出作为加权分和 pCTR 统一排序。但一期只在局部模块保量，和 VV 目标有差距。二期升级为全局定量扶持，基于媒资里的预估总 VV，用 f(已更新集数,已更新天数) 算当天所需 VV，除以全平台预估 VV 得到所需占比，自动替代 CMS 配置，而且从召回、排序到外显全链路加权。最终我们用了一二期融合方案，按缺量比例分五级加权，从 1.05 到 1.35。实验结果是精选综艺播放用户涨了 0.78%，VV 涨了 0.9%，全局没有显著负向。"

## 六、重排与多样性的评估指标

### 6.1 多样性指标

| 指标 | 定义 | 含义 |
|------|------|------|
| **覆盖率（Coverage）** | 被推荐过的 item 数 / 总 item 数 | 长尾内容是否获得曝光，越高越好 |
| **类目覆盖率** | 推荐列表中出现的类目数 / 总类目数 | 列表是否覆盖多种品类 |
| **基尼系数（Gini）** | 曝光量分布的不平等程度，0=完全平均，1=极端不均 | 衡量曝光公平性，越低越公平 |
| **熵（Entropy）** | 推荐列表中类目分布的信息熵 $-\sum p_i \log p_i$ | 列表多样性，越高越多样 |
| ** intra-list similarity** | 列表内 item 两两相似度的平均值 | 越低越多样（DPP 中对应夹角大） |

### 6.2 保量/生态指标

| 指标 | 定义 | 微视实践中的用法 |
|------|------|-----------------|
| **保量达成率** | 实际 VV / 目标 VV | 保量系统核心 KPI |
| **曝光占比偏差** | $\|displayRatio - cidRatio\|$ | PID 控制的误差项 |
| **缺量比例** | (目标 VV - 实际 VV) / 目标 VV | 二期分级加权的依据 |
| **模块 PV / CID PV** | 模块总曝光 / 单个 cid 曝光 | cidRatio = cidPV / modulePV |

### 6.3 用户满意度指标

| 指标 | 含义 |
|------|------|
| **人均 VV** | 人均播放量，重排不应显著降低 |
| **人均时长** | 人均播放时长，多样性提升浏览深度 |
| **CTR** | 点击率，相关性的直接体现 |
| **换一换率** | 用户点击"换一换"的比例，过高说明列表质量差 |

### 6.4 指标间的权衡

DPP 和保量都面临**多样性 vs 点击率**的权衡。微视的实践经验：
- DPP 通过**前两位固定**保证头部 CTR 不损失，尾部做多样性
- 保量通过**加权后统一排序**而非硬插入，尽量减少对 CTR 的影响
- 一二期融合实验中，精选页人均 VV/时长略降约 0.5%，但全局不显著（来源：保量机制二期.txt），说明局部扶持的代价可控

## 七、面试话术

### 7.1 口述版（3 分钟项目介绍）

> "我在腾讯微视负责推荐系统的重排层，主要做了三块工作。
>
> 第一块是 **DPP 多样性重排**。精排是 pointwise 的，相似 item 分数接近导致头部扎堆。我用 DPP（行列式点过程）解决——把每个 item 表示成向量，长度是质量分（pCTR），夹角是相似度，多个向量张成的行列式就是体积，体积大意味着质量高且多样性好。核矩阵 L_ij = q_i × q_j × s_ij，MAP 推断用贪心做次模最大化，每次选边际增益最大的 item。我们基于 Hulu 的 Fast-MAP-DPP 实现，用 Cholesky 增量更新保证效率，线上用 sliding-window DPP，前两位固定、topN 不打散，上线了精选和个人页的多个模块。
>
> 第二块是**保量机制**。一期用 PID 控制器做曝光占比闭环，5 分钟一个分片，在频道页卡六小图模块保量。二期升级为全局 VV 定量扶持，基于媒资预估 VV 自动计算所需曝光占比，全链路加权。最终落地一二期融合，按缺量比例分五级加权（1.05 到 1.35），实验使精选综艺播放用户 +0.78%、VV +0.9%，全局无显著负向。
>
> 第三块是对**个性化重排**的调研。DPP 是全局多样性，但不同用户对多样性的偏好不同——价格敏感用户应该在价格维度打散。Personalized Re-ranking 这篇论文用 Transformer + 个性化 PV 向量实现用户级重排，我评估了工程可行性，复用精排瓶颈层向量做 PV 预训练，尝试成本不高。"

### 7.2 高频 Q&A

**Q：为什么要做重排？精排不够吗？**

A：精排是 pointwise 的，每个 item 独立打分，最大的问题是相似 item 打分过于接近，导致列表头部同类目扎堆。比如用户喜欢电视剧，精排可能把 5 部同类型剧全堆前面。重排做的是列表级优化，同时考虑 item 质量和 item 间的相似度，还要满足保量、打散等业务约束。精排保证"每个 item 本身好"，重排保证"整个列表组合好"。（来源：DPP+多样性重排.txt）

**Q：DPP 的原理是什么？核矩阵怎么构造？**

A：DPP 的核心是行列式的几何意义——多维空间中向量张成的体积。每个 item 表示为向量 φ_i = q_i × f_i，q_i 是质量分（幅值），f_i 是内容特征（方向）。核矩阵 L_ij = φ_i · φ_j = q_i × q_j × s_ij，其中 s_ij 是余弦相似度。子集 Y 被选中的概率正比于 det(L_Y)。行列式大 = 幅值大（质量高）且夹角大（多样性好），所以 DPP 天然平衡了相关性和多样性。（来源：DPP+多样性重排.txt）

**Q：DPP 的贪心求解具体怎么做？**

A：MAP 推断是找 k 个 item 让子行列式最大，这是次模最大化问题，用贪心近似。已选集合 S，候选 j 的边际增益 = L_jj - L_jS × L_S^{-1} × L_Sj。前项 L_jj = q_j² 是质量奖励，后项是与已选集合的相似惩罚。每次选增益最大的加入。Hulu Fast-MAP-DPP 用 Cholesky 分解增量更新逆矩阵，每次 O(|S|²)，效率比 pairwise/listwise 高很多。（来源：DPP+多样性重排.txt）

**Q：多样性和点击率怎么平衡？会不会为了多样性损失 CTR？**

A：我们在工程上做了几层保护。第一，DPP 的质量分直接用精排 pCTR，所以质量本身就在目标函数里。第二，**前两个位置不动**，保证头部最高质量 item 不被打散。第三，用 **sliding-window DPP**，只在窗口内做最优，避免全局 DPP 把尾部排得太散。第四，加了 **topN 不打散**的强逻辑。实验上 DPP 能基本保持原有 ranking 排序，计算效率也比 pairwise/listwise 快。（来源：DPP+多样性重排.txt）

**Q：保量是怎么做的？PID 控制怎么用在推荐里？**

A：一期保量用 PID 控制器。误差 e(i) = CMS 配置的 cid 曝光占比 - 实际曝光占比，实际占比 = cidPV / modulePV，都是当天累计。每 5 分钟一个分片，保留 24 个分片。PID 的 P 项快速响应缺量，I 项消除稳态偏差保证最终达标，D 项抑制超调。PID 输出作为保量 item 的加权分，和推荐 pCTR 统一排序，不是硬插入。兜底逻辑是数据延迟超 10 分钟时退化为随机数对比配置占比。（来源：保量机制一期.txt）

**Q：保量一期和二期有什么区别？为什么做二期？**

A：一期只在频道页卡头部六小图模块保量，是局部曝光，和 VV 目标有差距，利用率低；而且只在重排层加权，召回层是硬性召回，某些模块（如明星模块）不适用。二期升级为全局定量扶持：基于媒资 estimate_vv_for_ad 预估每集 VV，用 f(已更新集数,已更新天数) 算当天所需 VV，除以全平台预估 VV 得到所需占比，自动替代 CMS 配置；而且从召回、排序到外显全链路加权。最终落地一二期融合，按缺量比例分级加权。（来源：保量机制二期.txt）

**Q：什么是个性化重排？和 DPP 有什么区别？**

A：DPP 是全局多样性，所有用户用同一套相似度度量。个性化重排指出多样性应该因人而异——比如价格敏感用户应该在价格维度打散，给他推荐相似但价格不同的商品；价格不敏感用户才需要丰富品类。模型用 Transformer 做编码，self-attention 能捕捉任意两个 item 的相互影响，关键是引入 PV 个性化向量，通过精排瓶颈层预训练得到，和 item 特征拼接后加位置编码 PE，最后 softmax 输出。区别是 DPP 无监督、可解释性强、效率高；个性化重排有监督、能学用户级多样性，但工程复杂度更高。（来源：Personalized+Re-ranking+for+Recommendation.txt）

**Q：重排层除了 DPP 和保量，还有哪些逻辑？**

A：微视的重排层是一个综合模块。除了 DPP 多样性打散和 PID 保量加权，还有：运营锁定位（新内容 N 天强曝光）、类目打散、同栏目/同 cid 去重、保量内容只做 cid 去重不做同栏目去重、上下架过滤、冷启动专辑强制分发、模块间去重、topN 不打散等强逻辑。这些规则和算法加权一起工作，最终统一排序输出。（来源：DPP+多样性重排.txt、保量机制一期.txt、保量机制二期.txt）

**Q：sliding-window DPP 和全局 DPP 有什么区别？为什么用 sliding-window？**

A：全局 DPP 是对整个候选列表做行列式最大化，计算量随列表长度增长，而且长列表尾部的多样性可能失控。sliding-window DPP 保证滑动窗口内的（多样性和相关性指标）组合最优，每次将窗口滑动。这样做的好处是：计算量只和窗口大小相关，降低了延迟；同时局部最优比全局最优更稳定，避免尾部 item 被过度打散。我们最新上线的版本就是基于 sliding-window DPP。（来源：DPP+多样性重排.txt）
