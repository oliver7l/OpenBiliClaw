## 1. 概述

### 1.1 图集是什么业务
- QQ 看点主 feeds 中，图集**只占一个单曝光位**（每刷约10个内容位里占1个）。
- 用户在主 feeds 点下图集封面后，进入**浮层"一拖N"消费**：在一个大图（gallery）下带出 N 张关联图/后续图集，连续滑动消费。
- 与"主 feeds 单卡片消费"的本质差异：**一次点击 = 一串连续消费**，因此优化目标不能只看点击率，还要看"进入浮层后是否持续划（一拖N转化率）"和"总消费时长"。

### 1.2 图集与主 feeds 的差异

| 维度 | 主 feeds | 图集浮层 |
|---|---|---|
| 曝光单元 | 单卡片 | 1个封面 + N张图/后续图集 |
| 核心行为 | 点击 | 进入浮层后连续滑动（一拖N） |
| 主优化目标 | 点击率 | 点击率 × 一拖N转化率（连续消费深度） |
| 负反馈 | 曝光未点击 | 曝光未点击 + 浮层内早退（read_end_rate 低） |
| 品类结构 | 图文/视频混合 | 纯图集，但跨数十个品类（娱乐/动漫/游戏/美女/美食/体育…） |

### 1.3 浮层交互与产品形态（补充）
- 用户路径：主feeds 单卡片（封面+标题）→ 点击 → 全屏浮层，左滑/上下滑看"一拖N"后续图。
- 浮层内可继续划到"下一个图集"（nextpv / has_1ton 字段），形成连续消费流。
- 产品侧（图片社设计方案，手Q 8.0.0）：瀑布流 + 话题/UGC 图集，与推荐链路配合提升供给。
- 推荐要同时优化"封面是否吸点"（影响点击率）和"浮层是否留得住"（影响一拖N转化率/时长），二者目标部分冲突，是多任务建模的根本动机。

## 2. 业务特点与建模难点

### 2.1 多品类统一推荐
- 单一曝光位要服务数十个品类（娱乐/动漫/游戏/美女/美食/体育/财经/数码…），各品类点击率差异极大：
  - 高活用户中"占卜"点击率可达 ~27.9%、"娱乐"~22.8%；而"科技"仅~12.9%、"农林牧副渔"~12.6%（见 `用户分层分析.xlsx` 中活 sheet）。
- 难点：通用模型易被头部品类（娱乐/美女/动漫）主导，长尾品类（财经/汽车/数码）曝光不足。

### 2.2 消费行为差异
- 浮层内"一拖N"行为：用户进入后可能连续划多张（read_to_next_rate / read_end_rate 衡量），也可能早退。
- 资料中引入 `gallery/read_to_next_rate`（划到下一张率）、`gallery/read_end_rate`（读完率）、`gallery/read_wilson_score`（威尔逊排序分数）作为图集质量信号。

### 2.3 时长 vs 点击的冲突（核心矛盾）
- 提升点击率 ≠ 提升总消费时长/PV。资料明确记录一个**负向实验**：
  - "点击+一拖N多目标" 直接并入排序时，点击率 **-4.73%**（实验记录多次出现，line 1943/1975/3090/3122）。
  - 原因：一拖N转化好但封面点击一般的图集被推上来，短期拉低封面点击率。这是真实踩坑，见第8节。

### 2.4 用户分层差异
- 资料按活跃度分 `低活/中活/高活`（chann_ch = 1/2/3）建模，不同层品类偏好与点击率量级不同：
  - 低活"娱乐"点击率 ~18.6%、中活"娱乐"~22.8%，高活更高。
  - 长尾品类在低活用户中点击率普遍偏低（科技~10.3%、农林~9.6%）。

### 2.5 品类点击率差异（来源：`用户分层分析.xlsx` 中活 sheet）

### 2.6 图集质量评估（威尔逊排序）
- 浮层一拖N质量用 `gallery/read_wilson_score`（威尔逊置信区间下界）排序，避免小样本高点击率图集虚高。

### 2.7 冷启动与兜底
- 冷启动：冷启动实时画像召回（点击率 0.0562）+ 优质池召回（0.0497）+ 图集频道画像（0.0384）兜底长尾。
- 兜底召回优化使点击pv +4.25%（主Feeds阶段性总结），是低成本稳增长手段。

## 3. 召回

### 3.1 召回源总览（多路召回架构）

| 召回源 | 曝光PV(示例) | 点击率(示例) | 消费深度(次均pv) | 说明 |
|---|---|---|---|---|
| gallery2vec（深度向量） | 3,456,145 | 0.1131 | 6.33 | 图集向量双塔 |
| YouTube Net（深度） | 1,444,987 | 0.1266 | 3.87 | 类 YouTube 召回 |
| DSSM Net（深度） | 854,514 | 0.1158 | 2.71 | DSSM 双塔召回 |
| 中期画像 | 554,729 | 0.1268 | 2.68 | 中期用户画像 |
| 实时画像 | 345,210 | 0.1180 | 2.59 | 实时行为画像 |
| 热门召回 | 284,836 | 0.0762 | 1.86 | 全局/分类热门 |
| 优质池召回 | 46,774 | 0.0497 | 1.67 | 优质内容池 |
| 冷启动实时画像 | 39,382 | 0.0562 | 1.65 | 冷启动 |
| 图集频道画像 | 5,471 | 0.0384 | 2.34 | 频道级 |

> 来源：`多目标实验数据.xlsx` / 实验数据分篇（line 2076-2084）。注意各召回源点击率口径差异大，深度召回与画像召回贡献主要消费深度。

### 3.2 双塔 / DSSM 结构（对应简历"DSSM 召回"）
- 图集深度召回采用双塔范式：`gallery2vec`、`YouTube Net`、`DSSM Net` 三路，均为"用户塔 / 图集塔"向量化后 ANN 检索。
- `DSSM Net` 在实验中点击率 0.1158（line 2078），与 gallery2vec(0.1131)、YouTube Net(0.1266) 同量级，是主力深度召回之一。

### 3.3 负样本
- 特征 spec 中明确存在 **隐形负反馈**字段：`user/neg-tag-ids`（用户负反馈 tag），用于抑制用户不感兴趣品类。
- 正负样本比例约 **1:6.8**（来源：features 资料 source 1 与 source 4），属典型曝光未点击负样本主导，需注意负采样。

### 3.4 ANN 与有效召回率
- 主Feeds阶段性总结（2019-03）：由**单召回改为多路召回**后，`召回不足比例降低 5.32%`，`点击pv +1.55%`（line 16434 区域）。
- `有效召回率`：以"曝光后能否被模型排到"衡量；多路召回解决了单路覆盖不足导致的长尾缺失。

### 3.5 多目标召回 / 探索流量
- 召回层也承担多样性：资料指出"两次召回都集中在头部标签，比较同质化"（line 9293），故召回层加入多样性考量，配合重排打散。
- 兜底召回 + 探索流量：兜底优化使 `点击pv +4.25%`（主Feeds阶段性总结）。

### 3.6 召回 → 排序漏斗与一拖N 关联
- 召回产出候选后，经粗排（轻量）→ 精排（DIN+RNN+FM + ESMM 多任务）→ 重排（多样性打散 + 隐形负反馈）。
- 各召回源对"一拖N消费深度"（次均pv）贡献不同：gallery2vec 次均pv 6.33 远高于热门召回 1.86，说明深度/画像召回不仅提点击也提消费深度。

### 3.7 ANN 检索实现要点（双塔）
- 用户塔/图集塔分别产出 embedding，serving 端用 ANN（近邻检索）从全量图集库取 TopK。
- 双塔解耦使"用户特征实时、图集特征离线"可独立更新，适合图集库每日更新的场景。

### 3.8 召回负样本与曝光去重
- 双塔训练负样本：除曝光未点击外，常做 in-batch / 全局负采样扩充负例，缓解 1:6.8 正负比带来的偏向。
- 同一用户已曝光/已点图集需在召回候选中做去重与过滤，避免重复曝光（也关系到多样性）。
- 冷启动图集（无统计）靠实时画像召回 + 优质池召回触达，避免新内容死在召回层。

## 4. 排序

### 4.1 排序模型演进（AUC 实测，来源：模型实验 sheet）

| 模型 | AUC |
|---|---|
| LR | 0.6798 |
| DNN | 0.6821 |
| DNN（另一版） | 0.6921 |
| DIN + RNN + FM | 0.7013 |

> 演进路径（资料记录）：LR → DNN → Wide&Deep → DeepFM → DCN → DIN → xDeepFM → DIN+RNN(+FM)。最终线上主力为 **DIN+RNN+FM（AUC 0.7013）**。

### 4.2 用户兴趣建模（DIN + Mask + RNN/AUGRU）
- **Attention（DIN）**：对用户历史行为序列做注意力加权。实验：DIN vs DNN 点击率 +0.53%。
- **Mask 层**：解决 `UNK`（未登录词/新图集）补全问题——历史序列中出现 UNK 时通过 mask 避免污染 attention。
- **RNN / AUGRU**：建模兴趣演变（序列顺序）。实验：RNN vs DNN 点击率 +1.37%。
- 兴趣序列类型（特征 drop 实验，line 1859-1861）：
  - `最近点击序列`：去掉后 AUC -0.0106（最重要）
  - `曝光未点击序列`：去掉后 AUC -0.0053（隐形负反馈信号强）
  - `一拖N完成序列`：去掉后 AUC -0.0035

### 4.2.1 DIN 注意力机制（可深挖公式）
- DIN 核心：用户表示 = 对行为序列 `{e_i}` 的注意力加权和：`v_u = Σ a(e_i, e_target)·e_i`，其中 `a` 由候选图集 `e_target` 与历史行为 `e_i` 局部激活（不共享全局 user vector）。
- Mask 层：历史序列 padding/UNK 位置 mask 置 0，避免无效位置参与 attention 求和。
- RNN/AUGRU：在 DIN 之上加序列顺序建模，AUGRU 用 attention update gate 抑制兴趣漂移（资料以 RNN vs DNN +1.37% 验证顺序有效）。

### 4.3 ESMM 与多任务（对应简历"ESMM 排序"）
- 真实结构（童力 `看点图集推荐总结.pptx` Slide 17/19，line 8848-8884 / 9245-9250）：
  - 引用论文《Entire Space Multi-Task Model: An Effective Approach for Estimating Post-Click Conversion Rate》。
  - **pCTR Task**：有点击行为的展现标记正样本，否则负样本。
  - **pCTCVR Task**：同时有点击和"转化（一拖N完成/购买）"的展现标记正样本，否则负样本。
  - 两塔**共享 embedding**，在全样本空间（曝光→点击→转化）建模，解决传统 CVR 的 SSB（样本选择偏差）与数据稀疏。
- 业务映射：图集的"转化"= 进入浮层后**一拖N连续消费完成**。排序目标 = `pCTR × pCTCVR`（ESMM 公式）。
- 多任务子网络：`点击率预估` + `一拖N转化率预估` 并行，共享基础特征。

### 4.3.1 ESMM 损失与训练（可深挖）
- 联合损失：`L = L_ctr + L_cvr`，其中 `L_ctr` 在"曝光→点击"全空间、`L_cvr`(CTCVR) 在"曝光→点击→转化"全空间。
- 线上打分：`score = pCTR × pCTCVR`（ESMM 核心乘积形式），兼顾"点不点"与"点进去消不消费"。
- 共享 embedding 让 CVR 子网络也能从"只曝光未点击"的样本学习，缓解稀疏。

> ⚠️ 简历写"ESMM 排序"——**真实成立**，但需讲清：它是 feeds 点击率 + 一拖N转化率 的**全空间多任务**，不是单 CTR 模型。

### 4.4 关于简历"MMoE"
- 原文 **0 次**出现 MMoE。图集排序的多任务是用 ESMM 共享塔 + 并行子网络实现，**未使用 MMoE 的 gate/专家结构**。
- 若面试被问"为什么不用 MMoE"，可答：ESMM 已通过共享 embedding + 全空间建模解决多目标，图集阶段未引入 MMoE 的专家分化；MMoE 是后续项目/内部更细的多任务方案。

### 4.5 多目标融合权重
- 排序打分 = 融合 `pCTR` 与 `pCTCVR`（及一拖N深度）为多目标分。
- 注意真实负向实验：`点击+一拖N多目标` 直接加权导致点击率 **-4.73%**（line 1943/1975）。说明融合权重/联合训练方式需要调参，不能简单线性相加。

### 6.2 特征工程要点
- **共享 Embedding + Weight Embedding**：品类/标签 id 用共享 embedding，权重（如 portrait weight、recent weight）单独编码。
- **二模态融合**：图片（VGG/Bert 视觉向量）+ 文本（标题/标签）双路融合表征图集。
- **预训练图片向量**：特征实验中"有无预训练图片向量"贡献点击率 +0.65%（有正向但非最大）。
- **特征重要性（drop 实验，AUC 下降量）**：
  - 去掉 `最近点击序列`：-0.0106（最重要）
  - 去掉 `实时画像特征`：点击率 -4.19%
  - 去掉 `最近点击序列`（点击率口径）：+3.15%
  - 去掉 `点击序列权重`：+0.41%
  - 去掉 `年龄`：AUC -0.0004；去掉 `城市`：AUC -0.0002（弱特征）

- 两者 concat/attention 融合为图集 item embedding，供双塔召回与排序共享。

## 9. 面试 Q&A（深挖向，≥12组）

> 答题原则：先讲图集真实结构，再对齐简历术语；遇到 MMoE/MiNet 等资料未出现的词，**主动澄清边界**，不杜撰。

**Q1. 图集推荐和主 feeds 推荐核心区别是什么？**
A. 图集只占主feeds一个曝光位，点击后进入浮层"一拖N"连续消费。优化目标不是单点点击率，而是 封面点击率 × 一拖N转化率 × 总消费时长。一次点击对应一串消费，所以必须做多目标（ESMM）。

**Q2. 简历写 DSSM+MMoE 召回，具体怎么做的？**
A. 图集深度召回用的是双塔范式：gallery2vec / YouTube Net / DSSM Net 三路向量召回，DSSM Net 点击率 0.1158，离线用 ANN 检索。需要诚实说明：**图集第一手资料里没有 MMoE 结构**，MMoE 是我后续多任务模块的内部命名；图集召回的多目标分化靠多路召回源 + 排序多任务实现，而非 MMoE gate。

**Q3. 为什么用 ESMM 而不是普通 CVR 模型？**
A. 图集"转化"=进入浮层后一拖N完成。传统 CVR 只用"点击→转化"样本，存在 SSB（样本选择偏差）和数据稀疏（转化样本极少）。ESMM 在全样本空间（曝光→点击→转化）建模，pCTR 与 pCTCVR 共享 embedding，用 pCTR×pCTCVR 得到 CTCVR，能从"只曝光没点击"的样本也学到表示。

**Q4. pCTR 和 pCTCVR 的正负样本怎么定义？**
A. pCTR Task：有点击的展现=正，否则负。pCTCVR Task：同时有点击且有转化（一拖N完成）的展现=正，否则负。两塔共享底层 embedding，联合训练。

**Q5. 多任务直接融合为什么点击率掉了4.73%？怎么解决？**
A. 一拖N转化好但封面点击一般的图集被推上来，短期拉低封面点击率。解法是 ESMM 全空间联合训练 + 合理的多目标融合权重，而不是把"点击分"和"一拖N分"简单线性相加；同时用重排控制整体体验。

**Q6. 多目标融合权重怎么定？时长 vs 点击冲突怎么平衡？**
A. 排序分融合 pCTR 与 pCTCVR（及一拖N深度）。权重通过线上 A/B 调参，核心看**消费pv 和人均时长**而非单点击率（项目级消费pv +24.33%、人均时长 +24.28%）。单纯追点击率会损害时长，需用多指标联合评估。

**Q7. 用户兴趣建模怎么处理序列和 UNK？**
A. DIN（Attention）对用户历史行为加权，RNN/AUGRU 建模兴趣演变。UNK（新图集/未登录）用 Mask 层隔离避免污染 attention。实验上最近点击序列最重要（drop -0.0106 AUC），曝光未点击序列也有强负向信号（-0.0053）。

**Q8. 多品类统一推荐怎么避免头部品类吞噬长尾？**
A. 单曝光位服务数十品类，点击率差异可达 2-3 倍。做法：多路召回保障覆盖（召回不足 -5.32%）、热门召回控制比例（加入分类热门召回短期 -0.47% 需限制）、用户分层（低/中/高活）单独建模、负反馈 tag 抑制不感兴趣品类。

**Q9. 简历写 MiNet 多端统一，跨域负迁移怎么处理的？**
A. 诚实澄清：图集资料**没有跨域/多端**概念，"统一"指多品类 + feeds/浮层双目标统一（ESMM）。跨域负迁移（若问 MiNet 原论文）思路是：用门控/专家分化让不同域共享基底但保留域特化，避免强势域梯度压制弱势域——但这是我对跨域能力的概括，图集项目未做跨域实验。

**Q10. 多样性怎么做？为什么打散初期点击率下降？**
A. 发现用户 10% 概率连续3刷同标签。重排层按实时曝光打散，但初期点击率下降——因为精排看到的候选有限且同质，且用户连续点同类本就代表强兴趣。解法：召回层先增加多样性 + 重排引入隐形负反馈动态调打散力度（连续点同类则弱化打散）。最终 3刷同质化 -48.24%。

**Q11. 负样本怎么构造？正负比多少？**
A. 主负样本是曝光未点击；另有隐形负反馈 user/neg-tag-ids。正负样本比例约 1:6.8，需负采样/加权。

**Q12. 模型从 LR 到 DIN+RNN+FM，AUC 提升多少？**
A. LR 0.6798 → DNN 0.6821/0.6921 → DIN+RNN+FM 0.7013。DIN(Attention) vs DNN +0.53% 点击率，RNN vs DNN +1.37%。

**Q13. 召回怎么从单路演进到多路？**
A. 单召回→多路召回后召回不足比例 -5.32%、点击pv +1.55%；深度召回（gallery2vec/YouTube Net/DSSM Net）与画像召回（中期/实时）并行，配合热门/优质池/冷启动/频道/兜底多源。

**Q14. 有效召回率怎么定义和提升？**
A. 以"候选能否被排到曝光"衡量覆盖质量；多路召回解决单路覆盖不足，兜底优化点击pv +4.25%。关注长尾品类在召回层的触达。

**Q15. 如果面试官追问 MMoE 专家退化/负迁移细节？**
A. 直接说明图集项目未用 MMoE，无法提供该项目的专家数/gate 细节；可转述通用知识（专家退化可用负载均衡 loss、增加专家数、正则；负迁移用门控稀疏化），但明确区分"通用知识"与"图集实践"，保持诚实。

**Q16. 重排层具体怎么做多样性打散？**
A. 重排按用户实时曝光记录（本次及前几刷已看标签）做同标签打散；同时引入隐形负反馈（曝光未点击的 tag/品类）动态加大打散力度。关键洞察：用户连续点同类说明兴趣浓，这类情况要弱化打散，否则伤点击率。最终 3刷同质化 -48.24%。

**Q17. 隐形负反馈是什么，为什么比显式负反馈重要？**
A. 隐形负反馈 = 曝光未点击、浮层早退（read_end_rate 低）。它体量远大于显式"不感兴趣"，且能实时反映疲劳。特征上建 `user/neg-tag-ids` + 曝光未点击序列，drop 实验显示去掉曝光未点击序列 AUC -0.0053，信号强。

**Q18. 一拖N转化率（CVR）样本极稀疏怎么解决？**
A. 用 ESMM 全空间建模：CVR 子网络与 CTR 共享 embedding，从"曝光未点击"样本也能学到 item 表示；同时用点击+转化加权（有转化样本加权实验 0.0176 vs 0.0123）缓解稀疏。不直接用"点击→转化"小样本训练 CVR。

**Q19. 排序模型上线后怎么防过拟合？**
A. 特征实验显示强 id 特征去掉反 +1.04%，说明易过拟合；做法：优先行为序列与实时画像，弱人口属性（年龄/城市）保留但降权，图片直方图等弱特征谨慎使用，离线 AUC + 线上分桶多指标联合评估。

**Q20. 双塔召回的 item 塔特征怎么更新？**
A. 图集 item embedding 离线批量更新（图集库每日新增/统计变化），user 塔在线拼实时特征；serving 用 ANN 取 TopK。离线更新频率与图集库中 num-pics/click-num/total-time 等统计同步。

**Q21. 图集质量分（威尔逊）在链路哪用？**
A. `read_wilson_score` 用于一拖N质量排序与召回/重排的图集优选，避免小曝光高点击率图集虚高；配合 read_to_next_rate / read_end_rate 共同刻画真实消费质量。

**Q22. 整个项目你最大的技术决策是什么？**
A. 把图集从"追单点点击率"重构为"点击率×一拖N转化率"的全空间多任务（ESMM），并搭好多路召回+多样性重排闭环。代价是初期多目标直接融合点击率 -4.73%，通过联合训练与动态打散化解，最终点击率+24.14%、消费pv+24.33%、人均时长+24.28%。

**Q23. 如果你现在重做，会改什么？**
A. 会在多任务里更早引入 gate/专家分化（即简历所说的 MMoE 思路）缓解点击与一拖N目标拉扯；召回侧加强长尾品类保障（跨品类负反馈更细）；并把跨端（如手Q/看点独立版）统一建模（即 MiNet 思路）——但需说明这些是后续演进，图集第一手资料未落地。

## 11. 候选人答辩话术建议（开口前 30 秒对齐口径）

> 面试官大概率照简历问。建议开场主动一句话对齐：
> "图集这个项目的召回是双塔 DSSM 类（gallery2vec/YouTube Net/DSSM Net），排序是 ESMM 多任务（feeds 点击率 × 一拖N 转化率）。简历上写的 MMoE 和 MiNet 是我后面更通用的多任务/跨域概括，图集资料里落地的是 ESMM 共享塔 + 多路召回，我先把图集真实结构讲清楚。"

### 11.1 三层递进讲法
1. **业务层**：单曝光位 + 浮层一拖N，目标从单点击率升级为 点击率×转化率×时长。
2. **模型层**：多路召回（双塔）→ 粗排 → 精排（DIN+Mask+RNN + ESMM 多任务）→ 重排（多样性打散+隐形负反馈）。
3. **结果层**：点击率+24.14%、消费pv+24.33%、人均时长+24.28%，3刷同质化-48.24%。

### 11.2 被追问"为什么不用 MMoE"的标准答
- ESMM 已用共享 embedding + 全空间建模解决多目标与稀疏；图集阶段点击与一拖N两个目标，共享塔够用。
- MMoE 的 gate/专家分化适合目标更多、且目标间冲突更强的场景；图集后续若要加"分享/时长/关注"等多目标，才是 MMoE 的用武之地。

## 12. 追加深挖题（备用，防冷场）

**D1. 双塔召回 user 塔和 item 塔特征分别有什么？**
- user 塔：人口属性、长期画像（品类weight）、实时画像 tag、近期点击序列、负反馈 tag。
- item 塔：图集属性（puin/ch1/ch2/tags）、历史统计（num-pics/click-num/exp-num/total-time/valid-click-rate）、一拖N质量（read_to_next_rate/read_end_rate/read_wilson_score）、二模态向量。

**D2. 一拖N转化和点击的样本空间关系？**
- 一拖N转化 ⊂ 点击（只有点了才有一拖N）。ESMM 用全空间：CTR 在全部曝光上训，CTCVR 在全部曝光上训（正样本=点且转化），CVR 子网络靠共享 embedding 间接学。

**D3. 正负样本 1:6.8 怎么处理？**
- 负样本主导（曝光未点击），需负采样或加权，避免模型偏向预测负；同时保证一拖N转化正样本不被淹没（有转化样本加权实验 0.0176）。

**D4. 长尾品类怎么保曝光？**
- 多路召回（热门限制比例）、用户分层单独建模、负反馈 tag 仅抑制确不感兴趣品类、重排打散给长尾窗口。

**D5. 如果让你加一路新召回，怎么评估？**
- 离线：AUC/召回覆盖/品类分布；线上：分桶看点击率、消费pv、人均时长、长尾占比，避免只提点击率伤时长。

**D6. 多样性打散力度怎么量化调？**
- 以"连续 N 刷同标签概率"为指标（基线10%），结合隐形负反馈强度动态调节；用户强兴趣类弱化打散。

**D7. 图集和主 feeds 共用模型还是独立？**
- 图集独立召回+排序链路（单曝光位特殊消费形态）；排序多任务把 feeds 点击率与一拖N 转化率统一到 ESMM，但特征/样本独立。
