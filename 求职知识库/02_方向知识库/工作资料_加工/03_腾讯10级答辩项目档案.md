## 3. 核心项目讲述（按答辩顺序）

> 以下"我的贡献"均以童力第一人称视角整理，保留原文可口述表达。所有数字见第 4、8 节。

### 3.1 项目 A：看点图集推荐（2018.10–2019.12，主 feeds）

- **背景**：图集是 QQ 看点信息流中基于图片的短内容消费场景；业务目标为提升消费总 pv。曝光 pv 约 5–6 亿/天，消费 pv 约 2.x–3 亿/天（⚠️ 两版规模描述冲突，见第 8 节）。
- **问题**：① 召回侧兴趣刻画不足、冷启动/热门偏置；② 排序侧用户兴趣序列截断丢信息、兴趣演变未建模；③ 一拖 N 浮层存在"点击→转化"级联目标与"完成+下滑"非级联多目标；④ 样本存在类型/位置偏差与异常值主导 loss。
- **方案**：
  - 召回：多路召回（画像/语义/模型召回），模型召回用图集向量预训练 + 行为少用户序列增强 + 热度降采样；引入 deepwalk、YouTube DNN、DSSM。
  - 排序：Wide&Deep/DeepFM/DIN/DCN 做加法；**DIN+Attention 对用户兴趣建模**（动态补全 + Mask 解决变长序列）；**RNN/ Self-Attention 建模兴趣演变**；**ESMM 对点击→转化级联建模**；**MMoE 对一拖 N 完成+下滑非级联多目标**；双稳态(Bi-Tempered)+Focal loss 解决样本偏差。
  - 重排：多样性打散（画像召回多样性 + 隐形负反馈降权）。
- **我的贡献**："我主导并搭建了图集主 feeds 推荐系统，覆盖召回、粗排、精排、重排等重要模块，具有全局掌控能力"（原文总结）；提出 Mask 层解决变长序列兴趣丢失、提出 RNN 各状态加权输出、提出 ESMM 三版迭代、提出 MMoE-Share 增加专家共享、提出双稳态+Focal loss 组合损失。
- **结果**：
  - ⚠️ **04 月版口径（整体项目相对提升）**：点击率 +24.14%（→约 11.x%）、人均时长 +24.28%（→约 3min）、消费 pv +24.33%（→约 3 亿）；总结"核心指标相对提升 20+%"。
  - **08 月版口径（子实验拆分）**：ESMM 上线图集 pv +2.7%；点击+时长 ESMM 图集总时长 +8%、人均时长 +10%。
- **亮点（可口述）**："整体优化工作使得核心指标相对提升 20+%，助力项目取得突破性发展"；"用户兴趣深度建模中借鉴 DIN 增加 Attention 层，一开始不及预期，分析发现是序列截断丢兴趣，于是用动态补全+Mask 解决——多看 case、从实际问题出发，永远是王道。"

### 3.2 项目 B：看点搜索排序混排（早期，08 版降级为技术沉淀）

- **背景**：看点搜索结果含多种业务（实体区：音乐/视频；内容区：看点文章/部落帖子等），需跨业务混排。
- **问题**：过度依赖点击率预估排序，带来**时效性**（新文章反馈少被排后）与**相关性**（长尾 query 召回不足、高 ctr 非相关结果排前）问题。
- **方案**：机器学习混排多业务预估排序（用户/Query/业务特征 → 构造样本 → 训练 → 在线预估）；对比三种方案：① 多模型；② 单模型多任务多目标；③ 目标融合构建新 label（点击+相关性高+时效性高→label=4，逐级递减）。
- **我的贡献**：设计跨业务排序特征与样本构造；用目标融合 label 在不引入额外 badcase 前提下优化时效性与相关性。
- **结果（两版一致）**：第一搜结果点击率对比普通混排 **+9.2%**；评估选取 60 top 搜索词+60 业务词+60 明星影视词，gsb=**52:113:0**，有提升 query 比例 **31.51%**，ndcg **+3.12%**（⚠️ 同版另有"ndcg 提升 3%"约数，见第 8 节）。
- **亮点（可口述）**："评估选了 180 个 query，实现在不引入额外 badcase 前提下优化时效性和相关性。"

### 3.3 项目 C：看点短内容浮层推荐（2020.1–至今，08 版主项目）

- **背景**：探索 QQ 看点信息流中短内容消费场景（类似微博形态）。曝光 pv 约 2 亿/天、消费 pv 约 2.3 亿/天；业务目标为提升业务总时长、大盘时长。
- **问题**：① 多目标未对齐——精排已多目标，召回仍为单目标，Gap 造成精排层候选集不足；② 多目标选择难——只看消费目标满意度不足，单 pv 时长建模易推长图体验差、点赞稀疏、pv 下降；③ 样本偏差（类型/位置）。
- **方案**：
  - **多目标对齐**：精排多目标 → 召回也多目标（多目标模型召回）。
  - **多目标选择**：用斯皮尔曼/皮尔逊相关系数衡量目标间相关性，选"有一定相关性但不冗余"的目标（停留时长+进评论）。
  - **多目标召回**：多目标向量 concat 后建一份索引、一次请求，直接召回综合最优（解决有效召回率低）。
  - **时长建模**：相对分位判定 + 时长分段作为正样本权重（多分类实验中）。
  - **消偏**：相对分位时长判定替代统一阈值。
- **我的贡献**："我尝试了多目标模型召回，对比了与多路单目标召回的差异，实践探索向量拼接这种简而美的方案直接召回综合最优，提升有效召回率"；"做加法也要做减法——迭代到后面一味加目标边际收益很少，我认为需要用科学方法指导目标实验。"
- **结果**（见第 4 节完整表）：短内容浮层多目标精排（2020-04-30）大盘累积使用时长 +0.42%、广义 DAU +0.10%、短内容互动行为 +35%、浮层时长 +6.8%、短内容总时长 +2.85%；多目标模型召回单 pv 时长 +9.21%（⚠️ 另有 +8% 口径）、短内容总时长 +3.85%（⚠️ 另有 +4% 口径）。
- **亮点（可口述）**："多目标召回通过向量拼接，一份索引一次请求直接召回综合最优——这是简而美的方案"；"目标选择三原则：1 不能太稀疏、2 不要太冗余、3 要具有一定相关性。"

### 3.4 召回方法体系与特征体系（项目支撑细节）

#### 3.4.1 多路召回框架
**多路召回的四个出发点（原文）**：① 用户兴趣的多元化；② 增强系统的鲁棒性；③ 召回目标的多元化；④ 产品运营特殊要求。
**画像召回 vs 模型召回对比**：

| 召回类型 | 优点 | 缺点 |
|---|---|---|
| 画像召回 | 可解释性好、可复用性好 | 基于字面匹配、缺乏泛化性、依赖标签准确性、缺乏容错性 |
| 模型召回 | 特征可更丰富、模型可更复杂 | 缺泛化性、缺容错性、特征单一、模型简单 |
| 语义召回 | 内容/行为语义向量化 | — |
| 深度树匹配（TDM） | 用户兴趣层次化、内积→任意模型、全量候选集 | Doing（进行中） |

**业界借鉴（原文列举）**：百度 DSSM+FM（加 FM 做特征组合减信息损失）；阿里 MIND（加 Multi-Interest 抽取层对用户多种兴趣建模）。

#### 3.4.2 序列特征与交叉特征设计（08 提交版 Slide 30，原文）
- **序列特征**：用户最近点击/评论/分享/点赞 itemid 序列（以时间间隔按**艾宾浩斯遗忘曲线衰减**作为权重）；由 itemid 序列得到分类/标签序列（以统计占比作为权重）。
- **交叉特征**：分年龄/性别的点击数/率、评论数/率、分享数/率、点赞数/率；正向点赞 = 点赞 − 点踩 的数/率。
- **用户细分统计**：用户对内容类型的曝光/点击/评论/分享 次数/率；对不同分类的同上。
- **基本特征**：用户基础属性、兴趣画像、物品基础属性、标签画像、曝光/点击分时间段统计。
- **其他**：召回理由作为特征传入排序层。

#### 3.4.3 图集特征体系（08 提交版 Slide 52，原文）
- **图集侧**：图片数、发布时间、图片清晰度、美观度、低质类型（色情暴力等）。
- **用户侧**：年龄/性别/城市/省份；画像（分类、标签，分主 feeds & 一拖 N 场景）的点击数/点击率；行为（主 feeds 实时点击序列、实时曝光未点击序列、一拖 N 实时浏览完成序列）。
- **场景**：小时、早/中/晚、工作日/周末、系统、网络。
- **预训练**：Bert 标题向量、CNN 图片向量。
- **规模**：特征规模千万级、模型参数亿级、模型大小 G 级；交叉特征含统计/活跃/向量交叉。

#### 3.4.4 特征交叉创新：Kernel 矩阵替代 Attention-Net（08 提交版 Slide 29，原文）
**问题**：不同 embedding size 的特征无法直接相乘做交叉，一般引入 Attention-Net 算交叉权重。
**我的方案**：引入 kernel 矩阵解决 embedding size 不同的特征交叉。

| 方法 | 参数量 | 训练速度(每小时数据) | AUC |
|---|---|---|---|
| Attention Net（32*16） | 3072 | 23 min | 0.74564 |
| Kernel 矩阵（64*16=1024） | 1024 | 19 min | 0.74562 |

> 参数量减少约 3 倍、训练更快，AUC 基本持平——更简洁有效的交叉方式。

### 3.6 重排与多样性（图集，04 版 Slide 24–25，原文）

**背景**：图集只占一个曝光位，用户多刷间可能看到同质化内容（数据显示 10% 概率连续 3 刷同标签）。
**做法**：
- 召回层：每次召回取用户 top5 标签（改进前取 top50 按概率随机选部分），覆盖尾部标签更分散。
- 重排层：引入**隐形负反馈**（曝光未点击）控制打散力度。例：模型预估 pctr 0.25、最近 7 次曝光 5 次未点、α=0.8 → 降权后 ctr 0.05。
- 弱化处理：用户连续点同一类说明兴趣浓，打散力度要弱化。
**效果**：3 刷标签同质化概率 **10% → 5%**，用户体验提升明显。

## 5. 技术亮点深挖

### 5.1 ESMM 迭代过程
**问题**：图集消费 = 主 feeds 点击 pv + 浮层一拖 N 转化 pv（点击→转化级联）。如何让模型同时学点击与转化？
**四版迭代（08 提交版 Slide 50–51，原文）**：
1. **第一版·优化样本构造**：正样本由"点击"改为"点击+转化"，倾向推高转化图集（⚠️ 同版 Slide 50 方案4 记多任务建模消费 pv +1.76%，Slide 51 第三版记 +1.35%，口径见第 8 节）。
2. **第二版·优化损失函数**：权重作用于样本 loss，转化 pv 高的点击样本更敏感 → 消费 pv **+1.23%**。
3. **第三版·优化模型结构**：点击+转化多任务建模 → 消费 pv **+1.35%**。
4. **组合增强**：引入 Bi-Tempered Logistic Loss（2019 Google，降噪鲁棒）+ Focal loss（难分样本）。
**演进**：业务目标从"点击+转化"变更为"点击+时长"，技术方案仍适用（图集总时长 +8%、人均时长 +10%）。
**可口述**："一般方案是样本清洗+负采样，我换了思路——用 ESMM 把级联目标变成多任务，再用双稳态+Focal loss 解决异常样本与不均衡。"

### 5.2 MMoE 专家退化（Expert Degradation）
**现象（原文诊断过程，08 版多处，15967/18515/21553/24547）**：做多目标（如"完成+下滑"两目标）时，**打印 Gate 参数，发现参数值极度集中（如 0.998，0.001，0.001）**——即**两个目标只激活了一个专家**。原本设想 Expert0/1/2 经 Gate 加权组合，实际 Gate 把权重压到单一专家上，其余专家形同虚设，导致"专家间差异性不足、模型拟合效果不充分"（专家退化）。
**解法**：增加专家间差异性——引入 DNN / LR / FM / CIN 等不同结构专家；实践中 **DNN+FM+CIN 最优**。
**实验佐证（08 实验数据）**：expert_num 2→8，task_auc_3 由 0.8463 升到 0.8627；DNN+FM+Fast_CIN 的 task_auc_3 达 0.8789（baseline 0.869）。
**方法论文**："针对 MMoE 中专家间无共享的情况，增加专家间共享模块，使得模型学习更加充分"（04 版方法论总结第 4 条）。
**⚠️ 与普通"表示趋同"的区别**：这不是笼统的"表示趋同"，而是**实测 Gate 权重塌缩到单专家**——这是定位问题的关键抓手，二面白板可画 Gate 权重直方图（0.998/0.001/0.001）说明。
**可口述**："MMoE 不是加专家就完事。我打印 Gate 参数发现，两个目标实际只激活了一个专家——权重都压到 0.998 那个，其他专家形同虚设。我让专家结构异构（DNN+FM+CIN），并加共享底层，既保差异又保共享。"

### 5.3 多目标召回的有效召回率
**核心问题**：精排是多目标排序，召回却是单目标，两者 Gap 导致精排拿不到好候选集。
**方案对比**：
- 方案2：多路单目标召回 + 多目标粗排
- 方案3：多目标模型召回（但多份向量/多份索引/多次请求，有效召回率低）
**有效召回率定义**：符合线上综合目标的召回数 / 召回数。
**关键数据**（第 4.5 节）：经典举例——目标 1、目标 2 各召回 top1000，共 2000 个物品中综合最优仅 600 个，**有效召回率仅 30%（600/2000）**；离线实验召回数 100→400，有效召回率 0.62→0.385，耗时 8→28ms；与多目标模型召回的差距随召回数增大而缩小（0.08→0.022），但耗时上升、**性价比不高**。
**我的做法**：将多个目标向量 concat 作为最终向量表示，目标间权重作用到相应目标向量，对 concat 向量建**一份索引、一次请求**，打分天然为综合打分，直接召回综合最优。
**可口述**："多路单目标召回靠堆量弥补 Gap，但有效召回率随量下降、耗时上升；我用一个 concat 向量一份索引一次请求，直接召回综合最优——简而美。"

### 5.4 多目标选型：皮尔逊 / 斯皮尔曼相关系数
**背景**：浮层目标众多（停留时长/评论/点赞/分享/下滑/不退出）。一开始以单 pv 停留时长建模 → pv 下降、总时长差；以进评论建模 → 单 pv 时长升但 pv 降；以点赞建模 → 稀疏、总时长降。
**科学选型方法**：
- 用**斯皮尔曼相关系数**（= 经过排行的两个变量的**皮尔逊相关系数**）衡量目标间相关性（08 提交版 Slide 19/58 原文给出皮尔逊定义及"斯皮尔曼=排行的皮尔逊"）。
- 相关性分析结论：**下滑和不退出相关性高（冗余）；停留时长和进评论有一定相关性（可协同）**。
- **目标选择三原则**（08 提交版 Slide 42，原文）：① 目标不能太稀疏；② 目标间不要太冗余；③ 目标间具有一定相关性。
**落地**：选"停留时长 + 进评论"建模 → 短内容总时长 +2.85%、大盘累积使用时长 +0.42%。
**可口述**："加目标做多了要做减法。我用斯皮尔曼（本质排行的皮尔逊）算目标相关性，选有相关性但不冗余的目标——这样既协同又不浪费资源。"

### 5.5 其他深挖点（备答）
- **变长序列兴趣建模**：动态补全（batch 内最大长度）+ Mask 层屏蔽 UNK，解决截断丢兴趣（体育类兴趣丢失）与补全引入噪声。
- **兴趣演变建模**：RNN 各状态加权输出（Attention 学权重）→ Self-Attention+position embedding 替代以降低耗时。
- **时长消偏**：相对分位判定（与过去 k 小时 x 分位比）替代统一阈值，样本判定更合理、生态更健康。
- **时长建模方式**：回归→取 log 回归→统一阈值二分类→统计分位二分类→分位+分段权重多分类（实验中）。结论：分类优于回归（回归受极值影响）。
- **特征交叉**：kernel 矩阵替代 Attention-Net 处理不同 embedding size 特征交叉（参数量 3072→1024，训练 23min→19min，AUC 基本持平 0.74564→0.74562）。

### 5.6 时长建模方式演化路径（详细，08 提交版 Slide 37，原文）

| 建模方式 | 单pv时长 | 总时长 | 说明 |
|---|---|---|---|
| 回归（直接回归阅读时长） | 下降 | 下降 | 受极值影响，不如分类好学的 |
| 取 log 后回归 | 下降减小 | 下降减小 | log 减小极值影响，仍不佳 |
| 统一阈值二分类 | 提升 | 持平 | 建模有效，但统一阈值不合理 |
| 统计分位阈值二分类 | 提升 | 提升 | 效果提升，但时长信息利用不全 |
| 分位 + 分段权重（正样本权重） | 提升增大 | 提升增大 | **实验最优** |
| 分段多分类 | — | — | 实验中 |

**时长消偏（08 提交版 Slide 34，原文）**：样本存在类型/位置偏差。相对分位判定——如本次停留 25s，若过去 k 小时第 1 位置平均 28s（>25s）判负，第 4 位置平均 18s（<25s）判正；段子过去平均 26s 判负，短文本平均 23s 判正。统一阈值（12s）则一刀切。相对分位更合理、生态更健康。

### 5.7 MMoE 结构示意与多目标召回结构（原文结构描述）
- **MMoE（一拖 N）**：Expert0/1/2 + Gate A/B → Tower A/B（Output A/B），专家间既有共享又有自身部分。
- **多目标召回双塔**：item feature → Item tower1/2（L2 Norm → item vec1/2）；user feature → User tower1/2（L2 Norm → user vec1/2）；user vec·item vec → pred1/pred2。多目标即多份 user/item 向量。
- **MMoE 多目标召回**：Expert0/1/2 + Gate A/B → user tower1/2；同样产出多份向量，再 concat 建一份索引。

## 6. 答辩常见追问与应答（基于材料推导）

> 标注：【原文】= 材料明确有；【推导】= 由材料逻辑推演，需候选人自行核实口径。

1. **Q：图集 +24% 和多目标 +2.7% 是什么关系？**【原文+推导】
   A：+24% 是 04 版"整体项目相对起始/现网"的累计口径；+2.7% 是 08 版 ESMM 单实验口径，两者不等价、不可相加。建议二面统一用"子实验可归因"口径，避免被追整体大数的归因。

2. **Q：MMoE 专家为什么会退化？你如何验证？**【原文】
   A：不是凭感觉，是**打印 Gate 参数实测发现**——两目标权重塌缩到单一专家（如 0.998/0.001/0.001），即"两个目标只激活了一个专家"。验证用离线 task_auc 随 expert_num 提升（0.8463→0.8627），并对比 DNN+FM+CIN 异构专家最优；线上以消费 pv 提升 +2.85% 佐证。

3. **Q：多目标召回为什么不用多份向量多份索引？**【原文】
   A：多份向量各自 TopK，交集才是有效召回，有效召回率低（数据 0.62→0.385）；concat 一份向量一次请求直接综合打分，性价比更高。

4. **Q：目标怎么选？凭感觉还是方法？**【原文】
   A：用斯皮尔曼（排行的皮尔逊）算相关性，遵循三原则（不稀疏/不冗余/有相关性），选停留时长+进评论。

5. **Q：ESMM 和 MMoE 分别解决什么？**【原文】
   A：ESMM 解决"点击→转化"级联目标（主 feeds）；MMoE 解决"完成+下滑"非级联、目标互相干扰（一拖 N 浮层）。

6. **Q：损失函数为什么用双稳态+Focal？**【原文】
   A：异常样本/噪声主导 loss、正负例失衡；双稳态（Google 2019）降噪鲁棒，Focal 聚焦难分样本。

7. **Q：你的成果被中台/其他部门复用过吗？**【原文】
   A：有。开源推荐系统方案被腾讯网、波动星球、全民 K 歌、微信支付等咨询借鉴；品类推荐 pipeline 内部复用；MMoE 成为 BG 首个无量 3.0 全量多目标业务。

8. **Q：半年规划你怎么做？**【原文+推导】
   A：材料提及规划 AutoML 快速搜参替代 rand search、用强化学习建模长期收益（关注等稀疏目标）。可补充：全链路多目标（召回+排序）一体化是后续方向。

9. **Q：搜索混排 ndcg 3.12% 显著性如何？**【推导】
   A：评估基于 180 个 query（60+60+60），gsb 52:113:0，有提升比例 31.51%；属人工评估+灰度，需说明评估口径与置信度。

10. **Q：序列建模为什么从 RNN 换 Self-Attention？**【原文】
    A：RNN 各状态加权输出有信息损失且预测耗时增加，Self-Attention+position embedding 在保留演变信息同时降复杂度。

11. **Q：多目标融合参数怎么搜？**【原文】
    A：当前是 rand search 搜参，规划尝试 AutoML 快速搜参（08 提交版 Slide 20）。

12. **Q：整体项目 +24% 的 baseline 是什么？**⚠️【推导-需核实】
    A：材料未明确 +24% 的精确 baseline 与时间窗（疑似 vs 项目起始/现网）。**此数字与简历若有出入以简历为准**，二面建议准备"相对哪个基线、统计周期多长"的说明。

13. **Q：时长消偏的相对分位判定会不会引入新的偏差？**【推导】
    A：相对分位仍依赖"过去 k 小时同位置/同类型"的统计分布，若某类内容样本极少，分位估计不稳定。材料未给该边界处理，二面可答"分位窗口与分层维度是超参，需按内容类型样本量调整"，并强调统一阈值更不合理。

14. **Q：多目标召回 concat 后不用 sigmoid 的原因？**【原文】
    A：材料明确指出"若 Score 使用 sigmoid 会有问题，注意不用 sigmoid"，因为多目标向量 concat 后直接做内积打分，sigmoid 会破坏"综合打分天然为综合最优"的性质，使各目标间权重被压缩失真。

15. **Q：图神经网络预研有没有落地？**【原文】
    A：属技术沉淀/其他工作，未作为主项目上线。作为 T10 业界调研与广度举证；主线落地仍以多目标建模为主。不要夸大其上线收益。

## 7. 面试 Q&A（第一人称口述，≥12 组）

1. **Q：请先自我介绍与核心项目。**
   A：我是童力，西交大本硕，百度 2 年、腾讯看点 2 年。我主导了腾讯看点图集主 feeds 推荐系统（召回/粗排/精排/重排全模块），2020 年起负责短内容浮层推荐，核心是用 ESMM、MMoE 和多目标召回做多目标建模，相关成果成为 BG 首个无量 3.0 全量多目标上线业务。

2. **Q：你最得意的一个技术点是什么？**
   A：多目标召回的向量拼接方案。精排多目标、召回单目标存在 Gap，多路单目标靠堆量补，但有效召回率随量下降到 0.385、耗时翻倍。我把多目标向量 concat 成一份向量、建一份索引、一次请求，打分天然综合，直接召回综合最优——简而美。

3. **Q：MMoE 专家退化你怎么发现和解决的？**
   A：我发现专家无共享时表示趋同、拟合不充分。做法是让专家结构异构（DNN+FM+CIN）并加共享底层，离线 task_auc_3 从 0.8463 升到 0.8627，DNN+FM+Fast_CIN 到 0.8789；线上消费 pv +2.85%。

4. **Q：多目标怎么选目标？**
   A：不能凭感觉。我用斯皮尔曼相关系数（本质就是排过序的皮尔逊）量化目标相关性，发现下滑和不退出高度冗余、停留时长和进评论有协同。遵循三原则——不稀疏、不冗余、有相关性——最终选停留时长+进评论。

5. **Q：ESMM 在你业务里怎么用的？**
   A：图集消费是"点击→转化"级联。我先优化样本构造（点击+转化当正样本），再优化损失函数让转化高的样本更敏感，最后上多任务模型结构；业务目标从点击+转化变到点击+时长，方案依然适用，图集总时长 +8%、人均时长 +10%。

6. **Q：样本偏差你怎么处理？**
   A：两方面——一是损失函数用双稳态+Focal loss 抗异常值和正负不均衡；二是时长建模用相对分位判定替代统一阈值，按过去 k 小时同位置/同类型分位判定正负，样本更合理、生态更健康，浮层停留时长 +1.5%。

7. **Q：用户兴趣序列你怎么建模？**
   A：DIN+Attention 学行为序列权重，但固定维度要截断会丢兴趣（比如丢体育类），我用动态补全+Mask 层屏蔽补全的 UNK，消费 pv +2.59%；兴趣演变用 RNN 各状态加权，后因耗时改 Self-Attention+position embedding。

8. **Q：你的成果有外部影响吗？**
   A：有。推荐系统方案开源后，腾讯网、波动星球、全民 K 歌、微信支付等同事都来借鉴；品类推荐 pipeline 内部复用；MMoE 多目标成为 BG 首个无量 3.0 全量上线，团队拿到 Q1 技术攻坚奖。

9. **Q：搜索排序混排你做了什么？**
   A：看点搜索过度依赖 ctr 导致时效性和相关性差。我做了跨业务机器学习混排，用目标融合 label（点击+相关性+时效性）优化，第一搜点击率 +9.2%，ndcg +3.12%，gsb 52:113:0。

10. **Q：多目标融合参数怎么定？**
    A：目前是 rand search 搜参，效率低。我规划用 AutoML 快速搜参；另外对特别稀疏但长期有价值的目标（如关注）计划用强化学习建模。

11. **Q：从 9 级到 10 级你能力上最大的变化？**
    A：9 级给子系统季度规划，10 级要能给半年规划、成果被中台复用、效果和公司内同类比属 top 级。我这一年补齐了"全链路多目标"（召回+排序）和完整举证链，从单点优化走向体系化。

12. **Q：如果让你重做图集项目，哪里会改？**
    A：一是整体大数拆成可归因子实验，避免归因受质疑；二是早一点做多目标召回对齐，而不是先单目标召回再补粗排；三是目标选择早用相关性量化方法，少走"加目标试错"的弯路。

13. **Q：你怎么看推荐系统的"加模型"趋势？**
    A：我不赞同直接搬论文当调库侠。我倾向借鉴论文有用思路给已有模型做加法，从实际问题出发——多看 case、看作者没写出来的，效果不好先想是不是没用到极致。

14. **Q：长尾/冷启动你怎么处理？**
    A：召回侧对行为少的图集做向量预训练固化参数、对行为少用户扩充点击序列、负样本热度降采样降趋热性；并引入 deepwalk 增强训练数据、YouTube DNN/DSSM 提升泛化。
15. **Q：损失函数你为什么不用普通交叉熵？**
    A：推荐样本里有大量异常值（极端时长、刷量）和正负例严重失衡，普通交叉熵会被这些噪声主导。我用双稳态(Bi-Tempered) Logistic Loss（Google 2019，两个温度参数 t1/t2 降噪、鲁棒）配合 Focal Loss（聚焦难分样本），在 ESMM 上组合增强，抗噪又抗不均衡。

16. **Q：你做过什么特征交叉的创新？**
    A：不同 embedding size 的特征不能直接相乘做交叉，常规做法是引 Attention-Net 学交叉权重。我改用 kernel 矩阵把不同 size 的特征投影到统一空间做交叉——参数量从 3072 降到 1024、训练 23min 降到 19min，AUC 基本持平（0.74564→0.74562）。更简洁也更省资源。

17. **Q：重排/多样性你是怎么做的？**
    A：图集只占一个曝光位，数据发现用户有 10% 概率连续 3 刷看到同标签内容。我在召回层每次只取用户 top5 标签（原来 top50 随机取）让覆盖更分散；重排层引入隐形负反馈（曝光未点击）控制打散力度——比如预估 ctr 0.25、最近 7 次 5 次未点、α=0.8，降权后 ctr 0.05。最终 3 刷同质化概率 10%→5%。

18. **Q：你跟不跟前沿？除了多目标还做过什么？**
    A：我系统调研过图神经网络（GNN）在工业界推荐的应用，作为技术储备，对应《图神经网络在工业界/推荐中的应用》两篇调研。主线还是多目标建模落地，但技术广度上我持续跟业界（DeepFM/DCN/xDeepFM/MIND/DSSM 等）并在组内做分享。

15. **Q：为什么用 DSSM / YouTube DNN 而不是纯 item2vec？**
    A：item2vec 只用到 ID 行为语义、内容侧无属性、泛化差、新内容难召回；YouTube DNN 加入用户特征，行为少的用户能靠画像泛化；DSSM 内容侧加属性特征，新内容也能召回。我是按"行为少用户/新内容"两类泛化短板来选模型的。

16. **Q：特征交叉你有什么创新？**
    A：不同 embedding size 的特征不能直接相乘，常规做法上 Attention-Net 算交叉权重。我引入 kernel 矩阵，参数量从 3072 降到 1024、训练从 23min 降到 19min，AUC 基本持平（0.74564→0.74562）——更简洁。

17. **Q：多目标融合参数现在怎么搜？效率如何？**
    A：目前是 rand search 搜参，能搜但慢、资源耗费大。我规划用 AutoML 快速搜参，这也是答辩里明确列的后续规划。

18. **Q：你怎么保证线上系统有效性，避免一味加目标？**
    A：我做加法也做减法。迭代到后面一味加目标边际收益很少、资源却增多，我用斯皮尔曼相关性做科学的目标选择，剔除冗余目标；同时维护线上系统，对极稀疏但长期有价值的目标（如关注）计划用强化学习建模。

19. **Q：你的工程落地能力体现在哪？**
    A：线上服务用织云部署、L5 统一路由及负载均衡；排序模型服务有耗时监控，我通过优化模型特征/结构减少模型耗时；浮层排序模型服务是网络工程举证的一部分。不是只做算法，端到端能上线。

20. **Q：如果面试官问"你的工作别人也能做，你的独特性在哪"？**
    A：独特性在三点——一是体系化：从召回单目标到多目标对齐到多目标召回，全链路打通而非单点；二是方法论沉淀：目标选择三原则、Mask 解决变长序列、concat 多目标召回，这些是可复用的抽象；三是落地影响：BG 首个无量 3.0 全量多目标业务、开源被多团队借鉴。

21. **Q：召回侧你做了哪些负样本优化？**
    A：召回面临的环境比排序复杂——排序是"优中选优"，召回是"良莠不齐中选潜在优质"。我做了两点：一是对点击序列少的用户做序列扩充、引入相似图集增强向量学习；二是负样本按热度降采样，缓解热门偏置、提升召回相关性，而不是简单随机负采样。

22. **Q：你如何衡量一次模型迭代到底有没有用？**
    A：我不只看离线 AUC。会做"目标→特征→模型"的归因拆分：先定业务目标，再据此建特征体系、选模型结构（ESMM/MMoE），每个子实验单独报数（如 DIN+Mask 消费 pv +2.59%、RNN +1.34%、MMoE +2.85%），这样线上收益可解释、可回溯。

23. **Q：你现在看推荐系统的技术趋势是什么？**
    A：我关注两条——一是全链路多目标（召回、粗排、精排对齐同一组目标，消除短板效应）；二是自动化，比如用 AutoML 替代人工 rand search 搜参、用强化学习建模关注这类长期稀疏收益。这也正是我答辩里列的后续规划。

24. **Q：如果二面让你现场设计一个多目标召回方案，你怎么做？**
    A：四步——① 明确精排目标集合，定义有效召回率（符合综合目标的召回/总召回）；② 召回模型也建成多目标双塔，产出多份 user/item 向量；③ 不建多份索引多次请求，而是把多目标向量按目标权重 concat 成一份向量、建一份索引、一次请求，打分天然综合；④ 上线后看单 pv 时长、总时长是否提升，并监控有效召回率与耗时，避免堆量损性价比。
