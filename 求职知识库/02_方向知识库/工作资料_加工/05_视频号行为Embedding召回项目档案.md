## 2. 召回方案：为什么选 Graph Embedding

### 2.1 多路召回背景

召回阶段一般用多路召回并行：标签召回、协同过滤召回、LBS 召回、热门召回、**embedding 召回**等。基于 embedding 召回已成为业界主流，分两类：
- **端到端方法**：YoutubeDNN、DSSM（谷歌、微软）——user/item 塔分别编码后内积
- **Graph Embedding**：把 user-item 交互历史构造成二部图，随机游走得序列，word2vec 训练得 embedding，再用 Faiss / hnsw 近邻搜索召回（淘宝、知乎等）

**本项目属于后者**——基于 Graph Embedding 的召回。

### 2.2 经典 Graph Embedding 的缺陷（项目出发点）

经典方法：user-item 二部图 → 随机游走 → word2vec → user/item embedding。

缺陷：**交互次数很少或没被交互过的 item，难以训出高质量 embedding**——典型的冷启动 / 长尾问题。

本项目的解法见 §3。

## 3. 核心方案：异构行为网络（重点，面试深挖区）

### 3.1 异构网络构造（4 类边）

不是在 user-item 二部图上游走，而是利用视频号上的多种行为，构造**异构网络**：

| 边类型 | 含义 | 权重/说明 |
|---|---|---|
| **user-feed 正向行为边** | 点赞 / 关注 / 完播且曝光时长>5s / 曝光时长>30s 四种行为 | 边权 **2 : 2 : 2 : 1** |
| **user-finder 关注边** | 用户关注号主 | — |
| **finder-feed 发表边** | 号主发表 feed | — |
| **feed-tag 边** | feed 被打上的 tag | — |

### 3.2 五种 metapath 随机游走

通过 5 种 metapath 生成训练语料：

1. `user-feed`
2. `user-finder`
3. `finder-feed`
4. `user-feed-finder-feed`
5. `feed-tag`

最终 word2vec 训练出 **user、finder、feed 三类节点的 embedding**。

### 3.3 为什么这样设计（难点 1 的解法）

> **难点 1**：视频号项目初期只对少部分微信用户灰度，**行为数据极其稀疏**，冷启动严重，稀疏 feed 的 embedding 学不充分。

解法：**靠 metapath 做数据增强**。在 user-feed 之外，增加 user-finder、finder-feed、user-feed-finder-feed、feed-tag 四种路径，把交互稀少的 feed 通过 `feed-finder-user`、`feed-finder-feed`、`feed-tag-feed` 三种连边与 user 及其他 feed 连接起来，生成更丰富的游走序列。

> 原文结论：「加入这一策略后 embedding 近邻质量可获得肉眼可见的提升」。

### 3.4 哈利波特热点问题（难点 2 的解法，面试加分点）

> **难点 2**：推荐系统常出「哈利波特热点问题」——热门 item 因连边极多，频繁作为正样本被优化，导致其 embedding 模（norm）偏大，cosine 相似度天然偏高，会协同出不太相关的热门 item。视频号也有此问题。

解法：在 word2vec 训练的**优化目标中加入正则项**，抑制热门 item embedding 模过大。

> 原文：「经过优化后的 UU embedding 召回效果提升显著」。⚠️ 原文未给量化提升，面试可讲「热点 item 的误召回明显下降，embedding 分布更均匀」，不要报具体数字。

## 4. 基于 embedding 的召回策略（13 路）

### 4.1 召回衍生

基于行为 embedding 衍生出 **13 种不同策略**的召回，成为欧拉推荐系统主力召回。包括：

- `feed2feed` 召回
- `user2user2feed` 召回
- `user2finder2feed` 召回
- ……（共 13 路）

### 4.2 user2user2feed 召回逻辑（原文还原，最具体的一路）

在线维护 `uin → 已读 Feed` 列表，冷热结合，**每个 uin 的 list 长度 = 100**，字段：
`uin, <feed#is_view#is_post#is_like#is_finish_play#is_click_head#is_follow#is_comm#is_unlike_feed#is_unlike_finder#max_expose_time>list`

请求流程：
1. 通过 **simsvr** 找到近邻的 100 个 touin 及其 similarity
2. 用这 100 个 touin 取各自「用户已读 Feed」得 feed list
3. `max_expose_time` 重缩放：`[<10s→0, 10s~20s→0.5, 20s~30s→1, ≥30s→2]`
4. 按 feed 去重聚合（group by feed），加权求和/求平均（权重 = similarity）：
   - `sum(is_like * similarity)` / `sum(is_finish_play * similarity)` / `sum(max_expose_time_rescale * similarity)` / `sum(is_follow * similarity)`
   - 同理 `avg(...)` 系列
5. **两层排序截取**：
   - 先过滤：只保留 `like_cnt>=1 或 follow_cnt>=1 或 finish_play_cnt>=2` 的 feed
   - 第一层用 **sum** 加权分倒排，截前 1000
   - 第二层用 **avg** 加权分倒排，截前 100

> 设计意图：sum 保证覆盖广度（热门 feed 不被漏），avg 保证精度（避免被少数强信号 item 主导），两层截取保召回质量。

## 5. 落地效果

### 5.1 系统级

- 行为 embedding 已落地应用到欧拉推荐系统**召回模块**，衍生 13 路召回，成为**主力召回**。
- 基于行为 embedding 的召回，效果**远优于欧拉召回平均效果**。

### 5.2 具体路效果（唯一量化口径）

> 原文：「81 路是基于行为 embedding 的 user2user2feed 召回（局部点赞率排序），30 路是基于行为 embedding 的 feed2feed 召回，**均比欧拉召回总体的点赞率高 60% 以上（相对）**」。

- 81 路 user2user2feed、30 路 feed2feed：**点赞率比欧拉召回总体高 60%+（相对）**
- 83 路 user2user2feed（点赞率 + 完播率 + 人均曝光时长排序）：点赞率及完播率均高于欧拉召回总体

⚠️ 注意：这是「相对欧拉召回总体」的相对提升，不是绝对值；面试讲「**相对提升 60% 以上**」即可，不要扩成绝对值。

## 6. 面试话术与雷区

### 6.1 一句话定位（150 字，可直接背诵）

> 在腾讯视频号，我负责**行为 Embedding 召回**——把视频号的 user-feed（点赞/关注/完播/曝光）、user-finder（关注）、finder-feed（发表）、feed-tag 四类行为构造成**异构网络**，用 5 种 metapath 随机游走 + word2vec 训出 user/finder/feed embedding，衍生出 13 路召回，成为欧拉推荐系统的主力召回。最体现算法深度的是两个难点：灰度期行为稀疏 → 用 metapath 数据增强打通冷门 feed；哈利波特热点 → 在 word2vec 加正则抑制热门 item embedding 模过大。落地后几路召回点赞率比基线高 60%+（相对）。

### 6.2 深挖追问链（L1 动机 → L2 技术 → L3 故障）

| 层 | 追问 | 应答要点 |
|---|---|---|
| L1 | 为什么用 Graph Embedding 而不是 DSSM？ | 视频号初期行为稀疏、graph 能借 finder/tag 连边补冷门；DSSM 更适合有丰富特征交互的场景。两者不冲突，是不同召回路 |
| L1 | user/finder/feed 三类节点，为什么要把 finder（号主）也训 embedding？ | 号主是 content 与 user 的桥梁，finder-feed 边能反哺 feed、finder 也能被 user 召回，丰富召回语义 |
| L2 | 4 类边权 2:2:2:1 怎么定的？ | 点赞/关注/完播是强正反馈给高权，单纯曝光>30s 是弱信号给低权；⚠️ 原文未给调参过程，可讲「按行为强度分层赋值，离线近邻质量评估迭代」 |
| L2 | 5 种 metapath 怎么选的？ | 覆盖 user↔feed 直接 + 经 finder 间接 + 经 tag 语义三类连接，专门补稀疏 feed |
| L2 | 哈利波特问题正则项具体加在哪？ | word2vec 优化目标上加约束 embedding 模的范数，惩罚热门 item 模过大；⚠️ 原文未给正则形式（L2？cosine 归一），可发散讲「对 embedding 做 L2 归一 / 对 loss 加 norm 惩罚」 |
| L2 | user2user2feed 为什么两层排序（sum→avg）？ | sum 保覆盖、avg 保精度，先粗排 1000 再精排 100，平衡召回质量与计算 |
| L3 | 灰度期行为极稀疏怎么办？ | metapath 数据增强 + finder/tag 连边，把冷门 feed 接入高频节点；同 §3.3 |
| L3 | 线上 simsvr 找 100 近邻延迟怎么控？ | 用 ANN（hnsw/Faiss）近邻检索；⚠️ 原文未明确视频号用哪款，可讲通用 hnsw |
