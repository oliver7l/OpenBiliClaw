## 1. 概述

### 1.1 业务背景

OPPO 海外应用商店（东南亚六国：**印尼、泰国、越南、菲律宾、马来西亚、新加坡**）的推荐系统。与国内环境天差地别：网络、设备、用户识别、应用生态全都不一样，是出海推荐的经典难题。

### 1.2 候选人在其中的角色

> 原文（第一人称）：「我负责的是 OPPO 海外应用商店在东南亚六国（印尼、泰国、越南、菲律宾、马来西亚、新加坡）的推荐系统。」

职责覆盖推荐系统全链路应对（挑战拆解 + 方案设计），重点是**环境适配 + 跨域知识迁移 + 多国联合建模**。

### 1.3 为什么这是差异化素材

出海经验在推荐/广告岗里**稀缺**。多数候选人只有国内经验，能把「弱网 / 低端机 / 无稳定 ID / 跨域迁移 / 多国分布偏移」讲透，是显著加分项。尤其适合：**字节（TikTok 出海）、大宇无限（海外）、任何带出海业务的岗位**。

## 2. 四大挑战与解法（面试主线，按层讲）

### 2.1 挑战一：基础设施层（网络差）

- 现象：东南亚网络质量参差不齐，**印尼很多地区只有 3G**，移动网速只有中国的 **1/5**
- 解法：**三层推荐结果缓存 + 兜底策略**，保证弱网下用户不会看到空白页

### 2.2 挑战二：设备层（低端机 + 缓存被清）

- 现象：**超过 60% 手机是 200 美元以下的低端机**，存储仅 32GB 且长期接近满；系统频繁清理 APP 缓存，推荐数据被清
- 解法：**分级缓存 + 端侧轻量模型**，确保核心推荐数据不被清理

### 2.3 挑战三：用户识别层（无稳定 ID）

- 现象：海外无国内那种稳定设备 ID，**GAID 可随时重置**，且很多用户**不登录**应用商店
- 解法：**多信号融合的设备指纹 + 会话级推荐 + 群体画像**三层策略，无论用户 ID 状态如何都给得出个性化推荐

### 2.4 挑战四：建模层（分布偏移 + 样本稀疏 + 多目标冲突）

- 现象：多国联合建模面临 **数据分布偏移、正样本极度稀疏（下载率不到 2%）、多目标冲突**
- 解法：
  - 分布偏移 → **共享底层 Embedding + 国家适配层**架构
  - 样本稀疏 → **多任务学习 + 隐式反馈信号**（用曝光/点击等隐式信号补下载正样本不足）
  - 多目标冲突 → 多任务学习统一建模

## 3. 跨域知识迁移（本项目的算法亮点，面试深挖区）

### 3.1 核心洞察：规律通用，实体不同

> 原文金句：「模型学到的不是『微信好』，而是『社交类 + 高评分 + 小体积 + 支持离线的应用好』。这条规律从国内迁移到海外，只需把『微信』换成『WhatsApp』，其他不变。」

即：不要把「应用 ID」当作特征，而是把应用**属性**映射到通用语义空间，规律可跨域复用。

### 3.2 三个迁移锚点

| 锚点 | 国内 → 海外可对齐维度 | 能否迁移 |
|---|---|---|
| **应用属性特征** | 类别（社交）、APK 大小、评分、是否支持离线、更新频率、图标主色调 | 同一语义/数值/视觉空间 |
| **用户设备与环境特征** | 设备价位段、存储空间、网络类型、OS 版本、语言、时段 | 映射到位价段/语种等通用维度 |
| **用户行为模式** | 搜索后下载、详情页>10s 表兴趣、下载后 3 天卸载表质量差、周末下载高 | 行为模式通用 |

### 3.3 第一步：构建共享特征空间

把国内 / 海外特征都映射到同一「通用语义空间」：
- 国内「微信」+ [社交, 通讯, 180MB, 4.6星, 支持离线, 中文]
- 海外「WhatsApp」+ [社交, 通讯, 65MB, 4.3星, 支持离线, 多语言]
- 虽 ID 不同，特征空间里向量相近 → 模型学到的规律可直接迁移

同理用户侧：国内「华为 Mate60 高端 + 128GB + WiFi/5G + 中文」与海外「三星 A04 低端 + 2GB + 3G/4G + 印尼语」都映射到「高端设备 + 大存储 + 好网络」通用维度。

## 4. 应用生态差异（展现业务理解，面试加分）

| 类别 | 国内主流 | 海外（东南亚）主流 |
|---|---|---|
| 社交 | 微信、QQ、微博 | WhatsApp、Facebook、Line、Zalo |
| 短视频 | 微视、B站 | TikTok、YouTube Shorts |
| 电商 | 淘宝、京东 | Shopee、Lazada、Tokopedia |
| 支付 | 支付宝、微信支付 | GoPay、GrabPay、MoMo |
| 出行 | 高德、滴滴 | Grab、Gojek |

> 原文：「应用之间的关联关系、竞争关系完全不同，不能直接复制。」→ 强调出海要重做生态理解，不能照搬国内策略。

## 6. 面试话术与雷区

### 6.1 一句话定位（150 字，可直接背诵）

> 在 OPPO 我负责海外应用商店（东南亚六国）的推荐系统。出海和国内最大的不同是环境：印尼很多地区只有 3G、网速是国内的 1/5，60%+ 是 200 美元以下低端机、存储常满被系统清缓存，海外还没稳定设备 ID、GAID 可重置、多数人不登录。我分四层应对：基础设施做三层缓存兜底、设备做分级缓存 + 端侧轻量模型、用户识别做多信号设备指纹 + 会话级推荐 + 群体画像、建模做共享底层 Embedding + 国家适配层解决分布偏移，用多任务 + 隐式反馈补下载率不到 2% 的样本稀疏。最关键的是跨域迁移：模型学的是「社交类 + 高评分 + 小体积」这种通用规律，不是「微信好」，把国内规律映射到海外只需换实体。小国家核心指标提升 8-12%。

### 6.2 深挖追问链

| 层 | 追问 | 应答要点 |
|---|---|---|
| L1 | 为什么不用各国独立建模？ | 小国家数据少，独立建模学不充分；共享底层 Embedding 让大国知识迁移到小国，原文小国指标 +8-12% |
| L1 | 端侧轻量模型具体什么模型？ | ⚠️ 原文未给模型名，可发散讲「端侧跑轻量召回/特征交叉，云侧跑重模型，分级缓存保核心数据」 |
| L2 | 设备指纹怎么融合多信号？ | ⚠️ 原文未给具体特征，可讲通用思路：硬件指纹 + 行为序列 + 会话聚类，对抗 GAID 重置 |
| L2 | 隐式反馈具体用哪些？ | 曝光、点击、详情页停留等作为下载正样本的补充信号，缓解下载率<2% 稀疏 |
| L2 | 国家适配层怎么设计？ | 共享底层 Embedding（跨域通用规律）+ 各国适配层（本地分布），类似多任务共享底座 + 任务特定头 |
| L3 | 分布偏移具体怎么发现/度量？ | ⚠️ 原文未给度量方法，可讲「分国监控特征分布 + 误差分解，定位偏移来源」 |

### 6.3 🚫 雷区（必看）

1. **X% 占位符**：整体下载转化率提升是 **X% 未填**，任何情况下不编具体数字。只讲「小国家 +8-12%」和「方法」。
2. **别和 OPPO 国内混淆**：国内讲 oCPX 出价/校准/冷启动，海外讲环境适配/跨域迁移/联合建模。面试官若听到「OPPO」问出价，先确认他问的是国内商业化还是海外推荐。
3. **模型名不杜撰**：端侧模型、设备指纹融合方法原文未给具体实现，被追问讲通用思路，不编框架名。
4. **下载率<2%**：这是原文给的真实口径（正样本稀疏），可讲，是说服力强的事实锚点。

## 7. 适用岗位串联

- **字节（TikTok 出海 / 国际化推荐）**：直接对口，重点讲四层环境适配 + 跨域迁移
- **大宇无限（海外应用商店/广告）**：环境高度相似（东南亚/拉美弱网低端机），海外经验是核心卖点
- **任何带出海业务的推荐/广告岗**：把「规律通用、实体不同」的迁移方法论作为差异化叙事
- 与「OPPO 国内 oCPX」组合：展现「同一家公司，我既做过国内商业化全链路，也做过海外推荐系统出海」的完整度
