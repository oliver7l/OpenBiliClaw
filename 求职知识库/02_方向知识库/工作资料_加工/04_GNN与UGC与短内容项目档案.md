# 1. 图神经网络部分（面试高频，重点）

## 1.1 为什么推荐系统需要 GNN

| 诉求 | 问题本质 | GNN 的解法（源文件依据） |
|---|---|---|
| **高阶连通性** | 用户-内容交互是稀疏二部图，协同过滤只利用一阶共现 | 邻域聚合（Neighborhood Aggregation）即"图卷积"：节点表示由其邻居迭代聚合得到，多层可捕获 2 跳、3 跳乃至更高阶关系（源文件：*The Core of GNN*，邻域聚合公式 `h_v = f(h_a,h_b,h_c,h_d,h_e)`，类比 CNN 的中心-环绕滤波） |
| **稀疏行为** | 长尾用户/内容行为极少，ID embedding 学不好 | 网络嵌入（DeepWalk / node2vec / LINE）用**随机游走**生成节点上下文，把图结构转化为"句子"再 SkipGram 训练，天然缓解稀疏（源文件：DeepWalk 用固定长度无偏随机游走生成 context） |
| **冷启动** | 新账号/新内容无历史行为，无法查表 | **归纳式（Inductive）学习**：GraphSAGE 对邻居采样+聚合，新节点到来只需聚合其邻居，**无需重训全图**；而谱方法 GCN 是**转导式（Transductive）**，新节点须重新跑全图（源文件：Spatial GCN 支持 inductive，Spectral GCN 需载入全图、效率低） |
| **异质信息** | 用户/账号/内容/标签多类型、多关系 | 异质图注意力网络 HAN（Heterogeneous Graph Attention Network, WWW 2019，源文件 §3322）按元路径聚合、用注意力区分不同类型邻居 |

> 面试话术要点：GNN 不是替代双塔/召回，而是**把"图结构信号"注入表征**。高阶连通性 + 归纳式冷启动 + 异质关系建模，是它对传统召回的核心增量。

## 1.2 具体模型详解（按源文件覆盖程度）

源文件覆盖：GCN、GraphSAGE、GAT、DeepWalk、node2vec、HAN、ProNE/NetMF。**未覆盖**：PinSage、EGES（业界推荐 GNN，但本批源文件未出现，不建议主动宣称做过）。

### 1.2.1 GCN（Graph Convolutional Network, Kipf & Welling, ICLR 2017）

- 传播规则（源文件原文）：

  ```
  h_v^(k) = σ( W^k · Σ_{u∈N(v)∪{v}} h_u^(k-1) / (|N(u)|·|N(v)|) )
  ```

  其中 `|N(u)|·|N(v)|` 为归一化（对称归一化邻接矩阵），`σ` 为非线性激活（如 ReLU），`W^k` 为第 k 层参数。
- 特性：**谱方法**，需载入整张图做滤波 → 大图低效、转导式（源文件明确其缺点："loading the whole graph into memory … low-efficiency for big graph, transductive working mode"）。
- 可理解为"多层图卷积网络"，是 ChebNet 的简化版（源文件：GCN = reduced version of ChebNet）。

### 1.2.2 GraphSAGE（Hamilton et al., NeurIPS 2017）—— **采样聚合的代表**

- 核心公式（源文件）：

  ```
  h_v^(k) = σ( [ AGG( h_u^(k-1), ∀u∈N(v) ) , B^k h_v^(k-1) ] )
  ```

  - 与 GCN 区别：GCN 用"求和+归一化"，GraphSAGE 用**任意可微聚合函数**（mean/pool/LSTM）聚合邻居，**再与自身表示拼接（concat）**而非简单相加。
  - **归纳式**：不依赖全图，新节点可直接聚合邻居得到表示。
- 两个关键步骤（源文件 AAAI 教程）：① **Sampling neighbors（采样邻居）**；② **Aggregating neighbors（聚合邻居）**。
- 工程意义：采样使训练可 **batch / mini-batch**，能处理超大规模图（大图友好的根本）。

### 1.2.3 GAT（Graph Attention Network, Veličković et al., ICLR 2018）—— **注意力的代表**

- 公式（源文件）：

  ```
  h_v^(k) = σ( Σ_{u∈N(v)∪{v}} α_{v,u} · W^k · h_u^(k-1) )
  ```

  - 与 GCN 区别：把固定的归一化系数换成**可学习的注意力权重 α_{v,u}**，邻居影响力由数据学出来（源文件：*"Realistically, neighbors play different influences"*）。
  - 参数含两部分：特征变换参数 + 注意力参数。
- 直觉：邻居重要性不同（如高互动好友 vs 偶然点击），注意力自动加权。

### 1.2.4 网络嵌入三剑客（GNN 前身的"浅编码器"）

| 模型 | 机制 | 源文件要点 |
|---|---|---|
| **DeepWalk** (KDD 2014) | 固定长度**无偏随机游走**生成节点序列 → SkipGram + 分层 softmax 学习表示 | 随机初始化表示，SGD 同时更新分类器权重与节点表示；YouTube/BlogCatalog 实验 |
| **LINE** (WWW 2015) | 显式保留**一阶 + 二阶**邻近度 | 作为 DeepWalk 之后的改进被列举 |
| **node2vec** (KDD 2016) | **有偏随机游走**，用 p、q 参数权衡"局部(BFS)/全局(DFS)"视野 | 源文件：node2vec 是 DeepWalk 的特例（biased walk ⊂ random walk） |
| **ProNE / NetMF** (IJCAI 2019 / WSDM 2018) | 把 DeepWalk/LINE/PTE/node2vec **统一为矩阵分解**；ProNE 在 1 亿节点上单线程 29 小时、比 20 线程其他方法快 10–400× | 源文件实证：Youtube ~1M 节点 10 分钟；1 亿节点单线程 29 小时 |

> 矩阵分解视角（面试加分）：DeepWalk 渐近等价于分解一个与邻接矩阵 `A` 相关的矩阵 `S=f(A)`，上下文窗口 T、负采样数 b 决定 `S` 的形式（源文件 §1502-1519）。这解释了为什么"网络嵌入"和"浅层查表 embedding"本质相通。

### 1.2.5 HAN（异质图注意力, WWW 2019）

- 源文件 §3322 引用：Xiao Wang et al., *Heterogeneous Graph Attention Network*, WWW 2019。
- 用于节点/边类型多样的场景（用户-账号-内容-标签），按元路径分别聚合再注意力融合。**候选人账号图落地可套此思路**（账号、用户两类节点 + 关注边）。

### 1.2.6 模型横向对比表（面试速答）

| 模型 | 聚合方式 | 是否归纳式 | 大图友好 | 注意力 | 适用场景 |
|---|---|---|---|---|---|
| GCN | 固定归一化求和 | 否（转导式） | 否（需全图） | 无 | 中小图、transductive |
| GraphSAGE | 可微聚合+拼接 | **是** | **是（采样）** | 无 | 大图、冷启动、工业 |
| GAT | 注意力加权 | 视实现 | 中等 | **有** | 关系异质、需可解释 |
| HAN | 元路径+注意力 | 视实现 | 中等 | 有（异质） | 多类型节点/边 |
| DeepWalk/node2vec | 随机游走+SkipGram | 是（嵌入） | 是 | 无 | 无特征图、基线上游嵌入 |

### 1.3.1 同质图 vs 异质图（面试追问）

- **同质图**：只有一类节点、一类边（如用户-用户对 Bhag 的协同图）。GCN/GraphSAGE/GAT 原生支持。
- **异质图**：多类节点 + 多类边（用户-账号-内容-标签）。推荐系统几乎都是异质图；HAN 通过"元路径"（meta-path，如 用户-关注-账号-发-内容）定义语义邻居再聚合。
- 候选人账号图是**二部异质图**（用户↔账号，仅"关注"一种边），用 GraphSAGE/GCN 已足够；若加入"同 tag""同内容"边则升级为异质图，可上 HAN。

## 1.4 训练与上线：与双塔/召回结合、serving 方案

> ⚠️ 以下"结合方式"为**通用工程范式**（源文件未给出候选人的具体 A/B 与延迟数字）；候选人的**真实落地形态**见 `UGC推荐特征生产总览`：

- **真实 serving 链路（源文件可考）**：
  - 账号向量（item2vec/DeepWalk/Line）离线产出到 HDFS：`hdfs://.../puin_day_embedding.vec`，向量格式。
  - 注册进**特征中心**，线上经 `trpc-cli` 调用 `trpc.kdrc.fetch_original_feature.Fetcher` 取 `puin_feature##overall_level` 等特征（源文件 §1.2.2、§1.2.3）。
  - 即：**离线图嵌入 → HDFS → 特征中心 → 在线 trpc 拉取**，属"T+1 批产特征 + 在线查表"模式。
- **GraphSage/GCN 账号向量**在特征总览中列为 **「待生产特征」**（规划中，未上线），逻辑同上式（基于用户-账号关注图离线产出账号 embedding）。
- **与双塔/召回结合（通用）**：GNN 产出的 user/item embedding 可直接作为双塔的输入表征或召回向量；源文件 `M7 汇报` 提及"图模型召回""账号协同推荐"作为召回方向之一（见 §2.3）。
- **线上延迟解法（通用知识，需候选人补充实测）**：① 图嵌入离线算好、在线只做向量查表/ANN 检索，避免实时多跳聚合；② 若需近实时，采用 mini-batch 采样 + 邻居缓存；③ 工业级参考（源文件未含 PinSage）：局部图采样 + 预计算。

### 1.4.1 大特征中心（M7 汇报，源文件可考的工程底座）

M7 汇报的「大特征中心&排序架构」给出统一特征服务形态：通用特征中心在线服务 = 用户特征 + Item 特征 + 特征算子 + 外部特征 + 特征 cache + serving（TensorFlow/无量/PE）；统一排序框架平台化、特征 cache、排序模型监控；离线计算（Spark 批 / Flink 实时）+ 画像/后验/session 多源特征统一管理。候选人的账号向量正是经此特征中心对外服务（§1.4 的 trpc 拉取即落在该体系内）。

## 1.5 效果与踩坑（源文件可考 + 通用）

| 坑 | 源文件依据 | 应对（通用） |
|---|---|---|
| **Over-smoothing（过平滑）** | 源文件原话：*"GNN: Over-smoothing, Overfitting, Non-robust"*；多层聚合后节点表示趋同、可分性下降 | 控制层数、加残差/跳连、邻居采样限制感受野 |
| **Overfitting（过拟合）** | 同上，列在 GNN 三大问题之首 |  dropout、早停、边 dropout |
| **Non-robust（不鲁棒）** | 同上 | 对抗训练、更稳的聚合 |
| **大图扩展性** | 谱方法 GCN 需载入全图、转导式、大图低效；空域 GCN 靠 batch + 采样支持大图（源文件 §2471-2484） | 用 GraphSAGE/采样式而非全图 GCN；归纳式支持新节点 |
| **冷启动依赖图结构** | 转导式模型新节点需重算 | 归纳式 GraphSAGE 天然支持 |

### 1.5.1 过平滑 vs 过挤压（面试追问）

- **过平滑（over-smoothing）**：层数过多，所有节点表示收敛到相同值（源文件明确列为 GNN 问题）。解法：浅层（2 层常见）、残差连接、Jumping Knowledge。
- **过挤压（over-squashing）**：深层把整图信息经根节点压入固定维度，远处信号丢失，影响长程依赖建模。**注：源文件未直接出现此术语，属通用 GNN 知识，候选人需自行补充**；通用解法：树状/层次聚合、增加跳连、采样放宽瓶颈。

# 2. UGC 推荐部分

## 2.1 UGC 内容特点（源文件画像）

- **质量参差 + 搬运泛滥**：生态治理目标含"搬运号被挤压、良币驱逐劣币"（源文件 §2987-2988），说明低质/搬运内容曾挤占分发。
- **强冷启动诉求**：账号有"新手期/成长期/成熟期/大 UP 主"生命周期（§3062-3069），新账号需冷启扶持避免 0 流量。
- **时效性强**：规划"新增时新优质账号召回"（§2859、§2947），视频新用户"时新性不足"被点名为问题（§2822-2824）。
- **内容类目长尾**：1591 个账号样本中类目分布极不均（游戏 352、美食 239、生活 185、搞笑 123… 详见 §5 数字清单），头部类目过度曝光。
- **互动稀疏 + 样本选择偏差**：图文"互动订阅行为很稀疏"且有样本选择偏差（§2848-2849）。
- **多目标冲突**：点击、时长、关注、点赞、收藏、订阅多个目标需平衡，且样本空间不一致（§2852、§2938）。

## 2.3 分发策略（M7-henrys 汇报，源文件可考）

**整体架构**：图文 / 视频 / 日报 / UGC 四条线，每线均含「推荐网关 → 精排 → 粗排 → 召回 → 特征」；现状"推荐架构一致，技术架构异构，研发能力复用度差"（§2552）。统一计划见 §5 时间线。

**多目标优化**（核心排序方向）：
- 主目标：图文/视频「点击 + 时长双目标」；图文进一步引入关注/点赞/收藏/订阅多目标；视频主 Feed 切到「点击+时长+下滑」多目标（§2852-2854）。
- 模型：尝试 **ESSM 与 MMoE 结合**解决样本空间问题；多目标参数融合用**贝叶斯优化**（§2855-2856）。
- 算力受限 → **模型蒸馏**；**召回层学习多目标**（§2854、§2939）。
- 在线调参：多目标寻参 `a*时长 + b*点赞 + c*关注 + d*转发 + e*点击资料卡 + …`；策略层寻参（关注率/新物品/优质账号调权）；算法含 Grid/Random/**Bayesian Optimization**，未来 AutoML（§2725-2765）。

**召回方向**：账号协同推荐（主 TL 增加优质高订阅账号）、新增时新优质账号召回 / 社交召回 / 关注召回 / **图模型召回**、优化视频 CB 召回（§2858-2860、§2947）。

**低活/新用户分发**（重点）：
- 图文低活：独立样本与特征模型；基于更细粒度人口属性+探索画像；"把低活当**中高活**推荐"（§2807-2809）。
- 视频纯新用户：新增兴趣探索（基于人群/兴趣探索优质账号内容）、排序结合人群+外部画像+样本选取优化；日报视频提升曝光与相关性（§2828-2833）。

**混排优化**：异构卡片时长分布差异大、难用回归/阈值分类拟合；需考虑"带动时长""序列上下文""强插/扶持业务逻辑（广告）""屏幕高度导致的曝光效率差异"。视频渗透率当前 60%（§2866-2887）。好友推荐探索（"我的好友都在关注什么"对兴趣内容加成）。

## 2.4 生态治理（账号生态，源文件可考）

- **关注总量翻倍**：300 万 → 600 万（2 周内）；新账号最高日涨粉 10 万；最高 682 万粉（§2961-2980）。

# 4. 面试 Q&A（第一人称可口述，≥12 组）

> 形式：面试官问 → 童力答（口述稿）。涉及模型原理的回答基于 §1 源文件；涉及项目数字的回答基于 §2/§3/§5，数字严禁改动。

**Q1：为什么推荐系统要上 GNN，双塔不够吗？**
A：双塔是"把用户和物品各自编码成向量再内积"，它假设用户-物品交互是独立样本，丢掉了**图结构里的高阶连通性**。GNN 的核心就是"邻域聚合=图卷积"——一个节点的表示由它邻居迭代聚合得到，多层就能拿到 2 跳、3 跳关系。比如账号推荐里，A 关注了 B、B 和 C 常被同一批人看，GCN/GraphSAGE 能把这种高阶相似编码进账号向量。我们 UGC 线就是用账号图产账号 embedding 做相似 UP 主召回。GNN 不是替代双塔，是给双塔/召回**补结构信号**。

**Q2：GraphSAGE 和 GCN 到底差在哪？采样怎么选？**
A：GCN 是谱方法，传播是固定归一化系数的邻居求和，而且要载入全图、转导式——新节点来了得重跑全图，大图很吃力。GraphSAGE 是把聚合函数**一般化**（mean/pool/LSTM 都行），再和自身表示拼接，而且关键在**采样邻居**：训练时对每个节点采固定数量邻居做 mini-batch，所以它支持归纳式、能上大图。采样数量怎么选？太小邻域信息不够、太大算力爆炸，工业上一般 2 层、每层采 10~25 个邻居（具体看图密度，我们账号图偏稀疏可适当调大）。这跟我们的"账号向量-GraphSage"路线一致。

**Q3：GAT 的注意力是怎么算的？和 GraphSAGE 比优劣？**
A：GAT 把 GCN 里固定的归一化系数换成**可学习的注意力权重 α**，公式上是 `Σ α_{v,u}·W·h_u`，α 由 query-key 式注意力学出来，邻居重要性自动区分。优点是能捕捉"高互动好友比偶然点击重要"；缺点是注意力要对每对邻居算，计算和存储比 GraphSAGE 的均值聚合重，大图下成本更高。所以实际选型：要可解释/异质关系复杂用 GAT/HAN，超大规模追求吞吐用 GraphSAGE 采样。

**Q4：过平滑（over-smoothing）和过挤压（over-squashing）你遇到过吗？怎么解？**
A：过平滑源文件里就列在 GNN 三大问题之首——层数一多，所有节点表示趋同、可分性掉。我们解法是控制层数（一般 2 层足够抓二阶邻居）、加残差/跳连。过挤压是另一回事：深层把整张图信息压进一个节点，远处信号"塞不进来"，典型是串行聚合时瓶颈在根节点。通用解法是加跳跃连接、用更合理的采样、或树状/层次聚合。**注：过挤压本批源文件未直接出现，是面试常见追问，建议候选人用通用知识补充。**

**Q5：GNN 上线推理延迟怎么解？线上怎么 serve？**
A：核心原则——**不要让线上做实时多跳聚合**。我们在 UGC 线的做法是离线把图 embedding 算好落到 HDFS（如 `puin_day_embedding.vec`），注册进特征中心，线上用 trpc-cli 拉 `puin_feature##overall_level` 这类特征，本质是"T+1 批产 + 在线向量查表/ANN 检索"。如果业务真要近实时，就用 mini-batch 采样 + 邻居缓存，把聚合限制在局部子图。延迟大头在向量检索，用 ANN（如 HNSW）压到毫秒级。

**Q6：你的 GNN 是转导式还是归纳式？冷启动怎么处理的？**
A：用的是 **GraphSAGE 归纳式**路线——新账号来了只要聚合它的关注邻居就能出向量，不用重训全图，这正是冷启动友好的关键。我们账号生态里新账号最高日涨粉 10 万，冷启必须靠结构信号快速给表示，而不是等它攒行为。再配合"新手期冷启动扶持、避免 0 流量"的分发策略，双管齐下。

**Q7：UGC 内容质量参差、搬运号多，你怎么建模质量、处理低质内容？**
A：分两层。特征层：我们建了"用户-账号亲密度"（点击/曝光/转评赞/分享/有效播放/进主页等行为）、账号特征、账号向量，这些本身就在刻画账号的"健康度"。生态层：用"关注效=关注数/曝光"当投入产出比，把高关注率账号分发占比提了 4 倍、SA 账号占比从 18% 拉到 40%，结果是搬运号被挤压、良币驱逐劣币。再叠加分级成长机制——大 UP 主限流、超高发文账号打压、每天前 2 条优先审核冷启，从供给端控质量。

**Q8：UGC 多目标怎么融合？ESSM 和 MMoE 你怎么用？**
A：我们主 Feed 是"点击+时长+下滑"多目标，图文还要加关注/点赞/收藏/订阅。难点是各目标样本空间不一致（比如订阅极稀疏），所以用 **ESSM 解决样本空间偏差、MMoE 做多任务共享+门控**；多目标权重用**贝叶斯优化**去搜融合参数，而不是拍脑袋。算力受限时靠模型蒸馏，并把多目标学习下沉到召回层。

**Q9：低活/新用户你怎么优化分发？**
A：图文低活我们直接独立样本、独立特征模型，不跟活跃用户混——因为低活的重要短期行为/画像缺失，混在一起会被泛化掉。低活 1（tagNum≤500 且 7 日无点击）用户量占 32.7%、请求量才 10.1%；低活 2（tagNum≤200）占 23.6%、请求 7.1%，是被严重低估的流量。打法上基于更细粒度人口属性+探索画像，并"把低活当用户高活推荐"。视频纯新用户 73% 在 19~40 岁、游戏类目过度曝光、时新性不足，就靠新增兴趣探索+日报视频提曝光来调结构。

**Q10：短内容时长目标怎么建模？下滑/退出信号怎么用？**
A：短内容人均时长基线才 3.4 分钟，春节峰值到 8.4，所以时长是核心优化目标之一。我们统一排序模型用多专家（Expert-P/Expert-S）+ 门控 + 定制 Tower，时长作为一个独立专家/目标头参与融合，再配 mix 辅助任务让专家分化。下滑信号上：滑过未点是隐式负样本、点击并看完整是强正样本，排序要平衡 CTR 和完播/时长，防"高 CTR 低时长"的标题党。可参考 UGC 线视频下翻率仅 50% 的教训——光优化点击不够，得把"下滑后是否继续消费"也建模进去。

**Q11：短内容和长内容推荐的差异，你怎么做模型取舍？**
A：短内容秒级消费、高频下滑、PV/UV 高，难点是快速捕获瞬时兴趣、避免重复疲劳，模型要轻、延迟要低，多目标偏 CTR+时长。长内容看完整率、订阅、深度时长，要长序列兴趣建模。所以短内容我们用轻量多专家排序 + 强 CTR/时长信号；长内容/视频用更深序列模型 + 关注/订阅生态目标。两条线架构一致、技术异构，正好是我们 M7 统一计划要解决的复用问题。

**Q12：你的图模型召回和双塔召回怎么配合？**
A：账号向量（GraphSAGE/GCN 或 item2vec）产出的是账号/内容 embedding，可直接作为**双塔的输入表征**，也能独立做**图模型召回**——在 UGC 线我们明确把"图模型召回"列为召回方向之一，和关注召回、社交召回、时新优质账号召回并列。分工上：双塔负责通用语义匹配，图模型补"结构邻居"信号（相似 UP 主、协同关注），两者在粗排/精排前融合候选。

**Q13：你们推荐架构统一计划的意义？**
A：现状四条线（图文/视频/日报/UGC）"架构一致、技术异构"，曝光去重/向量召回/特征共享都重复建设，特征不能一键取用。我们下半年目标是建统一特征中心（特征接入 200+）、统一排序框架、统一推荐网关，把实验上线效率从天级压到小时级。这对算法迭代速度是指数级提升。

**Q14：大图 GNN 训练为什么不用全图 GCN？**
A：源文件讲得很透——谱方法 GCN 要"loading the whole graph into memory for filtering"，大图内存扛不住且转导式。空域方法（GraphSAGE）靠 batch 训练 + 邻居采样支持大图、还是归纳式。所以工业大图基本选采样式空域模型，这也是我们账号向量选 GraphSAGE/GCN 路线的原因。

**Q15：你做过多目标里的样本选择偏差（sample selection bias）吗？怎么解？**
A：做过。源文件里图文互动订阅行为"具有样本选择偏差"是明确写进汇报的。本质是曝光样本不等于全量兴趣分布。我们用 ESSM 把粗粒度目标（如点击）当细粒度目标（如转化/订阅）的先验，用 CTR 校正曝光偏差；再配合负采样/纠偏权重、以及对未曝光候选做探索（探索召回）来缓解。这是 ESSM+MMoE 组合的另一重收益。

**Q16：账号生态"良币驱逐劣币"具体怎么量化、怎么落地？**
A：两个硬指标：一是"关注效=关注数/曝光"作为投入产出比，高关注率账号分发占比提了 4 倍；二是 SA 账号（优质/高订阅）分发占比从 18% 拉到 40%，同时搬运号被挤压。落地靠分级分发（新手冷启、成长加投、成熟自然、大号限流）+ 潜力 UP 主发掘模型（发布/转粉/完播/互动/复购多维）+ 运营审核入成长体系。结果是关注总量 2 周翻倍（300 万→600 万）。

**Q17（附加）：如果让你从 0 设计 UGC 账号 GNN，你会怎么构图和选模型？**
A：节点=用户+账号两类，边=关注（主）+行为共现（辅）；先上 GraphSAGE 归纳式（冷启友好、大图可采样），账号 embedding 离线产出进特征中心。若后续要融合"同 tag/同内容"等多关系，升级 HAN 做异质聚合。评估用召回侧的 TopK 相似账号命中（参考画像中台 Top5Recall@100=0.42 的口径）和下游关注率/涨粉指标。

## 附：术语表（面试速查）

| 术语 | 含义（源文件依据） |
|---|---|
| GCN | 谱方法图卷积，固定归一化邻居求和，转导式（Kipf & Welling 2017） |
| GraphSAGE | 采样+可微聚合+拼接，归纳式，大图友好（Hamilton 2017） |
| GAT | 注意力加权邻居聚合（Veličković 2018） |
| HAN | 异质图注意力网络，按元路径聚合（WWW 2019） |
| DeepWalk / node2vec | 随机游走+SkipGram 的网络嵌入；node2vec 为有偏游走 |
| ProNE / NetMF | 将网络嵌入统一为矩阵分解；ProNE 超大规模快速 |
| MMoE | 多专家多任务，门控做任务/专家个性化融合 |
| ESSM | 全空间多任务，用粗目标校正细目标样本选择偏差 |
| 转导式 / 归纳式 | Transductive（需全图、新节点重算）vs Inductive（采样聚合、新节点免重训） |
| 过平滑 | 多层聚合后节点表示趋同；源文件列为 GNN 三大问题之一 |
| 关注效 | 关注数 / 曝光（账号生态投入产出比） |
| SA 账号 | 优质/高订阅账号（源文件：分发占比 18%→40%） |
| 浮层 / 主 feeds / 日报 | 短内容与 UGC 的不同分发场景入口 |
| 下翻率 | 视频消费下滑比例（UGC 线仅 50%） |
