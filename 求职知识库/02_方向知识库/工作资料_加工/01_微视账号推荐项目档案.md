### 1.1 项目背景与业务目标
- 业务归属：**社交线「用户建联 → 关注分发 → 端内外互动」大思路**的第一环（关系建联/基础感知）。
- 核心目标：**帮助用户在微视找到同好，通过提升「关注率」来提升用户后续消费与留存**。（源：[[09_内部资料/微视账号推荐/账号推荐项目wiki.md]] 1.1 背景）

### 1.5 推人卡片逻辑与样式（场景细节）
源：wiki 1.2.2。各场景的下发逻辑不同，面试时能讲清「同一个推荐能力在不同入口的适配」很重要：
- **消息页**：用户消息<5条时出卡片，下发量不限制（渗透最广的入口）。
- **关注页**：每 5 个 vv 后插入一个推人卡片，每条下发 8 个用户；列表为空时是列表页、非空时是横向卡片。
- **个人主页**：用户关注某账号后，出现相关推荐账号，每条下发 8 个用户。
- **发现好友页**：个人主页-关注列表内可直接关注，每次下发 20 个用户，分 4 个 Tab（推荐/QQ好友/微信好友/通讯录好友）。

### 1.7 核心难点小结（面试一句话总括）
⚠️面试可发散（基于原文脉络归纳）：账号推荐难在「**稀疏 + 长期 + 社交**」三重叠加——关注行为稀疏（需图嵌入补泛化）、关注是长期关系（北极星看关注率而非即时 CTR）、且强依赖社交信任（好友关系链）。解法是一套「**图嵌入召回打底 + LR/规则排序 + 类目 TS 探索 + 品类强间隔多样性 + 曝光降权纠偏**」的可解释链路，每一层都对应一个明确痛点。

### 1.6 业务价值判断（面向「营销方向」面试的关联）
⚠️面试可发散（非原文，用于对齐比亚迪营销方向）：账号推荐的北极星「关注率」本质是**用户关系链增长/私域沉淀**指标——关注一个作者 = 建立一个长期可触达、可二次营销的通道。这与「营销方向」关注的用户增长（Acquisition）、留存（Retention）、生命周期价值（LTV）高度同源：图嵌入召回解决「找对人」，Thompson Sampling 重排解决「在有限曝光下平衡确定转化与长尾探索」，这套 EE 框架同样适用于广告/活动/权益的精准触达与探索。准备时可把「关注率→关系链→长期消费与留存」的增长闭环，类比到汽车营销的「线索→ owner 关系→复购/转介绍」。

## 2. 问题定义：账号推荐 vs 内容推荐的本质差异

| 维度 | 内容推荐 | 账号（作者）推荐 | 本项目应对 |
| --- | --- | --- | --- |
| 反馈信号 | 点击/完播/互动，频次高 | **关注**行为稀疏、决策重、不可逆性强 | 正=点击关注/点头像/看主页；负=曝光未点击（达人LR 下采样 1:5，好友LR 1:10） |
| 长期价值 | 短期消费 | 关注形成**关系链**，带来长期分发与留存 | 北极星=关注率，而非单纯 CTR |
| 冷启动 | 新内容靠物料特征 | 新作者缺行为、新用户画像不稳 | MetaPath2Vec 引入 sideinfo 解决作者冷启动；新用户走规则打分 |
| 稀疏性 | 物品-用户共现较密 | 作者-作者共现极稀疏 | **图嵌入（DeepWalk/Line/Node2vec）** 从行为序列/关注异构图补泛化 |
| 多样性目标 | 内容去重打散 | 防止「只推同类目作者」陷入推荐黑洞 | 类目强间隔 + **Thompson Sampling 类目维度探索** + 关注倾向配比 |
| 社交信号 | 无/弱 | 强（一度/二度好友、好友已关注你） | 好友召回+亲密度（共同好友数/图学习 EMB） |
> 源：`账号推荐项目wiki.md` 全文及各场景分布；`好友推荐指标建设.doc` 指标体系。

### 2.1 为什么账号推荐尤其适合图嵌入（分析）
⚠️面试可发散（基于原文事实的逻辑归纳）：① **行为稀疏**——用户关注行为远少于内容点击，作者-作者共现矩阵极稀疏，itemCF 难以支撑 I2I，而图嵌入把「序列/图结构」转成稠密向量，天然补泛化；② **异构关系丰富**——关注关系（用户-作者）、互动行为（点赞/完播）、社交关系（一度/二度好友）可统一成异构图，Node2vec/MetaPath2Vec 能分别刻画「同社区相似」与「结构相似」，并引入 sideinfo 缓解冷启动；③ **长尾覆盖**——graph emb 一期直接把发现好友页 pctr 拉 +11%~+14%，说明图结构信号对「猜你喜欢哪个作者」增益显著；④ **可解释与可迭代**——w2v 范式工程简单、可快速 A/B，验证有效后再上复杂模型，符合算法落地节奏。

## 3. 召回链路（重点）

整体架构：**显式召回（规则/画像/热门兜底）+ 隐式召回（图嵌入/embedding I2I）** 多路并行，分层 quota 混排。

### 3.1.2 整体推荐链路架构（召回→打分→重排→下发）
账号推荐线上链路（据 `好友达人梳理（总）` 与 `混排策略逻辑梳理` 还原）：

```
多路召回(并行)
  ├─ 好友召回：一度/二度/实时(新用户)  → BDB 加载
  ├─ 显式达人召回：兴趣画像热门 / UGC45 / 热门兜底 / 好友关注 / 外部画像
  └─ 隐式召回：w2v / DeepWalk / Line / Node2vec 图嵌入 I2I
        ↓  layer_policy 分层 quota (1:0.5 / 2:0.3 / 3:0.2)
排序打分(LR / 规则 / 中台DNN进行中)
        ↓
重排
  ├─ 初始化(场景/用户/隐私/队列拆分 好友队列+达人队列)
  ├─ 过滤(Pre_filter：屏蔽/黑名单/隐私/作品数/跨刷去重)
  ├─ 升降权(扶持提权 / 好友单向关注提权 / 曝光降权 score*exp(-0.1*count))
  ├─ 达人推荐 E&E(类目维度 Thompson Sampling → Top16 类目)
  ├─ 分数调整(rand_score 增随机性)
  └─ 策略重排(三次排序 + 品类强间隔 + 关注倾向配比)
        ↓
下发(推人卡片：消息页/关注页/个人主页/发现好友页)
```

### 3.3 隐式召回（图嵌入 / embedding I2I）——简历「图嵌入召回」出处
| 召回方式 | 状态 | 构图与训练要点 | 源 |
| --- | --- | --- | --- |
| **w2v 达人召回**（点赞序列） | 已全量 | 用户→达人**点赞序列** → word2vec → 达人隐式向量 → 种子用户(已关注/感兴趣) I2I 召回 | wiki 4.3.1（0507 推全 Review） |
| **Graph Embedding DeepWalk** 达人相似 | 已全量 | **推荐页用户→达人正向行为数据 → DeepWalk 随机游走生成序列**（序列含作者-作者共线相似关系）→ w2v 产出达人 EMB → I2I 召回 | wiki 4.3.2（0608 实验） |
| **Graph Embedding LINE** 达人相似 | 已全量 | 视作 **BFS 构造邻域**的图嵌入，定义一阶/二阶相似性 → 同部图模型 → 达人 EMB I2I | wiki 4.3.3 |
| **Graph Embedding Node2vec** 达人相似 | 已全量 | **用户关注关系建异构图，用户→达人的关注关系连边**；引入超参 **P、Q 控制 DFS/BFS 采样** → w2v 产出用户+达人向量 → 达人向量 I2I | wiki 4.3.4（0701 全量） |
| **MetaPath2Vec** 达人相似 | 实现中 | 异质网络，按**元路径（metapath）**游走（如 作者-论文-期刊 型）；引入达人 sideinfo（一二级发文垂直度）解决**作者冷启动**（粉丝少/VV少训练不充分） | wiki 4.3.5 |
| **DSSM** 达人相似 | 规划中 | 用户侧塔（近N条完播/互动达人序列+基础信息）与 item 侧塔（达人数据）双塔 | wiki 4.3.6 |

**图嵌入关键事实（原文明确写到的）**：
- 方法栈：**DeepWalk → Line → Node2vec**，均为「随机游走生成序列 + word2vec 训练向量 + I2I 召回」范式。
- 两种构图视角并存：① 推荐页**正向行为序列**（DeepWalk/Line，作者-作者共线）；② **关注关系异构图**（Node2vec，用户-达人连边）。
- 随机游走参数参考（来自同文档集 graph embedding 实验，doc-query 异构图）：**随机游走步长=5**，1879018 个 doc-query 对 → 生成 **10678660 条路径**。⚠️该参数为 doc-query 实验记录，非账号推荐图的直接参数，仅作同方法论参考（源：`09_内部资料` graph embedding 实验段，含 metapath2vec 描述）。
- 线上召回配置（图隐式达人召回）：`ws_daren_graph_emb_recmd`，`retnum=200, source_id=15004, topN_author=20, author_type_name=follow_author`。（源：[[01_微视/达人召回梳理.doc]]、[[09_内部资料/微视账号推荐/达人召回梳理.doc]]）

### 3.4 好友召回（社交关系链）
- **一度好友** = QQ好友 + 微信好友汇总；**二度好友** = 好友的好友。
- 存储截断：**一度 ≤ 150 个**（按共同好友数截断）、**二度 ≤ 100 个**，均要求**30天内活跃**。
- 更新频率：一度好友**天级**离线更新；二度好友因资源限制**周级**更新；出库至 BDB，线上调用 BDB 召回。
- **线上召回逻辑**：从 BDB 加载用户的一度/二度好友；**若好友已关注你，则推人理由为「该好友已关注你」，否则为「你的好友」**。（源：`01_微视/当前好友链路数据梳理` 2.线上好友召回逻辑）
- 亲密度两种算法：① 显示统计（共同好友数/共同关注好友数等融合公式）；② **图学习**（构造好友沟通网络：关注/消费/互动连边 → 图算法得用户 EMB → 向量相似度作为亲密度）。
- 离线产物字段格式：`(friend_id:好友类型:共同好友数:亲密度:pid是否关注好友:好友是否关注pid:关注的共同好友数量:好友来源:item与user已关注的人是好友的数量)`。（源：wiki 3.3）

### 3.6 多路召回如何混排（分层 quota + 关注倾向）
- 配置示例（layer_policy）：`1:15004@13804@14113@13996@13801; 2:14998@13997; 3:13010@13008@13007@13001@13004`
  - 层1（隐式/个性化）：图嵌入15004、embedding13804、个性化CF14113、实时关注13996、行为召回13801
  - 层2（画像/社交）：外部画像14998、好友关注13997
  - 层3（好友）：13010/13008/13007/13001/13004

### 3.7 召回分层 quota 解读（为什么这么分）
源：`01_微视/混排策略逻辑梳理`、`达人召回梳理`。配置 `layer_policy: 1:15004@13804@14113@13996@13801; 2:14998@13997; 3:13010@13008@13007@13001@13004`，`rule_layer=0.5;0.3;0.2`。

- **层1（权重0.5，个性化/隐式）**：图嵌入(15004)、行为embedding(13804)、个性化CF(14113)、实时关注(13996)、互动播放行为(13801)。承担最主要的「猜你喜欢」个性化召回，占比最高。
- **层2（权重0.3，社交/画像）**：外部画像(14998)、好友关注(13997)。用社交关系与跨产品画像补充个性化信号。
- **层3（权重0.2，好友关系链）**：新用户实时一/二度(13008/13007)、一度(13001)、二度(13004)。社交关系链召回，强信任背书、转化高但候选窄，给固定小比例保底。
- 设计意图：**隐式图嵌入为主、社交关系为辅、好友关系保底**，既保证个性化召回的覆盖面，又用社交信任拉高关注转化，多层 quota 防止任一路独大。

### 4.1.2 模型训练与上线部署（原文可溯）
- **LR 离线训练**：离线拼接特征样本、特征分桶，LR 训练，权重上传**共享内存**供在线预测（源：wiki 5.1）。
- **中台 DNN（进行中）**：小时级更新各场景离线曝光点击数据；模型部署到 **taf**，以 taf 服务对外提供（源：wiki 5.4）。
- **样本定义（好友 LR）**：近 7 天数据；正样本=关注、查看主页；负样本=有曝光未点击 Item；正负比 **1:10**（源：排序模型梳理 / wiki 5.2）。
- **负样本下采样**：达人 LR **1:5**、好友 LR **1:10**（缓解关注行为稀疏、正负不均衡，源：wiki 5.1/5.2）。

### 4.1.3 为什么排序先上 LR 而非直接深度模型
⚠️面试可发散（基于原文迭代脉络推断）：账号推荐反馈极稀疏、可解释性要求高（需向运营/产品解释为什么推这个人），LR + 分桶特征上手快、可解释、易排查；在 graph emb 召回已验证收益后，再推进中台多目标 DNN 统一建模（wiki 5.4 进行中），是「先验证链路、再上复杂模型」的稳妥路径。

### 3.8 图嵌入工程实现（平台与流程，原文可溯）

### 4.2 重排模块（简历「Thompson Sampling 重排」出处——原文还原）

重排 = **队列准备 → 过滤策略 → 升降权策略 → 混排/多样性打散**。（源：`账号推荐项目wiki.md` 6；`01_微视/混排策略逻辑梳理`）

#### 4.2.1 过滤与升降权（原文明确）
- **过滤**：特定账号过滤、隐私权限过滤、作品数量限制、跨刷去重。
- **提权**：特定扶持账号（45级UGC、运营账号）；好友单向关注用户提权（促双向关注）。
- **曝光降权（隐形负反馈）**：通过 Redis 取用户 Item 维度曝光数据，**降权公式 `score = score * exp(-0.1 * count)`**。（源：`01_微视/混排策略逻辑梳理` 曝光降权段）

#### 4.2.2 Thompson Sampling 在原文中的两处真实落点
原文**未出现「Thompson Sampling 重排」这一整句**，但有两处确凿使用（译名「汤姆森采样」= Thompson Sampling）：

1. **达人推荐的 E&E 策略（重排层，类目多样性探索）**
   - 原文：「策略说明：增加达人品类多样性；**1. 根据类目维度进行 Thompson Sampling 采样**；2. TS得分倒排后，选取最多16个类目的相应视频进入后续流程。」（源：`01_微视/混排策略逻辑梳理` 重排模块「达人推荐的E&E策略」段）
   - 含义：在**类目（category）维度**做 TS 采样决定曝光哪些品类，扩大品类多样性，倒排取 Top-16 类目进入后续。
2. **老用户低频兴趣 boost（兴趣探索提权）**
   - 原文：「老用户低频兴趣boost（**提权幅度依据汤姆森采样得分来计算**）」（源：[[01_微视/关注作者兴趣&兴趣探索boost&搜索承接优化.doc]] 4.2 段）
   - 配合：「新用户随机探索boost」（同段）。

#### 4.2.3 ⚠️ 关于 TS 参数的重要诚实声明（面试必读）
- **原文只记录了「在什么层面用 TS、怎么用」（类目维度采样→Top16；低频兴趣 boost 幅度由 TS 得分定），并没有记录 Beta 先验/后验的具体数值、更新公式、或为何选 TS 而非 UCB/ε-greedy 的论证。**
- 因此：本档案**不编造** Beta 参数。若面试官深挖「先验怎么设、怎么更新」，正确做法是先讲清楚上面的**真实机制**，再说明生产实现是「以类目为 arm 的 Beta-Bernoulli 框架、成功事件=该类目作者的关注/点击反馈」，具体超参为线上配置（可诚实表示「精确先验数值当时以线上配置为准，未固化在笔记中」）。
- 简历「Thompson Sampling 重排」与原文两处 TS 落点的对应关系，建议面试统一口径：**重排的 EE/多样性探索即由类目维度 TS 采样 + 低频兴趣 TS 提权实现**，与简历表述一致。

#### 4.2.4 多样性打散与关注倾向配比（保证多样性，原文）
- **账号推荐多样性规则打散**：达人按**一级发文品类 + 二级发文品类强间隔**排序；**好友不打散**；最后按关注倾向决定优先达人还是好友。
  - 例：「一次请求推荐10个账号，用户过去关注达人倾向为0.6，则优先出6个达人账号，再出4个好友账号」。（源：wiki 6.4）
- 重排三次排序：① 按 layer_num + rerank_score（layer 越小越靠前）；② 多样性队列与原候选队列拼接；③ 分层 quota、品类数量限制、品类维度间隔打散（间隔≥1）。（源：`01_微视/混排策略逻辑梳理` 策略重排段）
- 分数调整：给得分赋 `rand_score` 增加随机性（探索）。（同段）
- 有作品作者顺序调整（swap_item）：针对好友，将3个有视频的好友前置。（同段）

---

#### 4.2.5 EE、多样性、曝光降权的协同（原文事实串联）
重排层的三件事其实是一个闭环（均来自 `01_微视/混排策略逻辑梳理` 与 wiki 6.4）：
1. **探索（EE）**：类目维度 Thompson Sampling，TS 得分倒排取 Top16 类目进入后续——决定「推哪些品类」，扩宽候选面；
2. **多样性约束**：达人按一/二级品类**强间隔**（好友不打散）——决定「同屏不扎堆」，防推荐黑洞；
3. **利用纠偏（曝光降权）**：`score = score * exp(-0.1*count)`——对已高曝光却低转化的 item 惩罚，把坑位让给未充分曝光的候选。
三者配合：EE 负责「敢推新的」，强间隔负责「铺得开」，曝光降权负责「不重复烦你」，共同在保证关注率的同时守住体验。老用户低频兴趣的 TS 提权 boost、新用户随机 boost 则在前述框架上叠加个性化探索。

### 6.4 指标口径与评估易错点
源：`好友推荐指标建设.doc`、`各种emb实验.doc`。面试/复盘时最易踩的坑：
- **两种 ctr 不可混用**：关注 ctr = 点击关注数 / 曝光卡片数（`maylike.headpic.focus`）；而 graph emb 实验的 pctr/uctr 是「头像点击」口径（`maylike.headpic`），二者分母分子都不同，横向对比必须标注口径。
- **分场景拆分**：实验用户数、曝光卡片数、关注用户数均按「全场景/分场景」拆分；消息页/关注页/个人主页/发现好友页的渗透与形态不同，汇总指标会掩盖单场景退化（如关注页受改版下跌）。
- **关注率 vs 人均关注**：关注率是比率指标，人均关注数是绝对量；量级增长时二者可能背离，需同时看。
- **uctr 比 pctr 更抗噪**：pctr 对单次曝光敏感，uctr（用户级）更能反映「触达了多少人」，graph emb 消息页 pctr 略负但 uctr +3% 即此例。

## 8. 踩过的坑与解法（面试加分项）

| 坑 | 现象/原因 | 解法 | 源 |
| --- | --- | --- | --- |
| 兴趣探索频率过低，画像难沉淀 | 末尾强插只插1位，其他兴趣点无曝光 | 将低频/随机兴趣探索**从强插下沉为 boost**，保留搜索/外部画像/热点承接的强插 | `关注作者兴趣&兴趣探索boost` 4.2 |
| 探索硬伤体验 | 强插=强制曝光，易被用户感知为打扰 | 改用 boost（提权软探索）；老用户低频兴趣 boost 幅度由 TS 得分定，新用户随机 boost | 同上 |
| 推荐精准→推荐黑洞 | 精准但陷入同质，需长期收益 | 重排层多样性打散 + 隐形负反馈控打散力度；类目强间隔 | wiki 6.4 / `07_答辩04` 多样性策略 |
| 关注页改版致数据下跌 | 关注页推人卡片 7月 vs 4月下跌（受改版影响） | 关注页渗透率约20%，需结合改版口径看数 | wiki 1.2.2 |
| 二度好友资源受限 | 二度好友计算资源大 | 二度好友**周级**更新（一度天级） | wiki 3.2 |
| 新作者训练不充分 | 粉丝少/VV少，向量冷启动差 | MetaPath2Vec 引入 sideinfo（发文垂直度） | wiki 4.3.5 |
| 数据可溯性不足 | 推人信息未落 recommend_id，用 test_id | 后续固化需落 recommend_id | `好友推荐指标建设.doc` |
| 曝光但未点/未关注 | 高曝光低转化 item 占坑 | 曝光降权 `score*exp(-0.1*count)` | `01_微视/混排策略逻辑梳理` |
| 画像召回覆盖率 vs 准确性矛盾 | embedding 召回限制一级类目提准确但降覆盖 | 按场景需求灵活折中（不强制限制类目） | `好友达人梳理（总）` |
| 类目多样性不足 | 易反复推同类目作者 | 类目维度 TS 采样（Top16）+ 一级/二级品类强间隔 | `01_微视/混排策略逻辑梳理` |

> 复盘规律：账号推荐链路里**召回决定天花板、重排决定体验下限**。graph emb 解决「找得对」，强插→boost、品类强间隔、曝光降权解决「推得不烦、推得开」；二者缺一都会让关注率收益打折。

### 8.1 召回质量评估要点（原文可溯）
- **覆盖率 vs 准确性折中**：基于用户行为的达人 embedding 召回，限制一级类目可提准确性但降覆盖率，需按场景灵活折中（源：`好友达人梳理（总）`）。
- **类目采样多样性**：graph emb 一期验证有效后，仍要靠重排的类目 TS 采样 + 强间隔防同质。
- **好友链路数据质量**：一度天级、二度周级更新；二度好友线上曾「无数据」（源：`达人召回梳理` 注释），需确认数据产出再放量。

## 9. 面试 Q&A（第一人称口述，≥12 组）

> 标注「⚠️面试可发散」= 原文未写、用于补全逻辑，请结合自身真实经历使用；其余均可从原文溯源。

**Q1：你这个账号推荐，为什么用图嵌入而不用 itemCF？**
A：账号推荐里作者-作者共现极稀疏，纯 itemCF 只能靠已有共点/共关关系，覆盖和泛化都有限。我们用图嵌入（DeepWalk/Line/Node2vec）从「推荐页正向行为序列」和「用户-作者关注异构图」里随机游走生成序列，再用 word2vec 产出作者向量做 I2I 召回，能把行为稀少的作者也学到稠密向量，泛化远好于 itemCF。这也是为什么 graph emb 一期在发现好友页把 pctr 拉了 +11%~+14%。

**Q2：图嵌入具体怎么构图？正样本、随机游走参数怎么设？**
A：两条构图主线。一是推荐页用户对达人的正向行为序列直接当"句子"，DeepWalk/Line 游走产出作者向量；二是用**关注关系建异构图**，用户到作者连边，Node2vec 用 P/Q 控制 DFS/BFS 偏向。游走后就是 word2vec 标准训练。随机游走步长我们同方法论实验里用过步长=5（doc-query 异构图：187万对→1067万条路径作参考）。⚠️面试可发散：实际账号图的具体步长/窗口当时按线上效果调参，笔记未固化精确值。

**Q3：为什么是 DeepWalk→Line→Node2vec 三件套，而不是只上一个？**
A：它们是同范式的渐进：DeepWalk 最简单直接验证有效；LINE 显式建模一阶/二阶相似，对复杂图结构更稳；Node2vec 用 P/Q 兼顾 DFS/BFS，能平衡"同圈子相似"和"结构相似"。三者在账号推荐场景都全量了，相当于多路隐式召回互补。

**Q4：简历写「Thompson Sampling 重排」，具体怎么做探索与利用？**
A：重排的 EE 我落地在两层：① **类目维度 TS 采样**做多样性探索——对各品类做 Thompson Sampling，TS 得分倒排后取最多 16 个类目的作者进入后续，避免只推用户已偏好的少数品类；② **老用户低频兴趣 boost**——提权幅度直接由汤姆森（Thompson）采样得分计算，给长尾兴趣试探机会，新用户则用随机探索 boost。这就是简历说的"Thompson Sampling 重排"。

**Q5：TS 的先验/后验、Beta 参数你怎么设的？为什么选 TS 不选 UCB/ε-greedy？**
A（诚实版）：生产实现是「以类目为 arm 的 Beta-Bernoulli」框架，成功事件取该类目作者的关注/点击反馈来更新后验。至于精确先验数值，当时以线上配置为准，笔记没留具体数——这点我不回避。选 TS 而非 ε-greedy，是因为 ε-greedy 是盲目随机、UCB 偏乐观保守，TS 用后验采样天然在"已验证好类目"和"不确定类目"间做概率配比，更适合我们要"扩品类又不伤体验"的目标。⚠️面试可发散：若需给出示例，可说先验取弱信息 Beta(1,1)，按日反馈更新 α/β，但仍须说明这是通用做法、非原文记录。

**Q6：怎么保证探索不伤害体验？**
A：两点。一是把探索从"强插"改成"boost"——早期低频兴趣用末尾强插只插1位，既打扰又覆盖不了其他兴趣，后来下沉成提权软探索，体验更平滑；二是多样性硬约束：达人按一二级品类强间隔打散、好友不打散，再加曝光降权（高曝光低转化 item 按 `exp(-0.1*count)` 降权），避免同一作者/品类反复占坑。

**Q7：关注率和消费时长冲突怎么办？**
A：账号推荐的北极星是关注率，因为它对应关系链建联的长期价值；但只追关注率会陷入"推荐黑洞"。我们的做法是分层目标：召回/排序保相关性（时长、VV），重排层专门做多样性与 EE 来保关注率与长期留存，二者在链路不同阶段各司其职，不硬trade-off。⚠️面试可发散：可补"关注后留存""关注后消费时长"作为长期指标，原文指标建设以关注率/ctr为主。

**Q8：新作者冷启动怎么解？**
A：作者粉丝少、VV少，行为序列训练不充分，向量冷启动差。我们用 MetaPath2Vec，在异质网络里按元路径游走并引入作者 sideinfo（一二级发文垂直度）一起训练，把内容属性补进向量，缓解冷启动。同时显式召回里有扶持45级UGC作者的通道，给新作者基础曝光。

**Q9：新用户怎么推？**
A：新用户画像不稳，好友侧直接走规则 `0.7×共同好友得分 + 0.3×活跃得分`，并开新用户实时一/二度好友召回（retnum 100/200）；达人侧用外部画像召回、热门兜底，避免模型打分不准。

**Q10：多路召回怎么混排？**
A：用分层 quota 机制，配置如 `layer_policy: 1:图嵌入@embedding@CF@实时关注@行为; 2:外部画像@好友关注; 3:好友`，`rule_layer=0.5;0.3;0.2` 控各层比例；再用品类限制（同目最多2次）、多样性规则、关注倾向配比（按用户历史关注达人/好友倾向决定优先出谁，比如倾向0.6就先出6个达人再4个好友）做最终混排。

**Q11：多样性具体怎么做？**
A：账号推荐层面——达人按一级+二级发文品类**强间隔**排序，好友不打散；重排三次排序里专门有"品类维度间隔打散（间隔≥1）"和分层 quota。再叠加类目 TS 采样扩品类。这是从"精准但同质"的坑里总结出来的。

**Q12：你的模型效果怎么量化？**
A：排序 LR 训练/测试 AUC 0.81/0.80；graph emb 一期10%流量、发现好友页 pctr +11.19%/uctr +6.29%，26-29号拉到 pctr +14.22%；切换45级达人池整体关注率 +5.3%（6天稳定）。日新增关注日均190w、峰值230w。

**Q13：指标怎么分桶评估，口径注意什么？**
A：以 `position='maylike.headpic'`（曝光）和 `'maylike.headpic.focus'`（关注）落日志，按 qimei 去重算实验用户数、曝光卡片数、点击关注数，关注 ctr=点击关注数/曝光卡片数，关注 uctr=关注用户数/实验用户数，全场景/分场景拆分。注意 graph emb 实验的 pctr/uctr 是头像点击口径，和关注 ctr/uctr 不是一回事，汇报时要分清。

**Q14：好友召回的「推人理由」怎么来的？**
A：线上从 BDB 加载用户的一度/二度好友，如果某好友已经关注了你，推人理由就写"该好友已关注你"，否则就是"你的好友"。一度好友天级更新、二度周级（资源限制），均限制30天活跃并按共同好友数截断（一度≤150、二度≤100）。亲密度除了统计融合（共同好友/共同关注），还用图学习（好友沟通网络连边→EMB相似度）算。

**Q15：如果重做一遍，你会改进什么？**
A：① 指标可溯性——早期推人信息没落 recommend_id 只用 test_id，复盘不便；② 中台 DNN 多目标已在做，应把"关注/点击/时长"多目标统一建模而非分场景 LR；③ EE 的 TS 后验应固化监控，把"探索带来长期关注留存"量化出来，而不仅看即时关注率。

## 12. 高频追问速答（短答版，临场用）

> 以下为面试官最可能深挖的点，按「一句话能接住」的粒度准备。标注⚠️的为面试发散，需结合本人真实经历。

1. **为何不直接上 DNN 双塔做召回？** 早期样本与算力有限，图嵌入+w2v 工程简单、可解释、迭代快，先验证「隐式 I2I 召回」有效（graph emb 一期直接 +11%~+14% pctr）再升级。
2. **图嵌入 vs itemCF 一句话？** itemCF 靠共现、覆盖差；图嵌入把行为转序列做表示学习，泛化到稀疏/新作者。
3. **Node2vec 的 P、Q 怎么理解？** P 控制回到上一节点概率（偏向 BFS/同社区），Q 控制向外探索概率（偏向 DFS/结构相似）；我们按场景调 P/Q 平衡。
4. **TS 在你们项目里到底采什么？** 采「类目」这个 arm（重排多样性探索）和「低频兴趣」的提权幅度（老用户探索），不是对单个作者做 TS。
5. **Beta 先验在哪？** ⚠️原文未固化数值；落地是类目级 Beta-Bernoulli，成功事件=该类目作者的关注/点击。被追问就如实说"线上配置、笔记未留"。
6. **为什么不直接强插探索？** 强插只插1位、覆盖窄且打扰明显；改为 boost 软探索，体验平滑、覆盖更广。
7. **关注率和时长怎么权衡？** 召回/排序保相关性（时长/VV），重排专门做多样性+EE 保关注率，分层不硬 trade-off。
8. **新用户没行为怎么办？** 好友走规则 `0.7×共同好友+0.3×活跃`，并开实时一/二度好友召回；达人侧用外部画像+热门兜底。
9. **新作者没向量怎么办？** MetaPath2Vec 引入 sideinfo（发文垂直度）训练，缓冷启动；显式召回给45级UGC扶持曝光。
10. **多样性为什么用强间隔？** 防同类目作者扎堆、防推荐黑洞；一级+二级品类强间隔，好友不打散，再叠加类目 TS 采样扩品类。
11. **曝光降权为什么用 exp(-0.1*count)？** 对高曝光低转化的 item 平滑衰减，系数 0.1 是线上经验值（⚠️若问调参可说按曝光-转化衰减曲线估）。
12. **指标口径最易踩的坑？** graph emb 实验的 pctr/uctr 是「头像点击」口径，和「关注 ctr/uctr」不是一回事，汇报务必分清。
13. **怎么证明 EE 没伤体验？** 看 uctr 而非仅 pctr：消息页 pctr 略负但 uctr 仍 +3%，说明点击用户覆盖没降；且探索改成 boost 后体感更平滑。
14. **如果重做？** 落 recommend_id 做可溯性；中台多目标 DNN 统一建模；把 TS 后验监控起来量化探索的长期留存收益。

## 13. 一页纸速记（面试前 5 分钟过一遍）

- **业务**：微视账号推荐（推荐你关注哪些作者）= 社交线关系建联第一环，北极星=关注率，目标提升关注率→消费与留存。
- **召回**：显式（兴趣画像热门/UGC45/热门兜底/好友关注/外部画像）+ 隐式（w2v / **DeepWalk / Line / Node2vec 图嵌入** I2I）。基础池=粉丝>1000+45级+运营优质（V1号池5000+：45级1000+、官方300+、graphemb top5增扩）。好友=一度≤150/二度≤100（30天活跃，一度天级/二度周级）。
- **排序**：达人 LR（AUC 0.81/0.80，负采样1:5）/ 好友 LR（1:10）/ 新用户规则 `0.7×共同好友+0.3×活跃`；中台多目标 DNN 进行中。
- **重排/EE**：过滤→升降权（扶持提权、好友单向提权、**曝光降权 score*exp(-0.1*count)**）→ **类目维度 Thompson Sampling（取 Top16 类目）** + 老用户低频兴趣 TS 提权 boost / 新用户随机 boost → 品类强间隔打散 + 关注倾向配比（达人倾向0.6→先6达人后4好友）。
- **冷启动**：MetaPath2Vec+sideinfo（作者）、规则+实时好友（用户）、强插改 boost（兴趣）。
- **指标**：关注率=点击关注数/曝光卡片数；关注uctr=关注用户数/实验用户数；分场景评估。
- **收益（严禁改动）**：整体关注率 **+5.3%**（切45级达人池，6天）；graph emb 一期发现好友页 pctr **+11.19%**/uctr **+6.29%**，26-29号 pctr **+14.22%**；日新增关注 **190w/峰值230w**。
- **红线**：TS 的 Beta 先验数值原文**未记录**，被追问如实说"线上配置、笔记未固化"，绝不编造。
