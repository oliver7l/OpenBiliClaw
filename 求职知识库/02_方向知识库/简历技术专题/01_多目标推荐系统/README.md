# 专题 · 多目标推荐系统（Multi-objective / Multi-task Recommendation）

> 最后更新：2026-09-09
> 简历落点：QQ看点图集（ESMM/MMoE）、腾讯微视（DEN / 多目标融合 / 贝叶斯调参）、OPPO 广告多位置校准兜底。
> 主线话术：**点击、时长、互动、转化四个指标互相打架 → 从单目标升级到 ESMM → MMoE → 多目标召回下沉的全链路**，不是单一模型，而是一套"多目标建模方法论"。

---

## 一、一句话定位（自我介绍/被追问开场）

> "我做过从单目标到多目标的全链路升级：精排侧先上 ESMM 解决转化稀疏，再上 MMoE 同时优化时长与互动，把手头的曝光/点击/转化/时长统一到一致的样本空间做多目标建模，最后把多目标信号下沉到召回侧。这是一套可复用的方法论，不绑定某个具体模型，迁移到电商、广告、内容任何多指标优化场景都成立。"

### 三个最硬的数字（按简历口径背）
- 大盘**累积时长 +0.42%**、**互动 +35%**、**短内容浮层时长 +6.8%**
- **多目标召回下沉 → 进评论率 +80%**
- 微视方向（若被问）：DEN 人均时长 +2.33%、UTR +1.71%

## 二、核心原理（讲清楚"为什么难"）

### 2.1 为什么需要多目标（痛点）
- 单一点击率目标 → **标题党**占便宜：点进去不看、互动差、时长和留存受损。
- 四目标互相打架：
  - 点击率高的内容 → 时长短（猎奇标题）
  - 互动高的内容 → 曝光少（长尾）
  - 转化样本 → 极其稀疏，难以独立建模

### 2.2 样本空间不一致（多目标最大的坑）
- 各目标天然不在同一样本空间：点击在「曝光」上定义，转化在「点击后」定义，时长在「点击播放」上定义。
- **不统一样本空间** = 各塔在错误的分布上学，服务时又拼在一起 → 选择偏差。
- **解法**：统一到曝光层，用乘法关系拆解稀疏目标。

### 2.3 三个主流多任务范式对比
| 模型 | 机制 | 适用 | 弱点 |
|---|---|---|---|
| **Shared-Bottom** | 全部任务共享底层专家 | 任务高度相关 | 冲突任务互相干扰 |
| **MMoE** | 多个 Expert + 任务级 Gate 软共享 | 任务相关但存在冲突（工业最常用） | Expert 数需调、Gate 可能坍缩 |
| **ESMM** | 共享底层 + 双子网络，pCTCVR=pCTR×pCVR，统一到曝光空间 | 转化稀疏 + 有明确漏斗关系 | 只解决漏斗类目标，多平级目标不适用 |
| **DBMTL** | 贝叶斯网络建模任务间依赖 | 任务有因果链（点击→时长） | 结构复杂，浅层目标可能负向 |
| **DEN / Muti-gated DEN** | Engagement Network + Multi-Head Attention；Muti-gated 加 Side Info + 多门控 | 长视频、内容消费 | 训练耗时高，长尾泛化要调 |

### 2.4 目标选型三原则（被问"为什么选这几个目标"）
1. **不能太稀疏**：正例过少模型学不动（转化单目标难）→ 用 ESMM 借点击信号。
2. **目标间不能冗余**：高度相关目标相互收割样本量，承载的信息量小。
3. **行为可观测**：拿得到真实因果信号，避免 proxy 噪声。

### 5.3 你的 3 个差异化亮点（把"我的"讲成优势）
1. **ESMM+MMoE 分层打，不混用**：转化稀疏用 ESMM（结构化漏斗），时长/互动平级冲突用 MMoE——按"目标关系"分场景选结构，比"一把梭"更懂取舍。业界很多是单模型硬扛。
2. **从精排下沉到召回**：多目标信号不只停在精排，还下沉到召回侧让候选质量也按多目标优化（进评论率+80%）——业界多在精排做，端到端下沉是加分点。
3. **落到长期价值而不是只追短期指标**：北极星对到大盘时长/DAU/留存，权重视业务北极星反推，不是拍脑袋。

### 5.4 大模型时代（意识到前沿，讲"趋势"防被问）
- 近年多目标从"交互驱动 next-item"走向 LLM 范式：
  - **SIGMA**（阿里 2026，SIGIR）：语义接地 + 指令驱动的生成式多任务推荐，一个模型听指令完成 CTR/CVR/搜索等多样任务。
  - **MDL**（字节 2026）：把 feature/scenario/task 统一 token 化做多分布学习，已上抖音搜索。
  - **HA-MoE**：异构异质 feed 用显式上下文改造门控，避免多数派偏差/负迁移。
- **一句话定位自己**："多目标建模的下一个瓶颈是'多目标×多场景×LLM'的统一——我的 ESMM/MMoE/DEN 是经典时代的地基，转型时结构理解（共享/差异化/跷跷板）是最硬的能力，LLM 是新瓶装（新范式）旧酒（仍是多任务联合优化）。"

## 三、实战弹药（STAR，三选一按岗位）

### 方案A · 看点图集 ESMM → MMoE（内容/信息流岗首选）
- **S**：图集和短内容是看点核心消费场景，早期只用点击率单目标，标题党泛滥、时长互动差，四个指标互相打架。
- **T**：北极星=大盘累积时长、广义DAU、DAU留存；过程=短内容浮层时长、篇均时长、互动。
- **A**（演进路线）：
  ```
  单目标LR → 多召回+粗排 → DCN精排 → 图集点击+转化 ESMM
          → 短内容浮层 MMoE（时长+互动）→ 无量3.0 全量上线 → 多目标召回下沉
  ```
  - ESMM：两个共享底座塔（pCTCVR 塔 + pCTR 塔），样本空间统一到曝光层，pCTCVR=pCTR×pCVR 拆解稀疏转化（转化正负比 1:27）
  - MMoE：多专家多门控，同时优化时长+互动，成为 **BG 第一个在无量3.0全量上线多目标的业务**
  - 多目标下沉召回：候选集质量按多目标优化
- **R**：大盘时长 +0.42%、互动 +35%、浮层时长 +6.8%、多目标召回进评论率 +80%；方案推广到小说/短内容新品类，沉淀为品类推荐中台，被腾讯网、全民K歌等多个业务借鉴。

### 方案B · 微视 DEN 深度参与度网络（长视频岗）
- **S**：长视频推荐基线 DNN 有三大缺陷——无法捕捉中长期兴趣（只取最近20个cid）、没利用播放进度等参与度信号（只看是否点击）、忽略时序性。
- **A**：自研 DEN = Engagement Network 建模兴趣强度 + Target-Aware Multi-Head Attention 捕捉多峰兴趣；演进到 Muti-gated DEN 加 Side Info + 多门控解长尾泛化。
- **R**：人均时长 +2.33%、UTR +1.71%。
- 细节：见 `02_方向知识库/推荐系统/05_多目标与多任务.md`。

### 方案C · 多目标权重自动调参（体现工程方法论）
- MMoE 各目标 loss 权重靠手调费事 → **贝叶斯优化自动搜参**，目标融合分数可学习。

## 四、八股 QA（被追问）

**Q1：ESMM 为什么能解决样本选择偏差？**
A：把 pCVR 的训练从「点击后样本」改为「曝光层样本」，用 pCTCVR=pCTR×pCVR 的乘法关系 + 两个塔共享 embedding，在曝光分布上间接学习 pCVR，避免只在高点击人群上学产生选择偏差。

**Q2：MMoE 和 ESMM 什么时候用哪个？**
A：有明确漏斗关系（点击→转化）、转化稀疏 → ESMM；多平级业务目标（时长 vs 互动）且互相冲突 → MMoE。二者不互斥，图集里转化用 ESMM、浮层时长+互动用 MMoE。

**Q3：多目标怎么融合成一个分？**
A：加权和（权重可自动调/贝叶斯搜索）+ 必要时做约束（保量、曝光分配）。权重不是拍脑袋，要看业务北极星反推。

**Q4：DEN 和 MMoE 区别？**
A：MMoE 是通用多任务结构（Expert+Gate），DEN 是针对内容消费的兴趣网络（Engagement+Attention），一个管"任务间共享、冲突平衡"，一个管"兴趣强度建模"。

**Q5（微视版）：为什么基线只用最近20个cid不行？**
A：活跃用户播放历史覆盖长周期，只看 20 条中长期兴趣丢失；且没到时序，先看喜剧再看悬疑 vs 相反，当前兴趣不同。
