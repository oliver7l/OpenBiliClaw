# 专题 · 多场景统一建模 & 多目标多场景（Multi-Scenario Unified Modeling）

> 最后更新：2026-09-09
> 简历落点：OPPO 广告**多位置校准**（首页Banner/详情页/搜索/推荐流多展示位，全场景统一样本+多目标自适应）、腾讯**信息流场景迁移学习**、**微视场景化推人** / **UGC 多品类浮层主 Feeds**。
> 主线话术：**不同场景（推荐位置/品类/页面）点击分布天然差异大 + 小场景数据稀疏 → 用统一的多任务/多场景结构共享底层、场景专属差异建模，避免"各自训练浪费数据 + 一个模型被大场景带偏"。**
> 关联：**多目标多场景**是本主题的进阶——当"多个场景"被拆成多个目标视角，就用多目标(MMoE)结构来吸；两者本质是同一建模问题的两面。

---

## 一、一句话定位（开场）

> "我做过多场景统一建模。同一个产品里不同场景——比如首页 Banner、详情页、搜索、推荐流，或者不同品类、不同浮层——点击率天然差一个量级，数据量也严重不均：大场景样本足、小场景稀疏。逐个场景单独训练既浪费数据、又维护多套模型；一个统一模型又会**被大场景带偏**、对小场景失准。我的做法是用统一的底层共享 + 场景专属的差异建模：共享底层学全局通用知识，场景塔/场景网络学各自偏差，小场景靠**共享 + 类似场景互借**缓解稀疏。这套思路在 OPPO 多位置校准和腾讯场景化推送上都验证过。"

### 最硬数字
- OPPO 多位置校准：CTR 预估偏差从 **30%+ → 20% 以内**，ARPU +1.04%
- 全场景统一样本/特征体系：覆盖应用商店、游戏中心、搜索等多个分发场景，多目标自适应建模

---

## 二、核心原理（讲透"为什么难"）

### 2.1 多场景建模三大痛点
1. **场景分布差异**：不同场景（位置/品类/页面）ke CTR 基准差一个量级，同一模型评估偏差大。
2. **数据稀疏不平衡**：大场景样本足、小场景稀少，小场景单独训练学不动。
3. **场景间冲突**：一个统一模型应对多场景时，被大场景主导，小场景失准（trade-off 难调）。

### 2.2 核心思想：共享 + 场景专属
```
多个场景 ──► 一个统一模型
              ├─ 共享底层（通用 / 全局知识）          ← 数据复用、缓解稀疏
              ├─ 场景塔 / 场景网络（场景专属偏差）     ← 学各场景自己的分布
              └─ 场景交互（相似场景互借 / mutual）     ← 缓解小场景训练不足
```

### 2.3 主流模型族（按"如何建模场景"分类）
| 模型 | 核心机制 | 场景处理方式 | 特点 |
|---|---|---|---|
| **Shared-Embedding + 场景塔**（多位置校准范式） | 统一特征共享 + 每位置独立校准因子(Isotonic/Platt) | 校准层解场景偏差 | 轻量、成熟，工程稳 |
| **BMM (Bias-Mask-MMoE)** | **把每个小场景点击行为当成一个独立目标 → 多场景=多目标 → 用 MMoE 结构**；场景独立塔*mask 合并为 batch 级 mask-logistic；再加场景偏差网络(bias-ctr)刻画 sign/position | 场景当目标 | **多目标多场景的关键桥** |
| **SAML**（阿里） | embedding+attention 映射到全局/场景特定子空间；辅助网络建模共享知识 + 多分支建模差异 + **mutual unit 自适应学场景间相似/差异** | 场景感知表示 + 场景交互 | 显式建模场景关系，缓解小场景 |
| **HC²**（阿里广告） | **对比学习做多场景**：Generalized loss 拉近"本场景+他场景同label样本"(通用知识)；Individual loss 用 dropout 正例 + 跨场景难负例(场景差异) | 对比自监督 + 场景网络 | 前沿，衔接对比学习专题 |

> **多目标多场景（核心）**：BMM 给了最直接的桥——**场景的点击目标天然互斥（同一曝光只属于一个场景），所以"多场景"可以看成"多目标"**，直接套多目标 MMoE 的多专家+门控。这是本主题和 `01_多目标推荐系统` 共享的底层。

### 2.4 三种范式（为什么统一建模优于分开/单模型）
```
范式1：各场景独立建模 ── 数据浪费 + 多套模型维护
范式2：单一模型全场景共用 ── 小场景被大场景带偏
范式3：统一共享 + 场景专属差异建模 ★ —— 共享学通用、场景学差异、互借缓解稀疏
```

## 三、实战弹药（STAR）

### 方案A · OPPO 多位置 CTR 预估校准（广告岗首选）
- **S/T**：线上不同展示位置（首页Banner/详情页/搜索/推荐流）CTR 差异大，统一模型各位置预估偏差严重（整体 30%+），影响流量分配与收入。
- **A**：
  - 统一模型输出 pCTR 基础上，为每个位置学一个**校准因子**（calibration factor）
  - 校准方法：保序回归（Isotonic Regression）或 Platt Scaling
  - **多位置联合建模**：全场景统一样本/特征体系 + 每位置独立塔/校准
- **R**：整体偏差 **30%+ → 20% 以内**，ARPU +1.04%。

### 方案B · 全场景统一样本与特征体系（OPPO，多场景多目标自适应）
- 覆盖应用商店、游戏中心、搜索等多个分发场景，统一**样本口径和特征定义**。
- **多场景多目标自适应建模**：不同场景配不同目标权重，多位置校准 + oCPX 出价联动。
- 出处：`02_方向知识库/产品化项目弹药/OPPO_广告算法全项目集.md`（§项目一/全局目标）

### 方案C · 微视场景化推人（内容/社交岗首选）
- **S**：零关注用户无法用"关注偏好"为其推荐，社交关系链冷启动难。
- **A**：把用户**按场景分层精细化**推人（新用户授权关系链→好友；未授权→兴趣达人；老用户零关注有消费→消费兴趣；无消费→热门+兴趣探索），不同场景用不同策略与召回组合。
- **理念同源**：本质是"不同场景需求不同，用场景化建模/策略差异化"。
- 出处：`02_方向知识库/产品化项目弹药/微视_个人主页与场景化推人.md`

## 四、八股 QA（被追问）

**Q1：为什么不能每个场景单独训练一个模型？**
A：数据浪费（小场景样本不足）+ 维护多套模型成本高 + 场景间隐含有共性没利用。统一建模能共享通用知识，小场景也能借大场景学到的底层。

**Q2：统一模型为什么会被大场景带偏？**
A：loss 按样本量累计，大场景样本多、梯度占比大，模型整体去拟合大场景分布，小场景的更新被淹没 → 大场景准、小场景失准。解法=共享+场景专属塔，让场景差异在专属端表达。

**Q3：多场景和多目标什么关系？（核心）**
A：关键桥是——**样本天然按场景互斥**，所以"多场景"可看作"多目标"：BMM 就是把每个场景点击当独立目标，套多目标 MMoE 的多专家+门控来共享/差异化。因此多场景建模 = 多目标建模的结构 + 场景维度的样本切分（position/sign 等偏差特征）。

**Q4：BMM（Bias-Mask-MMoE）怎么把场景变目标？**
A：场景间样本互斥(同一曝光只属一个场景)，用多个场景独立塔*mask 合并为 batch 级 mask-logistic 求 loss，线上只用 mask 兴趣塔预估分；另加场景偏差网络(sign/position 特征)刻画 bias-ctr，得到最终 pCTR。

**Q5：多位置校准除了在输出层做，还能在模型里做吗？**
A：可以——把 position 做成特征让模型学"位置偏差"（bias 建模），或用多位置联合建模每位置独立塔。输出层校准(Isotonic/Platt)更轻、快、好回滚；模型内建模更融合但训练复杂。工业常两者结合：统一模型 + 输出层每位置校准兜底。

**Q6：SAML 为什么能帮小场景？**
A：mutual unit 自适应学场景间相似性/差异性，保持当前场景主导的同时从相似场景取信息 → 小场景在大场景的帮助下收敛更稳，缓解训练不足。
