# 微视账号推荐 · 简历亮点与面试话术

> 提炼自 `微视推荐库.db`（21 篇：embedding 实验 / 账号推荐 wiki / 召回梳理 / 排序模型 / 重排策略 / 指标建设）。
> 定位：腾讯微视（2020）**账号推荐**项目——在推荐流/消息/关注/个人主页/发现好友等场景，给用户推「达人（创作者）」和「好友」，提升关注率→消费→留存。
> 一句话主线：**用 Graph Embedding 做达人相似召回、用 LR 做排序、用 Thompson Sampling 做 E&E 重排，并跑通 A/B 实验闭环**。
> 设计：定位 → 简历落点 → 核心原理 → 实战弹药（真实数字+出处）→ 八股 QA → 资料索引 → 待丰富。

## 一、一句话定位（自我介绍/项目开场用）

> 我在腾讯微视负责**账号推荐**（推人/推达人）场景的召回—排序—重排全链路，核心是用 **Graph Embedding（DeepWalk/Node2Vec）** 把达人和用户映射到向量空间做相似召回，用 **LR** 做点击/关注预估排序，在重排阶段用 **Thompson Sampling 做类目维度的 E&E（探索-利用）** 提升品类多样性，并通过 A/B 实验验证指标增益。

---

## 二、简历落点（直接抄进简历的 bullet，全部可量化）

1. **Graph Embedding 召回**：基于推荐页用户对达人的正向行为（赞/转/评/完播）和关注关系构建异构图，用 DeepWalk / LINE / Node2Vec 训练达人/用户 Embedding，落地 I2I 相似达人召回（**已全量**），并探索 MetaPath2Vec 引入 side-info 缓解达人冷启动。
2. **LR 排序模型**：以点击头像/关注为正样本、曝光未点击为负样本（下采样 1:5）训练 LR，训练 AUC 0.81 / 测试 AUC 0.80；特征覆盖用户/达人/交叉三层。
3. **Thompson Sampling E&E 重排**：在重排阶段按**类目维度**做 TS 采样，倒排后选取 Top-16 类目进入后续队列，提升推荐品类多样性。
4. **A/B 实验闭环**：
   - Graph Embedding 召回实验（10% 流量，4 天）：关注页 **pctr +10.59%**、发现好友页 **pctr +14.22%**；
   - 热门达人召回切换 45 级达人池实验（6 天稳定）：**整体关注率 +5.3%**；
   - 业务大盘（3→6 月）：人均关注数 10→12、关注中位数 0→1、关注三分位数 3→6。

> ⚠️ **口径提醒**：上方提升是**特定小流量短窗口实验期**数据（2–6 天、10–20% 流量），讲法时统一口径为「实验期相对提升」，被深挖只补「当时答辩材料口径」，勿外推成全量长期值。

## 三、核心原理（被深挖时讲清楚）

### 3.1 召回：Graph Embedding 达人相似 I2I
- **构图**：节点=达人（/用户），边=用户对达人的正向行为（赞转评完播序列）或关注关系（异构图）。
- **游走**：DeepWalk（随机游走→序列）、LINE（一阶/二阶相似 BFS）、Node2Vec（P/Q 控制 DFS/BFS，异构图产用户+达人双向量）。
- **训练**：序列喂 w2v 得 32 维 Embedding → 同一级类目内 cosine 取 Top-N 相似达人 → I2I 召回。
- **冷启动**：MetaPath2Vec 引入达人的一二级发文垂直度等 side-info 做异质网络游走，缓解低粉达人训练不充分（实现中）。
- **工程形态**：离线训练 → 出库 BDB/Redis → 线上按 `emb_rec` 召回源拉相似达人（限制一级类目可提准、降覆盖，灵活折中）。

### 3.2 排序：LR 打分
- 样本：正=点击头像/关注，负=曝光未点击；下采样 1:5；训练/测试 AUC 0.81/0.80。
- 特征：用户侧（年龄/性别/长时兴趣画像/关注数/分群）+ 达人侧（等级/粉丝/发文倾向类目/近期涨粉）+ 交叉（性别×类目、长时兴趣×发文类目等）。
- 好友排序同思路（共同好友数、关系链类型、微信/QQ 好友等交叉特征），新用户用规则打分（0.7×共同好友 + 0.3×活跃）。

### 3.3 重排：Thompson Sampling E&E
- **问题**：贪心按分数排序会让头部类目霸屏、品类单一。
- **做法**：在类目维度上对每个类目维护一个 Beta 后验（点击/曝光），用 **Thompson Sampling** 采样类目得分并倒排，选取最多 16 个类目进入后续队列 → 提升多样性。
- **配套**：曝光降权 `score × exp(-0.1×count)`、分层 quota、类目间隔打散、达人与好友按关注倾向混排（如关注达人倾向 0.6 → 10 个坑位出 6 达人 4 好友）。

### 3.4 指标建设（A/B 闭环）
- 在线指标：pctr（曝光点击率）、uctr（用户点击率）、关注率；离线 AUC。
- 大盘指标：人均关注数、关注中位数、关注三分位数、日新增关注次数（峰值 230w/天）。

## 四、八股 QA（逐题给讲法 + 防守点）

**Q1：为什么用 Graph Embedding 而不是协同过滤（CF）做达人召回？**
- 讲法：CF 靠共现矩阵，对**长尾/新达人**覆盖差、且难融入 side-info；GE 把行为构造成图、用游走+embedding 自然获得稠密向量，可同时刻画「行为相似」和「关注关系」，并能扩展到异构图（用户+达人）拿到双塔向量。文档里 `emb_rec` 与 `daren_cf` 是两条并行召回，GE 在覆盖与语义上更稳。

**Q2：DeepWalk / LINE / Node2Vec 区别？你选了哪个、为什么？**
- 讲法：DeepWalk=随机游走的 word2vec；LINE=一阶+二阶相似、适合复杂图；Node2Vec 用 P/Q 可调 DFS/BFS 偏置。业务上三者**都已全量**做 I2I 召回，Node2Vec 因能建用户-达人异构图、产出双向量更适配「好友+达人」混合推荐，是主线；MetaPath2Vec 是为解决低粉达人冷启动的下一步。

**Q3：Thompson Sampling 具体怎么用？Beta 后验的 α/β 是什么？**
- 讲法：把每个一级类目当成一个「臂」，维护其点击率的 Beta(α,β) 后验（α=点击数+1，β=未点击数+1）。每次重排按类目采样一个 pctr，倒排取 Top-16 类目。对比 ε-greedy：TS 用**概率匹配**天然平衡探索与利用，且对稀疏类目更友好；对比 UCB：TS 计算轻、线上易实现。

**Q4：重排为什么不直接用模型做多样性，而用规则+TS？**
- 讲法：成本是主因——重排在请求链路末端、延迟敏感，规则（分层 quota、类目间隔打散、曝光降权）可解释、易调、零推理开销；TS 只解决「类目探索」这一个子问题，属**轻量 E&E** 插件，不替模型决策。后续把达人和好友排序模型接入算法中台（多目标 DNN）是另一条线。

**Q5：A/B 实验你是怎么设计并看指标的？**
- 讲法：分场景（发现好友页/关注页/消息页）各自分桶对照，看 pctr/uctr/关注率；小流量（10%→20%）先验证再扩。Graph Embedding 召回在关注页 pctr +10.59%、发现好友页 +14.22%（10% 流量 4 天）；热门达人切 45 级池整体关注率 +5.3%。注意新奇效应/短期波动，故都跑 4–6 天看稳定。

**Q6：怎么缓解达人冷启动？**
- 讲法：① MetaPath2Vec 把达人的一二级发文垂直度等 side-info 作为异质网络节点类型引入，缓解低粉达人训练样本不足；② 热门达人池兜底（粉丝/发文/互动加权和）；③ 外部画像召回（其他产品兴趣映射端内）；④ 扶持 45 级 UGC 作者的显式召回分支。

**Q7：你的项目里 LR 而不是 GBDT/深度模型，为什么？**
- 讲法：2020 年账号推荐场景样本规模与实时性约束下，LR 训练快、可解释、权重可上共享内存在线预测，迭代成本低；AUC 0.81 已满足业务。排序模型后续在接算法中台做多目标 DNN（点击/关注多任务），是演进方向而非当时必要。

**Q8：召回→排序→重排的延迟和量级你怎么控？**
- 讲法：召回源走 Redis/BDB 在线查（如 `emb_rec` 取最近关注 10 个达人的相似达人、召回 100），多路召回按优先级分层（layer_policy）后进重排；重排用规则类（Factory 封装）零推理开销，整体控制在请求预算内。

## 五、可能的追问与防守

| 追问 | 防守口径 |
|---|---|
| "提升数字是不是全量长期？" | 统一答「实验期相对提升（10–20% 流量、4–6 天）」，被逼只补「答辩材料口径」，不外推 |
| "TS 的 α/β 怎么初始化/更新？" | 先验 Beta(1,1) 均匀；每日用点击/曝光流式更新；类目稀疏时后验自然拉平探索 |
| "Graph Embedding 和双塔 DSSM 区别？" | GE 用图游走、DSSM 用端到端双塔；文档里 DSSM 是「规划中」，主线是 GE，别把规划说成已上线 |
| "怎么证明是 GE 带来的提升不是新奇效应？" | 多场景多天稳定、对照组同期、且 10%→20% 扩量后方向一致 |
| "你做模型还是策略？" | 全链路都参与：召回（GE 建模）+ 排序（LR 特征/样本）+ 重排（TS E&E 策略）+ 实验闭环；主线偏「召回建模 + 重排策略」 |
