# 专题 · 端云协同（On-device / Cloud-Device Collaboration）

> 最后更新：2026-09-09
> 简历落点：OPPO 广告**端云协同推荐架构**（云训 + 端推 + 模型压缩）+ 腾讯**端云重排**（云上重排 + 端上重排双通路）。
> 主线话术：**云端成本高、实时性差 → 把能力拆成"云侧训练上游 + 端侧实时推理下游"，用模型压缩解决端侧资源约束，实时性↑、云端成本↓、隐私↑。**

---

## 一、一句话定位（开场）

> "我做过端云协同的推荐架构。传统纯云端架构有两个痛点：延迟高（要等网络请求）、服务器成本大。我的方案是把能力拆开——**核心大模型在云端用全量数据训练，轻量模型部署到端侧做实时推理**，利用端侧当前 session 的实时行为增量更新，再通过量化/剪枝/参数分拆把模型压到端侧内存和算力能承受的规模。结果云端负载成本下降约25%，端上推荐实时性显著提升。"

### 最硬数字
- **云端负载成本下降约 25%**（部分推理迁移到端侧）
- 模型体积：FP32→INT8 量化可减小约 **75%**，推理速度提升
- 端侧推理**毫秒级**、无网络延迟

---

## 二、核心原理

### 2.1 三种范式（递进）
```
范式1：云侧训练 + 云侧推理（传统）
范式2：云侧训练 + 端侧推理 ★核心
范式3：云侧训练 + 端侧推理 + 端云联合训练（前沿/联邦学习思路）
```

### 2.2 标准架构（范式2）
1. **云侧训练**：核心模型（DNN/DeepFM/DIN 等）在云端 GPU 集群用全量数据训练，天级/小时级更新。
2. **端侧推理**：轻量模型部署手机端，实时推理；用端侧当前 session 的浏览/点击**增量更新**；毫秒级、无需网络。
3. **模型压缩（端侧核心约束）**：
   - **量化**：FP32→INT8，体积↓75%、速度↑
   - **剪枝**：去冗余神经元/连接，模型稀疏化
   - **参数分拆**：大模型拆成小模块，按需加载进端内存
   - ⚠️ **端侧内存和算力是硬约束**，压缩目标是"如何在保精度的前提下塞进手机"

### 2.3 端云联合训练（前沿/范式3）
- 端侧收集用户实时行为**梯度**→ 上传云端 → 云端聚合多端梯度 → 更新全局模型。
- **联邦学习思路**，保护用户隐私（梯度不上传原始行为数据）。

## 四、八股 QA（被追问）

**Q1：端云协同的价值是什么？（为什么不全在云端）**
A：性能（端侧实时、无网络延迟）+ 成本（云端推理迁移到端，负载↓25%）+ 隐私（行为数据可留在端侧/联邦化，不上传原始数据）。

**Q2：端侧模型为什么能做得小但不崩？**
A：三层压缩：量化(INT8)、剪枝(稀疏化)、参数分拆(按需加载)。本质是"精度-体积-速度"三角取舍，用打分卡在端侧内存/算力约束内选最优组合。

**Q3：端侧和云侧模型怎么同步/一致？**
A：云侧定期（天/小时）训练下沉版本；端侧用本地实时 session 增量微调。难点是**端云更新频率不同导致分布漂移**——需要校验端上在线收益 vs 准确度损耗。

**Q4：端云联合训练（联邦学习）和传统云端区别？**
A：传统把原始数据集中到云；联邦只在端上算梯度、把**梯度/加密更新**传云端聚合，原始行为不出端 → 隐私保护。代价是通信、non-iid 数据、聚合收敛变难。

**Q5：为什么端上重排只给高端机+高消人群？**
A：端上推理吃客户端算力/内存/耗电，中低端跑不起来高精度模型；高消人群价值高，值得为即时兴趣付出端侧资源，先小流量验证再扩。
