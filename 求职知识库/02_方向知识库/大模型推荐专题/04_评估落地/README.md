# 大模型推荐的评估落地：从"测量兴趣"到"定义兴趣"（考点）

> 触发：面试官问"LLM 推荐把用户画像写进 memory/prompt，人为引入变量、强行改变推荐兴趣，过去用历史数据算 AUC 评估，现在怎么评估？"
> 一句话：**不是评估手段失配，而是"被评估的对象"变了**——兴趣从外生测量值变成系统内生定义的变量，单一 AUC 失效，要转三层评估（推、记、归因）+ 长期反身性监控。

---

## 〇、核心认知（开场点题，必背）

传统推荐里，用户的兴趣是 **外生给定的观测值**，模型是"读取"兴趣的测量工具；
所以衡量"测量工具准不准"的 AUC 逻辑成立。

LLM 推荐把兴趣 **写进 memory、塞进 prompt**，系统从 **测量者变成定义者**——
测量工具反过来改变被测量的兴趣，这就是 **测量者效应（Measurement-as-intervention）**。

> "传统评估的前提是兴趣固定、可被对齐；LLM 评估的情境是系统在定义兴趣。参考系塌了，评估要换维度。"

---

## 一、为什么传统离线指标（AUC/NDCG）在 LLM 推荐失效

| 失效点 | 机制 | 应对 |
|---|---|---|
| **非确定性** | temperature/beam 采样，同一画像多次结果不同，指标不可复现 | 评测降温度+固定seed+多采样取统计；承认只能降噪不能消除 |
| **无标准答案** | 生成式输出无 label，AUC 对齐的是"被注入的兴趣"而非真兴趣 | 离线指标降为辅助，主评转移在线 |
| **benchmark 泄漏** | LLM 微调接触 benchmark 数据导致指标虚高（*Benchmark Leakage Trap*, 2026） | 评估集/训练集严格隔离，交叉验证 |
| **实体映射** | 生成文本需做 item 实体识别才能映射回候选集，引入额外误差 | 约束解码 / semanticID 保证生成命中物料库 |

> 结论：AUC/HR/NDCG **仍可算，但解释性严重受损**——最多当辅助指标，配合 LLM-judge + 人工评估交叉验证。

## 二、评估三支柱

### 支柱一：推的能力（在线价值）——替代 AUC 的主战场

- **核心指标上移**：单次点击/时长 → **长期留存曲线（D1/D7/D30）**、满意度（NPS + 画像认同度调研）、**探索度**（新品类覆盖量，对抗兴趣锁死）。
- **AB 实验注意**：LLM 状态会话级持久，会造成：
  - **实验组间污染**（共享缓存/session 状态）
  - **记忆漂移（自证预言）**——模型按画像"推"用户，用户行为被改写，无法区分真实偏好 vs 诱导
  - 对策：**session 级隔离**（不只流量隔离）、定义多维度指标（相关性/事实性/流畅性/安全性）、OEC 组合指标纳入长期因子（如 LTV）。

### 支柱二：记的保真（画像质量）——直接回答"人为引入变量"

直承"人设变量"，在系统里为这个人造变量建设监控：

| 画像评估维度 | 怎么测 |
|---|---|
| **保真度** | LLM 预测用户对候选 item 态度（喜欢/中立/不喜），对比真实反馈算 Accuracy/F1（LettinGo, 2025） |
| **更新速率** | 每次反馈后画像改动幅度。改太快=不稳定，太慢=不灵敏 |
| **可纠正性** | 用户"我不喜欢这个类型"后，下轮是否真的降权该类型（对抗性反馈鲁棒性） |
| **认同度** | 调研"系统懂不懂我"；画像应可被查看/编辑（可解释、可纠偏） |

### 支柱三：变的归因（因果追溯）——回答"怎么评估人造变量"

- **逐条记忆 ablation**：删一条画像看结果变不变，变了=高归因。最直观的反事实测试。
- **Δ-OPE 成对比较**：把"注入画像前 vs 后"当两个策略做**成对离线评估**（RecSys 2024 的 pairwise OPE）。
- **SAFE 句子级归因**：要求 LLM 对每个推荐项标注"依据了哪条记忆"，建立 推荐→证据 的可审计映射。
- **LLM-as-judge 去偏**：judge 模型爱给自家长篇高分（自我/位置/长度偏好），需去偏 + 多 judge 交叉 + 人工复核；judge 本身也有非确定性，多采样聚合。

## 三、长期反身性（自我强化闭环）——加分项，高级面试官最想听

> 最深的坑：**只推符合已写入画像的内容 → 用户看到越来越单一 → 越单一越强化画像 → 兴趣被锁死（filter bubble 加剧）**。

落地监控：
- **内容多样性时间序列**：品类覆盖率、长尾曝光占比是否单调下降。
- **反事实画像注入**：故意注入与历史不符的兴趣，看模型能否产生"跨域"推荐。
- **self-play 去偏**：定期反偏训练抑制偏好偏差与长尾消失（SPRec）。
- **合成数据偏置检测**：平台日志中模型生成内容占比过高会把输出"引向集中、长尾先消失"。

核心观点：LLM 推荐的长期风险不是"推荐不准"，而是"**太准却锁死了用户**"。

## 五、可直接照背的完整话术（30 秒串场）

> "我的结论是：LLM 推荐**不是评估手段失配，而是被评估对象变了**——兴趣从外生测量值变成了系统内生定义的变量，所以单一 AUC 失效。落地我会建三层：**在线层**用留存、满意度、探索度，做好 session 隔离的 AB；**画像层**监控保真度、更新速率、可纠正性，直接回答'人造画像准不准'；**归因层**用记忆 ablation 和 Δ-OPE 做反事实追溯，用去偏的 LLM-judge 辅助。再加上对**自我强化闭环**的长期监测，防止推荐把用户兴趣越推越窄。"

### 判断题角度（追问备选）

- "多目标怎么折？" → 核心收益 + 护栏（探索度/多样性）+ OEC 综合，不只看单一 CTR。
- "judge 会不会有偏？" → 会，自我/位置/长度三偏差，去偏 + 交叉 + 人工兜底。
- "温度降到 0 可复现吗？" → 能降噪不能消除，仍多采样 + 统计聚合。
