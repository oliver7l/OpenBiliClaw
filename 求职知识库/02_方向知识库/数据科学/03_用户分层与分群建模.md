# 用户分层与分群建模方法论

---

## 一、用户分层方法论全景

我在腾讯QQ看点和QB（QQ浏览器）做数据科学时，用户分层是我最核心的工作之一。用户分层不是简单地把用户分成几类，而是要构建一套**可解释、可操作、可迭代**的用户理解体系，直接服务于差异化运营、推荐策略调整和资源分配。

### 1.1 用户分层的三层架构

我在实践中把用户分层分为三个层次，从粗到细、从业务驱动到数据驱动：

| 层级 | 方法 | 粒度 | 业务用途 | 代表项目 |
|------|------|------|----------|----------|
| **第一层·业务规则分层** | 基于业务定义的硬规则 | 粗（3-5层） | 核心用户识别、运营圈人 | 核心用户定义（周活后下周仍>2天） |
| **第二层·多维分群模型** | 频次×逛×消费三维切分 | 中（64群） | 差异化推荐、精细化运营 | QB用户分群模型（64群） |
| **第三层·预测建模分层** | 机器学习模型预测用户行为概率 | 细（连续打分） | 精准干预、流失预警、召回策略 | 次活模型（WDL，AUC 0.84-0.88） |

这三层不是互相替代，而是**互补叠加**：业务规则层保证可解释性和业务对齐，多维分群层提供中等粒度的操作单元，预测建模层实现个体级别的精准打分。

### 1.2 用户分层的核心原则

我在做用户分层时总结了四条原则：

1. **维度正交原则**：选择的分层维度之间相关性要弱（张量夹角大），避免维度冗余。我在QB分群模型中选择频次、逛、消费三个维度，正是因为它们相关性偏弱、业务含义充分、抓手明确（来源：QB用户分群模型）。
2. **分组均匀原则**：每个分群的用户量不能过于悬殊，否则小群没有统计意义，大群无法精细化操作。QB分群模型抽样943,726用户，分为64组，平均每组约1.4万，分组均匀（来源：QB用户分群模型）。
3. **可解释原则**：分层结果必须能被业务方理解和使用。我用SkopeRules提取可解释规则，而不是用黑盒模型直接输出标签，就是为了让运营和产品能看懂"什么样的用户是核心用户"。
4. **动态迭代原则**：用户分层不是一次性的，需要定期更新。核心用户的定义和特征会随产品阶段、季节、内容供给变化而变化，需要持续监控和迭代。

### 1.3 用户分层的完整工作流

```
业务问题定义
    │
    ▼
数据准备（用户行为表 + 画像表 + 内容消费表）
    │
    ▼
维度选择（正交性检验 + 业务含义评估）
    │
    ▼
┌─────────────────────────────────────────┐
│  分层方法选择                              │
│  ├─ 业务规则层：核心用户定义 + 硬规则圈人  │
│  ├─ 多维分群层：三维切分 + 节点划分       │
│  └─ 预测建模层：特征工程 + WDL/其他模型   │
└─────────────────────────────────────────┘
    │
    ▼
可解释性验证（SkopeRules规则提取 + 业务对齐）
    │
    ▼
分层结果应用（差异化运营 + 推荐策略 + 资源分配）
    │
    ▼
效果监控与迭代（分层稳定性 + 业务指标提升）
```

> **面试口述版**：我在腾讯做用户分层时，用的是三层架构：第一层是业务规则分层，比如定义核心用户是"某周活跃后下周仍有超过2天使用"的用户，占比51.8%；第二层是多维分群模型，用频次×逛×消费三个维度切出64个用户群，抽样94万用户平均每群1.4万；第三层是预测建模分层，用WDL架构做次活预测模型，AUC 0.84-0.88，输出0.5-0.9的连续打分。这三层互补叠加，业务规则层保证可解释性，多维分群层提供操作单元，预测层实现个体精准打分。选维度的核心原则是正交性——三个维度相关性弱、业务含义充分、抓手明确。

## 二、核心用户特征分析与可解释规则提取

### 2.1 核心用户定义

我在QQ看点定义核心用户为：**主动且较稳定地使用看点的用户 = 某周活跃后下周依然有超过2天使用看点的用户**（来源：核心用户特征分析和分层）。

这个定义的设计思路是：
- **"主动"**：排除被动打开、端外调起等非主动行为
- **"较稳定"**：不是一次性活跃，而是有持续使用的趋势
- **"下周仍>2天"**：用未来行为验证当前用户的稳定性，避免把偶然活跃的用户误判为核心

**数据选取**：选取五月最后一周（20200525-20200531）的看点用户，通过判断他们在六月第一周（20200601-20200607）的使用天数是否超过2天来判断是否为核心用户（来源：核心用户特征分析和分层）。

**数据表**：`pcg_txkd_shared_data_app::fcc_share_user_behavior_d`（来源：核心用户特征分析和分层）。

### 2.3 SkopeRules可解释规则提取

#### 2.3.1 为什么选择SkopeRules

在核心用户特征提取中，我没有直接用逻辑回归或随机森林输出特征重要度，而是选择了**SkopeRules**（基于决策树的规则提取算法），原因有三：

1. **可解释性强**：输出的是"IF-THEN"形式的规则，业务方可以直接理解"满足什么条件的用户是核心用户"
2. **精度可控**：可以设置`precision_min`和`recall_min`过滤低质量规则，只保留高置信度的规则
3. **抗过拟合**：基于多棵决策树的Bagging集成，比单棵决策树更稳定

#### 2.3.2 模型参数配置

```python
from skrules import SkopeRules

clf = SkopeRules(
    max_depth=7,              # 单棵树最大深度7层
    max_depth_duplication=20, # 规则去重的深度
    n_estimators=30,          # 30棵决策树集成
    precision_min=0.5,        # 规则精度最低50%
    recall_min=0.05,          # 规则召回最低5%
    feature_names=feature_names
)
```
（来源：核心用户特征分析和分层）

#### 2.3.5 三大核心用户特征概括

从15条规则中，我概括出核心用户的三条主要特征（来源：核心用户特征分析和分层）：

**特征一：高频活跃**
- 条件：一周活跃6天以上（active_days > 6.5）
- 规则精度：最高98.9%
- 这是最直接的核心用户特征——高频活跃本身就意味着用户粘性强

**特征二：中频活跃 + 足够进入次数**
- 条件：
  - 一周活跃5天且app进入次数≥7次（active_days > 5.5 AND app_enter_cnt > 6.5）
  - 一周活跃4天且app进入次数≥6次（active_days > 4.5 AND app_enter_cnt > 5.5）
  - 一周活跃3天且app进入次数≥5次（active_days > 2.5 AND app_enter_cnt > 4.5）
- 规则精度：90%-95%
- 洞察：中频用户如果每次使用都有明确的进入行为（主动打开APP），说明有使用习惯，也是核心用户

**特征三：低频活跃 + 足够时长**
- 条件：一周活跃1-2天，且总时长大于11分钟（duration_session > 11.19）
- 规则精度：68%-82%
- 洞察：低频但深度消费的用户，虽然来的次数少，但每次使用时间长，有消费深度，也是核心用户

**补充特征：互动行为**
- 有点赞、收藏、分享行为的用户，直接视为核心用户（来源：核心用户特征分析和分层）
- 互动行为是用户参与度的强信号，有互动的用户留存意愿更强

### 2.4 核心用户分层与内容消费关联分析（CCA）

在得到核心用户特征的基础上，我进一步利用时序数据（用户在不同赛道、不同品类的消费变化趋势），判断赛道和品类的消费变化对于核心用户的表现（总时长、活跃天数）的影响（来源：核心用户特征分析和分层）。

#### 2.4.1 方法：典型相关分析（CCA）

使用**CCA（Canonical Correlation Analysis，典型相关分析）**分析两组变量之间的关系：
- **X（自变量组）**：用户赛道×品类消费变化（曝光PV/点击PV的一阶差分）
- **Y（因变量组）**：用户表现变化（总时长变化、活跃天数变化的一阶差分）

CCA的核心思想是：找到X的线性组合和Y的线性组合，使得两者之间的相关性最大。通过分析典型变量的载荷（loading），可以识别哪些品类的消费变化与用户表现变化最相关。

**数据处理**：
- 提取四月至七月共16周的核心用户数据，按月聚合为M1（4月）、M2（5月）、M3（6月）、M4（7月）
- 计算每月一阶差分：M2-M1、M3-M2、M4-M3
- 去除方差过小的变量（零值比例>80%的列）
- 去除共线性高的变量（VIF > 10）
- 抽样50,000核心用户进行分析

（来源：核心用户特征分析和分层）

#### 2.4.2 曝光PV变化与用户表现的关联

**显著性检验结果**（来源：核心用户特征分析和分层）：

| 典型变量 | Canonical Correlation | Wilks' lambda | F Value | Pr > F |
|----------|----------------------|---------------|---------|--------|
| 第1对 | 0.874 | 0.019 | 147.5 | <0.0001 |
| 第2对 | 0.856 | 0.079 | 103.9 | <0.0001 |
| 第3对 | 0.805 | 0.295 | 56.2 | <0.0001 |

三对典型变量均高度显著，说明核心用户的内容消费变化与用户表现变化之间存在显著的典型相关关系。

**核心结论**：核心用户每月的时长和活跃天数的变化趋势与以下品类的曝光PV变化趋势为**正相关**（来源：核心用户特征分析和分层）：

| 相关性强度 | 品类 |
|-----------|------|
| **最强相关** | 网红达人、搞笑、生活、社会 |
| **较强相关** | 游戏、娱乐、科学、电视剧、美食 |

这意味着：当核心用户在网红达人、搞笑、生活、社会这四个品类上的曝光增加时，他们的总时长和活跃天数也倾向于增加。这直接指导了内容运营策略——对核心用户加大这四个品类的推荐权重。

#### 2.4.3 点击PV变化与用户表现的关联

**显著性检验结果**（来源：核心用户特征分析和分层）：

| 典型变量 | Canonical Correlation | Wilks' lambda | F Value | Pr > F |
|----------|----------------------|---------------|---------|--------|
| 第1对 | 0.733 | 0.135 | 104.8 | <0.0001 |
| 第2对 | 0.700 | 0.292 | 74.2 | <0.0001 |
| 第3对 | 0.606 | 0.573 | 40.0 | <0.0001 |

**关键发现**（来源：核心用户特征分析和分层）：
1. 相比曝光PV，核心用户点击PV的变化与用户表现变化之间的关联性**相对小一些**（典型相关系数0.733 vs 0.874）
2. M3（六月和七月的差值）对应的变量明显比M1、M2多，说明六七月份核心用户点击的变化与用户表现的变化相关性比前两个月要大
3. **四五月份**：娱乐、电视剧、网红达人、美食、游戏、电影、综艺正相关
4. **六七月份**：游戏、电视剧、网红达人、生活、娱乐、搞笑、动漫、综艺、电影、教育正相关，其中**娱乐、电视剧、网红达人、生活、游戏**相关性最大

#### 2.4.4 周内不同日期的内容偏好差异

我进一步分析了核心用户在七月第一周的周一、周三、周五、周六、周日的内容消费与每日时长占比的关系（来源：核心用户特征分析和分层）。

| 时间段 | 与时长占比相关性最强的品类 |
|--------|---------------------------|
| **周六周日** | 生活小视频、网红达人小视频、搞笑小视频、游戏短视频、电视剧短视频、电影短视频 |
| **周一周三周五** | 生活小视频、搞笑小视频、游戏短视频、娱乐小视频、娱乐图文、电影短视频 |
| **每日通用** | **生活小视频始终是影响时长占比最大的品类** |

**关键洞察**（来源：核心用户特征分析和分层）：
- 相比周末，工作日的娱乐品类与时长占比相关性更高，电视剧、网红达人品类相关性更低
- 对于每一天，生活小视频都是影响时长占比最大的种类
- 这意味着：生活类小视频是核心用户时长的"基本盘"，无论工作日还是周末都最重要；周末可以适当增加电视剧、电影类内容的推荐权重

#### 2.4.5 QB信息流核心用户选择标准

在QB端做同样的分析时，我使用了不同的核心用户选择标准（来源：核心用户特征分析和分层）：

> 周总时长大于84分钟，或至少有关注/分享/点赞/评论其中一种行为，或周活跃4-5天且后台点击>4.5次，或周活跃4-5天且周时长>12分钟，或周活跃>5天。

这个标准比看点端更复杂，因为QB是浏览器产品，用户行为更多样，需要综合时长、互动、活跃、点击多个维度来定义核心用户。

### 2.5 核心用户分层对比表

|----------|------------|----------|--------|----------|----------|----------|
| **核心-高频型** | ≥6天 | - | - | - | 97%-99% | 核心用户主体 |
| **核心-中频型** | 3-5天 | 5-7次+ | - | - | 90%-95% | 核心用户重要组成 |
| **核心-低频深度型** | 1-2天 | - | >11分钟 | - | 68%-82% | 时长驱动型 |
| **核心-互动型** | - | - | - | 有点赞/收藏/分享 | 直接纳入 | 参与度驱动型 |
| **非核心** | 不满足以上任一条件 | - | - | - | - | 约48-51% |

> **面试口述版**：我在QQ看点做核心用户分析时，定义核心用户是"某周活跃后下周仍有超过2天使用"的用户，占比51.8%（9781万）。我用SkopeRules提取可解释规则，参数是max_depth=7、n_estimators=30、precision_min=0.5、recall_min=0.05，从12个行为特征中提取了15条高置信规则，概括出三大特征：第一是高频活跃（周活6天+，精度最高98.9%）；第二是中频活跃加足够进入次数（周活3-5天且app进入5-7次+，精度90%-95%）；第三是低频活跃加足够时长（周活1-2天但时长>11分钟，精度68%-82%），加上有互动行为的用户直接纳入。用特征筛选出的核心用户9308万，占49.3%，覆盖率达到定义口径的95.2%。然后我用CCA分析内容消费变化和用户表现变化的关联，发现网红达人、搞笑、生活、社会四个品类的曝光变化与核心用户时长和活跃天数变化正相关性最强，生活小视频每天都是影响时长的最大品类。这个分析直接指导了我们的内容运营策略——对核心用户加大网红达人和生活类内容的推荐权重。

## 三、QB用户分群模型（频次×逛×消费三维64群）

### 3.1 分群模型定位

QB用户分群的定位是**"介于千人一面和千人千面之间"**——既不像千人一面那样呆板，又不像千人千面那样不可控（来源：QB用户分群模型）。

这个定位的设计考量是：
- **千人一面**：所有用户用同一套策略，简单但无法差异化，浪费资源
- **千人千面**：每个用户一个策略，理论最优但工程复杂度极高、运营不可控、效果难以归因
- **分群运营**：将用户分成若干个有业务含义的群，每个群用不同策略，兼顾差异化和可控性

### 3.2 分群维度选择

我选择了三个维度来构建用户分群模型（来源：QB用户分群模型）：

| 维度 | 指标名 | 字段 | 取值范围 | 业务含义 |
|------|--------|------|----------|----------|
| **频次** | 最近30天活跃天数 | active_days_month | [1, 30] | 用户来的频率有多高 |
| **逛** | 主feeds真实曝光次数 | exp_main_tl | [0, ++) | 用户在信息流里逛了多少 |
| **消费** | 产品使用时长 | duration_session | [0, ++) | 用户实际消费了多少内容 |

**选择这三个维度的理由**（来源：QB用户分群模型）：

1. **理由一：相关性偏弱，张量夹角大**
   - 三个维度衡量的是用户行为的不同侧面：频次是"来不来"，逛是"看多少"，消费是"看多久"
   - 三者之间没有强线性相关，避免了维度冗余
   - 用张量夹角衡量维度间的正交性，夹角大说明维度独立

2. **理由二：业务含义充分，抓手明确**
   - 频次：可以通过Push、红点、活动等促活手段提升
   - 逛：可以通过推荐策略、内容供给、UI优化提升曝光
   - 消费：可以通过内容质量、推荐精准度、个性化提升时长
   - 每个维度都有明确的运营抓手，分群结果可以直接指导策略

### 3.3 分群节点划分

**抽样样本量**：943,726（来源：QB用户分群模型）

**数据过滤**：
- 过滤 exp_main_tl >= 200 的异常用户（曝光次数过高，可能是爬虫或异常账号）
- 过滤 duration_session >= 18000 的异常用户（时长超过300分钟/天，异常）

**节点划分**（每个维度按3个节点切分为4档）（来源：QB用户分群模型）：

| 节点 | 频次（活跃天数） | 逛（曝光次数） | 消费（时长/分钟） |
|------|------------------|----------------|-------------------|
| 节点1 | 5 | 5 | 30 |
| 节点2 | 15 | 10 | 120 |
| 节点3 | 25 | 30 | 300 |

每个维度按节点切分为4档：
- **频次**：1-5天 / 6-15天 / 16-25天 / 26-30天
- **逛**：0-5次 / 6-10次 / 11-30次 / >30次
- **消费**：0-30分钟 / 31-120分钟 / 121-300分钟 / >300分钟

3个维度 × 4档 = **4×4×4 = 64个用户群**

**分组均匀性**：抽样943,726用户，分为64组，平均每组约14,746人（约1.4万），从分组结果看分组方式比较均匀（来源：QB用户分群模型）。

### 3.4 64群的业务解读

64个用户群可以按三维度的高低组合进行业务解读：

| 群类型 | 频次 | 逛 | 消费 | 业务含义 | 运营策略 |
|--------|------|-----|------|----------|----------|
| **三高群（核心）** | 高 | 高 | 高 | 高频高逛高消费，最核心用户 | 保持体验，防流失，做高价值内容推荐 |
| **高频低消费群** | 高 | 中 | 低 | 来得多但看得少，可能是工具型用户 | 提升内容匹配度，引导深度消费 |
| **低频高消费群** | 低 | 中 | 高 | 来得少但每次看得久，深度用户 | 提升回访频率，Push/红点召回 |
| **高逛低消费群** | 中 | 高 | 低 | 曝光多但消费少，推荐不精准 | 优化推荐算法，提升点击和消费转化 |
| **三低群（边缘）** | 低 | 低 | 低 | 低频低逛低消费，边缘用户 | 低成本触达，或放弃运营 |

### 3.5 重要背景：用信息流DAU而非大盘DAU

**建议用信息流DAU而不是大盘DAU做分群，因为大盘DAU有大量僵尸用户**（来源：QB用户分群模型）。

这个背景非常重要：QB是浏览器产品，大盘DAU包含大量只使用文件、搜索、网页浏览等非信息流功能的用户，甚至有被动打开的僵尸用户。如果用大盘DAU做分群，会混入大量非目标用户，导致分群结果失真。用信息流DAU（严口径：当日有主feeds真实曝光）才能保证分群对象是真正消费推荐内容的用户。

### 3.6 分群模型的应用场景

QB用户分群模型的应用场景包括（来源：QB用户分群模型）：

1. **差异化推荐策略**：不同分群用户用不同的推荐权重和内容策略
2. **精细化运营**：按分群推送不同的Push、红点、活动
3. **资源分配**：高价值分群分配更多推荐资源和运营资源
4. **效果归因**：按分群拆解策略效果，定位哪些用户受益、哪些受损
5. **用户生命周期管理**：跟踪用户在分群间的流转，识别成长和衰退趋势

> **面试口述版**：我在QB做用户分群模型时，定位是"介于千人一面和千人千面之间"。我选了三个维度：频次（最近30天活跃天数）、逛（主feeds真实曝光次数）、消费（产品使用时长）。选这三个维度的理由是相关性偏弱（张量夹角大）、业务含义充分抓手明确。每个维度按3个节点切4档：频次节点是5/15/25天，逛是5/10/30次，消费是30/120/300分钟，总共4×4×4=64个用户群。抽样943,726用户，平均每群约1.4万，分组均匀。一个重要的背景是：必须用信息流DAU而不是大盘DAU做分群，因为大盘DAU有大量僵尸用户和纯浏览器用户，会污染分群结果。64群可以按三维度高低组合解读，比如三高群是核心用户要保持体验防流失，高频低消费群要提升内容匹配度，低频高消费群要提升回访频率。分群结果直接用于差异化推荐、精细化运营和资源分配。

## 四、次活模型（WDL架构留存预测）

### 4.1 模型目标与样本定义

我在QB搭建了次活预测模型，目标是**预测月活用户次日是否会主启**（主动打开APP）（来源：QB次活模型）。

**正负样本定义**（来源：QB次活模型）：
- **全部样本集合**：月活用户（包括T日往前28天内活跃的用户）
- **正样本**：月活用户中，T+1日有主启的用户
- **负样本**：月活用户除正样本外的其他所有用户

**采样策略**：正例8kw，按正负样本1:1比例，负例进行负采样，得到8kw样本（来源：QB次活模型）。

### 4.2 特征工程

次活模型的特征分为三大类（来源：QB次活模型）：

#### 4.2.1 活跃状态特征

| 特征子类 | 具体特征 | 时间窗口 | 预处理 |
|----------|----------|----------|--------|
| 累积活跃天数 | 近7/14/21/28天累积活跃天数 | 7/14/21/28天 | 数值特征 |
| 累积主启天数 | 近7/14/21/28天累积主启天数 | 7/14/21/28天 | 数值特征 |
| 累积时长 | 近7/14/21/28天累积时长 | 7/14/21/28天 | 数值特征 |

这组特征捕捉用户近期的活跃强度趋势，不同时间窗口的对比可以反映活跃是在上升还是下降。

#### 4.2.2 活跃序列特征

| 特征 | 表示方式 | 长度 |
|------|----------|------|
| 近30天活跃状态 | 每日是否活跃的0/1序列 | 30维 |
| 近30天主启状态 | 每日是否主启的0/1序列 | 30维 |
| 近30天当日时长 | 每日使用时长的序列化表示 | 30维 |

序列特征比累积特征保留了更多时序信息，比如活跃的连续性、间隔模式、最近几天的趋势变化。模型可以通过Embedding层和DNN自动学习序列中的模式。

#### 4.2.3 基础画像特征

| 特征 | 预处理方式 |
|------|-----------|
| 年龄 | OneHot编码 |
| 性别 | OneHot编码（1男2女） |
| 星座 | OneHot编码 |
| 手机类型 | OneHot编码 |
| 电话运营商 | OneHot编码 |
| 学历 | OneHot编码 |

#### 4.2.4 端内行为数据（初版未使用）

每日总PV、总曝光等端内行为数据，初版模型未使用，预留作为后续迭代的特征方向（来源：QB次活模型）。

### 4.3 模型架构：Embedding + WDL

**模型选择**：Embedding + WDL（Wide & Deep Learning）（来源：QB次活模型）。

选择WDL的原因：
- **Wide部分**：线性模型，擅长记忆特征之间的显式交叉关系（比如"近7天活跃天数高且近30天连续活跃"的组合效应）
- **Deep部分**：深度神经网络，擅长学习特征之间的隐式非线性关系
- **两者结合**：兼顾记忆能力和泛化能力，适合用户行为预测这种既有显式规则又有复杂模式的场景

**输出格式**：生成GSP标签——次日活跃打分，以0.1为步长，范围0.5-0.9（来源：QB次活模型）。

### 4.4 数据摸底

在建模前，我先做了数据摸底，了解主启行为的基线水平（来源：QB次活模型）：

| 日期 | 日活表 | 当日有主启 | 主启占比 |
|------|--------|-----------|----------|
| 20200801 | 126,018,039 | 85,282,541 | **67.67%** |
| 20200802 | 121,529,666 | 83,206,282 | **68.47%** |
| 20200805 | 135,134,106 | 90,185,995 | **66.74%** |
| 20200806 | 134,349,472 | 89,555,619 | **66.66%** |
| 20200807 | 132,780,994 | 86,166,823 | **64.89%** |

**关键发现**：QB日活用户中，约65%-68%的用户当日有主启行为，剩余32%-35%是被动打开或端外调起。主启占比在周末（8月1日周六、8月2日周日）略高于工作日，说明周末用户主动使用意愿更强。

> 注：20200803和20200804的主启数据异常（6.47%和20.69%），可能是数据上报问题或特殊事件，建模时使用正常日期的数据。

### 4.5 模型训练效果

#### 4.5.1 单日训练集效果

| 数据集 | 日期分区 | AUC | 来源 |
|--------|----------|-----|------|
| 训练集 | 0815分区 | **0.86** | QB次活模型 |
| 测试集 | 0816分区 | **0.88** | QB次活模型 |
| 预测集 | 0818分区 | **0.84** | QB次活模型 |

**计算流ID**：6030997，训练组件作业ID：815133783（来源：QB次活模型）。

AUC在0.84-0.88之间，说明模型有较好的区分能力。测试集AUC（0.88）高于训练集（0.86），可能是因为0816是周六，用户行为模式更规律；预测集AUC（0.84）略有下降，是时间衰减的正常现象。

#### 4.5.2 不同阈值下的精确率和召回率

| 用户群 | 阈值 | Precision | Recall | 来源 |
|--------|------|-----------|--------|------|
| 月活用户 | 0.8 | **76%** | **50%** | QB次活模型 |
| 月活∩T+1日活（次日真正受影响用户） | 0.7 | **89%** | **56%** | QB次活模型 |

**关键解读**：
- 在全量月活用户上，阈值0.8时precision 76%、recall 50%——预测为次日主启的用户中76%确实主启了，覆盖了50%的实际主启用户
- 在"月活∩T+1日活"这个更精准的用户群上（次日真正会受运营干预影响的用户），阈值0.7时precision达到89%、recall 56%——这个用户群的行为更可预测
- 阈值选择需要根据业务场景权衡：高阈值（0.8）适合精准干预（只对高概率用户做Push），低阈值（0.7）适合广覆盖干预

#### 4.5.3 训练集扩充为三日后的效果

将训练集从单日（0815）扩充为三日（0815-0817），测试集0818（来源：QB次活模型）：

| 配置 | 训练集 | 测试集 | AUC |
|------|--------|--------|-----|
| 单日训练 | 0815 | 0816 | 0.88 |
| 三日训练 | 0815-0817 | 0818 | **0.849** |

三日训练的AUC（0.849）与单日训练的预测集AUC（0.84）接近，说明扩充训练集没有显著提升效果，可能是因为用户行为模式在短期内比较稳定，单日数据已经足够捕捉。

### 4.6 模型输出与应用

**输出**：GSP标签——次日活跃打分，以0.1为步长，范围0.5-0.9（来源：QB次活模型）。

**应用场景**：

1. **差异化运营**：
   - 高概率次日活跃用户（打分>0.8）：正常服务，不做过度干预，避免打扰
   - 中概率用户（0.6-0.8）：适度干预，Push/红点提醒
   - 低概率用户（<0.6）：重点召回，个性化Push+内容推荐

2. **用户生命周期管理**：
   - 次活打分持续下降的用户：流失预警，提前干预
   - 次活打分持续上升的用户：成长用户，加大内容推荐深度

3. **运营资源优化**：
   - 根据次活打分分配Push配额，把资源用在最可能被召回的用户上
   - 避免对高概率用户过度推送导致负反馈

### 4.7 留存预测方法论延伸

次活模型本质上是**短期留存预测（次日）**，更长期的留存预测可以从以下方向延伸：

1. **扩展预测目标**：7日留存、14日留存、30日留存
2. **增加时间窗口特征**：用户生命周期阶段、历史留存模式、活跃间隔分布
3. **结合内容消费特征**：消费品类多样性、消费深度变化趋势、内容偏好迁移
4. **使用生存分析模型**：预测用户流失时间点而非二分类，更精细地刻画流失风险
5. **多任务学习**：同时预测次日留存、7日留存、30日留存，共享特征表示

> **面试口述版**：我在QB做过次活预测模型，目标是预测月活用户次日是否主动打开APP。正负样本定义是：正样本是月活用户中T+1有主启的，负样本是其余月活用户，1:1负采样各8kw。特征分三类：第一是活跃状态特征，近7/14/21/28天的累积活跃天数、主启天数、时长；第二是活跃序列特征，近30天活跃0/1、主启0/1、当日时长的序列化表示；第三是基础画像，年龄性别星座手机运营商学历OneHot。模型用Embedding+WDL架构，Wide部分记忆显式特征交叉，Deep部分学习隐式非线性关系。效果：训练AUC 0.86，测试AUC 0.88，预测AUC 0.84。在月活∩次日日活的用户群上，阈值0.7时precision 89%、recall 56%。模型输出0.5-0.9的打分标签，用于差异化运营——高概率用户正常服务，中概率用户适度干预，低概率用户重点召回。数据摸底发现QB日活中约65%-68%有主启行为，周末略高于工作日。

1. **交叉推荐**：利用业务间的关联规则做交叉推荐，如小说用户推信息流内容
2. **用户心智识别**：网页浏览的高关联度说明QB用户的浏览器心智强，推荐需要考虑如何从浏览场景导流到信息流
3. **冷启动**：新用户使用了某个业务后，可以基于关联规则推荐相关业务的内容

5. **产品策略**：如果核心目标是提升信息流消费，可以利用"网页浏览→信息流"的关联路径，在浏览场景中做信息流入口优化

## 八、面试话术

### 8.1 自我介绍（用户分层方向）

> "我在腾讯QQ看点和QB做了四年数据科学，用户分层和用户理解是我最核心的工作之一。我做了三套互补的用户分层体系：第一套是核心用户特征分析，定义核心用户是'某周活跃后下周仍有超过2天使用'的用户，占比51.8%，用SkopeRules提取出三大可解释特征（高频/中频+进入/低频+时长），再用CCA分析发现网红达人、搞笑、生活、社会四个品类与核心用户时长强正相关；第二套是QB用户分群模型，用频次×逛×消费三维度切出64个用户群，抽样94万用户平均每群1.4万，用于差异化推荐和精细化运营；第三套是次活预测模型，用Embedding+WDL架构预测月活用户次日是否主启，AUC 0.84-0.88，阈值0.7时precision 89%/recall 56%，输出0.5-0.9的打分用于差异化运营和召回干预。另外我还做过双端粉丝数据摸底，发现看点关注分发率是QB的近9倍，为QB关注模块优化提供了数据支撑。"

### 8.2 高频Q&A

**Q：怎么做用户分层？有哪些方法论？**

A：我在腾讯做用户分层时用的是三层架构。第一层是业务规则分层，比如定义核心用户是"某周活跃后下周仍有超过2天使用"的用户，占比51.8%（9781万人），这种分层可解释性最强，业务方最容易理解。第二层是多维分群模型，我在QB用频次（月活跃天数）、逛（主feeds真实曝光次数）、消费（产品使用时长）三个维度，每个维度按3个节点切4档，总共4×4×4=64个用户群。选这三个维度的理由是相关性偏弱（张量夹角大）、业务含义充分抓手明确。抽样943,726用户，平均每群约1.4万，分组均匀。第三层是预测建模分层，用WDL架构做次活预测模型，输出0.5-0.9的连续打分，实现个体级别的精准干预。这三层互补叠加，不是互相替代。

选维度的核心原则是正交性——维度之间相关性要弱，避免冗余。另外每个维度都要有明确的运营抓手，这样分群结果才能直接指导策略。还有一个重要的实践经验是：必须用信息流DAU而不是大盘DAU做分群，因为大盘DAU有大量僵尸用户和纯工具型用户，会污染分群结果。

**Q：核心用户怎么定义？怎么提取可解释特征？**

A：我在QQ看点定义核心用户是"某周活跃后下周依然有超过2天使用看点的用户"，选取五月最后一周用户，判断六月第一周使用天数是否>2天。按这个定义圈定的核心用户97,816,754人，占一周用户51.8%。

特征提取我用的是SkopeRules——基于决策树的规则提取算法，参数是max_depth=7、n_estimators=30、precision_min=0.5、recall_min=0.05。用了12个行为特征：曝光次数、时长、点赞、收藏、分享、主feeds刷新、上滑、频道刷新、app进入次数、总消费次数、活跃天数。提取了15条高置信规则，概括出三大特征：第一是高频活跃（周活6天+，规则精度最高98.9%）；第二是中频活跃加足够进入次数（周活5天且进入≥7次、4天且≥6次、3天且≥5次，精度90%-95%）；第三是低频活跃加足够时长（周活1-2天但总时长>11分钟，精度68%-82%）。另外有点赞收藏分享行为的用户直接视为核心用户。

用这些特征筛选出的核心用户93,081,176人，占49.3%，对定义口径的覆盖率达到95.2%。我选择SkopeRules而不是逻辑回归或随机森林，是因为它输出的是IF-THEN形式的规则，业务方可以直接理解"满足什么条件的用户是核心用户"，可解释性最强。

**Q：CCA分析是怎么做的？发现了什么？**

A：CCA（典型相关分析）是用来分析两组变量之间关系的方法。我用它分析核心用户的内容消费变化（X：赛道×品类的曝光PV/点击PV一阶差分）和用户表现变化（Y：总时长、活跃天数一阶差分）之间的关系。

数据是四月至七月共16周的核心用户，按月聚合为M1-M4，计算每月一阶差分，去除方差过小（零值>80%）和共线性高（VIF>10）的变量，抽样5万用户。

显著性检验结果三对典型变量都高度显著（F值147.5/103.9/56.2，p<0.0001）。核心结论是：核心用户每月时长和活跃天数的变化趋势与网红达人、搞笑、生活、社会这四个品类的曝光PV变化正相关性最强，其次是游戏、娱乐、科学、电视剧、美食。

我还做了周内不同日期的分析，发现周末（周六周日）与时长占比相关性最强的是生活小视频、网红达人小视频、搞笑小视频、游戏短视频、电视剧短视频、电影短视频；工作日（周一周三周五）是生活小视频、搞笑小视频、游戏短视频、娱乐小视频、娱乐图文、电影短视频。最重要的发现是：对于每一天，生活小视频都是影响时长占比最大的品类。这些发现直接指导了内容运营策略——对核心用户加大网红达人和生活类内容的推荐权重，周末适当增加电视剧电影类内容。

**Q：次活模型怎么做的？特征工程和模型架构是什么？**

A：我在QB做的次活模型目标是预测月活用户次日是否会主启（主动打开APP）。正负样本定义：正样本是月活用户中T+1有主启的，负样本是其余月活用户，1:1负采样各8kw。

特征工程分三类：第一是活跃状态特征，近7/14/21/28天的累积活跃天数、累积主启天数、累积时长——不同时间窗口的对比可以反映活跃趋势；第二是活跃序列特征，近30天活跃状态0/1、主启状态0/1、当日时长的序列化表示——序列特征保留了时序信息，比如活跃的连续性和间隔模式；第三是基础画像，年龄、性别、星座、手机类型、运营商、学历，用OneHot编码。端内行为数据（总PV、总曝光）初版未使用，预留迭代。

模型用Embedding+WDL（Wide & Deep Learning）。Wide部分是线性模型，擅长记忆特征之间的显式交叉关系；Deep部分是DNN，擅长学习隐式非线性关系。两者结合兼顾记忆和泛化，适合用户行为预测。

效果：训练集（0815分区）AUC 0.86，测试集（0816分区）AUC 0.88，预测集（0818分区）AUC 0.84。在月活∩T+1日活这个用户群上，阈值0.7时precision 89%、recall 56%。模型输出GSP标签——次日活跃打分0.5-0.9以0.1为步长，用于差异化运营：高概率用户正常服务，中概率用户适度干预，低概率用户重点召回。

数据摸底发现QB日活中约65%-68%有主启行为，周末略高于工作日。训练集扩充为三日后AUC 0.849，与单日训练的预测集接近，说明用户行为模式短期内稳定，单日数据已足够。

**Q：粉丝数据摸底发现了什么？双端差距有多大？**

A：我在QB和看点双端做过粉丝数据全面摸底，数据日期2020年8月31日，作者做了主从账号去重。核心发现是两端差距巨大。

作者生态方面：QB作者总数267.6万，看点167.1万，但QB 99.5%是0-3K粉丝的长尾作者，看点97.1%。看点中腰部作者（3K-10W）数量是QB的3-4倍，100W+头部作者看点82个而QB只有5个。按日活粉丝看，看点作者数反超QB（125.7万 vs 105.4万），说明看点作者的粉丝活跃度更高。

关注分发率方面：看点粉丝曝光占比3.55%，QB仅0.40%，差了近9倍；看点粉丝点击占比2.69%，QB 0.37%。看点粉丝阅读效率5.12%略低于大盘6.76%，QB粉丝阅读效率19.32%接近大盘20.84%但绝对量级太小。

用户参与度方面：看点日活中有关注行为的用户2.20%，QB只有0.25%，差8.8倍。看点有关注关系的用户总量3.97亿，QB 7211万；关注用户DAU看点5207万，QB 1345万。

这些数据直接支撑了QB后续大力优化关注模块的决策——差距就是空间。QB需要从创作者生态培育、关注分发机制优化、用户关注行为引导三个方面系统性提升。

**Q：关联规则分析发现了什么？对推荐策略有什么启示？**

A：我在QB做过业务使用的关联规则分析，定义用户在某个业务场景停留超过3秒视为使用过。数据是20200610 QB Android端日活用户，宽口径和最严口径各抽100万。

单个业务使用率：文件功能约52%最高，网页浏览38%，信息流36%，搜索21%。关联规则筛选条件是支持度>0.05、置信度>0.6、提升度>1.5。

核心发现是：比较有效的关联规则基本都指向网页浏览——QB用户不管使用哪个业务功能，同时基本都会使用网页浏览。这反映了QB在用户心智中主要是浏览器，用户打开QB的首要目的是浏览网页，其他功能是附加使用。另外最严口径DAU用户中，看小说的用户倾向于也会使用信息流。

对推荐策略的启示：第一，要利用"网页浏览→信息流"的关联路径，在浏览场景中做信息流入口优化，把浏览器用户导流到信息流；第二，可以做交叉推荐，比如小说用户推信息流内容；第三，新用户使用了某个业务后，可以基于关联规则推荐相关业务内容；第四，用户从多业务使用退化为单业务使用时，可能是流失前兆，可以做流失预警。

**Q：用户分层的结果怎么落地？怎么衡量分层的效果？**

A：用户分层的落地主要有四个方向。第一是差异化推荐策略：不同分群用户用不同的推荐权重和内容策略，比如三高群（高频高逛高消费）做高价值内容推荐和防流失，高频低消费群提升内容匹配度，低频高消费群做回访召回。第二是精细化运营：按分群推送不同的Push、红点、活动，把运营资源用在最可能被召回的用户上。第三是资源分配：高价值分群分配更多推荐资源和运营资源，边缘用户低成本触达或放弃。第四是效果归因：按分群拆解策略效果，定位哪些用户受益、哪些受损，避免"平均好看但部分用户受损"的问题。

衡量分层效果有几个维度：第一是分层稳定性——同一用户在不同时间窗口的分层标签是否稳定，频繁变动说明分层不可靠；第二是业务指标提升——分层后差异化策略是否带来了整体DAU、时长、留存的提升；第三是分群间差异——不同分群用户的行为指标是否有显著差异，如果差异不大说明分层没有区分度；第四是覆盖率——核心分层能否覆盖大部分有价值用户，比如我的特征筛选对核心用户定义口径的覆盖率达到95.2%。

我在实践中还有一个经验：用户分层不是一次性的，需要定期更新。核心用户的定义和特征会随产品阶段、季节、内容供给变化而变化，需要持续监控和迭代。比如我在CCA分析中就发现四五月份和六七月份的强相关品类有变化，说明用户的内容偏好是动态的，分层策略也需要随之调整。
