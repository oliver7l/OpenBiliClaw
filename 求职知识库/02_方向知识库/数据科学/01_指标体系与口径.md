## 一、指标体系分层设计

我在腾讯QQ看点和QB（QQ浏览器）做数据科学时，搭建了从北极星指标到过程指标再到漏斗指标的完整三层指标体系。指标体系的设计原则是：**北极星定方向、过程指标定抓手、漏斗指标定瓶颈**，三层互相校验、逐层下钻。

### 1.1 三层指标架构总览

```
┌─────────────────────────────────────────────────────────────┐
│                    北极星指标（North Star）                    │
│  DAU / 信息流DAU / 人均使用时长 / 月活跃天数                   │
│  意义：衡量产品整体健康度，所有策略最终服务于此                  │
└──────────────────────────┬──────────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────────┐
│                    过程指标（Process Metrics）                  │
│  曝光PV/UV → CTR → 消费VV/PV → 完播率 → 互动率 → 关注率       │
│  意义：定位策略执行效果，是算法/运营迭代的直接抓手                │
└──────────────────────────┬──────────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────────┐
│                    漏斗指标（Funnel Metrics）                   │
│  大盘DAU → 信息流DAU → 曝光UV → 点击UV → 消费UV → 互动UV      │
│  意义：逐层转化率定位链路瓶颈，指导资源投入优先级                │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 北极星指标层

| 指标名 | 定义 | 设计理由 | 口径注意事项 |
|--------|------|----------|-------------|
| **DAU（日活跃用户）** | 当日有活跃行为的去重用户数 | 产品规模的最直接衡量 | 有宽口径和严口径之分，宽口径包含所有启动行为，严口径通常要求有核心场景真实曝光 |
| **信息流DAU** | 当日有信息流真实曝光的去重用户数 | 推荐系统真正影响的用户群 | 必须排除延迟上报、纯浏览器用户、僵尸用户 |
| **人均使用时长** | 产品使用总时长 / DAU | 衡量用户消费深度，推荐质量的最终体现 | 注意时长统计的起止定义（前台时长vs总时长） |
| **月活跃天数** | 用户一个月内的活跃天数 | 比"使用次数"更能反映用户依赖度 | 一周内使用5天 vs 一天内使用5次，粘性完全不同（来源：QB分析handbook） |

> **关键洞察**：月活跃天数是比使用次数更好的粘性指标。用户"一周内使用了5次"并不反映依赖度——这5次可能集中在一天内连续尝试后就不再使用；但"一周内使用了5天"意味着7天中有5天都在使用，哪怕每天只用一次，也是强粘性（来源：QB分析handbook）。

### 1.3 过程指标层

过程指标是算法迭代和运营策略的直接抓手，我在精探（搜索推荐）和RS（推荐系统）业务中搭建了完整的过程指标体系。

#### 1.3.1 精探业务统计报表指标

精探业务是搜索+推荐融合场景，指标覆盖从请求到点击的全链路：

| 指标类别 | 指标名 | 计算口径 | 用途 |
|----------|--------|----------|------|
| **流量指标** | 请求UV | 发起请求的去重用户数 | 衡量场景覆盖广度 |
| **流量指标** | 请求PV | 发起请求的总次数 | 衡量场景使用频次 |
| **流量指标** | 有效PV | 排除异常/空请求后的有效请求数 | 过滤无效流量，确保分母准确 |
| **召回指标** | 召回PV | 有召回结果的请求数 | 衡量召回覆盖率 |
| **召回指标** | 召回词数 | 召回结果中的词条总数 | 衡量召回丰富度 |
| **召回指标** | 模块召回率 | 召回PV / 请求PV | 核心召回质量指标，衡量有多少请求能召回出结果 |
| **召回指标** | 平均召回词数 | 召回词数 / 召回PV | 衡量单次召回的丰富度 |
| **曝光指标** | 曝光PV | 结果实际展示的次数 | 衡量推荐覆盖 |
| **曝光指标** | 曝光词数 | 曝光结果中的词条总数 | 衡量曝光丰富度 |
| **曝光指标** | 模块曝光率 | 曝光PV / 请求PV（或召回PV） | 衡量召回结果到实际曝光的转化 |
| **曝光指标** | 平均曝光词数 | 曝光词数 / 曝光PV | 衡量单次曝光的丰富度 |
| **点击指标** | 点击PV | 用户点击的总次数 | 衡量推荐效果的绝对值 |
| **点击指标** | 点击UV | 有点击行为的去重用户数 | 衡量有多少用户产生了点击 |
| **点击指标** | 请求CTR（模块CTR） | 点击PV（词）/ 请求PV | 以请求为分母的点击率，衡量整体请求的点击效率 |
| **点击指标** | 曝光CTR（模块CTR） | 点击PV（词）/ 曝光PV | 以曝光为分母的点击率，衡量曝光内容的精准度 |
| **点击指标** | 词曝光CTR | 词点击 / 曝光PV | 按词条维度的点击率 |
| **点击指标** | UV请求CTR | 点击用户 / 请求用户 | 用户维度的请求点击率 |
| **点击指标** | UV曝光CTR | 点击用户 / 曝光用户 | 用户维度的曝光点击率 |
| **结果页指标** | 结果页点击 | 结果页上的点击次数 | 衡量结果页交互 |
| **结果页指标** | 结果页点击率 | 结果页点击 / 结果页曝光 | 结果页转化效率 |

（以上指标口径来源：统计报表.txt - 精探业务统计报表）

#### 1.3.2 精探系统统计报表指标

系统层面的统计报表关注推荐链路各阶段的候选量变化和模型预估准确性：

| 指标名 | 计算口径 | 用途 |
|--------|----------|------|
| **召回队列** | 各召回通道的标识 | 区分多路召回来源 |
| **召回数** | 各通道召回的词条个数 | 衡量各路召回的产出量 |
| **召回占比** | 召回词个数 / 总词个数 | 衡量各路召回的贡献占比 |
| **初排候选** | 粗排后的候选词个数 | 衡量粗排筛选后的候选量 |
| **初排占比** | 初排候选词个数 / 总词个数 | 粗排筛选比例 |
| **精排候选** | 精排后的候选词个数 | 精排筛选后的候选量 |
| **精排占比** | 精排候选词个数 / 总词个数 | 精排筛选比例 |
| **展现量** | 推送给前端的结果量 | 实际下发量 |
| **展现占比** | 展现量 / 总候选量 | 最终展现比例 |
| **曝光量** | 实际被用户看到的量 | 真实曝光 |
| **曝光CTR** | 点击量 / 曝光量 | 真实点击率 |
| **预估CTR** | 模型预估CTR取平均 | 模型预估值 |
| **预估偏差** | 预估CTR - 曝光CTR | 衡量模型预估准确性，校准的核心指标 |

（以上指标口径来源：统计报表.txt - 精探系统统计报表）

> **面试口述版**：我在腾讯做精探业务时，统计报表分业务层和系统层两套。业务层覆盖从请求UV/PV、有效PV、召回PV/召回词数、模块召回率，到曝光PV/曝光词数、模块曝光率，再到点击PV/UV、请求CTR、曝光CTR、词曝光CTR、UV请求/曝光CTR，最后是结果页点击和点击率。系统层关注召回队列→初排候选→精排候选→展现量→曝光量的逐级漏斗，每级都有占比指标，另外还有曝光CTR、预估CTR和预估偏差（预估-曝光），预估偏差是模型校准的核心指标。

#### 1.3.3 RS业务与系统统计报表

RS（推荐系统）业务的统计报表与精探类似，但不包含召回词数相关指标，更聚焦于推荐场景的请求-曝光-点击链路。RS系统报表同样关注召回→初排→精排→展现→曝光的漏斗和预估偏差。

（来源：统计报表.txt - RS业务统计报表、RS系统统计报表）

### 1.4 漏斗指标层

漏斗指标用于定位用户转化链路中的瓶颈环节。我在QB做大盘到信息流的路径漏斗分析时，搭建了完整的漏斗指标体系：

```
QB大盘流水表（每天1.3亿人）
    │ join 严口径DAU
    ▼
严口径DAU（8000万）
    │ 刨除延迟上报（非今天行为）
    ▼
有效DAU（6900万）
    │ 信息流场景渗透
    ▼
信息流用户（4100万，不刨除延迟前4500万）
    │ 曝光
    ▼
曝光UV
    │ 点击
    ▼
点击UV
    │ 消费
    ▼
消费UV
    │ 互动
    ▼
互动UV
```

（数据来源：qb大盘到qb信息流路径漏斗.txt）

> **口径红线**：QB大盘流水表每天1.3亿人，但join严口径DAU后只剩8000万，刨除延迟上报后仅剩6900万，其中信息流用户只有4100万。如果直接用1.3亿流水表做分母，所有转化率都会被严重低估。做漏斗分析时必须明确每一层的口径定义和过滤条件（来源：qb大盘到qb信息流路径漏斗.txt）。

## 二、QB分析Handbook：分析框架与指标体系

我在QB团队时，内部有一份持续更新的分析handbook，是我做指标体系和数据分析的方法论基石。

### 2.1 分析师核心素养

Handbook强调分析师要永远问自己三个问题：
1. **我是否真的找到了一个值得解决的问题？**
2. **我是否真的很想或者能够解决它？**
3. **我所提出的解决方案或者归因是否真的正确？**

同时借鉴滴滴分析师十条，核心原则包括：
- 分析师的核心能力是**思辨**
- 对讲真话负责，保持中立
- 论据充分，论证严谨，观点简明
- **数据先于观点，而不是观点先于数据**
- 不要把问题复杂化，也不要惧怕复杂度
- **分析什么问题，往往比用什么方法更重要**
- 好的分析师给别人输入，而不只是帮别人输出
- 分析没有任何价值，除非洞见改变了什么其他的东西
- 如果可能应该基于问题收集数据，而不只是基于数据来问问题
- 不是所有问题都可以分析出答案，以开放的心态采纳其他的观点

（来源：QB分析handbook）

### 2.2 九维分析框架

Handbook定义了九个分析维度，构成完整的业务分析框架：

| 分析维度 | 核心问题 | 关键指标 |
|----------|----------|----------|
| **指标体系大盘** | 整体健康度如何？ | DAU、时长、留存、活跃度分布 |
| **App获取分析** | 获客效率如何？ | 渠道ROI、渠道留存、获客成本 |
| **用户画像分析** | 用户是谁？ | 人口属性、兴趣标签、TGI |
| **用户粘性分析** | 用户有多依赖产品？ | 月活跃天数、使用频次、间隔天数 |
| **用户生命周期流转** | 用户在各阶段如何流转？ | 新增→成长→成熟→衰退→沉默转化率 |
| **核心功能拆解** | 用户真的在用核心功能吗？ | 功能渗透率、使用频次、Magic Number |
| **行为路径分析** | 用户主操作路径是什么？ | 路径分布、Aha Moment、操作流断点 |
| **用户使用时长分析** | 用户用了多久？分布如何？ | 时长分布、人均时长、异常点 |
| **跨平台分析** | 跨平台用户占比？ | 移动端/PC端重合度、跨端导流 |

（来源：QB分析handbook）

### 2.3 渠道ROI评估方法

业内通行的渠道评估方法是对以下六个角度打分（十分制，取平均分）：

| 评估角度 | 评估内容 |
|----------|----------|
| **成本** | 预计花费 |
| **定向** | 是否容易接触到目标受众？收集的信息可以详细到哪一步 |
| **控制** | 在多大程度可以控制试验？实验一旦开始，能否终止和调整 |
| **时间投入** | 启动试验需要多久 |
| **产出时间** | 多久拿到结果 |
| **规模** | 渠道规模量 |

（来源：QB分析handbook）

### 2.4 欲望-摩擦=转化框架

Handbook提出了一个核心的产品分析公式：

> **欲望 - 摩擦 = 转化**

这个公式用于度量产品过程中出现的摩擦。核心问题包括：
- 一个新客户在一段时间内是否完成了我们预期用户完成的行为？
- 我们改进了某个产品流程，期待改善用户体验、增加用户留存，如何验证？
- 想判断某项产品改动是否奏效，新增了一个功能，观察是否有用户因新增功能而多使用产品几个月？

（来源：QB分析handbook）

### 2.5 Handbook中的关键分析洞察

从handbook的分析实例中，我提炼了以下关键洞察：

| 分析领域 | 洞察 | 业务启示 |
|----------|------|----------|
| **大盘概览** | 下半年后QB活跃天数分布在衰退，月活跃天数10天以内的用户比例在增加 | 用户整体粘性下降，需要关注低活用户转化 |
| **App获取** | 回流用户整体活跃度弱于新增用户，显著弱于留存用户 | 回流用户需要特殊的召回和激活策略 |
| **用户粘性** | QB活跃用户留存优势明显，但新用户留存没有优势甚至偶尔劣势 | 新用户留存是重点突破方向 |
| **feeds消费** | 看热点的用户群留存明显高于其他群组 | 引导用户"看热点"是提升留存的有效手段 |
| **搜索用户** | 命中搜索直达的用户，留存率在以肉眼可见的速度变好 | 搜索直达是提升留存的关键功能 |
| **小说tab** | 用户留存在显著变差 | 小说业务需要专项治理 |
| **核心功能-摄像头** | 名画识别UV比植物高，但PV/UV接近1，说明名画是一次性需求，植物是多次性需求 | 不同功能需要不同的交互和运营策略，名画用户可导流到植物 |
| **大资讯-feeds推荐** | feeds推荐的曝光UV一直在涨，CTR从9月以来变化不大 | 推荐覆盖在扩大，但精准度没有同步提升 |
| **大资讯-图文消费** | feeds推荐的图文消费UV和PV一直在降 | 图文消费在萎缩，需要关注内容供给和推荐策略 |
| **大资讯-视频vs小视频** | feeds推荐视频的CTR一直在降，小视频的CTR一直在涨 | 内容形态在迁移，小视频是增长方向 |

（以上洞察来源：QB分析handbook）

> **面试口述版**：我在QB做分析时，handbook是我的方法论基石。核心原则是"数据先于观点"和"分析什么问题比用什么方法更重要"。分析框架覆盖九个维度：大盘、获客、画像、粘性、生命周期、核心功能、行为路径、时长、跨平台。渠道评估用六维打分法：成本、定向、控制、时间投入、产出时间、规模。产品分析的核心公式是"欲望-摩擦=转化"。几个关键洞察：月活跃天数比使用次数更能衡量粘性；看热点的用户留存最高；搜索直达用户留存变好最快；名画识别是一次性需求而植物是多次性需求；视频CTR在降而小视频CTR在涨。

## 三、指标口径定义与常见陷阱

### 3.1 CTR的多种口径

CTR（点击率）是最常用也最容易混淆的指标。我在精探业务中同时维护了多种CTR口径，每种口径的分母不同，含义也不同：

| CTR类型 | 计算公式 | 分母含义 | 适用场景 |
|---------|----------|----------|----------|
| **请求CTR（模块CTR）** | 点击PV（词）/ 请求PV | 所有发起的请求 | 衡量整体场景的点击效率，包含无召回/无曝光的请求 |
| **曝光CTR（模块CTR）** | 点击PV（词）/ 曝光PV | 实际有曝光的请求 | 衡量曝光内容的精准度，排除无曝光请求 |
| **词曝光CTR** | 词点击 / 曝光PV | 按词条维度 | 衡量单个词条的点击效率 |
| **UV请求CTR** | 点击用户 / 请求用户 | 用户维度 | 衡量有多少比例的请求用户产生了点击 |
| **UV曝光CTR** | 点击用户 / 曝光用户 | 用户维度 | 衡量有多少比例的曝光用户产生了点击 |

> **口径陷阱**：请求CTR和曝光CTR的差异可能非常大。如果模块召回率低（很多请求没有召回结果），请求CTR会远低于曝光CTR。做AB实验对比时，必须明确用的是哪种CTR口径，否则结论可能完全相反（来源：统计报表.txt）。

### 3.2 预估偏差与模型校准

在推荐系统中，模型预估CTR和真实曝光CTR之间的偏差是关键指标：

- **预估CTR**：模型对每个曝光item的pCTR取平均
- **曝光CTR**：真实点击量 / 真实曝光量
- **预估偏差** = 预估CTR - 曝光CTR

预估偏差的意义：
- 偏差>0：模型高估了点击率，需要下调
- 偏差<0：模型低估了点击率，需要上调
- 偏差接近0：模型校准良好

在oCPX广告出价场景中，预估偏差直接影响出价准确性和ROI。我在OPPO做广告算法时，多位置校准偏差从30%降到20%（与简历口径一致），就是通过校准模型预估偏差实现的。

### 3.3 宽口径vs严口径DAU

DAU是最容易出口径问题的指标：

| 口径 | 定义 | 典型数值（QB） | 适用场景 |
|------|------|----------------|----------|
| **流水表宽口径** | 所有有日志记录的用户 | 每天1.3亿人 | 数据采集完整性监控 |
| **宽口径DAU** | 当日有任意启动行为的用户 | - | 产品整体规模（财报口径） |
| **严口径DAU** | 当日有核心场景真实曝光的用户 | 8000万（join后） | 推荐/内容业务评估 |
| **有效DAU** | 刨除延迟上报后的严口径DAU | 6900万 | 精确的用户行为分析 |
| **信息流DAU** | 当日有信息流真实曝光的用户 | 4100万（刨除延迟后） | 推荐系统直接负责的用户群 |

（数据来源：qb大盘到qb信息流路径漏斗.txt）

> **口径陷阱**：用宽口径DAU做分母评估推荐效果，会因为包含大量纯浏览器用户和僵尸用户而严重低估推荐的真实影响力。我在QB做信息流推荐评估时，始终坚持用严口径信息流DAU（4100万）作为分母，而不是大盘流水表的1.3亿（来源：qb大盘到qb信息流路径漏斗.txt）。

### 3.4 PV/UV混淆

| 指标 | 定义 | 注意事项 |
|------|------|----------|
| **PV（Page View）** | 页面/内容被访问的总次数 | 不去重，反映使用频次 |
| **UV（Unique Visitor）** | 去重后的独立用户数 | 反映覆盖广度 |
| **PV/UV** | 人均访问次数 | 反映单用户使用深度 |

> **典型案例**：QB摄像头功能中，名画识别UV比植物高，但PV/UV接近1。这说明名画的识别需求往往是一次性的（用户识别一次就走了），而植物的识别需求是多次性的（用户反复识别不同植物）。同样的UV，不同的PV/UV，需要完全不同的运营策略（来源：QB分析handbook）。

### 3.5 人均时长的分子分母陷阱

在统计报表中，人均时长和人均播放VV的分子分母容易写反：

- **人均时长** = 总时长 / 播放用户数（不是总VV/播放用户数）
- **人均播放VV** = 总VV / 播放用户数（不是总时长/播放用户数）

我在微视手Q关注页做指标时，发现原表中这两个指标的分子分母写反了，修正后数据才合理（来源：推荐系统07_指标与评估文档中的手Q关注页指标说明）。

### 3.6 曝光频次与点击率的倒U型关系

我在统一数据分析中发现了一个重要规律：**同一账号被曝光的次数与点击率呈倒U型关系**。

以近一天内同一账号被曝光次数为例：

| 曝光次数 | 被曝光账号数 | 总曝光次数 | 点击次数 | 对应点击率 |
|----------|------------|-----------|---------|-----------|
| 1次 | 20,473,719 | 20,473,719 | 18,438 | **0.09%** |
| 2次 | 7,206,030 | 14,412,060 | 243,697 | **1.69%** |
| 3次 | 2,662,168 | 7,986,504 | 140,137 | **1.75%** |
| 4次 | 1,211,125 | 4,844,500 | 66,963 | 1.38% |
| 5次 | 576,185 | 2,880,925 | 31,911 | 1.11% |
| 6次 | 314,884 | 1,889,304 | 16,599 | 0.88% |
| 7次 | 181,670 | 1,271,690 | 9,346 | 0.73% |
| 8次 | 112,890 | 903,120 | 6,115 | 0.68% |
| 9次 | 73,143 | 658,287 | 3,872 | 0.59% |
| 10次 | 48,952 | 489,520 | 2,346 | 0.48% |
| 10+次 | 153,888 | 2,608,513 | 7,802 | 0.30% |

（数据来源：统一数据分析记录.txt - 近一天同一账号曝光次数分布）

**近七天**的趋势一致：1次曝光点击率0.10%，2次1.86%，3次1.80%，之后逐步下降，10+次仅0.21%（来源：统一数据分析记录.txt）。

> **关键结论**：
> 1. **1次曝光的点击率极低（0.09%）**：只曝光一次用户还没形成认知，几乎不会点击
> 2. **2-3次曝光点击率最高（1.69%-1.75%）**：这是曝光的"甜区"，用户形成了认知但还没疲劳
> 3. **超过3次后点击率持续下降**：曝光疲劳效应，用户反复看到同一账号会产生厌烦
> 4. **10次以上点击率仅0.30%**：严重过度曝光，不仅没有增量价值，还可能产生负反馈

这个发现直接指导了我们的曝光频次控制策略：对同一账号的推荐曝光控制在2-3次为最优，超过5次需要降权，超过10次应该停止曝光。

### 4.6 视频质量过滤实验结果

我做过视频清晰度过滤的AB实验，结果如下：

| 实验条件 | 曝光数 | feed个数 | 曝光占比 | feed占比 | 正例比 | 点赞率 | 关注率 | 点击评论率 | 平均停留时长 |
|----------|--------|---------|---------|---------|--------|--------|--------|-----------|------------|
| **去除清晰度<=3** | 64,798,018 | 7,202 | 63.13% | 67.51% | 35.92% | 1.58% | 0.092% | 1.38% | 0.1808 |
| **全部（对照组）** | 64,415,984 | 7,171 | 62.76% | 67.22% | 35.88% | 1.59% | 0.093% | 1.38% | 0.1808 |

（数据来源：数据分析.txt）

> **分析结论**：
> 1. 去除清晰度<=3的视频后，曝光占比63.13%，feed占比67.51%——说明低清晰度视频占了约1/3的曝光
> 2. 但去除后正例比、点赞率、关注率、平均停留时长几乎没有变化
> 3. 最初只能剔除2.6%的feedid，影响3.8%的曝光占比，感觉影响力太小
> 4. 把清晰度要求从严（<=2去除→<=3去除）后，影响面扩大到63%曝光，但效果指标仍无显著差异
> 5. 结论：清晰度过滤对用户体验的影响不如预期，可能是因为用户对低清晰度视频的容忍度较高，或者低清晰度视频集中在特定内容类型（如动漫、老剧），这些内容的用户对清晰度不敏感

## 六、指标体系建设的最佳实践

### 6.1 指标体系建设五步走

```
第一步：明确业务目标 → 确定北极星指标
    │
第二步：拆解业务链路 → 确定过程指标（每层链路对应一组指标）
    │
第三步：定义转化漏斗 → 确定漏斗指标（逐层转化率）
    │
第四步：统一口径规范 → 数据字典、字段说明、计算公式、分母分子定义
    │
第五步：建立监控告警 → 日报/周报、异动告警、下钻维度
```

### 6.2 指标口径统一的checklist

在定义任何一个新指标时，我都会按以下checklist确认口径：

- [ ] **分子定义**：分子统计的是什么行为？去重还是不去重？时间窗口是什么？
- [ ] **分母定义**：分母统计的是什么人群/行为？是否需要过滤无效数据？
- [ ] **时间口径**：是T+1还是实时？数据延迟如何处理？
- [ ] **去重口径**：按用户ID去重还是按设备ID去重？跨端如何处理？
- [ ] **过滤条件**：是否排除测试账号、内部员工、异常流量？
- [ ] **维度拆分**：支持哪些下钻维度（端、版本、渠道、用户群、内容类型）？
- [ ] **数据来源**：底层表是什么？是否有多个数据源需要对齐？
- [ ] **历史可比性**：口径变更时是否有回溯？新旧口径如何切换？

### 6.3 指标异动分析的通用流程

```
指标异动
    │
    ▼
1. 确认异动真实性 → 排除数据上报问题、口径变更、统计错误
    │
    ▼
2. 量化异动幅度 → 环比/同比/绝对值/相对值，确认是否在正常波动范围
    │
    ▼
3. 维度下钻定位 → 按端、版本、渠道、用户群、内容类型、时间分段下钻
    │
    ▼
4. 漏斗拆解 → 定位异动发生在漏斗的哪一层
    │
    ▼
5. 归因分析 → 内部因素（策略变更、产品迭代）vs 外部因素（竞品、季节、事件）
    │
    ▼
6. 验证因果 → AB实验回滚验证、DID/PSM等因果推断方法
    │
    ▼
7. 结论与行动 → 输出归因结论和改进建议
```

### 6.4 留存指标体系

留存是衡量产品长期价值的核心指标，我在QB搭建了完整的留存指标体系：

| 留存类型 | 定义 | 计算公式 | 用途 |
|----------|------|----------|------|
| **次日留存** | 新增用户在第2天仍活跃的比例 | 第2天活跃用户数 / 第1天新增用户数 | 衡量产品首日体验，最敏感的留存指标 |
| **7日留存** | 新增用户在第7天仍活跃的比例 | 第7天活跃用户数 / 第1天新增用户数 | 衡量中期留存，反映用户是否形成使用习惯 |
| **30日留存** | 新增用户在第30天仍活跃的比例 | 第30天活跃用户数 / 第1天新增用户数 | 衡量长期留存，反映产品核心价值 |
| **周留存** | 本周活跃用户在下周仍活跃的比例 | 下周活跃用户数 / 本周活跃用户数 | 衡量存量用户粘性，不受新增波动影响 |
| **月留存** | 本月活跃用户在下月仍活跃的比例 | 下月活跃用户数 / 本月活跃用户数 | 衡量长期用户粘性 |

> **留存分析的关键洞察**（来源：QB分析handbook）：
> - QB活跃用户留存优势明显，但新用户留存没有优势甚至偶尔劣势——新用户留存是重点突破方向
> - 看热点的用户群留存明显高于其他群组——引导用户"看热点"是提升留存的有效手段
> - 命中搜索直达的用户，留存率在以肉眼可见的速度变好——搜索直达是提升留存的关键功能
> - 小说tab用户留存在显著变差——小说业务需要专项治理

### 6.5 用户生命周期指标体系

用户生命周期管理是数据科学的重要应用场景，我在QB搭建了覆盖全生命周期的指标体系：

| 生命周期阶段 | 定义 | 核心指标 | 转化目标 |
|-------------|------|----------|----------|
| **新增期** | 首次使用产品的用户 | 新增用户数、新增渠道分布、首日行为、首日留存 | 从新增→成长，让用户完成Aha Moment |
| **成长期** | 开始频繁使用但尚未形成习惯的用户 | 活跃天数、使用频次、功能渗透率、Magic Number达成率 | 从成长→成熟，让用户达到Magic Number |
| **成熟期** | 稳定高频使用的核心用户 | 月活跃天数、人均时长、消费深度、互动率 | 维持成熟状态，防止衰退 |
| **衰退期** | 活跃度开始下降的用户 | 活跃天数环比下降、使用间隔变长、消费深度下降 | 从衰退→成熟，通过召回干预阻止衰退 |
| **沉默期** | 连续N天未活跃的用户 | 沉默用户数、沉默时长分布、沉默前最后行为 | 从沉默→召回，通过Push/红点/活动召回 |

> **生命周期分析的核心问题**（来源：QB分析handbook）：
> - 为什么有些用户过去很活跃，现在衰退了？
> - 为什么同一群用户，有些变活跃了，有些却变衰退了？两者的diff是什么？
> - 平均一个用户的生命轨迹是怎样的？
> - 有没有一个衰退的拐点？有没有一个活跃的拐点？
> - 是否存在一个Magic Number，使得用户做了a次b行为后，留存率大大提升？

### 6.6 互动与社交指标体系

互动行为是用户参与度的直接体现，也是推荐系统的重要信号。我在微视/QQ看点搭建了完整的互动指标体系：

| 互动类型 | 指标名 | 计算公式 | 业务含义 |
|----------|--------|----------|----------|
| **点赞** | 点赞率 | 点赞数 / 曝光数 | 内容认可度的最直接衡量 |
| **评论** | 评论率 | 评论数 / 曝光数 | 内容引发讨论的能力 |
| **分享** | 分享率 | 分享数 / 曝光数 | 内容传播价值，分享带来的新用户是重要增长来源 |
| **收藏** | 收藏率 | 收藏数 / 曝光数 | 内容长期价值，收藏用户的留存通常更高 |
| **关注** | 关注率 | 关注数 / 曝光卡片数 | 社交推荐核心指标，关注行为带来长期消费价值 |
| **负反馈** | 不感兴趣率 | 不感兴趣点击数 / 曝光数 | 推荐质量的负向指标，过高说明推荐不精准 |

> **互动指标的特殊价值**：互动行为（尤其是关注和收藏）的价值不在即时转化，而在长期留存。用户关注了一个创作者后，后续会持续消费其内容，形成稳定的消费习惯。我在微视做关注推荐时，发现有关注行为的用户次日留存和长期留存都显著高于无关注行为的用户，因此关注率是比CTR更有长期价值的指标。这也是为什么社交推荐的评估不能只看CTR，必须关注关注率和长期留存。

## 七、指标治理与数据质量监控

### 7.1 指标治理体系

指标体系建成后不是一成不变的，需要持续治理。我在腾讯建立了指标治理的四件套：

| 治理环节 | 具体动作 | 频率 | 负责人 |
|----------|----------|------|--------|
| **指标注册** | 新指标必须在指标平台注册，填写中文名、英文名、计算公式、分子分母、数据来源、更新频率、负责人 | 实时 | 指标提出人 |
| **指标审核** | 数据科学团队审核指标口径是否合理、是否与已有指标重复、计算公式是否正确 | 每个新指标 | 数据科学负责人 |
| **指标下线** | 长期无人使用的指标定期清理，避免指标膨胀 | 每季度 | 数据治理团队 |
| **口径变更** | 指标口径变更必须走变更流程，通知所有使用方，提供新旧口径对比数据 | 每次变更 | 指标负责人 |

### 7.2 数据质量监控的六个维度

| 监控维度 | 监控内容 | 告警规则示例 |
|----------|----------|--------------|
| **完整性** | 数据是否齐全，有无缺失分区、缺失字段 | 某分区数据量为0或低于历史均值50% |
| **准确性** | 数据是否正确，有无异常值 | 核心指标环比波动超过3个标准差 |
| **一致性** | 不同表/不同系统的同一指标是否一致 | A表DAU与B表DAU差异超过1% |
| **及时性** | 数据是否按时产出 | 数据产出时间超过SLA约定时间2小时 |
| **唯一性** | 数据是否有重复 | 主键重复率超过0.1% |
| **有效性** | 数据是否在合理范围内 | 时长为负数、CTR超过100% |

### 7.3 指标异动的常见数据原因

在排查指标异动时，首先要排除数据层面的原因，而不是直接归因到业务：

| 数据原因 | 表现 | 排查方法 |
|----------|------|----------|
| **上报延迟** | 当天数据偏低，第二天回补后恢复正常 | 对比T+1和T+2的数据，看是否回补 |
| **埋点变更** | 某个指标在特定版本后突然变化 | 查版本发布记录，对比新旧版本埋点逻辑 |
| **ETL故障** | 数据量异常减少或指标为0 | 查ETL任务运行日志，看是否有失败任务 |
| **口径变更** | 指标在某天突然跳变，且持续维持新水平 | 查指标变更记录，对比新旧口径计算公式 |
| **数据源切换** | 底层表更换后指标变化 | 查数据表血缘，看是否有数据源变更 |
| **去重逻辑变化** | UV类指标突然变化 | 查去重字段是否变更（用户ID vs 设备ID） |

> **面试口述版**：我在腾讯做指标治理时，建立了指标注册-审核-下线-变更的四件套流程，新指标必须在平台注册并经过审核才能使用。数据质量监控覆盖六个维度：完整性（有无缺失）、准确性（有无异常值）、一致性（跨表是否一致）、及时性（是否按时产出）、唯一性（有无重复）、有效性（是否在合理范围）。排查指标异动时，第一步永远是排除数据原因——上报延迟、埋点变更、ETL故障、口径变更、数据源切换、去重逻辑变化，这些都可能导致指标异动，但跟业务本身无关。我见过太多分析师一看到DAU跌了就开始归因业务，结果查了半天发现是埋点上报延迟了。

## 八、跨团队指标对齐与沟通

### 8.1 指标对齐的常见冲突

在实际工作中，不同团队对同一指标的理解经常不一致，导致沟通效率低下甚至决策失误：

| 冲突场景 | 典型表现 | 解决方案 |
|----------|----------|----------|
| **产品vs数据** | 产品说"DAU涨了"，数据说"DAU没涨"——产品用的是宽口径，数据用的是严口径 | 建立统一指标平台，所有团队使用同一套指标定义 |
| **算法vs运营** | 算法说"CTR提升了5%"，运营说"用户反馈变差了"——算法看的是曝光CTR，运营关注的是用户体验和长期留存 | 建立多维度指标体系，不仅看过程指标还要看北极星指标和护栏指标 |
| **前端vs后端** | 前端统计的曝光量和后端统计的不一致——前端按渲染成功统计，后端按下发成功统计 | 明确曝光定义：是下发成功、渲染成功、还是用户可见（在视口中停留超过N秒） |
| **业务线之间** | A业务说自己贡献了X DAU，B业务也说贡献了X DAU——两边都用去重前的口径，存在大量重合用户 | 建立用户去重和归因规则，明确多业务使用用户的归属逻辑 |

### 8.2 曝光定义的三个层次

曝光是最容易产生口径分歧的指标之一，我总结了三个层次的曝光定义：

| 层次 | 定义 | 优点 | 缺点 | 适用场景 |
|------|------|------|------|----------|
| **下发曝光** | 后端将内容推送给前端即算曝光 | 数据稳定、延迟低、易于统计 | 可能包含前端渲染失败的情况，高估真实曝光 | 系统层面监控、推荐链路分析 |
| **渲染曝光** | 前端成功渲染内容即算曝光 | 比下发曝光更接近真实用户可见 | 可能包含渲染后用户未看到的情况（如在屏幕外） | 通用业务分析、AB实验 |
| **有效曝光（可见曝光）** | 内容在用户视口中停留超过一定时间（如1秒）才算曝光 | 最准确反映用户真实看到的内容 | 实现复杂、依赖前端能力、数据延迟较高 | 广告计费、精准效果评估 |

> **关键洞察**：在推荐系统中，下发曝光、渲染曝光、有效曝光之间的差异可能很大。如果用户网络差，下发成功但渲染失败的比例会升高；如果内容在屏幕下方，渲染成功但用户没看到的比例会升高。做CTR分析时必须明确用的是哪种曝光定义，否则CTR的绝对值没有可比性（来源：统计报表.txt中的曝光PV定义，结合实际工程经验）。

### 8.3 指标沟通的STAR框架

向非技术团队（产品、运营、管理层）汇报指标时，我用STAR框架组织内容：

- **S（Situation 背景）**：当前指标处于什么水平，历史趋势如何
- **T（Task 目标）**：我们期望达到什么目标，差距有多大
- **A（Action 行动）**：为了达成目标，我们做了什么/计划做什么
- **R（Result 结果）**：行动带来了什么结果，数据验证如何

> **面试口述版**：跨团队指标对齐是数据科学家的核心能力之一。我遇到过最多的冲突是产品用宽口径DAU、数据用严口径DAU，两边数字对不上就开始吵架。我的解决方案是推动建立统一指标平台，所有团队使用同一套指标定义。曝光定义也是一个重灾区——下发曝光、渲染曝光、有效曝光三个层次差异很大，广告计费必须用有效曝光，系统监控用下发曝光就够了。向非技术团队汇报时我用STAR框架：背景、目标、行动、结果，先讲清楚现在什么情况、我们要去哪、做了什么、效果如何，而不是一上来就甩一堆数字。

## 九、面试话术

### 7.1 口述版：指标体系建设

> 我在腾讯QQ看点和QB做数据科学时，搭建了三层指标体系：北极星指标是DAU、信息流DAU、人均使用时长和月活跃天数。这里特别要提月活跃天数——它比"使用次数"更能衡量粘性，一周用5天和一天用5次是完全不同的概念。过程指标覆盖从请求UV/PV、召回PV/召回率、曝光PV/曝光率，到点击PV/UV、请求CTR、曝光CTR、词曝光CTR、UV维度CTR，再到消费VV、完播率、互动率、关注率。漏斗指标是从大盘DAU到信息流DAU再到曝光点击消费互动的逐层转化率。
>
> 口径方面我踩过很多坑。最典型的是CTR有至少五种口径：请求CTR（点击/请求PV）、曝光CTR（点击/曝光PV）、词曝光CTR、UV请求CTR、UV曝光CTR，每种分母不同含义完全不同。做AB实验必须明确用哪种口径。还有DAU的宽口径和严口径——QB大盘流水表每天1.3亿人，但严口径DAU只有8000万，刨除延迟上报后6900万，信息流用户只有4100万。如果用1.3亿做分母，所有转化率都会被严重低估。
>
> 我还发现了一个重要规律：同一账号的曝光次数和点击率呈倒U型关系。1次曝光点击率只有0.09%，2-3次最高达到1.69%-1.75%，超过3次后持续下降，10次以上只有0.30%。这个发现直接指导了我们的曝光频次控制策略——最优曝光是2-3次，超过5次降权，超过10次停止曝光。

### 7.2 口述版：分析框架与方法论

> 我在QB时内部有一份分析handbook，是我的方法论基石。核心原则有三条：第一，分析师永远要问自己三个问题——是否找到了值得解决的问题、是否真的能解决它、提出的归因是否真的正确。第二，数据先于观点，而不是观点先于数据。第三，分析什么问题往往比用什么方法更重要。
>
> 分析框架覆盖九个维度：指标体系大盘、App获取分析、用户画像分析、用户粘性分析、用户生命周期流转、核心功能拆解、行为路径分析、用户使用时长分析、跨平台分析。渠道评估用六维打分法：成本、定向、控制、时间投入、产出时间、规模，十分制取平均分。产品分析的核心公式是"欲望-摩擦=转化"，用来度量产品流程中的摩擦点。
>
> 从handbook的分析实例中我提炼了几个关键洞察：看热点的用户群留存最高，引导用户看热点是提升留存的有效手段；命中搜索直达的用户留存率在快速变好；小说tab用户留存在显著变差；名画识别是一次性需求而植物是多次性需求，PV/UV都接近1但UV不同；feeds推荐视频CTR在降而小视频CTR在涨，内容形态在迁移。

### 7.3 高频Q&A

**Q：怎么搭建一套指标体系？**

A：我分五步走。第一步明确业务目标，确定北极星指标——比如推荐系统的北极星是信息流DAU和人均时长，不是CTR，因为CTR可以靠标题党提升但伤害长期留存。第二步拆解业务链路，确定过程指标——推荐链路是召回→粗排→精排→重排→曝光→点击→消费→互动，每一层对应一组指标。第三步定义转化漏斗，确定漏斗指标——从大盘DAU到信息流DAU到曝光UV到点击UV逐层转化率，定位瓶颈。第四步统一口径规范——每个指标都要有明确的分子分母定义、时间窗口、去重规则、过滤条件、数据来源，形成数据字典。第五步建立监控告警——日报周报、异动告警、多维度下钻。

**Q：CTR有哪些口径？怎么选？**

A：CTR至少有五种口径。请求CTR=点击PV/请求PV，分母是所有请求，包含无召回无曝光的，衡量整体场景效率。曝光CTR=点击PV/曝光PV，分母是有实际曝光的请求，衡量曝光内容精准度。词曝光CTR按词条维度计算。UV请求CTR=点击用户/请求用户，UV曝光CTR=点击用户/曝光用户，用户维度的转化率。选哪种取决于分析目的：评估推荐算法精准度用曝光CTR，评估整个场景效率用请求CTR，评估用户覆盖用UV维度。做AB实验必须明确口径，否则结论可能相反。我在精探业务中同时维护这五种CTR，互相校验。

**Q：DAU口径不一致会导致什么问题？你怎么处理？**

A：DAU口径不一致是数据分析中最常见也最危险的问题。以QB为例，大盘流水表每天1.3亿人，但join严口径DAU后只有8000万，刨除延迟上报后6900万，其中信息流用户只有4100万。如果用1.3亿做分母评估推荐效果，会因为包含大量纯浏览器用户和僵尸用户而严重低估推荐的真实影响力。我的处理原则是：第一，明确每个指标的适用人群——推荐系统只对严口径信息流用户负责，不用大盘宽口径。第二，在所有报表和分析文档中标注口径定义。第三，跨团队对齐口径——和产品、运营、算法团队确认大家用的是同一个DAU定义。第四，做口径影响分析——量化不同口径下指标的差异，让大家意识到口径的重要性。

**Q：曝光频次和点击率是什么关系？对推荐策略有什么指导？**

A：我在统一数据分析中发现，同一账号被曝光的次数和点击率呈倒U型关系。1次曝光点击率只有0.09%——用户还没形成认知；2次曝光1.69%，3次曝光1.75%，这是最优区间；超过3次后持续下降，4次1.38%，5次1.11%，10次0.48%，10次以上只有0.30%。近七天的数据趋势一致。这个发现对推荐策略的指导是：第一，同一账号的最优曝光频次是2-3次，低于1次用户没认知，高于3次开始疲劳。第二，需要建立曝光频次控制机制——对同一账号的曝光进行频次封顶，超过5次降权，超过10次停止曝光。第三，频次控制要和用户兴趣衰减结合——用户近期交互过的账号可以适当提高频次上限，长期未交互的应该降低。第四，这个规律也解释了为什么多样性重要——如果推荐结果总是同一批账号，即使内容相关，点击率也会因为曝光疲劳而下降。

**Q：怎么衡量模型预估的准确性？预估偏差大怎么办？**

A：模型预估准确性用预估偏差衡量，预估偏差=预估CTR-曝光CTR。偏差大于0说明模型高估了点击率，小于0说明低估了，接近0说明校准良好。在推荐系统中，预估偏差直接影响排序质量——如果模型系统性高估某类内容的CTR，这类内容会被过度曝光，挤压其他内容的展示机会。在广告oCPX出价场景中，预估偏差直接影响出价准确性和ROI——我在OPPO做广告算法时，多位置校准偏差从30%降到20%（与简历口径一致），就是通过校准实现的。预估偏差大的处理方法：第一，做校准——用保序回归（Isotonic Regression）或Platt缩放对模型输出进行后处理校准。第二，分位置校准——不同展示位置的CTR差异很大，需要按位置分别校准。第三，监控分群偏差——按用户群、内容类型、时间段分别看偏差，定位是全局偏差还是局部偏差。第四，分析偏差原因——是样本偏差（训练数据和线上分布不一致）、特征缺失、还是模型架构问题，针对性解决。

**Q：数据字典和字段规范怎么建设？**

A：我在做视频内容质量分析时，建设了完整的数据字典。首先明确源数据——我们用了三类数据：100014用户-内容交互数据（key是用户ID，value是JSON包含finder_uin、score、show、label_1/0、各行为计数字段）、100018用户-内容-时间三维数据（key是user_content_date，value是各时段行为计数）、视频质量AI分析结果（包含封面文字占比、视频平均文字占比、诱惑度分数、清晰度、推广识别等30+字段）。然后定义核心指标公式——正例比=label_1/(label_-1+label_1+label_0)，点赞率=18068_1/总分母，关注率=18068_4/总分母，点击评论率=18054_6/总分母，平均停留时长=18054_2/总分母。这里特别要注意分母一致性——所有比率都用总标签数做分母，不是曝光量。最后做字段规范文档——每个字段写明中文名、含义、取值范围、数据类型、来源表、更新频率，新人拿到文档就能直接用，不用反复问口径。

**Q：指标异动了怎么排查？**

A：我的通用流程是七步。第一步确认异动真实性——排除数据上报故障、口径变更、统计错误，先看数据链路是否正常。第二步量化异动幅度——环比同比都看，绝对值和相对值都看，确认是否超出正常波动范围（比如超过2个标准差）。第三步维度下钻定位——按端（iOS/Android）、版本、渠道、用户群（新/老/高/中/低活）、内容类型、时间段分段下钻，找到异动最集中的维度。第四步漏斗拆解——如果是转化率异动，看漏斗每一层的变化，定位是哪一层出了问题。第五步归因分析——区分内部因素和外部因素，内部因素看最近有没有策略变更、产品迭代、运营活动，外部因素看竞品、季节、热点事件。第六步验证因果——不能只看相关性，要用AB实验回滚验证或者DID/PSM等因果推断方法确认是因果关系。第七步输出结论和行动建议——不仅要说是什么原因，还要给出可执行的改进方案。我在QB做过DAU持续六周下跌647万的完整拆解，就是用这套方法论定位了红点停投、文件暑期下降、用户主启心智缺失等核心原因。

**Q：人均时长这类指标容易出什么口径问题？**

A：人均时长的口径问题主要有三类。第一类是分子分母写反——我在微视手Q关注页做指标时，发现原表中人均时长和人均播放VV的分子分母写反了。人均时长应该是总时长/播放用户数，人均播放VV应该是总VV/播放用户数，但原表写反了，修正后数据才合理。第二类是时长统计的起止定义不明确——是只统计前台时长还是包含后台时长？是从APP启动到退出还是从内容曝光到离开？不同定义下的时长差异很大。第三类是异常值处理——有些用户可能因为网络问题或APP bug导致时长统计异常（比如挂了一晚上），需要设置合理的上限（比如单日时长不超过24小时，单次session不超过N小时）。我的处理原则是：在指标定义文档中明确写清分子分母和时长统计规则，做异常值截断，定期和客户端团队对齐时长埋点的实现逻辑。

**Q：怎么判断一个指标是不是好指标？好指标的标准是什么？**

A：我判断一个指标好不好有六个标准。第一是**可衡量性**——数据能不能准确采集到，采集成本高不高，如果一个指标需要人工标注才能拿到，那就不是好指标。第二是**可解释性**——指标变化了能不能解释清楚原因，如果CTR涨了但你说不清楚是算法好了还是标题党多了，这个指标就有问题。第三是**可行动性**——指标变化了能不能指导具体行动，如果指标涨了跌了都不知道该做什么，那这个指标就是摆设。第四是**稳定性**——指标在正常情况下不应该大幅波动，如果一个指标每天上下浮动50%，那就没法用来做监控和决策。第五是**抗操纵性**——指标不容易被人为刷高，比如如果只看CTR，运营就会上标题党；如果只看曝光量，算法就会推低质量内容。所以需要多指标互相制衡。第六是**业务相关性**——指标必须和业务目标有因果关系，而不是仅仅相关。比如推荐系统不能只看CTR，因为CTR和长期留存可能是负相关的（标题党提升CTR但伤害留存），最终要看DAU和时长这些北极星指标。

**Q：北极星指标怎么选？选错了会有什么后果？**

A：北极星指标的选择要满足三个条件：第一，它必须反映用户从产品中获得的核心价值——比如QQ浏览器的核心价值是信息获取，所以北极星是DAU和人均时长，而不是搜索次数，因为搜索只是手段不是目的。第二，它必须是可衡量、可归因的——能准确采集，且团队的行动能影响它。第三，它必须是领先指标而非滞后指标——比如收入是滞后指标，DAU和时长是领先指标，DAU涨了收入迟早会涨，但收入涨了不一定代表产品健康。

选错北极星指标的后果很严重。如果选了CTR当北极星，团队就会拼命上标题党和低俗内容，短期CTR涨了但长期用户流失、DAU下降。如果选了曝光量当北极星，算法就会推大量低质量内容，用户体验恶化。我在QB做推荐时，始终坚持北极星是信息流DAU和人均时长，CTR只是过程指标，所有算法迭代最终都要看对DAU和时长的影响，而不是只看CTR提升。这也是为什么我们做AB实验时，核心指标一定是DAU和时长，CTR只是参考指标。

**Q：过程指标和北极星指标不一致怎么办？比如CTR涨了但DAU跌了。**

A：这是非常常见的情况，我的处理原则是：**北极星指标优先，过程指标辅助定位**。CTR涨了但DAU跌了，说明CTR的提升是"虚假繁荣"——可能是标题党多了、可能是推了更多低质量但吸引眼球的内容、可能是曝光位置变了（首条曝光占比增加），这些都能提升CTR但伤害用户长期体验。

具体的排查方法：第一，看CTR提升的来源——是所有内容类型的CTR都涨了，还是只有某些类型涨了？如果是低俗、标题党内容的CTR涨了，那就是内容质量问题。第二，看用户分群——是新用户CTR涨了还是老用户涨了？如果新用户CTR涨了但老用户CTR跌了，说明推荐在讨好新用户但伤害了老用户体验。第三，看消费深度指标——CTR涨了但完播率、阅读完成度、人均消费VV有没有跌？如果用户点进去很快就退出来了，说明内容质量差。第四，看长期留存——CTR涨的实验组，次日留存、7日留存有没有下降？如果留存下降了，说明这个CTR提升不可持续。

我在实践中的结论是：过程指标和北极星指标不一致时，一定以北极星指标为准。过程指标的提升如果不能转化为北极星指标的提升，就是没有价值的。这也是为什么AB实验的放量决策必须看北极星指标的显著性，而不是只看过程指标。

**Q：怎么做指标的维度下钻？下钻到什么程度合适？**

A：指标下钻是定位问题的核心手段。我常用的下钻维度有六类：第一是**用户维度**——新用户/老用户、高活/中活/低活、年龄段、性别、城市等级、手机品牌、操作系统。第二是**内容维度**——内容类型（图文/视频/小视频）、内容品类（娱乐/社会/游戏/科技等）、内容来源（PGC/UGC/运营推荐）、内容质量分层。第三是**场景维度**——首页/频道页/搜索结果页/个人中心，首启/主启/外部调起。第四是**时间维度**——小时级、天级、周级，工作日/周末，节假日/非节假日。第五是**版本维度**——APP版本、操作系统版本、机型。第六是**渠道维度**——用户来源渠道、推广渠道。

下钻到什么程度合适？我的原则是：**下钻到能定位到可行动的问题为止**。比如DAU跌了，先按用户维度下钻，发现是51岁以上用户跌了20.9%（来源：QB大盘DAU下跌.txt）；再按业务维度下钻，发现是小说低活用户跌了12.7%；再归因，发现是6月1号下架了盗版转码功能。到这一步就够了——因为已经定位到了具体原因和可行动的改进方向。不需要继续下钻到每个用户的每个行为，那样会陷入细节无法自拔。同时要注意**下钻的维度不能太多**——同时按6个维度交叉下钻，每个格子的样本量会很小，统计噪声会很大，结论不可靠。一般同时下钻2-3个维度比较合适。
