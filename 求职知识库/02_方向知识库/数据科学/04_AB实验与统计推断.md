# AB实验与统计推断方法论

---

## 一、AB实验方法论全景

我在腾讯QQ看点和QB做数据科学时，AB实验是我日常工作中最核心的决策工具。从推荐算法迭代到运营策略验证，从产品功能上线到商业化策略调整，几乎所有重要决策都要通过AB实验验证。我在腾讯视频和QQ看点使用过两套实验系统——试金石系统1.0和骡马系统，积累了从实验设计、分流、监控到分析决策的完整经验。

### 1.1 AB实验的核心价值

AB实验的本质是**通过随机分组构建反事实，建立因果关系**。在数据科学工作中，相关性分析随处可见，但因果性结论才是决策的真正依据。AB实验是因果推断的"黄金标准"——通过随机化分配实验组和对照组，使得两组用户在除了实验变量之外的所有维度上（理论上）都相同，从而将观测到的指标差异唯一归因于实验变量。

**AB实验 vs 观察性分析的对比**：

| 维度 | AB实验 | 观察性分析（DID/PSM等） |
|------|--------|------------------------|
| **因果强度** | 最强（随机化控制混杂） | 中等（只能控制已观测混杂） |
| **适用场景** | 可随机分配的策略/功能/算法 | 不可随机的自然实验/历史数据 |
| **成本** | 高（需要真实流量和时间） | 低（用历史数据即可） |
| **速度** | 慢（至少一周，通常一个月） | 快（小时级出结果） |
| **可探索性** | 低（有用户体验风险） | 高（可以快速试错） |
| **结论可信度** | 高（因果证据） | 中（需要多方法交叉验证） |

我在实践中的原则是：**能AB就AB，不能AB才上DID/PSM，并且要多做稳健性检验**（来源：模拟面试问答集_深入版）。

### 1.2 AB实验的完整工作流

```
业务问题定义
    │
    ▼
┌─ 第一步：实验设计 ──────────────────────────────┐
│  ① 提出假设（H0/H1）                              │
│  ② 定指标（主指标 + 护栏指标 + 观测指标）         │
│  ③ 算样本量（功效分析，确定最小可检测效应）       │
│  ④ 定分流单元（用户级/设备级/请求级）             │
│  ⑤ 定实验周期（覆盖完整周中周末 + 效应显现时间）  │
└──────────────────────────────────────────────────┘
    │
    ▼
┌─ 第二步：实验执行 ──────────────────────────────┐
│  ① AA实验验证分流均匀性                           │
│  ② 上线实验，小流量起步（1%-5%）                 │
│  ③ SRM（样本比率不匹配）实时监控                  │
│  ④ 数据质量监控（埋点、上报、延迟）               │
└──────────────────────────────────────────────────┘
    │
    ▼
┌─ 第三步：实验分析 ──────────────────────────────┐
│  ① 统计显著性检验（p值、置信区间）                │
│  ② 区分统计显著 vs 业务显著（效应量）             │
│  ③ 分群异质性分析（谁受益、谁受损）               │
│  ④ 多重检验校正（Bonferroni/BH）                  │
│  ⑤ 辛普森悖论排查（分层 vs 汇总结论是否一致）     │
│  ⑥ 南辕北辙指标检查（短期涨 vs 长期跌）           │
└──────────────────────────────────────────────────┘
    │
    ▼
┌─ 第四步：决策与迭代 ────────────────────────────┐
│  ① 主指标显著正向 + 护栏无恶化 → 放量             │
│  ② 主指标不显著 → 分析原因，迭代或下线            │
│  ③ 主指标正向但护栏恶化 → 权衡，修复后再决策      │
│  ④ 分群异质性大 → 差异化策略或定向放量            │
│  ⑤ 邮件报备技术leader，批准后放量                 │
└──────────────────────────────────────────────────┘
```

- 新服务空跑一周观察数据，一周左右可以做数据对比

**信息流看点实验流程**（来源：推荐实验系统调研）：
1. 新服务空跑一周，观察数据
2. 一周左右做数据对比
3. 平均一个月完成一个实验
4. 邮件报备技术leader，批准后放量

**其他团队情况**（来源：推荐实验系统调研）：

## 二、实验设计：从假设到指标

### 2.1 假设提出与实验变量定义

每个AB实验都始于一个明确的假设。好的假设应该满足三个条件：
1. **可证伪**：能够通过数据验证或推翻
2. **可操作**：对应的实验变量是可控制、可实现的
3. **有业务价值**：验证后的结论能指导决策

**假设的形式化表达**：
- **H0（原假设）**：实验组与对照组的指标无差异（μ_treatment = μ_control）
- **H1（备择假设）**：实验组与对照组的指标有差异（μ_treatment ≠ μ_control，双侧检验；或 μ_treatment > μ_control，单侧检验）

**实验变量的类型**：

| 变量类型 | 示例 | 分流单元 |
|----------|------|----------|
| **算法策略** | 推荐排序模型版本、召回策略、重排策略 | 用户级 |
| **产品功能** | UI改版、新功能上线、交互优化 | 用户级/设备级 |
| **运营策略** | Push策略、红点策略、活动配置 | 用户级 |
| **商业化策略** | 广告加载策略、出价策略、校准策略 | 请求级/用户级 |
| **内容策略** | 内容供给调整、品类权重调整 | 用户级 |

### 2.2 指标体系设计

指标设计是AB实验中最关键的环节之一。我在实践中将指标分为三类（来源：模拟面试问答集_可直接背诵、模拟面试问答集_深入版）：

| 指标类型 | 定义 | 示例 | 决策作用 |
|----------|------|------|----------|
| **主指标（OEC）** | 实验最终要提升的核心业务指标 | 人均时长、DAU、留存率、收入 | 决定实验是否成功的核心依据 |
| **护栏指标** | 不能恶化的底线指标 | 负反馈率、1s快划率、崩溃率、延迟、多样性 | 即使主指标提升，护栏恶化也不能放量 |
| **观测指标** | 用于理解实验机制的辅助指标 | CTR、消费VV、完播率、各品类曝光占比 | 帮助解释"为什么主指标变了" |

**护栏指标的设计原则**（来源：模拟面试问答集_可直接背诵）：
- 防止"主指标涨了体验崩了"——比如通过强推低质内容提升了时长，但负反馈率飙升
- 护栏指标恶化时，即使核心指标正向也不能放量
- 常见护栏指标：负反馈率（不感兴趣/举报）、1s快划率、崩溃率、接口延迟、内容多样性、用户渗透率

**主指标选择的注意事项**：
1. **敏感性**：主指标应该对实验变量敏感，能在合理样本量和时间内检测到变化
2. **稳定性**：主指标的方差不能太大，否则需要过大的样本量
3. **业务对齐**：主指标应该与业务目标一致，避免"指标涨了但业务没变好"
4. **可归因**：主指标的变化应该能归因到实验变量，而不是外部因素

### 2.3 分流单元与随机化

**分流单元的选择**（来源：模拟面试问答集_深入版）：

| 分流单元 | 适用场景 | 优点 | 缺点 |
|----------|----------|------|------|
| **用户级** | 推荐算法、产品功能、运营策略 | 用户体验一致，无串扰 | 样本量需求大 |
| **设备级** | 跨端功能、硬件相关实验 | 覆盖设备维度 | 同一用户多设备可能串扰 |
| **请求级** | 广告加载、实时策略 | 样本量需求小，实验快 | 同一用户体验不一致，有串扰 |
| **内容级** | 内容策略、创作者实验 | 不影响用户体验 | 结果难以归因到用户层面 |

**随机化的关键注意事项**（来源：模拟面试问答集_深入版）：
1. **同一用户跨端要统一**：否则同一用户在不同端看到不同版本，造成串扰
2. **避免"同一用户既在实验组又在对照组"**：分流逻辑要保证用户的唯一性
3. **正交分层**：多层实验之间要正交分流，保证实验间互不干扰
4. **哈希分流**：通常用用户ID的哈希值取模来分流，保证分流的确定性和均匀性

### 2.4 实验周期设计

**实验周期的构成**：

| 阶段 | 时长 | 目的 |
|------|------|------|
| **空跑期** | 约1周 | 新服务上线先空跑，验证数据上报和系统稳定性（来源：推荐实验系统调研） |
| **对比期** | 至少1周 | 覆盖完整的周中周末周期，消除星期效应（来源：07_指标与评估） |
| **观察期** | 持续 | 放量后持续观察，防止延迟效应和长期负面影响 |

**实验周期的确定原则**：
1. **覆盖完整周中周末**：用户行为在工作日和周末有显著差异，至少覆盖一个完整周期
2. **考虑效应显现时间**：有些策略（如留存提升）需要更长时间才能显现效果
3. **考虑新奇效应**：新功能上线初期可能有新奇效应导致指标虚高，需要等效应稳定
4. **考虑用户学习成本**：用户需要时间适应新功能或新策略，短期数据可能低估长期效果

我在腾讯的实践是：**平均一个月完成一个实验**——空跑一周+对比一周+分析决策一周+放量观察一周（来源：推荐实验系统调研）。

> **面试口述版**：AB实验的设计我按四步走。第一步是提出假设，要可证伪、可操作、有业务价值，形式化就是H0两组无差异、H1两组有差异。第二步是定指标，分三类：主指标（比如人均时长、DAU、留存）是实验最终要提升的核心指标；护栏指标（负反馈率、1s快划率、崩溃率、延迟、多样性）是不能恶化的底线，防止"时长涨了体验崩了"；观测指标（CTR、消费VV、各品类曝光占比）用来理解实验机制。第三步是算样本量，用功效分析确定最小可检测效应。第四步是定分流单元和实验周期，推荐算法一般用用户级分流，实验至少覆盖一个完整周中周末周期。我在腾讯的实践是平均一个月完成一个实验——空跑一周验证数据、对比一周覆盖周中周末、分析决策、放量观察。

## 三、样本量计算与功效分析

### 3.1 为什么要算样本量

样本量计算是AB实验设计中最容易被忽视但最关键的环节之一。不算样本量直接跑实验，可能出现两种问题：

1. **样本量不足**：实验效应真实存在但检测不出来（第二类错误，β错误），导致"假阴性"——明明策略有效，却因为样本不够得出"不显著"的结论
2. **样本量过大**：浪费流量和时间，小流量就能验证的实验用了大流量，增加用户体验风险

**功效分析的核心思想**：在实验开始前，根据预期效应大小、指标波动率、显著性水平和统计功效，计算出需要的最小样本量。

### 3.2 样本量计算公式

**核心公式**（来源：模拟面试问答集_可直接背诵、模拟面试问答集_深入版）：

$$n \propto \frac{(z_{\alpha} + z_{\beta})^2 \cdot \sigma^2}{\delta^2}$$

其中：
- **n**：每组需要的样本量
- **z_α**：显著性水平α对应的z值（双侧检验α=0.05时，z_α=1.96）
- **z_β**：功效1-β对应的z值（功效=0.8时，β=0.2，z_β=0.84）
- **σ**：指标的标准差（波动率）
- **δ**：最小可检测效应（MDE，Minimum Detectable Effect）——业务上关心的最小指标变化

**更精确的公式（两组均值差异检验）**：

$$n = \frac{2 \cdot (z_{\alpha/2} + z_{\beta})^2 \cdot \sigma^2}{\delta^2}$$

（双侧检验用z_α/2，因子2是因为两组各需要n个样本）

**比例指标的样本量公式（如CTR、留存率）**：

$$n = \frac{(z_{\alpha/2} + z_{\beta})^2 \cdot [p_1(1-p_1) + p_2(1-p_2)]}{(p_1 - p_2)^2}$$

其中p1是对照组基线比例，p2是实验组预期比例。

### 3.3 公式参数详解

| 参数 | 含义 | 常用取值 | 说明 |
|------|------|----------|------|
| **α（显著性水平）** | 犯第一类错误（假阳性）的概率 | 0.05 | 行业标准，p<0.05认为显著 |
| **1-β（统计功效）** | 正确检测到真实效应的概率 | 0.8 | 行业标准，即有80%概率检测到δ大小的效应 |
| **σ（标准差）** | 指标的历史波动率 | 从历史数据估计 | 指标波动越大，需要样本越多 |
| **δ（MDE）** | 最小可检测效应 | 结合业务确定 | 效应越小，需要样本越多 |

**z值速查表**：

| α（双侧） | z_α/2 | 功效(1-β) | z_β |
|-----------|-------|-----------|-----|
| 0.01 | 2.576 | 0.8 | 0.842 |
| 0.05 | 1.960 | 0.9 | 1.282 |
| 0.10 | 1.645 | 0.95 | 1.645 |

### 3.4 样本量计算示例

**示例1：人均时长提升实验**

假设：
- 对照组人均时长基线：30分钟
- 预期提升：2%（即δ=0.6分钟）
- 人均时长的标准差σ：15分钟
- α=0.05（双侧），功效=0.8

计算：
$$n = \frac{2 \times (1.96 + 0.84)^2 \times 15^2}{0.6^2} = \frac{2 \times 7.84 \times 225}{0.36} = \frac{3528}{0.36} = 9800$$

每组需要约9800用户，两组共约19600用户。如果DAU是1000万，用1%流量（10万用户），一天就能满足样本量，但考虑到周中周末效应，仍建议跑至少一周。

**示例2：CTR提升实验**

假设：
- 对照组CTR基线：5%（p1=0.05）
- 预期提升：相对提升5%（即p2=0.0525，绝对提升0.25pp）
- α=0.05（双侧），功效=0.8

计算：
$$n = \frac{(1.96 + 0.84)^2 \times [0.05 \times 0.95 + 0.0525 \times 0.9475]}{(0.0525 - 0.05)^2}$$
$$= \frac{7.84 \times [0.0475 + 0.0497]}{0.00000625} = \frac{7.84 \times 0.0972}{0.00000625} = \frac{0.762}{0.00000625} \approx 121,920$$

每组需要约12.2万用户，两组共约24.4万用户。

### 3.5 影响样本量的关键因素

| 因素变化 | 对样本量的影响 | 直觉解释 |
|----------|---------------|----------|
| δ（MDE）减小 | 样本量增大（与δ²成反比） | 要检测更小的效应，需要更多样本 |
| σ（波动率）增大 | 样本量增大（与σ²成正比） | 指标越不稳定，越难区分信号和噪声 |
| α减小（更严格） | 样本量增大 | 要求更低的假阳性率，需要更多证据 |
| 功效1-β增大 | 样本量增大 | 要求更高的检测概率，需要更多样本 |
| 从双侧改为单侧检验 | 样本量减小 | 单侧检验更敏感，需要样本更少 |

### 3.6 实践中的样本量策略

1. **小流量起步**：先1%-5%流量跑，验证数据质量和无严重负向，再逐步放量（来源：推荐实验系统调研）
2. **效应预估要保守**：预期效应不要估得太大，否则实际效应小于MDE时检测不出来
3. **考虑用户重叠**：多层实验正交分流时，实际可用流量需要扣除其他实验占用
4. **时间维度的样本量**：不仅要考虑用户数，还要考虑实验天数——至少覆盖完整周中周末
5. **提前终止的条件**：如果实验出现严重护栏指标恶化，应立即停止，不必等到样本量满足

> **面试口述版**：样本量计算我用功效分析，核心公式是n ∝ (z_α + z_β)²·σ²/δ²。四个关键参数：α是显著性水平一般取0.05（z=1.96），1-β是统计功效一般取0.8（z_β=0.84），σ是指标的标准差从历史数据估计，δ是最小可检测效应——这是最关键的参数，要结合业务确定，比如留存提升0.5pp就算有价值。效应越小、波动越大，需要的样本越多，而且是平方关系——效应减半样本量要翻四倍。

举个例子：人均时长基线30分钟，预期提升2%（0.6分钟），标准差15分钟，α=0.05功效0.8，算出来每组约9800用户。如果是CTR从5%提升相对5%（绝对0.25pp），每组要约12.2万用户。实践中我会小流量起步（1%-5%），先验证数据质量，效应预估要保守，至少覆盖完整周中周末周期。样本量不够就别硬跑——检出不了小效应，跑了也是白跑。

## 四、AA实验与SRM检测

### 4.1 AA实验：分流均匀性验证

**什么是AA实验**：AA实验是指实验组和对照组使用完全相同的策略（都是base版本），验证分流是否均匀、两组基线指标是否无显著差异（来源：模拟面试问答集_可直接背诵、模拟面试问答集_深入版）。

**为什么要做AA实验**：
1. **验证分流逻辑正确性**：确认用户ID哈希分流是均匀的，没有分桶偏差
2. **验证埋点数据一致性**：确认两组的数据上报口径一致，没有埋点差异
3. **建立基线指标分布**：了解指标在无实验干预时的自然波动范围
4. **排除系统偏差**：如果AA实验中两组就有显著差异，说明分流或数据有问题，后续AB实验的结果不可信

**AA实验的通过标准**：
- 两组用户量比例符合预期（如50:50）
- 核心指标在两组之间无统计显著差异（p>0.05）
- 用户画像分布（年龄、性别、城市等级、活跃度）在两组之间无显著差异
- SRM检验通过

### 4.2 SRM（Sample Ratio Mismatch，样本比率不匹配）

**什么是SRM**：实验组和对照组的样本量比例偏离了预期的分流比例，且偏离在统计上显著（来源：模拟面试问答集_可直接背诵、模拟面试问答集_深入版）。

例如，预期分流比例是50:50，但实际实验组48%、对照组52%，且卡方检验显示这个偏离是统计显著的，就是SRM。

**SRM的检测方法——卡方检验**：

$$\chi^2 = \sum \frac{(O_i - E_i)^2}{E_i}$$

其中：
- O_i：第i组的实际观测样本量
- E_i：第i组的预期样本量（按分流比例计算）

自由度=组数-1，p<0.01时认为存在SRM（比常规0.05更严格，因为SRM是严重问题）。

**SRM检测示例**：
- 预期50:50分流，总样本200,000
- 实际：实验组95,000，对照组105,000
- E1=E2=100,000
- χ² = (95000-100000)²/100000 + (105000-100000)²/100000 = 2500 + 2500 = 5000
- 自由度=1，p值远小于0.001，存在严重SRM

### 4.3 SRM的常见原因与排查

SRM是AB实验中最严重的问题之一——如果存在SRM，实验结果**不可信**，必须先排查解决（来源：模拟面试问答集_深入版）。

| 原因类别 | 具体原因 | 排查方法 |
|----------|----------|----------|
| **分流逻辑问题** | 分流哈希函数有偏、分流逻辑bug、用户ID处理不一致 | 检查分流代码、对比用户ID分布 |
| **流失差异** | 实验组体验差导致用户流失/卸载，实验组样本量减少 | 对比两组的用户留存率、活跃率 |
| **准入条件差异** | 实验准入逻辑在两组不一致，部分用户只进入一组 | 检查实验准入条件、对比新用户占比 |
| **数据上报问题** | 实验组埋点上报率低，导致观测样本量少 | 对比两组的上报率、数据完整率 |
| **端/版本差异** | 实验组和对照组的客户端版本分布不一致 | 对比两组的版本分布、机型分布 |
| **机器人/爬虫** | 实验组被爬虫攻击，异常流量混入 | 过滤异常流量后重新检验 |
| **时间窗口问题** | 实验启动时间在两组不一致 | 检查实验启动时间、对齐时间窗口 |

**SRM的处理原则**（来源：模拟面试问答集_深入版）：
1. **先查分流逻辑和流失**：这是最常见的两个原因
2. **必要时重跑**：如果SRM是分流bug导致的，修复后必须重新跑实验
3. **不能用统计方法"校正"SRM**：SRM意味着随机化失败，任何后续的统计检验都建立在随机化的基础上，基础没了就无法校正
4. **SRM未解决前不能下结论**：即使主指标看起来很好，也不能放量

### 4.4 AA实验与SRM的关系

AA实验和SRM检测是互补的：
- **AA实验**：在实验开始前做，验证分流均匀性和基线一致性，是"预防性"检查
- **SRM检测**：在实验进行中持续监控，实时检测样本量比例是否偏离，是"监控性"检查

最佳实践是：**实验上线前做AA实验验证，实验上线后持续做SRM监控**（来源：模拟面试问答集_可直接背诵）。

> **面试口述版**：AA实验和SRM检测是AB实验质量的两道防线。AA实验是在实验开始前，实验组和对照组都用base版本，验证分流是否均匀、两组基线指标是否无显著差异。如果AA实验中两组就有显著差异，说明分流或数据有问题，后续AB结果不可信。

SRM（Sample Ratio Mismatch，样本比率不匹配）是指实验组和对照组的样本量比例偏离了预期分流比例，且统计显著。比如预期50:50，实际48:52且卡方检验显著。检测用卡方检验：χ²=Σ(O-E)²/E，p<0.01认为存在SRM。

SRM是AB实验中最严重的问题——存在SRM意味着随机化失败，实验结果不可信，不能用统计方法校正，必须先排查。常见原因有：分流逻辑bug、实验组体验差导致流失、准入条件差异、数据上报问题、端版本差异。排查顺序是先查分流逻辑和流失，必要时修复后重跑。我的实践是：实验上线前做AA实验验证，上线后持续做SRM监控，SRM未解决前不能下结论。

## 五、统计显著性检验与p值误区

### 5.1 常用统计检验方法

| 检验方法 | 适用场景 | 数据类型 | 原假设 |
|----------|----------|----------|--------|
| **Z检验** | 大样本（n>30）两组均值比较 | 连续指标（时长、VV） | 两组均值相等 |
| **t检验** | 小样本两组均值比较 | 连续指标 | 两组均值相等 |
| **卡方检验** | 两组比例比较 | 二分类指标（CTR、留存率） | 两组比例相等 |
| **Mann-Whitney U** | 非参数检验，不满足正态分布时 | 连续指标（有偏分布） | 两组分布相同 |
| **配对t检验** | 同一组用户前后对比 | 连续指标 | 前后均值相等 |
| **方差分析(ANOVA)** | 多组均值比较 | 连续指标 | 所有组均值相等 |

**推荐业务中的常用选择**：
- **人均时长、人均VV**：大样本用Z检验，分布有偏时考虑对数变换或Mann-Whitney U
- **CTR、留存率、渗透率**：用卡方检验或两比例Z检验
- **AUC、GAUC等模型指标**：用bootstrap置信区间

### 5.2 p值的正确理解

**p值的定义**：在原假设（H0）为真的前提下，观察到当前或更极端结果的概率。

$$p = P(\text{观测到当前或更极端的结果} | H_0 \text{为真})$$

**p值的正确解读**：
- p<0.05：在原假设为真的情况下，观察到当前结果的概率小于5%，因此"拒绝原假设"，认为两组有显著差异
- p≥0.05：没有足够的证据拒绝原假设，**不能说"两组没有差异"**，只能说"未检测到显著差异"

### 5.3 p值的常见误区

这是面试中最高频的考点之一，我总结了六个常见误区（来源：模拟面试问答集_可直接背诵、模拟面试问答集_深入版）：

**误区一：p值是原假设为真的概率**
- ❌ 错误："p=0.03说明原假设只有3%的概率为真"
- ✅ 正确：p值是在原假设为真的前提下观察到当前结果的概率，不是原假设为真的概率。要计算原假设为真的概率需要贝叶斯方法。

**误区二：p值越小效应越大**
- ❌ 错误："p=0.001比p=0.04的效果更好"
- ✅ 正确：p值只反映统计显著性，不反映效应大小。p值小可能只是因为样本量大。一个微小的效应在大样本下也能得到极小的p值。必须同时看效应量和置信区间。

**误区三：p>0.05就是没有效果**
- ❌ 错误："p=0.08说明策略完全没用"
- ✅ 正确：p>0.05只说明没有足够的证据拒绝原假设，可能是效应真实存在但样本量不足（第二类错误），也可能是效应确实很小。需要看置信区间和功效分析。

**误区四：p<0.05就一定能复现**
- ❌ 错误："p=0.04显著，下次跑一定还显著"
- ✅ 正确：单次实验的p值受随机波动影响，p=0.04的实验复现率可能只有50%左右。需要看效应量的置信区间，而不是只看是否跨过0.05的阈值。

**误区五：可以反复看p值直到显著**
- ❌ 错误："每天看一次数据，哪天p<0.05就停实验"
- ✅ 正确：这叫"偷看"（peeking），多次检验会放大假阳性率。如果每天看一次，实际假阳性率可能高达20%-30%而不是5%。需要预注册分析计划，或用序贯检验/EGO控制整体错误率（来源：模拟面试问答集_深入版）。

**误区六：统计显著=业务显著**
- ❌ 错误："p<0.05，实验成功，可以放量"
- ✅ 正确：统计显著只说明差异不太可能是随机波动，不代表差异有业务价值。比如人均时长提升0.01分钟（0.6秒），在大样本下可能p<0.001，但业务上毫无意义。必须区分统计显著和业务显著，看效应量是否达到业务关心的MDE（来源：模拟面试问答集_可直接背诵）。

### 5.4 置信区间：比p值更有信息量

**置信区间的定义**：在一定置信水平（通常95%）下，包含真实效应量的区间估计。

**95%置信区间的含义**：如果重复实验100次，约95次的置信区间会包含真实效应量。

**置信区间的优势**：
1. **同时给出显著性和效应量**：区间不包含0→显著；区间位置和宽度→效应量和精度
2. **更直观**：可以直接看到效应的可能范围，而不是一个抽象的p值
3. **便于比较**：不同实验的置信区间可以直接对比，p值则不能

**置信区间解读示例**：
- 人均时长提升的95%CI：[+0.5分钟, +1.5分钟] → 显著正向，效应量0.5-1.5分钟
- 人均时长提升的95%CI：[-0.2分钟, +0.8分钟] → 不显著（包含0），但不能排除正向效应
- 人均时长提升的95%CI：[+0.01分钟, +0.03分钟] → 显著但效应极小，业务上可能无意义

### 5.5 统计显著 vs 业务显著

这是AB实验分析中最重要的判断框架（来源：模拟面试问答集_可直接背诵、模拟面试问答集_深入版）：

|  | 业务显著（效应≥MDE） | 业务不显著（效应<MDE） |
|--|---------------------|---------------------|
| **统计显著（p<0.05）** | ✅ 成功，放量 | ⚠️ 统计显著但业务无意义，不放量 |
| **统计不显著（p≥0.05）** | ⚠️ 可能样本不足，需更多数据或迭代 | ❌ 无效果，下线或迭代 |

**决策原则**：
1. **统计显著 + 业务显著 + 护栏无恶化** → 放量
2. **统计显著但业务不显著** → 不放量，效应太小不值得投入
3. **统计不显著但效应方向正向且接近MDE** → 可能样本量不足，考虑延长实验或扩大流量
4. **统计不显著且效应接近0** → 策略无效，下线或重新设计

> **面试口述版**：统计显著性检验我根据指标类型选方法：连续指标（时长、VV）大样本用Z检验，有偏分布考虑对数变换或Mann-Whitney U；比例指标（CTR、留存率）用卡方检验或两比例Z检验；模型指标（AUC）用bootstrap置信区间。

p值是面试最高频的考点，我总结了六个常见误区：第一，p值不是原假设为真的概率，而是在原假设为真的前提下观察到当前结果的概率；第二，p值越小不代表效应越大，大样本下微小效应也能得到极小p值；第三，p>0.05不是"没有效果"，而是"未检测到显著差异"，可能是样本不足；第四，p<0.05不代表一定能复现，p=0.04的复现率可能只有50%；第五，不能反复看p值直到显著，这叫"偷看"，多次检验会把假阳性率从5%放大到20%-30%，要用序贯检验或预注册分析计划；第六，统计显著不等于业务显著，人均时长提升0.6秒在大样本下p<0.001但业务毫无意义。

我更推荐看置信区间而不是只看p值——95%置信区间同时给出了显著性（是否包含0）和效应量（区间位置和宽度），信息量更大。决策框架是：统计显著+业务显著+护栏无恶化才放量；统计显著但业务不显著不放量；统计不显著但效应正向接近MDE可能是样本不足，考虑延长实验。

## 六、多重检验校正

### 6.1 什么是多重检验问题

**多重检验问题（Multiple Testing Problem）**：当同时进行多个统计检验时，即使所有原假设都为真，至少有一个检验错误地拒绝原假设（假阳性）的概率会随着检验次数增加而增大。

**假阳性率的膨胀**：
- 单次检验，α=0.05：假阳性率=5%
- 10次独立检验，每次α=0.05：至少一次假阳性的概率=1-(1-0.05)^10≈40%
- 20次独立检验：至少一次假阳性的概率=1-(1-0.05)^20≈64%
- 100次独立检验：至少一次假阳性的概率≈99.4%

这就是为什么在AB实验中，如果同时看20个指标，很可能有1个指标"显著"但实际上是假阳性（来源：模拟面试问答集_深入版）。

### 6.2 AB实验中的多重检验场景

| 场景 | 检验次数 | 说明 |
|------|----------|------|
| **多指标检验** | 5-20个 | 同时看主指标、护栏指标、观测指标 |
| **多分群检验** | 10-50个 | 按年龄、性别、城市、活跃度等维度分群看效果 |
| **多天检验（偷看）** | 7-30次 | 每天看一次实验结果 |
| **多版本对比** | 2-5个 | 多个实验组 vs 对照组 |
| **组合** | 上百次 | 多指标×多分群×多天 |

### 6.3 Bonferroni校正

**方法**：将显著性水平α除以检验次数m，得到校正后的显著性水平α'=α/m。只有p<α'时才认为显著。

**示例**：同时检验20个指标，α=0.05，校正后α'=0.05/20=0.0025。只有p<0.0025的指标才认为显著。

**优点**：
- 简单易懂，计算方便
- 控制FWER（Family-Wise Error Rate，族错误率）严格——至少一次假阳性的概率≤α
- 适用于检验次数较少（<10）的场景

**缺点**：
- 过于保守，大幅降低统计功效（增加第二类错误）
- 检验次数多时，α'极小，几乎不可能显著
- 假设检验之间相互独立，实际中指标往往相关，保守程度更高

### 6.4 BH校正（Benjamini-Hochberg）

**方法**：控制FDR（False Discovery Rate，错误发现率）——在所有被拒绝的原假设中，假阳性所占的期望比例。

**步骤**：
1. 将m个p值从小到大排序：p_(1) ≤ p_(2) ≤ ... ≤ p_(m)
2. 找到最大的k，使得 p_(k) ≤ (k/m) × α
3. 拒绝前k个原假设（即前k个p值对应的检验显著）

**示例**：10个p值排序后：0.001, 0.004, 0.008, 0.012, 0.025, 0.04, 0.06, 0.08, 0.15, 0.30，α=0.05
- p_(1)=0.001 ≤ (1/10)×0.05=0.005 ✓
- p_(2)=0.004 ≤ (2/10)×0.05=0.01 ✓
- p_(3)=0.008 ≤ (3/10)×0.05=0.015 ✓
- p_(4)=0.012 ≤ (4/10)×0.05=0.02 ✓
- p_(5)=0.025 ≤ (5/10)×0.05=0.025 ✓
- p_(6)=0.04 ≤ (6/10)×0.05=0.03 ✗
- 最大k=5，前5个p值显著

**优点**：
- 比Bonferroni更宽松，统计功效更高
- 控制FDR而非FWER，更适合探索性分析
- 适用于检验次数较多的场景（如分群分析、基因组学）

**缺点**：
- 控制的是FDR而非FWER，允许一定比例的假阳性
- 不如Bonferroni严格，在需要严格控制假阳性的场景不适用
- 对p值的分布有一定假设

### 6.5 Bonferroni vs BH对比

| 维度 | Bonferroni | BH（Benjamini-Hochberg） |
|------|-----------|--------------------------|
| **控制目标** | FWER（族错误率） | FDR（错误发现率） |
| **严格程度** | 严格（保守） | 宽松（功效高） |
| **计算复杂度** | 简单（α/m） | 中等（排序+逐行比较） |
| **适用场景** | 检验次数少、需严格控制假阳性 | 检验次数多、探索性分析 |
| **假阳性控制** | 至少一次假阳性概率≤α | 显著结果中假阳性比例≤α |
| **对功效的影响** | 大幅降低功效 | 对功效影响较小 |
| **AB实验推荐** | 主指标+护栏指标（<10个） | 分群异质性分析（多分群） |

### 6.6 实践中的多重检验策略

1. **预注册分析计划**：实验前明确主指标和分析方法，避免事后挑数据（来源：模拟面试问答集_深入版）
2. **主指标用Bonferroni**：主指标和护栏指标数量少（<10），用Bonferroni严格控制
3. **分群分析用BH**：分群异质性分析是探索性的，用BH控制FDR
4. **序贯检验控制偷看**：如果需要中期看数据，用序贯检验（如O'Brien-Fleming边界、Pocock边界）或EGO（Always Valid Inference）控制整体错误率
5. **独立验证**：分群分析中发现的显著效果，需要在独立样本或后续实验中验证，不能直接作为结论

> **面试口述版**：多重检验是AB实验中容易踩坑的地方。核心问题是：同时做多个检验时，假阳性率会膨胀——单次检验α=0.05时假阳性率5%，但同时看20个指标，至少一个假阳性的概率高达64%。所以在AB实验中同时看20个指标，很可能有1个"显著"其实是假阳性。

校正方法有两种主流。第一种是Bonferroni校正，把α除以检验次数m，比如20个指标就用0.05/20=0.0025作为阈值。优点是简单严格，控制FWER（至少一次假阳性的概率≤α）；缺点是太保守，大幅降低功效，适合检验次数少（<10）的场景，比如主指标加护栏指标。

第二种是BH校正（Benjamini-Hochberg），控制FDR（错误发现率——显著结果中假阳性的比例）。方法是把p值排序，找到最大的k使得p_(k)≤(k/m)×α，前k个显著。优点是比Bonferroni宽松、功效高，适合检验次数多的探索性分析，比如分群异质性分析；缺点是允许一定比例的假阳性。

我的实践策略是：实验前预注册分析计划，明确主指标；主指标和护栏指标用Bonferroni；分群分析用BH；如果需要中期看数据用序贯检验或EGO控制整体错误率，不能"偷看"；分群发现的显著效果需要独立验证。

## 七、辛普森悖论与分群异质性

### 7.1 什么是辛普森悖论

**辛普森悖论（Simpson's Paradox）**：在分组分析中每组都呈现相同的趋势，但在汇总分析中趋势消失甚至反转的现象。

**经典示例**：

|  | 实验组 | 对照组 | 实验组转化率 | 对照组转化率 |
|--|--------|--------|------------|------------|
| **新用户** | 转化50/1000=5% | 转化100/2000=5% | 5% | 5% |
| **老用户** | 转化180/3000=6% | 转化40/500=8% | 6% | 8% |
| **汇总** | 转化230/4000=5.75% | 转化140/2500=5.6% | **5.75%** | **5.6%** |

在这个例子中：
- 新用户：两组转化率相同（5% vs 5%）
- 老用户：实验组转化率低于对照组（6% vs 8%）
- 但汇总后：实验组转化率高于对照组（5.75% vs 5.6%）

原因是：实验组中新用户占比低（1000/4000=25%），对照组中新用户占比高（2000/2500=80%），而新用户转化率低于老用户。用户结构的差异掩盖了真实的策略效果。

### 7.2 AB实验中的辛普森悖论场景

| 场景 | 悖论表现 | 原因 |
|------|----------|------|
| **新老用户结构差异** | 汇总正向，但新老用户各自负向或不变 | 实验组和对照组的新老用户比例不同 |
| **活跃度结构差异** | 汇总正向，但各活跃度分层负向 | 实验组高活用户占比高（高活用户指标天然高） |
| **流量来源差异** | 汇总正向，但各渠道负向 | 实验组高转化渠道流量占比高 |
| **时间结构差异** | 汇总正向，但每天负向 | 实验组在高转化时段（如晚间）流量占比高 |
| **地域结构差异** | 汇总正向，但各城市负向 | 实验组高线城市用户占比高 |

### 7.3 辛普森悖论的检测与处理

**检测方法**：
1. **分层分析**：按关键维度（新老用户、活跃度、渠道、地域、时间）分层看效果，对比分层结论和汇总结论是否一致
2. **协变量平衡检验**：检验实验组和对照组在关键协变量上的分布是否一致（如果随机化正确，应该一致）
3. **回归调整**：用回归模型控制协变量，估计调整后的处理效应
4. **CUPED**：利用实验前数据降低方差，同时控制协变量不平衡

**处理方法**：
1. **如果是随机化失败（SRM导致的结构差异）**：实验结果不可信，需要修复分流后重跑
2. **如果是随机波动导致的轻微结构差异**：用回归调整或CUPED估计调整后的效应
3. **如果是分群异质性（不同群效果确实不同）**：不是悖论，是真实的异质性，应该做差异化策略
4. **报告时同时给出汇总和分层结果**：不能只报汇总结果，要说明分层情况

### 7.4 分群异质性分析

分群异质性分析不是辛普森悖论，而是真实的效果差异——不同用户群对同一策略的反应不同。这在AB实验分析中非常重要（来源：模拟面试问答集_可直接背诵）。

**分群异质性的分析维度**：
- 用户属性：年龄、性别、城市等级、手机品牌
- 用户行为：活跃度（高/中/低活）、使用时长、内容偏好
- 用户生命周期：新用户/老用户、注册时长
- 实验环境：端（iOS/Android）、版本、网络环境
- 时间：工作日/周末、白天/晚间

**分群异质性的决策含义**（来源：模拟面试问答集_深入版）：
1. **所有分群都正向且显著** → 全量放量
2. **大部分分群正向，少数分群负向** → 分析负向分群原因，考虑定向放量（排除负向分群）或修复后全量
3. **正向和负向分群各半** → 策略有明显的人群针对性，应该做差异化策略（对正向分群上线，对负向分群不上线）
4. **所有分群都不显著** → 策略无效，下线或迭代
5. **汇总显著但分群都不显著** → 可能是多重检验假阳性或结构差异，需要深入排查

**注意事项**：
- 分群分析是探索性的，需要用BH校正控制多重检验
- 分群发现的显著效果需要在独立样本中验证
- 分群数量不宜过多，每个分群要有足够样本量
- 要注意分群后的SRM问题

> **面试口述版**：辛普森悖论是指分组分析中每组趋势相同，但汇总后趋势消失甚至反转。经典原因是实验组和对照组的用户结构不同——比如实验组高活用户占比高，高活用户转化率天然高，汇总后看起来实验组更好，但分层看每个群其实策略没效果甚至负向。

AB实验中常见的辛普森悖论场景有：新老用户结构差异、活跃度结构差异、流量来源差异、时间结构差异、地域结构差异。检测方法是分层分析——按关键维度分层看效果，对比分层结论和汇总结论是否一致；同时做协变量平衡检验，看两组在关键维度分布是否一致。

处理上要区分情况：如果是随机化失败（SRM导致结构差异），实验不可信必须重跑；如果是随机波动导致的轻微差异，用回归调整或CUPED估计调整后效应；如果是真实的分群异质性（不同群效果确实不同），那就不是悖论，应该做差异化策略。

分群异质性分析很重要——不能只看平均效果，要看哪些用户受益、哪些受损。决策上：所有分群正向就全量放量；大部分正向少数负向就分析原因考虑定向放量；正负各半就做差异化策略；汇总显著但分群都不显著可能是假阳性要排查。分群分析要用BH校正，发现的效果需要独立验证。

## 八、护栏指标与南辕北辙指标

### 8.1 护栏指标设计

**护栏指标（Guardrail Metrics）**：在AB实验中，即使主指标提升，也不能恶化的底线指标。护栏指标恶化时，实验不能放量（来源：模拟面试问答集_可直接背诵、模拟面试问答集_深入版）。

**为什么需要护栏指标**：
- 防止"主指标涨了体验崩了"——比如通过强推低质内容提升了时长，但负反馈率飙升
- 防止短期收益损害长期价值——比如通过增加广告加载提升了收入，但用户体验恶化导致长期留存下降
- 防止策略的副作用被忽视——任何策略都可能有未预期的负面影响，护栏指标是安全网

**推荐业务中的常见护栏指标**：

| 护栏类别 | 具体指标 | 恶化含义 |
|----------|----------|----------|
| **用户体验** | 1s快划率、不感兴趣率、举报率、负反馈率 | 推荐内容不匹配，用户体验恶化 |
| **系统稳定性** | 崩溃率、接口延迟、超时率、错误率 | 新策略导致系统不稳定 |
| **内容生态** | 内容多样性（熵/基尼系数）、创作者覆盖率、新内容曝光占比 | 推荐过于集中，头部效应加剧，生态恶化 |
| **用户渗透** | 功能渗透率、活跃用户数、新用户占比 | 策略只对部分用户有效，整体渗透下降 |
| **商业化** | 广告加载率、广告CTR、eCPM、用户付费率 | 内容策略变化影响了商业化表现 |
| **长期价值** | 次日留存、7日留存、30日留存、用户生命周期价值 | 短期收益损害了长期留存 |

### 8.2 护栏指标的监控与决策

**护栏指标的决策规则**：

| 主指标 | 护栏指标 | 决策 |
|--------|----------|------|
| 显著正向 | 无恶化 | ✅ 放量 |
| 显著正向 | 轻微恶化但在可接受范围 | ⚠️ 权衡后放量，持续监控 |
| 显著正向 | 严重恶化 | ❌ 不放量，修复护栏后再实验 |
| 不显著 | 无恶化 | ❌ 不放量，迭代或下线 |
| 不显著 | 恶化 | ❌ 不放量，下线 |
| 显著负向 | 任何 | ❌ 立即停止，下线 |

**护栏指标恶化的处理流程**：
1. **确认恶化是真实的**：排除数据问题、SRM、统计波动
2. **定位恶化原因**：分析是哪个环节、哪类用户、哪种内容导致的护栏恶化
3. **评估严重程度**：恶化幅度有多大、影响多少用户、是否可逆
4. **修复策略**：调整策略参数、增加约束条件、排除受影响的用户群
5. **重新实验**：修复后重新跑AB实验验证

### 8.3 南辕北辙指标

**南辕北辙指标（Short-term vs Long-term Trade-off）**：短期指标提升但长期指标下降的现象（来源：模拟面试问答集_可直接背诵、模拟面试问答集_深入版）。

**常见的南辕北辙场景**：

| 短期提升 | 长期下降 | 原因 |
|----------|----------|------|
| 人均时长↑ | 次日留存↓ | 强推低质但高时长内容，用户短期看了但长期不想来了 |
| CTR↑ | 人均时长↓ | 标题党内容点击高但消费深度低，用户点进去就退出 |
| 关注率↑ | 留存↓ | 引导关注了低质量账号，用户体验恶化 |
| 广告收入↑ | DAU↓ | 广告加载过多，用户体验恶化导致流失 |
| 新用户转化↑ | 长期留存↓ | 新用户引导过于激进，透支了用户兴趣 |
| 推荐精准度↑ | 多样性↓ | 过度推荐用户已喜欢的内容，导致信息茧房，长期疲劳 |

**南辕北辙的检测方法**：
1. **长期留存追踪**：实验结束后持续追踪实验组用户的长期留存（7日、14日、30日）
2. **延迟效应分析**：区分实验初期（新奇效应）和稳定期的效果
3. **用户疲劳监控**：监控用户的负反馈率、快划率随时间的变化趋势
4. **生态指标监控**：监控内容多样性、创作者生态等慢变量指标

**南辕北辙的防范**（来源：模拟面试问答集_深入版）：
1. **上线前把长期目标作为护栏**：把留存、生态等长期指标纳入护栏指标体系
2. **短期实验通过后做长期留存追踪**：不只信短实验窗口，放量后持续观察长期指标
3. **设置新奇效应消除期**：实验初期的数据可能受新奇效应影响，等效应稳定后再做决策
4. **多目标平衡**：在模型或策略中显式加入长期目标的约束，避免过度优化短期指标

> **面试口述版**：护栏指标是AB实验的安全网——即使主指标提升，护栏恶化也不能放量。比如通过强推低质内容提升了时长，但负反馈率飙升，这种实验不能放量。推荐业务的护栏指标分几类：用户体验类（1s快划率、不感兴趣率、举报率）、系统稳定性类（崩溃率、延迟、超时率）、内容生态类（多样性、创作者覆盖率、新内容曝光占比）、用户渗透类、商业化类、长期价值类（次留、7留、LTV）。

决策规则很明确：主指标显著正向+护栏无恶化才放量；护栏严重恶化即使主指标正向也不能放，要修复后再实验；主指标负向立即停止。护栏恶化后要先确认是真实的不是数据问题，再定位原因、评估严重程度、修复策略、重新实验。

比护栏更隐蔽的是"南辕北辙指标"——短期指标提升但长期指标下降。常见场景：强推低质高时长内容导致短期时长涨但次留跌；标题党导致CTR涨但消费深度降；广告加载过多导致收入涨但DAU跌；过度精准推荐导致多样性降形成信息茧房长期疲劳。防范方法是：上线前把长期目标作为护栏，短期实验通过后做长期留存追踪，设置新奇效应消除期，在模型中显式加入长期目标约束。我在腾讯做推荐时就特别注意这个——不会为了短期CTR提升而牺牲长期留存。

## 九、实验系统架构与多层正交分流

### 9.1 实验系统的核心架构

一个完整的AB实验系统通常包含以下模块（来源：推荐实验系统调研、07_指标与评估）：

```
用户请求
    │
    ▼
┌─ 分流层（Traffic Splitting）────────────────────┐
│  用户ID哈希 → 分桶 → 实验层匹配 → 实验组/对照组  │
│  多层正交分流，每层独立分配流量                    │
└──────────────────────────────────────────────────┘
    │
    ▼
┌─ 实验配置层（Experiment Config）──────────────────┐
│  实验参数管理、流量比例配置、启停控制、版本管理     │
│  支持多实验路、base路对照、灰度放量                │
└──────────────────────────────────────────────────┘
    │
    ▼
┌─ 数据采集层（Data Collection）────────────────────┐
│  曝光日志、点击日志、消费日志、互动日志、转化日志   │
│  实验ID、分组ID、用户ID关联                        │
└──────────────────────────────────────────────────┘
    │
    ▼
┌─ 指标计算层（Metrics Computation）────────────────┐
│  实时指标（分钟级）+ 离线指标（天级）               │
│  主指标、护栏指标、观测指标自动计算                 │
└──────────────────────────────────────────────────┘
    │
    ▼
┌─ 统计分析层（Statistical Analysis）───────────────┐
│  显著性检验、置信区间、SRM检测、多重检验校正        │
│  分群异质性分析、长期留存追踪                       │
└──────────────────────────────────────────────────┘
    │
    ▼
┌─ 决策与放量层（Decision & Ramp）──────────────────┐
│  实验报告生成、放量审批、灰度放量、全量上线         │
│  实验归档、效果复盘                                 │
└──────────────────────────────────────────────────┘
```

### 9.2 多层正交分流

**什么是多层正交分流**：将实验分为多个层（如UI层、粗排层、精排层、混排层），每层独立分流，用户在不同层的分组是正交（独立）的，保证实验间互不干扰（来源：推荐实验系统调研、07_指标与评估）。

**正交分流的原理**：
- 每层使用用户ID的不同哈希位或不同哈希函数来分流
- 由于哈希函数的独立性，用户在A层的分组和在B层的分组是不相关的
- 因此，A层实验的效果在B层的实验组和对照组中是均匀分布的，不会混淆B层实验的效果

**腾讯骡马系统的实践**（来源：推荐实验系统调研）：
- 信息流看点：60%流量，包括UI、粗排、精排、混排，合计十几层
- 每层有base路作为对照
- 各层之间正交分流，保证实验间互不干扰

**多层实验的注意事项**：
1. **层间正交性验证**：定期验证层间分流的正交性，防止哈希冲突或逻辑bug
2. **流量预算管理**：每层的流量比例要合理分配，避免某层流量过大影响其他层
3. **实验间交互效应**：虽然正交分流保证了统计独立性，但如果两个实验的策略有业务上的交互效应（如UI改版+推荐算法变更），可能需要专门的交互实验
4. **base路一致性**：每层的base路应该使用相同的基线策略，保证对照的一致性

### 9.3 离线实验 vs 在线实验

| 维度 | 离线实验 | 在线AB实验 |
|------|---------|-----------|
| **成本** | 低，用历史数据计算 | 高，需要真实流量 |
| **速度** | 快，小时级出结果 | 慢，至少一周，通常一个月 |
| **准确性** | 有偏差（样本偏差、位置偏差、延迟反馈） | 真实准确 |
| **可探索性** | 高，可以快速试错 | 低，有用户体验风险 |
| **适用场景** | 算法初筛、特征工程验证、参数调优 | 最终效果验证、上线决策 |
| **关系** | 离线是在线的前置筛选 | 在线是离线的最终验证 |

（来源：07_指标与评估）

**离线和在线不一致的原因**（来源：07_指标与评估）：
1. **样本偏差**：离线用历史数据评估，用户已经看过的内容不会再点击，但离线不排除已曝光内容
2. **位置偏差**：离线不考虑展示位置对CTR的影响，线上位置偏差显著
3. **延迟反馈**：视频消费、留存等指标有延迟，离线即时指标无法捕捉
4. **生态影响**：单用户体验提升不代表整体DAU提升，可能存在挤出效应
5. **探索与利用**：离线倾向于利用已知偏好，线上需要探索新内容

**最佳实践**：离线实验做初筛（AUC、HitRate等指标提升明显的算法），在线AB做最终验证，两者结合提高迭代效率（来源：07_指标与评估）。

### 9.4 实验效率优化

我在腾讯实践中总结了提升实验效率的几个方法：

1. **小流量快速验证**：先1%-5%流量跑，验证无严重负向和数据质量问题，再逐步放量（来源：推荐实验系统调研）
2. **空跑期并行**：新服务空跑一周观察数据的同时，可以准备实验配置和分析脚本
3. **多实验路并行**：精排有6个实验路，可以同时验证多个算法版本（来源：推荐实验系统调研）
4. **离线初筛前置**：离线AUC/HitRate提升不明显的算法不上线，节省在线实验资源
5. **实验模板化**：常见实验类型（如排序模型AB、召回策略AB）配置模板化，减少配置时间
6. **自动化分析**：实验报告自动生成，包括显著性检验、置信区间、SRM检测、分群分析，减少人工分析时间

> **面试口述版**：实验系统架构我按六层理解：分流层（用户ID哈希分桶，多层正交分流）、实验配置层（参数管理、流量比例、启停控制）、数据采集层（曝光/点击/消费/互动日志，实验ID关联）、指标计算层（实时+离线，主指标+护栏+观测指标）、统计分析层（显著性检验、置信区间、SRM检测、多重检验校正、分群异质性）、决策与放量层（报告生成、放量审批、灰度放量）。

多层正交分流是关键——把实验分成UI层、粗排层、精排层、混排层等，每层独立分流，层间正交保证实验间互不干扰。腾讯骡马系统在信息流看点有60%流量、十几层实验，每层有base路对照。注意事项：定期验证层间正交性，合理分配流量预算，注意实验间的业务交互效应，保证base路一致性。

离线和在线的关系是：离线做初筛快速试错，在线做最终验证。离线和在线不一致是常态，原因有样本偏差、位置偏差、延迟反馈、生态影响、探索与利用不平衡。最佳实践是离线AUC/HitRate提升明显的算法才上线，最终以上线AB为准。实验效率优化上，我用小流量快速验证、空跑期并行准备、多实验路并行、离线初筛前置、实验模板化、自动化分析报告这些方法。

### 10.3 样本量公式速记

$$n = \frac{2 \cdot (z_{\alpha/2} + z_{\beta})^2 \cdot \sigma^2}{\delta^2}$$

- α=0.05 → z_α/2=1.96
- 功效=0.8 → z_β=0.84
- δ减半 → 样本量×4（平方关系）
- σ加倍 → 样本量×4（平方关系）

### 10.4 p值六大误区速记

| 误区 | 正确理解 |
|------|----------|
| p=原假设为真的概率 | p=在原假设为真时观察到当前结果的概率 |
| p越小效应越大 | p只反映统计显著性，效应量要看差值和CI |
| p>0.05=没有效果 | p>0.05=未检测到显著差异，可能样本不足 |
| p<0.05=一定能复现 | 单次p值受随机波动影响，要看CI |
| 可以反复看p直到显著 | 偷看会放大假阳性率，要用序贯检验 |
| 统计显著=业务显著 | 要看效应量是否达到MDE |

### 10.5 多重检验校正速记

| 方法 | 控制目标 | 严格程度 | 适用场景 |
|------|----------|----------|----------|
| **Bonferroni** | FWER（族错误率） | 严格保守 | 检验次数少（<10），主指标+护栏 |
| **BH** | FDR（错误发现率） | 宽松高效 | 检验次数多，分群异质性探索分析 |

| 类别 | 示例指标 |

### 10.7 辛普森悖论速记

- **定义**：分组趋势一致，汇总趋势消失或反转
- **原因**：实验组和对照组的用户结构不同（新老/活跃度/渠道/时间/地域）
- **检测**：分层分析 + 协变量平衡检验
- **处理**：SRM导致→重跑；随机波动→回归调整/CUPED；真实异质性→差异化策略
- **关键**：不能只看汇总结果，必须分层验证

### 11.2 高频Q&A

**Q：AB实验的完整流程是什么？**

A：我按四步走。第一步是实验设计：提出可证伪的假设（H0两组无差异、H1两组有差异）；定指标，分主指标（人均时长、DAU、留存）、护栏指标（负反馈率、崩溃率、延迟、多样性）、观测指标（CTR、消费VV）三类；用功效分析算样本量，核心公式是n ∝ (z_α+z_β)²·σ²/δ²，α=0.05、功效=0.8、δ是最小可检测效应；定分流单元（推荐算法一般用户级）和实验周期（至少覆盖完整周中周末）。

第二步是实验执行：上线前做AA实验验证分流均匀性和基线一致性；小流量起步（1%-5%），验证无严重负向后逐步放量；持续做SRM（样本比率不匹配）监控，用卡方检验，p<0.01认为存在SRM；监控数据质量（埋点、上报、延迟）。

第三步是实验分析：做统计显著性检验（连续指标用Z检验，比例指标用卡方检验）；区分统计显著和业务显著，看效应量是否达到MDE，看置信区间而不是只看p值；做分群异质性分析，看哪些用户受益哪些受损；做多重检验校正，主指标用Bonferroni、分群分析用BH；排查辛普森悖论，分层验证汇总结论；检查南辕北辙指标，短期涨长期跌的不能放量。

第四步是决策：主指标显著正向+护栏无恶化→放量；主指标不显著→分析原因迭代或下线；主指标正向但护栏恶化→权衡修复后再决策。我在腾讯的实践是平均一个月完成一个实验——空跑一周、对比一周、分析决策、放量观察，邮件报备技术leader批准后放量。

**Q：怎么算样本量？能举个例子吗？**

A：样本量计算用功效分析，核心公式是n = 2·(z_α/2 + z_β)²·σ²/δ²。四个参数：α是显著性水平一般取0.05（双侧z=1.96），1-β是统计功效一般取0.8（z_β=0.84），σ是指标的标准差从历史数据估计，δ是最小可检测效应——这是最关键的参数，要结合业务确定，比如留存提升0.5pp就算有价值。

举个具体例子：人均时长基线30分钟，预期提升2%（δ=0.6分钟），标准差15分钟，α=0.05功效0.8。代入公式：n=2×(1.96+0.84)²×15²/0.6²=2×7.84×225/0.36≈9800。每组需要约9800用户，两组共约19600。如果DAU是1000万，用1%流量一天就够样本量，但考虑周中周末效应仍建议跑至少一周。

再比如CTR从5%提升相对5%（绝对0.25pp），用比例指标的公式，每组要约12.2万用户。关键直觉是：效应越小、波动越大，需要的样本越多，而且是平方关系——效应减半样本量要翻四倍。样本量不够就别硬跑，检出不了小效应，跑了也是白跑。

**Q：SRM是什么？怎么检测和处理？**

A：SRM是Sample Ratio Mismatch（样本比率不匹配），指实验组和对照组的样本量比例偏离了预期分流比例，且统计显著。比如预期50:50，实际48:52且卡方检验显著。

检测用卡方检验：χ²=Σ(O-E)²/E，O是实际观测样本量，E是按分流比例计算的预期样本量，自由度=组数-1，p<0.01认为存在SRM（比常规0.05更严格，因为SRM是严重问题）。举个例子：总样本20万，预期50:50即每组10万，实际实验组9.5万对照组10.5万，χ²=(95000-100000)²/100000+(105000-100000)²/100000=5000，p远小于0.001，严重SRM。

SRM是AB实验中最严重的问题——存在SRM意味着随机化失败，实验结果不可信，不能用统计方法校正，必须先排查解决。常见原因有六类：分流逻辑bug（哈希函数有偏、代码错误）、流失差异（实验组体验差导致用户流失）、准入条件差异（两组准入逻辑不一致）、数据上报问题（实验组埋点上报率低）、端/版本差异（两组客户端版本分布不一致）、机器人/爬虫异常流量。

排查顺序是先查分流逻辑和流失，这是最常见的两个原因；然后查数据上报和准入条件；必要时修复后重跑。SRM未解决前不能下结论，即使主指标看起来很好也不能放量。我的实践是：实验上线前做AA实验预防SRM，上线后持续做SRM监控，发现SRM立即暂停实验排查。

**Q：p值有哪些常见误区？怎么正确理解p值？**

A：p值是面试最高频的考点，我总结了六个常见误区。

第一，p值不是原假设为真的概率。p值的定义是：在原假设为真的前提下，观察到当前或更极端结果的概率。p=0.03不是说原假设只有3%概率为真，而是说如果原假设为真，观察到当前结果的概率只有3%。要算原假设为真的概率需要贝叶斯方法。

第二，p值越小不代表效应越大。p值只反映统计显著性，大样本下微小效应也能得到极小p值。比如人均时长提升0.6秒，在千万级样本下p可能<0.001，但业务上毫无意义。必须同时看效应量和置信区间。

第三，p>0.05不是"没有效果"。p>0.05只说明没有足够的证据拒绝原假设，可能是效应真实存在但样本量不足（第二类错误），也可能是效应确实很小。正确说法是"未检测到显著差异"，而不是"两组没有差异"。

第四，p<0.05不代表一定能复现。单次实验的p值受随机波动影响，p=0.04的实验复现率可能只有50%左右。要看效应量的置信区间，而不是只看是否跨过0.05的阈值。

第五，不能反复看p值直到显著。这叫"偷看"（peeking），多次检验会放大假阳性率——如果每天看一次，实际假阳性率可能高达20%-30%而不是5%。要预注册分析计划，或用序贯检验（如O'Brien-Fleming边界）或EGO控制整体错误率。

第六，统计显著不等于业务显著。统计显著只说明差异不太可能是随机波动，不代表差异有业务价值。必须区分统计显著和业务显著，看效应量是否达到业务关心的最小可检测效应（MDE）。

我更推荐看置信区间而不是只看p值——95%置信区间同时给出了显著性（区间是否包含0）和效应量（区间位置和宽度），信息量更大、更直观。

**Q：多重检验问题是什么？Bonferroni和BH有什么区别？**

A：多重检验问题是指同时进行多个统计检验时，即使所有原假设都为真，至少有一个检验错误地拒绝原假设（假阳性）的概率会随着检验次数增加而增大。单次检验α=0.05时假阳性率5%，但同时看10个指标，至少一个假阳性的概率=1-(1-0.05)^10≈40%；看20个指标高达64%。所以在AB实验中同时看20个指标，很可能有1个"显著"其实是假阳性。

AB实验中的多重检验场景包括：多指标检验（5-20个）、多分群检验（10-50个维度）、多天检验（偷看，7-30次）、多版本对比。

校正方法有两种主流。第一种是Bonferroni校正，把显著性水平α除以检验次数m，比如20个指标就用0.05/20=0.0025作为阈值。优点是简单易懂、严格控制FWER（族错误率——至少一次假阳性的概率≤α）；缺点是过于保守、大幅降低统计功效，适合检验次数少（<10）的场景，比如主指标加护栏指标。

第二种是BH校正（Benjamini-Hochberg），控制FDR（错误发现率——在所有被拒绝的原假设中假阳性所占的期望比例）。方法是把m个p值从小到大排序，找到最大的k使得p_(k)≤(k/m)×α，前k个显著。优点是比Bonferroni宽松、统计功效更高；缺点是控制的是FDR而非FWER，允许一定比例的假阳性，适合检验次数多的探索性分析，比如分群异质性分析。

我的实践策略是：实验前预注册分析计划明确主指标；主指标和护栏指标数量少用Bonferroni严格控制；分群异质性分析是探索性的用BH；如果需要中期看数据用序贯检验或EGO控制整体错误率，不能偷看；分群分析中发现的显著效果需要在独立样本或后续实验中验证，不能直接作为结论。

**Q：什么是辛普森悖论？AB实验中怎么排查？**

A：辛普森悖论是指在分组分析中每组都呈现相同的趋势，但在汇总分析中趋势消失甚至反转的现象。经典原因是实验组和对照组的用户结构不同——比如实验组高活用户占比高，高活用户转化率天然高，汇总后看起来实验组更好，但分层看每个群其实策略没效果甚至负向。

AB实验中常见的辛普森悖论场景有五类：新老用户结构差异（实验组新用户占比不同）、活跃度结构差异（实验组高活用户占比高）、流量来源差异（实验组高转化渠道流量占比高）、时间结构差异（实验组在高转化时段流量占比高）、地域结构差异（实验组高线城市用户占比高）。

检测方法有两个：第一是分层分析，按关键维度（新老用户、活跃度、渠道、地域、时间）分层看效果，对比分层结论和汇总结论是否一致；第二是协变量平衡检验，检验实验组和对照组在关键协变量上的分布是否一致——如果随机化正确，应该一致。

处理上要区分三种情况：第一，如果是随机化失败（SRM导致的结构差异），实验结果不可信，必须修复分流后重跑；第二，如果是随机波动导致的轻微结构差异，用回归调整或CUPED估计调整后的处理效应；第三，如果是真实的分群异质性（不同群效果确实不同），那就不是悖论，应该做差异化策略——对正向分群上线，对负向分群不上线。

关键原则是：不能只看汇总结果，必须分层验证。报告时同时给出汇总和分层结果，说明分层情况。我在腾讯做AB实验分析时，一定会做分层分析，特别是按新老用户和活跃度分层，这是最容易出现辛普森悖论的维度。

**Q：护栏指标怎么设计？什么是南辕北辙指标？**

A：护栏指标是AB实验的安全网——即使主指标提升，护栏恶化也不能放量。比如通过强推低质内容提升了时长，但负反馈率飙升，这种实验不能放量。

推荐业务的护栏指标分六类：第一是用户体验类，包括1s快划率、不感兴趣率、举报率、负反馈率；第二是系统稳定性类，包括崩溃率、接口延迟、超时率、错误率；第三是内容生态类，包括内容多样性（熵/基尼系数）、创作者覆盖率、新内容曝光占比；第四是用户渗透类，包括功能渗透率、活跃用户数、新用户占比；第五是商业化类，包括广告加载率、广告CTR、eCPM、付费率；第六是长期价值类，包括次日留存、7日留存、30日留存、用户生命周期价值。

决策规则很明确：主指标显著正向+护栏无恶化才放量；护栏轻微恶化但在可接受范围可以权衡后放量并持续监控；护栏严重恶化即使主指标正向也不能放，要修复后再实验；主指标负向立即停止。护栏恶化后要先确认是真实的不是数据问题，再定位原因、评估严重程度、修复策略、重新实验。

比护栏更隐蔽的是"南辕北辙指标"——短期指标提升但长期指标下降。常见场景：强推低质高时长内容导致短期时长涨但次留跌；标题党导致CTR涨但消费深度降；引导关注低质账号导致关注率涨但留存跌；广告加载过多导致收入涨但DAU跌；过度精准推荐导致多样性降形成信息茧房长期疲劳。

防范方法是：第一，上线前把长期目标（留存、生态）作为护栏指标；第二，短期实验通过后做长期留存追踪，不只信短实验窗口；第三，设置新奇效应消除期，等效应稳定后再决策；第四，在模型或策略中显式加入长期目标的约束，避免过度优化短期指标。我在腾讯做推荐时就特别注意这个——不会为了短期CTR提升而牺牲长期留存，会把次留和7留作为护栏指标持续监控。

**Q：AA实验是什么？和SRM有什么关系？**

A：AA实验是指实验组和对照组使用完全相同的策略（都是base版本），验证分流是否均匀、两组基线指标是否无显著差异。AA实验在实验开始前做，是"预防性"检查——如果AA实验中两组就有显著差异，说明分流或数据有问题，后续AB实验的结果不可信。

AA实验的通过标准有四个：两组用户量比例符合预期（如50:50）；核心指标在两组之间无统计显著差异（p>0.05）；用户画像分布（年龄、性别、城市等级、活跃度）在两组之间无显著差异；SRM检验通过。

SRM检测是在实验进行中持续监控的，实时检测样本量比例是否偏离预期，是"监控性"检查。两者互补：AA实验在实验前预防，SRM在实验中监控。最佳实践是实验上线前做AA实验验证，上线后持续做SRM监控。

为什么两者都需要？因为AA实验只能验证实验启动时的分流均匀性，但实验运行过程中可能出现新的问题导致SRM——比如实验组体验差导致用户流失（流失差异）、实验组埋点上报率下降（数据上报问题）、实验准入逻辑在运行中被修改（准入条件差异）。这些问题在AA实验阶段不会出现，但在实验运行中会导致SRM。所以需要持续监控。

我在腾讯的实践是：重要实验上线前必须做AA实验，AA通过后才能上线AB；AB上线后每天看SRM检测结果，发现SRM立即暂停排查。
