# DAU异常归因与拆解方法论

---

## 一、DAU异动排查八步拆解法

DAU异动排查是数据科学岗位面试最高频的考点，没有之一。我在QB经历过DAU持续六周线性下降647万的完整拆解，沉淀了一套系统化的八步拆解法。这套方法的核心思想是：**先确认问题、再定位人群、然后归因建模、最后输出行动**，每一步都有明确的输出物和判断标准。

### 1.1 八步拆解法全景

```
DAU异动
    │
    ▼
┌─ 第一步：确认问题 ────────────────────────────────────┐
│  跌幅多少？持续多久？是单点异动还是趋势性变化？        │
│  是否季节性？对比去年同期、看竞品是否同趋势             │
│  输出：问题定义文档（时间范围、跌幅、背景事实）         │
└────────────────────────────────────────────────────────┘
    │
    ▼
┌─ 第二步：人口属性拆解 ────────────────────────────────┐
│  按年龄段、城市等级、性别、手机品牌聚类                 │
│  用决策树建模找到下跌最明显的人群                       │
│  输出：高风险人群画像（哪些人跌得最狠）                 │
└────────────────────────────────────────────────────────┘
    │
    ▼
┌─ 第三步：活跃度拆解 ──────────────────────────────────┐
│  高活/中活/低活/沉默用户的流转矩阵变化                 │
│  哪个流转环节变化最大？高活→高活比例是否下降？          │
│  输出：活跃度流转差异矩阵（红色标记差异>5%的环节）      │
└────────────────────────────────────────────────────────┘
    │
    ▼
┌─ 第四步：业务渗透拆解 ────────────────────────────────┐
│  各业务（资讯/小说/搜索/文件/网页等）用户的变化        │
│  多业务交叉渗透用户的变化（如小说低活+搜索高活）        │
│  输出：业务渗透差异表（哪些业务用户跌得最狠）           │
└────────────────────────────────────────────────────────┘
    │
    ▼
┌─ 第五步：归因建模 ────────────────────────────────────┐
│  高活用户下跌归因：CART决策树建模，找特征重要度         │
│  资讯用户下跌归因：内容类型对留存间隔的影响             │
│  小说用户下跌归因：产品变更、竞品影响                   │
│  运营策略变更：红点、Push、活动等运营动作的影响         │
│  输出：归因结论（各因素可解释的降幅）                   │
└────────────────────────────────────────────────────────┘
    │
    ▼
┌─ 第六步：路径漏斗分析 ────────────────────────────────┐
│  首启→主启→信息流→曝光→点击→消费各环节转化率变化      │
│  大盘到信息流的路径漏斗，各起始路径的渗透率             │
│  输出：漏斗断点定位（哪个环节转化率下降最多）           │
└────────────────────────────────────────────────────────┘
    │
    ▼
┌─ 第七步：外部因素验证 ────────────────────────────────┐
│  竞品趋势对比（腾讯新闻等是否同趋势）                   │
│  季节性因素（暑期、疫情、节假日）                       │
│  行业性事件（政策、监管变化）                           │
│  输出：外部因素影响评估（行业性vs个体性）               │
└────────────────────────────────────────────────────────┘
    │
    ▼
┌─ 第八步：结论与行动建议 ──────────────────────────────┐
│  归因汇总（各因素可解释降幅及重合度说明）               │
│  企稳判断（利空因素是否已兑现）                         │
│  行动建议（可落地的改进措施及预期效果）                 │
│  输出：完整分析报告+行动清单                             │
└────────────────────────────────────────────────────────┘
```

### 1.2 每一步的关键判断标准

| 步骤 | 关键问题 | 判断标准 | 常见陷阱 |
|------|----------|----------|----------|
| **确认问题** | 是真跌还是数据问题？ | 对比T+1和T+2数据，排除上报延迟；查ETL任务日志 | 一看到跌就开始归因，结果是埋点延迟 |
| **人口属性** | 哪些人跌得最狠？ | 决策树分裂增益最大的节点 | 只看单维度，忽略交叉效应（如51岁+三线城市） |
| **活跃度** | 哪个流转环节变化最大？ | 流转矩阵差异>5%标记为红色 | 只看绝对值变化，不看比例变化 |
| **业务渗透** | 哪些业务用户跌得最狠？ | 单业务+多业务交叉都要看 | 只看单业务，忽略多业务交叉用户的特殊行为 |
| **归因建模** | 最重要的影响因素是什么？ | CART特征重要度排序 | 把相关性当因果性，缺少验证 |
| **路径漏斗** | 哪个环节转化率下降？ | 逐层转化率环比变化 | 用错口径（宽口径vs严口径）导致转化率失真 |
| **外部因素** | 是行业性还是个体性？ | 竞品同趋势=行业性，竞品不同=个体性 | 忽略竞品验证，把行业性下跌归因到自身策略 |
| **结论行动** | 归因是否完整？行动是否可落地？ | 可解释降幅之和≈总降幅（允许重合）；行动有owner和时间线 | 归因不完整就下结论；行动建议空泛不可执行 |

### 1.3 八步法的时间分配建议

在实际工作中，八步拆解的时间分配不是平均的：

- **第一步确认问题**：10%时间——快速排除数据问题，定义清楚问题
- **第二到第四步定位人群**：30%时间——下钻定位是基础工作，需要扎实
- **第五步归因建模**：35%时间——这是核心，需要建模和深入分析
- **第六步漏斗分析**：10%时间——辅助验证，确认链路断点
- **第七步外部验证**：5%时间——快速对比竞品
- **第八步结论行动**：10%时间——整理输出，确保行动可落地

> **面试口述版**：DAU跌了怎么排查？我的方法论是八步拆解法。第一步确认问题——跌幅多少、持续多久、是不是季节性，先排除数据上报问题。第二步人口属性拆解——按年龄、城市、性别、机型用决策树找下跌最明显的人群。第三步活跃度拆解——做高/中/低活/沉默的流转矩阵，看哪个流转环节变化大。第四步业务渗透拆解——各业务用户的变化，包括多业务交叉渗透用户。第五步归因建模——对高活用户用CART决策树找特征重要度，对资讯用户分析内容类型对留存间隔的影响，对小说用户看产品变更和竞品。第六步路径漏斗——首启→主启→信息流→消费各环节转化率。第七步外部因素——竞品、季节、疫情。第八步结论和行动建议。我在QB实际做过六周下跌647万的完整拆解，就是用这套方法论。

## 二、六周下跌647万完整案例

这是我在QB做过的最完整的DAU异动拆解案例，也是面试中最有说服力的项目经历。

### 2.1 问题定义

**时间范围**：2020年6月15日（周一）- 7月26日（周日），共计六个自然周。

**时间分段**：

| 周次 | 具体周期 |
|------|----------|
| w1 | 6.15-6.21 |
| w2 | 6.22-6.28 |
| w3 | 6.29-7.5 |
| w4 | 7.6-7.12 |
| w5 | 7.13-7.19 |
| w6 | 7.20-7.26 |

（来源：QB大盘DAU下跌.txt）

**核心现象**：QB大盘DAU呈现**线性下降趋势**，不是单点异动而是趋势性变化。

### 2.2 背景事实

在正式拆解前，先厘清几个关键背景事实：

**事实1：最近一年QB大盘DAU经历了三升三降。**
- 1到2阶段整体持平
- 3到4阶段净增量1000万
- 5到6阶段整体持平
- 流转差异大于5%的环节（红色标记）：高活转高活、中活转中活、中活转沉默、低活转沉默

（来源：QB大盘DAU持续六周下降拆解.txt）

**事实2：此时间段刚好是北京新发地二次疫情后的回落期。**
- 一次疫情拉动的用户和二次疫情拉动的用户左右箭头刚好持平
- 新发地二次疫情唤起的中低活+沉默用户，以及没有建立主启心智的用户，在6.15-7.26期间慢慢流失

（来源：QB大盘DAU持续六周下降拆解.txt）

### 2.3 跌幅量化

| 业务 | 局部高点→低点 | 高点降幅 | 局部低点→更低点 | 低点降幅 |
|------|-------------|---------|----------------|---------|
| **大盘** | 9057w→8410w（**647w**） | **7.7%** | 8249w→7833w | 5.3% |
| **资讯** | 4939w→4595w | 7.4% | 4412w→4310w | 2.3% |
| **文件** | 1936w→1755w | 10.3% | 1644w→1498w | 9.7% |
| **小说** | 885w→762w | 16.1% | 754w→540w | **39.6%** |

（数据来源：QB大盘DAU持续六周下降拆解.txt）

> **关键观察**：
> 1. 大盘下跌647万，降幅7.7%
> 2. 小说业务下跌最惨烈——高点降幅16.1%，低点降幅高达39.6%，远超大盘
> 3. 文件业务跌幅也超过大盘（10.3% vs 7.7%），说明文件业务是下跌重灾区
> 4. 资讯业务跌幅与大盘基本持平（7.4% vs 7.7%），属于跟随大盘下跌

### 2.4 跌幅归因汇总

大盘DAU总共647万的降幅，我拆解为以下几个可解释的因素：

| 归因因素 | 可解释降幅 | 计算逻辑 | 重合度说明 |
|----------|-----------|----------|-----------|
| **桌面红点停投** | **~200万** | 6月全量发红点，7月仅新用户+沉默+低活发放，结合红点AB实验比例折算 | 与活跃度下降有一定重合 |
| **主动文件暑期下降** | **~150万** | 文件tab+高级功能连续下降，降幅超过大盘，将主动文件用户降幅比例折算 | 与活跃度下降有一定重合 |
| **Push DAU下降（热点消退）** | **~47万** | push有启UV降幅 × 0.3 | 相对独立 |
| **用户活跃度下降** | **~400万** | 高活→高活比例下降，中活转低活/沉默比例上升，折算 | 与前三点有一定重合度 |
| **CTR下降** | 潜在传导 | 推荐侧排查中，CTR下降与DAU存在潜在传导关系 | 尚未量化 |
| **其他运营策略** | 已排除 | 排除了其他运营策略对大盘DAU的影响 | - |

（数据来源：QB大盘DAU持续六周下降拆解.txt）

> **归因解读**：
> 1. 四个主要因素的可解释降幅之和（200+150+47+400=797万）超过了总降幅647万，这是因为各因素之间存在重合度——同一个用户可能同时受到红点停投、活跃度下降等多个因素的影响
> 2. 用户活跃度下降（400万）是最大的单一因素，但它与其他因素高度重合，本质上是其他因素导致的结果
> 3. 红点停投（200万）和文件暑期下降（150万）是相对独立的可解释因素，合计350万，占总降幅的54%
> 4. Push消退（47万）影响较小但可精确量化

### 2.5 企稳验证

**7.26后QB大盘DAU相对企稳在8100万的位置**，没有进一步下跌。

**判断逻辑**：
- 短期内（3-6周），利空因素已兑现——红点停投、文件暑期下降、Push消退、用户活跃度下降这些因素都已经在6.15-7.26期间充分反映
- 预计QB大盘DAU不会进一步下跌

（来源：QB大盘DAU持续六周下降拆解.txt）

### 2.6 竞品验证

**相同时间范围，腾讯新闻的走向也有类似趋势。**

整体来说，QB的DAU、资讯DAU、腾讯新闻DAU保持了**"同趋势"**——说明这轮下跌有行业性因素，不完全是QB自身的问题。

（来源：QB大盘DAU持续六周下降拆解.txt）

> **面试口述版**：我在QB做过DAU持续六周下跌647万的完整拆解。时间是2020年6月15日到7月26日，六个自然周，大盘从9057万跌到8410万，降幅7.7%。分业务看，小说最惨——高点降幅16.1%，低点降幅39.6%；文件跌10.3%超过大盘；资讯跌7.4%跟大盘持平。
>
> 归因上我拆了四个因素：第一桌面红点停投解释200万——6月全量发红点，7月只对新用户+沉默+低活发放，结合AB实验比例折算；第二主动文件暑期下降解释150万——文件tab和高级功能连续下降，降幅超过大盘；第三Push消退解释47万——push有启UV降幅乘0.3；第四用户活跃度下降解释400万——高活转高活比例下降，中活转低活和沉默上升。四个因素加起来797万超过总降幅647万，因为有重合度。
>
> 最后7.26后企稳在8100万，利空因素已兑现。竞品验证发现腾讯新闻同趋势，说明有行业性因素。

## 三、CART决策树归因方法

在DAU拆解的第五步（归因建模）中，我对高活用户使用了CART分类树建模，这是整个拆解中最有技术含量的部分。

### 3.1 CART决策树原理

CART（Classification and Regression Trees）是一种二叉决策树算法，既可以做分类也可以做回归。在DAU归因场景中，我用的是分类树——目标是预测用户是否会流失（二分类），通过特征分裂找到对流失影响最大的因素。

**核心原理**：
```
输入：用户特征矩阵X（成为用户期间、疫情前活跃度、业务渗透数、使用时长、首启主启比例）
      用户标签y（是否流失：流失=1，留存=0）

算法流程：
1. 从根节点开始，遍历所有特征和所有可能的分裂点
2. 选择使Gini不纯度下降最大的特征和分裂点
3. 将节点分裂为左右两个子节点
4. 递归执行，直到满足停止条件（最大深度、最小样本数等）
5. 输出：决策树结构 + 特征重要度排序

特征重要度 = 该特征在所有节点上的Gini增益之和（归一化后）
```

**Gini不纯度公式**：
$$Gini = 1 - \sum_{i=1}^{n} p_i^2$$

其中$p_i$是节点中第$i$类样本的比例。Gini值越小，节点越纯。

### 3.2 建模设计

**样本**：随机抽取100万618当日高活用户，以guid粒度进行CART分类树建模。

**标签定义**：用户在疫情后是否流失（连续7天没有再来=流失）。

**特征工程**：

| 特征名 | 定义 | 取值/分箱 |
|--------|------|----------|
| **成为QB用户的期间** | first_date，用户首次使用QB的时间 | 分四段：pre（1月24日以前）、in（1/24-5/1）、post_pre（5/1-6/10）、post（6/10以后） |
| **疫情前是否是高活** | 6.10之前用户的活跃度状态 | 高活/中活/低活/沉默 |
| **业务渗透数目** | 用户使用的业务功能数量（612-618期间） | 数值特征 |
| **QB使用时长** | 用户的产品使用时长 | 分中/高/低三档（mean=66.02，+1std=68.68，-1std=63.35） |
| **首启为主启的比例** | 首启是主启的天数 / 周活跃天数 | 数值特征，关键阈值0.7 |

（数据来源：QB大盘DAU下跌.txt）

### 3.3 特征重要度结论

**影响高活用户最重要的因素是：在6.10号之前用户是否是高活用户。**

具体的流失率数据：

| 用户类型 | 流失率 | 留存率 |
|----------|--------|--------|
| 疫情前不是高活的用户 | **76%流失**（连续7天没再来） | 24% |
| 疫情前是低活的用户 | **92.9%流失** | 7.1% |
| 疫情前是高活的用户 | **仅36.9%流失** | 63.1% |
| 疫情前高活但首启主启比例<0.7 | **72.5%流失** | 27.5% |

（数据来源：QB大盘DAU持续六周下降拆解.txt、QB大盘DAU下跌.txt）

> **核心结论解读**：
> 1. **疫情前高活用户有63.1%的概率留下来**——说明高活用户的粘性确实更强
> 2. **但如果没有主启心智（首启主启概率<0.7），留存概率骤降到27.5%**——这是最关键的发现！高活本身不够，必须建立主启心智
> 3. **疫情前不是高活用户，留存概率仅24%**——疫情临时唤起的用户很难留住
> 4. **疫情前低活用户流失率高达92.9%**——低活用户几乎全部流失
>
> 总结：新发地二次疫情唤起的中低活+沉默用户，以及在二次疫情中没有建立主启心智的用户，在6.15-7.26期间慢慢流失，没有被很好地留住，构成了这轮下跌的主要动力。跟一次疫情相仿，但流失率比一次疫情更严重。

### 3.4 CART决策树的优势与局限

| 维度 | 说明 |
|------|------|
| **优势1：可解释性强** | 决策树的分裂路径可以直接解读，每个节点的条件和对应的流失率都很清晰，非技术团队也能理解 |
| **优势2：特征重要度排序** | 自动输出特征重要度，快速定位最关键的影响因素，不需要人工逐个试 |
| **优势3：处理非线性关系** | 能捕捉特征之间的交互效应（如"高活AND首启主启<0.7"的组合效应），这是线性模型做不到的 |
| **优势4：不需要特征标准化** | 决策树对特征尺度不敏感，数值特征和类别特征都能直接用 |
| **局限1：容易过拟合** | 单棵决策树如果不限制深度，会学到很多噪声，需要剪枝或用随机森林 |
| **局限2：不稳定性** | 样本稍微变化，树的结构可能就不一样，特征重要度可能波动 |
| **局限3：相关性≠因果性** | 决策树找到的是相关性，要确认因果还需要AB实验或DID等方法验证 |
| **局限4：类别特征处理** | 高基数类别特征（如用户ID）会导致过拟合，需要合理分箱 |

> **面试口述版**：在归因建模这一步，我对高活用户用了CART分类树。随机抽了100万618当日高活用户，标签是疫情后是否流失（连续7天没来=流失）。特征有五个：成为QB用户的期间（first_date分pre/in/post_pre/post四段）、疫情前是否高活、业务渗透数目、QB使用时长（分中高低，mean=66.02）、首启为主启的比例。
>
> 建模结果发现，影响高活用户最重要的因素是疫情前是否高活。疫情前不是高活的用户76%流失，低活用户92.9%流失，高活用户只有36.9%流失。但最关键的发现是——高活用户如果首启主启比例小于0.7（没有主启心智），72.5%会流失，留存率从63.1%骤降到27.5%。这说明高活本身不够，必须建立主启心智。
>
> CART决策树的优势是可解释性强、能输出特征重要度、能处理非线性和交互效应。局限是容易过拟合、不稳定、找到的是相关性不是因果性。所以我用CART做归因定位，然后用AB实验和DID做因果验证。

## 四、主启DAU分析框架

主启（用户主动打开APP）是QB DAU的核心组成部分，也是用户心智的直接体现。我在QB做过完整的主启DAU分析，形成了一套系统化的分析框架。

### 4.1 主启vs外部调起

QB的DAU由两种启动方式构成：

| 启动方式 | 定义 | start_type字段 | 用户心智 |
|----------|------|---------------|----------|
| **主启** | 用户主动点击APP图标打开 | `start_type='qb'` | 强心智，用户主动想来 |
| **外部调起** | 通过其他APP/链接/Pull调起打开 | `start_type='pull'` | 弱心智，被外部唤起 |

（来源：qb大盘首启主启&外部调起用户路径-脑图.txt）

> **为什么主启重要**：主启用户代表用户对产品有主动使用的心智，留存和长期价值远高于外部调起用户。DAU下跌的本质往往是主启DAU下跌——外部调起可以靠Push和红点拉回来，但主启心智一旦丢失就很难恢复。我在CART决策树分析中发现，首启主启比例<0.7的高活用户72.5%流失，就是主启心智重要性的直接证据。

### 4.2 新用户主启转化分析

我根据新用户现有转化及活跃情况，将用户拆解成5个人群：

| 人群 | 定义 | 占比 | 策略抓手 |
|------|------|------|----------|
| **人群1：未主启过** | 在新增的一个月内从未主启 | **17%** | 分析转化渠道来源、最佳转化周期、用户画像、行为差别 |
| **人群2：首启一次后再未主启** | 新增一个月内有过一次主启，之后再没有 | **38%** | 了解用户转化后的第一行为，不同业务渗透的转化情况 |
| **人群3：低活用户** | 新增一个月内的低活用户 | **32.6%** | 提升活跃度，引导更多业务渗透 |
| **人群4：中活用户** | 新增一个月内的中活用户 | **9.8%** | 从中活提升到高活 |
| **人群5：高活用户** | 新增一个月内的高活用户 | **9.2%** | 维持高活状态，防止衰退 |

（数据来源：主启DAU分析（旧）.txt）

> **关键发现**：
> 1. 新用户一个月内未主启过的只占17%，**超过83%的新用户在一个月内就主启了QB**
> 2. 其中**67%的用户新增当天就做过主启**
> 3. 以一月为例，1700万新用户只有299万用户未做过主启——所以将未做过主启的用户转化为主启的空间有限
> 4. 最大的人群是"首启一次后再未主启"（38%）——这说明很多用户尝试了一次但没有形成持续使用的习惯，这是主启提升的核心抓手

### 4.3 人群2深度分析：首启一次后再未主启

这是占比最大（38%）也最有提升空间的人群。我做了深入分析：

**用户首次主启后的第一行为分布**：
- **17%的用户直接关闭了QB**——说明首启体验不好，用户进来后没有找到感兴趣的内容
- **12%用户去访问外部链接**——说明用户被外部内容吸引走了，没有在QB内形成消费闭环

（数据来源：主启DAU分析（旧）.txt）

**业务渗透分布**（首启一次后再未主启的用户）：

| 业务渗透个数 | 占比 |
|-------------|------|
| 0 | 2.72% |
| 1 | 26.78% |
| 2 | 34.57% |
| 3 | 26.54% |
| 4 | 9.39% |

（数据来源：主启DAU分析（旧）.txt）

> **洞察**：首启一次后再未主启的用户中，超过97%有至少1个业务渗透，说明用户不是没有使用任何功能，而是使用了1-2个功能后没有形成持续使用的习惯。这说明问题不在"有没有用"，而在"用了之后为什么不回来"——需要从首启体验和内容承接上找原因。

### 4.4 主启转化的关键发现（第三版分析）

在后续的第三版分析中，我有了更深入的发现：

**发现1：未转化主启用户中pull渠道占比最大。**
- 单看渠道来说，常用pull渠道的用户有**47%未主启过**
- pull调起用户较为容易被"训练"为主启用户，相对来说push和noti的用户较难改变

（数据来源：主启DAU分析（旧）.txt）

**发现2：从1次主启变成2次主启是关键拐点。**
- 吸引用户多次主启可以帮助培养用户主启习惯
- **从1次主启变成2次主启，会培养36%的用户将主启当成主要启动方式**
- 策略要引导用户做二次主启

（数据来源：主启DAU分析（旧）.txt）

**发现3：搜索场景渗透对二次留存影响最大。**
- 使用过搜索场景的用户更容易有二次留存
- **有搜索场景渗透的用户，有二次留存的比例高35%**
- 资讯与文件场景也会对用户二次留存有一定正面影响
- **基础场景（收藏夹、设置、停留首页等）对用户二次留存并没有正面影响，甚至有负面影响**

（数据来源：主启DAU分析（旧）.txt）

**发现4：有二次留存用户的行为深度远高于无二次留存用户。**
- 有二次留存的用户在刷新次数、总时长、图文消费、主feed曝光等方面都远高于无二次留存的用户
- **图文消费影响最明显：有二次留存的用户图文消费是未二次留存用户的1.7倍**
- 频道刷新影响最不明显：有二次留存的用户图文消费仅比未二次留存的用户多15%
- 在对子业务拆分后，发现图文与图集的时长与PV对用户二次留存影响最大

（数据来源：主启DAU分析（旧）.txt）

**发现5：各渠道主启转化率差异显著。**
- **push渠道的转化率最高，60%的之前常用push的用户之后有主启**
- noti转化情况最差，只有40%

（数据来源：主启DAU分析（旧）.txt）

### 4.5 主启DAU提升策略框架

基于以上分析，我总结了主启DAU提升的策略框架：

```
主启DAU提升
    ├── 拉新侧：提升新用户首启率
    │   ├── 优化应用商店素材和描述
    │   ├── 渠道精细化运营（push渠道转化率60%最高）
    │   └── 新用户首启体验优化（17%用户首启后直接关闭）
    │
    ├── 转化侧：从1次主启→多次主启（关键拐点）
    │   ├── 引导二次主启（1→2次主启培养36%用户常主启）
    │   ├── 搜索场景渗透（有搜索渗透的用户二次留存高35%）
    │   ├── 图文内容承接（有二次留存用户图文消费是1.7倍）
    │   └── 避免基础场景（收藏夹/设置/首页停留对留存无正面影响）
    │
    ├── 召回侧：外部调起用户转主启
    │   ├── pull用户训练为主启（pull用户47%未主启，最易训练）
    │   ├── 红点召回（桌面红点提频预计贡献80万delta DAU）
    │   ├── Push召回（热点消退导致Push DAU下降47万）
    │   └── 每日仅外部调起的1200万用户转主启
    │
    └── 留存侧：建立主启心智
        ├── 首启主启比例>0.7（高活+主启心智=63.1%留存）
        ├── 多业务渗透（业务渗透越多留存越高）
        └── 内容消费深度（图文/图集消费对二次留存影响最大）
```

> **面试口述版**：主启DAU分析是我在QB做的另一个核心项目。QB的DAU分主启（start_type='qb'，用户主动打开）和外部调起（start_type='pull'，被其他APP唤起）两种，主启代表用户心智，是DAU的核心。
>
> 我把新用户拆成5个人群：未主启过17%、首启一次后再未主启38%、低活32.6%、中活9.8%、高活9.2%。关键发现是超过83%的新用户一个月内就主启了，67%新增当天就主启，所以未主启用户的转化空间有限。最大的抓手是"首启一次后再未主启"的38%用户——他们首启后17%直接关闭QB、12%去访问外部链接，说明首启体验和内容承接待优化。
>
> 第三版分析有几个关键发现：第一，pull渠道用户47%未主启，但最容易被训练为主启；第二，从1次主启到2次主启是关键拐点，能培养36%用户常主启；第三，搜索场景渗透的用户二次留存高35%，而基础场景（收藏夹/设置/首页停留）对留存甚至有负面影响；第四，有二次留存用户的图文消费是未二次留存的1.7倍；第五，push渠道主启转化率60%最高，noti只有40%。
>
> 这些发现直接指导了我们的策略：拉新侧优化首启体验，转化侧引导二次主启和搜索渗透，召回侧把pull用户和每日1200万仅外部调起的用户转主启，留存侧建立主启心智（首启主启比例>0.7）。

## 五、漏斗分析方法论

漏斗分析是定位用户转化链路瓶颈的核心方法。我在QB做过从大盘到信息流的完整路径漏斗分析，也做过首启→主启→信息流→消费的行为漏斗。

### 5.1 漏斗分析的核心原理

```
漏斗分析 = 逐层转化率分析 + 断点定位 + 优化优先级排序

核心公式：
  第i层转化率 = 第i层用户数 / 第i-1层用户数
  整体转化率 = 最终层用户数 / 起始层用户数
  层级损失 = 第i-1层用户数 - 第i层用户数

断点定位：
  找到转化率最低或损失最大的层级，就是优化重点
```

### 5.2 大盘到信息流路径漏斗

我分析了2020年9月2日大盘严口径DAU用户，他们经历的前5个场景每一步的人数，以及每个叶子节点的信息流最终渗透率。

**数据口径说明**：
- QB大盘流水表每天**1.3亿人**
- join大盘严口径DAU后**8000万**
- 刨除掉延迟上报条目（非今天的行为）后，仅剩**6900万**
- QB信息流用户仅剩**4100万**（不刨除之前是4500万，当天资讯DAU 4200万）

（数据来源：qb大盘到qb信息流路径漏斗.txt）

> **口径重要性**：这里"含有qb信息流路径的用户"与严口径信息流DAU有稍许出入，前者多出300万。做漏斗分析时必须明确每一层的口径定义和过滤条件，否则转化率会失真。

### 5.3 各起始路径的信息流渗透率排序

| 起始路径 | 信息流最终渗透率 | 排名 |
|----------|----------------|------|
| **QB小说起始** | **>60%**（最高） | 1 |
| 外部文件→基础框架 | 40-50% | 2 |
| 基础框架×4或×3 | 40-50% | 2 |
| 基础框架→搜索 | ~40% | 3 |
| 基础框架→内部文件 | ~40% | 3 |
| WEB其他开头 | 最差 | 4 |
| 外部文件→内部文件 | 较差（可能漏了钩子） | 4 |

（数据来源：qb大盘到qb信息流路径漏斗.txt）

> **关键洞察**：
> 1. **以"QB小说"起始的路径最终渗透最高，大于60%**——小说用户的内容消费意愿最强，最容易导流到信息流
> 2. 用户从一些明确场景（如小说、文件）一旦来到"基础框架"场景，或者一开始就是"基础框架"场景，信息流的渗透率就大大提高——基础框架是信息流承接的关键场景
> 3. **"基础框架-搜索"这一分支贡献信息流场景用户400万+**——搜索场景普遍渗透不高、但信息明确，是承接重点
> 4. "WEB其他"开头的路径渗透率提升空间较大
> 5. 外部文件→内部文件的路径渗透率差，可能是漏了钩子

### 5.4 连续基础框架用户的行为分析

对于连续几个"基础框架"场景的用户（约300万），我细看下用户主要干了什么。

**连续3个基础框架后的top场景**：

| 场景 | 用户数 |
|------|--------|
| QB基础框架_首页 | 395,921 |
| WEB网页 | 219,172 |
| WEB长视频 | 146,946 |
| QB基础框架_个人中心 | 110,434 |

（数据来源：qb大盘到qb信息流路径漏斗.txt）

> **关键发现**：用户除了进入一些目标明确的场景（信息流、搜索、小说等）之外，最常去的是**WEB网页和WEB长视频**。这部分用户（基础框架×3 → WEB网页/WEB长视频）细看多数去了**外部的视频网站或者成人网站（>42万）**。

### 5.6 首启主启与外部调起路径分析

我取2020年9月8日的DAU，分析用户前10步操作路径，区分主启（start_type='qb'）和外部调起（start_type='pull'）两种启动方式。

**SQL实现逻辑**（来源：qb大盘首启主启&外部调起用户路径-脑图.txt）：

```sql
-- 第一步：按序号路径，取每个用户前10步操作
create table tmp_path as
select guid, cat_1, cat_2, cat_3, content, seq
from (
  select guid, log_time, cat_1, cat_2, cat_3, content,
         row_number() over (partition by guid order by log_time asc) as seq
  from t_dwd_user_action_flow_d
  where p_date=20200908
    and to_char(log_time,'yyyymmdd')=p_date
) a
where seq <=10;

-- 第二步：路径展开，把前6步的cat1和content展开成宽表
create table tmp_path_wide as
select a.guid, a.start_type,
       max(if(seq=1,cat_1,null)) p1_cat1,
       max(if(seq=2,cat_1,null)) p2_cat1,
       ...
       max(if(seq=1,content,null)) p1_content,
       ...
from t_app_qb_user_indic_sum_guid_d a
join tmp_path b on a.guid=b.guid
where a.p_date=20200908 and a.is_dau=1
group by a.guid, a.start_type;

-- 第三步：按主启/外部调起分别统计路径分布
select start_type, p1_cat1, p2_cat1, p3_cat1, p4_cat1, count(1) user_num
from tmp_path_wide
where start_type = 'qb'  -- 或 'pull'
group by start_type, p1_cat1, p2_cat1, p3_cat1, p4_cat1;
```

**关键发现**：
- 主启用户和外部调起用户的行为路径差异显著
- 外部调起用户需要更好的承接策略，转化为主启
- 每日仅外部调起的用户约**1200万**，是转主启的重点人群

（数据来源：QB大盘DAU持续六周下降拆解.txt、qb大盘首启主启&外部调起用户路径-脑图.txt）

### 5.7 漏斗分析的最佳实践

| 实践要点 | 说明 |
|----------|------|
| **明确每一层口径** | 每一层的用户定义、过滤条件、去重规则必须明确，宽口径vs严口径差异巨大 |
| **从大到小逐层下钻** | 先看整体转化率，再逐层下钻定位断点，不要一上来就看细节 |
| **关注绝对损失和相对转化率** | 绝对损失大的层不一定是优化重点——如果基数大，即使转化率高绝对损失也大；要看相对转化率 |
| **分群看漏斗** | 不同用户群（新/老、高/低活、不同渠道）的漏斗差异很大，需要分群分析 |
| **路径漏斗vs环节漏斗** | 路径漏斗看用户的实际操作路径，环节漏斗看预设的转化环节，两者结合使用 |
| **漏斗优化的优先级** | 转化率最低且用户基数大的层级优先优化，投入产出比最高 |

> **面试口述版**：漏斗分析我在QB做过两个典型案例。第一个是大盘到信息流的路径漏斗——2020年9月2日的数据，大盘流水表1.3亿人，join严口径DAU后8000万，刨除延迟上报后6900万，信息流用户4100万。各起始路径的信息流渗透率排序：QB小说起始最高>60%，外部文件→基础框架和基础框架×3/×4是40-50%，基础框架→搜索约40%，WEB其他最差。关键发现是连续基础框架的用户约300万，其中最常去WEB网页和WEB长视频，>42万去了外部视频网站或成人网站。我抽了40个case分类：动漫21%、电影15%、剧集13%、成人11%，对应的建议是内容引入和精准推荐。
>
> 第二个是首启主启与外部调起路径分析——取9月8日DAU，用row_number取每个用户前10步操作，展开成宽表，按start_type='qb'/'pull'分别统计路径分布。发现主启和外部调起用户的行为路径差异显著，每日仅外部调起的用户约1200万，是转主启的重点人群。
>
> 漏斗分析的最佳实践：第一明确每一层口径，宽口径严口径差异巨大；第二从大到小逐层下钻；第三同时看绝对损失和相对转化率；第四分群看漏斗；第五路径漏斗和环节漏斗结合用；第六优化优先级是转化率最低且基数大的层级。

## 六、人口属性与业务渗透拆解

在八步拆解法的第二和第四步，我做了详细的人口属性和业务渗透拆解，找到了下跌最明显的人群。

### 6.1 人口属性拆解

我将6月15日和7月13日用户，按年龄段、城市等级、性别、手机品牌进行了聚类，通过决策树建模，找到下跌明显的人群：

| 人群 | 变化 | 严重程度 |
|------|------|----------|
| **51岁以上用户** | **下跌20.9%**（流失最严重） | 🔴 最严重 |
| 13-15岁用户 | 上涨9% | 🟢 增长 |
| 一线城市用户 | 下跌3% | 🟡 轻微 |
| 非一线城市用户 | 上涨7.4% | 🟢 增长 |
| 三线城市（安卓用户） | 上涨9.8% | 🟢 增长 |

（数据来源：QB大盘DAU下跌.txt）

> **解读**：51岁以上用户下跌20.9%是最严重的人群，这部分用户很可能是疫情期间被子女帮助安装/使用的，疫情过后就不再使用了。而13-15岁和三线城市安卓用户在上涨，说明年轻用户和下沉市场用户在增长。

### 6.2 业务渗透拆解

我将6月15日和7月13日用户，按业务渗透（如使用小说、搜索业务等）进行了聚类，通过决策树建模找到下跌明显的人群：

| 用户群 | 变化 | 严重程度 |
|--------|------|----------|
| **小说业务低活用户** | **下跌12.7%** | 🔴 严重 |
| **小说低活且搜索高活用户** | **下跌18.1%** | 🔴 最严重 |
| 小说业务中活用户 | 上涨6% | 🟢 增长 |
| 小说中活且文件高活用户 | 上涨15% | 🟢 增长 |
| 三方网页高活用户 | 上涨4% | 🟢 增长 |
| 非文件高活+非三方网页高活+非小说中低活 | 下跌7% | 🟡 中等 |

（数据来源：QB大盘DAU下跌.txt）

> **解读**：
> 1. **小说低活用户下跌12.7%，小说低活+搜索高活用户下跌18.1%**——这是下跌最严重的业务人群。原因是6月1号下架了盗版转码功能，小说低活用户（本来就只用盗版转码功能）直接流失
> 2. **小说中活用户反而上涨6%，小说中活+文件高活用户上涨15%**——说明正版小说用户和多业务用户没有受到下架盗版转码的影响，甚至可能因为竞品用户流入而增长
> 3. 三方网页高活用户上涨4%——说明用户还在用浏览器看网页，但没有转化到QB内部业务

### 6.3 资讯用户下跌归因：内容类型对留存间隔的影响

对于资讯用户的下跌，我通过统计用户在615-716期间每次访问QB时阅读文章的类型，建模分析影响用户留存间隔的文章类型：

| 内容类型 | 对留存间隔的影响 | 业务含义 |
|----------|----------------|----------|
| **教育类、时事、广告创意、体育** | 留存间隔**变长**（用户来得更慢） | 偏负面——这些内容不能让用户频繁回来 |
| **壁纸头像、心灵鸡汤、文化、旅游** | 留存间隔**变短**（用户来得更快） | 偏正面——这些内容能吸引用户频繁回访 |
| **摄影、美女** | 整体能缩短留存间隔，但波动较大 | 中性偏正面——不同人群反馈不同 |

（数据来源：QB大盘DAU下跌.txt）

> **推测**：不同人群对这几类资讯反馈不同，"我之蜜糖彼之砒霜"。比如教育类内容对学生用户可能缩短留存间隔，但对职场用户可能变长；心灵鸡汤对中老年用户吸引力强，但对年轻用户可能无效。这说明资讯推荐需要更精细的人群差异化策略，不能一刀切。

### 6.4 小说用户下跌归因

**直接原因：产品在6月1号下架了盗版转码功能，导致小说用户大幅衰减。**

（数据来源：QB大盘DAU下跌.txt）

> **因果链**：6月1号下架盗版转码 → 小说低活用户（主要用盗版转码）流失 → 小说DAU高点降幅16.1%、低点降幅39.6% → 拖累大盘DAU下跌。这是一个典型的产品策略变更导致DAU下跌的案例，归因非常明确。

## 八、面试话术

### 8.1 口述版：DAU八步拆解法+六周下跌647万完整案例

> DAU跌了怎么排查？我的方法论是八步拆解法。第一步确认问题——跌幅多少、持续多久、是不是季节性，先排除数据上报问题。第二步人口属性拆解——按年龄、城市、性别、机型用决策树找下跌最明显的人群。第三步活跃度拆解——做高/中/低活/沉默的流转矩阵，看哪个流转环节变化大。第四步业务渗透拆解——各业务用户的变化，包括多业务交叉渗透用户。第五步归因建模——对高活用户用CART决策树找特征重要度，对资讯用户分析内容类型对留存间隔的影响，对小说用户看产品变更和竞品。第六步路径漏斗——首启→主启→信息流→消费各环节转化率。第七步外部因素——竞品、季节、疫情。第八步结论和行动建议。
>
> 我在QB实际做过六周下跌647万的完整拆解。时间是2020年6月15日到7月26日，六个自然周，大盘从9057万跌到8410万，降幅7.7%。分业务看小说最惨——高点降幅16.1%，低点降幅39.6%；文件跌10.3%超过大盘；资讯跌7.4%跟大盘持平。
>
> 人口属性拆解发现51岁以上用户跌了20.9%最严重，13-15岁涨9%，三线城市安卓涨9.8%。业务渗透拆解发现小说低活用户跌12.7%，小说低活+搜索高活用户跌18.1%最严重，而小说中活用户反而涨6%。
>
> 归因建模是核心。我对高活用户用CART分类树，随机抽100万618当日高活用户，特征是成为用户期间、疫情前是否高活、业务渗透数、使用时长、首启主启比例。结果发现最重要的因素是疫情前是否高活——疫情前非高活用户76%流失，低活92.9%流失，高活只有36.9%流失。但最关键的发现是高活用户如果首启主启比例<0.7（没有主启心智），72.5%会流失，留存率从63.1%骤降到27.5%。
>
> 跌幅归因上我拆了四个因素：红点停投200万、文件暑期下降150万、Push消退47万、用户活跃度下降400万，加起来797万超过总降幅因为有重合度。小说下跌是因为6月1号下架了盗版转码功能。最后7.26后企稳在8100万，腾讯新闻同趋势验证了行业性因素。
>
> 行动建议包括红点提频（预计80万delta DAU）、小说专项提升、1400万0业务渗透用户转化、1200万外部调起用户转主启、业务教育与交叉渗透、生命周期分群运营。

### 8.2 口述版：主启DAU分析框架

> 主启DAU分析是我在QB做的另一个核心项目。QB的DAU分主启（用户主动打开）和外部调起（被其他APP唤起）两种，主启代表用户心智。我把新用户拆成5个人群：未主启过17%、首启一次后再未主启38%、低活32.6%、中活9.8%、高活9.2%。关键发现是超过83%的新用户一个月内就主启了，所以未主启用户转化空间有限，最大的抓手是"首启一次后再未主启"的38%用户。
>
> 第三版分析有几个关键发现：pull渠道用户47%未主启但最容易被训练为主启；从1次主启到2次主启是关键拐点，能培养36%用户常主启；搜索场景渗透的用户二次留存高35%，而基础场景对留存甚至有负面影响；有二次留存用户的图文消费是未二次留存的1.7倍；push渠道主启转化率60%最高。

### 8.3 口述版：漏斗分析方法论

> 漏斗分析我做过两个案例。第一个是大盘到信息流路径漏斗——各起始路径的信息流渗透率：QB小说起始最高>60%，基础框架→搜索约40%且贡献400万+信息流用户，WEB其他最差。连续基础框架的用户约300万，最常去WEB网页和长视频，>42万去外部视频或成人网站。我抽40个case分类：动漫21%、电影15%、剧集13%、成人11%，建议内容引入和精准推荐。第二个是首启主启与外部调起路径分析——用row_number取每个用户前10步操作，按start_type分主启/外部调起统计路径分布，发现每日仅外部调起用户约1200万是转主启重点。

### 8.4 高频Q&A

**Q：DAU跌了怎么排查？说一下你的完整方法论。**

A：我的方法论是八步拆解法。第一步确认问题——跌幅多少、持续多久、是单点异动还是趋势性变化、是否季节性，先排除数据上报问题（对比T+1和T+2数据、查ETL日志）。第二步人口属性拆解——按年龄段、城市等级、性别、手机品牌聚类，用决策树找下跌最明显的人群。第三步活跃度拆解——做高/中/低活/沉默用户的流转矩阵，标记差异>5%的环节，看哪个流转环节变化最大。第四步业务渗透拆解——各业务（资讯/小说/搜索/文件/网页）用户的变化，包括多业务交叉渗透用户（如小说低活+搜索高活）。第五步归因建模——对高活用户用CART决策树找特征重要度，对资讯用户分析内容类型对留存间隔的影响，对小说用户看产品变更和竞品影响，运营策略变更（红点/Push/活动）也要排查。第六步路径漏斗分析——首启→主启→信息流→曝光→点击→消费各环节转化率变化，大盘到信息流的各起始路径渗透率。第七步外部因素验证——竞品是否同趋势（行业性vs个体性）、季节性、疫情、政策。第八步结论与行动建议——归因汇总（各因素可解释降幅及重合度）、企稳判断、可落地的行动清单（有owner和时间线）。

我在QB实际做过六周下跌647万的完整拆解，就是用这套方法论，从人口属性、活跃度、业务渗透到归因建模，定位了红点停投、文件暑期下降、用户主启心智缺失等核心原因，最后输出了6项行动建议。

**Q：CART决策树怎么做归因？能详细说一下吗？**

A：在DAU拆解的归因建模环节，我对高活用户使用了CART分类树。具体做法是：随机抽取100万618当日高活用户，以guid粒度建模。标签是用户在疫情后是否流失（连续7天没有再来=流失，二分类）。特征有五个：第一成为QB用户的期间，用first_date分四段——pre（1月24日以前）、in（1/24-5/1）、post_pre（5/1-6/10）、post（6/10以后）；第二疫情前是否是高活；第三业务渗透数目（612-618期间使用的业务功能数量）；第四QB使用时长，分中高低三档（mean=66.02，+1std=68.68，-1std=63.35）；第五首启为主启的比例（首启是主启的天数/周活跃天数）。

CART算法的核心是遍历所有特征和分裂点，选择使Gini不纯度下降最大的特征进行分裂，递归生成二叉树，最后输出特征重要度排序。Gini不纯度公式是1-Σp_i²，Gini值越小节点越纯。

建模结果发现，影响高活用户最重要的因素是疫情前是否高活。具体数据：疫情前不是高活的用户76%流失，低活用户92.9%流失，高活用户只有36.9%流失。但最关键的发现是——高活用户如果首启主启比例<0.7（没有主启心智），72.5%会流失，留存率从63.1%骤降到27.5%。这个发现直接指导了我们的策略：不仅要提升用户活跃度，更要建立用户的主启心智。

CART的优势是可解释性强、能输出特征重要度、能处理非线性和交互效应（比如"高活AND首启主启<0.7"的组合效应）。局限是容易过拟合、不稳定、找到的是相关性不是因果性。所以我用CART做归因定位，然后用AB实验和DID做因果验证。

**Q：六周下跌647万的案例中，你是怎么归因的？各因素解释了多少？**

A：大盘总共647万的降幅，我拆成了四个可解释因素加一个潜在因素。第一桌面红点停投解释约200万——6月全量发红点，7月1号到6号仅对新用户投放，7月7号之后仅对新用户+沉默+低活发放，结合红点AB实验的比例折算。第二主动文件暑期下降解释约150万——受暑期效应影响，文件tab+高级功能连续下降，降幅超过大盘DAU降幅，将主动文件用户的降幅进行比例折算。第三Push DAU下降解释约47万——热点消退导致push有启UV下降，计算逻辑是push有启UV的降幅乘以0.3。第四用户活跃度下降解释约400万——高活转高活比例下降，中活转低活和中活转沉默的比例上升，折算得出，这个因素跟前三点有一定重合度。第五CTR下降是潜在传导因素——推荐侧排查中，CTR下降跟DAU存在潜在传导关系，尚未量化。

四个主要因素加起来797万（200+150+47+400），超过了总降幅647万，这是因为各因素之间存在重合度——同一个用户可能同时受到红点停投、文件暑期下降、活跃度下降等多个因素的影响。用户活跃度下降（400万）是最大的单一因素，但它与其他因素高度重合，本质上是其他因素导致的结果。红点停投（200万）和文件暑期下降（150万）是相对独立的可解释因素，合计350万占总降幅的54%。

另外小说业务的下跌有明确归因——6月1号下架了盗版转码功能，导致小说用户大幅衰减，小说低点降幅高达39.6%。最后企稳验证：7.26后QB大盘DAU相对企稳在8100万，短期内利空因素已兑现。竞品验证发现腾讯新闻同趋势，说明有行业性因素。

**Q：主启DAU怎么分析？有什么关键发现？**

A：主启DAU分析我从几个维度展开。首先明确主启和外部调起的定义——主启是start_type='qb'，用户主动点击APP图标打开，代表强心智；外部调起是start_type='pull'，被其他APP或链接唤起，代表弱心智。DAU下跌的本质往往是主启DAU下跌。

然后我把新用户拆成5个人群：未主启过17%、首启一次后再未主启38%、低活32.6%、中活9.8%、高活9.2%。关键发现是超过83%的新用户一个月内就主启了，67%新增当天就主启，所以未主启用户的转化空间有限——以一月为例1700万新用户只有299万未主启。最大的抓手是"首启一次后再未主启"的38%用户，他们首启后17%直接关闭QB、12%去访问外部链接，说明首启体验和内容承接待优化。

第三版分析有几个更深入的发现：第一，未转化主启用户中pull渠道占比最大，常用pull渠道的用户47%未主启过，但pull用户最容易被训练为主启；第二，从1次主启变成2次主启是关键拐点，会培养36%的用户将主启当成主要启动方式，所以策略要引导用户做二次主启；第三，搜索场景渗透对二次留存影响最大，有搜索渗透的用户二次留存比例高35%，资讯和文件也有正面影响，但基础场景（收藏夹、设置、停留首页）对二次留存没有正面影响甚至有负面影响；第四，有二次留存用户的行为深度远高于无二次留存用户，图文消费影响最明显——有二次留存的用户图文消费是未二次留存的1.7倍，频道刷新影响最小只多15%；第五，各渠道主启转化率差异大，push渠道最高60%，noti最差40%。

这些发现直接指导了策略：拉新侧优化首启体验，转化侧引导二次主启和搜索渗透，召回侧把pull用户和每日1200万仅外部调起用户转主启，留存侧建立主启心智（首启主启比例>0.7）。

**Q：漏斗分析怎么做？能举个实际案例吗？**

A：漏斗分析的核心是逐层转化率分析+断点定位+优化优先级排序。我在QB做过两个典型的漏斗分析案例。

第一个是大盘到信息流的路径漏斗。我取2020年9月2日大盘严口径DAU用户，分析他们经历的前5个场景每一步的人数，以及每个叶子节点的信息流最终渗透率。数据口径要特别注意：QB大盘流水表每天1.3亿人，join严口径DAU后8000万，刨除延迟上报后6900万，信息流用户4100万。各起始路径的信息流渗透率排序：QB小说起始最高>60%，外部文件→基础框架和基础框架×3/×4是40-50%，基础框架→搜索约40%（贡献信息流用户400万+），基础框架→内部文件约40%，WEB其他最差。关键发现是用户从明确场景（小说、文件）一旦来到基础框架场景，信息流渗透率就大大提高。连续基础框架的用户约300万，其中最常去WEB网页（21.9万）和WEB长视频（14.7万），>42万去了外部视频网站或成人网站。我抽了40个case分类：动漫21%、电影15%、剧集13%、成人11%、其他视频10%、未知30%，对应的建议是动漫/电影/剧集做内容引入和专门推荐，成人用户回主feeds推男科医疗知识文章。

第二个是首启主启与外部调起路径分析。我取9月8日DAU，用row_number() over(partition by guid order by log_time)取每个用户前10步操作，然后用max(if(seq=N,cat_1,null))把前6步的cat1和content展开成宽表，最后按start_type='qb'/'pull'分别group by统计路径分布。发现主启和外部调起用户的行为路径差异显著，每日仅外部调起的用户约1200万，是转主启的重点人群。

漏斗分析的最佳实践：第一明确每一层口径，宽口径严口径差异巨大；第二从大到小逐层下钻；第三同时看绝对损失和相对转化率，绝对损失大不一定是优化重点要看基数；第四分群看漏斗，不同用户群差异大；第五路径漏斗和环节漏斗结合用；第六优化优先级是转化率最低且用户基数大的层级。

**Q：DAU下跌和CTR下降是什么关系？怎么判断谁是因谁是果？**

A：DAU下跌和CTR下降之间存在潜在的传导关系，但因果方向需要仔细判断，不能简单下结论。可能的因果链有三种：

第一种是CTR下降导致DAU下跌——如果推荐精准度下降（CTR下降），用户每次打开APP看到的内容都不感兴趣，慢慢就不来了，DAU下跌。这种情况下CTR下降是因，DAU下跌是果。

第二种是DAU下跌导致CTR下降——如果高活用户流失了（DAU下跌），剩下的用户是低活用户，低活用户本身CTR就低，导致整体CTR下降。这种情况下DAU下跌是因，CTR下降是果，本质是用户结构变化。

第三种是共同原因——比如红点停投既导致DAU下跌（拉回来的用户少了），又导致CTR下降（红点拉回来的用户本身质量低、CTR低，停投后这部分用户减少，但同时整体用户结构变化也可能影响CTR）。

我在六周下跌案例中，CTR下降是作为潜在传导因素列出的，推荐侧还在排查中，没有最终确认因果方向。我的判断方法是：第一看时间先后——CTR下降和DAU下跌哪个先发生？如果CTR先降然后DAU才降，可能是CTR导致DAU；如果DAU先降然后CTR才降，可能是用户结构变化。第二看用户分群——分新用户/老用户、高活/低活看CTR变化，如果所有用户群CTR都降了，可能是推荐算法问题；如果只有低活用户CTR降而高活用户CTR没变，可能是用户结构变化。第三做AB实验回滚——如果怀疑是算法变更导致CTR下降，回滚算法看CTR是否恢复，DAU是否随之企稳。第四用DID/PSM做因果推断——对比受影响和不受影响的用户群，看CTR变化对DAU的因果效应。

总之，相关性不等于因果性，DAU和CTR的关系需要结合时间序列、用户分群、AB实验、因果推断多种方法综合判断，不能简单下结论。

**Q：如果让你重新做这个DAU拆解，你会在哪些方面改进？**

A：如果重新做，我会在四个方面改进。第一是**更早地引入因果推断方法**——当时主要用CART决策树做相关性归因，虽然找到了关键因素（疫情前是否高活、首启主启比例），但相关性不等于因果性。如果重新做，我会在CART定位关键因素后，用DID（双重差分）或PSM（倾向得分匹配）做因果验证，确认这些因素确实是因不是果。比如对于"首启主启比例<0.7的用户流失率高"这个发现，可以用PSM匹配两组其他特征相似但首启主启比例不同的用户，看流失率是否真的有显著差异。

第二是**更精细的时间序列分析**——当时主要看六周的整体趋势和周度对比，如果重新做，我会做日级别的时间序列分解，把趋势项、季节项、周内周期项、异常项分离开，更精确地定位下跌是从哪一天开始加速的，以及是否有特定的事件日（如红点策略变更日、盗版转码下架日）对应下跌加速点。

第三是**更系统的竞品对比**——当时只对比了腾讯新闻的整体趋势，如果重新做，我会做多竞品的多维度对比——不仅看DAU趋势，还看各业务线（资讯/小说/搜索/视频）的趋势、各用户群（年龄/城市/活跃度）的趋势，更精确地判断哪些下跌是行业性的、哪些是QB个体性的。

第四是**更闭环的行动效果追踪**——当时输出了行动建议但没有系统追踪每个行动的实际效果。如果重新做，我会为每个行动建议建立对应的效果追踪指标和AB实验，在行动上线后持续追踪效果，形成"拆解→行动→验证→迭代"的闭环，而不是拆解完输出报告就结束了。
