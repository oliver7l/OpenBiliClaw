## 一、对比学习（Contrastive Learning）

### 1.1 核心思想（一句话讲透）
对比学习不依赖"用户点了什么"这个**稀疏监督信号**，而是用**自监督**方式，让"相似的用户/行为"在 embedding 空间**靠近**、"不相似的"**远离**，从而在标签稀疏时也能学到有区分度的用户表征。

- 传统监督学习 ≈ "老师批改作业"：用户每点一次才给一个信号，中长尾用户作业太少，学不会。
- 对比学习 ≈ "同学互相讨论"：不需要老师，通过"谁和谁行为模式像、谁和谁不像"自己学，行为少也能学出个大概。

### 1.2 你简历里的三个对比辅助任务（按粒度展开）

#### 任务1：user-user 场景粒度对比（学"相似用户"）
| 项 | 内容 |
|---|---|
| 正样本对 | 行为模式相似的用户（同场景、同品类偏好、行为序列相似）互为正例 |
| 负样本对 | 随机采样的不同兴趣用户 |
| 学什么 | 让相似用户的 embedding 靠近 |
| 为什么有用 | 中长尾用户自身行为少，但只要找到"和他像的活跃用户"，就能借群体表征把自己"拉"到正确位置——**用群体信息补个体稀疏** |

#### 任务2：正负反馈对比（学"喜欢 vs 假喜欢"）
| 项 | 内容 |
|---|---|
| 正样本 | 用户深度行为（下载、长时、付费）对应的 item |
| 负样本 | 曝光未点击、或点击即走的 item |
| 学什么 | 让"真喜欢"与"假喜欢/不喜欢"在空间里拉开 |
| 为什么有用 | 稀疏用户哪怕只有几个行为，对比学习也能把信号放大和纯化，比单纯监督训练利用更充分 |

#### 任务3：热门 item 曝光偏差 / 反馈粒度差异
| 辅助任务 | 主要问题 | 核心思想 |
|---|---|---|
| 第一个 | 热门 item 曝光偏差 | 不要让热门度主导学习 |
| 第二个 | 用户兴趣被大众兴趣带偏 | 学习稳定、个性化的用户兴趣 |
| 第三个 | 正负反馈不平衡、粒度粗 | 学习不同反馈之间的细粒度差异 |

三者与主任务关系：
```
推荐主任务 (CTR/CVR 预估)
   ├─ 辅助任务1: Item 去偏      (热门 ≠ 更好)
   ├─ 辅助任务2: 用户差异        (大众 vs 个人)
   └─ 辅助任务3: 反馈差异        (点击 ≠ 喜欢)
        ↓
   更好的 Representation
```

### 1.3 与主架构结合（工程落地，防追问）
没有另起炉灶，而是在现有推荐主架构上加**自监督辅助任务**：
- 主任务：多场景多目标的 `CTR/CVR` 预估；
- 对比任务作为**辅助 loss** 联合训练：`Loss = Loss_main + α × Loss_contrastive`；
- 用户 tower 的 embedding 同时被两个任务优化，**serving 时只用学好的 embedding，不增加线上开销**；
- 负样本用 **batch 内负样本（in-batch negatives）+ 难负例**，控制训练成本。

### 1.4 为什么有效（面试官最想听的因果链）
1. 对比学习让中长尾用户 embedding 更有区分度（相似靠近、不同远离）；
2. 表征准了 → 召回能召回对的内容、排序能排准 → 中长尾看到的东西更相关；
3. 相关性↑ → 点击/下载/付费↑ → ARPU↑；
4. 因不依赖稀疏标签，提升**集中发生在中长尾用户**（头部行为多、监督信号够，边际收益小）——这解释了为什么大盘只涨一部分、而中长尾涨 2.3%。

> 一句话总结：对比学习解决"信号稀疏"——用自监督把少量行为和群体相似性利用起来，让模型在标签不够时也认识用户，表征准了，分发就准，变现自然涨。

### 1.5 面试 Q&A（防守追问）

**Q：正样本怎么构造？相似用户怎么定义？**
用行为序列相似度 + 同场景同品类偏好做规则筛选；也可用预训练模型算 user embedding 相似度取 topK。构造后要做清洗，避免把"都点了热门"的用户误判为相似。

**Q：和直接做 user-embedding 聚类 / 协同过滤有什么区别？**
协同过滤是离散的、基于统计的；对比学习是端到端学连续表征，能融合更多特征（场景、序列、图像），且和主模型联合优化，直接服务于排序目标。

**Q：α（辅助 loss 权重）怎么调？**
网格搜索 + 观察中长尾用户的离线 AUC/GAUC 和线上指标；α 太大会伤害头部用户主任务效果，所以要平衡，最终选"头部不降、中长尾明显涨"的点。

**Q：怎么验证是中长尾涨的？**
分用户活跃度分桶看实验效果：头部桶基本持平，中长尾桶 ARPU +2.3%，符合"对比学习补稀疏"预期，因果链对得上。

### 1.6 口述版（40 秒，可直接背）
"对比学习我是在 OPPO 推荐主架构上挂自监督辅助任务：user-user 场景粒度让相似用户 embedding 靠近，正负反馈对比把'真喜欢'和'假喜欢'拉开，再加一个热门 item 去偏任务。联合训练 `Loss = Loss_main + α·Loss_contrastive`，serving 只出 embedding、不增开销，负样本用 batch 内 + 难负例控成本。它解决的是标签稀疏——中长尾用户行为少，但能借相似活跃用户的群体表征把自己拉正，所以提升集中在中长尾，ARPU +2.3%，头部基本持平。"

## 二、数值稳定（Numerical Stability）

### 2.1 两种灾难
| 灾难 | 现象 | 举例 |
|---|---|---|
| 上溢 Overflow | logits 很大，exp 爆炸 | `z=[1000,1001,999]`，e^1000 是天文数字，直接变 inf；sum=inf，log(inf)=inf → loss=nan |
| 下溢 Underflow | logits 很小，exp 压成 0 | `z=[-1000,-999,-1001]`，e^-1000≈0，sum_exp=0，log(0)=-inf → loss=-inf/nan |

- 朴素写法问题：exp 输入值域无保护，z 稍微偏大偏小，exp 直接爆浮点数。
- float64 上限约 `1.8e308`；**logits 只要超过 700，exp 直接爆炸**（原文此处 OCR 失真，按浮点常识还原）。

### 2.2 log-sum-exp 数学变形（解决上溢）
数学恒等变换（原文公式 OCR 严重失真，按标准形式还原）：
```
log(Σ exp(z_i)) = log(Σ exp(z_i − m)) + m,   其中 m = max(z)
```
令 m 取当前行 logits 最大值，则对每一项 `z_i − m ≤ 0`，`exp(z_i − m) ∈ (0, 1]`。

效果：
1. 无论 z 多大，`z−m ≤ 0`，exp 输入永远 <0，输出范围 (0,1]，**永远不会上溢**，exp 最大只能是 1；
2. 即使 z 整体很小，`z−m` 只是相对差值，相对关系保留，不会全部压成 0。

### 2.3 高频坑：丢掉 `+m` 会怎样（超级考点）
若写成 `log Σ exp(z_i − m)`，**少加 m**：
- 这不是数学等价，算出的 log-sum-exp 整体偏小，loss 全部算错；
- **但是梯度完全不受影响**——因为 m 对 z 求导会抵消，梯度依旧是 `softmax − onehot(y)`。

面试高频问："如果 log-sum-exp 忘记加 m，反向传播还能跑吗？"
答：**反向传播可以跑，梯度正确，但 loss 数值错误**。现象：网络可以收敛，但打印出来的 loss 完全不对，loss 曲线不能用来判断训练状态。

### 2.4 keepdims=True 的作用（魔鬼 bug）
```python
m = np.max(logits, axis=1, keepdims=True)   # [N,1]
# keepdims=False → [N,]
```
- `keepdims=True`：shape `[N,1]`，广播时每一行 logits 分别减去**本行**最大值；
- `keepdims=False`：shape `[N,]`，numpy 会把 `[N,]` 当成 `[1,N]` 做**全局**广播，按列减最大值而非按行；

**魔鬼 bug**：当 `N=K`（方阵）时维度刚好对上，不报异常，但计算结果完全错误，单元测试极易漏掉。

### 2.5 Softmax-CE vs BCE（多标签）对比
| 对比项 | Softmax-CE（多分类） | BCE（多标签） |
|---|---|---|
| 激活函数 | softmax | sigmoid |
| 概率约束 | 各类别概率之和=1，互斥 | 每个类别独立，总和≠1 |
| 标签形式 | one-hot，只能有 1 个 1 | 每维 0/1，可多个同时为 1 |
| 适用场景 | 多分类单标签（猫/狗/鸟三选一） | 二分类、多标签（一张图同时有猫+狗） |
| PyTorch 接口 | `F.cross_entropy(logits, target)` | `F.bce_with_logits(logits, target)` |
| 输入要求 | 直接输入 logits，内部做 log-sum-exp 稳定 | 直接输入 logits，内部做 sigmoid 稳定 |
| 梯度形式 | `P_softmax − Y_onehot` | `P_sigmoid − Y` |

### 2.6 三个基础概念区分
1. **logit**：模型输出原始分数，无 0-1 约束，可正可负（如 `[3,-1]`、`[5]`），不是概率；
2. **softmax**：把一组 logits 转成一组概率，总和=1；
3. **sigmoid**：单独一个 logit 转成一个 0~1 概率。
   - BCE 只接收 1 个 logit；Softmax(K=2) 接收 2 个 logit。

### 2.7 训练稳定性要点清单
- 所有含 exp/softmax/log 的路径必须走数值稳定实现（log-sum-exp + m）；
- loss 数值失真 ≠ 梯度错误，排查时分开看；
- 矩阵运算注意 keepdims 维度语义，方阵场景的广播 bug 最隐蔽；
- 多标签用 BCE，单标签互斥用 Softmax-CE，不要混用。

## 三、大模型做推荐（二面最重点）

### 3.1 核心挑战表（面试必问）
| 挑战 | 具体问题 | 解决方案 |
|---|---|---|
| 推理延迟 | LLM 推理太慢，推荐要求 **P99 < 50ms** | 模型蒸馏、量化压缩、Token 化推荐（CoVE 实现 **100 倍加速**） |
| 物品规模 | 应用商店百万级应用，LLM 词表装不下 | 哈希压缩 Embedding、分层检索 |
| 实时性 | 用户行为变化快，LLM 更新慢 | 增量学习、LoRA 适配器微调 |
| 幻觉问题 | LLM 可能推荐不存在的应用 | 约束解码、检索增强（RAG） |
| 成本 | LLM 推理成本高 | 用**小模型**做候选生成，LLM 只做精排 |
| 冷启动 | 新应用没有交互数据 | LLM 的内容理解能力天然适合冷启动 |

### 3.2 大模型做推荐的方法（按成熟度从高到低四层）
1. **大模型做特征增强**（工业界落地最多）：用 BERT 等对商品描述、用户评论做语义编码，提取传统特征工程抓不到的隐含关联；核心价值在**冷启动**——新应用无交互数据，但 LLM 可根据描述、图标生成初始表征。
2. **端到端生成式推荐**（2025 以来最火）：用一个统一 Transformer，像 GPT 生成文本一样"生成"下一个推荐。代表：快手 **OneRec**（主站落地，用户观看时长 **+1.6%**）、Meta **HSTU**、Google **PLUM**、网易云音乐 **?（原文 Ciimber，OCR 失真）**。
3. **对话式推荐**：用户与系统"对话"直接表达需求，LLM 作为推荐智能体理解自然语言、动态调整推荐。
4. **用户仿真**：Meta **RecoWorld** 用 LLM 模拟真实用户行为，在虚拟环境训练推荐策略，避免拿真实用户做实验。

### 3.4 六大落地能力（按场景）
#### 能力一：跨语言语义对齐（最大价值点，海外场景）
- 问题：东南亚六国六种语言，用户搜索词与应用描述语言不同，传统关键词匹配失效。
- 方案（参考 Coupang 2025 **CSRM-LLM** 框架）：
  1. 多语言预训练模型（mBERT / XLM-R）把印尼语、泰语、越南语、英语等应用描述与搜索词映射到同一语义空间（印尼语搜"edit video"能匹配英语描述的 CapCut）；
  2. 机器翻译辅助任务，激活跨语言迁移能力，让模型理解"视频编辑"在多语言中同义；
  3. **对比学习**：把同一应用的不同语言描述作为"正样本对"，通过对比损失学跨语言相似性。
- 效果：在线 A/B 测试**缺陷率降低 45.8%，会话购买率提升 0.866%**。

#### 能力二：新兴市场冷启动（数据极度稀疏）
- LLM 生成伪行为数据：基于用户画像（设备型号、地区、语言）生成模拟行为序列作训练补充（扣子 Coze 的 SearchCLI 已验证——把店铺信息和目标人群告诉 LLM 即可生成可用模拟数据）；
- LLM 生成软标签（自蒸馏）：对应用做"质量评分""用户匹配度评分"作训练软标签；
- 检索增强生成（RAG）：缺乏行为数据时，用 LLM 生成伪行为数据蒸馏 Embedding 检索模型，增强领域知识注入。

#### 能力三：文化偏好理解
- LLM 具备世界知识，能理解"印尼是穆斯林国家，伊斯兰金融类应用需求大""泰国用户偏好社交娱乐""越南用户对游戏偏好强"；
- 编码为推荐信号，如理解"**斋月（Ramadan）**期间印尼用户对祈祷类、慈善类应用需求激增"，在特定时段调整策略。

#### 能力四：冷启动应用推荐（应用商店）
- 基于内容理解的初始表征：新应用上架时 LLM 根据描述、图标、类别生成高质量"初始 Embedding"，上线第一天就能合理推荐；
- 相似应用匹配：LLM 理解"新应用和已有 XX 应用功能类似"，推荐给喜欢 XX 的用户；
- **LLM-InS 框架（WSDM 2024）**：用大模型模拟用户对冷启动应用的交互行为，生成"伪交互数据"训练推荐模型，实验证明优于所有传统方法。

#### 能力五：游戏体验个性化匹配（游戏中心）
- 游戏评论语义分析：提取"上手难但深度高""适合碎片时间""社交性强"等隐含特征；
- 游戏视频/截图理解：多模态分析实机画面视觉风格（像素风/3A/卡通风）匹配审美偏好；
- 跨游戏关联推理：理解"喜欢《原神》开放世界的玩家可能也喜欢《塞尔达》"，即使传统标签体系完全不同。

#### 能力六：游戏冷启动与长尾分发（游戏中心）
- 用 LLM 理解独立游戏设计文档、开发者描述、截图，生成初始推荐表征；
- 用 LLM 模拟不同玩家类型反应，为游戏匹配合适目标用户群；
- 让小众游戏也能被精准推荐，而非永远被头部大作压死。

### 3.5 游戏中心深度案例：MeepleLM（? 原文"盛大东京研究院"，机构名 OCR 失真）
基于 **MDA（Mechanics-Dynamics-Aesthetics）** 游戏设计理论，从三层理解游戏：
| 层 | 含义 | 举例 |
|---|---|---|
| Mechanics（机制） | 游戏有什么规则 | "狼人杀有身份隐藏和投票机制" |
| Dynamics（动态） | 规则运行时产生什么交互 | "身份隐藏导致玩家互相猜疑，产生社交博弈" |
| Aesthetics（美学） | 交互带来什么情感体验 | "猜疑和欺骗带来紧张刺激的社交快感" |

五种典型玩家画像：系统纯粹主义者（追求平衡逻辑、讨厌随机）、效率至上者（追求流畅节奏、厌恶繁琐）、叙事建筑师（沉浸故事代入感）、社交润滑剂（为社交互动）、刺激追求者（高风险高回报快感）。价值：LLM 理解"游戏适合什么类型玩家"再匹配对应画像用户，比"按品类推荐"精准得多。

### 3.7 面试官必问题：大模型在应用商店/游戏中心/海外应用商店能做什么？
> 我认为大模型在推荐系统中的定位是"**上游内容理解引擎**"，而不是直接做在线排序。核心价值三层：
> 第一，**内容深度理解**——传统系统只能靠类别标签和下载量理解应用，大模型能理解应用描述语义、用户评论隐含偏好、甚至截图视觉风格；游戏中心还能基于 MDA 框架理解玩法机制与情感体验，实现"什么类型玩家推荐什么类型游戏"。
> 第二，**冷启动缓解**——应用商店最痛的点。新应用上架第一天，大模型通过理解描述和图标生成高质量初始表征。Coupang 2025 用多语言 LLM 做冷启动，搜索缺陷率降低 45.8%。
> 第三，**跨语言语义对齐**——海外尤其关键。东南亚六国六语，大模型把不同语言应用描述和搜索词映射到同一语义空间，实现跨语言精准匹配。
> 但大模型**不擅长在线实时排序**——推理延迟太高，无法满足 P99 < 50ms。所以工业界最佳实践：用大模型做离线特征生成和内容理解，把生成的 Embedding 注入传统轻量级排序模型，兼顾质量与速度。

### 3.8 RAG 知识库设计（part07）
知识库三类文档：
- **平台文档**：各广告平台投放规则、最佳实践（如"Meta 不允许同时设每日/总预算"）；
- **历史案例**：过往诊断报告和优化方案（结构化存储：问题描述 → 根因 → 操作 → 效果）；
- **行业基准**：各品类平均 CTR、CVR、CPA 等参考值。

检索策略：**混合检索（向量语义 + BM25 关键词）→ Rerank 精排 → 取 Top-3**，确保召回准确。

工具调用设计：
| 工具名 | 功能 | 参数 | 异常处理 |
|---|---|---|---|
| fetch_ad_data | 拉取投放数据 | platform, date_range, campaign_id | 超时重试 3 次，失败返回缓存数据 |

### 3.9 大模型做推荐 · 面试 Q&A
**Q：大模型推理太慢怎么满足推荐实时性？**
A：定位是离线内容理解引擎，不进实时排序链路；在线侧用蒸馏/量化后的小模型或缓存好的 Embedding；极端延迟要求用 CoVE 等 Token 化推荐做 100 倍加速。

**Q：百万级物品 LLM 词表装不下怎么办？**
A：哈希压缩 Embedding + 分层检索，把物品表征从 LLM 词表解耦。

**Q：LLM 幻觉推荐不存在的应用怎么防？**
A：约束解码 + 检索增强（RAG），生成结果必须命中知识库/物品库。

**Q：成本高怎么控？**
A：小模型做候选生成，LLM 只做精排；或用 LLM 离线生成 Embedding/软标签，在线零 LLM 调用。

## 五、CVR 优化与延迟反馈（part09）

### 5.1 样本优化技术全景（三大维度）
| 维度 | 核心矛盾 | 技术路线 | 最新进展 |
|---|---|---|---|
| 归因维度（MAL） | 同一转化 > 不同归因口径 > 样本稀疏 | 多场景统一建模（STAR/PEPNet/MI-DPG）、跨域知识迁移（UniSRec/UniCDR）、全空间+间接信号（ESMM/泛 Label） | MI-DPG(2026)、M-Scan 因果驱动 |
| 时间维度（延迟反馈） | 同一转化 > 时间维度 > 标签不完整 | 参数化生存模型（DFM/NoDeF）、标签修正+重要性采样（ES-DFM/DEFUSE/IF-DFM）、多窗口/多流建模（MISS/TESLA） | IF-DFM(2025)、TESLA(WWW'26) |
| 空间维度（场外/跨场域） | 同一转化 > 空间维度 > 跨场域归因 | 多场景统一建模、跨域知识迁移、全空间+间接信号 | — |

三者连接点：
- MAL 解决：同一转化 → 不同归因口径 → 样本稀疏；
- 延迟反馈解决：同一转化 → 时间维度 → 标签不完整；
- 场外反馈解决：同一转化 → 空间维度 → 跨场域归因。
- **终极形态：跨场域 × 多归因 × 延迟感知 = 全域全链路 CVR 预估**。

### 5.2 归因口径的场域博弈
| 口径 | 定义 | 问题 |
|---|---|---|
| 路过归因 | 用户路径所有触点都计 | 重复计算，场域之和 > 真实 ARPU |
| 唯一归因 | 只算一次，按规则分配 | 场域 GMV 绝对值下降，团队 KPI 难看 |
| 末触归因 | 最后一个触点 | 忽视种草价值，重定向严重 |
| 数据驱动归因 DDA | 基于 Shapley 值/马尔可夫链 | 模型复杂，可解释性差 |

根本矛盾：技术最优解（唯一归因）与组织激励（各团队要涨 KPI）的冲突。

### 5.3 延迟反馈工业落地决策树
```
延迟反馈建模
├─ 延迟 < 1天（分钟/小时级）?
│    └─ 在线学习场景 → DEFER / ES-DFM / IF-DFM
├─ 延迟 1~7天（RM）?
│    ├─ 时效性优先 → 向前归因 + 重加权
│    └─ 准确性优先 → 向后归因 N 天
├─ 延迟 > 7天（BR, WAR）?
│    └─ 多任务建模（DEFER）+ 生存分析
└─ 存在退货（MEER）?
     └─ ECAD / TESLA 结构
```

### 5.4 全域 CVR 的陷阱
观察："同一商品无论从哪个场景点进去都进同一商详页，似乎可训无偏全域 CVR"——但实际上：
- 不同场景进入同一商品，**券后价可能不同**（如淘金币抵扣）；
- 价格是用户决策核心因子；
- 所以"全域 CVR"并非真正无偏，场景差异隐藏在价格差异中。
落地建议：全域 CVR 模型需把场景相关特征（价格、优惠）**显式注入**；或如原文用概率建模而非直接训练全域 CVR。

### 5.5 冷启动解法（与对比学习、推荐系统同源）
#### 新广告/新计划冷启动（最常考）
- 问题：新计划无点击/转化历史，pCTR/pCVR 靠猜，eCPM 低竞不到量；即使竞到成本也不可控。
- 先验迁移（核心）：
  - 用相似广告历史数据做先验——按行业/素材类型/定向人群/落地页类目聚类，新计划继承同类老计划 PCTR/pCVR 先验；
  - 素材特征建模：用素材图像/文本 Embedding（CV/NLP 模型）直接预估 CTR，不依赖历史行为（"内容理解"解冷启动）；
  - 广告主历史：同账户老计划表现作账户级先验；
  - `pCTR = (点击 + α·先验CTR) / (曝光 + β)`（α、β 为平滑强度），数据少靠先验、数据多靠自身，**置信度过渡平滑**（与阿里妈妈 Bayes-SIR 校准冷启动同源）；
- 探索扶持（流量侧）：新计划保量/boost，竞价加探索权重或留专属探索流量池；广告主侧设"冷启动期"允许成本短期偏高换数据积累。

#### 新广告主冷启动
- 行业/类目先验：按行业继承同类账户出价区间、定向建议、CVR 先验；
- 冷启动期推荐用 **OCPX 自动出价**（系统按行业先验控成本，降广告主操作门槛）；
- 销售/运营侧提供行业 benchmark（同类账户 CPA/ROI 参考）帮设合理预期。

#### 新用户冷启动
- 上下文特征兜底：无行为画像时用设备/地域/时段/渠道先出粗分；
- 跨域迁移：同设备在其他场景（自然流量/搜索）行为迁移；
- 探索兴趣：新用户前几次曝光做多类目试探，快速收敛画像；
- 与 OPPO 经验挂钩：对比学习补中长尾稀疏用户表征，本质就是用户冷启动解法——用"谁和谁像"的自监督信号**替代**稀疏行为标签。

#### 新流量位/新场景冷启动
- 位置先验：新广告位继承相似位置（同形态/同屏位）CTR 先验和底价；
- 分位置校准冷启动：新位置 PCOC 不准时用贝叶斯平滑 + 相似位置先验（对应分维度校准）；
- 小流量试投：先小流量积累数据，校准稳定后放量。

### 5.6 冷启动共同方法论（面试升华）
"冷启动解法本质是三件事：
1. **借先验**——从相似对象（同类广告/同行业账户/相似位置/相似用户）迁移知识，解决'没数据'；
2. **做探索**——留探索流量/预算，主动积累数据，解决'拿不到数据'；
3. **快过渡**——贝叶斯平滑做置信度过渡，数据够了切回自身估计，解决'先验依赖'。
这三件事和推荐系统冷启动、LTV 稀疏、校准冷启动是同一套思想。"

### 5.7 冷启动评估方式（体现资深）
| 指标 | 看什么 |
|---|---|
| 冷启动通过率 | 新计划成功过冷启动的比例 |
| 过冷启动时长 | 从创建到达标的时间，越短越好 |
| 冷启动期成本达标率 | 探索期成本是否可控 |
| 冷启动后留存 | 过冷启动后是否持续投放（防"扶持一停就死"） |
| 新计划长期 ROI | 防扶持期刷量、长期价值差 |

关键：不能只看冷启动期拿量，要看过冷启动后的存活和长期价值，否则扶持是浪费。

### 6.5 长期价值分 & 结构校准追问
**Q：长期价值分具体怎么算的？**
简化版 `LTV = D7留存 × 付费率 × ARPPU × 生命周期系数`；更完整版对留存曲线逐日折现求和。口径是和运营对齐后定的，关键是大家认这个分。

**Q：结构校准具体怎么实现的？**
精排分基础上加长期价值项：`score' = score + λ×LTV分`，λ 按结构目标在线调；同时对高点击低价值游戏设流量上限。这个 λ 的调节思路和广告里"约束下控制出价"是同一类问题。

### 6.6 为什么去银行补短板（深挖版）
"触发点其实是在 OPPO 做推荐的时候。我做应用商店和游戏分发，核心优化的是分发效率——CTR、留存、ARPU，这些我都能做好。但我慢慢发现：当推荐要直接对收入负责时，光懂效率不够，还要懂'在约束下怎么分配资源'。比如游戏分发里，要平衡短期点击和长期 LTV、平衡头部和长尾生态、在有限流量里做结构校准——这些本质是约束下的资源分配问题，不是单纯模型优化问题。
我当时意识到，我缺的不是技术能力，而是在多重硬约束下做经营决策的思维方式——预算约束、成本约束、风险约束同时存在时，怎么定策略、怎么取舍、怎么推动落地。
这种东西在纯互联网推荐里练不到，因为互联网约束大多是'软约束'——你可以跑个 A/B 试试，不行就回滚。但金融场景约束是'硬约束'——每一笔定价要过财务审批，每一个额度调整要过风险审批，合规红线碰都不能碰。所以我想去一个约束更硬、决策更重的场景，把这块思维补上。"

**精简版（15 秒）**："在 OPPO 做推荐时我发现，当推荐要直接对收入负责，光懂模型优化不够，还要懂'在约束下怎么分配资源'。互联网约束是软的，可以 A/B 试错；但金融约束是硬的——定价要过财务、额度要过风险、合规是红线。我想去约束更硬的场景，把'约束下做决策'补上。"

**继续追："你在 OPPO 不是也做了长期价值、结构校准吗？"**
"对，OPPO 确实有一些，但程度不一样。OPPO 的约束更多是'体验 vs 效率'的平衡，本质还是产品内部取舍，我可以跑实验、快速迭代。但银行的约束是外部强加的、不可谈判的——财务说成本不能超就是不能超，风险说敞口不能大就是不能大，合规说这个客群不能碰就是不能碰。你得在这些'不可谈判'的约束下，还能找到最优策略并推动落地。这种'戴着镣铐跳舞'的决策能力，是我在 OPPO 练不到的。"

### 6.7 银行补完的四块能力（反问/深挖备用）
1. **约束下的策略设计能力**——银行定价过财务、额度过风险，学会在多方约束下找各方接受的最优解，对应广告预算 pacing、成本控制、ROI 达标；
2. **跨部门推动落地能力**——一个策略要同时推动财务、风险、渠道、运营四方，用数据把四方账算清，对应数据分析推动业务方采纳结论；
3. **精细化客群经营能力**——三层客群分层（分期目标/余额抢夺/竞品借贷），"梯次经营"把有限资源按客群价值精细分配，对应广告预算在人群间分配；
4. **事前预测代替事后推断**——前置预测客户未来 30 天在他行借贷概率，对应广告转化预估和冷启动预判。

### 6.8 稳定性反问技巧（针对"跳得多的主管顾虑"）
- 反问埋稳定："我这次回百度是想长期深耕广告数据分析的，您觉得在这个团队长期做下去，最有价值的成长点是什么？"——把"想长期干"藏在问题里，比直接说"我很稳定"自然。
- 业务方向反问（主管最爱听）："如果我有幸加入，您希望我前 3-6 个月重点做出什么成果？""您觉得这岗位做得好的人和普通人的差别在哪？""以我的背景，您觉得我最需先补齐哪块？"
- 技术体系反问（加分）："团队在归因和实验评估上主要用什么方法？有没有增量归因或因果推断实践？""数据分析这边有没有用大模型或自动化做分析提效？"

## 八、二面防追问速记（模型细节深挖预案）

1. **对比损失梯度推导**：`∂L/∂z_i = p_i − y_i`（softmax-CE），对比学习本质是 InfoNCE，温度 τ 在分母 `exp(z·z+/τ)` 中调节分布锐度。
2. **温度系数 τ**：τ 小 → 分布更尖锐，强迫难样本拉开；τ 大 → 更平滑，训练更易但区分度下降。需调参平衡难负例利用与训练稳定。
3. **防坍塌（collapse）**：若没有负样本或负样本太弱，对比学习会把所有 embedding 映射到同一点（表征坍塌）。对策：足够多负样本（batch 内 + 难负例）、温度调节、对比损失本身的正交约束。
4. **假阴性（false negative）**：batch 内随机负例可能实际是同类（如两用户都爱同一游戏却被当负例），会污染梯度。对策：难负例挖掘时排除潜在正例、用聚类/规则预筛、或采用去偏负采样。
5. **log-sum-exp 丢 m**：梯度对、loss 错——打印 loss 不能判断训练状态，要用验证集指标。
6. **keepdims 方阵 bug**：`[N,]` 被当 `[1,N]` 全局广播，N=K 时不报错但结果错。
7. **大模型不进实时排序**：P99<50ms 硬约束下，LLM 只做离线特征/内容理解，Embedding 注入轻量排序模型。
8. **延迟反馈三大维度**：归因（MAL）/ 时间（延迟窗口）/ 空间（跨场域），终态是全域全链路 CVR。
