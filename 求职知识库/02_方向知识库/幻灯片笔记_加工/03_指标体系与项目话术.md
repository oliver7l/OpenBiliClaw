## 二、指标体系

### 2.1 五层指标体系（OPPO 应用商店 & 游戏中心，最完整的一版）

> 原文表述：「我先搭了五层指标体系，确保'看什么'是清楚的」。这是**营销方向也能直接复用的骨架**。

| 层级 | 指标 | 口径要点 | 用途 |
|---|---|---|---|
| 结果层 | 收入、ARPU、下载量、激活量 | ARPU 分母必须先定 DAU 还是 MAU；收入按结算口径还是流水口径 | 业务最终目标，北极星 |
| 过程层（漏斗层） | 曝光 → 点击 → 下载 → 激活 → 付费，逐层转化率 | 「点击」是否剔除秒退；下载是否含失败重试 | 定位卡点环节 |
| 结构层 | 各品类/档位的流量份额、收益份额、**错配度** | 份额分母统一为同一时间窗的总曝光/总收益 | 看资源分配是否合理 |
| 质量层 | PCOC（预估/实际）、分切片相对偏差、分人群 AUC | PCOC 按 场景 × 位置 × 人群 分切片算，不看大盘均值 | 看预估是否可信 |
| 健康层 | 次留 / 7 留、负反馈率、品类多样性 | 「付费」是否扣退款；留存按设备还是账号 | 看生态是否可持续 |

**搭体系最关键的一句话（原文）**：
> 搭体系最关键的是统一口径 —— 比如'点击'算不算秒退、'付费'算不算退款、ARPU 的分母是 DAU 还是 MAU，这些我和产品、运营逐一对齐，**写进数据字典**，避免后面'同一个指标两个数'。

### 2.2 广告/商业化产品指标体系（四层版，用于"给新产品搭指标体系"这类开放题）

| 层级 | 指标 | 口径要点 | 用途 |
|---|---|---|---|
| 收入层 | 收入、eCPM、RPM | eCPM ≈ bid × pCTR × pCVR × 1000；RPM 按千次请求还是千次曝光要说清 | 北极星（收入 / 长期 LTV） |
| 效率层 | 填充率、CTR、CVR | 填充率 = 返回广告数 / 请求数；CVR 归因窗口要定死 | 找链路瓶颈 |
| 体验层 | 负反馈率、相关性、频控 | 负反馈含主动关闭/举报；频控看人均曝光上限触达比 | 防止短期透支生态 |
| 健康层 | 广告主留存、流失、集中度 | 集中度用 Top N 消耗占比 / HHI | 看供给端是否可持续 |

**四步法（答题模板）**：
1. 先明确业务目标和北极星指标（广告产品一般是收入或长期 LTV）；
2. 分层拆：收入层 / 效率层 / 体验层 / 健康层；
3. 统一口径 → 建监控看板 → 设报警阈值；
4. **把指标落到可执行动作**：每个指标有 owner、有对应策略抓手，避免"只看不用"。

### 2.3 核心公式速查表

| 场景 | 公式 | 用途 |
|---|---|---|
| 广告收入拆解 | 收入 = 请求量 × 填充率 × eCPM | 收入异动第一刀 |
| eCPM | eCPM ≈ bid × pCTR × pCVR × 1000 | 定位是出价问题还是预估问题 |
| ARPU 乘法拆解 | ARPU = 人均曝光 × CTR × 下载率 × 变现率 × ARPPU | OPPO 项目主拆解式 |
| OCPX 出价 | bid = tCPA × pCTR × pCVR / (1 + λ) | 价值预估 + 成本控制统一表达 |
| oCPC 出价 | 点击出价 = tCPA × pCVR / (1 + λ)，排序时再乘 pCTR | 与 oCPM 的区别（简历写的是曝光口径） |
| 因子贡献度 | 贡献度_i = Δln(X_i) / Δln(ARPU) | LMDI 对数分解 |
| 校准指标 | PCOC = 预估 / 实际，健康区间 [0.9, 1.1] | 度量衡是否可信 |

### 2.4 OCPX 出价公式口述版（30 秒，可直接背）

> 这个公式本质是「**按价值出价、按约束控制**」。
> `tCPA × pCTR × pCVR` 是这次曝光的期望价值：pCTR × pCVR 是曝光到转化的概率，乘上广告主愿意为一个转化付的 tCPA，就是这次曝光值多少钱，也就是**出价的理论上限**。
> 除以 (1 + λ) 是成本控制：λ 是预算和成本约束的拉格朗日乘子，线上用实际成本和目标的偏差做 PID 反馈调节 —— 成本超标就调大 λ 压出价，放量不足就调小 λ。
> 所以这个公式把「价值预估」和「成本控制」统一在一个表达式里。这也解释了为什么 pCTR/pCVR 必须校准：出价直接乘预估值，预估偏高就会高价买低质流量，成本直接失控。

**逐项拆解**

| 项 | 含义 | 直觉 |
|---|---|---|
| tCPA | 广告主愿意为一个转化付的钱（目标成本） | "一个激活值 20 块" |
| pCTR | 这次曝光被点击的概率 | 曝光 → 点击 |
| pCVR | 点击后转化的概率 | 点击 → 转化 |
| pCTR × pCVR | 这次曝光最终带来转化的概率 | 整条链路的转化概率 |
| tCPA × pCTR × pCVR | 这次曝光的期望价值 | "值多少钱，最多出多少" |
| 1 / (1 + λ) | 成本控制折扣系数 | λ 越大，出价越保守 |

**λ 的直觉：一个"节流阀"**

| λ 取值 | 约束状态 | 出价行为 |
|---|---|---|
| λ = 0 | 约束不紧（钱花不出去、成本远低于目标） | 按全价值出价，放量 |
| λ 变大 | 约束变紧（成本超标 / 预算快花完） | 所有出价等比压低，只赢便宜且优质的流量 |
| λ 很大 | 严重超标 | 出价趋近 0，几乎不参竞 |

**为什么是"除"而不是"减"**：等比缩放不改变流量优劣的排序 —— 所有曝光的出价乘同一个系数，系统仍然优先买高价值流量，只是整体买得更少/更便宜。这保证了"压成本"的同时不牺牲流量质量。

**λ 怎么调（闭环）**：按 campaign 分钟级 PID 反馈调节。
- 实际 CPA > tCPA → 调大 λ → 出价降 → 成本回落；
- 实际 CPA < tCPA 且预算花不出去 → 调小 λ → 出价升 → 放量。
- 整个 OCPX 是闭环：预估 → 出价 → 竞价成交?→ 成本回流 → 调 λ → 再出价。

### 3.2 异动归因：「昨天收入跌了 20%，你怎么排查」（最高频，务必准备?）

**核心态度**：我不会先猜原因，**先按公式拆**。

| 步骤 | 动作 | 细节 |
|---|---|---|
| 1. 拆公式 | 收入 = 请求量 × 填充率 × eCPM | 先看这三层哪个掉了 |
| 2. 定位层级? | 是流量少了？填充降了？还是 eCPM 跌了？ | 只锁一层，不散射 |
| 3a. 请求量掉 | 往流量侧查 | 某个广告位 / 某个版本 / 某个渠道流量少了 |
| 3b. 填充率掉 | 查竞价侧 | 参竞广告主少了、预算撞线、底价调高、某个 DSP 挂了 |
| 3c. eCPM 掉 | 再往下拆 | 出价降了？pCTR/pCVR 降了？排序/机制改动？ |
| 4. 维度下钻 | 行业 / 广告主 / 广告位 / 地域 / 设备 / 时段 | 找**贡献最大的子集** |
| 5. 分内外因 | 外因：大盘、节假日、政策、大客户停投；内因?：上线改动、数据链路、计费口径变化 | 两条线并行排 |
| 6. 收口 | 给结论 + 建议 + **跟进验证** | 不止定位，还要闭环 |

### 3.3 公式归因实操（LMDI 法 / 乘法拆解）

ARPU 是乘法型指标，用 **LMDI 法（对数平均迪氏指数法）**：

```
ARPU = 人均曝光 × CTR × 下载率 × 变现率 × ARPPU
贡献度_i = Δln(X_i) / Δln(ARPU)
```

- **异动信号**：CTR 在持续上涨，但 ARPU 不涨甚至微跌 —— "点击涨、收入不涨"是典型的**结构性问题信号**，说明用户点到的东西"不值钱了"。
- **拆解结果**：CTR 上升，但**变现率和 ARPPU 在下降** → 问题不在点击环节，而在"点击内容的质量"。
- **发现方式**：在看板上设了 `CTR vs ARPU` 的联动监控，两者走势背离超过阈值时自动告警。
- **防守追问「多项同时变怎么办」**：做因子分解，逐项计算各因子变化对 ARPU 变化的贡献度（对数分解），排序找主因，**不靠肉眼判断**。

### 3.4 维度下钻（组间组内拆解 + 结构错配分析）

把整体变现率拆成「各子群的变现率 × 各子群的流量占比」，看是**结构变了**（流量往低变现群体倾斜）还是**各组都变差了**。

| 切分维度 | 发现 |
|---|---|
| 按游戏档位 | 高点击档位流量份额从 **35% 涨到 52%**，但其变现率只有大盘的 **60%** → 结构倾斜是主因 |
| 按位置 | 头部位置（1-3 位）CTR 高但变现率低于中位（4-6 位），因为头部被高点击低付费游戏占据 |
| 按用户分群 | 中长尾用户（行为 < 10 次）ARPU 只有大盘的 **40%**，且 AUC 明显低 |

**流量份额 vs 收益份额错配分析**

| 对比项 | 流量份额 | 收益贡献 | 结论 |
|---|---|---|---|
| 高点击游戏 | 52% | 35% | 拿走流量但不值钱 |
| 高收益游戏 | 28% | 55% | 值钱但曝光不足 |
| 点击 Top50 与收益 Top50 名单重叠度 | — | — | 只有 **30%** |

> 结论：分发结构严重错配 —— 流量给了"点击高但不值钱"的内容，"值钱"的内容反而曝光不足。

### 3.5 假设验证（排除竞争性解释，这是"会拉数"和"会分析"的分界线）

**假设一：结构错配是"短期点击优化目标"导致的**

| 验证 | 做法 | 结论 |
|---|---|---|
| 验证 1（名单重叠） | 拉"点击 Top 游戏"与"收益 Top 游戏"名单对比 | 重叠度很低 → 点击与价值确实错配 |
| 验证 2（时间序列） | 拉过去 6 个月"模型迭代方向"与"高点击档位流量份额"的关系 | 每次往点击方向迭代后，份额上升、ARPU 下降，趋势吻合 |
| 验证 3（排除供给） | 查高价值游戏的库存数量和质量分布 | 供给是够的，只是曝光不足 → 是分发问题不是供给问题 |
| 验证 4（排除外部） | 看同期大盘、季节性、版本更新 | 排除外部干扰，确认是内部策略问题 |

**假设二：预估偏差主要来自位置偏差**

| 验证 | 做法 | 结论 |
|---|---|---|
| 验证 1 | 分位置画 PCOC | 同一位置内部偏差小、跨位置偏差大 → 位置是主因 |
| 验证 2 | 固定位置后看残余偏差，再分场景、分时段切 | 定位出**场景分布差异**和**回流延迟**两个次因 |
| 验证 3（量化回流延迟） | 拉点击回流时间分布 | 24 小时后晚回流比例约 **8%**，估算对 CTR 的低估影响约 **3-5%** → 延迟不可忽略 |

**假设三：中长尾用户差是因为行为稀疏、表征差**

| 验证 | 做法 | 结论 |
|---|---|---|
| 验证 1 | 画「用户行为数 vs AUC」曲线 | AUC 随行为数单调上升 → 稀疏是瓶颈 |
| 验证 2 | 看召回命中率 | 中长尾用户实际点击落在召回集里的比例**只有头部的 60%** → 召回也不准，不只是排序问题 |

> 每个假设都做到"**有证据、有量化、排除了其他解释**"，才进入策略阶段。

**防守追问：「CTR 涨 ARPU 跌，会不会是季节性或大盘？」**
> 我看了同期大盘和自然流量基线，排除了季节性和版本因素；且拆解后是变现率和 ARPPU 跌，和大盘趋势不一致，确认是内部结构问题。

### 3.6 漏斗分析（转化率下降怎么分析）

拉漏斗（曝光 → 点击 → 落地页 → 转化），定位卡点环节，再按维度下钻。
给一个新广告位/新场景搭分析框架的标准四步：
1. 先看它在大盘的位置（收入占比、eCPM、填充率）；
2. 再拆链路（请求 → 填充 → 曝光 → 点击 → 转化）；
3. 找瓶颈环节 → 按行业/广告主/人群下钻；
4. 给出优化方向 + **可验证的实验**。

### 3.7 AB 实验 / 准实验

**设计清单**

| 要素 | 要点 |
|---|---|
| 假设与主指标 | 先写死主指标，避免事后挑指标 |
| 分流单元 | 用户 / 广告主 / 请求；OPPO 项目用**用户** |
| 样本量 | 由基线转化率、MDE、显著性水平 α（一般 0.05）、统计功效 1-β（一般 0.8）决定 |
| 周期 | 长期价值有延迟效应 → 周期定 **2 周以上**；保留 **1-2%** 长期对照组观察留存 |
| 显著性 | 看 p 值（p < 0.05）+ 置信区间是否跨 0 |
| 护栏指标 | CTR、留存、负反馈 —— 防止主指标涨但体验降 |
| 广告场景特有 | 竞价干扰：实验组与对照组在同一拍卖里互相影响时普通分流会失真，要用**分桶或 switchback** |
| 常见陷阱 | 辛普森悖论、新奇效应、网络效应、peeking（提前偷看放大假阳性） |

**辛普森悖论标准答案**
> 分组看都是 A 好，合并看却是 B 好，因为分组权重不同。广告里常见：某策略在每个行业都提升 CTR，但合并后下降，因为流量往低 CTR 行业倾斜了。所以要**分层看 + 看结构变化**。

**归因方式（不能严格 A/B 时的准实验）**

| 情形 | 做法 | 表述纪律 |
|---|---|---|
| 能分流 | "策略客群 vs 对照客群"对比转化和规模，算增量 | 报增量，不报总量 |
| 不能严格 A/B | 策略前后对比 + 趋势剔除做辅助 | 明确说明"这是保守估计" |
| 多策略同时上 | 分批上线、单独实验、单独归因，避免"一锅烩" | 说清哪一项归谁 |
| 机制一致性检验 | 分桶看：中长尾桶涨 **2.3%**、头部桶持平 | 和"补稀疏"的机制预期一致，因果链对得上 |

**长期对照组的伦理/业务防守**
> 比例很小（比如 1-2%），且和产品、运营对齐过；长期价值类策略必须有长窗口对照，否则归因不可信，这是权衡后的选择。

### 3.8 SQL 模板（现场手写题）

**① 次日留存**（表 `active(uid, dt)`）
```sql
SELECT a.dt,
       COUNT(DISTINCT a.uid) AS active_uv,
       COUNT(DISTINCT b.uid) AS retain_uv,
       COUNT(DISTINCT b.uid) / COUNT(DISTINCT a.uid) AS retention_1d
  FROM active a
  LEFT JOIN active b
    ON a.uid = b.uid AND b.dt = date_add(a.dt, 1)
 GROUP BY a.dt;
```

**② 7 日留存（7 天内回访）**
```sql
SELECT a.dt,
       COUNT(DISTINCT a.uid) AS active_uv,
       COUNT(DISTINCT b.uid) AS retain7_uv
  FROM active a
  LEFT JOIN active b
    ON a.uid = b.uid
   AND b.dt BETWEEN date_add(a.dt, 1) AND date_add(a.dt, 7)
 GROUP BY a.dt;
```

**③ 分组 TopN（各行业消耗 Top3 广告主）**
```sql
SELECT industry, advertiser_id, cost
  FROM (
    SELECT industry, advertiser_id, cost,
           ROW_NUMBER() OVER (PARTITION BY industry ORDER BY cost DESC) AS rk
      FROM ad_cost
  ) t
 WHERE rk <= 3;
```

**④ 连续 7 天消耗的广告主（gap-and-island）**
```sql
SELECT advertiser_id
  FROM (
    SELECT advertiser_id,
           date_sub(dt, ROW_NUMBER() OVER (PARTITION BY advertiser_id ORDER BY dt)) AS grp
      FROM (SELECT DISTINCT advertiser_id, dt FROM ad_cost) t
  ) g
 GROUP BY advertiser_id, grp
HAVING COUNT(*) >= 7;
```

### 4.1 中信 · 余额抢夺项目（"用数据推动业务"的主力弹药）

**S｜背景**
卡中心要提升分期收入，但很多客户在他行已有信贷或分期，余额在别人那里。营销现状是**广覆盖但效率低**。我的任务是用数据找到这些客户，把余额抢回来。

**T｜任务**
从几千万有效客户里定位可抢夺人群，设计并落地抢夺策略，形成可评估、可迭代的闭环。

**A｜行动（三件事）**

| 动作 | 具体做法 | 关键数字 |
|---|---|---|
| ① 搭客群漏斗 | 从几千万有效客户里逐层剔除非目标、不可经营、分期中客户，锁定**近一年未分期客户**，再结合人行征信识别他行借贷目标 | 他行信贷 **587 万**、他行分期 **1142 万** |

**R｜结果**
累计落地 **13 项策略**，抢夺分期规模 **3.8 亿/月**；其中**定价对标**一项累计抢夺 **5.7 亿**。

**配套：六大渠道营销数据体系（同一个项目的第二条线）**

**数字口径防守（主管面必问：3.8 亿/月、5.7 亿怎么算的？怎么归因到你头上？）**

**贡献边界（考诚实）**

### 4.2 中信 · 抗压案例（三方博弈，HR 抗压题唯一指定素材）

**为什么用这个素材**：它同时具备三种压力，比"加班赶 deadline"高级得多。

| 压力类型 | 具体表现 |
|---|---|
| 时间压力 | 策略要按期上线，一期效果评估完马上迭代二期 |
| 多方博弈压力 | 财务要控成本、风险要控敞口、业务要冲规模，三方目标冲突 |
| 结果压力 | 有明确的规模目标，做不出来没法交代 |

**S｜背景 + 压力源**
> 我在中信主导余额抢夺项目时，有一次压力特别大。当时一期定价抢夺策略刚上线两周，领导要求马上做效果评估并迭代二期策略；同时财务要求我把成本控制在预算内，风险要求额度调整不能突破敞口红线，业务又催着要看到规模增长。三方同时提要求，而且目标互相矛盾 —— 财务要省钱、风险要保守、业务要放量。deadline 是**两周后**必须出二期方案。

**T｜任务**
> 在两周内，拿出一版三方都能接受的二期定价策略方案，并且要有数据支撑、能落地。

**A｜行动（三步方法论）**

| 步骤 | 做法 | 心法 |
|---|---|---|
| ① 先稳住自己，把问题结构化 | 把三方的核心诉求和底线列成一张表：财务底线是成本不超 X，风险底线是敞口不超 Y，业务期望是规模增长 Z | 列完发现冲突没想象中大，只是看问题角度不同 |
| ② 用数据找"三方都能接受的交集" | 花三天跑测算：按客群分层 —— 对高响应低风险客群做**激进定价**（满足业务），对中风险客群做**保守定价**（满足风险），整体成本控制在预算内（满足财务） | 用客群分层把**一个大冲突拆成多个小决策** |
| ③ 主动约三方一起过方案 | 拉联合评审会，把测算逻辑、客群分层、成本/敞口/规模三个数字同时摆桌上，让三方当场确认 | 避免"跟财务说完跟风险说、风险又推翻"的来回拉扯 |

**R｜结果**
> 二期方案在 deadline 前通过三方评审，按时上线。上线后效果比一期还好 —— 抢夺规模稳步增长，成本没有超预算，敞口也在红线内。整个项目累计落地 **13 项策略**，月抢夺规模做到 **3.8 亿**。
> 这段经历让我形成一个习惯：**压力大的时候，先结构化问题，再找交集，最后主动拉齐各方**。越是多方博弈，越不能自己闷头扛，要主动把信息摊开、把决策权交回去。

**口述压缩版（40 秒，背下来）**
> 我在中信做余额抢夺时压力最大的一次：一期策略刚上线，领导催着出二期，同时财务要控成本、风险要控敞口、业务要冲规模，三方目标互相矛盾，deadline 只有两周。
> 我的应对是：先把三方底线列成表，发现冲突没想象中大；然后用客群分层把一个大冲突拆成多个小决策，每个小决策里三方都能接受；最后主动拉三方联合评审，当场确认，避免来回拉扯。

### 4.3 OPPO · 应用商店 & 游戏中心分发优化（完整讲述版）

**① 业务背景（30 秒，先给画面）**
> OPPO 应用商店和游戏中心是手机系统里的核心分发入口，用户打开商店，我们决定给他展示哪些应用、哪些游戏。这个场景有两个特点：
> 第一，**它直接对商业收入负责**。应用分发挂钩应用下载和厂商合作收入，游戏分发挂钩游戏充值和联运收入，所以核心指标不只是点击和下载，还有 ARPU 和长期收益。
> 第二，**它有广告属性**。商店里有 CPC 竞价推广位，广告主花钱买曝光，所以分发系统要同时平衡自然分发和广告分发、平衡用户体验和商业收入。
> 我在这个场景负责推荐算法和数据分析，覆盖应用分发和游戏分发两条线。

> 这段的作用：让面试官立刻明白，这个场景和"程序化广告 / 营销投放"是同构的 —— 都是「流量分发 + 商业化收益 + 体验平衡」。

**② 面临的问题（1 分钟，用数据定义问题）**

| 问题 | 表现 | 本质 |
|---|---|---|
| 一：分发结构失衡，短期点击透支长期收益 | 高点击游戏留存和付费贡献很低却拿走大量曝光；高留存高付费的优质游戏曝光不足。短期点击在涨，长期 ARPU 被透支 | **优化目标错了** |
| 二：预估不准，位置偏差污染排序 | 不同位置 CTR 差异很大，模型把"位置好"误学成"内容好"。分位置看"预估/实际"，不少切片偏差**超过 50%** | **预估依据脏了** |
| 三：中长尾用户服务不好，变现差 | 行为稀疏，模型几乎不认识他们，召回排序都不准，点击/下载/付费都低，ARPU 明显低于大盘 | **稀疏用户没服务好** |

**③ 三个诊断（1.5 分钟，体现分析框架）**

| 诊断 | 做法 | 结论 / 支撑的决策 |
|---|---|---|
| 收益结构诊断 | 建游戏级价值表：用 **D7 留存、付费率、ARPPU** 算长期价值分，与流量份额对比 | 高价值游戏流量份额系统性低于收益贡献，**错配度可量化** → 支撑"优化目标从短期点击转向长期价值" |
| 预估校准诊断 | 分位置、分场景、分人群画校准曲线，看"预估 CTR vs 实际 CTR" | 偏差来自三类：**位置偏差、场景分布差异、回流延迟** → 决定"模型层去位置偏 + 输出层分维度校准" |
| 用户分层诊断 | 按活跃度和行为丰富度分桶，看各桶 ARPU 和 AUC | 中长尾桶 AUC 和 ARPU 都明显低 → 确认"稀疏用户表征差"是核心瓶颈，决定对比学习方向 |

> 三个诊断的共同特点：**先量化问题，再定方案**。不是拍脑袋上策略，每个策略都有数据依据。

**④ 四个策略（每个带因果链）**

| 策略 | 做法 | 解决哪个问题 |
|---|---|---|
| 一：建长期价值体系，改优化目标 | 把游戏长期价值分接入排序目标，替代单一短期点击；高价值游戏获得长期价值加成 | 优化目标错了 |
| 二：多位置预估 + 分维度校准 | 训练时位置单独建模（bias tower），serving 去掉位置影响，输出内容本身 CTR；再按**场景 × 位置 × 人群**分桶校准，建 PCOC 监控闭环 | 预估依据脏了 |
| 三：分发结构校准 | 精排后加一层重排校准：监控各档位"流量份额 vs 收益份额"错配度，高价值游戏加 boost、高点击低价值游戏限流，给长尾留探索流量 | 资源分配错了 |
| 四：对比学习补中长尾 | 主架构上加自监督对比辅助任务：相似用户互拉近、正负反馈拉开、浅行为向深行为对齐 | 稀疏用户没服务好 |

> **和广告分发的复用关系（重点讲）**：校准后的 pCTR 是广告出价和计费的依据；结构校准对应广告与自然结果的混排平衡；长期价值体系对应"收入 vs 体验 vs 生态"的权衡。所以我做的不只是自然分发，也为广告分发的收益优化打了基础。

**⑤ 策略优先级矩阵（收益面 × 落地成本）**

| 策略 | 收益 | 成本 | 优先级 | 理由 |
|---|---|---|---|---|
| 校准（修度量衡） | 中（所有策略的基础） | 低 | **P0，先做** | 预估准了，后面所有策略的依据才可信 |
| 长期价值体系（改目标） | 高（根本性） | 中 | **P0，并行** | 收益面最大 |
| 结构校准（调分配） | 高 | 中 | **P1** | 依赖长期价值分 |
| 对比学习（补能力） | 中（中长尾） | 高 | **P2** | 成本高、周期长，作为长期项目立项 |

> 排序逻辑一句话：**先修"度量衡"（校准），再改"目标"（长期价值），再调"分配"（结构），最后补"能力"（对比学习）**。

**⑥ 效果评估与结果**

| 维度 | 内容 |
|---|---|
| 实验设计 | 分流单元=用户；长期价值有延迟效应 → 周期 2 周以上；保留 1-2% 长期对照组观察留存；主指标 ARPU，护栏 CTR/留存/负反馈 |
| 归因方式 | 策略分批上线、分别实验、分别归因，避免"一锅烩"；对比学习用分桶验证：中长尾桶涨 **2.3%**、头部桶持平 → 机制预期一致 |
| 校准衡量 | PCOC + 分切片相对偏差两个口径；优化前主要切片偏差 **50%+**，优化后控制在 **20% 以内**，PCOC 收敛到接近 1 |
| 最终结果 | **ARPU +1.04%**，**中长尾 +2.3%**；高价值游戏曝光份额提升；护栏指标不降、点击体验不降 |

**⑦ 监控沉淀闭环**
- PCOC 分切片监控 + 阈值告警（偏离 **[0.9, 1.1]** 告警）；
- 流量份额 vs 收益份额**错配度周报**；
- 分人群 AUC / ARPU 监控；
- 策略上线后自动触发效果评估流程。
> 形成「监控 → 诊断 → 策略 → 评估 → 迭代」的闭环，不是一次性分析。这套机制后来成了团队的常态化流程。

**⑧ 三分钟口述版（背这个）**
> 这个项目的数据分析我按七阶段闭环做。
> 先搭**五层指标体系**，统一口径。
> 然后**发现异动**：CTR 涨但 ARPU 不涨，"点击涨收入不涨"是结构性问题信号。
> **公式归因**用 LMDI 法：把 ARPU 拆成 人均曝光 × CTR × 下载率 × 变现率 × ARPPU，算各因子贡献度，定位到变现率和 ARPPU 在跌。
> **维度下钻**用组间组内拆解：确认是流量往高点击低变现档位倾斜，不是各组都变差。同时做了流量份额 vs 收益份额的错配分析，名单重叠度只有 30%。
> **假设验证**：用时间序列、供给排查、外部因素排除，确认是优化目标问题；分位置 PCOC 定位偏差来源；行为数-AUC 曲线确认稀疏是瓶颈。每个假设都排除了竞争性解释。
> **策略排优先级**：先校准修度量衡，再改目标，再调分配，最后补能力。
> **评估**上分批实验、分桶归因，ARPU +1.04%、中长尾 +2.3%、偏差降到 20% 以内。
> 最后**沉淀**成 PCOC 监控和结构错配度周报的常态化闭环。

## 五、面试 Q&A

### 5.1 业务域（商业化/程序化广告）

| # | 问题 | 答案要点 |
|---|---|---|
| Q1 | 怎么理解程序化广告？和传统广告的区别？ | 核心是"按每次曝光实时竞价交易"。传统广告是包段排期、价格谈出来；程序化是每次曝光出现时广告主通过 DSP 实时出价、平台按 eCPM 排序成交，价格**竞**出来。好处是流量卖给最需要的人，媒体收入和广告主 ROI 都提升。分析视角变成 **per-impression**：请求、填充、竞价、eCPM、转化整条链路都可拆。 |
| Q2 | eCPM 是什么？怎么提升平台收入？ | eCPM 是每千次展示收入，≈ bid × pCTR × pCVR × 1000。看三层：流量侧看请求量和填充率；竞价侧看参竞广告主数与竞争强度?；预估侧看 pCTR/pCVR 的准确性和校准。同时平衡体验，不能短期透支生态，否则长期收入会掉。 |
| Q3 | OCPX 是什么？成本怎么控？ | 广告主给目标转化成本，平台自动出价，bid ≈ tCPA × pCTR × pCVR / (1+λ)。成本控制靠两点：① pCTR/pCVR 要准且校准，否则出价和计费失真；② λ 在线调节，用实际成本与目标成本的偏差做反馈（类似 PID），把成本拉回目标。 |
| Q4 | 一价和二价的区别？ | 二价赢家付第二高价，**真实出价是最优策略**；一价付自己的出价，所以要 **bid shading**，根据竞得价分布把出价压低一点。近年行业整体往一价走，shading 是 DSP 标配。 |
| Q5 | pCVR 高估会怎样？ | bid 虚高 → 高价赢下低转化流量 → 成本超标；λ 会被迫调大压制，但**治本要靠校准**。 |
| Q6 | oCPC 和 oCPM 出价的区别？ | oCPC 按点击计费，点击出价 = tCPA × pCVR / (1+λ)，排序时再乘 pCTR；oCPM 按曝光计费，直接 bid = tCPA × pCTR × pCVR / (1+λ)。**简历里写的是曝光口径这个**。 |
| Q7 | 冷启动时 pCVR 不准怎么办？ | 用先验/行业均值/lookalike 兜底，或先用浅层目标（点击）过渡，攒够转化样本再切深层。 |

### 5.2 分析题（几乎必考 2-3 道）

| # | 问题 | 答案骨架 |
|---|---|---|
| Q8 | 昨天收入跌了 20%，怎么排查？ | 见 3.2 六步法：拆公式 → 定位层 → 分层往下查 → 维度下钻找贡献最大子集 → 分内外因 → 给结论+建议+跟进验证。**不先猜原因。** |

| Q13 | 最小样本量怎么定？ | 取决于四个量：基线转化率、最小可检测效应 MDE、显著性水平 α（一般 0.05）、统计功效 1-β（一般 0.8）。效应越小、方差越大，需要样本越多。 |
| Q14 | 辛普森悖论是什么？举例？ | 见 3.7。分层看 + 看结构变化。 |
| Q15 | 给你一个广告位/渠道，怎么搭分析框架？ | 见 3.6 四步。 |
| Q16 | 对比学习和 BERT 的 mask 有什么区别？ | 都是自监督，但方式不同：对比式是"拉近相似、推远不相似"，学表征空间的距离关系；生成式（mask）是"遮住一部分、预测被遮住的"，学内容重建。对比学习更适合学 embedding，生成式更适合 token 级理解。损失是 **InfoNCE**：对一个 anchor，在所有负例中识别出自己的正例，形式上是 softmax 形式?，温度系数 τ 控制分布尖锐度。**面试时准确说"自监督对比学习"**，不要简单说"对比学习就是自监督"。 |
