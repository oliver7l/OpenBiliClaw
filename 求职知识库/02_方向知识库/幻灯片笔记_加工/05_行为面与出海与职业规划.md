## 2. 端云协同（三种范式、工程约束、量化/剪枝）

### 2.1 痛点与方案（最亮点部分）

- **痛点**：云端模型更新慢，无法捕捉"此时此刻"兴趣（如用户刚打完一局游戏、手机发热，不应再推重度游戏）。
- **创新方案：端云协同推荐架构**
  - **云端**：负责复杂模型训练（大参数模型），定期下发基础排序模型到端侧。
  - **端侧**：利用手机本地算力，实时捕捉实时特征（当前 App 前台时长、电量、网络状态）。
- **数据验证**：分析端侧实时特征重要性，发现"当前电量 < 20%"时重度游戏转化率下降 **50%**。据此在端侧加实时门控：低电量自动过滤重度游戏、推轻量应用。

### 2.2 三种协同范式（范式对照）

| 范式 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| 完全端侧 | 端侧独立推理 | 实时性最强、隐私好、弱网可用 | 端侧算力/存储有限，模型能力弱 |
| 完全云端 | 云端集中推理 | 模型强、易迭代 | 实时性差、弱网/断网失效 |
| 端云协同（推荐） | 云端训大模型定期下发 + 端侧实时特征门控 | 兼顾模型能力与实时性 | 工程复杂度高、需通信压缩 |

### 2.3 工程约束与量化/剪枝要点

- **端侧模型约束**：大小控制在几百 KB 以内，不影响低端机性能（基于规则排序 + 小型 Embedding 查表）。
- **通信协议**：推荐请求/返回用 Protocol Buffers 替代 JSON，payload 压缩到原来的 **1/3**；弱网成功率提升约 **30%**。
- **特征降级（三层兜底）**：实时特征拿不到 → 用离线特征兜底（昨天浏览） → 离线也没有 → 用静态画像（设备/语言/地区） → 再没有 → 全局热门。
- **分级缓存**：第一优先级（必须缓存）应用 ID + 排序（几 KB 纯文本）；第二优先级（尽量缓存）图标（几十 KB/个）；第三优先级（网络好才加载）截图/描述。
- **预计算 + 端侧缓存**：用户打开商店前预加载推荐结果；网络超时展示本地缓存上次结果 + 热门榜单，保证不空白页。
- **存储感知推荐**：存储充足推高质量图文应用；存储紧张推轻量级应用（APK 体积小）并减图片加载——双赢（装得下 + 轻量转化率高）。
- 量化/剪枝落地：端侧极轻量模型（规则 + 小型 Embedding 查表），断网也能按本地缓存行为做简单个性化排序。

### 2.4 端云协同数值注意（softmax 溢出）

- 端侧排序若用 softmax 打分，朴素实现 `log_sum = log(sum(exp(logits)))` 在 logits 较大时会有数值灾难（溢出为 inf/nan）。
- 工业做法：用 **log-sum-exp 技巧** 平移最大值 `m = max(logits)`，再 `log_sum = m + log(sum(exp(logits - m)))`，避免溢出；端侧算力弱更要规避此类数值坑。

## 3. LTV 预估与用户洞察

### 3.1 LTV 三种口径

| 口径 | 公式 / 做法 | 优点 | 缺点 |
|---|---|---|---|
| 队列统计法（RB） | LTV_n = 某队列前 n 天累计收入 / 该队列新增用户数；常用 LTV1/LTV7/LTV30/LTV90 | 口径简单、无假设 | 要等 n 天才能算（右截断），新用户标签不成熟，没法指导早期决策 |
| 留存曲线拟合法 | 平均生命周期 LT = ΣR(n)；LTV = ARPDAU × LT；留存 R(n)=a·n^(-b) 或指数衰减 | 不用等用户全流失就能估全周期 | 需足够长窗口截断求和避免发散 |
| 比例系数法（买量） | LTV_n = LTV_d × 历史(LTV_n/LTV_d) 系数 | baseline，D7 即出价 | 假设历史曲线形态不变 |

- 买量场景：LTV_n / CPI > 1 才回本。

### 3.2 LTV 预估方法阶梯（由浅入深）

| 方法 | 思路 | 适用 |
|---|---|---|
| 比例系数法 | LTV_n = LTV_d × 历史系数 | baseline / 买量出价 |
| 曲线拟合外推 | 拟合个体/队列早期收入曲线外推 | 队列级 |
| 特征=早期行为（D0-3 登录/时长/关卡/付费/看广告/社交）标签=LTV_n；GBDT/DNN | 早期行为预测 | 出价/分发 |
| 两阶段建模 | 先分类"会不会付费"，再对付费用户回归"付多少"；LTV = p(付费)×E[金额] | 解决零膨胀 |
| ZILN（Google） | 零膨胀对数正态：分类头判零/非零 + lognormal 回归头估金额，可输出不确定性 | 用户级主流 |
| 序列模型 | 行为序列（Transformer 等）建模兴趣演化 | 行为丰富场景 |

### 3.3 资深一招：把回归转成排序/分层

分发与资源分配真正要的是 LTV **排序**（谁/哪个游戏长期价值更高），不是绝对值。
- 用 pairwise/listwise 排序损失直接学排序；或做高/中/低价值分层分类——从根本绕开稀疏绝对值估计。

### 3.4 游戏级 vs 用户级 LTV

| 维度 | 游戏级 LTV | 用户级 LTV |
|---|---|---|
| 聚合单位 | 游戏（或游戏×渠道队列） | 单个用户 |
| 回答的问题 | 这个游戏值不值得分发/投入？ | 这个用户值不值得运营/出价？ |
| 数据性质 | 聚合后不稀疏，分布稳定 | 零膨胀、长尾、截断、延迟 |
| 预估目标 | 绝对值（算 ROI） | 排序/分层（差异化） |
| 主要方法 | 付费留存拆解、队列统计、留存曲线拟合 | 两阶段、ZILN、排序学习、分层分类 |
| 评估方式 | 绝对值校准、队列回测 | Top-K 命中率、排序指标、分桶校准 |
| 典型用途 | 分发结构校准、买量评估、生态资源分配 | 个性化运营、差异化出价、鲸鱼识别 |

### 3.5 面试口述版（40 秒，挂钩 OPPO）

"我在 OPPO 两层都做了。游戏级用付费留存拆解法估绝对值——D7 留存 × 付费率 × ARPPU × 生命周期系数，再接队列实际值校准，接入分发结构校准（聚合后不稀疏，绝对值估得稳，分配决策要绝对值算 ROI）。用户级做分层和排序——零膨胀长尾绝对值估不准，差异化运营要排序，所以把用户分**高价值/中低活/潜在付费/新用户四层**做差异化分发，**中长尾 ARPU +2.3%**。两层各司其职：游戏级解决'分发什么游戏'，用户级解决'怎么分给谁'。"

### 3.6 LTV360（最难一档）核心思路

**不要直接回归 360 天绝对值，而是"分层借力 + 曲线外推 + 再校准?"**。

| 本质困难 | 表现 |
|---|---|
| 标签永远不成熟 | 今天用户要等一年才有真实 LTV360，训练样本严重滞后 |
| 截断 + 延迟 | 近期队列标签不完整，直接训练系统性低估 |
| 不确定性大 | 行为漂移、版本更新、活动刺激，长期外推误差随窗口放大 |

五种主流方法：
1. **比例系数法**：LTV360 = LTV_d × K(d→360)，K 分渠道/分品类/分用户层统计；D7 即出价。
2. **留存/收入曲线拟合外推**：R(n)=a·n^(-b) 或混合形式，用前 d 天拟合外推 360 天求和。
3. **两阶段 + 分布建模**：先分类 360 天是否付费，再对付费用户 log 变换/ZILN/分桶序数回归；LTV360 = p(付费)×E[金额]。
4. **surrogate 代理指标法**：先估早期强相关代理（D7 留存/D7 付费/D3 时长/关卡进度），再映射外推（Google Surrogate 思路）。
5. **序列/深度模型直接建模**：早期行为序列直接输出 LTV360 分布，需足够成熟标签与工程投入。

标签不成熟怎么办（灵魂问题）：
- 成熟队列训练 + 不成熟队列校准：只用成熟旧队列训模型，新队列上线用早期实际值（如 LTV7 实际）比例校准，形成"成熟队列训 → 新队列早期校准"滚动闭环。
- 截断标签修正：曲线拟合补全到 360 天，或逆截断加权（标签越不成熟权重越低）。
- 多窗口联合建模：同时训 LTV7/30/90/360 多头共享表征，短窗口信号密帮长窗口头学稳（多任务迁移）。

评估（体现资深）：分桶校准（每十分位预估边际）、Top-K 高价值命中率/排序指标、队列回测（历史队列"假装 D7 预测"对比真实 LTV360）、分渠道/分品类误差。**不要只看 RMSE**——会被鲸鱼拉爆，无业务意义。

LTV360 口述版（60 秒）：组合方案 = ① 比例系数 baseline（D7 出价）② 用户级两阶段+log 变换解决零膨胀长尾 ③ 标签不成熟用成熟旧队列训+新队列早期校准滚动闭环+多窗口联合建模 ④ 评估看分桶校准/Top-K/队列回测。OPPO 游戏级拆解法估绝对值做分配，用户级转排序分层，LTV360 长窗口用比例外推+校准。

防守追问：K 不稳定→分渠道/品类/用户层统计+监控漂移+近期成熟队列滚动更新+异常回退曲线拟合；版本大更新历史曲线失效→引入版本/活动特征条件外推或重拟参数；买量结合→bid = pLTV360，约束 LTV360/CPI > 1 回本线，不确定性大降出价或留探索预算。

### 3.7 用户洞察（硬件/频次/生命周期/跨渠道，体现数据广度）

| 洞察 | 数据发现 | 策略与效果 |
|---|---|---|
| 电量焦虑（硬件特征） | 电量 >30% 大型游戏(>1GB)下载转化平稳；跌破 20% 暴跌 **40%**（轻量 <50MB 几乎不受影响）；低电量 CTR 未降，降的是"下载确认"步——"省电防御心态" | 引入实时电量特征，<20% 降大型应用权重转轻量；低电量场景下载成功率 **+15%** |
| 展示疲劳与负面光环（频次） | 前 3 次曝光转化升；第 5 次后转负（连附近推荐位意愿都降）——"广告盲区/杀鸡取卵" | 疲劳度模型设曝光上限阈值（如 4 次）强下线/换素材；已点击未下载推攻略礼包；负面反馈（不感兴趣/X）**-20%** |
| 游戏生命周期红利窗口（时序） | 首周流量红利；第 14 天自然流量断崖；头部长尾、腰部短命 | 导入期(D1-3)激进抢首屏、平稳期(D4-14)精准追投、衰退期(D15+)止损腾位；CPA **下降 10%** |
| 搜索二次唤醒（跨渠道） | 搜过未转化用户 24h 内首页再看到相关游戏，下载转化率是普通推荐流 **3 倍以上** | 搜索-推荐联合召回池，实时打标提权；流失用户召回率 **+25%** |
| WiFi 前置下载（场景） | >1GB 非 WiFi 点击到下载转化极低；非 WiFi 看详情页的有强意图但止步流量顾虑 | 检测移动网切 WiFi + 闲置 + 电量足时后台静默预下载；WiFi 下大型游戏转化 **+18%** |
| 位置点击陷阱（偏差分析） | 首屏第一卡位 CTR 达 10%+，其中约 40% 属"位置性点击"；Swap 实验换到第四位 CTR 跌至 2% | 训练样本加位置特征权重 / Loss 加位置惩罚项剥离虚假点击；预估偏差控制 20% 以内，剔除"靠位置上位"低质游戏 |

## 4. 海外与跨国家推荐

### 4.1 海外市场背景（东南亚六国：印尼/泰国/越南/菲律宾/马来西亚/新加坡）

| 国家 | 用户特征 | 网络（Ookla 2024） |
|---|---|---|
| 印尼 | 人口 2.7 亿，低端机占比高，偏免费/轻量，伊斯兰文化影响内容 | ~28.8 Mbps（中国 1/5）；5G 覆盖 26.3%；多岛屿弱网 |
| 泰国 | 中等消费力，社交娱乐渗透高，泰语忠诚度高 | — |
| 越南 | 年轻用户多，偏游戏/短视频，价格敏感 | ~87 Mbps（接近中国） |
| 菲律宾 | 英语普及高，接受欧美应用，社媒时长全球前列 | ~36 Mbps（中国 1/4） |
| 马来西亚 | 多语言（马来/英/中），多元文化，消费力较高 | — |
| 新加坡 | 高消费力，偏精品应用 | ~129 Mbps（接近中国） |
| 柬埔寨 | — | ~32 Mbps（中国 1/4） |

- 设备现实：东南亚 >60% 手机是 200 美元以下低端机，存储仅 32GB 且长期几乎满；移动网速约中国 1/5；系统频繁清理 APP 缓存。

### 4.2 六大挑战

| 挑战 | 本质 | 关键数据/表现 |
|---|---|---|
| ① 跨国家数据分布偏移 | 各国行为分布差异大 | 印尼/泰国 Top10 应用重合度仅 30-40%；同应用印尼 CTR 8% vs 泰国 3%；联合建模被数据量大国（印尼）主导，小国被稀释 |
| ② 数据稀疏与冷启动 | 双重冷启动 | 东南亚多首次触网用户无画像；低端机无 Google 账号；每日海量新应用上架；新用户前 3-5 次推荐只能靠热门榜 CTR 极低 |
| ③ 马太效应与长尾 | 头部集中 | Top 1% 应用占 80%+ 下载；纯按 CTR 优化热门更热；本地化应用（Gojek/Line Man）跨国家几乎无曝光 |
| ④ 多语言/文化 | 同名异语、跨文化偏好 | 同应用各国本地化名称不同；印尼搜"编辑视频"要匹配英语描述；新闻品类印尼偏伊斯兰/泰国偏娱乐/越南偏时政 |
| ⑤ 实时性与架构 | 秒级期望但弱网 | 印尼多 3G/4G 弱网；商店刷新频率不需像信息流高，但新行为后要尽快更新 |
| ⑥ 用户 ID 不可靠 | 身份危机 | GAID 可重置/可限广告追踪（2025 Play 要求 Data Safety 表单）；登录率低；多设备多账号 |

### 4.3 多国联合建模：三种方案对比（面试高频追问）

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| 各国独立建模 | 每国一个独立模型 | 完全个性化，不受他国影响 | 小国数据量不够，效果差 |
| 完全联合建模 | 所有国家数据混训一个模型 | 数据量大、泛化强 | 被大国（印尼）主导，小国效果差 |
| 共享底层 + 国家适配（推荐） | 底层共享 Embedding，上层各国独立适配 | 兼顾共性个性 | 工程复杂度高 |

- **落地话术**：最初独立建模→新马小市场数据不够效果差；完全联合→印尼数据量是他国 3-5 倍，模型被主导、泰国反而降；最终**共享底层 Embedding（跨国家共性偏好）+ 每国轻量 MLP 适配层（几十万参数，用本国数据微调）**。
- **效果**：联合建模 vs 独立建模，小国 NDCG@10 **+8~12%**，大国基本持平或略升；整体加权提升约 **5%**。

### 4.4 三层时效架构（实时性解法）

| 层 | 职责 | 时效 |
|---|---|---|
| 离线层 | 每天/每小时全量算用户画像 + 应用 Embedding，生成候选集 | 天/小时 |
| 近线层 | 基于最近行为（最近 1h 内下载/浏览）增量更新画像 | 15-30 分钟批量 |
| 在线层 | 请求到达时轻量排序模型最终排序 | P99 延迟 < 50ms |

- 弱网容灾三层兜底：实时推荐（画像+实时行为）→ 离线预计算（画像+历史行为）→ 本地缓存+热门榜单。
- 特征降级链：实时特征缺失→离线特征兜底→静态画像→全局热门。
- 端侧轻量模型（几百 KB）：断网也能按本地缓存行为做基本个性化；存储感知推荐双赢。

### 4.5 弱网 / 低端机专项数据

- 网络：印尼 28.8 / 菲律宾 36 / 柬埔寨 32 / 越南 87 / 新加坡 129 Mbps；印尼 5G 覆盖 26.3%。
- 通信优化：Protobuf 替代 JSON，payload 压到 1/3，弱网成功率 **+30%**。
- 分级缓存 + 端侧轻量模型 + 存储感知：低端机用户推荐 CTR **+15%**，加载成功率 **72%→89%**。

### 4.6 数据建模四难点与解法

| 难点 | 表现 | 解法 |
|---|---|---|
| 正样本极稀疏 | 下载/曝光仅 0.5%-2%（比信息流 CTR 低一量级） | 样本加权 + Focal Loss；隐式反馈扩 5-10 倍 |
| 多目标冲突 | CVR vs 7 日留存 vs 长尾覆盖率 vs 商业化收入 | 多任务学习（共享 Embedding + 多预测头），最终分 = 下载概率×留存概率×多样性权重 |
| 跨国家分布偏移 | 大国主导小国 | 共享底层 + 国家适配层（适配参数仅底层 1/10） |
| 实时特征难获取 | 回传延迟/杀后台丢埋点 | 三层时效（在线/近线/离线）降依赖 |

- 隐式反馈权重：详情页停留 >10s = 0.3；点"查看更多截图" = 0.5；点"安装"但取消 = 0.7；实际下载 = 1.0；下载后 3 天内卸载 = -0.5。训练数据量扩 5-10 倍。
- 多任务效果：相比单任务，下载后 7 日留存率 **+12%**（推荐质量真提高，非"会点不会用"）。

### 4.7 多语言与文化/节假日差异

- 跨语言语义空间：mBERT / XLM-R 把不同语言应用描述与搜索词映射到同一语义空间（印尼语搜"编辑视频"匹配英语描述应用）。
- 语言偏好特征：用户历史主要浏览/下载何种语言应用，作为排序重要特征。
- 文化偏好：新闻品类印尼偏伊斯兰 / 泰国偏娱乐 / 越南偏时政；节假日效应需进归因（点击率突降分析要区分内外部，外部含节假日）。
- 应用生态差异（不可直接复刻）：国内微信/QQ/微博 vs 海外 WhatsApp/FB/Line/Zalo；电商国内淘宝京东 vs 海外 Shopee/Lazada/Tokopedia；支付支付宝微信 vs GoPay/GrabPay/MoMo；出行高德滴滴 vs Grab/Gojek。

### 4.8 知识迁移与 Adapter（跨域迁移核心）

**核心原则：不迁移个体，迁移模式。** 三类跨域共享锚点：

| 锚点 | 对齐方式 | 例 |
|---|---|---|
| 应用属性特征 | 同一语义/数值空间 | 微信[社交,180MB,4.6星]≈WhatsApp[社交,65MB,4.3星]；模型学"社交+高评分+小体积+离线好"，全球通用 |
| 用户设备与环境 | 映射通用维度 | 华为 Mate60(高端)≈三星 A04(低端)；模型学"高端+大存储+WiFi 接受大型应用"，跨国界成立 |
| 行为模式 | 全球通用 | "搜索后下载意图强""详情页>10s 表示兴趣""下载后 3 天卸载=质量差""周末下载 +30%(国内)/+25%(海外)" |

迁移流程：①构建共享特征空间（用特征把不可对齐 ID 转成对齐全向量）②国内数据预训练（编码通用规律到参数）③海外数据微调（底层保留、上层重训、学习率极小防忘）。

**正向迁移效果好**：用户偏好与设备/环境关系、行为信号与转化概率关系、应用属性与转化关系、多目标平衡策略、冷启动内容理解（NLP 多语言适配）——极好/通用。
**不能迁移**：具体应用间关联关系（微信↔支付宝 ≠ WhatsApp↔GoPay）、具体用户长期画像（张三≠Budi 完全不能迁移）。

Adapter 方案（不修改原参数，插小型适配器只训适配器）：国内预训练模型冻结 + [适配器A 印尼][适配器B 泰国][适配器C 越南]，某国不好只重训该国适配器不影响他国。

负迁移三场景与避免：
| 场景 | 表现 | 避免 |
|---|---|---|
| 源域目标域差异太大 | 国内"从众搜索"强信号迁印尼忽视社交信号 | 迁移前做域间相似度检测（JS 散度 / MMD 距离），超阈值不迁移或只迁底层 |
| 国内模型过拟合中国特有模式 | 偏好大厂(BAT) / 广告容忍高 / 编辑推荐 CTR 高 / WiFi 批量下载——海外不成立 | 门控机制（如美团 CCTL 信息流网络自动调样本权重） |
| 微调策略不当 | 学习率太大忘通用知识 / 冻结不当 / 微调数据偏印尼 | 渐进式微调（先冻结底层 80% 只训上层 20%，观察后逐步解冻，全模型极小学习率；首步下降立即停） |

- 域间相似度检测：JS 散度超阈值不如目标域从头训。
- 迁移价值取决于目标域数据量：新加坡/马来西亚极小→强迁移；印尼大→边际收益小；新上线国家冷启动→必须迁移。
- 实证：美团 2023 KDD CCTL 框架跨域迁移带来 **CTR +4.37% / GMV +5.43%**（前提目标域相对源域更稀疏）。
- 完整例子：国内学"存储 <5GB 推 APK <50MB，转化 +40%"（存储紧张用户大应用转化 0.3% vs 小应用 1.2%）；迁印尼 Budi 存储 1.2GB→推 Facebook Lite(2MB) 而非主应用(280MB) 成功。
- 必须 A/B：实验组"国内预训练+海外微调" vs 对照组"纯海外从头训"，对比 NDCG/CTR/CVR；负向立即回退。
- 求职话术锚点：海外最大痛点是数据稀疏，国内预训练 = 给海外模型"好的起点"，数据少也能快速可用。

### 4.9 海外平台出价体系速查（百度国际化竞争视野）

| 平台 | 出价策略 | 备注 |
|---|---|---|
| Google Ads | Manual CPC / Max Clicks / Max Conversions / Max Conversion Value / Target CPA / Target ROAS | Enhanced CPC 已于 2025-03 淘汰 |
| Meta Ads | Lowest Cost（默认）/ Cost Cap / Bid Cap / Highest Value / ROAS 保底 | 不区分 CPC/CPM，选优化目标系统定计费 |
| TikTok Ads | 成本上限 Cost Cap / 最大投放量 Maximize Delivery | 2025-07 推 GMV Max（成交额最大化全自动） |
| 第三方 Open Web | DSP: oCPM/CPM；SSP: CPM 底价/二价；PMP 固定 CPM/优先竞价；PDB 固定 CPM 保量 | 流量分散数据不通，智能出价受限 |

- 大平台生态趋势全面转全智能出价（平台有数据有模型）；Open Web 仍 CPM 为主 + DSP 端 oCPM。
- 百度国际化建议：海外自建智能出价能力（oCPM/tCPA）；成熟市场（东南亚/中东数据足）推 tROAS，新兴市场数据不足先用 oCPM 积累。

## 5. 职业规划与 BP 面（含反问清单）

### 5.1 自我介绍模板（1-2 分钟）

"面试官您好，我是 XXX，硕士毕业于 XXX。核心经历两块：①推荐系统——OPPO 负责海外应用商店推荐，做东南亚六国联合建模，解决跨国家分布偏移/冷启动/弱网容灾，小国核心指标 +8-12%；②广告数据分析——熟悉程序化广告全链路（RTB/oCPM/归因/A-B）。了解百度联盟今年海外 App 广告业务与 Hybrid 模型，看好国际化出海方向。选这岗位因推荐背景+广告分析能力与需求高度匹配。"

### 5.2 对岗位的理解

核心职责围绕 DSP 业务数据分析与策略：流量变现、填充率、eCPM、收益。日常=数据监控（消耗/填充率/eCPM/竞价胜率）→ 专项分析（收入波动/填充异常/竞价变化根因）→ 策略优化（广告请求/竞价/流量分层）→ 跨团队推动落地。最核心能力="从数据中发现业务问题"（哪个媒体填充率降了、哪国 eCPM 异常、哪时段竞价胜率差）。

### 5.3 为什么选百度国际化

1. 赛道看好：2026 海外广告市场 **7200 亿美元**（占全球预算 80%），年复合增长 **12%**；百度联盟推海外 App 广告 + Hybrid 模型 + 1 亿美元扶持。
2. 技术匹配：MediaGo DSP 基于深度学习，每秒处理超 **50 万次**广告请求。
3. 经历匹配：OPPO 海外应用商店推荐，东南亚用户特征/数据挑战第一手经验可直接复用。

### 5.4 百度国际化业务功课（BP 面必展示）

- 国际事业部 2018 重组。产品矩阵：输入法 Simeji（日本累计下载超 **8400 万**，份额前三）、Facemoji（120 种语言，全球安装超 **1 亿**）；推荐平台 popln（亚洲领先原生广告，合作媒体超 **1000 家**）；广告平台 MediaGo（面向出海企业，聚合 Snapchat/Reddit 等）。
- 今年 4 月动作：海外 App 广告已接入超 **1 万家** App 广告主、覆盖 **113 个**垂直行业、海外本土直客预算占比超 **80%**；Hybrid 模型整合 Web+App 双端全域匹配；星云计划和小米/荣耀/vivo 合作纳入 OEM 厂商流量；**1 亿美元**海外专项扶持。
- 核心优势 = AI 技术 + 中国出海广告主资源 + 全球媒体流量三者结合。
- 竞争格局差异化：①中国出海广告主天然连接 ②OEM 厂商流量（星云计划，Google/Meta 覆盖不到）③AI 技术（Hybrid 全域匹配）。挑战：Google/Meta 全球份额领先，需在东南亚/中东 + OEM 流量建差异化。

### 5.5 中信银行经验迁移（回答"银行和广告有什么关系"）

"底层逻辑相通：银行定价策略 ↔ 广告出价策略（都是约束下资源分配）；客群分层建模 ↔ 受众定向（特征工程刻画用户价值）；抢夺规模归因 ↔ 收入归因（都用乘法链拆解）。中信'分期抢夺规模 3.8?亿/月'本质即'成本约束下最大化转化'，与 OCPX 广告主目标 CPA 下最大化转化是同一优化问题。"

### 5.6 广告点击率突降分析（BP 业务题四步走）

1. 确认数据口径（埋点异常/回传延迟/口径变更导致的"假下降"）。
2. 多维度下钻（时间/地域/媒体渠道/设备/iOS-Android/广告样式）。
3. 分内外部原因：内部=创意疲劳/落地页故障/出价调整/模型漂移；外部=竞品抢量/节假日/政策。
4. 制定对策 + A/B 验证。

### 5.7 职业规划（BP 稳定性，明确）

- 短期（1-2 年）：熟悉百度国际化广告业务，把海外推荐/广告商业化经验落地到填充率优化、竞价策略优化出成果。
- 中期（3-5 年）：吃透全链路（流量获取→竞价→归因→LTV），成长为能独立负责一条业务线数据分析的资深分析师。
- 转管理追问："先把专业做扎实，业务需要带团队时水到渠成。"
- 稳定性收束："这次是升级版回归——第一次刚毕业不懂，这次带海外推荐+广告分析经验回来能做的事多得多；不想再重新适应，定下来。"

### 5.9 分析师成长路径（展示稳定性与专业纵深，来自职场阶段梳理）

| 阶段 | 定位 | 能力要求 | 阶段产出 |
|---|---|---|---|
| 初级（0-2 年） | 取数 + 异动排查 | SQL 多表关联/窗口函数；统计思维（置信区间/p 值/样本量/A-B，拒绝小样本波动当结论）；业务全链路（RTB 漏斗/ID-Mapping/GAP 对账/IVT 反作弊/归因/PDB-PD-PA-RTB） | 沉淀 2-3 小专题（如《某 ADX 渠道质量诊断报告》）+ 异常排查 SOP/对账 SOP |
| 高级（2-4 年，核心跃迁） | 自己提项目 | 业务洞察（识别瓶颈）/项目设计（背景-痛点-目标-方案-风险-收益）/跨部门协同/价值闭环 | 简历 3-5 完整业务专题；可走业务策略或数据科学分支 |
| 资深（本岗目标） | 独立负责业务线 | 从看数据到带团队做决策 | 成为团队对该业务最懂的人之一 |

- 工作重点提醒（别只做取数）：异动排查/对账复盘标准化沉淀；看报表时主动记异常（哪渠道质量差、哪人群包匹配率低、哪 ADX 超时率高）——项目来源就在日常报表，不是凭空想。
- 可复用项目范式（面试可讲）：①媒体/ADX 流量质量与无效流量评估体系（CTR 偏离/到达率/设备 IP 集中度/转化后留存，分级高危中危低危，识别高危媒体 X 家、降低无效消耗 X%）；②多 ADX 边际 CPA 测算与预算分配（平均 CPA vs 边际 CPA，总预算不变最大化真实转化）；③多方数据 GAP 对账标准化（SOP+看板+差异阈值告警）；④垂类行业模型校准 CoPC 评估（分 ADX 分行业算 CoPC，识别高估低估垂类给算法团队）。
