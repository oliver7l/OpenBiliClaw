## 一、概述

- **RTB（Real-Time Bidding，实时竞价）**：用户打开 APP / 网页那一瞬间（约 100ms 内，比眨眼还快），对"这一次广告曝光"做一次线上拍卖。买的是"当下这个用户"，不是广告位。价高者拿到展示权。
- **与传统广告区别**：传统广告提前包段 / 排期，固定价格、不论谁看；RTB 每次曝光单独定价、单独竞价，把流量卖给"最想要它的人"，同时提升媒体收入与广告主 ROI。
- **oCPX**：一种"优化目标 / 出价模式"。广告主给定目标转化成本，平台自动出价。本质是媒体侧替广告主做 auto-bidding，数学与 DSP 出价完全一致。
- **SmartBid**：一套更完整的"智能竞价系统 / 策略"，不止看 CVR，还综合 CTR、CVR、用户价值、广告位、竞价环境、预算节奏，在每次 Ad Request 中实时决定"参不参加、出多少"。
- **一句话串起来**：RTB 是交易机制（谁赢得曝光），oCPX 定义"优化什么目标"（成本达标），SmartBid 解决"怎么出价"（价值最大化）。OCPX 是骨架，SmartBid 是肌肉。

### 营销方向为何重点考这些
- 营销/商业化算法岗的核心 KPI 是 ROI、CPA、ROAS、eCPM，本质都是"在预算与成本约束下，对每次曝光求出最优出价"。
- RTB 链路里的 pCTR/pCVR 预估、出价、pacing、成本控制，与你做过的推荐排序、长期价值体系、定价/额度策略同构，是可迁移主线。
- 面试官常借"你做过 RTB 吗"考察迁移能力，以及"稳定性/动机"考察职业判断——后者见第五部分 Q9–Q19。
- 准备策略：机制题讲清"为什么"（如二价 truthful、一价 shading），原理题讲清"公式+局限"（如 oCPX PID 纠偏），场景题讲清"对比"（如 OCPX 漏捕大 R vs SmartBid 溢价）。
- 表达原则：先给一句话定义，再给链路/公式，最后挂回自己的迁移经验——避免堆术语、避免虚报"做过 DSP"。

## 二、核心概念

| 概念 | 一句话解释 | 面试怎么用 |
|---|---|---|
| RTB | 每次曝光实时拍卖，~100ms 内完成，按 eCPM 排序决出胜者 | 讲清"per-impression 实时决策"，挂到端云协同/低延迟经验 |
| 媒体 / Publisher | 手握广告位的一方（APP、网站、应用商店） | 说明流量卖方视角 |
| SSP（Supply-Side Platform） | 代表媒体管理流量，接多家 AdX/DSP，设底价，优化填充与收益 | 与 DSP 对称记忆 |
| AdX（Ad Exchange） | 广告交易所，撮合 SSP 与 DSP，组织竞价（一价/二价） | 竞价发生地 |
| DSP（Demand-Side Platform） | 代表广告主参与竞价：人群定向、估价、出价、预算控制 | 你经验同构的核心模块（pCTR/pCVR/出价/pacing） |
| DMP / CDP | 数据平台，输出用户画像、标签、设备数据，支持定向与估价 | 提"画像+特征"即可 |
| TD（Trading Desk） | 代理商/广告主操作台，不参与竞价，通过 API 调多家 DSP（Report、Operation 两类 API） | 说明它不直接 bidding |
| eCPM | 期望每千次曝光收益 = bid × pCTR（× pCVR），排序依据 | 排序目标的统一货币 |
| oCPC / oCPM | 优化目标为转化/激活的计费模式，按目标 CPA 自动调价 | 出价 = 目标CPA × pCVR |
| SmartBid | 价值导向智能出价，差异化"千面千价"，敢为高 LTV 用户溢价 | "骨架 vs 肌肉""成本可控 vs 价值最大化" |
| 一价拍卖 | 赢家按自己的出价支付，真实出价非占优，需 bid shading | 讲赢者诅咒 + shading |
| 二价拍卖 | 赢家付第二高价（或 +0.01），真实出价占优 | Vickrey 定理、truthful bidding |
| GSP（广义二价） | 多坑位场景，第 k 名支付第 k+1 名价格 | 多广告位排序 |
| bid shading | 一价下依"竞得价分布"压价，最大化期望盈余 | DSP 标配能力 |
| Budget Pacing | 控制广告主预算在时段内平滑消耗 | 广告 vs 推荐的关键约束之一 |
| 延迟反馈 | 转化（激活/付费）非点击即发生，标签不完整致模型低估 | 延迟建模 / surrogate / IPW |

## 三、机制与流程

### 3.1 RTB 全链路（一次曝光）

1. 用户打开 APP / 网页，页面加载，触发广告位。
2. 媒体 → SSP，把广告位尺寸、设备 IP、匿名用户 ID、底价传给 AdX，生成一次竞价请求 **BidRequest**。
3. AdX 把竞价请求广播发给所有接入的 DSP，附带用户、设备、页面信息。
4. **DSP 内部处理**（通常 < 50ms，有严格超时，一般 100ms，超时判弃权）：
   - 查 DMP 拿用户画像；
   - 匹配定向条件（地域、年龄、兴趣、预算剩余）；
   - 模型预估 CTR / CVR，算出这次曝光愿意出多少；
   - 匹配不上不返回出价，匹配上返回 BidResponse（出价 + 广告素材地址）。
5. AdX 收集各家出价，执行拍卖（大多二价：最高者赢，实际付第二高价）。
6. AdX 把赢家广告下发回 SSP → 媒体页面，广告展示给用户。
7. 曝光、点击、转化事件经监测回传给 DSP / DMP，用于训练模型、优化下一轮出价。

> 全部在页面加载完成前做完，用户无感知。整个过程是 per-impression 实时决策，对延迟、特征实时性、模型推理效率要求极高——可与端云协同、模型压缩经验挂钩。

### 3.2 一价 vs 二价

**二价（Second Price / VCG / GSP）**
- 最高价者赢，但支付第二高价（或第二高价 + 0.01）。
- 真实出价是占优策略（Vickrey 定理）：出多少只影响"赢不赢"，不影响"付多少"，故最优即按真实价值 v 出价。
- 多坑位用 GSP：第 k 名支付第 k+1 名的价格。

**一价（First Price）**
- 赢家按自己的出价支付。
- 真实出价不再最优，出太高会"赢者诅咒"。
- 出现 **bid shading**（出价压价）：依据对"竞得价分布"的估计，把出价压到"赢的概率 × 盈余"最优的点。
- 近年行业（尤其 header bidding 后）普遍转向一价，shading 成为 DSP 标配能力。

**面试常问**
- Q：二价下最优出价？A：按真实价值 v 出价（truthful bidding）。
- Q：一价下怎么出？A：建模赢率曲线 w(b)，最大化期望盈余 E[(v−b)·w(b)]，或用历史竞得价分布做 shading。

### 3.3 oCPC / oCPM 原理

- 广告主设目标 CPA（如 100 元），平台按用户转化概率动态调整 CPC。
- 粗略公式：`Bid = 目标CPA × pCVR`
  - 用户 A 预测转化率 10% → 可高价买；
  - 用户 B 预测转化率 1% → 少出钱甚至不买。
- **核心不在"限制每一次都不超"，而在动态纠偏**：发现近期单次转化成本偏高（如最近 10 个转化均值到 60 元、超目标 50 元），OCPX 的 PID 控制器启动：
  1. 降权：判定流量太贵/转化太差，自动降低出价系数甚至暂停；
  2. 提门槛：提高转化概率门槛，只许最准的用户通过，把均值拉回目标。
- 口述话术："OCPX 单次'出价'通常有硬上限（≤ 目标 CPA）防风险；但单次'转化成本'因概率波动与预估偏差允许超目标，系统靠长期统计回归控整体成本。"

### 3.4 SmartBid 类智能出价原理

- 广告主设目标（如注册 ≤ $20 / CPA / ROAS / Leads / Purchase）。
- 系统预测：用户会不会点击？会不会转化？广告位值不值得买？→ 自动实时出价，尽量把预算买到更易转化的人群。
- 一次 Ad Request 的简化决策：

```
Expected Value = P(click) × P(conversion|click) × Conversion Value
Bid           = Expected Value × Advertiser Target × Optimization Factor
```

- 实际 `Bid = f(pCTR, pCVR, Value, Budget, Pacing, Competition, Auction Context, Frequency, Exploration)`。
- **与 oCPX 的本质区别**：oCPX 偏"成本可控"（让均值=目标，保守，易漏捕高价值流量）；SmartBid 偏"价值最大化"，引入 LTV / 边际收益，做差异化出价（千面千价），敢为高价值用户出高于目标 CPA 的价。
- **相比普通 target CPA bidding**：SmartBid 同时解决 value estimation、auction optimization、budget pacing、exploration-exploitation；Open Web 流量异质性极高，同一广告主对不同 Publisher/Placement/用户的最优 Bid 差异极大。

### 3.5 指标归因拆解（Delta / LDMI / BWD）

| 指标类型 | 例子 | 方法 |
|---|---|---|
| 加法型 | 收入 = 行业A + 行业B + 行业C | Delta 法（直接可加） |
| 乘法型 | 收入 = 请求 × 填充 × eCPM | LDMI 法（对数分解） |
| 比率型 | 变现率 = Σ(各组变现率 × 各组占比) | 组间组内拆解（BWD） |

- **Delta 法**：`ΔY = ΣΔXᵢ`，贡献度ᵢ = ΔXᵢ / ΔY × 100%（各维度贡献度加和=100%）。
- **LDMI 法（对数平均迪氏指数）**：`贡献度ᵢ = (ln Xᵢ' − ln Xᵢ) / (ln Y' − ln Y)`。乘法关系下小变化百分比近似可加（ln(1+x)≈x），LDMI 保证精确可加，避免"多项同变说不清谁贡献"。

### 3.6 MediaGo 生态与平台定位

MediaGo 是百度国际旗下智能广告平台，核心产品 SmartBid 系列（以 3.0 为代表）主打缩短冷启动、稳成本。其定位更接近 **Taboola / Outbrain / The Trade Desk / DV360** 这类程序化/开放网络（Open Web）体系，强调效果广告与 CPC/智能出价。

| 平台 | 核心流量来源 |
|---|---|
| Meta | Facebook、Instagram |
| Google | Search、YouTube、Google Display 等 |
| TikTok | TikTok |
| MediaGo | Open Web：大量第三方网站、App、媒体流量 |
| Taboola / Outbrain | 新闻、内容媒体原生广告 |

- **商业模式**：以效果导向、主要 CPC 计费为主；官方称用深度学习做实时转化预测、广告位价值评估、智能竞价。
- **三大行业难题解法**：冷启动低效、扩量成本失控、投放稳定性不足。
- **核心卖点链路**：广告主设定目标（如注册 ≤ $20）→ MediaGo 分析大量广告位 → 预测（点不点、转不转、广告位值不值）→ 自动实时出价 → 把预算买到更易转化的人群。

**实战案例**
- 电商：CVR +42.9%，CPA −35.3%。
- 线索类（Peak Performance Advertising，"最大转化模式"）：一个月内转化量 +280%，成本稳在目标内。
- 全球数字营销：保持 ROAS 稳定前提下，投放规模 +111%。

### 3.7 延迟反馈四层建模（游戏/应用分发高频硬题）

转化（激活、付费、注册）非点击后立刻发生，延迟导致"标签不完整 → 模型低估 → 评估失真"。按"问题本质 → 建模层 → 评估层 → 校准闭环"四层处理。

**延迟表现**
| 环节 | 延迟表现 | 后果 |
|---|---|---|
| 点击→激活 | 点了下载几小时后才打开激活 | 当天算 CTR/CVR 会低估 |
| 激活→付费 | 可能几天后才首充 | LTV 标签不成熟 |
| 曝光→转化归因 | 归因窗口内转化才计入 | 窗口外转化丢失 |

**建模层解法（让模型"等得起/猜得准"）**
1. **延迟转化建模（Delay Feedback Model）**：把"转化"拆成 `p(转化|点击) × p(在 t 前被观测|转化)`；前者是真实转化率（想学的），后者是延迟分布（用指数/对数正态建模）；对"点击后还没转化"的样本不直接当负样本，而按"还有多大可能转化"加权——越新样本越不当负样本。关键：不是"没转化=负例"，而是"还没到时间=不确定"。
2. **重要性加权 / 逆延迟加权（IPW）**：估计延迟分布 `F(t)=P(转化在 t 前被观测)`，对已观测正样本按 `1/F(t)` 加权，补偿未观测正样本；优点简单，缺点延迟分布估不准时方差大。
3. **两阶段（Surrogate）**：先估短期强相关代理指标（D1 留存、D1 时长、首关卡通过、点击后 5 分钟行为），用历史学"代理→长期转化"映射；本质把长延迟转短延迟。
4. **多任务/多窗口联合建模**：同时训"即时转化/D1/D7"多头共享表征，短窗口标签成熟快、帮长窗口头学稳，新样本先用短窗口头出分、长窗口成熟后接管。

**评估层 / 校准层**
- 归因窗口明确化；转化类指标等标签成熟再下结论；留长期对照组观察延迟效应；不可分流时用前后对比 + 趋势剔除。
- 实时 PCOC 只作预警，成熟数据才算校准；监控延迟分布漂移，触发重训。
- 工程兜底：标签回填 + 滚动重训。

### 3.8 指标归因完整算例

**加法型（Delta 法）**：收入跌 100 万，维度贡献度加和=100%。
| 维度 | 变化 | 贡献度 |
|---|---|---|
| 行业A | −80万 | 80%（主因） |
| 行业B | −30万 | 30% |
| 行业C | +10万 | −10%（对冲） |

**乘法型（LDMI 法）**：收入 = 请求 × 填充 × eCPM，设 Y'/Y=0.90（ln0.90=−0.1054）。
| 因子 | X'/X | ln变化 | 贡献度 |
|---|---|---|---|
| 请求(RE) | 0.98 | −0.0202 | 19% |
| 填充率 | 0.97 | −0.0305 | 29% |
| eCPM | 0.95 | −0.0513 | 49% |
| 合计 | 0.90 | −0.1054 | 100% |

> 校验：0.98×0.97×0.95≈0.903；对数差和 −0.1020 与 −0.1054 之差为交叉项量级，小变化时可忽略或均摊。注意"贡献度=自身变化率/总变化率"只在小变化时近似成立（5%/10.5%≈48%），大变化必须用对数算。

### 3.9 oCPX 与 SmartBid 完整对比

| 维度 | oCPC / oCPX | SmartBid |
|---|---|---|
| 核心目标 | 控制 CPA、获取转化 | 综合预测价值并智能出价 |
| 优化对象 | 转化概率 | 点击、转化、价值、竞争等 |
| 输入 | 用户是否易转化 | 用户+广告位+素材+上下文+竞价环境 |
| 出价方式 | 围绕目标 CPA 自动调价 | 每次请求动态计算最优 Bid |
| 关注重点 | 拿到转化 | 规模、成本、ROI 间优化 |
| 局限 | 偏保守，易放弃高价值高成本流量、跑量难 | — |
| 进阶 | — | 引入 LTV/边际收益，差异化出价（千面千价） |

**一句话金句**："OCPX 是骨架，定义成本目标；SmartBid 是肌肉，决定具体出价。普通 OCPX 让成本'及格'易漏捕高价值流量；SmartBid 结合价值模型，敢在优质流量上溢价，追求预算约束下全局收益最大化。"

### 3.10 抗压追问防守库（可直接口述）

- **Q：抗压能力怎么样？** "我的抗压不是'硬打'而是'拆解'。压力大时不逼自己'顶住'，而是把问题拆开、找到可行动部分先做，压力就从情绪变成任务清单，处理就稳定了。"
- **Q：压力大到影响工作的时候？** "坦白说 OPPO 刚接手时确有两天适应期——多方博弈、时间紧、还要出结果。但我很快用结构化方式拆开，没让情绪影响产出。偶尔波动正常，关键是能很快调整回来。"
- **Q：压力来自领导/业务方催？** "先理解真实诉求——通常催的不是'你慢'，而是'他不确定进展'。所以主动同步进展和卡点给预期；合理时间压力就拆解、先交付核心；不合理要求就把约束摆出来让对方取舍，而不是自己硬扛。"
- **Q：下班后怎么释放？** "运动，跑步或散步，让脑子切出工作模式。结构化拆解后，能做的做了、不能做的交出去了，就不一直想。"

| 会不会失控 | "先做能做的、主动拉齐"，不闷头不独扛 | 可控 |
| 会不会硬撑崩 | "不追求超常发挥，保证不变形" | 务实 |
| 有没有实例 | OPPO 多方冲突一句话带过 | 有但不喧宾 |

### 3.11 RTB 与 OCPX 的关系（串讲）

- RTB 是**交易机制**：解决"这次曝光卖给谁、多少钱"——拍卖、排序、结算。
- OCPX 是**计费/优化模式**：广告主给目标转化成本，平台自动出价。
- 本质上 OCPX 就是媒体侧替广告主做 auto-bidding，数学与 DSP 出价完全一样：`bid = tCPA × pCTR × pCVR / (1+λ)`，λ 把实际成本控在目标 CPA 附近。
- 口述："OCPX 可理解为平台内置了一个 DSP：它做 pCTR/pCVR 预估、出价、pacing 和成本控制，只是竞价发生在平台内部 eCPM 排序里。"

### 3.12 一次 Ad Request 的出价决策信息流

```
Ad Request
   │
   ├─> CTR 预测 ─┐
   ├─> CVR 预测 ─┤
   ├─> 价值预测  ─┤
   ├─> Budget / Pacing
   ├─> Auction Context（竞价环境）
   │
   └─> SmartBid 综合 ──> Final Bid = f(pCTR, pCVR, Value, Budget, Pacing, Competition)
```

> 出价前还需综合：Auction Price、Budget、Pacing、Frequency、Advertiser Goal、Exploration。最终 Expected Value ≈ pCTR × pCVR × ConversionValue，再叠加广告主目标与优化因子。

### 3.13 bid shading 与一价行业背景

- 一价下赢家付自身出价，真实价值 v 不再占优，过高出价触发"赢者诅咒"（winner's curse）。
- bid shading：估"竞得价分布"，把出价压到 `argmax_b E[(v−b)·w(b)]`（w(b) 为赢率曲线）。
- 行业背景：header bidding 普及后，AdX 普遍从二价切一价，shading 成为 DSP 标配——面试可主动提到"我们 DSP 要有 shading 能力"。

### 3.14 二面速记清单（进场前扫一遍）

1. RTB = 每次曝光 ~100ms 拍卖，按 eCPM 排序，买"当下这个用户"。
2. 角色链：媒体 → SSP → AdX → DSP（← DMP 画像）→ 展示 → 事件回流。
3. 二价：付第二高价，truthful bidding 占优；一价：付自己出价，需 bid shading。
4. GSP：第 k 名付第 k+1 名；header bidding 后行业转一价。
5. eCPM = bid × pCTR × pCVR；排序统一货币。
6. oCPC 出价 = 目标CPA × pCVR；OCPX 是平台内置 DSP。
7. SmartBid = 价值导向、千面千价、敢为高 LTV 用户溢价；bid = f(pCTR,pCVR,Value,Budget,Pacing,Competition)。
8. OCPX 控成本用 PID 纠偏：降权 + 提门槛；单次出价有硬上限，单成本允许波动。
9. 指标归因：加法 Delta、乘法 LDMI（对数）、比率 BWD。
10. 延迟反馈：不把"没转化"当负例，用延迟分布 + surrogate（D1 留存等）+ IPW(1/F(t)) + 回填重训。

12. 没做过外部 DSP 也能答：百度 eCPM 排序、OPPO pCTR 校准 + 长期价值、中信约束下出价，均同构。
13. 稳定性话术：主线是推荐/广告一条线 + 一次有目的拓展（补金融），回贵司=稳定信号。
14. 抗压话术：压力要"拆"不是"打"——结构化→先做能做的→主动拉齐。

## 四、公式汇总

| 公式 | 含义 |
|---|---|
| `eCPM = bid × pCTR × pCVR` | 排序依据（二价/一价均按 eCPM 排序） |
| `Bid(oCPC) = 目标CPA × pCVR` | 按目标转化成本出价（CPC 制） |
| `bid = tCPA × pCTR × pCVR / (1+λ)` | OCPX 自动出价，λ 把实际成本控在目标 CPA 附近 |
| `Expected Value = P(click) × P(conversion\|click) × Conversion Value` | 单次曝光期望价值 |
| `Bid = Expected Value × Advertiser Target × Optimization Factor` | SmartBid 简化出价 |
| `Bid = f(pCTR, pCVR, Value, Budget, Pacing, Competition)` | 完整智能出价函数 |
| 一价期望盈余 `E[(v−b)·w(b)]` | 建模赢率曲线 w(b) 求最优出价 |
| 二价 `pay = price₂ (+0.01)` | 赢家付第二高价 |
| GSP `pay_k = price_{k+1}` | 第 k 名付第 k+1 名 |
| `贡献度ᵢ = ΔXᵢ / ΔY × 100%` | Delta 法（加法型） |
| `贡献度ᵢ = (ln Xᵢ' − ln Xᵢ) / (ln Y' − ln Y)` | LDMI 法（乘法型） |
| `p(转化\|点击) × p(在 t 前被观测\|转化)` | 延迟转化建模（拆真实转化×观测概率） |
| IPW 权重 `1 / F(t)` | 逆延迟加权，补偿未观测正样本（F(t)=P(转化在 t 前被观测)） |

## 五、面试 Q&A（可直接口述）

### Q1. RTB 是什么？一次请求怎么走完？
"每次用户曝光机会出现时，广告系统在约 100ms 内完成一次拍卖：多个广告主通过 DSP 实时出价，按 eCPM 排序获得展示。和传统包段不同，RTB 按每次曝光单独定价竞价，把流量卖给最想要它的人。链路是：用户打开页面 → 媒体/SSP 发 BidRequest 给 AdX → AdX 广播给各 DSP → DSP 做定向、pCTR/pCVR 预估、算出价（<50ms，超 100ms 判弃权）→ AdX 按 eCPM 排序拍卖 → 胜者下发展示 → 事件回流训练模型。整条是 per-impression 实时决策，对延迟和推理效率要求极高。"

### Q2. 一价和二价区别？最优出价策略？
"二价下最高者赢但付第二高价，真实出价是占优策略——按真实价值 v 出价即可，因为出多少只影响赢不赢、不影响付多少。一价下赢家付自己出价，真实出价会赢者诅咒，所以要 bid shading：建模赢率曲线 w(b)，最大化期望盈余 E[(v−b)·w(b)]，或用历史竞得价分布压价。近年 header bidding 后行业普遍转一价，shading 是 DSP 标配。"

### Q3. oCPX 和 SmartBid 什么关系？
"我理解 oCPX 更偏向面向广告主的效果优化和出价模式，核心是依预测转化概率动态调 CPC 以达到目标 CPA；SmartBid 更像底层/平台级智能竞价能力，不只看 CVR，还综合 CTR、CVR、用户价值、广告位、竞价环境、预算节奏，在每次 Ad Request 实时决定参不参与、出多少。关系上：oCPX 定义'优化什么目标'，SmartBid 解决'怎么出价'。一句话——OCPX 是骨架（成本目标），SmartBid 是肌肉（具体出价）。"

### Q4. SmartBid 和普通 target CPA bidding 本质区别？
"Target CPA 多在成本约束下最大化转化；更完整的 SmartBid 要同时解决 value estimation、auction optimization、budget pacing、exploration-exploitation。尤其 Open Web 流量异质性高，同一广告主对不同 Publisher、Placement、用户的最优 Bid 差异极大，所以必须价值建模而非固定出价。"

### Q5. 为什么普通 OCPX 会漏掉高价值流量？（场景题）
"假设目标 CPA 50 元，来个大 R 用户，系统预测转化率高，算该出 80 元才能拿下；但 OCPX 一看'目标才 50，出 80 太贵会超成本触发风控'，于是出 50、竞拍失败、错失大 R。SmartBid 通过历史知道这类用户首充成本高但 LTV 极高（未来充 1 万），逻辑是'为抢金主愿出 100 元'，结果竞拍成功、赢得高价值用户。这就是成本可控 vs 价值最大化。"

### Q6. OCPX 为什么有时会超成本？怎么处理？
"两类原因：一是转化概率预估偏差，模型低估难度，按 pCVR 出价后实际多次点击才转化，单成本被拉到 80；二是二价机制下，激烈流量里系统顶格出价，结算价仍可能接近甚至略超目标。处理上 OCPX 靠动态纠偏：发现近期单成本偏高就启动 PID 控制——降权（降出价系数/暂停）、提门槛（只许最准用户过），把均值拉回目标。单次出价有硬上限防风险，单次成本允许波动，靠长期统计回归控整体。"

### Q7. 推荐算法和广告算法异同？
"底层共通：都要做 CTR/CVR 用户行为预测，涉及特征工程、排序、多目标优化。但广告多几个核心约束：一是 Auction，不同广告主实时竞争；二是 Bid，要把预测价值转成实际出价；三是 Budget Pacing，控广告主预算消耗；四是广告主 ROI/CPA 约束，不能只优化 CTR/CVR。换句话说，广告除排序还要解决'值不值得买、买多少、预算怎么分'。"

### Q8. 延迟反馈（激活/付费非点击即发生）怎么处理？
"我分三层。建模层：不把'点击后没转化'直接当负样本，用延迟分布建模——拆成'真实转化率 × 观测概率'，对未成熟样本按还有多大可能转化加权；同时用短期代理指标（D1 留存、首充前行为）做 surrogate，把长延迟转短延迟。评估层：归因窗口明确化，转化类指标等标签成熟再下结论，留长期对照组。校准层：实时 PCOC 只作预警，成熟数据才校准，监控延迟分布漂移触发重训。我在 OPPO 游戏分发里付费延迟是天级的，主要用 surrogate + 长周期实验 + 回填重训组合，保证模型和实验不被延迟骗。"

### Q9. 你怎么把过往经验接到 RTB 上？（没做过外部 DSP 也能答）
"我没有直接做过外部 RTB DSP，但经验和 RTB 核心模块高度同构：第一，在百度做应用商店推荐和搜索排序，核心指标就是 eCPM，和广告排序目标一致；第二，在 OPPO 做 CTR 预估校准、分发结构校准和长期价值体系，对应 RTB 的 pCTR 校准、机制策略和 value 建模；第三，在中信做定价/额度策略，本质是在成本和风险约束下给出价，和 DSP 的 constrained bidding、pacing 是同一类优化问题。所以预估、出价、机制、成本控制几块我都有可迁移经验。"

### Q21. 常见概念混淆速辨（防口误）

- **eCPM vs bid**：eCPM 是排序分（= bid × pCTR × pCVR），bid 是 DSP 愿意付的钱；二价下实付 ≠ bid。
- **oCPC vs oCPM**：前者优化点击后转化成本（CPC 计费），后者优化千次展示转化成本（CPM 计费）；oCPX 是统称。
- **SmartBid vs target CPA**：前者多解 value/auction/pacing/exploration，后者只控成本最大化转化。
- **一价 vs 二价**：付自己出价 vs 付第二高价；前者需 shading，后者 truthful 占优。
- **GSP vs VCG**：GSP 是第 k 名付第 k+1 名（实用），VCG 按边际贡献计价（理论最优）。
- **IPW vs surrogate**：IPW 用 1/F(t) 加权补偿未观测正样本；surrogate 用短期代理指标绕过长延迟。
- **Delta vs LDMI**：加法指标用 Delta（ΔXᵢ/ΔY），乘法指标用 LDMI（对数差比）。
- **pacing vs bid shading**：pacing 控预算时段平滑，shading 控一价下出价不亏。
