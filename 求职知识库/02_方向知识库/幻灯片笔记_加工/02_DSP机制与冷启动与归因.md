## 一、概述

程序化广告的本质：**把每一次广告展示的买卖决策，交给算法在毫秒级完成**。数据分析岗在其中的产出不是"直接创造收入"，而是：

- **决策依据**：让业务方知道"为什么跌 / 该放量还是回滚"
- **问题预警**：让异常第一时间被发现，而非月度才察觉
- **效率提升**：让口径统一、策略更快落地

> 一句话：**你的产出 = 决策依据 + 问题预警 + 效率提升**。这是数据分析岗安身立命的根本。

### 数据分析的 6 大类产出

| 类别 | 具体产出 | 频率 |
|---|---|---|
| 1 监控类 | 日报/周报/月报、核心看板、异常告警 | 周期性，固定交付 |
| 2 归因类 | 收入波动归因、指标异动分析、策略效果评估 | 按需，业务方提需求 |
| 3 实验类 | 实验设计方案、实验报告、A/B 评估结论 | 跟着策略迭代走 |
| 4 专题类 | 客群分析、行业分析、流失分析、预算分析 | 季度级，主动发起 |
| 5 模型/工具类 | 预测模型、自动化脚本、取数工具 | 按需 |
| 6 基建类 | 指标口径文档、数据质量治理、方法论文档 | 长期沉淀 |

### 做到什么程度算"够"（三档标准）

| 层级 | 标准 | 说明 |
|---|---|---|
| 及格线（不被淘汰） | 按时交付 / 质量合格 / 响应及时 | 报表按时出、数据准确口径清、需求响应不拖延 |
| 正常水平（稳定产出） | 主动发现问题 / 给出建议 / 被采纳被引用 | 不等业务方，自己发现"指标不对劲"并同步，归因后给"可试 A 或 B" |
| 进阶（被信任） | 每周稳定交付 + 每月 1–2 个主动发现 + 每季度 1 个沉淀 + 每年某方向"来问我就行" | "稳定、可靠、不会被轻易替代" |

## 二、核心概念表

### 2.1 程序化交易谱系（是否保量 × 是否竞价）

| 模式 | 是否预留 | 是否竞价 | 关系 | 适用场景 | 记忆口诀 |
|---|---|---|---|---|---|
| **PDB** 程序化直投 | 预留（保量） | 定价 | 一对一 | 大广告主跨媒体频控、子产品流量分配 | "包场" |
| **PD** 优选 | 非预留 | 定价 | 一对一 | 优质广告主挑流量、不愿竞价 | "VIP 优先" |
| **PMP** 私有市场 | 非预留 | 竞价（邀请制） | 一对少 | 优质媒体保护流量、兼顾质量控制与变现 | "会员制拍卖" |
| **公开 RTB** | 非预留 | 竞价 | 公开 | 长尾媒体、效果广告主 | "公开菜市场" |

> 高维区分：**合约广告（PDB 等）不竞价、提前锁定**；**竞价广告（RTB）实时竞价、价高者得**。RTB 内部再分 **瀑布流（Waterfall，串行依次询价）** 与 **Header Bidding（并行同时询价）**，二者跑的都是 RTB 机制，区别只在"竞价请求怎么发出去"。

### 2.2 四方角色（必背）

| 角色 | 代表谁 | 一句话 | 面试类比 |
|---|---|---|---|
| **DSP** | 广告主 | 拿着预算全网自动买最合适流量 | 广告主的"AI 采购员" |
| **SSP** | 媒体 | 帮媒体把广告位卖给最高价买家 | 媒体的"自动收银台" |
| **Ad Exchange** | 交易所 | DSP 与 SSP 碰面竞价的地方 | 广告位的"证券交易所" |
| **DMP** | 数据 | 收集用户数据、打标签让投放更准 | 用户的"档案室" |

> 面试话术（老王找对象版）：老王（广告主）找 AI 助手（DSP），在相亲大会（Ad Exchange）上看到公园大妈（SSP）有个空位，查了姑娘资料（DMP），出价中标，广告展示——全程 100 毫秒搞定。

### 2.3 第一价格 vs 第二价格（GSP）

| 维度 | 第一价格 | 第二价格（GSP） |
|---|---|---|
| 赢家付多少 | 付自己的出价 | 付第二高的出价 |
| 出价策略 | 需压价博弈（Bid Shading） | 出真实估值即可 |
| 透明度 | 高（付即所出） | 低（付非所出） |
| 复杂度 | 高（多层时仍清晰） | 高（多层嵌套时口径混乱） |
| 价格稳定性 | 低（每次不同，但市场成熟后收敛） | 高（锚定第二名） |
| 对平台收入 | 可预测、且理论更高 | 收入不稳定（多层下更差） |
| 当前状态 | 程序化展示广告主流 | 搜索广告仍用 |

### 2.4 oCPC vs oCPM

| 维度 | oCPC | oCPM |
|---|---|---|
| 计费 | 按点击计费 | 按曝光计费 |
| 出价对象 | 每次点击出多少 | 每次曝光出多少 |
| 公式 | 出价 = pCVR × 目标CPA | 出价 = pCTR × pCVR × 目标CPA × 1000 |
| 广告主风险 | 低（没点击不花钱） | 较高（曝光就花钱，不管点击） |
| 平台风险 | 较高（点了没转化收不到钱） | 较低（曝光即收钱） |
| 主流趋势 | 逐渐被 oCPM 取代 | 目前国内信息流绝对主流 |

### 2.5 第一方 DMP vs 第三方 DMP

| 项目 | 第一方 DMP | 第三方 DMP（Data Exchange） |
|---|---|---|
| 数据所有权 | 归广告主/媒体客户 | 归 DMP 平台 |
| 商业模式 | 提供加工托管服务，不卖数据 | 加工标签、对外售卖数据盈利 |
| 数据来源 | 客户自己的网站、CRM | 全网多方采购外部数据源 |
| 典型用途 | 重定向、生成 Look-alike 种子人群、扩量 | 买通用兴趣标签 |
| 数据质量 | 高（自家真实访客） | 参差不齐、不可控 |

> 挖坑点：狭义 DMP = 第一方 DMP；第三方 DMP 实为数据交易平台。

### 2.6 流量侧 vs 行业侧（面试官重点痛点）

| 维度 | 流量侧 | 行业侧 |
|---|---|---|
| 视角 | 广告平台 / DSP / 流量本身 | 广告主垂直行业、生意模式 |
| 看的数据 | CTR、CVR、CPA、CPM、填充率 | LTV、付费、复购、线索质量、退保率 |
| 解决什么问题 | 消耗跑不动？成本为何涨？哪些媒体差？ | ROAS 达标为何生意不赚钱？预算怎么配生意目标？ |
| 产出物 | 出价/定向/媒体黑名单等投放调整 | 行业投放策略、素材方向、全链路根因诊断 |
| 局限 | 看平台指标，缺行业经验 | 需懂行业业务，对客户行业经验要求高 |

> 面试官原话翻译："流量侧基础 OK（RTB、DSP、指标、排查你都能搞）；但行业侧不足——拿到数据更多站 MediaGo 平台流量角度，缺广告主生意视角，不太能结合行业商业模式、后端真实业务指标输出面向客户的完整策略。"

## 三、关键机制

### 3.1 程序化广告谱系与 DSP 角色

**全景链路（用户打开页面 → 看到广告，全程 < 100ms）**

```
广告主侧           平台/媒体侧
 MKT-API ──创建/管理──▶ 广告平台（百度营销/百青藤）
 (营销API) ◀──报表/数据──┘
                         │
                   SSP 发起 + DSP 出价（RTB 实时竞价，毫秒级）
                   选最高价赢得展示
                         │
                  （若广告主接入 RTA）
                         ▼
                  RTA 实时决策接口（毫秒级）
                  平台调广告主服务器：投不投？出多少钱？
```

**MKT-API / RTB / RTA 三者关系（不在同一层）**

| 维度 | MKT-API | RTB | RTA |
|---|---|---|---|
| 层次 | 管理层 | 交易层 | 决策层 |
| 解决什么 | 怎么创建/管理广告 | 展示机会怎么买卖 | 广告主怎么实时参与决策 |
| 时间维度 | 离线/准实时 | 毫秒级 | 毫秒级 |
| 调用频率 | 低频（每天/每小时批量） | 高频（每次展示） | 高频（每次展示） |
| 谁调谁 | 广告主 ↔ 平台 | 平台内部（SSP↔DSP） | 平台 → 广告主 |
| 数据方向 | 双向 | 平台传递竞价请求/结果 | 全双向 |

> 一句话：**MKT-API 是管理工具，RTB 是交易机制，RTA 是决策增强**。

**Ad Exchange 的收入模式**

- `Ad Exchange 收入 = 交易额 × 抽成比例（通常 5%–20%）`
- 百度的"百青藤"即承担 Ad Exchange 角色（连接外部媒体供给）
- 对你工作的意义：
  - **填充率**（多少请求成功匹配到广告）直接影响收入
  - **竞价深度**（每次竞价有几个 DSP 参与）影响价格水平
  - 收入归因时，"填充率下降"和"竞价深度下降"是**两个不同的根因**

**DSP 的核心决策链**

```
收到竞价请求
  → 这个用户我认不认识？（Cookie 映射 / ID-Mapping）
  → 认识 → 这个用户值多少？（pCTR / pCVR 预估）
  → 该出多少钱？（出价策略）
  → 出价 → 赢了展示，没赢放弃
```

**出价和定价过程的角色分工**

| 角色 | 做什么 |
|---|---|
| DSP | 决定"出多少"（基于预估 + 策略） |
| Ad Exchange | 决定"谁赢、付多少"（基于拍卖规则） |
| SSP | 决定"要不要参与"（底价 Floor Price 过滤） |

**竞价与流量分析核心模块**

| 模块 | 核心问题 | 关键指标 |
|---|---|---|
| 竞价与流量分析 | 为什么某些 request 没赢？ | Win Rate、Bid Density、Fill Rate（原文 OCR 为数字串，存疑）、eCPM、Floor Price 命中率 |
| 流量质量治理 | 流量是不是假的？ | 异常点击率、SDK 伪造率、IP/DeviceID 聚类、留存衰减曲线 |
| 转化归因 | 钱花在哪带来真实用户？ | 安装归因、LTV 回传、MMP 对齐（AppsFlyer/Adjust） |
| 创意效能 | 哪个素材跑得动？ | CTR、CVR、素材疲劳度、视频完播率 |
| ROI / 预算分配 | 钱该往哪拨？ | ROAS、Payback Period、分国家/分渠道 CPA |
| 异常监控 | 投放是否出问题？ | 实时掉量告警、预算燃烧速率、CTR 突变检测 |

**流量质量治理（聚合平台假量排查要点）**

- 设备维度聚类（同一 DeviceID/IP 短时间高频）
- 点击-安装时间窗分布异常（<1 秒或过长都可疑）
- 留存对比：正常渠道 D7 留存曲线 vs 可疑渠道断崖式下跌
- 建立黑名单 + 评分卡，回灌竞价环节做屏蔽

**分维度 ROI 优化**

- 按「国家 × 媒体 × 创意」三维切片算真实 ROAS（必须用回传的 LTV，不是安装数）
- 用**边际 ROI 递减逻辑**做预算再分配（从 ROAS 已饱和渠道挪到上升期渠道）
- 游戏类重点看 D7/D30 ROAS；工具类看留存 + 广告变现回收

**实时监控与告警**

- 投放量、spend 燃烧速率、CTR 实时看板
- 设置同比/环比突变告警（如某渠道 CTR 半小时内掉 30%）
- 归因窗口延迟补偿：SKAdNetwork 有 24–72h 延迟，看板要标注"数据未完整"

**技术栈建议（实战可用）**

| 层 | 选型 |
|---|---|
| 数仓 | BigQuery / ClickHouse（竞价日志量大，ClickHouse 性价比高） |
| BI | Metabase / Superset 自助看板，Tableau 给客户汇报 |
| 归因 | 自研 + MMP 双轨，SKAN 用 Adjust/AppsFlyer 聚合端点 |
| 特征工程 | 用户行为序列、设备指纹、渠道质量分 |
| 建模 | 出价模型（CTR/CVR 预估，GBDT/DeepFM）、LTV 预测、异常检测（Isolation Forest） |

**算法/技术深挖方向（按岗位取舍）**

| 方向 | 学什么 | 来源 |
|---|---|---|
| 竞价机制 | GSP/VCG 拍卖、出价策略、pacing | 《计算广告》+ 论文 |
| 预估模型 | pCTR/pCVR 建模、校准、冷启动 | 内部文档 + KDD/RecSys |
| 归因 | 多触点归因、增量归因、因果推断 | 论文 + 内部实践 |
| 实验设计 | A/B、A/A、RAB、DID | 内部实验平台 + 统计教材 |
| 用户画像/定向 | DMP、look-alike、RTA | 内部系统 + 行业文章 |

> 针对"实验评估 + 收入归因"方向，重点补 **归因、实验设计、竞价机制** 三块。

### 3.2 第一价格 vs 第二价格（含 Bid Shading）

**传统 RTB（第二价格可行）**：一个 Ad Exchange + 多个 DSP 竞价，Exchange 内部用二价定价，结构简单、激励相容成立。

**Header Bidding 时代（第二价格出问题）**：同一时间多个需求方（SSP-A 内部竞价返回一价、SSP-B 内部竞价返回一价、DSP-C/D 直接出价），媒体层面这些"价格"口径不一致、无法直接比较 → 定价混乱、收入反而更不稳定。

**第一价格催生 Bid Shading（出价压缩）**

| 维度 | 说明 |
|---|---|
| 是什么 | 在第一价格拍卖中，DSP 预估"刚好能赢的最低价"，出那个价而非真实估值 |
| 为什么需要 | 第一价格下出多少付多少，出高多花钱 |
| 技术难点 | 要预估"竞争对手会出多少"——本质是预测市场价 |
| 谁来做 | DSP 用历史竞价数据训练模型预估；广告主不用自己做 |
| 对数据分析意义 | Bid Shading 准确性直接影响广告主成本和平台收入 |

**效果示例**

| 情形 | 出价 | 支付 | 结果 |
|---|---|---|---|
| 无 Bid Shading | 真实估值 80 元 | 付 80 元 | 多付 15 元 |
| 有 Bid Shading | 出 65 元 | 付 65 元 | 省 15 元，ROAS 更好 |

**数字例子（平台收入对比）**

| DSP | 真实估值 | Bid Shading 后出价 |
|---|---|---|
| A | 80 元 | 68 元 |
| B | 70 元 | 62 元 |
| C | 50 元 | 45 元 |

- 第二价格：A 赢，付 62 元（B 的出价）→ 平台收入 62
- 第一价格：A 赢，付 68 元（自己的出价）→ 平台收入 68
- 第一价格下平台多收 6 元；虽然 A 多付 6 元，但 Bid Shading 已帮他省 12 元（80→68）

**当前实际状态（2025 年）**

| 场景 | 定价机制 |
|---|---|
| 程序化展示广告（Display/信息流） | 第一价格为主流 |
| 搜索广告（百度/Google 搜索） | 仍用 GSP（第二价格） |
| 视频广告（尤其是） | 大部分已转向第一价格或类似机制 |
| PDB/合约 | 保量、非竞价 |

**为什么搜索广告仍用 GSP？**

| 维度 | 程序化展示广告 | 搜索广告 |
|---|---|---|
| 竞价结构 | 多层 Header Bidding | 单层（搜索引擎内部排序），一次搜索多广告争有限位置 |
| Header Bidding | 有（多层嵌套） | 无（单层 + 多位置） |
| GSP 适用性 | 多层下激励相容被打破、口径混乱 | 单层 + 多位置，激励相容仍成立 |

> 搜索广告没有 Header Bidding 多层嵌套问题，GSP（二价）仍然有效。

**行业转向第一价格的真实逻辑（两害相权取其轻）**

- 第二价格在 Header Bidding 多层结构下：定价逻辑混乱、收入不可预测
- 第一价格在多层结构下：定价逻辑简单、虽压价但可预测可管理
- 第一价格问题（出价博弈）可用 **Bid Shading + 底价（Floor Price）+ 竞价深度** 缓解：
  - **Bid Shading** 让市场趋近均衡，价格波动收敛
  - **底价**：所有出价低于底价直接拒绝，保住底线（如底价 20 元，<20 不成交）
  - **竞价深度**：每次 10 个 DSP 参与，即使压价竞争仍充分
- 平台还可动态调整：调底价保收入、设最低出价增幅、优化竞价深度引入更多 DSP
- 收入不稳定主要发生在**竞价深度低（1–2 参与者）**，这是供给不足问题，非一/二价问题

> 修正认知：不是"第一价格没问题"，而是"第一价格的问题可控可缓解，第二价格在 HB 下的问题不可控"。第一价格下平台收入**可能反而更高**（赢家付自己出价 > 第二高出价）。

### 3.3 Header Bidding

| 维度 | Header Bidding | 传统瀑布流（Waterfall） |
|---|---|---|
| 请求方式 | 同时向所有 Ad Exchange / SSP 并行询价 | 按优先级串行依次询问 |
| 定价 | 取最高价 | 第一个接受即成交 |
| 收入 | 更高（充分竞争） | 可能贱卖（无充分竞争） |
| 延迟 | 增加（客户端并行请求多） | 低 |
| 本质 | 商业博弈产物（非技术进步） | 旧方案，串行时延大、高价值源排后面拿不到机会 |

**为什么会出现？** 谷歌 DoubleClick AdX 垄断后：① 流量分配优先自家 AdWords 广告主；② 抽成高达 40%——媒体和 DSP 利益受损，联合用 Header Bidding 打破垄断。

**缺点（为何不是所有媒体都用）**：① 客户端并行询价延迟大、伤体验；② 技术接入复杂、需维护多 DSP 对接；③ 小媒体无议价能力，DSP 不一定愿接。故主要是**中大型媒体**在用。

**加分项**：Prebid.js 是海外 Open Web 广告技术标准——媒体用 Prebid.js 在网页搭"小型竞价场"，多 SSP/DSP 同时参竞、价高者得，让媒体不再依赖单一平台。

### 3.4 oCPX 冷启动阶段

**oCPX 是什么**：o = optimized（优化）；X = 目标（如 C/M/A），即 oCPM / oCPC / oCPA。广告主只提供**转化目标 + 转化出价**，CTR/CVR 全部交给平台预估；平台按原 X 计费，但内部向转化目标优化排序。**计费口径 ≠ 优化目标**——oCPA 不是按转化收费，只是向转化目标优化排序。

**两个核心阶段**

| 阶段 | 特征 | 数据/成本表现 |
|---|---|---|
| 冷启动（学习期） | 平台缺该广告转化数据，CVR 预估不准 | 先拿部分流量探索、积累样本；成本波动大，可能远高于出价 |
| 稳定期 | 积累足够转化样本，CVR 预估收敛 | 实际转化成本向广告主出价靠拢 |

**冷启动常见误区（必答）**

1. **频繁改出价**：打乱模型学习，延长冷启动周期
2. **跑一天就关停**：样本不足就判效果差，很多计划还没度过探索期
3. **一次性大幅加预算**：流量池突变，模型重新学习，成本大概率反弹——正确做法是**每次加预算不超过 20%–30%**

**冷启动数据分析面试话术**

> "冷启动阶段我不会只看绝对成本下结论，因为小样本随机波动很大。首先判断样本量是否足够——至少积累 30 个转化、置信区间波动在可接受范围再评估效果；前期重点看健康度（拿量能力、CTR、链路通畅度、转化信号），预判计划能不能跑起来；同时避免频繁调出价、过早关停、大幅加预算这类干扰模型学习的操作。"

**oCPX 的风险与局限（挖坑题）**

1. 广告主出价只是**参考目标**，不是保证成本；流量/竞争变化实际成本会浮动
2. **必须回传转化数据**（如注册/付费事件）——没有回传，平台拿不到 label，CVR 模型无法训练，oCPX 完全失效。大量投放问题根因就是回传缺失/延迟/漏报

### 3.5 四方数据（对账差异）

**四方数据差异全景**

| 数据方 | 统计节点 | 普遍大小关系 | 正常差异率 |
|---|---|---|---|
| ADX 侧 | 赢单即算曝光/点击 | 最大（基准） | 基准 |
| DSP 侧 | 创意加载成功算曝光，客户端点击算点击 | 小于 ADX | 曝光差异 5%–15% |
| 第三方监测 | 用户端像素触发才算曝光/点击 | 小于 DSP | 再差 5%–10% |
| 广告主后端 | 用户真实到达/激活/注册 | 最小 | 到达率 60%–90% |

**各环节差异核心原因**

1. **ADX > DSP 曝光差异**：赢单后创意加载失败、用户快速划走、网络超时、广告拦截插件；差异率**超 20% 属异常**，排查创意尺寸/加载速度/超时率
2. **DSP > 第三方监测差异**：统计时机不同（DSP 服务端计数 vs 第三方客户端像素）；广告拦截/Cookie 禁用/跳离过早；差异率**超 15%** 需排查监测链接部署、像素触发位置
3. **点击 > 到达差异**：落地页加载慢、用户中途关闭、监测跳转故障、作弊流量；到达率**低于 50% 属异常**，优先排查落地页和作弊
4. **转化数据差异**：归因窗口不同（平台默认 7 天点击，广告主可能按 30 天）；归因模型不同（平台末次点击，广告主可能多触点）；回传延迟（转化几天后才回传，当天对不上）

**对账标准化步骤（面试话术）**

> "程序化链路长、多方数据存在差异正常，关键是区分正常损耗和异常问题。对账先统一口径（时间时区、指标定义、归因窗口、过滤规则）把规则拉平；再从曝光、点击到转化逐层算差异率，和正常阈值对比，定位差异放大环节；最后区分正常链路损耗还是投放/监测/作弊导致的异常，针对性解决。"

### 3.6 DMP

见 2.5 第一方/第三方 DMP 对比表。核心：**狭义 DMP = 第一方 DMP**（重定向、Look-alike 种子人群）；第三方 DMP 是数据交易平台。

### 3.7 归因

**常见归因模型**

| 模型 | 规则 | 适用 | 优缺点 |
|---|---|---|---|
| 末次点击（Last Click） | 100% 功劳给转化前最后一次点击 | 大多数平台默认 | 简单，但对前期种草渠道不公平 |
| 首次点击（First Click） | 100% 给第一次接触 | 拉新/获客 | 忽略后续促成渠道 |
| 线性（Linear） | 所有触点平均分配 | 通用 | 公平但无区分贡献 |
| 时间衰减（Time Decay） | 越靠近转化功劳越大（指数衰减） | 短决策链路（电商下单） | 兼顾时间 |
| 位置/U 型（Position-Based） | 首触 40% + 末触 40% + 中间平分 20% | 长决策（教育/保险/金融） | 首末最重要 |

**归因窗口（Attribution Window）**：不是一年前点击现在转化也算。常见：点击后 7 天/30 天；曝光后 1 天/7 天（浏览归因 View-through）。不同平台窗口不同，跨渠道对比口径不一致会"数据打架"。

**多触点归因（MTA）与数据驱动归因（DDA）**：规则型之上，用 Shapley 值、马尔可夫链算各渠道真实边际贡献。需大量数据、计算复杂，中小广告主用不起。

**归因模型选择逻辑**

- 效果广告、短决策链路（电商、游戏下载）：末次点击，简单直接
- 品牌广告、长决策链路（教育、保险、金融）：时间衰减或 U 型，兼顾前端种草
- 渠道策略复盘、年度预算分配：DDA（Shapley 值）算真实边际贡献

**预算分配定量思路**

> 核心规律：**同一渠道预算加到一定程度，边际转化成本会上升（边际效益递减）**。最优分配原则：**当所有渠道边际转化成本相等时，总转化量最大**。实操：各渠道逐步加预算，观察边际成本，把边际成本低的渠道多加、高的少加，直到各渠道边际成本趋近一致。

**程序化全链路漏斗（异常排查基础）**

```
ADX 询价量 → DSP 参竞量 → 赢单(填充) → 曝光量 → 点击量 → 到达 → 转化量
  参竞率        赢率         填充损耗      CTR        到达率      CVR
```

每一层核心指标与常见问题：

| 层 | 指标 | 偏低常见原因 |
|---|---|---|
| 询价→参竞 | 参竞率 | ID 映射失败、人群包不匹配、ADX 询价优化过滤 |
| 参竞→赢单 | 赢率 | 出价低、竞价竞争力不足 |
| 赢单→曝光 | 填充损耗 | 超时、创意加载失败 |
| 曝光→点击 | CTR | 素材质量、定向精准度 |
| 点击→到达 | 到达率 | 落地页加载慢、监测跳转故障、作弊流量 |
| 到达→转化 | CVR | 落地页质量、用户意图匹配度 |

> 书里强调：很多优化师一看到转化少就直接改出价换素材，**应先走一遍漏斗看卡在第几层**。如到达率仅 30%，问题不在广告而在链路/落地页，改出价没用。

## 四、公式

| 公式 | 含义 | 备注 |
|---|---|---|
| `eCPM = 出价 × pCTR × pCVR × 1000` | DSP 出价/排序核心 | 通用 eCPM 公式 |
| `oCPX 点击出价 = 目标CPA × pCVR` | OCPX 反推出价 | 本质"把出价决策从广告主交给平台" |
| `oCPC 出价 = pCVR × 目标CPA` | oCPC 公式 | 按点击计费 |
| `oCPM 出价 = pCTR × pCVR × 目标CPA × 1000` | oCPM 公式 | 按曝光计费，国内主流 |
| `eCPM = CTR × CVR × 转化出价` | oCPA 排序公式 | 计费仍按原 X 模式 |
| `pacing 系数 = 剩余预算 / 剩余时间应消耗预算` | 预算匀速消耗 | >1 加速，<1 减速 |
| `实际出价 = 基础出价 × pacing 系数` | 受预算约束后的出价 | — |
| `CTR = 总点击量 / 总曝光量` | 点击率 | — |
| `CPC = 总消耗 / 总点击量` | 单次点击成本 | 平台承担风险 |
| `CPA = 总消耗 / 总转化量` | 单次行动成本 | 平台承担最大风险 |
| `ROAS = 广告带来的收入 / 广告花费 × 100%` | 广告支出回报率 | 如花 $1000 带来 $5000，ROAS=500% |
| `到达率 = 成功打开落地页用户数 / 广告点击数` | 落地页到达 | <50% 异常 |
| `映射匹配率 = 已完成身份映射的请求 / 全部 ADX 请求` | Cookie/ID 映射质量 | 重定向消耗不出优先查 |
| `Bid Shading 后出价 = 预估市场最高出价 + 略高（确保赢）` | 第一价格压价 | 如估 63 出 65–70 |

**典型数值示例**

- 真实 CTR=2%、CPC 出价 2 元：`eCPM = 2 × 0.02 × 1000 = 40 元`
  - 故意估低 CTR=1% → eCPM=20 元 → 赢单率降、预算花不出、丢客户
  - 故意估高 CTR=4% → eCPM=80 元 → 赢单率高但真实仅 2% CTR，千次展示仅 20 元收入却付五六十元 → 大批量亏钱
- 市场价日内波动：凌晨约 20 元 CPM，晚高峰约 80 元 CPM
- 广告主设日预算 1 万元：DSP 不能上午花完，需 pacing 匀速
- tROAS 例子：跨境卖鞋，tROAS=500%（每花 1 元赚回 5 元）；用户 A 看高价球鞋($200) 出价 $3，用户 B 随便看拖鞋($15) 出价 $0.2，用户 C 加购未付 出价 $1.5
- 用户 OPPO 经历（面试案例）：游戏分发三方目标不一致，列底线表找交集 + 拉联合评审 → **ARPU +1.04%**，体验没降

## 五、面试 Q&A（问题 + 可第一人称口述答案）

### 5.1 RTB / DSP / 机制类

**Q1：你怎么理解 RTB？它和传统竞价广告的区别？**
> "RTB（Real-Time Bidding）是程序化交易核心机制，本质是每一次广告展示都由需求方实时决策是否购买、出多少价。它产生的根本原因是广告主有定制化人群划分需求——比如重定向找回流失用户、Look-alike 拓展新客，这些人群只有广告主自己的数据能定义，传统 ADN 那种'平台定义标签、广告主选标签'的封闭模式做不到。和传统竞价广告最核心的区别是：需求方是否在每次展示时实时参与竞价。搜索广告、ADN 虽然也是竞价，但人群和出价都是预先设定，不是每次实时决策；RTB 是用户打开页面那一刻，ADX 同时问多个 DSP'这个用户你出多少钱'，价高者得。完整流程：Cookie 映射（前置）→ 媒体请求 ADX → ADX 向各 DSP 询价 → DSP 基于自己数据判断并出价 → ADX 选最高 → 媒体展示，全程 100 毫秒内完成。"

**Q2：RTB 和 PDB 的核心区别？各自适用？**
> "RTB 逐次实时竞价、不保量，适合效果广告/长尾流量；PDB 提前锁定量和价，适合品牌广告主要确定性曝光。核心区别是'确定性'——PDB 保量保价保位置，RTB 不保证。"

**Q3：为什么 RTB 用第二价格拍卖而不是第一价格？**
> "第二价格鼓励'真实出价'——你不需要猜'出多少刚好赢'，直接出你认为值多少。第一价格会导致'出价博弈'（大家都压低出价试探），降低平台收入和效率。不过要注意，这是传统单 ADX 场景；在 Header Bidding 多层结构下第二价格的激励相容被打破，行业已转向第一价格。"

**Q4：DSP 的出价策略是怎样的？**
> "分两种情况。没有预算约束时，DSP 精准估算每次展示 eCPM，按 eCPM 出价即可，因 ADX 用 GSP 二价计费，按真实价值出价是最优策略。有预算约束时（实际常态）策略完全不同：广告市场价一天内波动剧烈——凌晨可能 20 元 CPM，晚高峰 80 元。若不管时段都按 eCPM 出价，预算会在低价时段花完、高价时段买不到，性价比低。正确做法是预测 eCPM 和市场价两条随时间变化的曲线，把预算集中分配到 eCPM/市价比最大的流量上，专挑'价值高但便宜'的流量买。实践中时间维度最关键，其他维度（性别、地域）影响相对小。"

**Q5：DSP 出价时除了预估还要考虑什么？（至少 3 个）**
> "预算约束（快花完就降出价 pacing）、频次控制（同一用户看过 3 次就降出价）、竞争环境（激烈时可能加价）、广告主目标（CPA 目标 50 元就反推出价）、定向匹配度。"

**Q6：Pacing 是什么？为什么需要？pacing 系数怎么算？**
> "Pacing 是预算匀速消耗。因为广告主设了日预算，不能上午花完下午没量。pacing 系数 = 剩余预算 / 剩余时间应消耗预算；>1 加速，<1 减速。"

**Q7：OCPX 的出价公式是什么？和 CPC 出价区别？**
> "OCPX 点击出价 = 目标CPA × pCVR。区别：CPC 是广告主自己定点击出价；OCPX 是广告主定目标转化成本，平台用 pCVR 反推点击出价。本质是'把出价决策从广告主交给平台'。"

**Q8：填充率下降可能有哪些原因？（至少 3 个）**
> "① 供给不足（广告主预算花完/下线）；② 底价过高（SSP Floor Price 设太高，出价够不上）；③ 定向匹配不上；④ 竞价深度不足（参与竞价 DSP 太少）；⑤ 技术问题（超时、接口异常）。"

**Q9：Header Bidding 和传统瀑布流的区别？**
> "Header Bidding 同时向所有 Ad Exchange 竞价取最高价——收入更高但延迟增加；瀑布流按优先级依次询问——延迟低但可能贱卖（第一个接受就成交，无充分竞争）。"

**Q10：重定向为什么转化率高？对延迟反馈有什么影响？**
> "重定向用户已有行为（加购/浏览），意图明确，pCVR 高。但转化可能延迟（今天加购 3 天后下单），延迟反馈问题突出——归因窗口太短会低估重定向真实效果。"

**Q11：你在 OPPO 做的"分发排序"和广告"eCPM 竞价排序"有什么异同？（面试串联题）**
> "相同：都是'按价值排序分配有限资源'——OPPO 按 LTV 排序分配曝光，广告按 eCPM 排序分配展示。不同：① 广告有明确的'价格'（出价），分发没有；② 广告是多方博弈（广告主/平台/用户），分发主要是平台内部优化；③ 广告用拍卖机制定价，分发用排序+加权。核心思想一致：把资源分配给价值最高的对象。"

**Q12：RTB 的"实时"和搜索广告的"实时"有什么不一样？**
> "搜索广告的实时是供给方（搜索引擎）实时检索、排序、定价，但需求方（广告主）人群和出价是预先设好的，不是每次查询实时决策。RTB 的实时特指需求方在每次展示时实时参与竞价——DSP 在用户打开页面那一刻才判断'这个用户我要不要、出多少钱'。这是本质区别。"

**Q13：DSP 按 CPC 向广告主收费、按 CPM 向 ADX 出价，中间的风险是什么？**
> "风险在点击率估算不准。DSP 估这条流量 CTR 2% 按对应 eCPM 出价，但实际只有 1%，那从广告主收的 CPC 费用就不够覆盖付给 ADX 的 CPM 成本，就亏了。所以 DSP 核心竞争力是 CTR/CVR 预估准确度，估得越准利润越稳。"

**Q14：为什么个性化重定向需要商品库存实时接口？**
> "因为个性化重定向是实时推荐具体商品，如果用户点进广告发现商品已售罄或价格和广告不一致，会严重伤害广告主品牌形象。商品库存和价格动态变化，必须准实时同步，不能用离线数据。"

**Q15：Header Bidding 的缺点是什么？为什么不是所有媒体都用？**
> "三个缺点：① 客户端同时询价导致延迟大、伤体验；② 技术接入复杂、需维护多 DSP 对接；③ 小媒体无议价能力，DSP 不一定愿接。所以主要是中大型媒体在用，小媒体仍依赖 ADX/SSP。"

**Q16：DS P 和 ADN 有什么区别？**
> "人群定义权：ADN 平台定义标签广告主选，DSP 广告主自定义（第一方数据）；决策时机：ADN 预先设定非实时，DSP 每次展示实时决策；计费：ADN 多为 CPC，DSP 多为向 ADX 的 CPM；核心能力：ADN 流量聚合+受众定向，DSP 定制化人群+实时出价策略；广告主控制力：ADN 弱（选标签），DSP 强（每次展示都能决策）。"

**Q17：书上高频考点——为什么 ADX 用 CPM 结算而 ADN 用 CPC？**
> "核心逻辑：谁有能力精准预估 CTR，谁就承担这个风险。ADN 聚合五花八门媒体，没法精准预估每个广告+广告位点击率，若按 CPM 向广告主收费，没人点击广告主白花钱——所以 ADN 选 CPC，点击风险平台自己扛。RTB 场景下，人群判断、CTR/CVR 预估全由 DSP 做，DSP 握广告主第一方数据最清楚流量值多少钱，ADX 只做比价不碰预估，把点击率风险交给 DSP，因此用 CPM 按展示计费。"

**Q18：为什么 ADX/媒体只能是 CPM、广告主偏要 CPC，形成混合计费？**
> "对广告主，CPC 是友好效果保护——他不懂 RTB 流量好坏，但点击是可观测事件，产生点击才花钱。对 ADX/媒体，曝光机会是资产，一旦输出资源就消耗，不能等点击再收钱（点击发生在曝光后且不必然发生），否则媒体承担'没人点就拿不到钱'的巨大风险。于是形成：下游广告主要 CPC（效果导向）、上游 ADX/媒体只接受 CPM（曝光即消耗），DSP 夹中间做风险承接方。"

**Q19：DSP 故意把 CTR 估低/估高会发生什么？**
> "估低：出价保守、赢单率大降、拿不到量、预算花不出、广告主不满意丢客户。估高：赢单率高抢大量流量，但真实 CTR 低，千次展示实际收入远不够付 ADX 成本，大批量亏钱。所以 DSP 不能故意估高也不能故意估低，必须把 CTR 预估校准到接近真实值——DSP 竞价场景下，校准（calibration）和 AUC 排序能力同样重要。"

**Q20：现实里 DSP 怎么做折中？**
> "不会无脑压低或抬高，会设安全系数。例如理论 eCPM=40，实际出价乘 0.8 保守系数最高出 32——少量牺牲拿量能力，避免预估模型出错带来大规模亏损。这就是工程上风险控制手段。"

### 5.2 oCPX / 重定向 / 定向类

**Q21：重定向有哪几种？适用什么场景？**
> "三种：① 网站重定向——把一段时间来过广告主网站/App 的用户作目标，效果最好，eCPM 比无定向高一个数量级，但量级受访客量+媒体重合度限制；② 个性化重定向——网站重定向升级，根据用户看过的商品、购买阶段（浏览/加购/已购）实时生成创意，本质是'站外推荐'，需动态创意+推荐引擎+库存实时接口，典型代表 Criteo；③ 搜索重定向——把搜过相关关键词的用户作目标，量级比网站重定向大、精准度稍低，词表最佳策略是统计广告主网站从搜索引擎来的高频词。品牌广告用重定向强化决策信心，效果广告用重定向找回未转化用户或做二次购买推荐。"

**Q22：PDB、PD、PMP、公开 RTB 怎么区分？**
> "按'是否预留 + 是否竞价'两维：PDB 预留+定价（一对一，签保量合同，需求方可自决投放，适合大广告主跨媒体频控）；PD 非预留+定价（一对一，提前谈价，每次有流量先问买家要不要，适合优质广告主挑流量不愿竞价）；PMP 非预留+竞价（邀请制，只有受邀少数买家，兼顾质量控制与竞价变现，是优质媒体首选）；公开 RTB 非预留+竞价（公开，所有人能参与，适合长尾媒体和效果广告主）。口诀：PDB 包场、PD VIP 优先、PMP 会员制拍卖、RTB 公开菜市场。"

**Q23：oCPX 是什么？为什么诞生？**
> "o=optimized 优化，X 是目标（C/M/A）。广告主只提供转化目标与转化出价，CTR/CVR 全部交给平台预估，平台按原 X 计费但内部向转化目标优化。诞生背景：早期 CPC 竞价门槛高，中小广告主不懂投放、不会调出价；oCPX 把预估转化转移给平台，降低门槛——广告主只需说'我要什么转化、愿花多少钱一个'，剩下模型交给平台。"

**Q24：RTB 和 oCPX 最大的本质区别是什么？**
> "谁负责做 CTR、CVR 预估，谁掌握流量决策权力。RTB：流量过来把信息丢给外面 DSP，DSP 自己判断买不买、出多少钱，需求方掌握决策。oCPX：全部决策留媒体平台内部，广告主只输入转化目标，供给方掌握预估与流量分配决策。"

**Q25：RTB 和 oCPX 哪个更先进、更主流？**
> "没有绝对先进，解决场景不同。oCPX：国内信息流效果广告绝对主流，适合中小广告主、信息流闭环平台（抖音/快手/腾讯广告），门槛极低、媒体模型强，但数据黑盒、高度依赖回传、难用广告主第一方人群精细筛选。RTB：品牌广告、有技术的大广告主场景主流；纯公开 RTB 国内占比逐年下降，现在大量是 PMP/PDB。RTB 优点是完全掌控人群和出价、跨媒体统一采买、充分用第一方数据；短板是门槛高、需 DSP/ID-mapping、Cookie/设备 ID 合规限制越来越大、Web 端 RTB 萎缩。"

**Q26：广告模式演进对比（必背）**
> "传统 CPC 竞价（搜索/ADN）：供给方估 CTR、广告主估 CVR，适合懂投放的成熟广告主。RTB/DSP：需求方（DSP）同时估 CTR、CVR，适合有第一方数据、技术能力的大广告主。oCPX：供给方（平台）同时估 CTR、CVR，适合中小广告主降低门槛。整条主线：CTR/CVR 预估这件工作不断在需求方、供给方之间转移——RTB 交给需求方 DSP，oCPX 拿回媒体供给方。"

**Q27：RTB 和 oCPX 是替代关系吗？**
> "不是同一维度概念，不能直接比先进。二者底层排序公式都是 eCPM=CTR×CVR×出价，差别是谁来算 CTR、CVR。oCPX 可运行在 RTB 内（DSP 收到 ADX 询价后内部用 oCPX 式智能出价再返回），但国内主流 oCPX 都跑在媒体闭环生态、不走 RTB 对外链路。新趋势是 RTA 接口——媒体内部 oCPX 竞价，流量到达时调广告主接口由广告主做人群过滤，把部分决策交还广告主，兼顾闭环效率和第一方数据。"

**Q28：频次控制是什么？为什么重要？**
> "频次控制是限制单个用户一段时间看到同一广告的最大次数。随曝光频次升高用户会广告疲劳、CTR 逐步下降。品牌 GD 合约尤其重要——目的是把曝光分散给更多用户提升触达 Reach，而非反复轰炸同一批人（如 7 天最多 4 次）。分析重点看人均曝光频次、分频次 CTR、总独立触达人数。"

### 5.3 行业侧 / 业务视角（面试官痛点应答）

**Q29：你怎么理解"我们流量侧还行、行业侧不足"这个现状？**
> "我的理解，流量侧指 DSP 通用程序化采买底层能力，包括 RTB 竞价、智能出价、反作弊、通用定向、指标体系，这块 MediaGo 已较成熟，不管什么行业广告主平台都能完成流量获取。而行业侧，是针对手游、保险、跨境电商这类垂直行业，沉淀行业专属模型、分析模板、最佳实践。不同行业成功指标差异很大——游戏看 LTV 留存、保险看线索有效率退保率、电商看 GMV，不只是浅层 CPA。目前平台更多是一套通用能力给全部客户，缺少分行业深度定制，很多行业深层业务指标需广告主自己拼接，行业问题根因诊断能力不足，这也是业务接下来重点攻坚补齐的方向。"

**Q30：被问到行业侧短板怎么答？（应答模板）**
> "我的流量侧基础比较扎实，熟悉 MediaGo 这类 DSP 程序化投放整套机制，能基于平台流量报表做流量分层、问题定位、出价定向等优化。但短板是行业侧经验还有提升空间：过去更多聚焦广告平台本身指标，看 CPA、广告端 ROAS，对不同垂直广告主完整生意链路理解不够深——比如游戏看 LTV、保险看线索有效率退保率这类后端业务指标。后续我会补足：做分析时不只看 DSP 后台指标，主动对齐广告主后端业务数据，理解行业商业模式，区分问题根源是流量侧还是客户落地页/产品本身，输出对客户生意有价值的策略，而不只是平台层调参建议。"

**行业侧核心要点（补能力落地）**
- 每次分析客户先问两件事：客户怎么赚钱？什么才是客户真正的成功指标（不一定是 CPA）？
- 尽可能拿到客户后端数据（LTV、线索质量、付费、退款）与 MediaGo 广告数据关联
- 刻意区分问题来自【流量（媒体/出价/定向）】还是【客户业务（落地页/产品/素材/行业竞争）】
- 看同行业竞品投放，总结行业投放特点与常见坑

**案例**：出海保险广告主 CPA 达标但客户不满意——流量侧看 CTR/CVR 正常、CPA 符合目标看不出问题；行业侧看保险不仅看注册，要看有效保单、保单金额、退保率——拿到大量低成本注册但是无效垃圾线索、退保率极高，客户亏钱。流量侧看广告平台指标，行业侧看广告主最终商业结果。

### 5.4 异常排查 / 出价策略分析类

**Q31：出价策略分析——为什么今天花不出去预算 / ROI 下降了？**
> "四步：① eCPM 估算是否准确（CTR 预估模型衰减？CVR 波动？）；② 市场价波动（大促整体市场价上涨？分时段看成交价）；③ 预算分配（预算是否在低价时段提前花完、高价时段没预算？）；④ 人群覆盖（重定向人群量级够不够？Look-alike 拓展质量是否下降？）。核心指标：CPM（成交价）、CTR、CVR、eCPM、预算消耗节奏、ROI。"

**Q32：CTR 预估不准的线上业务后果？**
> "整体高估 pCTR：排序上广告拿到高于应得 eCPM 抢大量曝光，但真实点击少——oCPX 消耗跑很快转化少、CPA 严重超标；DSP 向 ADX 付很高 CPM 但点击寥寥。整体低估 pCTR：eCPM 偏低竞价打不过别人拿不到曝光，明明质量好却没量，是 oCPX'消耗跑不出去'的一类原因。偏差可全局也可分人群/素材/行业局部——比如模型对游戏行业 CTR 普遍高估、工具 App 低估，这正对应'流量侧还行、行业侧不行'，通用模型在垂类校准失效。"

**Q33：MRP 市场保留价（底价）怎么权衡？**
> "MRP 是拍卖最低门槛价，两层作用：① 过滤 eCPM 低于底价的广告，连参竞资格都没有；② 若第二高价算出的扣费比 MRP 低，强制按 MRP 扣费。权衡：设太高很多广告被挡、填充率下跌流量浪费；设太低广告质量差、单流量收益上不去。策略：① 全局统一底价；② 分关键词/分流量维度动态设置（竞争激烈流量 MRP 抬高、冷流量降低）。复盘指标：填充率、千次展现收益 eCPM、底价以上候选广告数量。填充率突降优先排查 MRP 是否调太高。"

**Q34：Cookie-Mapping（身份同步）是什么？为什么重要？**
> "问题根源浏览器同源策略：ADX 与各 DSP 域名不同，同一用户两边 Cookie ID 完全不同，DSP 拿到 ADX 的 bid-request 只看到 ADX 用户 ID，认不出自己库里的重定向/Look-alike 用户，定制化人群包直接失效。规则：Cookie 映射由 **DSP 侧发起**，在广告主网站页面完成，非 ADX 发起；DSP 只需识别访问过广告主站点的访客，全网同步带宽成本巨大没必要。移动端 App 无 Cookie，报文直接下发明文设备 ID（IDFA/GAID/OAID），不需这套流程。关键指标**映射匹配率 = 已完成映射的请求 / 全部 ADX 请求**。现象：重定向人群包量级很大但实际参竞极少，优先查映射匹配率；匹配率下跌根因：广告主官网 JS 埋点缺失、浏览器第三方 Cookie 限制（Chrome）、用户清 Cookie、ADX-DSP 同步接口故障。"

**Q35：曝光监测、点击监测、到达率？**
> "曝光监测两种方式：① 客户端（Client-side）广告素材加载时发 1×1 透明 gif 像素，真实反映用户端是否加载，但加载失败/网络差会漏统计；② 服务端（S2S）媒体服务器直接回调第三方接口记录，稳定不受客户端影响，但可能记了曝光用户端实际没看到。业务坑：媒体后台曝光数与第三方监测曝光数永远对不上，差异来自客户端加载失败、广告被拦截、口径不一致、时差——分析师要解释差异而非强行让两数字相等。点击监测是跳转链路（先跳第三方监测记录点击再 302 重定向落地页），多一跳增时延，监测故障直接损转化。到达率 = 成功打开落地页用户数 / 广告点击数；到达率低原因：落地页加载慢、监测跳转故障、恶意/虫点击、服务器故障 404。复盘：点击高转化少先查到达率，到达率低问题不在流量在链路/落地页。"

**Q36：询价优化（Call-out Optimization）是什么？**
> "RTB 痛点：每次请求广播给全部 DSP，带宽服务器成本爆炸。询价优化即只呼叫大概率会出价的 DSP：基于历史数据过滤总报极低价'蹭数据'却几乎不赢单的 DSP，在'呼叫 DSP 数量'与'拿到最高出价概率'间权衡。现实两难：呼叫太少漏掉高价值 DSP 媒体收益受损；呼叫太多成本暴涨、延迟变大。两种思路：① 规则过滤（该 DSP 对某类媒体/地域几乎不出价就停发）；② 预测式路由（预估该 DSP 对本次请求出价概率、期望 eCPM，优先呼叫高预期）。"

### 5.5 智能出价演进（t 系列）

**Q37：你了解智能出价吗？**
> "智能出价核心逻辑是从'按位置/按点击统一出价'进化到'按用户价值动态出价'。最基础是 oCPC/pCPC，系统在广告主设定基准出价上根据转化预估概率动态调整，高概率用户加价、低概率用户降价。再往上是 tCPA，广告主不再管单次点击出多少，而是告诉系统'我每个转化愿意花多少钱'，系统自动优化。最高级是 tROAS，广告主告诉系统'我的投入产出比目标是多少'，系统不仅考虑转化概率还考虑每个转化的价值大小，实现精细化预算分配。这些策略前提都是足够转化数据和准确转化回传，否则模型没学习素材出价就不准——这也是数据分析岗在程序化广告中如此重要的原因：数据质量直接决定智能出价效果。"

**智能出价演进路线**

| 阶段 | 出价方式 | 广告主角色 |
|---|---|---|
| 手动出价 | CPM / CPC / CPA / CPD-CPT | 完全控制，人工拍脑袋 |
| 半智能 | oCPC / oCPM / oCPA | 出基准价 + AI 微调 |
| 全智能（t 系列） | tCPA / tROAS / Maximize Conversions / Maximize Conversion Value / Enhanced CPC(pCPC) | 只定目标，AI 全自动 |

（tCPA vs tROAS 对比见第四章公式区；核心区别：tCPA 控单个转化成本、每个转化价值相近时适用，前提 30 天 30+ 转化；tROAS 控整体投入产出比、转化价值差异大时适用，前提需给转化标注金额。）

**pCPC / Enhanced CPC**：设基准 CPC 出价，系统按转化概率自动微调——转化概率高用户可能出 $3.5（抢），低用户可能出 $0.5（省），但长期平均 CPC 不超设定。重要变化：**Google 已于 2025 年 3 月宣布逐步淘汰 eCPC**，搜索和展示不再支持，强制迁移；Microsoft Ads 仍支持。

### 5.6 趋势 / 产业（加分）

**Q38：程序化广告未来大方向？**
> "第一，产业格局上媒体系围墙花园持续壮大，传统通用独立 DSP 承压，独立 DSP 走向垂直深耕或输出技术服务；公开 RTB 回归长尾补充，PDB 程序化保量在品牌场景进一步普及，行业从赚流量差价向服务费模式转型。第二，数据底层受全球隐私政策影响，传统 Cookie、IDFA 可用性下降，转向第一方数据、上下文定向、隐私计算，个体级追踪能力减弱。第三，AI/AIGC 渗透创意、出价、报表告警全链路，但业务判断、作弊识别仍靠人；模型竞争重点从 AUC 排序转向概率校准。第四，投放更看重真实增量 Lift、品效协同，反作弊/流量质量管控成平台核心竞争力，CTV、数字户外等新终端程序化持续扩张。长期痛点仍在：数据孤岛、虚假流量、供应链透明化难题。"

**独立 DSP 突围方向（吴俊书）**：① 垂直化深耕（聚焦游戏/电商/工具，沉淀行业模型、垂类媒体，行业模型校准成核心壁垒）；② 技术服务输出（不卖流量，输出 Trading-desk、DMP、竞价引擎、反作弊，私有化/托管）。

**PDB 1:1.5 退量机制**：品牌广告大规模落地，合约+程序化结合，兼顾保量、人群筛选、跨媒体频控、创意轮播。

## 六、异常排查框架

### 6.1 标准四步法

**第一步：先确认是不是真异常（排除 3 个假异常）**
1. **口径问题**：统计时间窗口不同、数据延迟（转化回传延迟）、指标定义变了
2. **大盘周期波动**：周末/工作日差异、节假日、海外时区差异、行业大盘整体波动
3. **数据报错**：监测链路故障、ADX 接口异常、数据上报丢包

> 程序化特别注意：转化有延迟，当天 CPA 一定不准，至少看 **T+3 甚至 T+7** 回溯数据，不能拿当天实时数据判成本炸了。

**第二步：按转化漏斗从上到下拆，定位流失层**

```
ADX 询价量 → DSP 参竞量 → 赢单(填充) → 曝光量 → 点击量 → 到达 → 转化量
```

| 异常现象 | 优先排查层级 | 常见根因 |
|---|---|---|
| 整体消耗暴跌、拿不到量 | ADX 询价→参竞 | ① ADX 侧询价覆盖率下降（询价优化降权）；② ID 映射匹配率暴跌；③ 出价过低/定向过窄；④ DSP 超时率飙升来不及回包 |
| 曝光正常、点击量暴跌 | 点击（CTR） | ① 素材衰减疲劳；② 流量质量变差、ADX 给的流量人群变了；③ 定向放宽人群不精准 |
| 点击正常、转化暴跌 | 点击→到达→转化 | ① 落地页故障加载失败；② 监测跳转链路断了；③ 作弊流量涌入到达率跳水；④ 广告主转化回传缺失/延迟 |

**第三步：维度拆解，定位具体子集**
- 流量维度：分 ADX 渠道、分媒体站点、分广告位类型
- 业务维度：分广告主行业、分投放策略、分人群包、分素材
- 时间维度：分时点看突变（配置/接口故障）还是渐变（素材衰减、竞争加剧）

> 例：整体 CPA 涨 20% → 漏斗看 CVR 暴跌 → 拆媒体发现 X 媒体 CVR 跌 50% 且占总消耗 40% → 根因锁定 X 媒体流量质量变化 → 进一步查是否作弊增加或定向偏移。

**第四步：区分正常损耗 vs 异常问题，输出整改**

### 6.2 oCPX 冷启动排查专项
- 先判样本量是否足够（至少 30 个转化、置信区间可接受）再下结论
- 前期看健康度：拿量能力、CTR、链路通畅度、转化信号
- 避免：频繁改出价、过早关停、一次性大幅加预算（每次加 ≤20%–30%）

## 七、关键数字与术语

### 7.1 关键数字（全部来自原文，未杜撰）
- Ad Exchange 抽成：**5%–20%**
- RTB 全链路耗时：**< 100 毫秒**
- 日内市场价波动：凌晨约 **20 元 CPM**，晚高峰约 **80 元 CPM**
- Bid Shading 示例：真实估值 80 → 出 65–70；A(80/68)、B(70/62)、C(50/45)；二价平台收 62、一价收 68（多 6 元）
- oCPX 冷启动样本门槛：**至少 30 个转化**（tCPA 建议 30+/月）
- 加预算节奏：每次 **不超过 20%–30%**
- 四方数据差异：ADX>DSP 曝光差 **5%–15%**；DSP>第三方再差 **5%–10%**；广告主后端到达率 **60%–90%**
- 异常阈值：ADX>DSP 差异 **>20%** 异常；DSP>第三方 **>15%** 排查；到达率 **<50%** 异常
- SKAdNetwork 归因延迟：**24–72 小时**
- 品牌频次控制示例：7 天最多看同广告 **4 次**
- 新用户 D7 留存案例：密度上调后 **35%→26%**（伤害大）；老用户 **47%→44%**（影响小）
- 合约示例：1000 万曝光 / 30 天，第 10 天理论完成 **33%**
- OPPO 案例：游戏分发 ARPU **+1.04%**，体验未降
- Google eCPC 淘汰时间：**2025 年 3 月**
- tROAS 示例：每花 $1 赚回 $5（ROAS 500%）
- PDB 退量机制：**1:1.5**
- Header Bidding 谷歌 AdX 抽成：**高达 40%**

### 7.3 易混概念辨析
- **计费口径 ≠ 优化目标**：oCPA 不是按转化收费，只是向转化目标优化排序
- **RTB ≠ oCPX**：RTB 是跨平台流量交易机制（外部拍卖），oCPX 是媒体内部出价优化策略；二者底层公式同为 eCPM=CTR×CVR×出价，差别是谁算 CTR/CVR
- **流量侧 ≠ 行业侧**：前者看平台指标（CTR/CVR/CPA），后者看商业结果（LTV/退保率/GMV）
- **第一价格 vs 第二价格**：不是"第一价格没问题"，而是"第二价格在 Header Bidding 多层下问题更大，两害相权取其轻"
- **正常损耗 vs 异常问题**：四方数据差异是常态，对账先拉平口径再逐层算差异率
