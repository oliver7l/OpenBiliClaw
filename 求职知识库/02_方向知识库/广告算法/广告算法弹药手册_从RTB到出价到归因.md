## 一、程序化广告谱系（先建立层次，别一上来就讲 RTB）

```
程序化交易（大概念）
├── 合约广告（PDB 等）—— 不竞价，提前锁定量级与价格
└── 竞价广告（RTB）—— 实时竞价，价高者得
    ├── 瀑布流（Waterfall）—— 按顺序逐个发起竞价
    └── Header Bidding —— 同时向多家发起竞价
```

**关键理解**：Header Bidding 和瀑布流**都是 RTB 的子方式**，里面跑的都是 RTB 机制（实时/逐次/竞价/价高者得），区别只在于"**竞价请求怎么发出去**"。

**面试一句话**：
> "程序化交易分两大类，合约和竞价。合约是提前锁量锁价，适合品牌广告主要保量的场景；竞价是 RTB，每一次曝光单独拍卖。RTB 内部又分瀑布流和 Header Bidding，前者按顺序逐个问、后者同时问，本质区别是请求方式不是竞价机制。"

## 二、RTB 全链路：100ms 内发生了什么

### 2.1 完整流程（7 步，背下来）

1. 用户打开 APP/网页，页面加载，触发广告位
2. **媒体 → SSP**：把广告位尺寸、设备 IP、匿名用户 ID、**底价**传给 ADX，生成竞价请求 `BidRequest`
3. **ADX → 所有接入的 DSP**：广播这条请求，附带用户/设备/页面信息
4. **DSP 内部处理（核心）**：
   - 查 **DMP** 拿用户画像
   - 匹配广告主定向条件（地域/年龄/兴趣/预算剩余）
   - **模型预估 CTR/CVR**，算出这次曝光愿意出多少钱
   - 匹配不上就不返回；匹配上返回 `BidResponse`（出价 + 素材地址）
   - ⚠️ **严格超时，一般 100ms**，超时直接判弃权
5. **ADX 执行拍卖**（大多是**二价拍卖**：最高出价者赢，实际付第二高的价格）
6. ADX 把赢家广告下发回 SSP → 媒体页面，广告展示
7. 曝光/点击/转化事件通过**监测回传**给 DSP/DMP，用来训练模型、优化下一轮出价

> 整套必须在页面加载完成前做完，用户无感知。

### 2.2 六个角色（别搞混）

| 角色 | 全称 | 干什么 |
|---|---|---|
| **媒体** | — | 手上有广告位（流量卖方） |
| **SSP** | Supply Side Platform | 帮媒体管广告位、收集流量、上报 ADX，**最大化媒体收入** |
| **ADX** | Ad Exchange | 广告交易所，连接 SSP 和 DSP，执行拍卖 |
| **DSP** | Demand Side Platform | **代表广告主出价**：拿请求 → 判断要不要 → 算价 → 返回 |
| **DMP** | Data Management Platform | 输出用户画像（地域/兴趣/设备/行为），给 DSP 做定向参考 |
| **TD** | Trading Desk | 代理商/广告主操作台，**本身不参与竞价**，通过 API 调多家 DSP 统一管理 |

**RTB 一句话**：买的不是广告位，是**当下这个用户**。同一个广告位，不同用户访问，卖给不同广告主，价格也不一样。

## 三、竞价机制（高频考点）

### 3.1 第一价格 vs 第二价格

| 维度 | 第一价格 | 第二价格 |
|---|---|---|
| 赢家付多少 | **付自己的出价** | 付第二高的出价 |
| 出价策略 | 需要 shading（报低于真实估值） | **出真实估值即可（激励相容）** |
| 透明度 | 高（付的就是出的） | 低（付的不是出的） |
| 复杂度 | 低 | 高（多层时更复杂） |
| 对平台 | 收入更高（无 shading 损耗） | 需要机制设计保证真实性 |

**为什么 RTB 传统上用第二价格？**
> 因为**激励相容**：第二价格下，出真实估值是最优策略（出高了不会多付，出低了可能丢量），所以 DSP 不需要博弈，市场效率高。

### 3.2 为什么 Header Bidding 推动了"转向第一价格"？

**传统 RTB 时代（第二价格可行）**：
```
一个 Ad Exchange + 多个 DSP 竞价
  └─ Ad Exchange 内部用第二价格定价
     （结构简单，"激励相容"成立）
```

**Header Bidding 时代（第二价格出问题）**：
```
同一时刻多个需求方：
  ├─ SSP-A（内部竞价）→ 返回一个出价
  ├─ SSP-B（内部竞价）→ 返回一个出价
  ├─ SSP-C → 直接出价
  └─ DSP-D → 直接出价
        ↓
  媒体层面：这些出价怎么定价？
```
> 问题在于：**每个 SSP 内部已经是二价了**，媒体拿到的是各家"已经算过一刀"的价格。再在媒体层做一次二价，等于对已经打折的价格再打折，媒体收入受损，且 DSP 的出价策略变得不可预测。
> 所以 Header Bidding 普及后，行业整体**转向第一价格**，配合 DSP 侧做 bid shading（用模型预测获胜所需的最低出价）。

**面试话术**：
> "第一价格和第二价格的分水岭其实在 Header Bidding。传统单一 ADX 时代二价是激励相容的，但 HB 之后媒体同时面对多个已经各自算过二价的 SSP，再套一层二价会让媒体收入受损、DSP 出价也失去稳定性，所以行业转向一价 + DSP 侧做 bid shading。"

### 3.3 其他机制
- **VCG**：按"给他人造成的损失"计价，理论最优但复杂，工业界少用
- **底价（floor price）**：媒体侧设的最低可接受价格，低于此不出

## 四、出价体系（广告算法的核心）

### 4.1 出价方式演进

| 方式 | 广告主为什么付 | 风险归谁 | 平台要求 |
|---|---|---|---|
| **CPM** | 千次曝光 | 广告主（效果不确定） | 低 |
| **CPC** | 点击 | 广告主（转化不确定） | 中（需 pCTR） |
| **CPA** | 转化 | 平台（转化不确定） | 高（需 pCVR） |
| **oCPC/oCPM** | 按点击/曝光付费，但**按目标成本优化** | 平台 | 高（需 pCTR×pCVR + 出价控制） |
| **oCPX** | 广告主只给目标成本（tCPA），平台全自动 | 平台 | 最高 |

### 4.2 oCPX 核心公式

```
bid = tCPA × pCTR × pCVR / (1 + λ)
```
- `tCPA`：广告主给的目标转化成本
- `pCTR / pCVR`：平台预估
- `λ`：**动态调节因子**，由反馈控制（PID）根据"实际成本 vs 目标成本"的偏差调整

**和 CPC 出价的区别**：
> CPC 是广告主自己对每个点击定价，平台只负责排序；oCPX 是广告主只给**成本目标**，平台根据预估和实时反馈**自动算出每一次曝光该出多少**，并把成本波动用控制环路压住。

### 4.3 Pacing（预算平滑）

**是什么**：把一天的预算均匀花掉，而不是早上就烧完。
**为什么需要**：不均会导致上午竞争激烈成本高、下午没量，整体 ROI 变差。
**怎么做**：pacing 系数按"剩余预算 / 剩余可用流量机会"动态计算，本质是**约束下的出价缩放**。
**面试话术**：
> "Pacing 我理解为'带预算约束的出价缩放'。在大促这种流量突变的场景尤其关键——流量突然放大时如果 pacing 不放宽会跑不起量，放宽太猛又会导致成本失控，所以 pacing 和成本控制是要联合调的。"

## 五、预估体系（CTR / CVR / LTV）

### 5.1 三个预估的关系

```
eCPM = bid × pCTR × pCVR        （广告侧，决定排序与收入）
GMV  = UV × CTR × CVR × 客单价  （电商侧，决定业务价值）
```
> 这两条公式是**同构**的——广告的 eCPM 就是电商 GMV 去掉价格项、加上出价项。这是广告经验迁移到电商推荐的最强支点。

### 5.2 校准（Calibration）

- **问题**：模型输出的是**排序**能力（AUC），但出价需要的是**绝对概率**（pCVR 准不准直接决定成本达成）
- **多位置校准**：不同坑位的点击率天然差异巨大，不校准会有系统性偏差
  - 我的实践（OPPO）：位置特征 + 分位置校准层 + 多任务联合建模，**偏差 30% → 20%**，ARPU +1.04%
- **常用方法**：Platt Scaling / Isotonic Regression / 分桶校准

### 5.3 延迟反馈（Delay Feedback）

**核心矛盾**：**时效性 vs 标签准确性**

**工业落地决策树**：
```
延迟反馈建模
├─ 延迟 < 1 天（分钟/小时级）  → 在线学习场景：DEFER / ES-DFM / IF-DFM
├─ 延迟 1~7 天
│   ├─ 时效性优先 → 向前归因 + 重加权
│   └─ 准确性优先 → 向后归因 N 天
├─ 延迟 > 7 天（退货/长周期）  → 多任务建模（DEFER）+ 生存分析
└─ 存在退货？ → 需要单独的负向建模 / 样本降权
```

**技术路线三条**：
1. **参数化生存模型**（DFM / NoDeF）
2. **标签修正 + 重要性采样**（ES-DFM / DEFUSE）
3. **多窗口 / 多流建模**（MISS / TESLA）

### 5.4 CVR 样本优化的三个维度（面试加分）

```
CVR 样本优化
├── 归因维度：多归因口径（首触/末触/线性/MTA/DDA）
├── 时间维度：延迟反馈（等待窗口 / 生存分析）
└── 空间维度：跨场域（首猜/搜索/直播/站外/跨境）

终极形态 = 跨场域 × 多归因 × 延迟感知 = 全域全链路 CVR 预估
```

**归因口径的场域博弈**（面试官很爱听这段）：

| 口径 | 定义 | 问题 |
|---|---|---|
| 路过归因 | 路径中所有触点都计 | 重复计算，各场域之和 > 实际 |
| 唯一归因 | 只算一次，按规则分配 | 场域 GMV 绝对值下降，团队 KPI 难看 |
| 末触归因 | 最后一个触点 | 忽视种草价值，重定向被严重高估 |
| 数据驱动归因（DDA） | Shapley 值 / 马尔可夫链 | 模型复杂，可解释性差 |

> **根本矛盾**：技术最优解（唯一归因）与组织激励（各团队要涨 KPI）之间的冲突。
> 面试时补一句自己的判断："归因模型的选择从来不只是技术问题，还涉及各团队的 KPI 分配，所以落地时往往要找一个'技术上可接受、组织上可执行'的折中。"

## 六、冷启动

### 6.1 标准做法（三层）

1. **冷启动保护期**：新广告给固定探索预算，不让成本波动直接把它打死
2. **探索流量池**（典型 10%）：用探索流量快速积累样本
3. **贝叶斯平滑 + 渐进退出**：样本少时用先验平滑预估，样本够了再逐步退出保护

### 6.2 常见误区（面试必答，显得真做过）

1. **频繁改出价** —— 冷启动期模型在探索，频繁改出价会打乱学习，**延长**冷启动周期
2. **跑一天就关停** —— 样本量不足就判死刑，很多计划只是还没度过探索期
3. **一次性大幅加预算** —— 预算翻倍导致流量池突变，模型要重新学习，成本大概率反弹；**正确做法是每次加预算不超过 20%-30%**

### 6.3 标准话术

> "冷启动阶段我不会只看绝对成本下结论，因为小样本的随机波动很大。首先判断**样本量是否足够**（至少积累 30 个转化、置信区间波动在可接受范围），再评估效果。前期重点看**健康度**：拿量能力、CTR、链路通畅度、转化信号，用来预判这个计划能不能跑起来。同时避免频繁调价、过早关停、大幅加预算这三类会干扰模型学习的操作。"

## 七、数据与对账（DSP 岗的硬功夫）

### 7.1 四方数据差异全景

| 数据方 | 统计节点 | 大小关系 | 正常差异率 |
|---|---|---|---|
| **ADX 侧** | 赢单即算曝光/点击 | 最大 | 基准 |
| **DSP 侧** | 创意加载成功算曝光，客户端点击算点击 | 小于 ADX | 曝光差异 **5%~15%** |
| **第三方监测** | 用户端像素触发才算 | 小于 DSP | 再差 **5%~10%** |
| **广告主后端** | 用户真实到达/激活/注册 | 最小 | 到达率 **60%~90%** |

### 7.2 差异原因（逐层）

- **ADX > DSP**：赢单后创意加载失败、用户快速划走、网络超时、广告拦截插件
  → **差异率 > 20% 属异常**，排查创意尺寸、加载速度、超时率
- **DSP > 第三方监测**：统计时机不同（DSP 服务端计数 vs 第三方客户端像素）+ 广告拦截/禁用第三方 Cookie/用户跳离过早
  → **差异率 > 15%** 排查监测链接部署、像素触发位置
- **点击 > 到达**：落地页加载慢、用户中途关闭、监测跳转故障、作弊流量
  → **到达率 < 50% 属异常**，优先排查落地页和作弊
- **转化数据对不上**：归因窗口不同（平台默认 7 天点击归因 vs 广告主 30 天）、归因模型不同、转化回传延迟

### 7.3 对账标准化步骤
1. **先拉平规则**：统一统计时间、时区、指标定义、归因窗口、过滤规则
2. **再算差异率**：逐层算，和正常区间比
3. **定位异常层**：哪一层差异率超阈值，就从那一层往下钻

## 八、异常排查四步法（面试高频，结构化答题模板）

### 第一步：先确认"是不是真异常"——排除三个假异常
1. **口径问题**：统计时间窗口不一致、数据延迟（转化回传延迟）、指标定义变了
2. **大盘周期波动**：周末/工作日差异、节假日、海外时区差异、行业大盘整体波动
3. **数据报错**：监测链路故障、ADX 接口异常、数据上报丢包

> ⚠️ 程序化场景特别注意：**转化有延迟，当天的 CPA 一定不准**，至少要看 **T+3 甚至 T+7** 的回溯数据，不能拿当天实时数据就判断"成本炸了"。

### 第二步：按转化漏斗从上到下拆，定位流失层
```
ADX 询价量 → DSP 参竞量 → 曝光量 → 点击量 → 到达量 → 转化量
```

| 异常现象 | 优先排查层级 | 常见根因 |
|---|---|---|
| 整体消耗暴跌、拿不到量 | 询价 → 参竞 | ① ADX 询价覆盖率下降（询价优化把你降权）② ID 映射匹配率暴跌 ③ 出价过低 ④ DSP 超时率飙升来不及回包 |
| 曝光正常，点击量暴跌 | 曝光 → 点击（CTR） | ① 素材衰减疲劳 ② 流量质量变差 ③ 定向放宽，人群不精准 |
| 点击正常，到达暴跌 | 点击 → 到达 | ① 落地页故障/加载失败 ② 监测跳转链路断了 ③ 作弊流量涌入 |
| 点击正常，转化暴跌 | 到达 → 转化 | ① 广告主回传延迟 ② 归因口径变化 ③ 落地页改版 |

### 第三步：维度拆解，定位具体子集
- **流量维度**：分 ADX 渠道、分媒体站点、分广告位类型
- **业务维度**：分广告主行业、分投放策略、分人群包、分素材
- **时间维度**：分时点看**突变还是渐变**
  - 突变 → 一般是配置/接口故障
  - 渐变 → 一般是素材衰减、竞争加剧

**案例（可直接讲）**：
> 整体 CPA 涨 20% → 漏斗看是 CVR 跌 → 拆媒体发现 X 媒体 CVR 跌 50% 且占总消耗 40% → 根因锁定 X 媒体流量质量变化 → 进一步排查是该媒体作弊流量增加还是定向偏移。

### 第四步：给出动作并验证
- 短期止血（暂停/降预算/换素材）+ 长期修复（模型/链路/策略）
- **必须做 AB 或分流量验证**，不要全量改

> 第 10 题的标准答案骨架：
> 相同点——都是 `预估分 × 出价/价值` 的统一排序框架，都要校准、都要处理位置偏差。
> 不同点——① 广告排序直接对**收入**负责，出价是广告主的真实约束，必须成本可控；推荐排序对**体验/留存**负责，没有"出价"这个硬约束。② 广告有**预算 pacing** 这个外生约束，推荐没有。③ 广告的"转化"定义受广告主归因口径影响，比推荐的 label 更"脏"。
