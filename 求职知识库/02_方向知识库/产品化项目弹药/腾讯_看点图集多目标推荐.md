# 腾讯_看点图集多目标推荐

## 产品定位（一句话）
QQ看点图集（多图内容）及短内容场景的多目标推荐系统，从单一点击率优化演进为ESMM/MMoE多目标精排+多目标召回，同时优化点击、时长、互动、转化，带动大盘时长和DAU增长，并沉淀为可复用的品类推荐中台。

## 背景与业务问题
- 图集是QQ看点核心消费场景之一，但早期推荐只用单一点击率目标，导致"标题党"内容占便宜，用户点进去不看、互动差，时长和留存受损。
- 点击、时长、互动、转化四个指标互相打架：点击率高的内容时长短，互动高的内容曝光少，转化稀疏难以建模。
- 召回侧也只按相关度召回，没有考虑多目标质量，候选集本身就有偏。
- 看点同时有图集、小说、短内容等多个品类，各品类推荐逻辑不统一，重复建设。

## 目标与核心指标
- **北极星指标**：大盘累积使用时长、广义DAU、DAU留存
- **过程指标**：
  - 短内容浮层时长、短内容总时长、篇均时长
  - 互动行为（点赞/评论/分享）、进评论率/进评论数
  - 模型AUC、线上CTR
  - 召回覆盖率、多样性

## 方案设计
整体演进路线：**单目标LR → 多召回+粗排 → DCN精排 → ESMM多目标 → MMoE多目标（无量3.0）→ 多目标召回下沉**

```
2019.01-06  基础建设期
  ├─ 召回：现网画像/协同 → new_w2c/deeprecall/usercf/全局热门/标签/分类
  ├─ 粗排：原规则 → 7天点击率 → 威尔逊分数 → 点击率综合打分
  └─ 精排：LR(TensorFlow) → DCN模型排序
       AUC: 0.546 → 0.639, CTR: 0.1179 → 0.1219

2019.09-10  多目标精排期
  ├─ 图集点击+转化 ESMM：曝光层对齐样本空间，pCTCVR=pCTR×pCVR
  └─ 图集点击+时长 ESMM：加入时长目标，兼顾点击和深度消费

2020.04-06  短内容多目标期
  ├─ 短内容浮层多目标精排：同时优化停留时长+用户互动
  ├─ 短内容浮层多目标召回：多目标从精排下沉到召回
  └─ 无量3.0 MMoE全量上线：BG第一个在无量3.0全量多目标的业务

2020+  品类中台化
  └─ 图集推荐技术方案推广至小说、短内容等新品类，成为品类研发中心推荐小业务中台
```

**召回架构（6+路）**：
```
用户请求
  ├─ 现网画像召回（GALLERY_ARTICLE_PORTRAIT_TAG_RECALL）
  ├─ 现网协同召回（GALLERY_CURW2C_RECALL）
  ├─ 新版协同new_w2c（GALLERY_NEWW2C_RECALL）
  ├─ 深度召回DNN（GALLERY_DNN_RECALL / gallery_feeds_recall_deep_recall）
  ├─ UserCF召回（GALLERY_USERCF_RECALL）
  ├─ 全局热门兜底（GALLERY_GLOBAL_HOT_RECALL，200个结果）
  ├─ 标签召回（GALLERY_TAG_RECALL）
  └─ 分类召回（GALLERY_CH1_RECALL）
  ↓ 粗排（7天点击率/威尔逊分数/综合打分）
  ↓ 精排（LR → DCN → ESMM → MMoE）
  ↓ 兜底（点击率阈值0.03/0.01，威尔逊热门兜底，协同兜底）
```

## 技术实现要点

### 特征体系
- **用户特征**：年龄、性别、省份、城市、用户画像（一级/二级/三级分类+标签）、实时画像（最近点击序列生成）
- **图集数值特征**：PicCount（图片数）、ReadNum、ClickNum、ExpNum、ClickRate、QualityScore、r_click_num/rate、r_exp_num、r_lifetime、r_pic_count、r_total_num/time、r_valid_click/rate、r_read_num
- **图集类别特征**：ChannelId、Author(puin)、article_ch1/ch2、tag1/tag、panda_ch1、r_reason、r_rowkey
- **序列特征（16维）**：r_exp_cnt、read_cnt、read_end_cnt、to_next_cnt、read_pic_cnt等用户-图集交互序列
- **特征上报**：seq_id、recall_reason后台透传，recall_score特征上报，用户最近点击序列上报

### 模型演进
- **LR基线**：8天数据，CTR特征，AUC(0.5761, 0.6101)，线上CTR 0.1179
- **LR+valid_ctr**：8天数据，AUC(0.5794, 0.6142)，线上CTR 0.1219
- **DCN精排**：多召回+DCN模型排序（57号桶 vs 56号桶7天点击率排序）
- **ESMM多目标**：两个共享底座的塔（pCTCVR塔和pCTR塔），样本空间统一到曝光层，用pCTCVR=pCTR×pCVR乘法关系拆解稀疏转化目标，避免选择偏差
- **MMoE多目标**：多专家多门控结构，同时优化停留时长和用户互动，通过无量3.0平台部署

### 向量化/召回模型实验
- word2vec、fasttext文本向量化
- YouTube DNN召回模型
- node2vec图嵌入
- 深度召回模型gallery_feeds_recall_deep_recall

### 数据规模
- 用户数(uin)：49,723,323（约5000万）
- 图集数(rowkey)：148,470
- 曝光数：225,283,364（约2.25亿）
- 用户平均消费图集数：4.53
- 正负样本比：0.0375（约1:27）

### 工程平台
- **无量3.0**：负责快速对接无量3.0平台，MMoE模型全量上线，成为BG第一个在无量3.0全量上线多目标的业务
- **算法中台**：提供品类推荐训练pipeline（kandian_categroy_rank_model），方便特征添加、模型实验、模型上线
- **开源组件**：模型统一实现方案，模块组件化，企业微信上腾讯网、波动星球、全民K歌、微信支付等业务咨询借鉴

## 亮点与难点
- **多目标从精排到召回的全链路下沉**：不仅精排用MMoE，还把多目标信号下沉到召回，让候选集质量也按多目标优化，进评论率提升80%。
- **ESMM解决转化稀疏**：图集转化样本极其稀疏（正负比1:27），通过曝光层样本空间对齐和pCTCVR=pCTR×pCVR乘法关系，避免在点击后样本上学CVR的选择偏差。
- **无量3.0首个全量多目标业务**：牵头对接新平台，踩坑铺路，为后续业务接入提供参考。
- **从单场景到品类中台**：图集推荐技术方案推广到小说、短内容等新品类，沉淀为品类研发中心推荐的小业务中台，避免重复建设。
- **召回体系从1路到8路的完整建设**：从现网画像/协同单路，逐步扩展到new_w2c、deeprecall、usercf、全局热门、标签、分类等多路召回，并配套粗排、兜底、标签扩展实验。
- **模型统一实现开源**：将深度模型组件化，提升模型搭建效率，被多个BG内外业务借鉴。

## 复盘与局限
- **时长建模方式仍有探索空间**：时长目标用连续值/分档/顺序哪种方式最优，材料中提到做了实验但未记录最终结论。
- **召回负样本优化**：提到从"相关度不好"的样本里选负样本的方法论，但具体策略和效果未详细记录。
- **多目标权重调参**：MMoE各目标的loss权重如何平衡，材料中未记录具体调参过程和最终权重。
- **冷启动内容覆盖**：图集新内容冷启动策略在本项目中不是重点，主要靠全局热门兜底。
- **实验体系**：早期实验桶规划（50-90号桶）较粗放，部分实验效果列未填写，说明实验跟踪和结果沉淀不够系统化。

## 可迁移点
- **多目标推荐全链路方法论**：ESMM（转化稀疏场景）→ MMoE（多目标平衡）→ 多目标召回下沉的演进路径，可迁移到电商、广告、内容等任何多指标优化场景。
- **品类推荐中台化经验**：从单品类推荐到多品类复用的技术抽象和pipeline建设，可迁移到有多个内容品类的平台。
- **召回体系建设方法论**：从单路到多路召回、粗排、兜底、标签扩展的完整实验框架，可迁移到任何推荐系统冷启动阶段。
- **新平台快速接入能力**：无量3.0从对接到全量的踩坑经验，可迁移到任何算法平台迁移/升级场景。
- **模型组件化开源思路**：将模型实现模块化、可复用，提升团队效率的工程实践。
