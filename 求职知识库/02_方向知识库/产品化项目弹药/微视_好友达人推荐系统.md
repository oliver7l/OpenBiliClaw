# 微视好友达人推荐系统

## 产品定位（一句话）
基于微信/QQ关系链与社交图谱，为微视用户在"发现好友页""关注页""消息页"三大场景提供"好友+达人"混合推荐，驱动关注渗透率与社交关系链冷启动。

## 背景与业务问题
- 微视DAU中近73%用户为"0关注"，登录用户中近40%（约630万）为0关注，其中300万已授权关系链但未充分利用（来源：关注价值分析.txt）。
- 授权关系链的1000万用户中70%未关注好友，好友关系链作为社区冷启动来源未被充分使用（来源：关注价值分析.txt）。
- 推荐页每天触达超3000万用户，但关注转化率仅0.8%；近一半关注行为发生在个人主页，个人页关注转化率3.6%，有较大提升空间（来源：关注价值分析.txt）。
- 推荐页中好友关系VV占比仅0.15%，关注关系VV占比仅1.4%，社交关系分发严重不足（来源：关注价值分析.txt）。

## 目标与核心指标
- **北极星指标**：关注渗透率（降低0关注用户占比）、关注好友用户占比、人均日均关注次数。
- **过程指标**：发现好友页/关注页/消息页的pCTR、uCTR（人均点击率）、关注转化率。
- **业务指标**：推荐页好友VV占比、关注关系VV占比、关系链Push拉活量。

## 方案设计（含技术栈/模型/表，可用ASCII图）

### 整体链路
```
用户请求 → 多路召回 → 粗排(LR) → 精排 → 混排/规则 → 曝光
            │
   ┌────────┼────────┬──────────┐
   ▼        ▼        ▼          ▼
 一度好友  二度好友  达人推荐   Graph Embedding
 (微信/QQ) (共同好友) (权威等级)  (图谱召回)
```

### 召回层
- **一度好友召回**：基于微信/QQ授权关系链，从 `wesee::t_complex_first_hop_fri` 表获取用户的微信好友、QQ好友列表。
- **二度好友召回**：基于共同好友数（Jaccard相似度），从 `wesee::t_complex_two_hop_fri_total` 表获取二度好友。
- **达人召回**：基于作者权威等级信号（发文质量、粉丝规模、领域集中度），筛选高权威达人候选。
- **Graph Embedding召回**：基于社交图谱的DeepWalk/Node2Vec向量，通过ANN检索相似用户（详见embedding实验卡片）。

### 排序层（LR + FTRL）
- **模型**：Sparse LR with FTRL（稀疏逻辑回归 + 在线学习），代码 `SparseLRWithFTRL.scala`。
- **样本**：过去7天数据；正样本=关注+查看主页；负样本=有关注/点击行为的Item之前曝光未点击的Item；正负样本比1:10。
- **训练平台**：Tesla ML平台（projectId=19688, flowId=88460），模型存储HDFS。
- **线上服务**：特征共享内存 `weishi_recall:growth_person_lr_model`，Angel LR模型。

### 特征体系（三大类）
| 特征分类 | 维度 | 数据源表 |
|---|---|---|
| 用户特征 | 性别/年龄/地区/学历、一级兴趣、粉丝数/关注数/评论/点赞/分享、已关注微信/QQ/一度/二度好友数 | `t_ug_push_user_attributes`、`t_fri_rcmd_followlist`、`growth_user_stat_up` |
| Item特征 | 性别/年龄/地区/学历、一级类目兴趣、粉丝数/关注数/作品数/被点赞/被评论/被分享 | `t_ug_personid_userprofile_day`、`weishi_public_video_info_dim_daily` |
| 交叉特征 | 共同好友数、好友关系类型(一度/二度/微信/QQ)、item与user已关注人的社交关联数、User关注数×Item粉丝数等乘积特征 | `t_complex_first_hop_fri`、`t_fri_rcmd_followlist` |

### 三大场景差异化
- **发现好友页**：以一度/二度好友为主，达人补充，目标是关系链冷启动。
- **关注页**：以用户已关注人的相似达人为主，目标是关注关系扩展。
- **消息页**：结合社交互动信号，推荐可能产生互动的好友/达人。

## 技术实现要点
1. **离线数据流水线**：Scala + Spark，样本生成（`DataInstance.scala`）→ 特征拼接（`FeatureConcate.scala`）→ FTRL训练（`SparseLRWithFTRL.scala`），TDW表 `t_fri_ranking_sample_day` 存储训练数据。
2. **正负样本构造策略**：负样本采用"曝光未点击且在正样本Item之前曝光"的策略，避免位置偏差；正负比1:10控制训练效率。
3. **社交图谱特征工程**：共同好友数用Jaccard系数计算；社区特征（item与user已关注人的微信/QQ好友关联数）是强特信号。
4. **多场景统一模型**：一套LR模型服务三大场景，通过场景特征和召回源差异实现差异化，降低维护成本。
5. **Graph Embedding融合**：将图谱向量作为召回路补充，实验显示发现好友页pCTR相对提升11.19%（10%流量，2天数据），uctr相对+6.29%（来源：各种emb实验.txt）。

## 亮点与难点
- **亮点1：从0到1搭建好友推荐全链路**。涵盖关系链数据摸底、召回策略设计、LR排序模型训练上线、多场景适配，是完整的推荐系统工程。
- **亮点2：社交图谱特征的深度挖掘**。共同好友数、社区关联特征、一度/二度/微信/QQ关系类型等社交特征是关注推荐的核心强特，远超传统内容推荐特征。
- **亮点3：数据摸底驱动策略**。先做全面的数据摸底（0关注占比、关系链覆盖率、各场景转化率、关注漏斗），再针对性设计优化策略，避免盲目迭代。
- **难点1：关系链数据覆盖与权限**。微信/QQ关系链数据需要申请权限，部分表（如 `t_ug_push_user_attributes`）覆盖度不足（如学历特征），需要多源补全。
- **难点2：关注行为稀疏性**。关注转化率仅0.8%，正样本极其稀疏，LR模型在稀疏场景下的训练需要FTRL在线学习和合理的负采样策略。
- **难点3：多场景效果平衡**。发现好友页、关注页、消息页的用户意图和候选池差异大，统一模型需要在各场景间取得效果平衡。

## 复盘与局限
- **复盘**：好友达人推荐系统的核心价值在于利用微信/QQ关系链这一微视独有的社交资产，解决内容推荐无法解决的"冷启动+社交沉淀"问题。数据摸底阶段发现的73%零关注、70%关系链未利用等问题，直接指导了后续"场景化推人""个人主页优化""关注价值因果分析"等一系列项目的优先级排序。
- **局限1**：LR模型表达能力有限，在关注行为极度稀疏的场景下，复杂的用户-达人交互模式难以被LR捕捉，后续可升级为DNN/DeepFM等模型。
- **局限2**：关系链数据依赖用户授权，未授权用户无法使用好友召回，达人推荐成为唯一路径，效果受限。
- **局限3**：排序模型上线效果在材料中未记录（标注"待产出"），无法量化LR排序相对于规则排序的提升。
- **局限4**：Graph Embedding实验虽在pCTR/uctr上有提升，但未记录最终是否全量上线，以及对关注转化率和留存的长期影响。

## 可迁移点
1. **社交关系链推荐方法论**：关系链数据摸底→一度/二度召回→社交特征工程→多场景适配的完整框架，可迁移到任何有社交关系链的产品（如短视频、社区、直播）。
2. **稀疏行为场景的LR+FTRL方案**：在关注/收藏等稀疏正样本场景下，FTRL在线学习+合理负采样的LR方案是工程性价比极高的基线。
3. **数据摸底驱动项目优先级**：先做全面的数据摸底（覆盖率、转化率、漏斗、用户分层），用数据说话确定优化方向，这一方法论可迁移到任何推荐/增长项目。
4. **多场景统一模型+差异化召回**：一套排序模型服务多个场景，通过召回源和场景特征实现差异化，降低维护成本，适用于多入口产品。

## 面试话术（150-250字，STAR，第一人称，可直接背诵）
在腾讯微视期间，我负责好友达人推荐系统的从0到1搭建。当时微视DAU中73%的用户是零关注，授权关系链的1000万用户里70%没关注好友，社交资产完全没被用起来。我先做了全面的数据摸底，摸清了零关注占比、各场景转化率、关注漏斗等核心数据，然后设计了"一度好友+二度好友+达人+Graph Embedding"的多路召回架构，排序层用LR+FTRL模型，构建了用户特征、Item特征、交叉特征三大类共数十个特征，其中共同好友数、社区关联数等社交特征是核心强特。系统上线后覆盖发现好友页、关注页、消息页三大场景，Graph Embedding召回实验在发现好友页pCTR提升11%。这个项目让我深刻理解了社交推荐和内容推荐的本质差异——关系链是微视独有的护城河。
