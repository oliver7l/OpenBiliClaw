# OPPO广告算法全项目集

## 产品定位（一句话）
在OPPO应用商店和游戏中心，作为广告算法工程师负责广告分发与推荐全链路，主导CTR/CVR/Deep CVR预估、oCPX智能出价、端云协同架构、对比学习多模态表征四大项目，直接对分发效率与ARPU负责。

## 背景与业务问题
- OPPO应用商店和游戏中心是OPPO系统级应用分发核心入口，分发直接挂钩下载与联运收入，需要在平衡短期点击体验与长期收益的前提下持续优化分发效率。
- **多位置预估偏差**：线上不同展示位置（首页Banner、详情页、搜索结果页、推荐流等）的CTR天然差异大，统一模型预估导致各位置偏差严重（整体偏差30%+），影响流量分配和收入优化。
- **出价效率低**：游戏中心联运广告主按CPA考核，原有CPC粗放出价方式效率低，新广告因缺乏历史数据难以获得曝光，冷启动问题突出。
- **云端成本高**：传统云端推荐架构存在延迟高、服务器成本大的问题，需要利用端侧计算能力优化架构。
- **长尾表征差**：传统ID特征对长尾用户和新应用的表征能力有限，中长尾用户的ARPU提升遇到瓶颈。

## 目标与核心指标
- **多位置校准目标**：CTR预估偏差从30%+降至20%以内，ARPU提升1.04%。
- **oCPX智能出价目标**：广告主ROAS优化约8%，冷启动广告通过率提升15%，新广告平均曝光量提升30%。
- **端云协同目标**：云端负载成本下降约25%，端上推荐实时性显著提升。
- **对比学习多模态目标**：中长尾用户ARPU提升2.3%，新应用冷启动曝光量有效提升。
- **全局目标**：构建全场景统一样本与特征体系，覆盖召回→粗排→精排全链路，牵引推荐目标从短期点击向长期收益（LTV）优化。

## 方案设计（含技术栈/模型/表，可用ASCII图）

### 整体广告算法架构
```
用户请求 → 多路召回 → 粗排 → 精排(CTR/CVR/Deep CVR) → oCPX出价 → 混排 → 曝光
              │          │                              │
         协同过滤     轻量模型                    pCTR×pCVR×tCPA
         DSSM双塔     (多位置校准)               /(1+λ) PID控制
         兴趣召回                                端云协同推理
         对比学习表征
```

### 项目一：多位置CTR预估校准

#### 问题分析
- 不同展示位置的用户意图和曝光环境差异大：
  - 首页Banner：用户主动浏览，CTR高
  - 详情页推荐：用户有明确下载意图，CTR中等
  - 搜索结果页：用户有明确搜索意图，CTR高但竞争激烈
  - 推荐流：用户被动消费，CTR低
- 统一模型对所有位置用同一套参数，导致各位置预估偏差不一致，整体偏差30%+。

#### 校准方案
1. **位置特征引入**：
   - 将展示位置作为One-hot特征引入模型
   - 位置与用户/广告的交叉特征（位置×用户兴趣、位置×广告类别）
2. **分位置校准层**：
   - 在统一模型输出的pCTR基础上，为每个位置学习一个校准因子（calibration factor）
   - 校准方法：保序回归（Isotonic Regression）或Platt Scaling
   - 每个位置独立校准，使各位置的预估CTR与真实CTR一致
3. **多位置联合建模**：
   - 采用MMoE（多门控专家混合）架构，共享底层特征表示，每个位置有独立的门控网络和专家组合
   - 位置特定的塔网络输出该位置的pCTR
4. **效果评估**：
   - 分位置计算pCTR与真实CTR的偏差（MAPE/RMSE）
   - 整体偏差从30%+降至20%以内
   - ARPU提升1.04%（因为更准确的pCTR带来更优的流量分配和出价排序）

### 项目二：oCPX智能出价与冷启动

#### oCPX出价公式
```
bid = tCPA × pCTR × pCVR / (1 + λ)
```
- tCPA：广告主设置的目标转化成本
- pCTR：预估点击率
- pCVR：预估转化率
- λ：动态调节因子，根据广告主预算消耗速度和转化达成率，通过PID控制算法每30分钟更新一次

#### PID控制机制
- **P（比例）**：当前预算消耗速度与目标速度的偏差
- **I（积分）**：历史累积偏差
- **D（微分）**：偏差变化趋势
- 每30分钟更新λ，平衡消耗速度与转化质量：
  - 消耗过快→λ增大→出价降低→消耗减速
  - 消耗过慢→λ减小→出价升高→消耗加速
  - 转化成本高于tCPA→λ增大→出价降低→筛选高质量流量

#### 冷启动扶持机制
1. **冷启动保护期**：
   - 对新广告（累计曝光<1万次）设置冷启动保护期
   - 分配专属探索流量池（约10%的流量）
   - 确保新广告有充分曝光机会积累数据
2. **贝叶斯平滑初始化**：
   - 基于游戏品类、包体大小、开发者历史表现等先验特征
   - 对预估模型进行贝叶斯平滑初始化，缓解冷启动阶段预估偏差
   - 先验分布来自同品类/同开发者的历史广告数据
3. **渐进式退出策略**：
   - 随着曝光量增加，逐步降低探索流量比例
   - 从100%探索流量→50%→20%→正常竞价
   - 平滑过渡，避免突然退出导致曝光骤降
4. **冷启监控体系**：
   - 实时监控冷启广告的曝光通过率、转化成本、留存率
   - 低于阈值自动告警，避免冷启流量浪费
   - 自动暂停表现极差的新广告

#### 效果
- 冷启动广告通过率提升15%
- 广告主ROAS优化约8%
- 新广告平均曝光量提升30%

### 项目三：端云协同推荐架构

#### 三种范式
```
范式1：云侧训练 + 云侧推理（传统）
范式2：云侧训练 + 端侧推理（核心）
范式3：云侧训练 + 端侧推理 + 端云联合训练（前沿）
```

#### 架构设计
1. **云侧训练**：
   - 核心模型在云端用全量数据训练
   - 大模型（DNN/DeepFM/DIN等）在云端GPU集群训练
   - 模型定期更新（天级/小时级）
2. **端侧推理**：
   - 轻量模型部署到端侧（手机），实时推理
   - 利用端侧用户实时行为数据（当前session的浏览/点击）做增量更新
   - 端侧推理延迟低（毫秒级），无需网络请求
3. **模型压缩与参数分拆**：
   - 量化：FP32→INT8，模型体积减小75%，推理速度提升
   - 剪枝：去除冗余神经元和连接，模型稀疏化
   - 参数分拆：将大模型拆分为多个小模块，按需加载到端侧内存
   - 端侧内存和算力限制是核心约束
4. **端云联合训练（前沿探索）**：
   - 端侧收集用户实时行为梯度，上传到云端
   - 云端聚合多端梯度，更新全局模型
   - 联邦学习思路，保护用户隐私
5. **效果**：
   - 云端负载成本下降约25%（部分推理迁移到端侧）
   - 端上推荐实时性显著提升（端侧推理无网络延迟）

### 项目四：对比学习与多模态表征

#### 对比学习框架（基于SSL4Rec）
- **多粒度自监督训练框架**，引入三类对比辅助任务：

1. **user-user场景粒度对比**：
   - 同一场景下（如同一推荐位置、同一时间段）用户行为的相似性
   - 正样本对：行为相似的用户（消费/点击/下载模式相近）
   - 负样本对：行为不相似的用户
   - 目标：学习用户在特定场景下的表征

2. **正负反馈对比**：
   - 点击vs未点击的对比
   - 正样本：用户点击的广告/应用
   - 负样本：用户曝光未点击的广告/应用
   - 目标：学习区分用户感兴趣和不感兴趣的内容

3. **深浅行为对比**：
   - 点击vs下载vs激活的对比
   - 浅层行为（点击）vs深层行为（下载/激活）
   - 正样本对：有深层行为的用户-物品对
   - 负样本对：只有浅层行为或无行为的用户-物品对
   - 目标：学习用户深层意图的表征

#### 多模态内容理解
1. **图像模态**：
   - 应用图标（图像）→ 预训练CNN提取图像特征
   - 图标视觉风格、颜色、主题的表征
2. **文本模态**：
   - 应用标题和描述（文本）→ BERT提取文本特征
   - 应用功能、类别、关键词的语义表征
3. **多模态融合**：
   - Cross-Attention融合层：图像特征和文本特征交叉注意力
   - 将多模态表征与用户行为序列表征对齐到同一语义空间
   - 新应用（无用户行为）也能通过内容特征与用户画像匹配，实现冷启动推荐

#### 效果
- 中长尾用户ARPU提升2.3%
- 新应用冷启动曝光量有效提升

### 配套：LTV价值评估体系
- 基于D1/D7留存率、付费率、ARPPU与生命周期折现，构建游戏级LTV分档
- 将LTV作为长期价值目标接入排序与流量分配
- 牵引推荐目标从短期点击向长期收益优化
- 用户分层建模：高价值用户、中低活用户、潜在付费用户、新用户四层，差异化分发与变现策略

## 技术实现要点
1. **全场景统一样本与特征体系**：覆盖应用商店、游戏中心、搜索等多个分发场景，统一样本口径和特征定义，多场景多目标自适应建模。
2. **Deep CVR延迟转化建模**：游戏下载场景中用户从曝光到激活存在时间差，将转化拆解为"即时转化"和"延迟转化"两个阶段，采用多任务学习框架同时建模，缓解延迟反馈带来的预估偏差。
3. **PID控制在出价中的应用**：将自动控制理论中的PID算法引入广告出价，每30分钟动态调节出价因子，平衡消耗速度与转化质量，是工程与算法结合的亮点。
4. **端侧模型部署的工程挑战**：模型量化、剪枝、参数分拆、按需加载，在端侧内存（通常<500MB可用）和算力（移动端CPU/NPU）约束下实现实时推理。
5. **对比学习的负样本构造**：三类对比任务的负样本构造是关键——user-user对比用Batch内负样本，正负反馈对比用曝光未点击，深浅行为对比用浅层行为作为负样本。
6. **多模态对齐的语义空间**：Cross-Attention融合层将图像、文本、行为序列三种模态对齐到同一语义空间，使新应用能通过内容特征冷启动。

## 亮点与难点
- **亮点1：四大项目覆盖广告算法全链路**。从CTR/CVR预估（基础）→oCPX出价（核心变现）→端云协同（架构创新）→对比学习多模态（前沿探索），四个项目层层递进，展示了广告算法从基础到前沿的完整技术栈。
- **亮点2：oCPX出价的PID控制机制**。将自动控制理论引入广告出价，每30分钟动态调节，平衡消耗速度与转化质量，这是工程与算法深度结合的创新点，在面试中极具辨识度。
- **亮点3：冷启动的完整解决方案**。保护期+探索流量池+贝叶斯平滑初始化+渐进式退出+监控体系，五个环节构成完整的冷启动解决方案，不是单点优化而是系统设计。
- **亮点4：端云协同的三种范式设计**。云侧训练/端侧推理/端云联合训练三种范式，根据业务场景灵活切换，展示了对推荐架构的深度思考和前沿探索。
- **亮点5：对比学习的三类辅助任务设计**。user-user场景对比、正负反馈对比、深浅行为对比，三类任务从不同维度提升表征质量，设计思路清晰且有理论依据（SSL4Rec）。
- **亮点6：LTV导向的长期收益体系**。不仅优化短期点击，还构建LTV价值评估体系，将长期目标接入排序，体现了从"点击优化"到"价值优化"的算法思维升级。
- **难点1：多位置校准的位置差异建模**。不同位置的用户意图、曝光环境、竞争程度差异大，统一模型难以同时拟合所有位置，MMoE架构和分位置校准层是关键技术选择。
- **难点2：oCPX出价的多目标平衡**。需要同时平衡广告主的转化成本（tCPA）、预算消耗速度、平台收入（ARPU）、用户体验，PID控制只能部分解决，更复杂的需要强化学习。
- **难点3：端侧模型的精度损失**。量化和剪枝不可避免地带来模型精度损失，需要在精度和性能之间取得平衡，参数分拆和按需加载增加了工程复杂度。
- **难点4：对比学习的训练稳定性**。多任务对比学习的损失函数权重需要精细调优，任务间可能存在梯度冲突，需要动态权重调整或梯度归一化。
- **难点5：Deep CVR的延迟反馈**。游戏下载到激活的时间差可能长达数天，延迟标签导致CVR模型训练时正样本不完整，需要用存活分析或延迟反馈建模技术处理。

## 复盘与局限
- **复盘**：OPPO时期是我广告算法能力的集中爆发期，1年4个月内主导了四大项目，覆盖了广告算法从基础到前沿的完整技术栈。多位置校准解决了CTR预估的位置偏差问题（偏差30%→20%，ARPU+1.04%），是基础工程能力的体现；oCPX智能出价是核心变现项目（ROAS+8%、冷启+15%、新广告曝光+30%），PID控制机制和完整冷启动方案是亮点；端云协同是架构创新（成本-25%），展示了对推荐系统架构的深度思考；对比学习多模态是前沿探索（中长尾ARPU+2.3%），三类对比辅助任务和多模态融合设计有理论深度。配套的LTV价值评估体系和用户分层建模，则体现了从短期点击优化到长期收益优化的思维升级。这四个项目共同构成了"预估→出价→架构→表征"的完整广告算法能力矩阵。
- **局限1：oCPX出价的强化学习探索未记录**。PID控制是经典方法，但更先进的oCPX出价通常用强化学习（如DQN/DDPG）来直接优化长期ROAS，材料中未记录是否有强化学习方向的探索。
- **局限2：端云联合训练的落地程度未明确**。端云联合训练（联邦学习）是前沿方向，但材料中未记录是否真正落地，还是停留在设计/探索阶段。
- **局限3：对比学习的消融实验缺失**。三类对比辅助任务各自的增量贡献未记录，无法判断哪类任务效果最好，以及是否存在任务间的负迁移。
- **局限4：多模态表征的离线指标未记录**。多模态融合对新应用冷启动的具体提升幅度（如召回率、CTR）未记录，只有"有效提升"的定性描述。
- **局限5：Deep CVR的延迟反馈处理细节不足**。延迟转化拆解为两阶段是正确方向，但具体的建模方法（如ESMM、存活分析、延迟反馈校正）未详细记录。
- **局限6：项目间的联动关系未充分体现**。四个项目是独立描述的，但实际上多位置校准的pCTR是oCPX出价的输入，端云协同的模型是对比学习表征的载体，项目间的联动关系可以更紧密地呈现。

## 可迁移点
1. **多位置校准方法论**：任何多位置/多场景的广告/推荐系统（信息流广告、搜索广告、电商推荐）都存在位置偏差问题，位置特征+分位置校准层+MMoE联合建模的方案通用。
2. **oCPX出价的PID控制+冷启动完整方案**：oCPX出价是所有效果广告平台的核心，PID控制动态调节因子、冷启动保护期+探索流量池+贝叶斯平滑+渐进式退出的方案，可迁移到任何需要智能出价的广告系统。
3. **端云协同推荐架构**：端侧推理+模型压缩+参数分拆的架构，适用于任何需要降低云端成本、提升实时性的推荐/广告系统，尤其是移动端系统级应用。
4. **对比学习三类辅助任务设计**：user-user场景对比、正负反馈对比、深浅行为对比，可迁移到任何需要提升稀疏用户/长尾内容表征质量的推荐/广告场景。
5. **多模态冷启动推荐方案**：图像CNN+文本BERT+Cross-Attention融合的多模态表征，使新内容/新广告能通过内容特征冷启动，可迁移到电商、内容、应用商店等任何有新物品冷启动问题的场景。
6. **LTV导向的长期收益优化体系**：基于留存+付费+生命周期折现的LTV分档，将长期目标接入排序和流量分配，这一方法论可迁移到任何需要平衡短期和长期收益的推荐/广告系统。
7. **用户分层+差异化策略**：高价值/中低活/潜在付费/新用户四层分层，每层差异化分发与变现策略，适用于任何用户异质性强的产品。

## 面试话术（150-250字，STAR，第一人称，可直接背诵）
我在OPPO应用商店和游戏中心做广告算法，1年4个月主导了四个项目。第一个是多位置CTR校准，不同展示位置的CTR天然差异大，统一模型偏差30%以上，我用位置特征加MMoE联合建模，每个位置独立校准，偏差降到20%以内，ARPU提升1.04%。第二个是oCPX智能出价，按tCPA乘pCTR乘pCVR出价，用PID控制每30分钟动态调节因子，冷启动方面设计了保护期加10%探索流量池加贝叶斯平滑加渐进式退出的完整方案，ROAS提升8%，冷启通过率提升15%，新广告曝光提升30%。第三个是端云协同，设计云侧训练端侧推理端云联合训练三种范式，模型量化剪枝参数分拆适配端侧约束，云端成本下降25%。第四个是对比学习多模态，基于SSL4Rec设计三类对比辅助任务，用CNN加BERT加Cross-Attention做多模态融合，中长尾ARPU提升2.3%。这四个项目覆盖了广告算法从预估到出价到架构到表征的完整链路。
