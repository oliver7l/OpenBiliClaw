# 腾讯_UGC内容推荐召回体系

## 产品定位（一句话）
QQ看点UGC内容（短视频/图文）的召回体系，通过内容池分层管理、画像召回、Embedding/DSSM向量召回、冷启动三档探索等多路召回策略，为QB烟火Tab、主Feeds、沉浸式播放等场景提供高质量候选集，解决UGC内容海量但质量参差、新内容冷启动难的问题。

## 背景与业务问题
- QQ看点UGC化后，内容量爆发但质量参差不齐，需要精细化的内容池管理和召回策略。
- 新发布内容缺乏交互数据，传统协同过滤无法覆盖，冷启动通过率低。
- 用户兴趣多样，单一召回源（如画像召回）覆盖不足，需要多路召回来保证相关性和多样性。
- 不同场景（主Feeds、烟火Tab、沉浸式播放）的召回需求不同，需要可配置的召回框架。
- 老用户和新用户行为数据差异大，需要差异化召回策略。

## 目标与核心指标
- **北极星指标**：召回内容的点击率、完播率、消费时长
- **过程指标**：
  - 召回覆盖率（不同召回源的贡献占比）
  - 冷启动内容通过率/曝光量
  - 新用户首屏点击率/消费类目数
  - 内容池规模与更新频率
  - Embedding召回的相关性指标

## 方案设计
整体架构：**内容池分层 → 多路召回（画像+Embedding+冷启动+兜底）→ 场景化配置 → 粗排/精排**

```
内容池分层
  ├─ 大盘池 POOL_RECOM（全量可推荐内容，版本1数量7554）
  ├─ 首屏池 POOL_FIRSTSHOW（高质量内容，用于首屏）
  ├─ 冷启动一档池 POOL_COLDSTART_LEVEL_1（explore_state='10'）
  ├─ 冷启动二档池 POOL_COLDSTART_LEVEL_2（explore_state='20'）
  └─ 冷启动三档池 POOL_COLDSTART_LEVEL_3（explore_state='30'）

多路召回（QB烟火Tab示例）
  ├─ FIREWORK_RECALL（画像召回）
  │    ├─ 老用户：QB画像一级/二级/三级分类 + 标签
  │    └─ 新用户(NEW_USER桶)：简化画像 + 热门兜底
  ├─ Q_FIREWORK_EMBEDDING_RECALL（Embedding/DSSM召回）
  │    ├─ EMB_COVER（封面embedding）
  │    ├─ EMB_TITLE（标题embedding）
  │    ├─ EMB_VIDEO128（视频帧embedding）
  │    ├─ EMB_FIREWORK_CLICK（烟火点击行为embedding）
  │    ├─ EMB_FEEDS_CLICK（主Feeds点击embedding）
  │    ├─ EMB_DSSM_NEW_USER（新用户DSSM双塔）
  │    └─ EMB_DSSM（老用户DSSM双塔）
  ├─ Q_FIREWORK_UGC_COLD_START（冷启动召回）
  │    └─ explore_state档位 + account_merged_score>0.88过滤
  └─ Q_FIREWORK_DOUDI（兜底召回）
       └─ nolan侧 KDWB_RANDOM_BASELINE_RECALL

场景化配置
  ├─ QB主Feeds场景
  ├─ QB烟火Tab
  ├─ 烟火沉浸式播放
  └─ 独立Tab场景
```

**召回命名规范**：队列 `Q_业务_名称`（如Q_FIREWORK_COLD_START），召回策略 `POOL-METHOD`（如POOL_RECOM-QB_CH1），便于配置化和中台管理。

## 技术实现要点

### 内容池分层与过滤
- **PGC内容池**：多版本过滤策略（v1/v2/v3），逐步加入时长过滤、质量分过滤、作者等级过滤等。
- **大盘池**：全量可推荐内容，版本1（2020-12-26）数量7554条。
- **冷启动池**：按explore_state分三档（10/20/30），配合account_merged_score>0.88的账号质量过滤，三档渐进式曝光。
- **内容池更新**：天级/小时级增量更新，过期内容自动退场。

### 画像召回
- **老用户画像**：基于用户历史消费行为生成QB画像，包含一级分类、二级分类、三级分类和标签，按画像匹配内容池中的对应分类/标签内容。
- **新用户画像**：新用户行为少，使用简化画像（注册信息+设备信息+渠道），配合热门内容兜底。新用户分群达7470组（基于OS、isnew、network、profession、gender、education、channel、age_group）。
- **实时画像**：基于用户最近点击序列实时生成画像，用于实时召回（如GALLERY_REAL_TIME_PORTRAIT_RECALL）。

### Embedding/DSSM召回
- **多模态Embedding**：封面（EMB_COVER）、标题（EMB_TITLE）、视频帧（EMB_VIDEO128）三种内容侧embedding，覆盖视觉和文本信号。
- **行为Embedding**：烟火点击行为（EMB_FIREWORK_CLICK）、主Feeds点击（EMB_FEEDS_CLICK），基于用户点击序列训练内容embedding。
- **DSSM双塔召回**：用户塔（用户特征+行为序列）和内容塔（内容特征）分别编码，线上用用户最近点击列表N=10触发，计算cos相似度召回。新老用户分开建模（EMB_DSSM_NEW_USER / EMB_DSSM），解决新用户行为稀疏问题。
- **线上服务**：embedding向量存入ANN索引（如FAISS），线上毫秒级检索topN相似内容。

### 冷启动三档策略
- **一档（explore_state='10'）**：新发布内容初始档位，获得基础曝光，收集初始交互数据。
- **二档（explore_state='20'）**：一档表现好的内容升级，获得更多曝光。
- **三档（explore_state='30'）**：二档表现好的内容升级，接近大盘池曝光量。
- **账号质量过滤**：account_merged_score>0.88，确保冷启动内容来自优质账号，避免低质内容占用探索流量。
- **冷启动目标**：帮助增量内容（视频、UP主）在推荐系统中存活和成长，冷启动池与系统状态（曝光、播放、收敛）、场景、时间相关。

### 新用户专项
- 火锅端新用户曝光二级类目8.5个、播放4.5个；老用户曝光10.7个、播放5个（来源：05_UGC推荐/冷启动.md）。
- 新用户召回以热门+简化画像为主，逐步引入个性化召回。

### 特征体系（配套）
- **亲密度特征**：guid维度（互动汇总/真实曝光点击/时长）+ guid-文章 + guid-puin聚合，输出用户-账号亲密度分。
- **账号特征**：分类、等级、创作能力、粉丝数、关注率/互动率（1h/1day/3day/1week/全时段多时间窗口）。
- **内容特征**：分类、标签、质量分、时长、交互统计。
- **分层**：基础数据（关注/粉丝列表）→ 账号特征 → 用户特征 → 内容特征 → 用户账号亲密度。

## 亮点与难点
- **内容池精细化分层**：大盘池+首屏池+冷启动三档池的五层架构，既保证了核心流量的内容质量，又为新内容提供了渐进式探索通道。
- **7种Embedding召回并行**：封面/标题/视频帧多模态 + 点击行为 + DSSM双塔（新老用户分开），最大化召回覆盖率和相关性。
- **冷启动与账号质量联动**：account_merged_score>0.88的过滤机制，将有限的探索流量导向优质账号的新内容，提升冷启动效率。
- **新老用户差异化召回**：新用户7470组精细分群 + 简化画像 + 热门兜底，老用户全量画像 + 多路Embedding，解决新用户冷启动问题。
- **配置化召回框架**：Q_业务_名称 + POOL-METHOD的命名规范，支持多场景（主Feeds/烟火Tab/沉浸式/独立Tab）灵活配置召回源。
- **召回问题系统化排查**：建立了召回问题排查方法论（召回为空、召回量少、召回不准等场景的定位流程）。

## 复盘与局限
- **冷启动档位升级标准不透明**：材料中记录了三档状态，但未明确各档之间的升级/降级具体指标和阈值。
- **Embedding召回效果未量化**：7种embedding召回各自的贡献占比和效果对比未记录，难以判断哪种embedding最有效。
- **内容池规模偏小**：大盘池仅7554条（版本1），相对于UGC内容总量可能偏小，召回多样性受限。
- **新用户体验仍有差距**：新用户曝光类目8.5个 vs 老用户10.7个，播放4.5个 vs 5个，新用户消费深度明显不足。
- **DSSM召回新老用户分开**：增加了模型维护成本，是否可以用统一模型+新用户特征工程来替代，未做深入探索。
- **兜底策略较简单**：nolan侧随机兜底，缺乏基于场景的智能兜底。

## 可迁移点
- **内容池分层管理方法论**：大盘池+首屏池+冷启动多档池的架构，可迁移到任何UGC内容平台（短视频、图文、社区）。
- **多模态Embedding召回实践**：封面/标题/视频帧+行为embedding的多路向量召回，可迁移到视频推荐、商品推荐等场景。
- **DSSM双塔新老用户分开建模**：解决新用户行为稀疏的召回方案，可迁移到用户增长期的推荐系统。
- **冷启动三档渐进式探索**：explore_state档位+账号质量过滤的冷启动方案，可迁移到内容冷启动、作者冷启动场景。
- **配置化多场景召回框架**：Q_业务_名称+POOL-METHOD的命名规范和场景化配置，可迁移到多入口推荐系统。
