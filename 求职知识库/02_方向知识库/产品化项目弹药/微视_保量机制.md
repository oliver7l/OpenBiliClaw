# 保量机制（一期+二期）

## 产品定位（一句话）
在腾讯内容平台精选频道，从"运营配比保量"升级为"全局定量扶持机制"，用PID控制和缺量分级加权保障有商业化/竞品/品质诉求内容的分发量，同时不损害整体VV。

> 注：本项目实际落地于腾讯视频精选频道（长视频），技术方法论可迁移至微视短视频分发。

## 背景与业务问题
- 业务侧对部分内容有明确的分发量诉求：
  1. 头部内容进行了商业化售卖，为保证贴片收入，内容VV必须达到一定量
  2. 部分内容多平台播放，竞品对比中需要保证平台分发量
  3. 优质/高质量内容为打造品质感，需要分发保障或冷启动扶持
  4. 任务性内容需要保障分发
- 一期保量仅在局部模块（频道页卡头部六小图模块）做曝光配比，与VV有差距，利用率低
- 一期技术上在重排层做加权，召回层是硬性召回，某些模块（如明星模块）不适用
- 新内容如何实时进入召回池是技术难点

## 目标与核心指标
- **一期目标**：在保量模块内按运营配置的曝光占比，用PID控制保证保量内容的曝光量
- **二期目标**：升级为全局定量扶持机制，从召回/排序/外显多层加权，基于预估VV动态调整扶持力度
- **核心指标**：
  - 保量内容的VV达成率（实际VV/预估VV）
  - 精选频道缺量item的总VV、人均时长、人均VV
  - 全局商业化收入
  - 整体VV（不损害为约束）

## 方案设计（含技术栈/模型/表，可用ASCII图）

### 一期：运营配比保量策略

#### 三类海报位
```
海报位
  ├── 运营锁定：新上线内容N天锁定，强曝光诉求（不做曝光过滤）
  ├── 保量配比：按比例对需要保量的内容曝光保量，保证VV要求
  └── 个性化推荐：剩余海报位做长尾推荐，提升整体效果
```

#### 保量配比排序逻辑
- 第一优先级：锁定（不做曝光过滤）
- 第二优先级：保量（依据CMS配置的曝光占比，PID控制保证曝光量+兜底逻辑）
- 第三优先级：推荐（未选取上的保量内容加入推荐召回）
- 排序规则：保量后的分数与推荐pCTR统一排序

#### PID控制机制
```
e(i) = 玲珑系统配置的cid曝光占比 - 实际cid在模块中曝光占比

每5分钟一个分片，保留2小时数据（24个分片）
cidRatio(i) = cidPV(i) / modulePV(i)  （当天0点开始累计）

PID输出 → 调整保量内容的排序分数 → 控制实际曝光占比趋近目标
```

- P（比例）：当前分片的偏差
- I（积分）：历史累积偏差（24个分片）
- D（微分）：偏差变化趋势

#### 兜底逻辑
- 当曝光实时数据延迟10min以上时，按保量1.0方案出：生成随机数，对比配置的曝光占比判断是否出
- 冷启动专辑强制分发（鹰眼日志标识ka2lock），开关amount_cold_start
- 统计数据过期10分钟采用保量随机分发（鹰眼日志标识kard_delay）

#### 支持频道
精选、电视剧、动漫、电影、综艺
- 与运营商议的保量百分比尽量控制在80%以内

### 二期：全局定量扶持机制

#### 升级定位
从局部模块曝光保量 → 全局推荐场景生效的定量扶持机制
- 支持不同类型的保量/冷启动诉求
- 召回+排序+外显三层加权
- 基于预估VV的动态扶持力度

#### 基于预估VV的动态保量流程
```
1. 新栏目/专辑上线前 → 基于相似内容经验+预估总VV(estimate_vv_for_ad) → 预测每集VV
2. 预测item当天VV量 → f(已更新集数, 已更新天数)
3. 实时拉取媒资信息 → item_vv = f(已更新集数,已更新天数) + 前期缺量
4. 预估当天全平台VV → all_vv = f(工作日/节假日/周几/寒暑假)
5. item当天所需VV占比 = item_vv / all_vv → 替代CMS配置
6. 实时统计item信息（分平台分桶：曝光量/播放量/CTR，当天累计+切片）
7. 实时统计全平台VV → 计算item实际VV占比
8. 用"期望VV占比"和"实际VV占比"替代原保量参数 → 传给引擎PID控制
```

#### 三层加权体系
1. **召回层**：召回池粗排时加大保量内容权重，保证进入精排
2. **排序层**：排序时进行pCTR加权
3. **外显层**：曝光/播放过滤、模块间去重、模块内去重、同栏目同系列去重等灵活定义

#### 缺量分级扶持（一二期融合方案）
根据item的预估缺量比例，配置差异化扶持力度：

| 缺量比例 | 扶持力度（pCTR加权倍数） |
|---|---|
| (0, 10%] | 1.05 |
| (10%, 30%] | 1.10 |
| (30%, 50%] | 1.20 |
| (50%, 80%] | 1.30 |
| (80%, 100%] | 1.35 |

配置示例：`"ka_sec_weight":"0_0.1_1.05:0.1_0.3_1.1:0.3_0.5_1.2:0.5_0.8_1.3:0.8_1_1.35"`

- 一期运营配置保量模块保证曝光量，同时引入二期商业化预估VV指标
- 运营调整内容的预估总VV指标，推荐把控保量力度
- 在尽量不降低总VV的同时，帮助运营保量头部内容

#### 数据体系
- 保量item监控报表：有商业化预估VV需求的item，每天下午4点邮件同步给精选频道运营
- VV保量实验效果报表
- 大盘现状监控：头部多个大剧严重缺量的预警

## 技术实现要点
1. **PID控制在分发保量中的应用**：将自动控制理论中的PID算法引入内容分发，每5分钟一个时间分片，用目标曝光占比与实际曝光占比的偏差作为PID输入，输出调整排序分数，动态控制保量内容的曝光量。这与OPPO oCPX出价中的PID控制是同一方法论在不同场景的应用。
2. **基于预估VV的动态目标计算**：不是静态配置曝光占比，而是基于内容的预估总VV、已更新集数、已更新天数、全平台VV预测等多因素，动态计算每个内容当天所需的VV占比，使保量目标更科学。
3. **缺量分级加权的平滑过渡**：根据缺量比例设置5档加权倍数（1.05-1.35），缺量越多扶持力度越大，避免一刀切，同时加权倍数有上限控制对整体VV的影响。
4. **兜底机制的工程健壮性**：数据延迟10分钟以上降级为随机分发，冷启动专辑强制分发，多重兜底保证系统在异常情况下仍能基本运行。
5. **召回+排序+外显三层协同**：不是只在排序层加权，而是从召回层保证保量内容能进入候选池，排序层提升优先级，外显层控制去重过滤，三层协同保证保量效果。
6. **内容实时入库问题**：新内容上线后需要实时进入召回池，这是二期的核心技术难点，需要媒资系统与推荐系统的实时同步。

## 亮点与难点
- **亮点1：PID控制在内容分发中的创新应用**。将自动控制理论引入内容分发保量，用闭环控制动态调整曝光量，比静态配置更精准、更自适应，这在内容推荐领域是较少见的工程创新。
- **亮点2：从局部保量到全局定量扶持的系统升级**。一期只是局部模块的曝光配比，二期升级为覆盖全场景、多层加权、动态目标的定量扶持机制，系统设计能力有质的飞跃。
- **亮点3：缺量分级加权的精细化策略**。5档缺量比例对应5档加权倍数，缺量越多扶持越大，同时有上限约束，在保量效果和整体VV之间取得平衡。
- **亮点4：与OPPO oCPX的PID方法论呼应**。保量机制的PID控制和OPPO oCPX出价的PID控制（每30分钟调节出价因子）是同一方法论在不同场景的应用，体现了跨项目的技术复用能力。
- **亮点5：商业化与推荐的平衡设计**。保量机制的核心约束是"不损害整体VV"，在满足商业化诉求的同时保证用户体验，这是推荐系统中商业目标与用户目标平衡的典型案例。
- **难点1：预估VV的准确性**。动态保量的效果高度依赖于预估VV的准确性，新内容缺乏历史数据，预估偏差会导致保量过度或不足。
- **难点2：内容实时入库**。新内容上线后需要实时进入召回池，涉及媒资系统与推荐系统的实时同步，工程复杂度高。
- **难点3：多内容同时保量的资源竞争**。多个头部内容同时有保量诉求时，有限的保量流量如何分配，需要更复杂的调度机制。
- **难点4：对整体VV的影响控制**。保量内容加权会挤压个性化推荐的流量，如何量化和控制对整体VV的影响，需要精细的实验设计。

## 复盘与局限
- **复盘**：保量机制是推荐系统中"商业目标与用户目标平衡"的典型项目。一期用PID控制实现了局部模块的曝光配比保量，证明了闭环控制在分发场景的有效性；二期升级为全局定量扶持机制，基于预估VV动态计算保量目标，从召回/排序/外显三层加权，用缺量分级加权实现精细化扶持。实验结果显示精选频道综艺品类播放用户+0.78%、VV+0.9%，同时对APP全局影响不显著，验证了"在不损害整体VV的前提下提升保量内容分发"的目标。这个项目与OPPO oCPX出价的PID控制形成方法论呼应，展示了跨场景的技术复用能力。
- **局限1：预估VV的准确性未量化**。动态保量的核心是预估VV，但材料中未记录预估VV的准确率（如MAE/RMSE），预估偏差直接影响保量效果。
- **局限2：多内容同时保量的调度机制未记录**。当多个头部内容同时有保量诉求时，有限流量如何分配，材料中未记录具体的调度策略。
- **局限3：长期效果未追踪**。实验结果只记录了短期的VV/用户变化，保量策略对内容生命周期、用户长期留存的影响未记录。
- **局限4：内容实时入库的解决方案未详述**。二期提到"解决内容实时入库的问题"是难点，但具体的技术方案（如实时消息队列、增量索引更新）未详述。
- **局限5：商业化收入的量化缺失**。项目目标提到"提升全局商业化收入"，但实验结果中未记录收入提升的具体数字，只有VV和用户指标。

## 可迁移点
1. **PID控制在资源分配中的应用**：PID闭环控制可迁移到任何需要动态调节资源分配的场景——广告出价（oCPX）、内容保量、流量调度、库存管理等，核心是"目标值-实际值→偏差→PID输出→调节动作"的闭环。
2. **缺量分级加权的精细化策略**：根据缺口比例设置多档扶持力度，缺口越大力度越大，同时有上限约束，这一思路可迁移到冷启动扶持、新作者扶持、新商品扶持等任何需要差异化扶持的场景。
3. **基于预估值的动态目标计算**：不是静态配置目标，而是基于业务预测动态计算目标值，可迁移到任何有预测能力的资源分配场景。
4. **召回+排序+外显三层协同的保量架构**：从召回层保证进入候选池、排序层提升优先级、外显层控制过滤，三层协同保证扶持效果，可迁移到任何需要内容扶持的推荐系统。
5. **兜底降级机制的工程设计**：数据延迟降级、冷启动强制分发、多重兜底保证系统健壮性，这是任何高可用推荐系统的必备工程能力。
6. **商业目标与用户目标的平衡方法论**：以"不损害整体VV"为约束，在约束内优化商业目标，这是推荐系统中多目标优化的经典框架，可迁移到任何商业化推荐场景。

## 面试话术（150-250字，STAR，第一人称，可直接背诵）
我在腾讯内容平台负责保量机制，从一期做到二期。一期是运营配比保量，把频道页卡的海报位分成运营锁定、保量配比、个性化推荐三类，保量内容用PID控制保证曝光占比，每5分钟一个分片，保留2小时数据，目标占比减实际占比作为偏差输入PID，输出调整排序分数，数据延迟10分钟以上降级为随机分发兜底。二期升级为全局定量扶持机制，不再是局部模块曝光配比，而是基于内容的预估总VV动态计算每天所需的VV占比，从召回、排序、外显三层加权。排序层根据缺量比例设5档扶持力度，缺量0到10%加权1.05倍，缺量80%以上加权1.35倍，缺量越多扶持越大。实验结果精选频道综艺品类播放用户提升0.78%，VV提升0.9%，对APP全局影响不显著。这个项目和我在OPPO做的oCPX出价用的是同一套PID控制方法论，一个管内容分发，一个管广告出价，跨场景复用。
