# 知识库 · Obsidian 改造规范

> 目的：根治「每次整理都要改好多地方」的痛点。
> 关键转变：**把"手写路径索引"变成"自动查询 + 双向链接"**，让专题跟随素材自己长出来。

---

## 一、痛点根因

这套三层结构（01 原始 → 02 方向 → 03 弹药）本身没问题，问题出在**导航引用是手写硬编码的相对路径**：

- README / 专题文档里登记 `01_原始资料库/08_解码文本/04_看点推荐/xxx.txt`
- 一旦移动/重命名/新增文件，就要同步改「总索引 + 专题资料索引 + kb.py 登记 + 看板」多处
- 维护成本随素材量线性上升，越整理越脆

**解法不是"整理得更勤"，而是让引用自动跟随内容。**

---

## 二、采用的三种机制

### 1) Obsidian 双向链接（wikilink）——解决"移动/重命名文件导致引用断裂"

- 写法：`` `02_方向知识库/推荐系统/05_多目标与多任务.md` `` → `[[02_方向知识库/推荐系统/05_多目标与多任务]]`
- **在 Obsidian 内移动/重命名**文件时，所有 `[[...]]` 自动更新（默认开启），永不手改。
- 目录引用：`[[简历库/30_原始简历档案/]]`（带尾斜杠 = 文件夹）。
- 链接文本保留在 `[[...]]` 内，`kb.py` 全文检索不受影响。

### 2) Dataview 动态聚合——解决"新增素材要手动登记一行"

- 每个专题「资料索引」头部放一个 Dataview 查询块，把**专题目录里的所有素材**自动列出来。
- 新增素材 = 直接丢进专题目录 → Dataview 自动收录 → **零登记**。

```dataview
LIST file.name
FROM "02_方向知识库/简历技术专题/01_多目标推荐系统"
WHERE file.name != "README"
SORT file.name ASC
```

### 3) frontmatter 元数据——让"专题打标签"而非"搬文件改引用"

- 每个文档加 YAML 头，承载 `tags / topic / type / updated`。
- Obsidian 用标签做图/反链聚合，专题归属靠标签完成，不靠冗余路径列表。
- 已注入的专题文件见下节「模板」。

> ✅ 已落地：
> - `02_方向知识库/简历技术专题/` 五个文件已改造（01 多目标 / 02 对比学习 / 03 端云协同 / 04 多场景统一建模 + 顶层导航）。
> - `02_方向知识库/` 全部方向文档已批量改造：94 处跨层硬编码路径 → `[[wikilink]]`；6 个方向 README 注入 frontmatter + Dataview 自动聚合。
> 迁移脚本可重复执行（幂等）：
> - `python3 _系统_知识库引擎/scripts/kb_obsidian_links.py`（简历技术专题）
> - `python3 _系统_知识库引擎/scripts/kb_obsidian_links_dir.py`（整个 02_方向知识库）

### 4) 自动打标 + 自动跨链——新增素材连标签/关联也不用手写（`kb.py add / flush` 已内置）

参考 `obsidian-curator` 的 7 步标签管线，在 `kb.py` 里做了两步增强，**全自动、无人工**：

- **规则打标（离线、零延迟）**：`DIR_RULES`（8 个方向）+ `TYPE_RULES`（面经/复盘/题库/弹药）关键词命中即打标。
- **标签别名 + 通用词过滤**：`TAG_ALIAS` 把口语/英文缩写收敛到规范标签（如 `推荐`/`recsys`→`推荐系统`），避免"推荐"和"推荐系统"悬成两个标签。
- **语义兜底（Ollama bge-m3 本地）**：方向标签一个都没命中时，用 bge-m3 把笔记向量跟「方向标签 + 关键词」的 passage 做余弦，`>0.6` 补打方向标签，抓"绕开关键词但明显是某方向"的内容。Ollama 不可用时**静默降级**，绝不影响 `add/flush`。
- **自动跨链**：按「文件夹名包含标签」模糊匹配到专题 README，在笔记末尾追加 `## 关联` wikilink 块，Obsidian 里可直接点跳。

## 三、frontmatter 元数据契约（新文档都按此写）

```yaml
---
tags:
  - <方向标签>          # 如 多目标推荐系统 / 对比学习 / 端云协同 / 多场景统一建模
  - <可选：原始/提炼/弹药>
topic: <专题名>         # 所属专题（与本库 02_方向知识库/简历技术专题 对齐）
type: 专题|导航|索引|笔记|情报|弹药    # 一个取值
updated: 2026-09-09     # YYYY-MM-DD
---
```

### 标签命名建议（保持小写、短横线、同主题同词）
- 用**专题全名**作标签（与专题目录同名），Obsidian 点标签即得该专题全集。
- 可用子标签表达归属层：`多目标推荐系统/原始`、`多目标推荐系统/提炼`。

## 四、新增素材的流程（止痛点，务必照做）

**三种路径，选一种，都不用再"满库搜路径去改多处"。**

### 路径 A · 纯 CLI（最常用，推荐）
```bash
# 新建/归入某专题的带标签笔记（自动重建索引）
python3 _系统_知识库引擎/scripts/kb.py add --topic 对比学习 --title "SIMCLR 要点" --body "自监督对比…"

# 从文件导入
python3 _系统_知识库引擎/scripts/kb.py add --topic 端云协同 --title "端云重排复盘" --file /tmp/草稿.md
```

### 路径 B · 收件箱自动归类（完全无人值守）
把资料丢进 `_收件箱/`，文件名用「下划线前缀 = 专题名」命名，脚本自动归类成笔记并重建索引：
```bash
# 单次处理一批
python3 _系统_知识库引擎/scripts/kb.py flush

# 常驻监听（丢文件即自动处理，适合长期开着）
python3 _系统_知识库引擎/scripts/kb.py watch
```
示例：丢 `对比学习_SIMCLR复盘.md` → 自动进 `02_方向知识库/简历技术专题/02_对比学习/`，无需任何登记。
> 说明：前缀必须命中白名单（8 方向 / 4 题型 / 既有专题目录），否则归入「未分类专题」；无下划线的文件同样归「未分类专题」。这样避免随此前缀自动新建一堆碎片专题目录（新专题用 `kb.py add --topic` 显式创建）。处理后的文件被移到 `_收件箱/_已处理/`。可用 cron 定时跑 `flush` 实现"定时自动清理收件箱"。

### 路径 C · Obsidian 内操作（配合可视化）
在 Obsidian 里直接把文件拖进专题目录、或右键重命名——`[[wikilink]]` 自动跟随，观察关系图与 Dataview 自动聚合。

> **无论哪条路：新增素材放入专题目录后，Dataview 与 `kb.py 索引` 会自动收录，无需手改「资料索引」。**

### 原始材料仍然放底层
原始 PDF/PPT/解码文本 → 仍丢进 `01_原始资料库/` 对应分类目录（保持现有目录），不改变定位。

## 五、安装与启用（一次性步骤）

1. **安装 Obsidian**
   - 官网下载：<https://obsidian.md/download>
   - 或命令行：`brew install --cask obsidian`
2. **打开本库为 vault**：启动 → "Open folder as vault" → 选择 `求职知识库/` 目录。
3. **启用 Dataview**（动态聚合必需）：
   - `Settings → Community plugins → Turn on community plugins`（关闭受限模式）
   - "Browse" 搜 **Dataview** → Install → Enable
   - 如频繁建新专题，可再装 **Templater**（模板自动填 frontmatter）。
4. 打开任一专题 README，确认 Dataview 块已渲染出素材列表。
5. **断链检查**：左下角命令面板搜 "Unlinked mentions" / 或用搜索 `"[[x"` 找未解析链接。

> 说明：Obsidian 不改变文件系统，vault 目录仍可直接被 `kb.py` 等脚本读取，两者共存不冲突。

## 六、设计决策与取舍

- **为什么用 wikilink 而非继续手写路径**：wikilink 在 Obsidian 内移动时自动更新，这是本轮改造的根本收益。
- **为什么保留"精编注释 + 手动要点"**：资料索引里 `✅ 最全 / STAR / 口径出处` 这类人工判断有信息量，Dataview 只做"机械自动收录"，二者互补而非互斥。
- **为什么 FROM 用完整 vault 相对路径**：Dataview 的 FROM 是相对 vault 根的路径，写全避免歧义。
- **兼容性**：`[[...]]` 内文本仍是路径原文，`kb.py 查 <关键词>` 全文检索不受影响；纯 Markdown 查看器也能读出路径内容。
- **暂不做的**：不为 1450+ 份原始素材批量注入 frontmatter（成本高、收益低）；原始素材靠目录 + kb.py 取数即可，只有"需要进专题聚合"的加工文档才打标。
