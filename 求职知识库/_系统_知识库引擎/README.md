**数据流（完整闭环）：**
```
新岗位
   ↓ ① 匹配评估（五维打分 + deal-breaker，投/谨慎/不投）
   ↓ ② 建目录 + 三件套（JD拆解/攻略/题库）
   ↓ ③ 双 Agent 审查（起草→面试官视角独立审查→修订）
   ↓ ④ ATS 简历校验（文本层 + 关键词覆盖率，差距如实标注）
   ↓ ⑤ 登记系统层（岗位/题索引/概念关系）+ doctor.py 自检 PASS
   ↓ ⑥ 面试前 kb.py 速记/检索
   ↓ ⑦ 面试后 outcome（日志+复盘）+ 校准回路（补题/修正匹配权重/upskill）
```

## 二、为什么用"结构化数据表 + 关键词检索"而不是 RAG

| 维度 | 本方案（结构化+关键词） | RAG（向量语义检索） |
|---|---|---|
| 数字准确性 | ✅ 真实数字表=权威源，查询即精确命中 | ⚠️ 语义检索可能命中错误数字（有幻觉风险） |
| 可审计性 | ✅ 每条数字/记录可追溯来源文档 | ❌ 命中来源不透明 |
| 检索速度 | ✅ 秒级，无环境依赖 | 需向量库环境 |
| 适用阶段 | 当前几百份可检索文档，足够 | 资料膨胀到上千份再考虑 |

**结论：** 简历数字、项目数字都是"精确事实"，结构化查询比语义检索可靠得多。RAG 作为**可选扩展层**保留（见第六节），当前不启用。

### 三层库（kb_layers.py）

原始资料 → 处理库 → 弹药库三层数据库，与 01/02/03 目录分层一一对应：

```
L0 原始库 面试资料总库.db   ← kb_ingest.py（文档抽原文，只读源）
        ↓ 构建
L1 处理库 面试处理库.db     ← 标题感知分块（~1500字/块）+ 段落级 FTS，精确到段落命中
        ↓ 构建
L2 弹药库 面试弹药库.db     ← 7 张 CSV 结构化事实（岗位/项目/数字/题库/日志/概念）
                             + 03_岗位弹药库 104 篇备战文档全文 + FTS
```

```bash
python3 scripts/kb_layers.py 构建                  # 增量构建处理库 + 弹药库（原始库只读）
python3 scripts/kb_layers.py 构建 --库 处理 --强制  # 强制全量重建
python3 scripts/kb_layers.py 统计                  # 三层库规模总览
python3 scripts/kb_layers.py 查 冷启动通过率        # 跨库查询（先弹药后处理）
python3 scripts/kb_layers.py 查 出价 --库 弹药 --岗位 大宇   # 按岗位过滤弹药库
```

约定：L0 由 `kb_ingest.py` 独自维护；L1 按 (doc_id, mtime) 增量续跑；
L2 可随时重建（数据源是 CSV + 03 目录，幂等覆盖）；数字答案永远以
`03_真实数字表.csv`（L2 number 表同源）为权威。

## 六、可选扩展层（RAG，暂不启用）

当资料量膨胀到上千份可检索文档、且需要"模糊语义提问命中"时，可在此层加向量检索：
- 建 `scripts/vector/` 存向量化脚本（embedding → 本地向量库如 Chroma/Faiss）
- **约束：** 向量层只用于"找文档"，**数字答案永远以 `03_真实数字表.csv` 为权威源**，禁止向量命中覆盖真实数字。
- 前置条件：资料量评估通过 + 用户确认启用。

## 七、维护责任

- **内容归位**：新素材 → 01；新方法论 → 02；新岗位 → 03；事实数据 → 数据表；新概念 → 07。谁录入谁负责与总索引同步。
- **数字守门**：任何数字入库前必须在 `03_真实数字表.csv` 核对；查无来源的数字一律不入库、不用于面试回答。
- **复盘闭环**：每场面试结束后 24 小时内更新 `04_面试日志.csv`，并同步到对应岗位目录的复盘文档 + 校准回路。
- **系统健康**：重大变更后跑 `python3 scripts/doctor.py`，PASS 才算完成；大量新增文件后跑 `build_index.py` 重建索引。
