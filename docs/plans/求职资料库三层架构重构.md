### 1.3 脚本层

`_系统_知识库引擎/scripts/` 共 **45 个脚本**。常驻能力其实只有：kb.py（中文子命令 CLI：查/岗位/数字/速记/方向/索引/项目/记录/add/flush/watch/语义）+ ingest/ocr/embed/search_hybrid/doctor 几条链路。其余 30+ 个是 `kb_fix_* / kb_salvage_* / kb_clean_* / kb_split_* / kb_migrate_*` 类**一次性修复脚本坟场**。

### 1.4 乱的五大根因

1. **interview.db 一个库装五种职责**（知识文档/弹药/面试题/简历/岗位/待办），且 job vs job_positions、interview_questions vs iq_* 双套并存。
2. **按来源拆的 18 个分库**（727MB）与统一后的 kb_documents 并存，新旧两代。
3. **knowledge_audit.db 242MB**（100 万行 audit_issues）纯垃圾占空间。
4. **02_方向知识库原始与加工混放**（568 md 无分层）。
5. **45 个脚本无区分**，一次性脚本与常驻能力混在一层。

## 二、三层架构设计（目标态）

```
┌─ L1 原始层（纯文件，不进 DB，整齐归档）
│    求职知识库/01_原始资料库/        ← 全部原始件唯一归口
│      ├ 01_书籍（书/课件/仓库原件）
│      ├ 02_我的笔记（原稿，按来源分子目录）
│      ├ 03_工作资料（内部文档/MIME 解码前的原始导出）
│      ├ 04_幻灯片与分享（PPT/技术分享原件）
│      └ 99_收件箱（flush 前的暂存）
│    简历库/30_原始简历档案/          ← 简历原件（简历流水线自成体系，不迁移）
│
├─ L2 加工层（DB 为唯一事实源，md 为可读镜像）
│    求职知识库/_系统_知识库引擎/数据/  ← 现行 18 个来源分库 + file_index.db
│      （按来源拆库是现行架构，34 脚本依赖，保留；期 1 只迁入 kb_documents 系）
│    data/knowledge.db                ← 知识图谱（现有 entities/relations/cards/topics）
│      + kb_documents + chunks + embeddings（自 interview.db 迁入：02 md 的分块索引）
│    求职知识库/02_加工知识库/        ← md 镜像（方法论档案/项目档案/提炼笔记）
│
└─ L3 应用层（DB 为准，md 为人读视图）— 拆两域
     data/resume.db（简历投递域，独立库）★用户拍板
       ├ companies              公司档案
       ├ job_postings           岗位（公司×岗位名×JD×链接×状态）
       ├ applications           投递记录（岗位×简历版本×日期×渠道×结果）
       ├ job_ammo               岗位弹药索引（源 = 弹药库 md，派生）
       ├ resumes                简历版本（自 interview.db.resumes 迁入）
       └ resume_files           简历文件索引（现有，sha256 去重）
     求职知识库/03_岗位弹药库/        ← 弹药 md（源文件，人读）
     data/interview.db（瘦身后）      ← 面试域
       ├ 面试题：interview_questions（唯一，吸收 iq_*）
       ├ 面试记录：interview_reviews/recordings/scripts/rebuttals
       └ 待办：todo
```

**职责判定一句话**：原始件＝拿来就存不改（L1）；加工＝由原始件推导可重建（L2）；应用＝服务求职动作的事实与记录（L3）。

**双轨治理原则**（对齐内容库 v2 模式）：凡 md 与 DB 并存的，**md 是源、DB 是派生索引**，sync 脚本幂等（键=文件路径）。

## 三、分期实施（低风险先行，每期独立闭环）

## 五、风险与对策

- **最大风险**：kb_documents 迁移牵动 20 个引用文件 + FTS/向量索引重建 → 用"先归档不删除 + 行数对账 + 检索回归"三保险；interview.db 整库先备份。
- 外接盘 IO 缓存假象：迁移脚本全部串行 + 落盘后 python 直读复核。
- 每期独立提交可回滚；求职知识库/简历库目录是 git 外资产，迁移用 mv 前先 cp 备份清单。
