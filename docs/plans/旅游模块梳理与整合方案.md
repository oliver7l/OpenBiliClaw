## 0. 一句话结论

旅游模块的问题不是「没整理」，而是**功能已经在线上坏掉了一半**：桌面端「✈️ 旅行」的三个子标签全部 404，而唯一能出数据的端点桌面端一个都没调。根因是**同一个文件里两套路径机制**，其中一半依赖一个从未被配置的配置段。

真值源方面：**md 定稿与 `travel.db` 不是二选一** —— 它们各自持有对方没有的东西（md 有分钟级叙事，db 有勾选状态）。正确模型是**混合**，见 §3.2。

## 3. 方案

分三步：**Step 1 可立即执行且零拍板依赖**；Step 2 需你先定真值源；Step 3 是补课。

### 3.1 Step 1 —— 先让坏掉的活过来（低风险，不改数据语义）

**1.1 路径机制统一为「配置驱动 + 相对路径按项目根解析」**

现状：DB 端点硬编码 `_project_root()/"data"/"travel.db"`；文档端点在 `data_path == ""` 时直接 404。

改法（`travel/routes.py` + `config.py`）：

1. `TravelConfig` 增字段 `db_path: str = "data/travel.db"`（与 `data_path` 同族，风格参照 `StorageConfig`）。
2. `TravelConfig.data_path` 默认值由 `""` 改为 `"data/travel"` —— **这样桌面端开箱即用**，而不是依赖本地 `config.toml`（该文件在 `.gitignore:132`，换机即丢）。
3. `build_travel_router()` 统一解析 `data_path` / `db_path`：**相对路径一律按 `_project_root()` 解析**，绝对路径原样用；删掉 5 处硬编码。
4. 保留「目录不存在 → 404 带明确中文原因」的行为（现在是对的，别改成静默空数据）。

> 备选（不推荐）：只往 `config.toml` 补 `[travel] data_path`。能立刻修好本机，但**修不了换机/换人**，且违反「默认可用」。

**1.2 修前端契约漂移（`web/desktop/assets/js/app.js`）**

- 提醒卡片改用真实字段：`a.route` / `a.date` / `a.vs_baseline.diff` / `a.lowest_price`。
- 航班时刻改 `r.lowest_departure`，儿童价改 `r.child_fare`。
- 顺带把这段渲染逻辑抽成 `assets/js/travel-view.js`（**纯视图模型，UMD**），沿用本项目已有范式（先例 `interview-schedule-view.js` → `tests/desktop/test_interview_schedule_view_model.py`），让「字段名对得上」由 node 真跑断言守住，而不是 grep 源码。

⚠️ **两个易踩的坑（本轮踩到）**：

1. `_web_ui_routes.py` 里有**两个**名字相似的清单，加错地方不报错但也不生效：
   - 第 82 行的 `for script in (...)` tuple —— **静态资源版本号注入**（`html.replace`
     给 `<script src>` 补 `?v=`）。**新加 JS 登记这里。**
   - 第 119 行的 `_desktop_page_names` set —— `/web/{page}` 可书签路由白名单，
     **与版本号无关**。误加入会凭空多出一个 `GET /web/travel-view` 页面。
2. 版本号是对**整个 `assets` 目录**做的 digest（各文件 mtime+size），所有脚本共用
   同一个 `?v=`，所以只看 hash 无法判断某个文件是否被纳入——要以
   `curl /web | grep <文件名>` 有无 `?v=` 为准。

### 3.2 Step 2 —— 真值源定案 + md→db 生成器（需你拍板）

#### 判据（实测得来）

把 `travel.db` 各表逐列映射回 md 定稿：

| db 表 | md 对应章节 | 映射质量 |
|---|---|---|
| `trip_flights`（8） | 「一、航班信息（已出票）」表 | ✅ 完整 |
| `trip_expenses`（10） | 「五、费用明细」团费/自费住宿/机票段 | ✅ 完整 |
| `trip_hotels`（7） | 「六、住宿安排」表 | ✅ 完整 |
| `trip_members`（11） | 「七、同行成员」表 | ✅ 完整（db 的 `id_card` 全 NULL） |
| `trip_days`（8） | 「三、每日精确行程」8 个 `### Day N` | 🟠 **人工摘要**（md 是分钟级表格，db 是压缩叙述） |
| `trip_checklist`（22） | 「八、物品准备」5 条列表 | 🔴 **只有骨架**：db 的 `owner`（负责人）与 `done`（勾选）**md 里完全没有** |
| `trips`（1） | 头部元信息 + 「五、费用汇总」 | 🟠 `status='已定稿'` / `budget=66159` 可派生 |

#### 结论：混合模型（建议采纳）

**md 是「内容」的真值源，db 是「派生视图 + 独有可变状态」。**

- **内容列**（行程 / 航班 / 费用 / 住宿 / 成员）：只允许 md → db **单向**生成。手改 db 会被下次生成覆盖。
- **状态列**（`trip_checklist.owner` / `.done`、`trips.status`）：**只存在于 db**，生成器**绝不写这两列** —— upsert 时把它们排除在 `DO UPDATE SET` 之外，否则你勾过的清单会被清空。

这样既解决「改 md 页面不变」，又不丢手上的勾选进度。

#### 生成器设计

- 位置：`scripts/travel/build_travel_db.py`（与 `scripts/import_diary.py` 同风格）
- 默认 **dry-run**，`--apply` 才落库；`--md <path>` 指定源，默认定稿。
- 解析器拆成可测纯函数模块 `src/openbiliclaw/travel/md_parser.py`（**无 IO、无 sqlite**，输入 str 输出 dict），这样 pytest 能直接喂样本字符串。
- 幂等键（与现有表结构对齐）：
  - `trip_days`：`(trip_id, day_number)`
  - `trip_flights`：`(trip_id, flight_type, flight_no, passengers)`（同航班不同乘机人分组必须区分）
  - `trip_hotels`：`(trip_id, day_number, hotel_name)`
  - `trip_expenses`：`(trip_id, category, item)`
  - `trip_members`：`(trip_id, name)`
  - `trip_checklist`：`(trip_id, category, item)` —— **只插不改**，已存在则跳过（保住 `owner`/`done`）
- 表格标题匹配改为**结构匹配**（按「标题正则 + 表头列名」），替掉 T4 的中文字符串匹配。
- 落库前打印 diff 摘要（新增 N / 更新 M / 保留 K），与 `import_diary.py` 的 stats 风格一致。

## 5. 需要你拍板（3 件）

1. **真值源**：采纳「md 是内容源、db 是派生视图 + 状态寄主」的混合模型吗？（我推荐采纳，理由见 §3.2）
2. **`trip_days.description` 的现状要不要保留？** 它是人工从 md 压缩出来的叙述，md 里没有一段完全对应的文字。生成器若接管，会把它改成「从 md 抽取的原文摘要」。两个选项：
   - (a) 生成器重写它（一致性优先，但会丢掉现在这句精炼文案）
   - (b) 把生成器只作「新增/补缺」，不覆盖已有 `description`（保守，但一致性打折）
3. **`data_path` 默认值改不改？** 改成 `"data/travel"` 让桌面端开箱即用（推荐），还是保持 `""` 维持「显式配置才生效」的现状？
