## 一、LTV 怎么做才算「做好」（对方最感兴趣的问题）

### 1.1 口径层——先把问题定义对（面试官听的第一分钟）

- LTV(N) = 群体（cohort）在安装后 N 天累计收入 / 群体规模。**不是常数，是曲线**：LTV(0)/D1/D7/D30/D90，曲线形状（何时拐弯）比单点更重要。
- 诊断拆解：**ARPU = 付费率 × ARPPU**。ARPU 低要先分清是「没人付」还是「付得少」——两条完全不同的改造路线（前者修首付漏斗，后者修定价深度）。我在 OPPO 建的 LTV 评估体系就是这条口径（D1/D7 留存、付费率、ARPPU 折现）。

### 1.2 建模层——损失函数的演进史（讲这条=懂行）

| 代际 | 方法 | 解决什么 | 借鉴点 |
|---|---|---|---|
| 1 | 直接 MSE 回归 | 简单 | 大 R 一条样本梯度爆炸、多数用户 LTV=0，学废 |
| 2 | 两阶段（先分类付费倾向，再回归金额） | 分开处理 0 值和金额 | 工程双模型、误差串联 |
| 3 | **ZILN 零膨胀对数正态**（Google） | 一个损失同时出流失概率+金额，天然适配重尾 | 视频号 lognormal 损失同族 |
| 4 | **分桶序数回归**（快手 CIKM'22） | 长尾分布切子分布再分桶，桶内均衡化 | 大 R 建模的工程正解 |
| 5 | **ODMN 有序依赖单调网络**（快手） | 多时间跨度 LTV30≤LTV90≤LTV180 单调约束，短窗辅助长窗 | 视频号「大 R 辅助任务」的架构级同类 |
| 6 | 生成式回归 GR（快手 WWW'25） | 数值→token 序列生成回归 | 可作前沿谈资 |

- **大 R 长尾三板斧**：①损失换 ZILN/分桶（不动梯度炸）②动态归一化（Tenjin 每 2h 刷新，异常大 R 不扭曲均值）③大 R 辅助任务（单独辅助头保住头部识别，视频号正在用的思路）。
- **评估**：别报 MSE——讲 **normalized Gini / Mutual Gini**（洛伦兹曲线衡量分布拟合）+ 十分位校准图。「LTV 模型好不好看的是把高价值人挑出来的排序能力，不是点估计误差」——这句是面试加分句。
- **不确定性与折现**：pLTV 输出分布→按 D7 ROAS 目标折算出价（pROAS）；早期信号用广告曝光粒度数据（day0 即有，破解付费信号稀疏）。

### 1.3 我的场景嫁接（OPPO 游戏中心 → 微信小游戏/游戏中心）

**面试三段答法**：
1. 「我用过」：OPPO 期间共建 LTV 评估体系（D1/D7 留存、付费率、ARPPU 折现），并把它用进用户分层分发与变现——机制层的「用」我有一手经验。
2. 「业界怎么做」：损失函数从 MSE→ZILN→分桶序数→ODMN 单调约束的演进我全部跟过（可展开任一层）。
3. 「落地第一步」：若由我做游戏中心 pLTV——先定口径（付费率×ARPPU 折现，IAP 与 IAA 分账），再用 ZILN 基线+分桶保大 R，多时间跨度加单调约束，评估用 Gini 系数，最后把 pLTV 融进排序分做 IAP 提权。

## 二、IAP 与 IAA 如何统一推荐/变现

### 2.1 为什么难（一句话打动面试官）

「同一个用户身上有两种价值机制：IAP 变现的是付费意图，IAA 变现的是注意力——用单一目标排序必然系统性错杀一边：非付费用户看 5 条激励视频可能比低频付费用户更值钱。」

### 2.2 业界统一框架（四层）

1. **价值层**：统一 pLTV = IAP LTV + IAA LTV。IAA 侧 = Σ 预估曝光 × eCPM（联盟 unified auction 可拿到 impression-level 竞价净值，IAA 归因从"国家均值"进化到"用户级"）。
2. **排序层**：统一分 = pCTR × (IAP 价值 + IAA 价值) 进入混排——正是对方「ECMP 预估模型、混排逻辑」+「融合公式 IAP 提权」的位置。IAP 提权 = 带业务先验的乘性因子，物理意义=对该品类策略性加权。
3. **出价层**：**Hybrid ROAS 混合变现出价**（Mintegral 等已产品化）：一个 ROAS 目标同时优化 IAP+IAA 双流（D0/D7 目标、oCPI 动态出价）——「预算不再偏向单一变现流」。
4. **机制层**：频控按付费状态三段分层（非付费：全量广告；微付费：避开购后窗口、激励视频为主；高价值付费：保护体验压侵扰格式）；**激励视频当 IAP 转化器用**——免费用户体验会员功能后付费率显著提升（rewarded→IAP 漏斗）。

### 2.3 我的嫁接话术

「OPPO 的用户分层差异化分发就是 IAP 视角统一分发的雏形——当时缺的是把 IAA 折算价值也塞进同一个排序分。若在游戏中心落地：非付费用户价值 = IAA 预估曝光收入，付费用户 = IAP LTV，两者折现到同一时间窗进融合公式，IAP 提权做成可解释乘性因子，激励视频位当品类转化器运营。」

## 三、端云协同 × 预请求缓存（用户指定深挖包装）

### 3.1 同构论证（一句话立住）

「预请求缓存和端云协同是同一个哲学的三种『前置』：**算力前置**（推理下沉端侧）、**请求前置**（用户落点前预拉候选）、**数据前置**（端侧缓存特征）——我在 OPPO 做的就是第一种，另外两种是同一思路在网络与存储层的展开。」

### 3.2 我的真弹药（简历已回填）

- OPPO 端云协同：云侧训练/端侧推理/端云联合训练三范式 + 量化/剪枝压缩适配端侧约束，云端负载成本 -25%。
- 迁移逻辑：端侧经验教会我「精度-延迟-算力」三角怎么权衡——预请求缓存的命中率×浪费成本权衡是同一个决策结构。

### 3.3 落地第一步讲法（对方问「预请求架构你会怎么做」时）

1. 预请求本质是**期望收益下的赌注**：预取命中省一次网络往返，猜错白耗带宽与算力——所以核心不是缓存，是**预测用户下一落点的分布**。
2. 方案：用推荐模型输出「下一 tab / 下一游戏品类」的分布（MMoE 多目标天然给多场景概率），按 期望节省 = P(落点)×延迟成本 决定每个候选的预取深度（全量/特征/不取）。
3. 工程兜底：分级预取 + 端侧 LRU + 失效策略；用我在端侧做过量化压缩的经验控制预取 payload 大小。

## 四、游戏中心接入广告 DSP × 联运混排：统一打分的故事（用户指定主线）

### 4.1 故事线：问题 → 解决 → 效果

**背景**：游戏中心原本是「自然推荐 + 联运游戏」——联运收入 = 流水分成，结算口径是 LTV/ARPU（长周期）。接入广告 DSP 后，信息流里多了一种供给（IAA 游戏推广、外部广告主），变现口径变成 eCPM（即时、单次曝光）。

**三个冲突（问题）**：
1. **口径不一致**：联运看 LTV 折现（月/生命周期），广告看 eCPM（单次曝光）——直接比大小等于拿月薪比日薪，广告天然占优。
2. **生态挤压**：广告 eCPM 高峰把联运/自然供给挤出 → 短期收入↑，但大盘留存/后续流水↓（广告 fatigue + 供给生态劣化）。
3. **反噬**：频次无节制 → 用户浏览质量下降 → eCPM 自身衰减，饮鸩止渴。

**解法：统一到同一货币（广义 eCPM）**：
- 广告供给：eCPM = pCTR × bid（原有口径）
- 联运 IAP：eCPM_eff = pCTR × P(下载→付费) × ARPPU 折现 × 分成比例——**把联运游戏当作一个"内部广告主"，用 LTV 折现值出价**
- 自然/生态位：不进收入分，走配额 + 保量约束（生态护栏）
- 融合排序：score = pCTR × [ w₁·广告 eCPM + w₂·联运折现值 ] + 生态约束项；w₁/w₂ 用 A/B 在「短期收入 × 大盘留存/流水」的 Pareto 前沿上定
- 机制护栏：频次上限、广告独立混排层、新广告冷启动走 EE 池

**效果口径**：综合变现 ARPU / 大盘 eCPM ↑，且 D1/D7 留存、自然流水不跌——「赚更多的钱，但留存曲线不动」。

### 4.2 与对方工作的接点（这是他们正在做的）

对方清单「AMS 集资：联营 IAP 游戏打分」= 正在把联运 IAP 游戏纳入广告打分体系——你的故事从两侧都接得上：广告侧（oCPX 出价、eCPM 混排）+ 推荐侧（游戏中心分发、LTV 体系）。面试被问「联运游戏怎么和广告统一打分」时，直接按 4.1 输出。

### 4.3 金句收尾

「联运和广告不是抢流量，是同一张曝光竞价里的两种出价货币——把联运 LTV 折现成广义 eCPM，生态约束做成护栏，混排就从零和博弈变成增量。」

## 五、LHUC 消偏 vs 多位置多任务预估（对方必问对比题）

> 背景：视频号 CTR 做法是「LHUC 消偏、PCOC 修复」；你简历上的是「多位置预估校准（30%+→20% 以内）」。对方大概率让你对比。

### 5.1 LHUC 机理（先讲对结构再谈优劣）

- LHUC = Learning Hidden Unit Contributions（NeurIPS 2016，源自 ASR 说话人自适应；腾讯广告移植到 CTR 消偏）。
- **偏置特征（广告位/位置/场景）不走主通路**：位置 embedding → 小网络 → 生成门控系数 → 调制隐层激活 `h' = 2σ(a ⊙ h + b)`（逐隐单元放大/抑制）。
- **消偏原理**：位置效应只能经由调制旁路表达，污染不了主网络的兴趣表征；推理时把偏置条件置空/默认，主网络直接输出「无位置效应的兴趣 CTR」——**消偏在表征层前置完成，而非事后校准**。

### 5.2 对比表（面试直接输出）

| 维度 | LHUC 消偏（调制旁路） | 多位置多任务+后置校准（我的 OPPO 做法） |
|---|---|---|
| 消偏位置 | 表征层前置：位置进不了兴趣表征 | 输出层后置：各位置学出带偏估计，再校准 |
| 参数成本 | 极小（每层一个门控向量） | 每位置一个头/校准曲线，位置数线性增长 |
| 长尾位置 | 门控共享结构，新位置平滑泛化 | 曝光少的位置头欠拟合，需校准数据兜底 |
| 拟合容量 | 调制容量有限，位置效应复杂（非线性/交互强）时可能欠拟合 | 各位置独立建模，效应刻画更充分 |
| 跨位可比性 | 天然可比（同一个无偏分） | 需依赖校准曲线把各位置拉回同一标尺 |
| 校准需求 | 仍建议后接 PCOC 校准兜分布漂移 | 校准就是方案本体 |
| 工程复杂度 | 一套模型+旁路 | 多任务/多头+多条校准管线 |
| 归因可解释性 | 位置效应藏在门控里，归因较难 | 分位置数字直白，好汇报 |

### 5.3 标准答法（三段）

1. **两者不是对立而是互补**：「LHUC 解决的是『别让位置污染兴趣表征』，多任务+校准解决的是『各位置响应差异要刻画准』——前者管无偏，后者管精准。」
2. **用我的数据说话**：「OPPO 的场景里位置差异不止是偏置——闪屏位和信息流位的用户意图本身不同（强推 vs 主动浏览），多任务分开学是对的；但如果位置只是曝光序位差异，LHUC 更优雅，参数省、跨位天然可比。」
3. **混合方案收尾**：「业界常见组合是 PAL/LHUC 前置消偏 + PCOC 后置校准：表征层去偏、输出层修分布漂移。视频号的做法（LHUC+PCOC）正是这个组合——我在 OPPO 做的是后半段，前半段我懂原理、知道工程上偏置条件不能泄漏进主路径这个关键坑。」

### 5.4 提醒

- 别把 LHUC 说成「消偏万能」：它对**曝光分布漂移**（PCOC 管的那个）无能为力——两层问题要分清。
- 被追问细节时按 A/B/C 档位降级（见包装矩阵 §二）：LHUC 你没实操过，口径是 B 档「深入评估过」——答机理+选型对比+「当时为什么选了多任务路线（位置意图差异大）」最稳。

## 六、高频三问速答卡（对方清单原题）

### 6.1 LTV 建模，大 R 如何处理

**问题本质**：LTV 分布是「零值巨峰 + 长尾 + 上扬尾部」，大 R 一条样本贡献一年收入，MSE 下梯度爆炸、cohort 均值被单点扭曲。

**业界做法（四板斧）**：
1. **损失换型**：ZILN/lognormal 重尾假设天然适配（对 log x 回归，大 R 不再炸梯度）；快手 MDME 把大 R 切成独立子分布再分桶序数回归。
2. **大 R 专门通道**：辅助任务头/分层 expert 单独保头部识别（视频号「大 R 辅助任务」正是此法）；结构上可用分层专家按价值层路由。
3. **动态归一化**：大 R 异常定期校正（Tenjin 每 2h 刷新），防 cohort 级均值失真。
4. **评估换标尺**：normalized Gini / 十分位校准——大 R 场景考核的是「把高价值挑出来的排序能力」和尾部分位（P90/P95）校准，不是点估计 MSE。

**我的嫁接**：OPPO 时 LTV 体系（付费率×ARPPU 折现）+ 付费深度分层分发就是机制层的「大 R 差异化对待」；建模层落地第一步 = ZILN 基线 + 大 R 独立子分布/辅助头 + Gini 上线评估。

### 6.2 新游如何冷启

**先拆题**：供给冷启（新游戏/新广告主）与用户冷启不同；对方清单「客户冷启」= 广告主/游戏侧冷启。

**业界做法**：
1. **内容理解扛冷启**：品类/题材/美术/视频素材多模态特征（CNN/BERT），同品类老游戏先验迁移（embedding 迁移、品类 CTR/CVR prior）——新游没有行为，但有「相似游戏的行为」。
2. **EE 框架化投放**：保护期（预算内纯探索）+ 专属探索流量池（受控曝光）+ 贝叶斯平滑初始化（同品类 Beta/Dirichlet 先验收缩）——即我 OPPO 冷启动机制本体（通过率 +15%、新广告曝光 +30%）。
3. **早期信号加速**：用素材粒度 day0 互动（曝光/点击/停留）而非等待转化回传，解决转化信号稀疏（Tenjin 用 day0 广告互动预测 D30 同思路）。
4. **客户冷启（广告主侧）**：行业品类 rate card 定初始出价 → 小额试投收集分布 → 成本保障缓冲期 → 按 pLTV 置信度放开预算；配额上防头部广告主垄断探索流量。
5. **元学习/跨游迁移**：口头提级即可（MAML 类、参数解耦微调），不讲深。

**我的嫁接**：OPPO 冷启动扶持机制全套真做过（EE 三件套+贝叶斯平滑），客户冷启与之同构——「我做过 EE 冷启的完整闭环，游戏侧冷启把先验源从『同品类广告』换成『同品类游戏』即可」。

### 6.3 推荐如何做 AI agent（开放题，C 档答法）

**先定框架**（三层次，展示结构化思维）：
1. **内容层**（已成熟）：LLM 生成推荐理由/文案/摘要——对方红点文案小模型（glm/kimi）就是这一层。
2. **特征/模拟层**：LLM 做用户兴趣摘要、会话式改写查询、生成合成行为增强冷启特征。
3. **闭环层**（真 agent）：感知（实时行为）→ 规划（LLM 决定召回源组合/融合权重/干预策略）→ 工具调用（召回/预估/重排 API）→ 执行 → 反思（反馈回写修正策略）。

**关键判断（加分句）**：「agent 不该进毫秒级主链路——延迟和成本都不允许；它的正确位置是**近线/离线层**：策略迭代、badcase 归因、特征生成、运营位编排这些『人肉高频环节』的自动化。」
**与 genrec 的关系**：生成式推荐是「模型即策略」，agent 是「模型+工具编排」，两条互补路线——语义 ID 解决预估范式，agent 解决策略迭代效率。

**落地第一步**：挑最高频的人肉环节 agent 化——badcase 归因 agent（自动拉数据→定位特征/模型/机制问题→出报告）或场景策略调参 agent；先建工具接口和评测集，再谈自主规划。

**我的口径（已升级为实操）**：个人项目（OpenBiliClaw，2026.06 起）就是 LLM×推荐的端到端落地——LLM 批量评估入池、会话式 RankAgent 混合打分（规则×语义质心×点赞学习×停留时长）、LLM 批量文案生成（按 ID 绑定防错位/重复丢弃/限流降级）、兴趣探针（LLM 猜方向→用户确认→入画像）。面试可答：「我自己的推荐系统里 LLM 没进毫秒级主链路——评估、表达、agent 排序都在近线/异步层，这正是延迟与成本的现实约束下我做出的架构选择。」被问细节时按代码实际讲（MMR/疲劳双轴/Thompson 采样都有真实实现），**不要往外延伸 RQ-VAE/语义 ID 生成式召回**——代码里没有，那部分维持 C 档「跟踪业界」。
