# 专题 07 · 推荐 AI Agent（2026-09-16）

> 对方痛点：基础模型「推荐 AI agent」、游戏中心「社区推荐系统性诊断」。
> 简历钩子：个人项目 RankAgent + 兴趣探针 + LLM 评估/文案全链路（A− 档，实操）。

## 一、业界框架（2025-2026 综述口径）

**三范式**（EMNLP 2025 Findings 综述 / Agent4Rec 综述）：
1. **Recommender-oriented / Agent for Rec**：agent 增强推荐内核——特征生成、召回编排、打分融合。
2. **Interaction-oriented**：对话式推荐——多轮引导偏好、可解释推荐。
3. **Simulation-oriented**：agent 模拟用户——离线评测沙盒、行为仿真。

**四模块架构**：Profile（画像）· Memory（分层记忆）· Planning（策略规划）· Action（工具执行）。

**开放挑战**（答出来就是加分）：推理成本（LLM 不进主链路）、评测难（轨迹级评估/贡献归因）、安全与可控。

## 二、关键判断（面试主答）

「agent 不该进毫秒级主链路——延迟和成本都不允许；它的正确位置是**近线/离线层**：策略迭代、badcase 归因、特征生成、运营位编排这些『人肉高频环节』的自动化。」

**与 genrec 的关系**：生成式推荐是「模型即策略」，agent 是「模型+工具编排」，两条互补——语义 ID 解决预估范式，agent 解决策略迭代效率。

## 三、我的实操（个人项目，A− 档）

| 能力 | 实现 |
|---|---|
| 会话式排序 agent | RankAgent：规则分 × 语义质心余弦 × 点赞学习（α）× 停留时长（β）混合打分 + 80/20 多样性配比 |
| LLM 主动探索 | 兴趣探针：LLM 猜测兴趣方向 → 用户确认/拒绝 → 入画像（4h 去重冷却）；避雷探针同理 |
| LLM 批量生产 | 评估入池 / 推荐文案批量预生成：按内容 ID 绑定防错位、重复文案整组丢弃、限流降级拆半重试 |
| 工程判断 | LLM 全部在近线/异步层，主链路零 LLM 调用；热路径只读缓存 |

## 四、面试三段答法

1. 「我自己跑过」：§三 四项，讲 RankAgent 打分融合的设计取舍（为什么 α/β 要随样本量爬坡、为什么质心只读缓存）。
2. 「业界框架」：三范式四模块 + 三挑战（成本/评测/安全）——说明不是只会自己那套。
3. 「落地第一步」：挑最高频的人肉环节 agent 化——**badcase 归因 agent**（自动拉数据→定位特征/模型/机制问题→出报告）或场景策略调参 agent；先建工具接口和评测集，再谈自主规划。

## 五、追问防御

- 「agent 幻觉怎么控？」→ 工具返回结构化数据、LLM 只做编排不做事实生产；关键动作落库可回滚。
- 「怎么评测 agent 好坏？」→ 任务完成率 + 人工抽检 + 归因结论的线下验证率；别答「看推荐指标」——agent 层和模型层的指标要分开。
- **金句**：「agent 化推荐的难点不在 LLM 在工具治理——工具接口和评测集没建好，再强的模型也只是嘴上会推荐。」
