## 一、一句话本质

混合排序的难点**不在排序算法本身**，在于放进同一个分数的两种"价值"根本不是同一种东西：

- **广告 eCPM = 已落袋的现金**：即时结算、可实测、按单次曝光度量。
- **联运折现 = 未发生的期望**：后置分成、靠模型估、按生命周期度量。

硬塞进一个分数，会同时暴露三层问题：
**价值不可比（计量层）→ 置信度不可比（数据层）→ 优化目标被自己的决策污染（机制层）**。

> 面试开口第一句就用这个：**"这不是排序算法问题，是三种问题叠在一起。"** 把定义权拿到自己手里。

## 二、两类供给画像：联运游戏 vs 广告游戏

> 这是问题 1 / 2 的**前置知识**——不理解两类供给的差异，就答不出"为什么不能简单排序"。
> 面试里不用一次倒完，用来接住"你先把联运和广告的区别说说"这类开场题。

### 2.1 一句话分野

- **联运游戏是「投资标的」**：今天给它流量，赌它以后能把钱还回来（分成）。看的是**长期回收**。
- **广告游戏是「库存变现」**：用户此刻的注意力就是库存，当场卖出去、当场结算。看的是**即时效率**。

一句话记住：**一个是赌用户以后花钱，一个是卖用户现在的时间。**

### 2.2 十四维对照表（背这张表就够）

| 维度 | 联运游戏（IAP 为主） | 广告游戏（IAA 为主） |
|---|---|---|
| 钱从谁来 | 玩家内购（道具 / 礼包 / 月卡） | 广告主预算 |
| 平台角色 | **渠道 / 发行伙伴**（要谈分成） | **媒体**（卖用户注意力） |
| 结算事件 | 内购订单（SDK 回传） | 广告曝光 / 点击 |
| 到账时点 | **后置**（周期结算，T+1 ~ 月结） | **即时**（按次入账） |
| 反馈速度 | 慢：LTV 需 1–2 周收敛 | 快：eCPM 小时级可测 |
| 价值确定性 | 低（pLTV 是**估**的） | 高（eCPM 是**测**的） |
| 出价性质 | 自估价格（可能倒贴 / 可能低估） | 真金竞价（二价机制有效） |
| 收入分布 | **重尾**：少数大 R 贡献大头 | **长尾**：靠 DAU × 频次 × eCPM |
| 供给数量 | 少而精（几十 ~ 几百款） | 多而杂（海量长尾） |
| 生命周期 | 长（月 ~ 年，大版本回流） | 短（周 ~ 月，爆款快起快落） |
| 稀缺资源 | **入口曝光位**（游戏本身可无限被玩） | **用户时间 / 广告库存** |
| 核心指标 | LTV、ROI、留存、ARPPU、回收期 | eCPM、广告 ARPU、填充率、广告容忍度 |
| 主要风险 | 分成谈判、大 R 流失、长周期回收失败 | 密度过高伤留存、eCPM 波动 |
| 对用户的诉求 | 让他**掏钱** | 让他**多花时间、多看点广告** |

### 2.3 联运游戏的六个特点（展开）

1. **钱从玩家来，后置且重尾**：平台拿的是流水分成，钱在用户付费之后、按周期结算；收入分布极度重尾。
2. **大 R 决定生死**：少数重度付费用户贡献大部分流水（行业常见 3–5% 用户贡献 60%+）。这意味着**均值模型会被头部样本带歪**——高价值人群必须单独建模（对应对方的「大 R 辅助任务」）。
3. **反馈慢、链路长**：曝光 → 进入 / 下载 → 留存 → 付费 → SDK 回传 → 分成结算，每一环都有损耗和延迟。链路越长，模型估计的方差越大、越容易被"好测量"的一方压制。
4. **平台是渠道方，不是纯媒体**：有分成比例、首发 / 保底 / 阶梯条款、运营资源倾斜。**要考核的不只是钱**——还要护 CP 关系、护生态健康。
5. **供给少而精、有生命周期**：上线 → 成长 → 成熟 → 衰退，大版本更新带来回流。所以"给不给量"是**阶段性决策**，不是一次性的分数。
6. **入口比库存稀缺**：单款游戏可以被无限次玩（库存不稀缺），但首页 / 推荐位是稀缺的。**竞争发生在入口，不在库存。**

### 2.4 广告游戏的六个特点（展开）

1. **钱从广告主来，即时按次**：平台是媒体，把注意力卖出去，按曝光 / 点击结算，钱当场入账。
2. **收入 = DAU × 人均广告次数 × eCPM**：三个因子都是规模项——低 DAU 游戏广告收入天花板很低（对应对方清单里「召回池优化 / 低 DAU 过滤」）。
3. **反馈快、可实测**：小时级拿到 eCPM，且出价来自广告主真金竞价，**二价机制在这里有效**（与联运侧完全不同）。
4. **平台是媒体方**：自助投放 / 程序化为主，与游戏厂商是流量分成的松散关系，不像联运那样深度绑定。
5. **供给多而杂、生命周期短**：海量轻量小游戏，长尾占比高，爆款快起快落。
6. **广告容忍度是硬约束**：用户看广告的意愿有限。密度提高短期收入涨，但**跳过率上升、pCTR 下滑、eCPM 内生衰减**，且流失风险累积。所以密度 / 频次是**约束**，不是可随便调的优化变量。

### 2.5 混合变现（IAP × IAA）——现在才是主流

微信小游戏生态里内购约占 68%、广告约 32%，而**大量游戏是混合变现**：同一款游戏既开内购、又接激励视频。这带来三个新问题：

1. **平台同时是渠道和媒体** → 同一份用户价值会被两边各计一次收入，**必须防双边计收入**。
2. **两类收入互相挤占** → 用户的时间池固定：看了广告可能就不买月卡，买了月卡就不看激励视频。统一 LTV 应是 `IAP LTV + IAA LTV − 挤占损失`，**光加不减会高估**。
3. **归因更难拆** → 应用商店里"下载"是清晰分界；小游戏即点即玩，联运与广告在同一会话里交替发生。

> **面试机会点**：这三点正好可以引出"我在 OPPO 面对的就是同款结构"，再自然过渡到统一竞价与广义 eCPM 的讲法。

### 2.6 附：同一个"联运"里的两种形态（精品游戏 vs 小游戏）

| 维度 | 精品游戏（重度） | 小游戏（轻量） |
|---|---|---|
| 获取方式 | 下载安装（有安装环节） | 即点即玩（无下载，转化链最短） |
| 驱动方式 | 买量驱动，与大 R 重氪强相关 | 自然流量 + 社交裂变，IAA 占比更高 |
| 付费特征 | 大 R 集中、ARPPU 高、周期长 | 小额高频、ARPPU 低、以看广告为主 |
| 冷启动 | 需买量 + 平台资源扶持，起量慢 | 起量快、衰减也快 |
| 内容稀缺性 | 精品稀缺，平台要抢首发 | 供给海量，平台要做质量筛选 |

对平台的启示：**精品游戏看"值不值得投资"（长期回收 + 生态），小游戏看"效率高不高"（即时产出 + 留存）**——这就是对方清单里会把「低 DAU 过滤」「素材优选」单独列出来的原因。

### 2.7 这节怎么接回混排（30 秒口述）

> 两类游戏根本是两种生意：联运是投资——钱从玩家来、后置分成、重尾、靠大 R，反馈要一到两周，平台是渠道方，要谈分成、要护生态；广告是变现——钱从广告主来、按次即时结算、靠 DAU×频次×eCPM，小时级可测，平台是媒体方，供给多而杂。把这两种供给放进同一个排序分，等于让"投资决策"和"现金流结算"用同一把尺子——混排难就难在这。
> 更麻烦的是现在小游戏大量混合变现，同一款游戏既内购又投广告，平台同时是渠道和媒体，两类收入还抢同一份用户时间，所以要防双边计收入、还要把挤占效应扣进统一 LTV。

### 2.8 追问防御

| 追问 | 怎么接 |
|---|---|
| 「联运和广告游戏不都是游戏吗？有本质区别？」 | 对用户是，对平台不是：一个是**分成收入**（后置 / 估算 / 重尾），一个是**广告收入**（即时 / 实测 / 规模驱动）——钱从哪来、反馈多快、分布多偏全不一样，所以不能直接比大小。 |
| 「你做过混合变现的盘子吗？」 | 做过——OPPO 游戏中心就是联运 + 广告同池（A 档），处理的核心正是两类口径可比性与挤占。 |
| 「挤占效应你怎么量化？」 | 干净做法是同一款游戏做"开广告 / 不开广告"分层 A/B，看内购 ARPPU 与留存变化；退一步看"看广告用户 vs 不看广告用户的内购率"，但要主动说明这是**相关性不是因果**（有选择偏差）。 |
| 「IAA 游戏为什么不把广告密度再提上去？」 | eCPM 是密度的函数（内生）：过拐点后跳过率上升、pCTR 下滑，真实 eCPM 反降，还伤留存。所以密度是**硬约束**，不是能无限调的优化变量。 |
| 「精品游戏和小游戏要不要分池排？」 | 不建议再分池——分池会丢失两类供给之间的比较；正确做法是**统一口径 + 差异化约束**（各自的折现窗、探索预算、配额下限）。 |

**金句**

> 联运是「投资标的」，广告是「库存变现」——一个是赌用户以后花钱，一个是卖用户现在的时间；同一张曝光位评这两种价值，难点从一开始就不在算法。

### 2.9 概念对齐：IAP / IAA 是「变现方式」，不是「品类」（别把两个维度混了）

> 触发场景：被问「IAP 是不是就是精品游戏？IAA 是不是就是广告类游戏？」
> 这节是**口径纪律**——说错维度不会当场被纠，但遇到混合变现的游戏就说不圆，而且会暴露"没在游戏行业真待过"。

**两个独立维度**

| 维度 | 取值 | 回答的问题 |
|---|---|---|
| **变现方式** | IAP（内购）/ IAA（广告）/ 混合 | 这款游戏**怎么赚钱** |
| **品类与品质** | 精品重度 / 中度 / 休闲超休闲 | 这款游戏**是什么、有多重** |

**统计上高度相关，逻辑上不互相定义**

- **为什么相关**：精品重度游戏买量成本高、需要大 R 支撑回收 → 天然走 IAP；超休闲轻量、门槛低、用户付费意愿弱 → 天然走 IAA。所以**主流落在主对角**（精品×IAP、休闲×IAA）。
- **为什么不能互相定义**，三个反例：
  1. **几乎没有"纯 IAA"游戏**——绝大多数 IAA 游戏都带「去广告」内购，这本身就是 IAP；
  2. **重度精品也接 IAA**——给非付费用户挂激励视频是**补变现**，不是"它变成了广告游戏"；
  3. **同一款游戏不同阶段不同**——冷启动期靠 IAA 起量、成熟期转 IAP 收割，标签会随时间变。
- **另一层最容易混的**：**「联运」≠ IAP**。"联运"是平台与厂商的**分成关系**（渠道关系）；"接入广告 DSP"是**媒体关系**。联运游戏通常以 IAP 为主，但同样可以接广告。§2.2 的表头之所以写成「联运游戏（**IAP 为主**）」，就是为了留出这个空间。

**面试口径纪律（背下来）**

1. 说「**以 IAP 为主**」「IAA 占比高」，**不说**「这是 IAP 游戏 / 这是广告游戏」；
2. 涉及收入口径时讲「**变现结构**」（IAP 占比多少），不讲品类标签——混合变现是主流（小游戏生态内购约 68%、广告约 32%，且**单款游戏内部**两者也在交叉）；
3. 一句话记法：**IAP / IAA 是「钱从哪来」，精品 / 休闲是「游戏长什么样」——不是一回事。**

**追问防御**

| 追问 | 怎么接 |
|---|---|
| 「那 IAP 和精品游戏、IAA 和广告游戏，不是一回事吗？」 | 两个维度：一个是**怎么赚钱**，一个是**游戏长什么样**。统计上相关（主对角），但逻辑上不互定义——几乎每个 IAA 游戏都带去广告内购，很多重度精品也挂激励视频。所以我只说"**以 IAP 为主**"。 |
| 「联运游戏是不是都靠内购？」 | 联运指的是**分成关系**（平台是渠道方），不是变现方式。联运游戏通常以 IAP 为主，但一样能接广告——所以我在表里写"联运游戏（IAP 为主）"。 |
| 「你怎么区分一款游戏算 IAP 还是 IAA？」 | 看**变现结构**：记 IAP 收入占比，两套价值模型加权，占比随生命周期滚动更新（冷启靠 IAA、成熟转 IAP 很常见）。不做二元归类。 |

## 三、三层问题（14 条）

### 第一层：计量层 —— 两种钱怎么换算（本质，答不好后面全错）

**1. 折现窗口本身就是价值判断，不是技术参数**

- **机理**：联运的单次曝光期望收入 = P(下载) × P(下载→付费) × ARPPU × 分成比例，每一项都要在某个"观测/折现窗口"内计算。
- **后果**：窗口取 7 天 vs 90 天，IAP 长尾收入的计入量差几倍 → **窗口一选，胜负已定**。IAP 回本周期本来就长，窗口短了等于把长尾切掉、系统性低估联运。
- **关键认知**：这是唯一一条**没有"技术最优解"**的问题——它本质是业务决策（愿意为未来多久的钱在今天买单），算法同学只能提出方案 + 对齐业务口径，不能自己拍。
- **我的改造**：**折现窗按品类 / 变现模式的回本周期差异化**，而不是全局一个窗（见专题 12）。⚠️ **具体怎么差异化 → 专题 14**：计价口径**统一**到完整生命周期，差异化的只是**观测窗 + 外推系数**——不要按字面理解成"每个品类算不同时间的钱"，那样反而不可比。
- **对方为什么疼**：小游戏 IAP:IAA ≈ 7:3，联运是主粮；窗口偏短＝主粮被系统性压价。

**2. 折现必须带存活率和资金成本，不能线性加总**

- **机理**：第 t 天的 1 元 ≠ 今天的 1 元。严格式：`E[R] = Σ_t S(t)·ARPU(t)/(1+r)^t`，S(t) 是留存到 t 的概率。
- **后果**：用"假设用户必然留存"的简单加总，会系统性高估长周期游戏；用固定折现率又不分品类，则对高留存品类失真。
- **解法**：至少把 S(t) 显式建模（留存曲线 × ARPU 曲线），而不是拿一个平均 ARPPU 乘上去。

**3. 计量事件必须对齐，换算链每层都有损耗假设**

- **机理**：广告主出价针对特定优化事件（曝光 / 点击 / 下载 / 付费），联运分成按流水。
- **后果**：要进同一个分数，必须换算到同一计费事件（一般归到"一次曝光"）。换算链是 `P(下载|曝光) × P(付费|下载) × ARPPU × 分成`——**每一环的偏差都会乘进去**，所以联运分数天然比广告分数"链更长、更脆"。
- **对应做法**：打分用归一化价值、结算层才用绝对比例（**打分解耦结算**，见专题 12）。

### 第二层：数据层 —— 两种分数的可信度不一样（最容易被忽略，杀伤力最大）

**4. 反馈延迟 → 冷启动天然吃亏 → 自我强化循环**

- **机理**：广告 eCPM 小时级可测；联运 LTV 要 1–2 周才收敛。
- **后果**：新游戏 / 新用户的联运分是"猜的"，广告分是"测的"。系统偏好自己确定的那个 → 联运新游拿不到量 → 更没数据 → 更不准。**最终供给结构会收缩到只剩头部游戏**。
- **解法**：给联运新供给**独立探索预算（EE 池）+ 保守下界出价**，不能指望它自己爬出来。
- **我的改造**：**先定"在哪探索"**——用低机会成本位承担探索量，先验迁移回高价值位。

**5. 删失不等于 0：未回传不是"没发生"**

- **机理**：T+1 回传的日子里，"今天还没付费"里混着"以后会付费的慢付费人群"。
- **后果**：把未观测当负样本 → 系统性低估慢付费人群（先体验后付费、看激励视频攒币再付费这类），而这**正好是联运最值钱的那部分**。
- **解法**：观测时长 t 作为条件输入（新样本即时可用）+ 未回传样本无偏加权（IPW），并盯住加权带来的方差上升。

**6. 可测性偏差会直接变成排序偏差**

- 广告那边也测不准（归因窗、跨端），但两侧的**不确定性结构不同**。混排需要统一的"不确定性感知"处理（保守分位数出价），否则就是让"好测量"的一方赢——这不是它更值钱，只是它更容易被证明值钱。

### 第三层：机制层 —— 目标被自己的决策改变（真正显功力的一层）

**7. eCPM 是密度的函数，不是常数 —— 贪心排序必然过度商业化**

- **机理**：当前 eCPM 是在**当前广告密度下**测出来的。把密度从 10% 提到 30%，前段实测 eCPM 可能还高，但用户反感和跳过率同步上升，pCTR 掉得比密度涨得更快，真实 eCPM 衰减。
- **本质**：**把内生变量当成外生参数用**。这是固定点问题，不是单步最优问题。
- **后果**：拿"当前 eCPM"做贪心，会系统性超配广告——短期收入曲线漂亮，半年后留存崩。
- **解法**：密度 / 频率做成硬约束或惩罚项；广告位做成固定配额层（不参与自由竞价）；疲劳曲线显式建模。→ **展开见专题 09 §3.3：频率约束不写「次数 cap」，写成疲劳度定价阈值 λ_freq（与配额是同一形式的影子价格项）。**

**8. 外部性没有定价**

- 一次广告曝光挤掉的联运机会成本、以及用户**下次访问概率**的损失，都不在分数里。
- **解法**：配额保底（联运 / 自然最低份额）+ 生态惩罚项 + 业务侧对齐的长期指标约束。
- **对方证据**：平台排行权重里"生态健康"占约 25% —— **平台已经在用非收入指标纠偏**，说明这是真实发生过的风险，不是理论担忧。这句用对方的证据说对方的痛点，很有力。

**9. 拿自己估的价，去和真金白银竞价**

- **机理**：联运的"出价"是我们自己估的 pLTV，广告主出的是真钱。
- **后果**：估高了平台倒贴（亏的是自己的钱）、估低了联运吃亏；而且**二价机制在这里失灵**——次高价变成估计值，收不到真金。
- **解法**：内部价格控制（成本 cap / shadow price / 分位数下界出价），不能直接把 GSP 套上去。

**10. 多目标 + Goodhart**

- 收入 / 留存 / 生态 / 新游扶持是多目标，融合权重是**结构性参数**——数据里没有反事实，学不出来，只能 A/B + 业务先验。
- 一旦权重固定，各方会去优化权重而不是真实目标（Goodhart）→ 权重需要定期重估，考核指标要防被单一团队操纵。

### 第四层：工程与实验细节（会被追问的地方）

| # | 问题 | 要点 |
|---|---|---|
| 11 | 量纲与融合形式 | 只能走 `score = pCTR × 单次期望价值` 的乘法框架；直接加两个分数会量纲失衡、一方主导。`eCPM = pCTR × bid × 1000` 是两侧共同的可比基准。 |
| 12 | pCTR 偏差会同时放大两边 | 若 pCTR 被位置偏差污染，混排结果被位置偏差主导 → **先消偏 / 校准，再混排**（连到问题 7 位置偏差）。 |

## 五、口述稿

**60 秒版（背熟）**

> 混合排序的难点不在排序算法，在两种钱不是同一种东西：广告 eCPM 是**已落袋的现金**——即时、实测、按次算；联运折现是**没发生的期望**——后置、估算、按生命周期算。硬放进一个分数会出三层问题。
> 第一层是**换算率**：折现窗口取多长本身就是价值判断，窗口一选胜负已定，而且不能线性加总、要带存活率和资金成本。
> 第二层是**置信度不可比**：广告小时级可测，联运 LTV 要两周，新游天然吃亏，会形成"没量→没数据→更没量"的循环。
> 第三层是**目标被自己污染**：eCPM 是广告密度的函数，拿当前 eCPM 贪心排一定会过度商业化，短期收入好看、留存半年后崩。
> 所以我做的是：统一到广义 eCPM 做换算式，折现窗按品类回本周期差异化，把密度和生态做成硬护栏，新供给给独立探索预算。

## 八、IAP 与 IAA 游戏同池分发的问题（另一个切面）

> 承接 §二：§二 讲"两类游戏**是什么**"，本节讲"把两类游戏放进同一个推荐池分发会出**什么问题**"。
> 与 §三 的分工：**§三 讲"钱怎么换算"（平台两种收入的口径），本节讲"内容怎么共处"（用户与生态的视角）**。两个切面合起来才是完整的混排问题。
> 解决方案层（统一 pLTV / Hybrid ROAS / 频控分层）在专题 02，本节只讲问题侧。

### 8.1 一句话本质

**不是"两种钱不好比"，而是"这两类游戏要的用户不是同一批人"**：

- **IAP 游戏**要的是**愿意掏钱的少数**——付费意愿 × 支付能力，价值集中在 3–5% 的人身上。
- **IAA 游戏**要的是**愿意花时间的多数**——注意力富余 × 价格敏感，价值分散在大部分人身上。

同一个用户在两边的价值排序**常常是相反的**：一个爱玩但从不付费的休闲用户，对 IAA 游戏是优质用户、对 IAP 游戏几乎等于"白玩"；反过来，一个高付费潜力但时间碎片化的用户，在 IAP 侧极值钱、在 IAA 侧只贡献几条曝光。

用单一的用户价值分排序，等于**逼推荐系统在"掏钱"和"花时间"之间二选一**。

### 8.2 六个具体问题

**1. 用户价值的"方向"不同 → 单一分数必然错配**

- **机理**：IAP 价值 = 付费概率 × ARPPU（集中少数）；IAA 价值 = 曝光量 × eCPM（分散多数）。
- **后果**：按统一 pLTV 排，高付费潜力用户会被推给 IAA 游戏（那边也能出即时价值），**付费潜力被浪费**；时间富余但无付费意愿的用户被推给 IAP 游戏，**两边都拿不到应有价值**。
- **本质**：这不是"价值大小"问题，是**价值结构**问题——需要 `pLTV(u, g)` 与 `Rev_IAA(u, g)` 两个 **用户 × 内容**匹配矩阵，而不是"游戏价值"一个标量。

**2. 反馈速度不对等 → 短期指标系统性偏向 IAA（最隐蔽）**

- IAA 游戏曝光即产生收入（分钟级可测）；IAP 要等付费，且大 R 付费周期更长。
- 上线用短期指标做在线学习 / 探索时，系统**天然把量倾斜给 IAA**——不是它更值钱，只是它**更容易被证明值钱**。
- 后果：IAP 中腰部游戏（还没跑出数据的）拿不到量 → 没数据 → 排序更低 → 慢慢从池子里消失。**微信这边 IAP 是主粮，这个偏移伤的是主粮。**
- 与 §三 第 4 条同源，但更隐蔽：两边都是"游戏"、都在同一个池子，短期指标看起来"可以直接比"。

**3. IAA 游戏的设计目标与推荐系统目标直接冲突**

- IAA 游戏的商业模式决定了它要**最大化广告观看**；推荐系统的目标是**用户满意 / 留存 / 长期价值**。
- 给 IAA 游戏流量，本质是在为它**透支用户耐心**——这个成本不在游戏方的账上，记在平台的留存上。
- 一句话：**IAA 的收入是即时的，成本是滞后的。** 只看收入排，一定过度供给。

**4. 供给数量悬殊 → 池子结构被长尾主导**

- IAA 供给海量、同质化强（消除 / 合成 / 超休闲动辄一大把）；IAP 少而精。
- 后果：① 召回池被长尾灌满，优质 IAP 游戏抢不到曝光；② 同类 IAA 反复出现 → 内容多样性塌陷、用户审美疲劳；③ 新品冷启动更难——竞争对手不是"更好"，而是"更多"。
- 对应对方清单：「召回池优化（低 DAU 过滤）」「素材优选」。

**5. 混合变现游戏无法二元归类**

- 大量小游戏既内购又接激励视频 → 按"IAP 游戏 / IAA 游戏"打标签本身就是错的。
- 正确做法：按**变现结构**处理——记 IAP 占比 + 两套价值模型加权，且占比随生命周期滚动更新（**冷启动期靠 IAA 起量、成熟期转 IAP 收割**是很常见的形态）。

**6. 实验周期不对等 → 结论天然偏短期**

- IAA 的效果几天就测得出；IAP 的长期 LTV / 大 R 付费要 30–90 天才收敛。
- 混排 A/B 只跑两周得出的"最优权重"，必然偏 IAA。**实验设计要先定评估周期，再定权重。**

### 8.3 怎么解（我的做法 + 改造）

**总框架：从"游戏价值标量"改成"用户 × 内容的价值结构"**

1. **双层价值，不急着合成**：分别建 `pLTV_IAP(u,g)` 与 `Rev_IAA(u,g)`，都折算到"单次曝光期望价值"，但排序分**保留两个分量**。
2. **权重按人群分层，而不是全站一个数**（我的改造）：高付费潜力人群抬 IAP 侧权重；时间富余 / 价格敏感人群抬 IAA 侧权重。依据是"该人群在两个模型上的价值离散度"，不是一个人拍的全局权重。这是我在 OPPO 分层分发（按付费深度四层差异化）经验上的自然延伸。
3. **IAA 收入做"留存折价"**（我的改造）：给 IAA 的即时收入乘一个基于该游戏历史留存影响 / 广告密度的系数——**把外部性内化进排序**，而不是按会计口径全额入账。
4. **硬约束而非软权重**：广告密度上限、人均广告观看上限、疲劳曲线；IAP 供给保底曝光份额——"过度商业化"是**约束问题**，不是可以调权重解决的权衡问题。
5. **中腰部 IAP 独立探索预算**：短期指标永远选不中它们，必须给独立通道（复用 §三 第 4 条的 EE 思路）。
6. **混合变现按结构建模**：不二元分类，按 IAP 占比加权，占比随生命周期滚动更新。
7. **评估口径先定**：分群 AB + 长周期指标（D30 留存、长期 LTV、生态多样性），不接受只用 7 天收入下结论。

### 8.4 口述稿（60 秒）

> IAP 和 IAA 游戏放到一个池子里分发，最麻烦的不是两种钱不好比，是**这两类游戏要的用户不是同一批人**：IAP 要愿意掏钱的少数，IAA 要愿意花时间的多数。同一个用户在两边价值排序经常是反的——爱玩但不付费的休闲用户，对 IAA 是优质用户，对 IAP 基本白玩。所以用一个统一价值分排，一定会错配：高付费潜力用户被推去看广告，时间富余的人被推去玩要付费的重度游戏。
> 第二个问题是**反馈速度不对等**：IAA 曝光就有钱、分钟级可测，IAP 要等付费、大 R 周期更长。用短期指标做在线学习，系统会天然把量倾斜给 IAA——不是它更值钱，是它更容易被证明值钱。而 IAA 游戏的设计目标本来就是让你多看广告，给它流量等于帮它透支用户耐心：**收入是即时的，成本记在平台的留存上，而且是滞后的**。
> 第三是结构问题：IAA 供给海量同质、IAP 少而精，池子会被长尾灌满；再加上混合变现游戏没法二元归类、实验周期也不对等。
> 我会改两件事：一是排序不合成一个标量，保留 IAP/IAA 两个价值分量，**权重按人群分层**而不是全局一个数；二是把 IAA 的即时收入做**留存折价**，把外部性内化进去，密度和疲劳走硬约束。

### 8.5 追问防御

| 追问 | 怎么接 |
|---|---|
| 「IAP、IAA 一起排不就是算钱吗？」 | 钱的量纲是同一个，但**用户不是同一批人**：一边要付费意愿、一边要时间富余，方向常常相反。算钱只解决"怎么比"，没解决"该给谁"。 |
| 「那你 IAP/IAA 的权重怎么定？」 | 权重是**结构性参数**（数据里没有反事实，学不出来）：分人群扫参数画 Pareto 前沿，选业务能接受的留存损失下收入最大的点；而且要做成人群分层，不是全站一个值。 |
| 「你怎么证明给 IAA 流量会伤留存？」 | 分群 AB + 长周期指标（短期收入与 D30 留存通常反向）；也可以看"广告密度分档 × 留存"曲线，拐点就是约束该设的位置。 |
| 「混合变现的游戏怎么归类？」 | 不归类——按**变现结构**建模：记 IAP 占比，两套价值模型加权，占比随生命周期滚动更新。 |
| 「这样排会不会复杂到线上跑不动？」 | 线上仍是 `pCTR × 单次期望价值` 的乘法框架，复杂度只在**权重从哪来**——人群分层权重是离线产出的一张表，线上只查表。 |
| 「低 DAU 的 IAA 游戏怎么办？」 | 冷启动给独立探索预算；长期靠质量门槛（素材质量分、次留门槛）筛。不能靠排序自然淘汰——那样它永远没机会证明自己。 |

**金句**

> IAP 游戏和 IAA 游戏要的不是同一批人——一个要愿意掏钱的少数，一个要愿意花时间的多数；把这两类放进一个池子按同一个分排，问题不在"怎么比"，在"该给谁"。

> IAA 的收入是即时的，成本是滞后的：它透支的是用户耐心，账记在留存上——而留存的账，三个月后才出现在报表里。

### 8.6 这条怎么接回主线

- **接 §二**：先讲两类供给画像（投资标的 vs 库存变现），再讲"要的人不同"。
- **接 §三**：§三 是"钱怎么换算"，本节是"内容怎么共处"——两个切面合起来才是完整答案。
- **接专题 02**：统一 pLTV / Hybrid ROAS / 频控分层的**解法**在专题 02，本节是**问题侧**，配套使用。

## 九、哪种 LTV 算得更准：测量 vs 预测（「准」为什么反而是陷阱）

> 承接 §二 / §八：前两节讲"两类供给是什么、放在一起出什么问题"，本节讲**估计层**——两类 LTV 的误差性质根本不同。
> 面试里的价值：这是一道**看起来是常识、答对了显功力**的题。答"广告更准"只能拿到及格分；答出"准的口径分三种、而且广告的准是条件准确"才是能立住的回答。

### 9.1 一句话本质

- **广告侧（IAA / eCPM）是「会计算的账」**——测量型：曝光即计费、有结算单可核对、不依赖模型。
- **联运侧（IAP / LTV）是「要猜的账」**——预测型：删失、延迟、重尾、漂移，四项都是结构性的。

**单看数字准确度：广告更准。** 但对混排决策，广告的"准"是**条件准确**（在当前投放密度下才成立），当成外生参数用比"不准"更危险。

### 9.2 先分清三种"准"的口径（这是拿定义权的地方）

| 口径 | 问的是什么 | 谁更准 |
|---|---|---|
| **会计口径** | 这次 / 当期收入算得对不对 | **IAA 完胜**（有结算单可核对，不靠模型） |
| **预测口径** | 这个用户长期值多少钱 | **都难，IAP 难得多**（删失 + 重尾） |
| **决策口径** | 我换策略之后它还值多少（反事实） | **IAA 的准不能外推；IAP 的不准反而可被建模刻画** |

> 一句话对比记牢：**IAA 是「确定但受限」，IAP 是「不确定但可建模」。**

### 9.3 广告侧：测量型准确，但有三个条件

**准在哪**

1. **不依赖模型**：eCPM 由广告主真金竞价形成，事后与结算单对得上——是"测"出来的，不是"估"出来的。
2. **统计方差小**：时间粒度细（小时级收敛）+ 样本量大（曝光量级比付费事件量级高出若干个数量级）。
3. **不需要外推**：它回答的正是"此刻这次曝光值多少"，不需要跨时间预测。

**边界在哪（这三条是加分项）**

1. **条件准确**：这个数是在"当前密度 + 当前人群 + 当前竞价环境"下测出来的。换策略它就变（内生性，见 §三 第 7 条）→ 只能当**测量值**用，不能当**参数**外推。
2. **impression-level 准 ≠ user-level 准**：要归到"这个用户值多少"，得做多广告位分摊 / 归因，这一步误差不小——把曝光级准确度误当用户级 LTV 准确度是常见坑。
3. **它准的是"现在的价"，不是"这个用户对生态的价值"**：留存、审美疲劳、长期活跃这些它一概不反映。

### 9.4 联运侧：预测型不准，而且是结构性不准（采样解决不了）

| # | 误差来源 | 机理 | 能否靠加数据消除 |
|---|---|---|---|
| 1 | **删失** | 观测窗内没付费 ≠ 不付费，慢付费人群被当负样本 | 不能（要靠建模/拉长窗） |
| 2 | **延迟** | LTV 需 1–2 周收敛，大 R 更久；T+1 数据必然低估 | 不能（只是等） |
| 3 | **重尾** | 均值由 3–5% 大 R 决定 → 均值估计方差极大、收敛极慢 | **不能**（分布使然，不是样本不够） |
| 4 | **异质 + 漂移** | 每款游戏、每个渠道、每次版本更新的分布都不同 | 不能（要靠条件建模） |

**关键认知**：IAP LTV 的误差**不会因为样本变多而线性消失**——它是**模型问题，不是采样问题**。这正是它必须上 ZILN（σ 输出供分位下界）、ODMN（多分布专家分治）这类建模的原因。

### 9.5 反直觉结论（这节最值钱的一条）

- **会计口径的准确度：IAA 更准。**
- **但 IAA 的准是自证的**：你用它的数去提广告密度，提完之后**原来那个数就不成立了**（eCPM 是密度的函数）。

> **IAA 是「精确的错误」，IAP 是「粗糙的真实」。** 宁可要一个知道自己错在哪的估计，也不要一个看起来确定、却被自己决策污染的估计。

再补一刀（面试可以主动说）：广告侧的"准"还有一个隐性代价——**它会让人放弃建模**。长期价值、大 R、uplift 这些必须建的东西，一旦"有现成数字可用"就没人愿意投入了；反倒是 IAP 的"不准"逼着团队把模型做对。

### 9.6 实操：谁更容易做准（可交付的部分）

**IAA 侧**

- 收入本身好估（RPM / 广告 ARPU 基本是除法）；
- 难点在**归因到内容与人群**：多广告位、多次曝光要分摊，新游戏样本少、还要防无效流量。

**IAP 侧（三条把准确度"挣"回来的路）**

1. **漏斗分解**：曝光 → 点击 → 下载 → 首充 → 留存 → 累计付费，每环单独建模，比端到端硬估 LTV 方差小得多。
2. **分层贝叶斯 / 向大盘借先验**：同品类游戏 pooling，解决新游样本少（对应"新游冷启"）。
3. **延迟反馈校准**：真值回来后反标预测偏差；同时把**观测时长 t 当条件输入**，新样本即时可用（见 §三 第 5 条、专题 12）。

**一句话**：**广告的准确度是天生有的，代价是结构性受限；联运的准确度是设计出来的，靠建模和校准挣。**

### 9.7 落到混排决策（这条为什么值得问）

**错误姿势**：用"谁的 LTV 准"来决定谁该拿量 → 必然偏向 IAA → 这就是 §八 第 2 条「反馈速度不对等」的**估计层版本**，也是主粮被压的原因之一。

**正确姿势**

1. **不按"准"排，按"价值"排**：准不准只影响我**敢不敢用这个数出价**，不影响它值多少。
2. **不确定性显式进排序**，而不是当"信/不信"的开关：IAP 侧走保守分位数下界 + 成本 cap；新游给独立探索预算。
3. **反过来修 IAA 侧的内生性**：把即时收入按"密度提升则衰减"做折价（留存折价），别按会计口径全额入账。

### 9.8 口述稿（40 秒）

> 单看准确度，广告侧更准——它的 eCPM 是**测出来的**：曝光即计费、有结算单可核对、小时级收敛，样本量还比付费事件大好几个数量级。联运的 LTV 是**估出来的**，要面对删失、延迟、重尾和漂移，而且这四个误差不会因为数据变多就消失——它是模型问题不是采样问题，所以我用漏斗分段建、向大盘借先验、真值回来做校准来挣准确度。
> 但混排里有个陷阱：广告的"准"是**条件准确**，它是在当前投放密度下测出来的，你按它加密度，原来那个数就不成立了。所以我把两件事分开——**准不准，决定我敢不敢拿它出价；值多少，决定它排多前**。不确定性用保守分位数进排序，而不是用"谁准就信谁"来决定给谁量；真那么做，被牺牲的一定是联运这个主粮。

### 9.9 追问防御

| 追问 | 怎么接 |
|---|---|
| 「那联运 LTV 不准，你还怎么敢用？」 | 不用点估计用分布：**分位下界出价 + 成本 cap**；再给新供给独立探索预算让它自己挣数据。 |
| 「广告不也有延迟吗？」 | 延迟在**出价方**（广告主回传优化目标），平台侧的广告收入结算是即时的——关键区别在这：平台广告收入即时确认，联运分成后置。 |
| 「你到哪信哪个？」 | 都信，但用法不同：广告的数当**测量值**用、不外推；联运的数当**分布**用、走保守边界。分水岭是"这个数是测的还是推的"。 |
| 「多采样能不能把联运估准？」 | 重尾分布下均值收敛极慢，加数据不是解法；要么改分位数 / 分治建模，要么拉长观测窗。 |
| 「那广告的 LTV 是不是可以照搬去做联运？」 | 不行——广告是 impression 级、单次独立可测；联运是 user-lifecycle 级、跨期相关不可测。把单次测量往用户生命周期搬，是量纲和分布的双重错配。 |

**金句**

> 广告的 LTV 是**测出来的**，联运的 LTV 是**挣出来的**——一个准在当下，一个准在模型。混排里最危险的不是联运估不准，是把广告那个"精确的错误"当成了外生参数。

## 十、自然流量与商业流量怎么同池排序（我最独特的经历）

> 对应问题 6（清单「自然流量」模块：搜索 / PC / 发现页 / 外部）。
> **为什么这条要单独成节**：前四节讲的是"两种商业收入"（联运 vs 广告）和"两类商业供给"（IAP/IAA 游戏）怎么比。
> 本节讲的是**第三个、也是更根上的切面**：**自然结果（不收钱的那部分）和商业结果（收钱的那部分）怎么放在同一次请求里排**。
> 面试价值：这个坑我做过**三种形态**——应用商店（自然应用 × 广告）、搜索（自然结果 × 商业推广）、游戏中心（自然推荐 × 联运 × 广告）。同一个问题换三种形态各踩一遍的人不多，这是**别人抄不走的经历**。

### 10.1 一句话本质

**自然和商业的冲突不在"内容好坏"，在"两本账不能合成一个分数"：**

- **自然结果优化的是用户效用**——相关性、多样性、时效、权威、去重，全是**非货币**的、且**无法标价**的。
- **商业结果优化的是平台收入**——eCPM / 折现值，**天然是货币**的、且可结算。

同池排序不等于"打一个共同的分"，而是**给自然位的机会成本定价，再把不可标价的约束交给机制层**。

> 面试开口第一句：**"这两个东西没法合成一个分数，也不该合成——合不成的部分交给机制，能算的部分交给价格。"**

### 10.2 为什么必须同池（先回答"为什么不干脆分层"）

这是第一个会来的追问。很多人只会说"同池能提升效率"，讲不清反面：

| 方案 | 好处 | 死法 |
|---|---|---|
| **硬分层**（自然位固定 N 条 + 广告位固定 M 条） | 生态安全、约束好表达、实现简单 | ① **位置价格被锁死**：广告需求旺时提不了价（价格天花板固定），需求淡时又浪费曝光；② **自然侧感受不到机会成本**——它不知道自己挤掉的钱，排序不收敛到最优；③ 流量波动时无法自适应（大促/热点场景） |
| **完全同池**（一个分数自由竞价） | 效率上限高、自适应 | **生态崩**：短期收入曲线漂亮，半年后留存掉（§三第 7 条 eCPM 内生的同款死法） |
| **同池竞价 + 机制层约束**（我的做法） | 兼顾 | 需要一套"定价 + 护栏"的机制设计能力，这是门槛 |

**结论一句话**：分层解决的是**生态安全**，同池解决的是**定价效率**——所以正确形态是"**同池竞价、约束在机制层**"，不是二选一。

**为什么影子价格优于硬配额**（我的改造，见 10.5）：硬配额在"配额没用完"时白白浪费曝光，在"配额刚用完"时出现断崖；把配额约束写成**对偶量（影子价格）**，它自动变成出价折扣因子——约束紧时分值自觉降下来，约束松时自动放开，**连续、可解释、可回滚**。

### 10.3 四个真问题（这是本节的主干，比"怎么排"重要得多）

**问题 1：自然分没有货币单位 → 和收入不可比**

- 这是所有人卡住的地方。业界的本能反应是"**给用户效用标一个钱**"（willingness-to-pay / utility→货币 的 transform）——方向没错，但落地极难：真正要估的是"用户这一次多看到一条自然结果，愿意付多少钱"，**没有观测数据、没有反事实、只能靠问卷和假设**。
- **我的判断（差异化洞察）**：不要给**用户效用**定价，给**位置的机会成本**定价。
  - 自然位的机会成本 = **这个位置如果不放自然、放商业，能拿到多少钱**。
  - 这个东西**可测**——查该位置 / 该流量的历史 eCPM 分布（分位数）就有，不需要给"用户满意度"编一个货币汇率。
  - 一把尺子解决两件事：自然结果的"价值"有了货币等价（机会成本），且这个等价**天然随市场波动**（广告需求涨，自然位的门槛也跟着涨），不需要人工调参。
- **面试话术**：**"给用户效用标价很难也很虚；给位置的机会成本标价是可测的——同一个问题的两个方向，我选后者。"**
  > 这句话是本节的**王牌**：它把一个"谁都答不上来的哲学问题"转成一个"有数据的工程问题"，这是判断力的展示。

**问题 2：约束不是分数能表达的东西 → 必须进机制层**

- 自然侧身上背着四类**硬约束**：多样性（品类不相邻）、时效性、权威性、去重；商业侧还有：不能连续广告、单页广告上限、预算与频控。
- 这些**都不是"分数高低"能表达的**——你没法用一个加权惩罚项同时表达四种约束（典型的调参地狱：压住多样性伤了相关性，护住时效又破了权威）。
- **实证（我的经历）**：腾讯搜索混排改造，正是因为"点击率预估表达不了**该给谁**的排序语义"——时效性 / 权威性 badcase 用点估分压不住，最后改成 **LTR** 方案（listwise 的排序语义 + 约束作为特征/约束层）。这条可以直接讲：**"我踩过这个坑，所以我知道约束要从分数里拿出来。"**
- **正确做法**：分数负责"值多少"，机制负责"能不能放、放几条、放哪"——**两层分工，不要混**。

**问题 3：商业结果的外部性不在分里**

- 一次商业曝光对用户后续自然消费的伤害（疲劳、信任损耗、跳出）不在 eCPM 里——外部性必须显式定价或做成约束（§三第 8 条，同源）。
- 对自然×商业这一对，外部性还有**双向性**：商业挤自然（伤用户体验）+ 自然挤商业（伤收入）。**只盯一头一定会跑偏**，所以护栏要双向（自然保底份额 + 商业密度上限），且考核要**净收入口径**（回捞收益要减掉被挤掉的正常收入，见问题 3 那节）。

**问题 4：同一请求内不是独立打分 → 带约束的序列决策**

- 混排是**一个请求内的互相竞争**：独立估 pCTR 在混排里不准（位置递降、上下文互相影响），还要满足"品类不相邻""不连续广告""广告不过首屏第 1 位"这类**序列约束**，本质是 listwise / 序列决策，不是 pointwise 排序。
- 这也是为什么"把自然分和商业分各自算好、再从高到低排"这种做法**在混排里必然失真**。

### 10.4 三种形态对照（这是经历证据，面试用来"一次讲完三种"）

| 形态 | 自然侧 | 商业侧 | 当年的融合方式 | 我踩到的真问题 |
|---|---|---|---|---|
| **百度·应用商店**（2016-2018） | 应用相关性 / 下载转化 | 广告：`pCVR × price` | **`eCPM` 混排**（判分即混排，实测 eCPM +24%） | 纯按 price 排 → **高价低质应用长期占位**；补了一层**质量因子**（下载完成率、卸载率等后验信号回灌排序） |
| **百度·搜索 CTR** | 自然检索结果 | 商业推广 | `pCTR × price` 排序（eCPM +21%+） | 点估分压不住"该给谁"的语义（与腾讯搜索同款病根） |
| **腾讯·QQ看点搜索混排**（2020） | 自然结果 | 商业结果 | CTR 预估 → **改 LTR** | 时效性 / 权威性 badcase 表达不出来 → **约束要从分数里拿出来** |
| **OPPO·游戏中心**（2022-2023） | 自然推荐位 | 联运（内部广告主，pLTV 折现出价）+ 广告 DSP（eCPM） | **广义 eCPM 统一 + 配额 / 影子价格护栏**（专题 03） | 三方同池：口径不可比 + 生态挤压 + eCPM 内生反噬 |

**这张表的用法**：面试里被问"你做过自然和商业一起排吗"，先给这张表（**三种形态，判分与混排的耦合度逐层加深**），再落到一句总结——

> **"三种形态的坑是同一个：自然侧的价值没有货币单位，商业侧的外部性不在分数里。我三次的解法都是在收敛同一套东西——先统一计量口径，再用可解释因子做权衡，最后用配额与护栏兜住生态。"**

### 10.5 解法五件套（我的做法 + 每条的改造）

**① 统一计量口径：把自然价值折算成"机会成本"的货币等价**

- 做法：自然位的价值不进"用户效用货币化"，而按**该位置的机会成本**（历史商业 eCPM 分位数）折算。
- **改造点**：不取均值取**分位数**（保守），且按流量时段 / 人群分层（大促期机会成本本来就高，自动收紧自然位）。

**② 分数层保留双分量，冲突在机制层裁决**

- 做法：`score = pCTR × [ eCPM_商业 或 机会成本_自然 ]`，**保留两个分量**而不是合成一个标量（同一份分数给不同人群不同权重，见 §八 8.3 第 2 条）。
- **改造点**：权重**按人群分层**——高商业容忍度人群抬商业权重，低容忍度人群抬自然权重；依据是"该人群在两个分量上的价值离散度"，不是全站一个数。

**③ 配额护栏不做硬截断，写影子价格**

- 做法：把"自然保底份额 / 商业密度上限"的约束转成**对偶量**，作为出价折扣因子进分数。
- **改造点（相对业界硬配额）**：连续可调、不会"配额没用完白白浪费"、不会"配额用完断崖"，而且约束值本身可解释（业务方看得懂"现在商业位的隐含价格是多少"）。

**④ 质量因子只降权、不提权（百度经验的教训，我最看重的一条）**

- 百度那次的教训：只按 `pCVR × price` 排，高价低质的应用会长期占位——所以要补质量后验信号（下载完成率、卸载率）。
- **改造点**：质量因子**只用于商业侧降权，不用于提权**。
  - 理由：提权等于**平台给商业内容做信用背书**（"这条是平台推荐的"），一旦质量分被优化（Goodhart）就变成公关风险；
  - 降权才是**纠错**——低质高价自己掉下去，机制上干净。

**⑤ 生态护栏 + 净收入口径**

- 双向护栏：自然保底份额（防商业挤死自然）+ 商业密度上限（防透支用户）。
- 考核用**净收入口径**（回捞 / 加密度带来的收入，要减掉被挤掉的正常收入与留存损失），否则团队会被自己造出来的 KPI 牵着走（§三第 10 条 Goodhart）。

### 10.6 口述稿（60 秒）

> 自然结果和商业结果同池排序，最容易被问的一句是"为什么不分层"。我的答案是：**分层解决生态安全，同池解决定价效率**——分层会把位置价格锁死（广告旺季提不了价、淡季浪费曝光），而且自然侧感受不到机会成本，所以我的形态是**同池竞价、约束在机制层**。
> 真正的难点是**自然侧没有货币单位**：业界本能是给用户效用标价，但你无法观测"用户多看到一条自然结果愿意付多少钱"。我的做法是**不给效用定价，给位置的机会成本定价**——这个位置如果不放自然、放商业能卖多少钱，查历史 eCPM 分位数就有，可测、天然随行情浮动、不需要人工调参。
> 第二件事是**约束不能进分数**：多样性、时效、权威、去重，你没法用一个惩罚项同时表达，只会掉进调参地狱。这条我踩过——腾讯搜索混排就是因为点击率预估表达不了"该给谁"的语义、时效和权威 badcase 压不住，最后改成了 LTR。所以约束交给机制层，分数只管"值多少"。
> 落地我做了三件事：配额护栏不做硬截断、写成影子价格（连续、不会浪费曝光）；质量因子只对商业侧降权、不提权（提权等于平台给商业内容背书）；考核走净收入口径，否则就是在自己造 KPI。

### 10.7 追问防御

| 追问 | 怎么接 |
|---|---|
| 「自然结果和广告一起排，会不会把自然挤死？」 | 不会——护栏是**双向**的：自然保底份额 + 商业密度上限，而且自然位有机会成本定价（商业需求旺时自然位门槛也涨，但**保底份额不动**）。挤死的不是自然，是"**生态没有上限的密度**"。 |
| 「自然侧的价值你怎么量化？用户满意度能标价吗？」 | 我不给用户效用标价——那是不可观测的。我给**位置的机会成本**标价（历史商业 eCPM 分位数），可测、可解释、随行情自动浮动。 |
| 「为什么不用一个大模型端到端学出来？」 | 三个东西学不出来：① **数据里没有反事实**（自然位如果放广告会怎样，没有观测）；② **约束不可微**（多样性 / 不相邻 / 去重）；③ **业务口径要可解释**（分成比例、保底条款是要和商务谈的）。所以分工是"模型管预估、机制管裁决"。 |
| 「三种场景（商店 / 搜索 / 游戏）差别在哪？」 | 差别在**判分与混排的耦合度**：商店是"判分即混排"（`pCVR × price` 直接出分），搜索要处理自然结果的语义与约束（所以走到 LTR），游戏中心最麻烦——商业侧自己就分两种口径（联运折现 vs 广告 eCPM）。**同一套方法论，三种约束强度。** |
| 「质量因子为什么只降不提？」 | 提权等于**平台给商业内容做信用担保**，一旦质量分被针对性优化就是风险；降权只是纠错。而且"高价低质占位"这个病，本来就是**只用价格排**造成的——用价格排的账，用质量信号还回去。 |
| 「影子价格这东西线上怎么实现？」 | 约束求解产出对偶量，作为 bid 折扣因子下发；线上仍是 `pCTR × 价值` 的乘法框架，复杂度只在**折扣因子怎么来**（离线/准实时求解，查表下发）。 |
| 「用户能不能感知到"这是广告"？」 | 能，而且应该——**标注是合规也是体验设计**（打标后点击率会掉，所以要把标注损失计进 eCPM 口径，不能拿未标注的 eCPM 做决策）。这条要主动提，说明我想过真实线上约束。 |

**金句**

> 自然和商业不是两种内容，是**两本账**——同池排序的核心不是给它们打一个共同的分数，而是**给自然位的机会成本定价、把标不出价的约束交给机制层**。

> 给用户效用标价很难也很虚；给位置的机会成本标价是可测的——**同一个问题的两个方向，我选后者**。

### 10.8 这条怎么接回主线

- **接 §二 / §八**：§二、§八 讲商业侧内部（联运 vs 广告、IAP vs IAA）怎么共处；本节讲**商业侧整体 vs 自然侧**怎么共处——三层合起来是完整的混排图景。
- **接 §三**：§三的"外部性没定价"在本节升级成**双向外部性**（商业挤自然 + 自然挤商业），护栏因此必须双向。
- **接问题 3（下一节）**：广告卡提效与控频不伤留存，是本节 ⑤ 生态护栏的**操作版**（密度 / 频次怎么定、怎么测不劣化）。
- **接简历**：个人优势第 3 条"自然 × 商业统一排序：三种形态都做过"——面试被问时**先给 10.4 那张表，再给 10.6 的口述稿**。
