## 项目经历

### 游戏分发与变现算法（与微信小游戏同构场景） | OPPO 游戏中心 & 应用商店 | 2022.06 - 2023.10

- **广告×联运统一竞价（IAP × IAA 统一打分）**：联运收入靠 LTV 后置归收、广告即时按次结算，计量口径不可比 → 排序天然偏广告，而密度失控又反噬留存。业界 value-based bidding 是统一到同一个 eCPM，我做了两点改造：**①折现窗不取全局固定值**——精品 IAP 与小游戏 IAA 的回本周期差一个量级，按品类回本周期定差异化折现窗，否则小游戏被系统性高估；**②配额护栏不做硬截断**，而是把约束写成影子价格（对偶量）转成出价折扣因子，硬截断会在配额没用完时白白浪费剩余曝光。IAP 提权设计为带业务先验的可解释乘性因子——短期收入与大盘留存兼得
- **pLTV 建模与大 R 处理**：pLTV 作为精排融合分输入，按 IAP 付费深度四层差异化分发——头部极小比例用户贡献主要流水，必须单独对待。业界 ZILN 范式拆「付费概率 × 对数正态金额」、ODMN 用多分布专家分治，我的两处改造：**①专家不按金额区间硬分桶，按 σ（预测不确定性）路由**——真正扭曲梯度的不是"金额大"而是"猜不准"，按不确定性路由才能让每个专家拿到方差相近的子分布；**②评估不看 MSE/Gini 就收工**，补一层决策层回检——按出价档位看实际 ROI 与回本周期，预测指标好不等于出价对（Gini 高但分位系统性偏高，出价会全档超耗）
- **出价用的是分位数而非点估计**：pLTV 输出 σ 后我按分位数下界出价，且**分位随样本量自适应**——新游样本少取保守分位（宁可少买不可超耗），积累到一定样本后放开到中位。这条是统一竞价能扛住超耗投诉的关键
- **游戏生态的商业理解**：LTV 折现口径直接对齐游戏买量回收模型（首日回收/7 日回本），并与商务侧对齐联运分成结构——算法口径与业务口径打通是统一竞价能落地的前提，纯技术方案在这类问题上推不动
- **oCPX 智能出价（策略/执行解耦）**：人工调价重构为带预算约束的反馈控制——bid = tCPA × pCTR × pCVR / (1+λ)。选型上对比 RL 出价后选 PID（样本效率与可控性）。改造点：**λ 不由成本单一驱动，而是两维**——成本达成率 × 预算 pacing 进度（只看成本会把预算上午花光或晚上剩量）；并加抗积分饱和与按日重置积分，否则跨日累积的积分项会让调价在新的一天起步就跑偏。CPC/CPA/oCPM 三类结算分别适配出价与成本保障；策略层与执行层解耦，独立迭代回滚
- **CTR 多位置消偏**：先定位根因是分广告位曝光分布漂移而非模型容量。业界两条路线我都没照搬——LHUC 把位置当偏置旁路调制掉，但**在这个场景位置本身就是意图**（闪屏强推 vs 信息流主动浏览，用户对广告的接受度不是同一个量），位置不该被消掉而该进主网络，所以按位置为任务维度构建 MMoE（分位置专家 + 门控）；PCOC 后校准我也做了改造：**校准因子在线滑动更新而非离线固定，且小样本位向全局收缩**（贝叶斯收缩），否则长尾位会因为几条样本剧烈抖动。预估偏差 30%+ 降至 20% 以内、ARPU +1.04%
- **延迟转化建模（T+1 回传）**：游戏转化信号隔日回传且随素材/人群漂移，固定观测窗口必然失真。常见做法是等固定窗口再打标签，我改成**把「已观测时长 t」作为条件喂进模型**（学 P(转化 | 已观测 t)）——新样本进来就能用，不必等窗口结束；同时**早期未回传样本不当负样本**，用观测概率倒数做无偏加权。延迟路以 lognormal 时延分布刻画，且参数按素材×人群分群而非全局一套
- **冷启动 EE 与流量回捞**：冷启动拆解为探索利用——保护期 = 预算内纯探索、专属流量池 = 受控探索、贝叶斯平滑 = 分层先验（新品类借用父类先验，不是全局先验）。关键改造是**先决定「在哪探索」再决定「探索多少」**：高价值流量位的探索机会成本高，所以在低峰/低价值位做探索、把学到的先验迁移回高价值位——同样的探索预算，信息收益更高。新广告平均曝光 +30%、通过率 +15%。回捞沿用同一套「低效流量二次定价」，但加一个**剩余机会系数**——即将流失的曝光按"这次不捞就没了"提价，不是简单重排
- **素材多模态优选**：CNN/BERT 双塔 + Cross-Attention 图文融合支撑素材质量分与优选；SSL4Rec 多粒度对比学习，中长尾用户 ARPU +2.3%
- **端云协同与预取式分发**：云训/端推/端云联合三范式，量化/剪枝产出端侧 Lite 模型，云端负载成本 -25%。预取上我的判断是**深度不该固定**：按「下一落点分布的熵」自适应——行为确定性高时预取深，熵高时只取头部高质量候选；并且**把预取作废率计进成本账**，否则命中率指标会把策略引向"多预取总没错"的浪费方向

### LLM 驱动的个性化推荐系统（个人项目 · 端到端独立开发） | 2026.06 - 至今

- **多源发现与 LLM 评估入池**：自爬 B 站/YouTube/知乎/小红书/播客/音乐/听书等多源异构内容（平台 API + RSS 双通道），四类发现策略（explore/search/trending/related_chain）统一走 LLM 批量评估——相关性打分 + 分数门 admission 入池（300+ 候选）
- **LLM 分只当门控、不当主分**：这是个刻意的取舍——LLM 打分有系统性偏差（偏好长内容、偏好热点），直接拿它排序会放大偏差。我的做法是 LLM 只决定「能不能进池」，排序交给可解释的多路融合分；并且**用 dwell 残差在线校准门限**——LLM 分高但真实停留低的内容持续出现时，说明门限在该类内容上失效，自动收紧
- **排序与多样性**：tier/相关性/新鲜度（3 天半衰期）混合排序；MMR（embedding 余弦打散近义主题）+ 来源硬配比 + 风格限流 + topic 疲劳双轴（细粒度/粗粒度取 max）——单批 10 条主题零重复
- **LLM 重排 agent**：会话式排序——规则分 × 语义分（兴趣质心余弦）× 点赞学习分 × 停留时长分混合打分。探索用 Thompson 采样（Beta 后验），改造点是**零均值注入**——探索只抬后验不确定的臂、不整体抬高或压低分数均值，避免探索期大盘指标难看；且探索预算按后验不确定性分配而非均匀撒
- **LLM 表达生成**：批量预生成朋友式推荐文案——按内容 ID 绑定防乱序错位、跨内容重复文案整组丢弃、限流时降级重试，语气画像驱动表达风格
- **反馈闭环**：显式反馈（like/dismiss）+ 隐式停留时长（dwell）累计触发画像重建，回流影响发现评分与排序；兴趣探针——LLM 猜方向、用户确认或拒绝、结论入画像
- **性能优化**：换一批延迟 2.6s → 0.6s——embedding 并发预热 + 缓存命中率 0→100% + 批量写库 10 次 fsync 合并为 1 次
- **生成式推荐的跟踪与判断**：跟进快手 OneRec 等工业实践（RQ-KMeans 语义 ID、端到端替代级联、推理侧 Pass@K 算力换效果、成本结构重构）——判断是：短期应单点切入（语义 ID 做召回/重排增强），全链路替换的门槛在工程与成本，长期价值在 OPEX 结构；可展开
- **三个一手判断**：①LLM 适合做「裁判」不适合做「主排序算子」——全量打分的延迟/成本与模型分差两个量级；②探索必须显式建模——任何确定性排序都会让「未点过的新兴趣」永久不可见；③隐式信号（dwell）密度比显式反馈高一个量级但噪声大，两者分开建模、加权融合优于混作单一标签
