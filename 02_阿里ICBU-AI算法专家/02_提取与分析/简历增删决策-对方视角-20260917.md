## 一、先定"对方不感兴趣"的判断标准

JD 全文（职位描述 3 条 + 要求 5 条）**一个字都没有出现**：推荐 / 广告 / 搜索 / 排序 / CTR / CVR / eCPM / 召回。

而 **ICBU 的三个关键词**是：**RAG 系统 · 智能 Agent · 智能工作流**；业务是**跨境 B2B 销售**（长周期、多轮、销售团队 + 平台商家两侧）。

所以三类内容要区别对待：

| 类别 | 处置 | 理由 |
|---|---|---|
| **纯广告/推荐机制细节**（位置校准、CTR 偏差、MMoE 结构、召回算法名） | **删或压缩** | 对方不会问，占篇幅，且让读者觉得"这人是做广告的" |
| **可迁移的能力**（从 0 到 1 搭能力、闭环控制、冷启动、价值预估、模型诊断） | **留，但换 JD 的视角写** | 这正是职责 2「主导 / 能力构建」与职责 3「推动迭代」要的 |
| **AI+Sales 正面命中**（线索、触达、工作流、因果验证、RAG、Agent、大模型） | **全部保留并前置** | 命中即加分 |

## 三、加了什么（母版里有、此前从没进过简历）

### ★★★ 1. oCPX 出价闭环：`bid = tCPA × pCTR × pCVR / (1+λ)`，**λ 由 PID 控制每 30 分钟更新**

**这是本轮最重要的发现。** JD 职责 2 要的三件套里，"智能工作流"一直是空的（JD 对齐矩阵判为**空**）。但母版里一直写着这条——**它本质上就是一个自动调节的控制回路**：目标成本进 → 出价自动调 → 每 30 分钟用新反馈修正 → 再出价。

> 之前在腾讯 WXG 那边，我把它评为"λ 两维驱动 = pacing 标准做法，站不住"；**在 ICBU 这个岗位上它的价值完全不同**——这里不考算法新颖度，考**你有没有搭过"自动跑起来的工作流"**。同一条事实，在两个岗位上一个是减分项、一个是王牌。

### ★★★ 2. 延迟转化与用户价值建模（LTV 评估体系）

母版原文：转化拆成"即时转化 / 延迟转化"多任务建模；用户分层（高价值/中低活/潜在付费/新用户）差异化分发；**与产品运营共建 LTV 价值评估体系（D1/D7 留存、付费率、ARPPU 折现）**。

**为什么对方感兴趣**：B2B 跨境销售是**长周期**生意，AI 给的线索今天成交不了、三个月后才成交——**"怎么给一个还没成交的客户估值"是 AI+Sales 的核心问题**，而这个候选人在游戏场景里已经做过一遍。同时它还命中 JD 要求 4 的"跨职能协作"（与产品运营共建）。

### ★★★ 3. 新供给冷启动机制：保护期 + 专属探索流量池 + 贝叶斯平滑初始化

**为什么对方感兴趣**：ICBU 是**双边平台**，既要服务自家销售，也要让**平台商家会卖**（JD 标签有 SaaS）。新商家/新商品拿不到曝光、没有历史数据——**和"新广告主冷启动"是同一个问题**。而且我方有结果数字（通过率 +15%、曝光 +30%）。

### ★★ 4. 腾讯「一站式模型分析系统」

母版：支持特征重要度分析（单 slot / **Shapley** / 基于梯度）、AUC 与特征重要度下钻、指标监控告警。

**为什么对方感兴趣**：AI+Sales 最大的障碍不是模型不准，是**业务方不信**（Salesforce 内部原话 Insight ≠ Impact）。"能解释模型为什么给出这个分"是**跨职能说服**的硬能力，命中 JD 要求 4。

### ★★ 5. 百度段整段换主线：内容评价体系 + 自助查询系统

母版：作为**内容指数负责人**与产品运营共建内容评价体系（**优质度 / 领域集中度 / 原创度**），构建搜索指数特征库与评分模型，**开发内部查询系统供业务方自助取用**。

**为什么对方感兴趣**：这就是 ICBU 那两件事的早期版本——**① 给"供给"打分**（商家/商品质量分层）；**② 给业务方做一个能自助用的工具**（SaaS 化的雏形）。而且"与产品运营共建"= 跨职能。原简历这段写的是"广告 CTR 预估"，对方看了没感觉。

### ★ 6. 保留并已在前一版加入的

- OPPO 多模态大模型素材理解与质量分 → 对应"帮商家把商品卖出去 / 素材生成"
- OPPO 端云协同（量化、剪枝、参数拆分，云端成本 −25%）→ 职责 3 工程纵深
- OPPO SSL4Rec 对比学习（中长尾 ARPU +2.3%）→ 数学/统计功底与表征学习

## 四、v3.2 之后，项目经历的阅读顺序（这就是"套进我的场景"的结果）

```
① AI+Sales 销售线索与触达决策链路（中信）   ← AI+Sales 正面
② 端到端 LLM 系统：RAG + Agent（个人）      ← JD 职责 2 前两件套
③ 多模态内容理解与自动化策略引擎（OPPO）    ← 智能工作流（PID 闭环）+ 冷启动 + LTV
④ 从 0 到 1 的多目标推荐能力构建与模型诊断（腾讯） ← 主导能力构建 + 模型可解释
⑤ 内容质量评估与用户画像（百度）            ← 供给质量评估 + 业务自助工具
```

**读下来是一条线**：销售线索怎么来 → 大模型系统怎么做 → 工作流怎么自动跑 → 能力怎么从 0 搭 → 供给质量怎么评。**没有一段是在讲广告。**
