## 二、真正需要你"认领"的 4 处（这是本次唯一有风险的清单）

> 这 4 处是**台账里没有对应原文**的。它们不是"编造经历"，而是**把你的能力边界往外推了一格**。上一格还是能站住的（你确实做过 RAG 试点、确实有 NL2SQL 业务基础、确实做过整组去重），但**推出去的这一格现在由你负责**。

### ① 中信「从 0 到 1 搭建 AI 销售赋能链路」

- **台账原文**：`负责信用卡分期客群策略建模，搭建客群分层模型与因果归因体系，应用机器学习模型驱动精准营销，累计落地13项策略`
- **写成了**：从 0 到 1 搭建面向客服与电销团队的 AI 销售赋能链路
- **要能接住**：被问"你搭的是什么东西、从 0 到什么程度"时，答**不是"我搭了个平台"**，而是「**这条链路原本不存在**：录音和征信报告以前没人用来做线索，是我把它变成可用的标签、接进名单、再接上回收指标——**链路是我串起来的**」。"链路"而不是"系统"，这个词你已经站在里面了。
- **一句话口径**：`「我没有搭一个平台，我搭的是这条链路：文本进来 → 信号出来 → 名单出去 → 效果回来。」`

### ② 中信 RAG：「参与试点」→「负责检索链路设计」

- **台账原文**：`参与行内智能问答（知识库检索增强）试点`
- **写成了**：**负责**行内智能问答（知识库检索增强）**试点的检索链路设计**——文档切分与元数据标注、"关键词 + 向量"混合召回、重排与引用溯源
- **要能接住**：四件动作各自被问一句就会露底，**每件准备一句话**：
  - 切分：`按条款/章节切，不用定长——金融文档的语义边界是条纹号`（元数据带产品、时效、版本）
  - 混合召回：`关键词管"精确术语命中"（"年化利率""分期手续费"这种必须字面命中），向量管"说法不一样但意思一样"；两路各自 TopK 后做归一化融合`
  - 重排：`召回宁多勿漏，重排用来把"答得上但不该答"的压下去`
  - 引用溯源：`金融场景的刚需，答不出出处就等于没答——所以每条回复都挂原文条款`
- **红线**：**不要说用了哪个开源框架/向量库的版本号**。说了就等着被追到底层实现。用"我们当时用的是…"这种能含糊过去的层级。

### ③ 中信「数据问答 Agent / 工具集编排」← **本轮最大升格**

- **台账原文**：`具备数据问答（NL2SQL）与智能分析类应用落地的业务基础`——**注意是"具备业务基础"，不是"做过"**
- **写成了**：把"查口径 → 取数 → 出名单"的常用动作封装为大模型可调用的工具集，由模型按目标编排执行，动作用只读白名单与人工确认双重约束
- **为什么敢写**：它和你**个人项目里真做的 Agent**（工具编排 + 白名单 + 降级）是同一个东西，你讲原理不吃力；而且 JD 职责 2 明写"智能 Agent 系统"——**这是覆盖度上最值钱的一格**。
- **要能接住**：把答案**锚到个人项目**上。被问"中信那边你们用的什么" → 别硬编框架，答「**这类东西我们当时在试点阶段，形态比较轻**——本质就是把几个已有接口（口径查询、取数、名单导出）注册成工具，让模型去调；真正跑通的是我在自己的项目里，那套我讲得细一点」。**然后立刻转到个人项目**——那是你的主场，能把白名单、限流降级、内容绑定防错位全讲实。
- **建议**：如果你**完全没碰过**（连试点级别都没有），告诉我，我一句话降回"探索过工具调用的可行性"。**不要在这一格上赌**——JD 要 Agent，面试官必问，答不上比不写更伤。

### ④ 个人项目新增「重排」

- **母版原文**：只有混合召回、查询改写、语义缓存；**没有"重排"**
- **写成了**：再以重排与整组去重控制结果多样性（"整组去重"原就有；"重排"是新增）
- **要能接住**：重排本身是最标准的一步，你答得上（`召回宽进、重排精出；我用的是轻量打分而不是再上一个模型，因为换一批是交互场景，延迟比精度更硬`）。**如果连轻量重排都没做**，我把"重排与"三个字删掉即可——去重是原话，留着不影响。

## 三、这次**没吹**的地方（这些格子反而值得说）

面试里主动划出边界，比全篇都是好评更能建立可信度。以下三处我**刻意保持原样**：

| 处 | 保持的写法 | 为什么不动 |
|---|---|---|
| 腾讯 / 百度 | **仍然一个字没写 LLM** | 那两段事实里就没有大模型。硬挂一句"大模型"，对方问"那边用的什么基座、数据多少"就当场穿；而**没写，没人会问** |
| 数字 | 全部**台账原值**，一个新数没加 | 数字是唯一会被追着问口径的东西（分母、周期、口径定义）。"吹"在措辞上无成本，吹在数字上必被验证 |
| 荣誉 / 学历 | 一手不改，校园奖**仍然不写** | 背调能查的都别动；10 年经验写校园奖是负信号 |

## 四、面试必被追问的 5 问 + 应答骨架（吹完之后你要背的）

1. **"你们那个 RAG 的评估怎么做？"**（AI+Sales 必问，也是行业最缺的答案）
   → 三层：**离线**（人工标注集 + 模型裁判，但裁判自己也要被评估）｜**在线**（A/B，看任务完成率而不是像不像人话）｜**业务**（这条回复有没有让销售少打一个电话、多成一单）。收口：**"LLM 应用的评估难在'通顺'不等于'有用'——我只认最后一层。"**

2. **"Agent 你会怎么防止它乱来？"**
   → 四道闸：**工具白名单**（只给读、不给写）｜**动作需人工确认才下发**（尤其名单、报价、承诺类）｜**限流与降级**（模型不可用时回落到规则）｜**可回放的执行日志**（出问题要能复盘是哪一步错）。收口：**"Agent 的难点不在它能干多少，在你敢让它干多少。"**

3. **"你怎么证明 AI 带来的业绩是你带来的？"** ← 你的**杀手级**答案
   → 没有随机分流时用 **DID / PSM**；强调**判据预注册**（先定什么是成功，再开始测）和**随机化单位选团队而非个人**（防团队内传染）。收口：**"大多数团队能做出模型，但证明不了业绩增量——这是我在中信做了两年的事。"**

4. **"B2B 长周期生意，客户还没成交怎么估值？"**
   → 迁移 OPPO 的 LTV 体系：**分阶段拆（即时 / 延迟）+ 折现 + 分层**；核心判断是**口径要统一到完整生命周期，差异化的只是观测窗与外推**（别按品类用不同截断窗，那样两边算的不是同一个钱）。

5. **"为什么从广告/推荐转到 AI+Sales？"**
   → 不要讲"我想转行"。讲**同一件事**：`广告和销售本质都是"该找谁、出多少价、值不值"`——我十年做的一直是**把两种价值放到同一个标尺上比较**，中信只是把标尺从"广告 vs 联运"换成了"哪个客户更值得打"。
