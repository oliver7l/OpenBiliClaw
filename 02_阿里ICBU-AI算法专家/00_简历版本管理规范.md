> 建立：2026-09-17｜位置：项目根 `02_阿里ICBU-AI算法专家/03_简历版本/`（与 `简历库/`、`求职知识库/` 同级）
> 与 `01_腾讯WXG-推荐投放算法/00_简历版本管理规范.md` 同源，规则一致，仅岗位不同。

## 一、为什么不放在岗位弹药库里

弹药库（`求职知识库/03_岗位弹药库/`）装的是**情报与调研**；简历是**交付物**。
混在一起会出现两个问题：①改简历时反复被调研文档干扰；②版本迭代会覆盖、追溯困难。

**情报归弹药库，简历归版本库**，两边靠索引文档互相指路。
⇒ 本岗位的简历已于 2026-09-17 从 `03_岗位弹药库/阿里ICBU-AI算法专家-深圳-面试准备/` 迁出，该目录只留一个指路 README。

## 三、版本编号规则

- **格式**：`vN-<标签>-<日期>`，例 `v1-AI+Sales初稿-20260917`
- **N 递增**，不复用、不回退；小步措辞改动不递增（记在版本索引里即可）
- **三件套同版同号**：`童力-ICBU-AI算法专家-深圳-vN-<标签>-<日期>.{md,docx,pdf}`
  - `.md` = 唯一真值源（所有改动先改 md）
  - `.docx` = 投递主用（HR 系统解析）
  - `.pdf` = 投递备用（保排版、可搜索，ATS 友好）
- `现役/` 内文件名**不带版本号**（`童力-ICBU-AI算法专家-深圳.{md,docx,pdf}`），方便直接发送

## 四、快照规则（可追溯的关键）

触发条件（满足任一即存快照）：
1. **用户明确认可**（"这版可以"）→ 目录名带 `-用户认可`
2. **对外投递前** → 目录名带 `-投递留档`
3. **大改前** → 目录名带 `-改前基线`

快照一旦存入**不再修改**，只增不删。回滚 = 从快照目录复制回 `现役/`。

## 五、改动流程（纪律）

```
1. 改 md（唯一真值源，不直接改 docx/pdf）
2. 跑生成脚本 → docx + pdf
     .venv/bin/python scripts/resume_library/build_resume_files.py <md路径>
3. 校验：页数 / 关键数字零缺失 / 禁用词零残留 / 文本层无坏字符
4. 同步 03_简历版本/00_版本索引.md（记一行业改动）
5. 认可则存快照；更新 现役/
6. 重建索引：scripts/resume_library/build_resume_index.py
```

## 六、事实底线（任何版本不得突破）

- **数字纪律**：所有数字必须可溯源到 `简历库/00_事实源/童力-事实台账.md`；台账没有的一律不写，**属实则先补台账、再从台账出发改简历**
- **归因纪律**：数字只能挂在台账里它真正所属的那件事上（⚠️ 本岗位初稿已出现一处归因错位，见 `02_提取与分析/简历事实核查-台账对账-20260917.md`）
- **禁用项**：ROAS +8%（用户指示删除）、中信不续签/分流处境（披露纪律）、未做过的实操（按 A/B/C 答辩档位）
- **包装边界**：场景与数字必须真，方法名词可借业界范式；被深挖时按档位降级，不硬撑
- **本岗位的特殊例外**：`个人 LLM 项目` 在台账 5B 里标注为「仅面试可聊、不进简历」。本岗位为 LLM 重岗，初稿把它写进了项目经历——**该例外必须由用户拍板后同步修改台账**，否则视为违规项。
