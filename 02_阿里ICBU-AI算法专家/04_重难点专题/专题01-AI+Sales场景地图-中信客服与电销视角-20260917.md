## 一、先定位置：我是「决策中台」，不是「面客工具」

一句话说清我在中信的角色：

> **我做的是销售 AI 的「上游」和「下游」——上游是「该找谁」（把非结构化文本变成需求信号、出名单），下游是「算得准不准」（渠道口径统一 + 因果归因）。中间那一段「怎么触达、说什么」，不在我手上。**

拆开就是三段：

| 段位 | 回答的问题 | 我 | 典型形态 |
|---|---|---|---|
| **上游 · 找谁** | 该打给谁？为什么是他？ | ✅ **主力** | 文本抽取 → 需求标签 → 线索评分 → 名单 |
| **中游 · 怎么说** | 说什么、什么时候说、能不能实时提示 | ❌ **空** | 实时坐席辅助、话术生成、外呼机器人、陪练、质检 |
| **下游 · 算不算得准** | 这件事到底有没有用？ | ✅ **主力** | 六渠道口径统一、转化漏斗、DID/PSM + uplift |

### 为什么这个「缺中游」的位置，在 ICBU 反而更好讲

因为 **B2B 跨境销售 ≠ 电话电销**，两者的价值重心不一样：

| | 银行电销 | ICBU 跨境 B2B 销售 |
|---|---|---|
| 决策单元 | **单次通话**定成败 | **长周期多轮**：询盘 → 报价 → 打样 → 谈判 → 下单 |
| 单次接触的杠杆 | 极高（一开口就定生死） | 中（一轮谈不成很正常） |
| 最缺什么 | **临场说什么** → 实时 copilot | **该找谁 + 带什么材料去谈** |
| 所以 | 中游工具最值钱 | **上游信号 + 下游算账最值钱** |

**结论**：我在电销场景里"缺的那一块"，恰恰是 B2B 场景里相对次要的一块；我**最强的上游能力**（把难以利用的文本变成可执行线索）在 B2B 是核心能力，不是边角能力。

> **面试可用的一句话**：
> 「我在中信做的是销售 AI 的上游和下游——**该找谁**，以及**这件事到底有没有用**。ICBU 让我补上中游：怎么把找到的客户谈下来。三段加起来才是完整的 AI+Sales。」

## 三、A 类：我一手做过的（可进简历 + 要能顶住追问）

### A1 · 人行征信报告 → 需求信号

**业务问题**：征信报告是 PDF/文本，字段多、格式杂（一代/二代、各家银行口径不同），此前靠规则和关键词匹配，**口语化表述、跨格式文本、他行信贷与查询记录都吃不到**。

**我做的**：用大模型统一抽取为**需求标签与强度特征**——把"有多少额度、在还什么、最近查了几次、负债结构什么样"变成模型能吃的东西，直接供给下游名单策略。

**为什么这条在业内是标准动作**（可用来证明方向对）：
- 中原银行现金分期项目的数据层第一条就是"整合行内流水、代发工资、公积金缴存、**人行征信报告**、APP 埋点"。
- 贵阳银行把"人行征信报告中历史还款记录、负债结构、循环使用率"做成**上千个动态特征变量**的一环。
- 有研究专门量化"**外部征信数据对信用卡分期精准营销的提升**"，用 XGBoost 对比行内特征 vs 加外部征信特征。
→ **不是我拍脑袋，是整个行业在把征信文本往营销特征里灌。**

**面试口径**：讲"我把非结构化文本变成可执行信号"，**不讲模型细节**（台账禁写基座/参数量）。追问"怎么保证抽取准确"→ 落"抽取结果要能对回业务可验证的事实（额度/账龄/查询次数），不对不回，宁可不用"。

### A2 · 坐席通话录音 → 需求信号（★ 最像 ICBU 的一条）

**业务问题**：录音里有最真实的意图，但**非结构化、量大、口语化**，此前只能抽检或者干脆不用。

**我做的**：录音转写 → 大模型抽取需求标签与强度特征 → 进线索模型 → 进名单。

**这条有两个极硬的外部背书（面试直接用）**：

1. **广发信用卡「线索雷达智能体」**——公开定义是「通过**多渠道客户交互会话分析**，构建**线索挖掘—精准触达—高效转化**机制，将海量客户交互数据转化为可执行的营销策略」。
   → 这句话**几乎逐字对应我做的事**：会话分析（录音/交互）→ 线索挖掘（我的抽取）→ 精准触达（我的名单）→ 高效转化（我的漏斗与归因）。**区别只是他们给它起了个产品名。**
2. **Axis Max Life（印度上市寿险）** 用 AI 分析 60 万+通话（1.4 千万分钟 / 700+ 坐席）后得到一个反直觉结论：
   > **「销售对话的前 90–120 秒，比客户人口统计特征更能预测转化」**
   → 这条能帮我把**方法论**讲透：**对话文本的信息量高于画像特征**，所以"从录音里挖"不是降本手段，是**提精度手段**。这正是我为什么把它做成模型输入而不是只做质检。

**为什么这条对 ICBU 特别值钱**（B2B 迁移）：
IBCU 的销售沟通同样沉淀在**询盘聊天、邮件、旺旺/WhatsApp 会话、通话**里，而且**跨语言**（买家英文/小语种）。我这套"转写 → 抽取 → 标签 → 进模型"的链路，**语言换一换就能用**，且抽取的东西从"分期意愿"换成"采购意向、品类偏好、报价敏感度、认证要求"。这是我可以**直接认领**的能力。

### A3 · 汽车分期等重点产品的名单（★ 用户点名要讲的故事）

**为什么"汽车分期"这个故事好讲**：

| 维度 | 汽车分期的特殊性 | 为什么它是个好例子 |
|---|---|---|
| **需求有明确触发点** | 买车是低频、大额、有明确时间窗的决策 | 所以"该找谁"的信号价值极高——**找错人 = 全损，找对人 = 高价值** |
| **信息天然分散** | 购车意向常常**先出现在对话里**（客服咨询、他行查询、消费流水变化） | 正好印证 A2：**文本里比画像里更早看到意向** |
| **多方参与、链路长** | 客户 / 4S 店 / 银行三方，客户可能被 4S 店金融方案抢走 | 所以"触达时机 + 承接率"两个指标都关键 |
| **金额大、可归因** | 单笔分期额度大，策略效果能算清楚 | 正好接 **DID/PSM**（A5）——**效果可证的故事才立得住** |

**我做的**：基于需求特征构建线索评分与分层，落到汽车分期等重点产品的触达名单，**月均产出线索 20 万条、线索承接率 35%**（口径：分期客群触达名单口径，含汽车分期等重点产品）。

**面试讲法（三层）**：
1. **业务**：为什么汽车分期值得单独做分层——低频大额、窗口短、竞争者（4S 店金融）在侧。
2. **方法**：需求信号从哪来（征信 + 录音 + 行为）→ 线索评分 → 分层 → 名单。
3. **闭环**：35% 承接率是**回收指标**，不是产出指标——它反过来告诉我们**名单质量**和**坐席执行**各占多少（**这句是区分度所在**：多数人只会说"我产出了多少名单"，不会说"我盯的是承接"）。

### A4 · 六渠道口径统一 + 转化漏斗

**业务问题**：外呼、动卡、短信、企微、公众号、APP **六个渠道各算各的**，口径不统一就**没法比较渠道效率，也没法做组合优化**。

**我做的**：统一「触达 → 响应 → 转化」三段口径，构建转化漏斗，驱动渠道组合与名单投放优化。

**为什么这是"AI+Sales 的必备地基"**（可迁移的通用判断）：
> **智能工作流的价值不在"能自动跑"，在"每一段都能被度量、能回收、能迭代"。**
> 我做的第一件事不是加模型，是**把口径打通**——因为口径不统一，后面所有的模型和策略都无法验证。
→ 这句话对 ICBU 的映射：跨境 B2B 的销售动作散在**询盘 / 邮件 / IM / 电话 / 展会**里，**第一个真问题同样是"口径不统一"**。我有一套现成的做法。

### A5 · DID/PSM 因果归因 + 累计落地 13 项策略（★ 最硬的一块）

**业务问题**：真实业务里**没有随机分流**——名单是策略挑过的、坐席有偏好、时间窗口有季节性。**直接对比"A 组 vs 非 A 组"必然有偏**（这正是我 9/17 腾讯 WXG 那场被追问的口子）。

**我做的**：用 **DID / PSM** 在无随机分流的真实业务里评估策略对转化与业绩的真实增量；累计落地 13 项策略。

**这条是"AI+Sales 最容易被忽略但最决定成败"的一环**：
- 业内公开案例非常一致地指向同一个痛点：**Insight ≠ Impact**。Salesforce 内部实践的原话是——**模型在测试里表现很好，但销售根本不用**；真正要解决的是"把已有的模型变成行动"。
- 大量银行项目的难点也**不在建模**，在"**效果无法量化归因**"。
→ 所以我的定位话术是：**「我不只是把模型做出来，我是那个能让业务方相信这个模型真的有用的人。」**

**这条对 ICBU 的直接价值**：ICBU 销售团队做 AI 产品，**最大障碍不是技术，是"销售愿不愿意用"**（JD 职责 1 的原话是"**提升销售流程的效率和团队业绩**"）。我有一套把"AI 建议"变成"可验证业绩增量"的方法，这是**从 0 到 1 做 AI+Sales 产品必须有的能力**。

## 六、落到 ICBU：三条主线怎么讲

### 主线 1 · 「找对人」：我做的事在跨境 B2B 直接复用

银行侧：征信文本 + 录音 → 需求标签 → 线索评分 → 名单（20 万条/月）
ICBU 侧：卖家/买家资料 + 询盘会话 + 交易行为 → 采购意向标签 → 商机评分 → 销售跟进名单

**同一个问题：把难以利用的文本，变成可执行、可回收、可迭代的线索。** 换的只是标签体系与语言。

### 主线 2 · 「算得准」：这是我区别于纯算法候选人的地方

ICBU 做 AI+Sales 的最大障碍不是模型，是**销售愿不愿意用、用了算不算业绩**。
我有无分流场景下的因果评估经验，能把"AI 建议"变成"可验证的业绩增量"——**这是从 0 到 1 产品化必须补上的一环**，而多数算法候选人只会讲指标。

### 主线 3 · 「智能工作流」：我做过口径统一，这是工作流的前置

智能工作流的前提是**每一段能被度量**。我在中信第一件事是把六渠道口径打通、建漏斗——**这就是"工作流能跑起来"的地基**。
→ ICBU 的销售动作散在询盘/邮件/IM/电话/展会，同样先要口径统一。

### 附：一条 ICBU 独有的洞察（可主动抛，显示我想过业务）

ICBU 的「AI+Sales」是**双向的**：
- 对**自家销售**：帮他找客户、准备材料、提效（= 银行侧的我）
- 对**平台商家**：让商家**自己会卖**——帮起标题、做素材、回询盘、选品（= 商家也是"销售方"）
> **「JD 标签里有 'SaaS'，说明产品是要被商家用起来的，不只是内部工具。我在 OPPO 做过素材理解与优选，那一套正好对得上"帮商家把商品卖出去"。」**
