# 媒体浏览系统模块

## Context（背景与目标）

用户希望为本地媒体文件搭建一个「媒体浏览系统模块」，支持**视频播放**与**图片浏览**，起始根目录为：

- `/Volumes/固态硬盘1T/009-暂存内容/115网盘下载`（当前为空文件夹）
- `/Volumes/固态硬盘1T/009-暂存内容/Telegram Desktop`（含 mp4 视频与 jpg 图片，视频体积大，最大 ~650MB）

后续还会新增其他下载目录。经确认，采用：
- **入口**：桌面顶栏新增「媒体」tab，点击进入独立页 `/media`
- **加目录**：页面内一键添加，写入 `config.toml` 的 `[media] roots`

实现方式：新增一个自包含的 FastAPI 后端模块（目录扫描 + 文件流式传输）+ 一个独立的静态页（卡片网格、图片灯箱、视频播放器），复用项目现有的独立页 + 模块路由接入模式（参照 topics / interview 模块）。

## 后端新增

### 1. 配置接入（`src/openbiliclaw/config.py`）
- 新增 `@dataclass class MediaConfig`：`roots: list[str] = field(default_factory=list)`（放在 `InterviewConfig` 附近）。
- `Config` 类新增字段：`media: MediaConfig = field(default_factory=MediaConfig)`。
- `_build_config` 中解析 `raw.get("media", {})`，读取 `roots`（字符串列表，兼容单字符串→len 1）：
  `media=MediaConfig(roots=[...])`。
- `config.example.toml` 追加 `[media] roots = []` 段并注释说明（参照 `[travel]`/`[interview]` 写法模板）。

### 2. 核心模块 `src/openbiliclaw/media/`
- `__init__.py`
- `service.py`：纯逻辑，便于单测。
  - 常量 `VIDEO_EXTS` / `IMAGE_EXTS`。
  - `MediaService(roots: list[str])`
    - `roots_meta()` → 每个根的 `{path, exists, is_dir, video_count, image_count}`（用 `os.scandir` 顶层扫描计数，避免遍历大目录）。
    - `list_items(root, *, kind='all', q='', sub='', offset, limit)` → 顶层/子目录分页列表，每个 item：`{name, is_dir, kind(video/image/other), size, mtime, rel}`（`rel` 用于文件/子目录访问）。仅 `os.scandir`，非递归，保证大目录快。
    - `resolve_file(root, rel)` → 安全解析：`root` 必须是配置内的规范化绝对路径精确匹配；`rel` 经 `resolve()` 后必须仍在 root 内（防目录穿越）；不存在则抛 `MediaNotFound`。
- `routes.py`：`build_media_router(*, config: Config, config_save_lock=None) -> APIRouter(prefix="/api/media")`
  - `GET /api/media/roots` → roots 元信息。
  - `POST /api/media/roots` body `{path: str}` → 校验目录存在，追加到 `config.media.roots`，调用 `save_config(config)`（受 `config_save_lock` 保护）持久化，返回新 roots。锁以参数注入（遵循项目"闭包变量通过函数参数传递"约束）。
  - `GET /api/media/list`（`root, kind, q, sub, offset, limit`）→ 分页列表 `{items, total_or_has_more, offset}`。
  - `GET /api/media/file?root=&path=` → 校验后返回 `FileResponse`，用 `mimetypes.guess_type` 设 media_type（未知格式回退 `application/octet-stream`）。视频 `<video>` 的 Range 拖动由 Starlette `FileResponse` 原生支持（实现时若版本不支持则改用 `StreamingResponse` + 手动解析 Range）。

### 3. 静态页挂载（`src/openbiliclaw/api/_web_ui_routes.py`）
在既有独立页区块后追加，仿照 health/topics：
```python
_media_dir = _web_dir / "media"
if _media_dir.is_dir():
    app.mount("/media", _StaticFiles(directory=_media_dir, html=True), name="media-page")
```

### 4. 路由注册（`src/openbiliclaw/api/_route_registry.py`）
在 `register_all_routes` 内追加一段（仿照 interview 注册），把 `config` 与 `config_save_lock` 传入 `build_media_router`。`config_save_lock` 已在当前作用域可用（已有多个 router 依赖它）。

## 前端新增

### `src/openbiliclaw/web/media/index.html`（自包含独立页）
- 布局（贴合用户偏好：卡片 3 列/行、tab 左对齐、无突兀选中态）：
  - 顶栏：标题「媒体浏览」+ 根目录 tab 胶囊（来自 `/api/media/roots`）；右下/右上一个小按钮「+ 添加目录」。
  - 工具栏：媒体类型分段（全部/视频/图片）、搜索框（文件名包含）、刷新。
  - 卡片网格：CSS Grid 每行 3 张。
    - 图片卡：`<img loading="lazy" src="/api/media/file?root=&path=">`。
    - 视频卡：缩略区域用占位渐变 + 播放 ▸ 图标 + 文件名。
    - 子目录卡（若存在子目录）：文件夹图标，点击进入该子目录（`sub` 参数），提供面包屑/返回。
  - 底部：「加载更多」按钮（分页追加）。
- 交互：
  - 图片点击 → 灯箱 modal（大图 + 上一张/下一张 + 关闭）。
  - 视频点击 → 播放 modal：`<video controls autoplay src="/api/media/file?...">`。视频若浏览器不支持（mkv/avi/flv/wmv/ts）给出提示文案（HTML5 仅支持 mp4/webm/mov/m4v 常见编码），其余照常列出。
  - 添加目录：输入框 + 确认 → POST `/api/media/roots` → 刷新根 tab。
  - 空状态文案处理。
